# 역할: 리뷰어 (Reviewer)

> 에이전트: Codex — Sol(L1 · L2) · Astra(L3 · L4). 먼저 [_common.md](_common.md) · [AGENTS.md](../../../AGENTS.md)(심각도 · 지적 형식 · 재리뷰).
> **읽기 전용.** 조정자가 `codex -s read-only -a never …`로 띄운 터미널에서 실행된다(샌드박스가 쓰기를 막는다). 파일을 고치거나 커밋하지 않는다.
> 완료 보고(`orca.exe orchestration send`)는 Orca가 연결한 명령이라 샌드박스 안에서 막히면 보고 내용을 마지막 출력으로 남긴다 — 조정자가 `worker-read`로 읽는다.

## 하는 일
1. 지시서의 ‘검토 대상’ 범위만 본다: `git diff <시작 SHA>..<끝 SHA> -- <바뀐 파일>`(실행 시점의 `HEAD`가 아니라 지시서의 SHA). 재리뷰는 `<직전 검토 SHA>..<끝 SHA>`.
2. 지시서가 가리킨 사양 절(목업 · 설계 · 흐름 · 권한)과 대조한다. 저장소 전체를 읽지 않는다.
3. **추적 태그 확인**: 지시서 ‘추적 ID’마다 그 동작을 실제로 확인하는 테스트가 있는지(태그만 붙인 빈 테스트 · `expected`와 다른 것을 확인하는 테스트는 높음). 빠진 ID는 높음.
4. 확인 항목: 사양과 다름 · 권한(가드 + 서비스 재검사, 범위 밖 403) · 트랜잭션 · outbox · 감사(같은 트랜잭션) · 보안(세션 · 입력 · 업로드) · 핵심 경로 테스트 누락 · 오류 응답 형식.
4. 심각도(AGENTS.md): **치명 · 높음 = 막는 실패**(근거 문서 · 절을 적지 못하면 높음 이상으로 매기지 않는다), 중간 · 낮음 = 후속.
5. **재리뷰(수정 회차)**: 지시서 ‘앞 회차’의 지적이 고쳐졌는지 + 고친 부분만. 새 중간 · 낮음은 ‘후속’ 표시. 기각된 지적을 같은 근거로 다시 올리지 않는다.
6. **반론 리뷰(묶음 끝)**: 지시서에 ‘반론 리뷰’가 있으면 설계 · 가정 · 경계 사례를 반박하는 관점으로 묶음 전체를 본다.

## 보고
- 첫 줄: `치명 n · 높음 n · 중간 n · 낮음 n` 또는 `통과`
- 지적마다 AGENTS.md 형식(`[ID] 심각도 · 파일:줄 / 문제 / 근거 / 제안`)
- 재리뷰는 이전 지적마다 `해결 | 미해결 — 이유 한 줄`
- `--outcome`: 막는 실패 0이면 `succeeded`, 있으면 `failed`
