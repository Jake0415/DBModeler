# 역할: 공동 편집 담당 (Collab)

> 에이전트: Claude — **Fable 5.2(L4 고정): 처음 xhigh, 수정 회차 max**(계획 §5.4 L4 열). 먼저 [_common.md](_common.md).
> 가장 위험한 영역이다. 설계 §13.1(고정 → 검증 → 커밋) · §13.2(열람 범위) · §13.6(회수 전파)이 기준이다.

## 쓰기 범위
- `apps/collab` · `packages/model-doc` · 그 테스트
- 금지: `apps/api`(BE와 같이 맡는 작업은 조정자가 BE 몫을 별도 작업으로 나눈다 — 내부 RPC 계약은 `packages/model-doc` 또는 계약 담당 작업으로) · 그 밖의 `packages/*` · `apps/web` · `docs/*`

## 하는 일
1. 버전별 쓰기 주인은 collab 하나. 갱신은 증가 순번으로 내구 저장(`ydoc_updates`) · 체크포인트 · 재시작은 체크포인트 + 재생.
2. 저장 ACK: 내구 저장한 순번을 클라이언트에 돌려준다(목업의 저장 상태 표시).
3. 쓰기 검증: 적용 전에 구조 · 참조 무결성을 검사해 거부. 갱신 크기 · 빈도 상한.
4. 접속 판정 = 세션 유효 × 조회 범위 × 검토 상태. `review`가 되면 결재선 · 신청자 아닌 연결은 끊는다. 권한 회수는 갱신 수신마다 자격 확인.
5. 확정 신청 고정: 고정 요청 → 새 쓰기 거부 → 대기 갱신 저장 → 고정 순번 · 해시 반환 → 실패 시 해제. 재시작해도 DB 상태로 복구.
6. 스파이크(`spikes/yjs-sync`)의 측정을 재사용한다.

## 완료 기준
- `npm run build` · 테스트 통과, 두 클라이언트 동시 편집 · readOnly 전환 · 고정 중 쓰기 거부 · 재시작 복구 테스트
- 보고에 동시성 시험 결과(클라이언트 수 · 갱신 수 · 손실 0 확인)를 숫자로
