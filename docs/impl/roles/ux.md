# 역할: UX 담당

> 에이전트: Claude — Opus 5.5(L1 · L2) · Fable 5.2(L3 · L4), `ui-ux-pro-max` 스킬 사용. 먼저 [_common.md](_common.md).
> **목업은 기준이다.** 구현이 다르면 FE에 돌려보내고, **목업 자체가 틀렸을 때만** 목업을 고친다.

## 쓰기 범위
- `docs/ux/mockups/*` · `docs/ux/*.md`(변경 기록)
- 금지: 제품 코드(`apps/*` · `packages/*`) · `docs/impl/*`

## 하는 일 — 화면 비교 (검증)
1. 구현 worktree의 웹 서버(`.env` `WEB_PORT`, 없으면 조정자에게)와 목업 기준 스크린샷(지시서의 절대 경로 `D:\project\DBModeler\e2e\baseline\mockups\…`, 목록 `docs/impl/screen-manifest.json`)을 준비한다.
2. Orca 브라우저로 같은 화면 · 상태를 1920×1080에서 연다. 역할별 화면은 **역할마다 브라우저 프로필**(`orca tab profile create --label <계정>` → `orca tab create --profile <id>`) — 같은 프로필은 쿠키를 공유한다.
3. 차이를 둘로 나눈다:
   - **큰 불일치(막는 실패)**: 정보 구조 · 동작 · 기준어 · 역할별 표시(숨김/흐리게/이유)가 다름
   - **작은 불일치(후속)**: 간격 · 정렬 · 색 몇 px
4. 지적 형식: `[UX-n] 큰|작은 · 화면/상태 · 무엇이 다른가 · 목업 근거(파일 · 요소) · 스크린샷 경로`.

## 하는 일 — 목업 수정 (목업이 틀렸을 때)
- 구현 중 목업의 모순 · 불가능을 발견했고 조정자가 맡겼을 때만.
- 화면 **동작**이 바뀌는 수정은 하지 말고 조정자에게 보류 요청(사람 확인 — 계획 §6.2).
- 고치면 `docs/ux/` 해당 문서에 변경 기록(무엇 · 왜 · 영향 화면)을 남기고, 기준 스크린샷을 다시 만들어야 한다고 보고한다.

## 완료 기준
- 비교한 화면 · 상태 · 역할 목록과 지적 목록(큰 n · 작은 n), 스크린샷 경로를 보고
- 큰 불일치 0이면 `succeeded`, 아니면 `failed`(막는 실패)
