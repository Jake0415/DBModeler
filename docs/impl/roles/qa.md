# 역할: QA

> 에이전트: Codex — Sol(L1 · L2) · Astra(L3 · L4). 먼저 [_common.md](_common.md) · [AGENTS.md](../../../AGENTS.md).
> **사양을 보고 테스트를 쓴다.** 구현 코드를 보고 기대값을 맞추지 않는다(구현자와 다른 모델이 검증하는 이유).

## 쓰기 범위
- `e2e/` 중 `e2e/scenarios/` · `e2e/rbac/` · `e2e/baseline/` **제외** · 테스트 데이터(`e2e/fixtures/` 등)
- 금지: 제품 코드(`apps/*` · `packages/*`) · `docs/*`

## 하는 일
1. 지시서의 사양(목업 화면 · 상태, 흐름 절, 설계 절)에서 기대 동작을 뽑아 E2E · 회귀 테스트로 쓴다(Playwright — P1 E2E 틀이 생긴 뒤).
2. 데이터는 이 worktree DB에서(BE · FE가 나뉜 묶음은 조정자가 만든 **통합 worktree**에서, 역할 시나리오 · 권한 감사와 차례로): 시작 때 초기화 + 시드(시험 계정 `@neodb/domain` TEST_ACCOUNTS, 비밀번호 `.env` `TEST_PASSWORD`). 다른 worktree DB를 쓰지 않는다.
3. 성능 기준이 있는 작업(검색 · 300 엔터티 · 10만 행)은 설계 23 §6 숫자를 기준선으로 측정해 적는다.
4. 실패하면 재현 절차 · 기대 · 실제를 적는다. 불안정하면 한 번 다시 돌려 보고 ‘환경’으로 구분한다.

## 완료 기준 · 보고
- 테스트를 커밋하고, 실행 결과(통과 n · 실패 n · 건너뜀 n, 측정값)를 보고
- 사양대로 동작하지 않는 것 = 막는 실패(`failed`), 모두 통과 = `succeeded`
