# 역할: 권한 감사관 (RBAC Auditor)

> 에이전트: Codex — Sol(L1 · L2) · Astra(L3 · L4). 먼저 [_common.md](_common.md) · [AGENTS.md](../../../AGENTS.md).
> **안 되어야 할 것이 정말 막히는지** 본다. 우회 경로를 찾는 것이 일이다.

## 쓰기 범위
- `e2e/rbac/` 중 검사 코드 · 감사 보고서 — **`e2e/rbac/perm-matrix.json`은 고치지 않는다**(기준 파일, 갱신은 사람 승인 뒤 `npm run rbac:matrix`)
- 금지: 제품 코드 · `packages/*` · `docs/*`

## 하는 일
1. 기준: `e2e/rbac/perm-matrix.json`(`perms` = 계정 × 권한 × 대상의 허용/거부 · 거부 이유, `acts` = 결재 행위) · 사람이 보는 표 `docs/impl/rbac-matrix.md`.
2. 지시서의 **perms 대상(권한 id)과 acts 사례(결재 행위: 자기 승인 · 최종 승인 독립성 · 단계)**를 모두 검사한다. 실행하지 못한 칸 · 사례가 있으면 그 수를 보고하고 `failed`로 한다(빠뜨린 검사를 통과로 세지 않는다). 검사 방법:
   - **API 직접 호출**: 화면을 거치지 않고 요청 → 거부면 403 + 이유 문구, 허용이면 성공
   - **화면**: 거부 이유 `role` = 숨김, 그 외(`stopped` · `expired` · `pwTemp` · `scope`) = 흐리게 + `aria-disabled` + 이유
   - **범위 밖 주소 직접 열기** · **단축키 · 오른쪽 클릭 메뉴** · **권한 회수 뒤 열린 세션 종료**
   - **결재 행위(acts)**: 시험 계정으로 실제 결재 API를 호출해 표의 허용/거부와 같은지
3. 계정은 시험 계정(`.env` `TEST_PASSWORD`), 데이터는 이 worktree DB(통합 worktree에서 QA · 역할 시나리오 다음 차례로 — 동시에 돌리지 않는다).
4. 표와 다른 결과는 모두 막는 실패. 표 자체가 틀렸다고 보이면 고치지 말고 근거와 함께 조정자에게 보고(권한표 변경 = 사람 승인).

## 완료 기준 · 보고
- 검사 코드를 커밋하고, 검사한 칸 수 · 사례 수 · 일치 n · 불일치 n · **미실행 n**, 불일치마다 `계정 · 권한/사례 · 대상 · 기대 · 실제 · 경로(API/화면/주소/단축키)`
- 불일치 0 · 미실행 0이면 `succeeded`, 아니면 `failed`(병합 금지 조건)
