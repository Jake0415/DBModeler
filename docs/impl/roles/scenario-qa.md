# 역할: 역할 시나리오 QA (다중 계정)

> 에이전트: Claude — Opus 5.5(L1 · L2) · Fable 5.2(L3 · L4). 먼저 [_common.md](_common.md).
> 한 업무 흐름을 **여러 계정으로 이어서** 실행해 끝까지 되는지 본다(신청 → 1단계 → 최종 → 반영, 반려 · 회수 · 위임 · 자기 승인 · 열람 범위).

## 쓰기 범위
- `e2e/scenarios/` · 시나리오 데이터
- 금지: 제품 코드 · `e2e/rbac/` · `docs/*`

## 하는 일
1. 지시서의 시나리오 ID(01-task-list §2, 예: S-02)의 흐름 · 계정 · 허용/거부 경로를 그대로 테스트로 옮긴다.
2. 계정 바꾸기(계획 §9.2): Playwright **역할별 로그인 상태 저장 + 브라우저 컨텍스트 여러 개**로 한 시나리오 안에서 창을 오간다. 로그인 화면 자체는 시나리오마다 1회만 실제로 거친다.
3. 시나리오 시작마다 이 worktree DB를 초기화 + 시드(앞 시나리오의 결재 상태가 남지 않게). BE · FE가 나뉜 묶음은 조정자가 만든 **통합 worktree**에서, QA · 권한 감사와 차례로 돈다(동시에 DB를 초기화하지 않게).
4. 단계마다 확인: 화면 상태(대기함 · 버튼 · 안내 띠) · API 응답 · 감사 로그 행 · 다른 계정에서 보이는지/안 보이는지.
5. 역할별 화면 스크린샷을 남긴다(Orca 브라우저는 역할마다 프로필).

## 완료 기준 · 보고
- 시나리오 테스트를 커밋하고, 단계별 결과(통과 · 실패 · 계정 · 확인 내용)와 스크린샷 경로를 보고
- 흐름이 끊기거나 거부여야 할 것이 허용되면 막는 실패(`failed`)
