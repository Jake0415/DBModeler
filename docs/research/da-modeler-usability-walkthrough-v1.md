# DA# Modeler 사용성 워크스루 — 요구사항관리시스템 샘플 (v1)

> 상태: **조사 기록 (1회 실사용 워크스루)**. 구현 계획 아님.
> 목적: 웹 데이터 모델러 2차(UX 개선) 입력으로, 데스크톱 원본을 직접 조작하며 겪은 **사용성 문제**를 근거와 함께 남긴다.
> 관련: [기능 인벤토리 v1](../planning/web-data-modeler-feature-inventory-v1.md)

## 0. 조사 조건

| 항목 | 내용 |

## 1. 수행한 시나리오와 결과

| # | 단계 | 수행 내용 | 결과 |
|---|---|---|---|
| 1 | 엔터티 생성 | 리본 `엔터티` → 캔버스 클릭 → 더블클릭으로 편집창 → 이름 `산출물기본`, 속성 4개(`산출물ID`(식별자)·`산출물명`·`산출물유형코드`·`제출일자`) 입력 | 성공 (수동 크기 맞춤 필요) |
| 2 | 관계 생성 | `관계선 ▾` → `1:M Mandatory` → `요구사항내역` → `산출물기본` | 단일 클릭 시 **의도치 않은 재귀관계** 생성 → Undo 후 **드래그**로 성공. FK `요구사항ID` 자동 전이 |
| 3 | 물리 변환 | `물리설계` → `물리 모델 생성`(ORACLE, 표준화=대상) → `물리 다이어그램` | 성공. 기존 엔터티는 영문명(예 `RQRM_D`, `DEMND_MATER_ID`)으로 변환, **신규 엔터티는 한글명·데이터타입 공란 그대로** |
| 4 | 표준 적용 | `데이터` 탭 표준 그룹 / 엔터티 편집 `표준 정보` / `검토` → 표준화 탭 | **진행 불가**. 표준 동기화 버튼 대부분 비활성, `사전`은 별도 프로그램 실행, `검토`는 결과 표시 없음 |
| 5 | DDL 생성 | `스크립트 작성` → CREATE TABLE·COMMENT 섹션 체크 → `스크립트 생성` → 저장 | 생성됨. 단 **신규 테이블 DDL이 문법 오류**(타입 없는 컬럼), **FK 제약 0건**, COMMENT 중복 |

신규 테이블에 대해 실제 생성된 DDL (발췌, Oracle):

```sql
CREATE TABLE 산출물기본
(
    산출물ID NOT NULL,
    산출물명,
    산출물유형코드,
    제출일자,
    DEMND_MATER_ID    VARCHAR2(10) NOT NULL
);
```

→ 데이터타입이 없는 컬럼 4개와 따옴표 없는 한글 식별자가 그대로 나왔다. 생성 중 경고는 없었다.

## 2. 사용성 문제 목록

심각도: **상** = 잘못된 산출물/작업 불가, **중** = 작업은 되나 시행착오·혼란, **하** = 불편.

### 2.1 산출물 품질 (검증 부재)

| ID | 심각도 | 문제 | 관찰 근거 | 웹 버전 시사점 |
|---|---|---|---|---|
| U-01 | 상 | **불완전 모델로 DDL이 무경고 생성** | 데이터타입 없는 컬럼이 그대로 `CREATE TABLE`에 포함. 실행하면 실패할 스크립트 | DDL 생성 전 **사전 검증(타입 누락·비표준명·예약어)** 을 차단/경고로 노출 |
| U-02 | 상 | **FK 제약이 DDL에 나오지 않음 — 원인을 UI에서 알 수 없음** | 물리 Relation 7건 존재. `CREATE TABLE ▸ FK`와 `CONSTRAINT ▸ FK ▸ Add`를 모두 체크해도 `FOREIGN KEY` 0건 | 옵션 결과 미리보기 + "관계 N건 중 FK M건 생성" 요약. 누락 시 이유(관계 속성 등) 표시 |
| U-03 | 중 | **물리 변환 시 미표준 엔터티가 조용히 통과** | 용어 미등록 `산출물기본`은 테이블·컬럼명이 한글 그대로, 타입 공란. 변환 완료 메시지·경고 없음 | 변환 결과 요약: 표준 매핑 성공/실패 건수, 실패 항목 바로가기 |
| U-04 | 중 | **COMMENT 문 중복 출력** | `CREATE TABLE ▸ Comment`와 `[COMMENT] Section`이 각각 같은 주석을 생성 (총 100건, 테이블당 2벌) | 같은 결과를 내는 옵션은 하나로. 겹치면 비활성/안내 |

### 2.2 표준 적용 흐름

| ID | 심각도 | 문제 | 관찰 근거 | 웹 버전 시사점 |
|---|---|---|---|---|
| U-05 | 상 | **표준 기능이 비활성인데 이유를 안 알려 줌** | `분류체계 선택`·`속성/엔터티 표준 동기화`·`표준속성 추가`·`용어 자동분석`·`준수검사` 비활성. 엔터티를 선택해도 동일. 툴팁은 기능 설명만 ("선택한 엔터티에서 엔터티명에 대한 표준화를 진행합니다") | 비활성 사유와 해결 동작("저장소 연결 필요 → 연결하기")을 버튼 옆/툴팁에 |
| U-06 | 중 | **표준 사전이 별도 프로그램으로 분리** | `사전` 클릭 시 `DAWordict.exe`가 새 창(작업표시줄 별도 아이콘)으로 실행. 모델과 사전을 오가는 컨텍스트 전환 | 사전 조회·용어 등록을 모델러 안 사이드 패널로. 미등록 용어는 그 자리에서 후보 등록 |
| U-07 | 중 | **`표준 정보` 버튼이 눈에 보이는 반응 없음** | 엔터티 편집 → 속성 선택 → `표준 정보` 클릭 후 화면 변화 없음, 편집창은 비활성(제목 회색)·`취소` 무반응 → 앱을 다시 앞으로 가져와야 복구 | 결과는 같은 창 안에서. 다른 창으로 포커스를 넘길 때는 명시적으로 |
| U-08 | 중 | **모델 내 용어(`용어` 노드)를 모델러에서 추가할 방법이 안 보임** | 트리 `논리 객체 ▸ 용어` 우클릭 시 메뉴 없음. 엔터티 우클릭 메뉴(약 25항목)에도 표준 관련 항목 없음 | 엔터티/속성 우클릭에 "표준 용어 찾기·등록" 제공 |

### 2.3 검토(모델 체크)

| ID | 심각도 | 문제 | 관찰 근거 | 웹 버전 시사점 |
|---|---|---|---|---|
| U-09 | 중 | **검토 실행 후 결과가 어디에도 안 보임** | `검토` → 표준화 탭 `미표준 엔터티/속성` 체크 → `검토` → 창 닫힘. 출력 패널 `검토`·`알림` 탭 모두 비어 있음 | 실행 결과를 항상 표시 (0건이어도 "위반 0건") |

## 3. 정리 — 웹 버전 우선순위로의 반영

1. **검증을 생성 흐름 안으로 (U-01·02·03·09)** — 물리 변환·DDL 생성 직전에 "미표준·타입 누락·FK 누락"을 한 화면에서 보여 주고, 클릭 한 번으로 해당 객체로 이동. 원본에서 가장 큰 문제는 *잘못된 결과가 조용히 나온다*는 점이다.
2. **표준 사전을 모델러 안에 (U-05~08)** — 별도 프로그램·저장소 연결 없이도 모델 내 용어로 표준 매핑, 미등록 용어는 후보 큐로 등록. 기능 인벤토리 §3.4 P0 항목(속성/엔터티 표준 동기화·준수 검사)의 UX 요구사항으로 사용.
3. **다이어그램 기본 동작 정리 (U-11~15)** — 관계 생성 2단계+미리보기, 자동 크기 맞춤 일관화, 엔터티 회피 라우팅.
4. **대화상자 줄이기 (U-16~22)** — 모달 대신 우측 속성 패널, 탭 전환 확인창 제거, 옵션 프리셋.

## 4. 한계와 후속 확인

- 표준관리자(`DAWordict.exe`) 화면은 보지 못했다. 원본의 정식 표준 적용 흐름(사전 업로드 → 동기화)은 **저장소 연결 + 표준관리자**를 거치는 것으로 보이며, 샘플 동봉 `요구사항관리시스템_용어일괄등록템플릿.xlsx`·`도메인일괄등록시스템.xlsx`가 그 입력으로 추정된다. 이 경로로 다시 워크스루해 U-05~U-09를 확정/수정할 것.
- U-02(FK 미생성)의 원인은 확인하지 못했다(관계 속성, `객체 선택` 범위, 트라이얼 제한 가능성). 원인보다 **UI가 이유를 알려 주지 않는다**는 점을 문제로 기록한다.
- U-09(검토 결과 없음)은 결과가 다른 창/모니터에 떴을 가능성을 배제하지 못했다(두 모니터 모두 확인했으나 표시 없음).
- 1회 워크스루, 1인 관찰. 빈도·심각도는 추가 사용자 관찰로 보정 필요.
