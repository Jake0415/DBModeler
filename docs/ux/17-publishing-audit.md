# 17. 퍼블리싱 점검 — 화면 전체 일관성

> 2026-11-20 · 상태: **P0~P4 적용 완료**(§6). 결정 D1~D4는 권장안으로 확정(사용자, 2026-11-20).
> 범위: FE 목업 21개 화면(`docs/ux/mockups/*.html`)과 공통 `assets/app.css` · `assets/app.js`. 실제 구현은 하지 않는다.
>
> 방법:
> - 화면마다 1920px · 1600px 폭으로 열어 자동으로 측정했다(42회).
>   - 측정 항목: 글자 크기 · 굵기, 버튼 · 입력 높이, 인라인 스타일, 직접 쓴 색, 이름 없는 버튼 · 입력, 아이콘 대신 쓴 문자, 가로 넘침, 페이지 헤더 · 표 · 배지 · 탭 · 배너 종류
>   - 역할: 모델러 김모델. 설정 · 감사 로그는 DA · Admin 계정(lee).
> - 대표 화면 캡처로 비교했다.
> - 기준 문서:
>   - [01 디자인 가이드 v1](01-design-guide.md)
>   - [08 디자인 리프레시](08-design-refresh-plan.md)
>   - [09 Geist 컴포넌트](09-geist-components.md)
>   - 견본 `styleguide.html`

## 1. 한눈에

| 구분 | 상태 |
|---|---|
| 좋은 점 | 상단 바 · 페이지 헤더(56px, 제목 20/600)는 21개 화면 모두 같다. 표 머리줄 · 행 높이(44px)도 모든 표에서 같다. 아이콘 세트(Lucide 선 아이콘), 색 토큰은 화면 HTML에 직접 쓴 색이 거의 없다(모델 화면 6곳뿐). 가로 넘침은 목업 목록(index)을 빼면 없다. 이름 없는 버튼은 견본 1개뿐이다 |
| 가장 큰 문제 | **기준이 세 겹이다.** 가이드 v1(행 32px · 표 13px · 굵기 700 금지) → 08(v8 꼬리표 `.tag`) → 09(Geist: 행 44px · 표 14px · 배지 `.badge`)가 차례로 덮였는데, 앞 문서를 고치지 않았고 `app.css`도 앞 규칙을 지우지 않고 뒤에 덧붙였다. 그래서 같은 역할이 화면마다 다른 부품으로 그려진다(상태 표시 2종, 탭 4종, 버튼 높이 8종) |

## 3. 결정이 필요한 것

| # | 질문 | 권장 | 이유 |
|---|---|---|---|
| **D1** | 표 밀도: 행 44px(지금) vs 32px(가이드 v1 · "촘촘한 밀도" 요구) | **기본 36px + 설정에서 촘촘(32) / 보통(44)** | 00-inputs의 "촘촘한 밀도" 요구는 32 쪽이다. 지금 44px는 Geist 측정값을 그대로 따른 것으로, 표준 맞추기 · 사전처럼 행이 많은 화면에서 한 화면에 보이는 행이 줄어든다. 하나만 고른다면 36px |
| **D2** | 상태 표시 체계 | **Geist 배지(`.badge`) 하나** + 의미표(진행 중 · 내 차례 · 승인 · 반려 · 경고 · 예외) | 화면 수로 이미 다수다. v8 꼬리표는 홈 · 결재함 2곳만 바꾸면 된다 |
| **D3** | 우측 패널 폭 | **1920 이상 420 · 1600~1919 380 · 넓히기 560**(가이드 v1대로), 결재함도 같은 규칙 | 화면마다 다른 폭은 패널 내용이 화면마다 다르게 접히는 원인 |
| **D4** | 페이지 경로 | **모델 계열(시스템 › 업무 영역)에만** 둔다. 상단 메뉴 화면은 제목만 둔다. 사전 하위 화면은 제목 위에 "사전" 탭 줄로 묶는다 | 상단 메뉴 화면은 깊이가 1단계라 경로가 정보가 없다 |
