# 22. 목록 화면 표준 — 표 탐색 · 검색 · 필터 (v1.0)

> 상태: **v1.0** (2026-11-23) — 초안 v0.1을 Codex 협의(`review/codex-list-standard.md`, R-01~10)와 Claude UX 전문가 검토(`review/claude-list-standard.md`, CL-01~12)로 고쳤다. 처리 내용: `review/resolution-list-standard.md`.
> 범위: 목업(docs/ux/mockups)의 목록 · 표. 화면 모양(행 높이 · 머리줄 · 색)은 `01-design-guide.md` §6.4, 이 문서는 **동작**(찾기 · 거르기 · 훑기 · 고르기 · 상태 저장 · 접근성)을 정한다.
> 용어: 사용자에게 보이는 말은 **'필터'** 하나로 쓴다('조건'은 쓰지 않는다).

## 1. 적용 범위 (L-0)

| 종류 | 예 | 적용 |
|---|---|---|
| **조회 목록** | 사전, 공통표준, 도메인 그룹, 변경 내역, 감사 로그, 업로드 이력, 사용자 | 이 문서 전부 |
| **처리 큐** | 결재함 대기함, 후보 큐 '대기', 표준 맞추기 | 전부 + L-9 큐 규칙 |
| **편집 표** | 엑셀 5단계, 모델 표 보기 · 속성 그리드, 바구니 편집, 용어 마법사 검토 | 건수 · 빈 결과 · 접근성 · 선택 범위만. 키 · 편집 범위는 화면 규칙 |
| **트리 표** | 도메인 그룹, 모델 트리 | 검색 · 건수 · 빈 결과. 계층 키(←→)는 화면 규칙 |
| **작은 표** | 홈 요약, 상세 안 표, 미리보기, 설정 표 | 기본 표 모양 · 빈 결과만 |

## 2. 목록 화면 구조 (위 → 아래)

```
[화면 제목]                                          [주 행동]
[함 · 보기 세그먼트]       (다른 집합으로 바꿀 때만)
[검색] [빠른 칩 …] [주축 필터 하나] [필터 ▾ n]        [내보내기 · 보기 설정]
[건수 줄: 128건 중 12건 · 관련도순 · 적용된 필터 칩 × … 모두 지우기 | 3개 선택 · 일괄 행동]
[표 — 머리줄 고정]                              [오른쪽 패널]
```
- 적용된 필터 칩은 건수 줄에 두고, 넘칠 때만 다음 줄로 내린다. 검색어도 칩 하나로 보인다.

## 3. 규칙

### L-1 부품
| 할 일 | 부품 | 판정 기준 |
|---|---|---|
| 다른 **집합 · 보기**로 바꿈(함, 종류, 논리/물리) | 세그먼트 `.seg` + `aria-pressed` | **열 · 행 행동 · 기본 정렬이 바뀌면** 세그먼트 |
| 같은 열에서 **행만 줄임**(상태 · 분류) | 칩 `<button class="chip" aria-pressed>` | 칩 묶음은 `role="group"` + `aria-label`. 높이 32. '전체'는 맨 앞 |
| 화면의 **주축 필터 하나**(감사 · 이력의 기간, 공통표준의 기관) | 도구줄의 선택상자 | 화면당 하나까지 |
| 그 밖의 필터 | [필터 ▾ n] 팝오버 | 버튼에 적용 개수 |

- 칩이 7개를 넘으면: 처리가 필요한 상태(오류 · 확인 필요 · 보류)를 앞에, 6개 + [더보기 ▾]. 더보기 안에서 고른 칩은 건수 줄의 적용된 필터 칩으로 보인다. 건수 0인 칩은 흐리게 두되 고를 수 있다(자리 이동 없음).
- 같은 필터군 안의 다중 칩은 OR, 서로 다른 필터군 사이는 AND.
- 같은 필터를 두 곳(칩 · 팝오버 · 적용 칩)에서 바꿀 수 있으면 상태를 늘 같게 한다.

### L-2 검색
공통 함수 `listMatch(q, fields, profile)`. 사전도 이 규칙에 맞춰 고친다(지금 사전은 첫 칸만 보고 설명은 대소문자 구분).
- 정규화: 대소문자 · 전각/반각 · 앞뒤 공백 무시. **공백을 지운 값끼리도 비교**(띄어쓰기 차이 흡수).
- 낱말: 공백으로 나눈 낱말은 모두 맞아야(AND). 한 낱말은 **한 칸 안에서** 맞고, 서로 다른 낱말은 다른 칸에서 맞아도 된다(칸 경계를 넘겨 맞지 않음).
- 프로필:
  | 프로필 | 쓰는 곳 | 일치 |
  |---|---|---|
  | **명칭** | 사전, 공통표준, 도메인 그룹, 트리 | 초성(초성 · 완성 글자 섞인 입력 포함) · 순위. 낱말 하나이고 2글자 이하면 이름 · 약어 앞부분 |
  | **문서 · 코드** | 결재함, 업로드, 변경 내역 | 번호 · 코드는 포함 일치(예: '12' → REQ-2026-0012), 이름은 포함 |
  | **로그** | 감사 로그 | 칸별 포함 일치(사용자 · 대상 · 내용) |
- 입력 즉시(150ms 뒤) 거른다. 한글 조합 중(`isComposing`)의 Enter · 화살표는 무시. Enter = 첫 결과 열기(조합 끝난 뒤).
- 찾은 글자는 원문 위치를 알 때만 `<mark>`. 동의어 · 초성 · 과거 이름으로 맞으면 '일치 이유'를 작게 적는다.
- 검색 대상 칸은 자리표시자와 접근 가능한 이름에 적는다(예: "이름 · 약어 · 설명 찾기").
- 사전의 금칙어 안내(맨 위)와 빈 검색 = 최근 변경은 지킨다.
- 모델 표 '찾기'는 찾기 · 바꾸기 도구다(거르기 아님). 거르기를 더하려면 바꾸기 대상 범위를 먼저 적는다.

### L-3 주소 상태
- **목록이 소유하는 키만** 쓴다: `q`(검색), `f`(칩), `v`(보기), `s`(정렬), `sel`(선택 행), 팝오버 필터는 이름 그대로. 기본값은 쓰지 않는다.
- **기존 키는 계속 읽는다**(별칭): `doc` `b` `c` `user` `code` `pub` `per` 등. 검토 모드 · 되돌아가기 키(`as` `audit` `ret` `tree`)와 해시는 지우지 않는다.
- 필터 · 검색 · 선택은 `replaceState`. **함 · 보기 전환(세그먼트)만 `pushState`** + `popstate`로 복원.
- 상세 화면에 갔다 뒤로 오면 필터 · 선택 행 · 스크롤 위치를 되살린다.
- `sel`은 권한이 있고 존재할 때만 복원한다. 없으면 "찾을 수 없거나 볼 권한이 없습니다" + 목록으로.
- 일괄 체크, 작성 중 내용은 주소에 넣지 않는다. 저장 검색은 사전만(지금처럼), 나머지는 주소 복사.

### L-4 기본 보기 · 지우기
- 화면마다 **필터 없는 기본 상태**를 정하고 건수 줄에 적는다: 사전 = 최근 변경 8건, 결재함 = 대기함 · 내 차례 우선, 후보 = 대기, 감사 로그 = **최근 30일**, 변경 내역 = 최근 30일.
- **[모두 지우기]**(건수 줄)는 검색 · 칩 · 팝오버 필터를 기본 상태로 되돌린다. 함 · 업무 영역 · 보기 · 정렬은 유지한다.
- 팝오버 안 버튼은 **'필터 초기화'**. 다른 문구('초기화' 단독 · '필터 지우기')는 쓰지 않는다.

### L-5 건수 줄 · 알림
- 모든 조회 목록 · 큐에 `.listhead`: "128건" → 거르면 "128건 중 12건" → 선택 시 "· 3개 선택". 기본 순서도 적는다("관련도순", "오래된 순").
- 상한을 넘으면 "앞 500건만 표시 — 필터를 좁히세요".
- 화면낭독기 알림은 건수 줄이 아니라 **숨은 `role="status"` 칸 하나**에 "12건"만, 입력이 멈춘 뒤(약 500ms) 한 번. 같은 수면 다시 알리지 않는다. 건수 줄의 `aria-live`는 뗀다.

### L-6 빈 결과 · 로딩 · 오류 (한 부품 `tr.er`)
| 경우 | 클래스 | 문구 · 행동 |
|---|---|---|
| 아직 데이터 없음 | `er first` | 여기 무엇이 쌓이는지 + 만드는 행동 |
| 필터 때문에 비었음 | `er none` | "필터에 맞는 항목이 없습니다" + [모두 지우기] |
| 큐를 다 처리함 | `er done` | 체크 + "모두 처리했습니다" — **기본 상태(필터 없음)가 비었을 때만** |
| 불러오지 못함 | `er fail` | "불러오지 못했습니다" + [다시 시도]. 필터는 지우지 않음 |
- 판정은 DOM이 아니라 **결과 수와 필터 유무**로 한다. 목록은 행을 숨기지 말고 다시 그린다. 숨겨야 하는 화면은 표에 `.is-empty`를 붙여 머리줄을 숨긴다. 정렬 머리줄이 있는 표는 머리줄을 남긴다.
- 첫 로딩은 표 모양 뼈대(`?skel=1` 방식). 다시 거를 때는 기존 행을 둔 채 건수 줄에 '불러오는 중'. 늦게 온 이전 응답은 버린다.

### L-7 많은 행
- 목업은 **그리기 상한 500**(성능 장치, 과업 단위 아님). 조용히 자르지 않는다 — 바구니 고르기 50은 "앞 50건 · 더 찾으려면 검색" 안내.
- 구현은 가상 스크롤 + 서버 페이지로 끝까지 닿게 한다. 페이지 번호는 쓰지 않는다.
- 감사 로그 · 변경 내역은 행 수 대신 **기간 창**(기본 30일)으로 좁힌다.
- 전체 선택 · 내보내기는 상한과 별개다(L-10, L-12).

### L-8 정렬
- **한 칸 정렬만**: 화면마다 정렬 가능한 칸(날짜 · 이름 · 건수 등)을 정하고, 누르면 오름 → 내림 → 기본. `<th aria-sort>` 안에 `<button>`. 주소 `s=칸:asc`.
- 기본 순서는 화면이 정한다(사전 검색 중 = 관련도, 결재함 = 내 차례 → 머문 일). 칸을 눌러 바꾸면 건수 줄에 "[관련도순으로 되돌리기]".
- 같은 값이면 고정 보조 키(ID)로 순서를 지킨다. 편집 표는 원본 행 순서를 지킨다(정렬 없음). 다중 정렬은 쓰지 않는다.

### L-9 행 선택 · 패널 · 키보드
- 행 클릭 = 선택 + 오른쪽 패널. 행 안의 링크 · 버튼 · 체크는 행 선택을 바꾸지 않는다.
- **조회 목록: 패널 기본 닫힘.** `sel=` 링크로 들어오면 그 행을 고른 채 연다.
- **처리 큐: 첫 행 자동 선택**(결재함 대기함, 후보 '대기'). 처리 뒤 다음 행으로 넘어가고 포커스는 목록에 둔다. 처리해 필터에서 빠진 행은 다음 행으로 넘어간 뒤 사라진다. 내 신청 · 참조함 · 완료 · 이력은 조회 목록 규칙.
- 키보드(조회 목록 · 큐): ↑↓ 행 이동(목록에 포커스가 있을 때), Enter 패널 열기, `/` 검색 칸으로. 승인 · 반려 · 편집은 별도 버튼과 확인을 거친다. 화면 고유 단축키(결재함 J/K/A/R, 엑셀 F8)는 그대로, 입력 칸 · 편집 중 · 모달에서는 가로채지 않고, 마이페이지의 한 글자 단축키 설정을 따른다.
- **Esc 순서**(하나만 처리): 대화상자 → 팝오버 → 검색 칸에 글자가 있으면 지우기 → 패널 닫기.

### L-10 고르기 · 일괄
- 체크 칸은 일괄 행동이 있는 화면에만. 머리줄 체크와 부분 선택 표시는 **그려진 행 중 고를 수 있는 행** 한 집합에서 계산한다(사전의 상한 밖 선택 결함 고침).
- 머리줄 체크로 그려진 행을 다 고르면 건수 줄에 "필터에 맞는 전체 n건 고르기"(별도 행동).
- 일괄 행동의 기본 대상은 **보이는 선택**. 필터로 숨은 선택은 "3개 선택(숨은 1개)"로 따로 세고, 포함하려면 별도 버튼 + 두 번째 확인(모델 표 방식).
- 일괄 도구줄 자리는 늘 두고, 선택이 없으면 비활성 + 이유. 실행 직전에 대상 수 · 제외 수를 알리고 권한 · 최신 버전을 확인한다. 실패한 항목은 이유와 함께 선택을 남긴다.

### L-11 접근성
- 행은 **로빙 tabindex**(고른 행 · 처음엔 첫 행만 0, 나머지 -1). 표에서 Tab 한 번이면 패널 · 다음 영역으로 간다. 고른 행은 `aria-selected="true"`.
- 패널이 열려도 포커스는 행에 남는다. 패널을 닫으면 그 행으로, 팝오버를 닫으면 연 버튼으로 포커스를 돌린다.
- 선택 · 오류는 색만으로 구분하지 않는다(막대 · 아이콘 · 글자).

### L-12 내보내기
- 대상과 건수를 적는다("필터에 맞는 128건 내보내기" / "선택 3건"). 그리기 상한과 무관하게 필터에 맞는 전체. 숨은 선택 포함 여부를 알린다. 파일 첫 줄에 적용 필터를 남긴다.
- 조회 결과 내보내기와 **편집용 양식**(사전 › 편집용 엑셀)은 이름 · 동작을 나눈다. 조회 권한 · 열 공개 범위를 따른다.

### L-13 실시간 갱신
- 보고 있는 동안 들어온 새 항목은 끼워 넣지 않는다. 건수 줄에 "새 항목 n건 · [새로 고침]". 새로 고칠 때 선택 · 포커스는 행 ID로 되살린다.

### L-14 열
- 화면마다 기본 열 순서 · 최소 너비를 정한다. 패널이 열려도 이름 · 식별자는 보인다.
- 가로로 넓은 표(엑셀 5단계 · 모델 표)는 식별 칸을 왼쪽에 고정. 고정 열 · 머리줄이 포커스 셀을 가리지 않게.
- 열 너비 조절 · 숨김 · 저장 보기는 반복 수요가 확인된 화면부터(사전 우선). 사용자별로 저장하고 주소에는 넣지 않는다. 기본값으로 되돌리기를 둔다.

### L-15 같은 목록은 한 곳
- '내 신청'의 정본은 결재함 › 내 신청. 마이페이지는 같은 집계 기준의 건수 + 최근 5건 + [결재함에서 보기].

## 4. 공통 코드 방향
- 큰 `listView` 하나로 묶지 않는다. **작은 부품**으로 나누고 화면이 필요한 것만 쓴다:
  `listMatch`(검색 · 프로필) · `listResult`(필터 · 정렬 · 상한 → 결과 모델: 전체/일치/그림/선택 수) · `urlState`(소유 키 · 별칭 · replace/push) · `countLine` + `liveCount` · `emptyRow` · `rovingRows`(로빙 tabindex · ↑↓ · aria-selected).
- 건수 · 빈 결과 · 전체 선택은 같은 결과 모델에서 계산한다. 기존 `wire()`의 칩 · 행 처리와 중복 실행되지 않게 목록 루트에 표시를 둔다.
- 순서: 업로드 이력 · 감사 로그에서 먼저 검증 → 결재함 · 후보 큐 → 사전(별칭 · 권한 · 선택 계약을 고정한 뒤) → 나머지. 트리 · 편집 표는 필요한 부품만.
