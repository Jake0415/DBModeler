## 1. 구조 — 두 층
| 층 | 범위 | 내용 |
|---|---|---|
| **논리 타입 · 축약명** | 기관 공통 또는 시스템 전용 | 이름 · 축약명 · 인자 형태(`n` / `p,s` / 없음) · 설명 · 종류(표준 / 추가 / DBMS 전용) · 상태(사용 / 사용 중지) |
| **물리 매핑** | 시스템별(`dbm-typemap-<코드>`) | 논리 타입 한 행 = **길이 범위 → 물리 타입 규칙 1개 이상** |

- 행 수를 고정하지 않는다. 논리 타입 목록이 매핑 표의 행이 된다.
- 도메인 폼의 논리 타입 목록, 모델의 도메인 → 물리 타입, DDL 생성이 **모두 이 두 층에서 값을 읽는다**(`DOMT` 하드코딩 제거).

## 2. 누가 무엇을 하나
| 할 일 | 모델러 | DA | Admin | 권한 `id` |
|---|---|---|---|---|
| 표준 논리 타입 추가 · 수정 · 사용 중지 | — | ✔ | ✔ | `type.std` |
| 추가 타입 · 축약명 등록(공통 / 시스템 전용) | — | ✔ | ✔ | `type.add` |
| 시스템 매핑 표 수정 | — | 담당 시스템 | ✔ | `type.map` |
| 추가 타입 요청 | ✔ (담당 시스템) | — | — | `type.request` |
| 속성에 타입 고르기 | ✔ | ✔ | ✔ | 모델 편집 권한 |

- **결재는 거치지 않는다.** DA · Admin이 바로 바꾼다. 대신 다음 세 가지를 둔다.
  - **영향 확인 창**(검수 기준 저장과 같은 꼴): 이 타입을 쓰는 도메인 n · 속성 n, 바뀌는 시스템 매핑 n, 정책 버전 v3 → v4를 보여 주고 [확인하고 저장] · [취소].
  - **감사 로그**: 누가 · 무엇을 · 전 → 후 · 이유.
  - **변경 이력 · [되돌리기]**.
- 모델러는 직접 등록하지 못한다. 맞는 타입이 없으면 **[타입 추가 요청]**을 보낸다(마이페이지 요청 창, ‘담당 시스템 추가 요청’과 같은 꼴). 요청 항목: 필요한 물리 타입 · 쓰려는 곳(시스템 · 속성) · 이유. 요청은 `type.add` 권한자에게 알림이 가고, 등록되면 요청이 닫히며 요청자에게 알림이 간다.

## 3. 축약명 규칙
| 구분 | 형식 | 예 |
|---|---|---|
| **표준** | 영문 대문자 **1자** | C · V · N · D · T · L · B |
| **추가 · DBMS 전용** | 영문 대문자 **2~3자** | `JS`(JSON) · `GM`(공간) · `XML` |

- 두 이름 공간이 길이로 갈리므로 추가 축약명이 표준과 겹칠 일이 없다.
- 숫자는 쓸 수 없다. 도메인 이름이 ‘형식단어 + 축약명 + 길이’(`연월일C8`, `내용JS`)라서 길이 숫자와 섞이면 안 된다.
- **기관 전체에서 하나.** 시스템 전용이라도 다른 시스템에 같은 축약명이 있으면 막고 [기존 타입 쓰기]를 제안한다. 같은 물리 타입을 가진 타입이 이미 있어도 알린다.
- **사용 중인 축약명은 바꾸지 않는다**(표준 · 추가 모두). 바꾸려면 **[새 축약명으로 옮기기]**만 쓴다.
  1. 새 축약명으로 타입을 만든다(나머지 정의 · 시스템 매핑은 복사).
  2. 이 타입을 쓰는 도메인 이름을 미리 보여 주고 한꺼번에 바꾼다(예: `일시T` → `일시TS`). 도메인 이름 변경은 사전 변경 이력에 남는다.
  3. 도메인을 쓰는 속성은 도메인을 따라가므로 따로 고치지 않는다. 직접 타입을 고른 속성은 새 타입으로 다시 잇는다.
  4. 이전 타입은 사용 중지(사유 자동: ‘새 축약명 ○○로 옮김’).
- 사용처가 없는 축약명은 이름을 고칠 수 있다.
- 삭제는 없고 사용 중지만 있다. 사용처가 있으면 사용 중지도 막고 사용처 목록을 보여 준다.
- **추가 타입 → 표준으로 올리기**: DA · Admin이 [표준으로 올리기]를 누르면 1자 축약명을 정하고 위 ‘새 축약명으로 옮기기’ 흐름을 탄다. 시스템 전용이었다면 기관 공통이 된다.

## 4. 타입 종류별 규칙
### 4-1. 표준 논리 타입 (기본 7개)
| 축약 | 이름 | 인자 | Oracle · Tibero | PostgreSQL | MySQL |
|---|---|---|---|---|---|
| C | 문자(고정) | n | `CHAR(n)` | `CHAR(n)` | `CHAR(n)` |
| V | 문자(가변) | n | `VARCHAR2(n)` · 4000 초과 `CLOB` | `VARCHAR(n)` | `VARCHAR(n)` · 16383 초과 `LONGTEXT` |
| N | 숫자 | p,s | `NUMBER(p,s)` | `NUMERIC(p,s)` | `DECIMAL(p,s)` |
| D | 날짜시각(DATE) | 없음 | `DATE` | `TIMESTAMP(0)` | `DATETIME` |
| T | 일시 | n(초 아래 자릿수) | §4-2 | §4-2 | §4-2 |
| L | 대용량 문자 | 없음 | `CLOB` | `TEXT` | `LONGTEXT` |
| B | 이진 대용량 | 없음 | `BLOB` | `BYTEA` | `LONGBLOB` |

- `D`는 **공통표준의 DATE형**이다. 사전 데이터의 `연월일시분초D` 도메인을 용어 855개가 쓴다. 연월일 8자리는 `C`(`연월일C8`)로 쓴다.
- 그래서 `T`의 자릿수 0과 `D`는 Oracle에서 둘 다 `DATE`가 된다. `D`는 공통표준 호환용, `T`는 초 아래 자릿수가 필요한 기관 도메인용으로 둔다.

### 4-2. T 일시 — 하나의 타입, 길이 범위 규칙
- 일시의 ‘길이’ = **초 아래 자릿수(0~9)**. `T`와 `TIMESTAMP`를 나누지 않는다.

| T 자릿수 | Oracle · Tibero | PostgreSQL | MySQL |
|---|---|---|---|
| 0 | `DATE` | `TIMESTAMP(0)` | `DATETIME` |
| 1~9 | `TIMESTAMP(n)` | `TIMESTAMP(n)` (최대 6) | `DATETIME(n)` (최대 6) |

- 도메인 이름: 자릿수 0이면 `일시T`, 1 이상이면 `일시T3`.
- DBMS 상한(6)을 넘는 값은 매핑 표에서 ‘상한으로 줄임’ 경고를 띄운다.

### 4-3. 길이 범위 규칙 (모든 타입 공통 틀)
- 매핑 표의 한 행에 **[범위 → 물리 타입]** 규칙을 여러 개 둔다. 예: V `1~4000 → VARCHAR2(n)` · `4001~ → CLOB`.
- 저장할 때 검사한다: 범위 겹침 · 빈 구간 · 인자 형태 불일치 → 저장 막음.
- 비고 칸은 설명만 남긴다. 조건은 규칙으로만 동작한다.
- 다른 시스템으로 옮기거나 복제할 때(25 §8)도 이 규칙으로 바꾼다.

### 4-4. DBMS 전용 타입 (허용)
- 추가 타입 등록 때 **‘DBMS 전용’**을 고르면 대상 DBMS를 지정한다(예: PostgreSQL `JSONB`, Oracle `XMLTYPE`).
- 매핑 표에는 그 DBMS를 쓰는 시스템에만 행이 생긴다.
- 속성 목록 · 검수 보고서에 ‘DBMS 전용’ 배지를 단다. DDL 전 점검(게이트 B)은 **경고만** 한다.
- 다른 DBMS 시스템으로 옮기거나 복제하면 미리 보기에 **‘변환 불가 n개’**를 따로 보여 준다. 행마다 [대상 타입 고르기] 또는 [대용량 문자(L)로 · 경고 남김] 중 하나를 골라야 진행된다.

### 4-5. 추가 타입 (시스템 전용 · 기관 공통)
- 등록 항목: 이름 · 축약명(2~3자) · 인자 형태 · 적용 범위(공통 / 시스템) · 시스템별 물리 타입 · 설명 · 이유.
- 공통으로 등록하면 모든 시스템의 매핑 표에 행이 생긴다. DBMS 기본값이 없으면 빈 칸 + ‘매핑 없음’ 경고를 띄운다.
- 매핑이 빈 타입을 쓰는 속성은 DDL 전 점검에서 **막는다**.
- 시스템 전용 추가 타입을 쓰는 도메인은 **같은 시스템 전용 도메인**으로만 신청할 수 있다.

## 5. 모델링 중 화면
- 속성 타입 칸 목록: 표준 도메인 → 이 시스템에서 쓸 수 있는 추가 · DBMS 전용 타입 순서. 추가 타입에는 ‘추가’ · ‘DBMS 전용’ 배지를 단다.
- 추가 · DBMS 전용 타입을 고른 속성은 **‘표준 외 타입’**으로 표시한다. 위반은 아니고 검수 보고서에서 따로 집계한다.
- 맞는 타입이 없으면 목록 끝 **[타입 추가 요청]** → 요청 창(물리 타입 · 이유가 미리 채워짐). 요청하는 동안 속성은 직접 입력 + 예외 처리(`ex` + 이유)로 둘 수 있다. 등록되면 알림에서 [이 타입으로 바꾸기]를 누른다.
- DA · Admin은 같은 자리에서 **[타입 등록]**을 바로 연다. 저장하면 그 속성에 그 타입이 골라진 상태가 된다.

## 7. 목업 반영 범위 (다음 단계)
- `assets/app.js`: 논리 타입 목록 저장소(`dbm-types`) · 행 수 고정 해제 · 길이 범위 규칙 · `convertTypeByMap`이 규칙과 DBMS 전용을 처리.
