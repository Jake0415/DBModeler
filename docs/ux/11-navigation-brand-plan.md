# 메뉴 재설계·브랜드(NeoDB) 수정 플랜

> 2026-11-19 · 상태: **플랜(적용 전)**
> 사용자 요청
> - 홈 메뉴를 없애고, 로고를 누르면 홈으로 간다.
> - 제품명을 **NeoDB**로 바꾸고 BI를 새로 만든다.
> - 통합 검색(사전)·결재·설정·감사 로그는 **상단 메뉴**로 옮긴다.
> - **왼쪽은 가장 많이 쓰는 모델 설계에 집중**한다.

## 1. 지금 구조와 문제
| 영역 | 지금 | 문제 |
|---|---|---|
| 왼쪽 메뉴(224px) | 홈 / 사전(통합 검색·엑셀·후보 큐) / 결재 / 시스템 트리 / 관리 / 버전 | 모델 트리가 화면 중간에 끼어 있고, 업무 영역은 들여쓴 글자 두 줄뿐이다. 모델러가 쓰는 표준 맞추기·DDL·산출물은 메뉴에 없다 |
| 상단 바 | 로고 · 전역 검색 · (목업 도구) · 알림 · 사용자 | 상단은 검색만 하고, 화면 이동은 모두 왼쪽에서 한다 |
| 제품명 | DBModeler (화면 32곳, 문서 7곳) | 새 이름 NeoDB로 바꿔야 한다 |

### 2.1 상단 메뉴 (전역 이동)
| 메뉴 | 형태 | 내용 | 보이는 역할 |
|---|---|---|---|
| **모델** | 링크 (활성 표시) | 시스템 홈(system.html)으로 이동한다. 모델 계열 화면에서는 이 탭이 켜진다 | 모두 |
| **사전** ▾ | 드롭다운 | 통합 검색 · 엑셀 가져오기 · 업로드 이력 · 후보 큐 `2` · 변경 내역 | 모두 |
| **결재함** `6` | 링크 + 건수 | approvals.html. 숫자는 내 차례 건수이고, 기한을 넘긴 결재가 있으면 빨간 점을 붙인다 | 모두 |
| **관리** ▾ | 드롭다운 | 설정(Admin) · 감사 로그(DA·Admin) | DA·Admin만 |
| 검색 | 상단 오른쪽 입력 | 지금의 Ctrl K 전체 검색을 그대로 쓴다 | 모두 |

- 활성 탭은 Vercel 하위 메뉴처럼 회색 알약(gray-100)으로 표시한다. 드롭다운은 공통 메뉴 규격(반경 12, 36px 항목)을 쓴다.
- 홈 메뉴는 없앤다. **로고(NeoDB)를 누르면 홈**으로 간다. 로고에 `aria-label="NeoDB 홈"`을 붙인다.

### 2.2 왼쪽 = 모델 트리 (모델 설계 집중)
| 요소 | 내용 |
|---|---|
| 시스템 선택 | 맨 위 선택 상자에 요구사항관리·인사시스템·회계시스템과 DBMS를 보인다. 바꾸면 그 시스템의 업무 영역 목록이 나온다 |
| 찾기 | 업무 영역·엔터티 이름으로 트리 안에서 거른다 |
| 업무 영역 목록 | 영역마다 이름과 상태 배지(작업 중 vN · 검토 · 확정)를 보인다. **지금 연 영역은 펼쳐서** 모델 · 표준 맞추기(미준수 수) · DDL · 산출물 링크를 보인다. ＋는 새 업무 영역이다 |
| 시스템 도구 | 시스템 전체 ERD · DDL 가져오기 |
| 최근 연 엔터티 | 마지막으로 연 엔터티 3개(바로 가기) |
| 접기 | 240px ↔ 56px 아이콘 열. 접힘 상태는 기억한다 |

- **보이는 화면**: 홈, 시스템 홈, 모델, 표준 맞추기, DDL, 산출물, 가져오기 같은 모델 계열 화면에 보인다.
- **숨기는 화면**: 상단 메뉴 화면(사전·결재함·설정·감사 로그·마이페이지)에서는 왼쪽 트리를 숨기고 본문을 전체 폭으로 쓴다. Vercel처럼 영역마다 레이아웃이 다른 방식이다. 결정 #2에서 정한다.
- 버전·빌드 표시는 왼쪽 아래에서 사용자 메뉴의 "제품 정보"로 옮긴다.

### 2.3 목업 도구 정리
- 지금 상단 바 오른쪽에 있는 목업 도구(역할 전환·화면 크기·테마·초기화·화면 정보·지도)는 실제 제품에 없는 것이라, 상단 바를 실제 제품처럼 보이지 않게 만든다.
- 화면 오른쪽 아래의 **떠 있는 "목업" 버튼**(팝오버)으로 옮긴다. 기능은 그대로다.

## 3. 브랜드 — NeoDB
### 3.1 이름 바꾸기 범위
- **화면**: 상단 로고, 각 페이지 `<title>`(`· NeoDB`), 제품 정보 창, 로그인 화면, 오류 화면, 견본, 목업 지도, 토스트·안내 문구.
- **데이터**: `PRODUCT.name = 'NeoDB'`.
- **문서**: UX 문서(01·06·08·09·10)에서 제품을 가리키는 이름을 NeoDB로 바꾼다. 저장소와 폴더 이름(DBModeler)은 그대로 둔다.

### 3.2 BI 안 (견본에 나란히 두고 고른다)
| 안 | 마크 | 글자 로고 | 성격 |
|---|---|---|---|
| **A. 연결된 N (권장)** | 반경 6px 잉크 사각형 안에, 노드 두 개를 관계선으로 이은 N자 선 그림(ERD의 엔터티-관계 모양) | `NeoDB` · Geist 600 · −0.3px | 모델링 도구임을 바로 보여 준다. 단색이라 다크·인쇄·파비콘에 강하다 |
| B. 층 쌓인 원통 + N | DB 원통 세 겹 위에 작은 N | `NeoDB` · `DB`만 gray-900 | 데이터베이스 도구 인상이 강하다. 흔한 DB 아이콘과 비슷해질 위험이 있다 |
| C. 글자 마크 | `N` 한 글자를 고정폭(Geist Mono)으로 | `neodb` 소문자 | 가장 단순하다. 개성이 약하다 |

- **공통 규칙**: 색은 잉크(`gray-1000`)와 흰색만 쓴다(Geist 원칙: 브랜드 색 없이 단색). 마크는 16/20/32px로 만들고, 파비콘(SVG)도 함께 만든다.
- **크기**: 상단 바의 로고는 마크 20px + 글자 15px/600이다. 기관명은 구분선 뒤 회색 14px로 둔다.

## 5. 진행 순서
1. **BI 3안 견본**: 마크 SVG와 견본 페이지 비교 → 사용자 선택.
2. **상단 바**: 로고(홈 링크), 상단 메뉴 4개, 드롭다운, 결재 건수, 검색, 알림, 사용자. 목업 도구는 떠 있는 버튼으로 옮긴다.
3. **왼쪽 모델 트리**: 시스템 선택, 찾기, 업무 영역 펼침과 하위 링크, 시스템 도구, 최근 엔터티, 접기.
4. **화면별 레이아웃**: 상단 메뉴 화면은 전체 폭, 모델 계열 화면은 트리 + 본문. 활성 탭과 활성 트리 항목을 표시한다.
5. **제품명 일괄 변경**: 화면, 데이터, 문서.
6. **검증**: 전 화면을 역할별로 열어 오류와 넘침이 없는지 본다. 키보드(Tab 순서·드롭다운 Esc·접기)와 1600px 폭을 확인한다.
7. **Codex·Claude 교차 검토** 뒤 수정, 기록, 커밋.

## 6. 결정 필요
1. **BI**: A 연결된 N(권장) / B 원통 + N / C 글자 마크. 1단계 견본을 보고 정해도 된다.
2. **상단 메뉴 화면의 왼쪽 트리**: 숨기고 전체 폭(권장) / 늘 보이게.
3. **관리 메뉴**: 드롭다운 하나(권장, 상단을 짧게 유지) / 설정·감사 로그를 따로 상단에 노출.
4. **홈 화면의 왼쪽 트리**: 보이게(권장, 모델러의 첫 화면) / 숨기기.
