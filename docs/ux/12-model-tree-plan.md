## 1. 지금 트리의 한계
지금 트리(11 §2.2)는 **화면 이동 메뉴**다. 업무 영역 아래에는 모델 · 표준 맞추기 · DDL · 산출물 같은 화면 이름만 있다. 그래서 다음이 안 된다.
- 엔터티·관계·테이블을 트리에서 보거나 고를 수 없다.
- 객체에 대한 작업(이름 바꾸기, 정의, 배치·참조, 표준 확인)을 트리에서 시작할 수 없다.
- DA# 사용자가 익숙한 **모델 관리 브라우저**(주제영역 목록 + 객체 목록)와 모양이 다르다.

## 3. NeoDB 개념과 맞추기
### 3.1 단위
| DA# | NeoDB | 범위 |
|---|---|---|
| 프로젝트 | **시스템** | 대상 DB 하나. DBMS·명명 기준과 업무 영역 목록의 범위다. 트리 맨 위의 시스템 선택으로 바꾼다 |
| 모델 폴더 · 모델 | (없앰) | 시스템 하나 = 모델 하나. DBMS가 하나라 **물리모델도 하나**다. DA#의 "물리모델 추가"는 두지 않는다 |
| 주제영역 | **업무 영역** | 모델링·**버전·결재**의 범위다. 확정은 업무 영역 단위로 한다 |
| 한 주제영역의 여러 다이어그램 | 업무 영역 안의 **보기** | 같은 영역 객체의 **배치와 표시 범위**만 저장한다. 기본은 "전체" 보기다. 영역의 버전·결재를 따른다 |
| 다른 주제영역의 엔터티를 보여 주기 | **참조** | 다른 영역 원본을 가리키는 읽기 전용 표시다(§3.2) |

### 3.2 배치와 참조 (두 용어를 고정한다)
| | **배치** | **참조** |
|---|---|---|
| 무엇 | 같은 영역의 객체를 **다른 보기에도 그린다** | **다른 영역**의 엔터티를 이 영역 캔버스에 읽기 전용으로 보인다 |
| 데이터 | 객체는 하나, 위치만 보기마다 따로 둔다 | 이 영역에 "참조" 줄 하나(원본 영역·엔터티·원본 버전) |
| 가리키는 버전 | — | 원본 영역의 **최신 확정본**. 원본이 새로 확정되면 참조 줄에 "원본 v6 확정 · 갱신" 표시가 뜨고, 사용자가 갱신한다. 원본이 아직 확정본이 없으면 참조할 수 없다 |
| 편집 | 어느 보기에서 고쳐도 같은 객체가 바뀐다 | 편집 불가. 메뉴의 [원본 열기]로 원본 영역에 간다 |
| 개수·준수율 | 한 번만 센다 | **세지 않는다**(지금 `compOf`의 `e.ref` 제외와 같다) |
| 관계 | 그대로 | 참조 엔터티와 이 영역 엔터티 사이의 관계는 이 영역 소유다. 참조를 해제하면 그 관계도 지워지므로 영향 확인을 거친다 |
| 결재 | 보기 배치는 확정 대상에 들어가지만, 비교 표에서 "배치만 바뀜"으로 따로 묶는다 | 참조 추가·해제·갱신은 확정 대상이다 |
| 잠김 | 이 영역이 검토 중·확정이면 할 수 없다 | 이 영역이 검토 중·확정이면 할 수 없다. 원본 잠김과는 상관없다 |
| 하는 방법 | 트리의 이 영역 엔터티를 **지금 캔버스**(다른 보기)에 끌어 놓기, 또는 메뉴 [보기에 배치…] | 트리에서 **다른 영역**의 엔터티를 지금 캔버스에 끌어 놓기, 또는 메뉴 [이 영역에 참조 추가] |

- 끌어 놓기는 **지금 열린 캔버스에만** 한다. 다른 영역 캔버스로 끌어 놓는 일은 없다.

## 4. 새 트리 구조
트리는 **캔버스가 연 것과 같은 시스템·영역·버전**을 보인다. 확정본이나 이력 스냅숏을 열면 트리도 그 버전의 객체와 상태를 보인다. 위에는 "v4 확정본 · 조회 전용" 줄이 뜬다.

```
┌ 왼쪽 칸 (모델 계열: 내용에 맞춰 넓힘 · 끌어서 조절 · 접으면 56px) ┐
│ [ 모델 | 사전 ]                    ← 탭 (사전 = 지금 PN-32) │
│ [요구사항관리 · Oracle 19c                         ▾]       │
│ [ 찾기: 엔터티·테이블·용어 ]                [거르기 ▾]      │
│ ─────────────────────────────────────────────────────────── │
│ 업무 영역 2                                             ＋  │
│ ▾ 요구사항 · 프로젝트                            v5 작업 중  │
│     모델 · 표준 맞추기 5 · DDL · 산출물   ← 바로가기 한 줄   │
│   ▸ 보기 2                                                  │
│   ▾ 엔터티 7                                                │
│       ● 프로젝트기본                                        │
│       ◐ 산출물기본                                   2      │
│         ▾ 속성 5                                            │
│             산출물ID                         PK            │
│             산출물제출일                     조합 가능      │
│             요구사항ID                       FK            │
│       ↗ 공통코드기본                          참조 · 공통   │
│   ▸ 관계 6                                                  │
│   ▸ 서브타입 1                                              │
│   ▸ 사용한 표준 · 용어 23 · 도메인 9                         │
│ ▸ 리스크                                            검토    │
│ ─────────────────────────────────────────────────────────── │
│ 시스템 전체 ERD · DDL 가져오기 · 최근 연 엔터티               │
│                                                   《 접기  │
└─────────────────────────────────────────────────────────────┘
물리 보기로 바꾸면 엔터티·관계·서브타입 자리에 테이블 · 관계 · 제약조건 · 인덱스가 온다.
```

- **깊이는 4단계**다: 업무 영역 › 폴더 › 객체 › 속성(결정 #2). 엔터티를 펼치면 속성이 보이고, 물리 모드에서는 테이블을 펼치면 컬럼이 보인다. 속성·컬럼은 펼칠 때 불러온다. 엔터티는 기본으로 접혀 있고, 찾기 결과나 캔버스에서 속성을 고르면 그 경로가 펼쳐진다.
- **논리/물리 전환을 따른다**: 캔버스가 논리면 논리 객체, 물리면 물리 객체를 보인다. 이렇게 하면 들여쓰기 단계가 하나 줄고 폴더 수도 줄어든다.
- **바로가기 줄**: 모델 · 표준 맞추기(미준수 수) · DDL · 산출물은 영역을 펼치면 바로 보이는 한 줄이다. 접힌 폴더 안에 숨기지 않는다.

### 4.1 노드 종류와 표시
| 노드 | 줄에 보이는 것 | 펼치면 |
|---|---|---|
| 업무 영역 | 이름 · 상태 배지 1개(작업 중 vN · 검토 · 확정) | 바로가기 줄 · 보기 · 객체 폴더 · 사용한 표준 |
| 보기 | 이름. 지금 연 보기는 선택 표시 | — 누르면 그 보기를 연다 |
| 폴더 | 이름 · 개수(회색) | 객체 목록. 이름순·분류순·미준수순 정렬 |
| 엔터티 | 표준 상태 점 · 논리명 · 미준수 수. 물리명은 툴팁 | 속성 |
| 속성 | 이름 · PK/FK · 표준 상태(준수면 표시 없음, 조합 가능 · 미등록 · 예외는 글자로). 물리명·타입은 툴팁 | — |
| 참조 엔터티 | ↗ · 이름 · "참조 · 원본 영역". 원본이 새로 확정됐으면 "갱신" 점 | — |
| 관계(논리) | 부모 → 자식 · 관계명 | — |
| 테이블 | 물리명. **지금 물리 보기에 배치되지 않은 테이블은 회색**(DA# 계승) | 컬럼(물리명 · 타입 · PK/FK) |
| 관계(물리) | 부모 테이블 → 자식 테이블. FK 상태(반영 · 제외 · 누락) | — |
| 제약조건 | PK · FK · UK 묶음과 개수. **누락 FK가 있으면 경고 점** | 이름 목록 |
| 인덱스 | 이름 · 대상 테이블 | — |
| 사용한 표준 | 용어 · 도메인 개수. 미등록 단어가 있으면 "후보 n" | 용어 / 도메인 목록 |

- 상태는 색에만 기대지 않는다. 점 모양을 다르게 하고(● 준수 · ◐ 미준수 있음 · ◆ 예외), 툴팁과 낭독기 이름에 "미준수 2"처럼 글자로 넣는다.
- 한 줄에 배지는 하나만 둔다. 개수는 회색 숫자로 둔다.
- **FK 상태는 DDL과 같은 계산**을 쓴다. 관계마다 FK를 만들 수 있는지 판정하는 함수 하나를 트리 · DDL · 게이트 A가 함께 쓴다. 상태는 셋이다.
  - 반영: 관계가 있고 FK 제약조건이 만들어졌다.
  - 제외: 사유를 남기고 FK를 만들지 않았다(예: 이력 테이블).
  - 누락: 관계는 있는데 FK 컬럼이나 제약조건이 없다(F-38).
  - 복합 FK는 하나로 센다. M:N 관계는 해소 전이라 "해소 필요"로 따로 보인다.

### 4.2 누르기 규칙 (모든 화면 같음)
| 입력 | 결과 |
|---|---|
| **▸ 표시 누르기** | 펼치기/접기만 한다 |
| **줄 누르기 · Enter** | 그 객체를 **선택**한다. 모델 화면에서는 캔버스 선택과 오른쪽 패널이 바뀐다. **속성·컬럼 줄은 그 엔터티·테이블을 선택하고 오른쪽 패널의 해당 행을 강조**한다. 다른 화면에서는 §5대로 한다. 폴더·영역 줄은 펼치기/접기 |
| **두 번 누르기** | 그 객체로 **위치 맞춤**(확대·이동). 메뉴의 [위치 맞춤]과 같다. 이름 바꾸기는 F2나 메뉴로만 한다(캔버스의 두 번 누르기 = 이름 수정과 겹치지 않게) |
| **용어 두 번 누르기** | 사용한 엔터티 강조(DA# M-C06) |
| **끌어 놓기** | §3.2 배치·참조. 용어는 사전 탭에서 끌어 놓는다(03 §8) |

- **캔버스 → 트리 따라가기**: 캔버스에서 고르면 트리의 그 줄을 선택 표시하고, 보이지 않을 때만 스크롤한다. 닫힌 폴더는 필요한 경로만 펼친다. **포커스는 옮기지 않는다**(트리가 출렁이거나 키보드 위치를 빼앗지 않게).
- 지금 보기에 없는 객체를 고르면 "이 보기에 없음 · [배치] [전체 보기에서 열기]"를 안내한다.
- 바꾸는 명령(메뉴 · F2 · Delete · 끌어 놓기)은 **실행할 때** 역할·잠금·버전을 다시 확인한다. 검토 중·확정·조회 전용이면 항목은 비활성이고 이유를 툴팁으로 단다.
- 모델 화면의 전역 키(Delete · Enter · V/E/R/M)는 **포커스가 트리 안이면 캔버스로 보내지 않는다**.

### 4.3 우클릭 · ⋯ 메뉴
| 노드 | 메뉴 | DA# 대응 |
|---|---|---|
| 업무 영역 | 열기 · 이름 바꾸기 · 정의 · 보기 추가 · 영역 복제 · 내보내기(DDL · 정의서) · 버전·결재 이력 · 확정 신청(작업 중이고 모델러일 때) · 객체 정보 | M-C04·C05. DA#의 "모델로 내보내기"(다른 모델 파일 만들기)는 결과물이 달라 영역 복제로 대신한다 |
| 업무 영역 폴더 | 새 업무 영역 · 이름순 정렬 | DG-02 |

### 4.4 찾기·거르기
- 찾기: 엔터티 · 속성 · 테이블 · 컬럼 · 용어의 논리명·물리명을 찾는다. 2글자 이하는 앞부분 일치(23 §6-1)로 찾는다. 결과는 맞는 객체 줄까지 펼쳐서 강조하고, 결과 수를 낭독기에 알린다. 속성·컬럼이 맞으면 그 엔터티·테이블 줄에 "속성: 산출물제출일"을 덧붙인다.
- 거르기: 미준수만 · 예외만 · 지금 보기에 있는 것만(M-B01 "다이어그램 객체") · 분류(K · M · A · H) · 참조 숨기기.
- 거르는 중에는 트리 위에 "미준수만 · 12개 · 지우기" 줄을 둔다.
- DA#의 조건 검색·태그 관리는 이번 범위 밖이다(§7.3).

### 4.5 키보드·접근성 (WAI-ARIA Tree View)
- 트리에는 `role="tree"`와 이름("모델 트리 · 요구사항 · 프로젝트 v5")을 준다.
  - `aria-expanded`: 자식이 있는 줄에만 둔다.
  - `aria-selected`: 선택할 수 있는 객체 줄에만 둔다.
  - 보이는 줄만 그리므로 `aria-level` · `aria-posinset` · `aria-setsize`를 모두 적는다.
- Tab 정지점은 트리 전체에서 하나다(roving tabindex). 줄 안의 ⋯ 버튼은 `tabindex=-1`이다. 메뉴는 Shift+F10 · 메뉴 키로 열고, 닫으면 그 줄로 돌아간다.
- 키 동작
  - ↑↓: 줄 이동
  - →: 펼치기 / 첫 자식으로 이동
  - ←: 접기 / 부모로 이동
  - Home · End: 맨 위 · 맨 아래
  - 글자 입력: 그 글자로 시작하는 줄로 이동
  - Enter: 선택
  - F2: 이름 바꾸기
  - Delete: 객체 삭제(확인)
  - `*`: 형제 모두 펼치기
- 거르기·삭제·접기 뒤에 포커스 줄이 사라지면 가장 가까운 보이는 줄로 옮긴다. 스크롤로 포커스 줄이 화면 밖에 가도 포커스는 유지하고, 키를 누르면 그 줄로 되돌아온다.
- 펼침 상태, 선택한 줄, 스크롤 위치는 **시스템 · 영역 · 버전**마다 기억한다.

### 4.6 폭·성능 — 왼쪽은 한 칸
- 모델 계열 화면의 왼쪽은 **[모델 | 사전] 탭 한 칸**이다. 지금 모델 화면의 사전 패널(PN-32)이 트리와 나란히 서면 왼쪽이 두 칸이 되어, 1600px에서 캔버스가 03 기준(760px)보다 좁아진다.
  - 사전 탭은 지금 사전 패널 기능을 그대로 쓴다(검색 · 용어 끌어 놓기 · 속성 추가).
  - 캔버스에서 속성 용어를 고치면 사전 탭이 자동으로 열린다. 모델 탭으로는 Alt+1, 사전 탭으로는 Alt+2로 바꾼다.
- **폭은 내용에 맞춘다(결정 #4)**: 속성까지 펼치면 들여쓰기와 이름이 길어지므로, 트리가 필요한 만큼 넓어진다.
  - 처음 폭: 펼친 줄 중 가장 긴 줄이 잘리지 않는 폭(최소 240px).
  - 펼치거나 찾기로 긴 줄이 보이면 그만큼 넓힌다. 줄여서 잘리게 하지는 않고, 사용자가 줄인 폭은 그대로 둔다.
  - 손잡이를 끌어 넓히거나 줄일 수 있다. ←→ 키로도 조절하고, 현재 폭을 알려 준다.
  - 손잡이를 두 번 누르면 **내용에 맞춤**: 지금 보이는 줄에 꼭 맞는 폭으로 바꾼다.
  - 상한: 캔버스가 760px 아래로 줄지 않는 폭(1600px, 오른쪽 패널 380px이면 약 460px). 상한에 닿으면 긴 이름은 말줄임 + 툴팁.
  - 폭은 사용자마다 기억한다. 공간이 모자라면 왼쪽 칸이 먼저 접힌다.
- 1600~1919px 모델 화면은 사용자가 고른 적이 없으면 왼쪽 칸을 접은 채 시작한다(11 §7.2).
- 홈·시스템 홈은 240px 고정이다(사전 탭 없음).
- 목표: 영역 하나에 엔터티 300 · 관계 500(23 §6).
  - 트리는 보이는 줄만 그린다.
  - 300개 성능은 목업 시드가 아니라 **성능 측정 스파이크**에서 확인한다.

| 트리 | 업무 영역 › 바로가기(모델 · 표준 맞추기 n · DDL · 산출물) · 보기 · 엔터티(› 속성) · 관계 · 서브타입 · 사용한 표준(용어 · 도메인 · 후보 n) 순서다.<br>• 물리 모드에서는 테이블(› 컬럼) · 관계(FK 반영 · 제외 · 누락 · 해소 필요) · 제약조건 · 인덱스로 바뀐다.<br>• 엔터티 줄에는 상태 점(● 준수 · ◐ 미준수 · ◆ 예외)과 낭독기 이름이 붙는다.<br>• 참조 엔터티는 펼치지 않는다.<br>• 닫힌 엔터티는 속성을 만들지 않는다. |

| 찾기 · 거르기 | 찾기: 엔터티 · 속성 · 테이블 · 컬럼 · 용어를 찾고, 맞는 경로를 펼쳐 표시한다. 물리명으로 맞은 속성은 부모 줄에 "속성 n"을 보인다. 결과 수(용어 포함)를 낭독기에 알린다.<br>거르기: 미준수 · 예외 · 참조 숨기기 · 분류. 거르기 메뉴는 고를 때 닫히지 않는다. 거르는 중에는 지우기 줄이 뜬다. |

| 폭 | 모델 계열 화면은 내용에 맞춰 넓어진다. 손잡이를 끌거나 ←→로 조절하고, 두 번 누르면 내용에 맞춘다.<br>캔버스 760px을 지키도록 창 크기가 바뀌면 다시 계산한다. 240px도 들어가지 않으면 트리를 접는다.<br>1600 프레임이나 창에서는 모델 화면이 접힌 채 시작한다. 홈 · 시스템 홈은 240px 고정이다. |
| 표 보기 | 표 보기 중에 트리에서 골라도 표 보기를 닫지 않는다 |

### 9.3 T3 보기 · 배치 · 참조 · FK (2026-11-20, FE 목업)
> 목업 화면 동작만 만든다. 실제 구현은 전체 설계와 퍼블리싱을 맞춘 뒤 사용자 확인을 받고 시작한다.

| 영역 | 적용 |
|---|---|
| 보기 데이터 | 보기 목록(`V`)을 업무 영역의 모델 데이터(엔터티 · 관계와 같은 저장본)에 넣었다. 그래서 버전 · 결재 제출본 · 실행 취소를 그대로 따른다. 보기마다 다음을 둔다.<br>• `ents`: 배치한 엔터티<br>• `pos`: 보기별 위치(논리 · 물리)<br>• `hide`: 숨긴 관계선<br>"전체" 보기는 모든 엔터티를 엔터티 자체 위치로 보인다. 시드 보기는 처음 저장할 때 데이터로 옮겨진다 |
| 보기 전환 | 캔버스 도구 막대의 [보기] 선택, 트리의 보기 줄 누르기 · [열기]로 바꾼다. 마지막 보기는 영역별로 기억하고, `?view=`로도 연다.<br>빈 보기에는 "트리에서 끌어 놓으세요" 안내가 뜬다.<br>트리는 보는 중인 보기를 표시하고, 그 보기에 없는 엔터티를 회색으로 보인다(낭독: "이 보기에 없음").<br>보기에 없는 엔터티를 트리에서 고르면 패널은 열고 "이 보기에 없음 · [전체 보기에서 열기]"를 알린다 |
| 보기 관리 | 새 보기 · 이름 바꾸기 · 복제 · 삭제(확인). 이름은 겹치지 않게 한다. 전체 보기는 이름을 바꾸거나 지울 수 없다. 새 보기는 선택한 엔터티 하나로 시작하고, 복제는 배치 · 위치 · 숨긴 선을 복사한다. 보기를 지워도 엔터티는 남는다 |
| 배치 | 트리의 엔터티 줄을 캔버스로 끌어 놓으면 지금 보기에 그 자리로 배치된다(전체 보기에서는 안내만 한다).<br>[보기에 배치…]는 보기별 체크로 고른다. [보기에서 빼기]는 지금 보기에서만 뺀다.<br>보기에서 새로 만든 엔터티 · M:N 교차 엔터티는 그 보기에도 배치된다. 엔터티를 지우면 모든 보기의 배치도 지운다 |
| 참조 | 다른 업무 영역의 엔터티를 끌어 놓거나 메뉴 [지금 영역에 참조 추가]를 쓰면, 원본의 **최신 확정본**에서 PK · 이름 속성을 읽기 전용으로 가져온다.<br>막는 경우: 원본에 확정본이 없음, 그 엔터티가 확정본에 없음, 다른 시스템, 이미 참조함, 지금 영역이 조회 전용.<br>캔버스 꼬리표 · 트리 · 패널에 "원본 영역 vN 확정본"을 보이고, 원본에 새 확정본이 나오면 "갱신"을 표시한다.<br>[갱신]은 새 확정본으로 바꾸고, PK가 바뀌어 자식 FK가 누락되면 알린다.<br>[참조 해제]는 캔버스와 같은 영향 확인(관계 · 자식 FK)을 거친다. [원본 열기]로 원본 영역에 간다.<br>시드: 재무관리의 은행계좌기본 참조가 회계관리 v2를 가리켜 갱신 표시를 시연한다 |
| 관계선 숨기기 | 지금 보기에서만 관계선을 숨기고 다시 보인다. 관계와 FK는 그대로이고, 트리 관계 줄에 "선 숨김"을 표시한다 |
| FK 만들기 | 게이트 A 확인 창에서 추가할 컬럼(같은 이름 컬럼이 있으면 FK로 지정)을 보여 주고 만든다. 이름이 겹치거나 재귀이거나 같은 자식으로 관계가 둘이면 역할명(`ORG_` · `UPR_`)과 관계 그룹으로 만든다. 부모 PK가 없거나 물리명이 없으면 막는다. 만든 뒤 FK 이름 · 컬럼을 알린다 |
| 결재 비교 | 구조 변경 표에 [참조 추가 · 해제 · 갱신]을 따로 보인다. 위치 이동 · 보기 추가/삭제/이름 · 배치/빼기 · 관계선은 "**배치만 바뀜 n건**"(접힘)으로 묶고 "테이블 구조와 DDL에는 영향이 없습니다"라고 단다. 결재함 요약은 "확인할 변경 n건 · 배치만 m"으로 센다 |

- **검증**(재무관리 · 김모델):
  - [차입 · 투자] 보기로 바꿈 → 캔버스 4개, 트리 회색 5개.
  - 입출금내역 끌어 놓기 → 배치.
  - 회계관리의 계정과목기본 끌어 놓기 → v3 확정본 참조(지금 보기에도 배치).
  - 은행계좌기본 [갱신] v2 → v3.
  - 관계선 숨기기.
  - 계정과목 → 차입금 관계 [FK 만들기] → `LOAN_M_ACNT_SBJT_M_FK` 정상.
  - [참조 해제] → 관계 · FK 정리, 보기 배치도 제거.
  - 새 보기 · 이름 중복 막기 · [보기에 배치…] · 보기 삭제.
  - 저장 후 다시 열어 비교: 참조 갱신 1 + 배치만 바뀜 2.
  - 화면 11개 × 역할 4개 오류 0건.
- **남긴 것**:
  - 영역 메뉴의 이름 바꾸기 · 정의 · 내보내기 · 확정 신청 · 객체 정보, 엔터티 [객체 정보].
  - 다른 영역 캔버스로의 끌어 놓기(설계상 하지 않음).
  - 보기별 논리/물리 배치를 따로 정리하는 기능.
  - 트리 속성 노드 키를 이름 기준으로 바꾸기.
  - 이 단계의 교차 검토.

### 9.0 기획 검토 t1 반영
- 두 검토의 높음 지적을 반영했다.
  - 배치와 참조 용어를 고정하고, 참조의 버전·결재·잠김·개수 규칙을 정했다(§3.2).
  - 트리를 열린 버전에 맞췄다(§4).
  - FK 판정을 DDL과 같은 함수로 하게 했다(§4.1).
  - 누르기·두 번 누르기·펼치기 우선순위를 정하고, 역방향 따라가기에서 포커스를 지키게 했다(§4.2).
  - 대상이 다른 명령의 이름을 나눴다(§4.3).
  - 가상화와 ⋯ 버튼의 ARIA 규칙을 정했다(§4.5).
  - 왼쪽을 한 칸으로 합쳐 1600에서 캔버스 760을 지키게 했다(§4.6).
  - 3단계 적용과 선행 작업을 정했다(§7).
- 중간·낮음 지적도 반영했다.
  - 바로가기 줄을 폴더 밖으로 꺼냈다.
  - 화면별 누르기 동작을 통일했다.
  - 전역 키 포커스를 확인하게 했다.
  - 회색 테이블 기준을 "지금 물리 보기에 없음"으로 정했다.
  - 물리 관계 노드를 추가했다.
  - 용어 업데이트를 두 갈래로 나눴다.
  - 도메인 강조는 NeoDB 추가 기능으로 명시했다.
  - 물리모델 추가를 뺀 근거를 적었다.
  - "내가 바꾼 것" 거르기는 범위 밖으로 옮겼다.
  - 확정 신청 조건을 적었다.
- 결정 #2는 두 검토 의견이 갈렸다(Codex: 속성까지, 기본 접힘 / Claude: 엔터티까지만). DA# 근거를 바로잡고, **엔터티까지 + 찾기 결과로 속성까지 가기**를 권장안으로 바꿨다.
