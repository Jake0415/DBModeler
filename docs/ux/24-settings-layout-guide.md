# 24. 설정형 화면 레이아웃 가이드 (v1, 2026-11-24)

> 대상: **설정**(`settings.html`)과 **마이페이지**(`mypage.html`)처럼 “가끔 와서 값을 몇 개 바꾸고, 관련 표를 확인하는” 화면.
> 감사 로그 · 결재함 · 표준 사전 같은 목록 화면과 모델 캔버스는 기존 작업 영역 규칙(01 · 22)을 그대로 따른다.
> 근거: 요청서 [brief-settings-layout](review/brief-settings-layout.md) · Codex [codex-settings-layout](review/codex-settings-layout.md)(SL-01 ~ 06) · UX [claude-settings-layout](review/claude-settings-layout.md)(실측 · G1 ~ G15).
> 상태: **가이드 확정안 — 목업 적용 전.**

## 0. 한 줄 결론
**왼쪽 정렬은 그대로 두고, 본문을 창 폭 전체로 쓴다.** 폼 행은 `라벨 240 │ 입력 최대 760 │ 보조 칸(남는 폭)` 세 칸으로 나누고, 그동안 흩어져 있던 마지막 변경 · 적용 시점 · 영향 범위 · 관련 링크를 오른쪽 보조 칸으로 모은다. 표는 ‘넓은 행’(최대 1200)이나 표 탭(본문 전체)으로 쓴다. 다섯 탭의 본문 바깥 폭은 모두 같고, 저장 막대도 같은 폭이다.

## 2. 후보 비교와 결정
| 안 | 요지 | 판단 |
|---|---|---|

| B. 왼쪽 섹션 목차 + 폼 | GitHub · Vercel식 | ✕ 탭당 4 ~ 7행이라 세로 넘침이 135 ~ 361px뿐 — 목차 이득이 거의 없고 탭과 겹쳐 메뉴가 두 겹 |
| C. 2열 카드 | 빈 폭 없음 | ✕ 읽는 순서가 Z자로 깨지고 관련 설정(최종 승인 ↔ 결재선)이 갈라짐, 표 행이 맞지 않음 |
| D. 오른쪽 고정 도움말 열 | 영향 정보 한곳 | ✕ 포커스한 행을 따라 바뀌는 보이지 않는 동작, 행과 설명이 멀어짐, 표 탭에서 폭이 다시 튐 |
| E-1. **1280px 중앙 열 공유**(Codex) | 머리 · 탭 · 본문 · 저장 막대를 1280 가운데 열에 정렬 | △ 탭 간 폭 통일 · 저장 정렬은 해결. 하지만 다른 모든 화면(왼쪽 정렬)과 첫 글자 위치가 달라지고, 1920에서 양쪽 320px씩 여전히 빈다 |
| **E-2. 전체 폭 행 + 입력 폭 제한 + 행별 보조 칸**(UX) | 라벨 240 · 입력 ≤760 · 보조 1fr, 표는 넓은 행 | **채택** |

**E-2를 고른 이유**
- 제품의 모든 화면이 **왼쪽 정렬(x20)** 이다. 설정만 가운데로 옮기면 상단 메뉴로 화면을 오갈 때 첫 글자 위치가 튄다.
- 빈 폭을 **쓸모 있는 정보**(마지막 변경 · 적용 시점 · 영향 · 링크)로 채운다. 이 정보는 이미 화면 안에 있는데 흩어져 있었다.
- 입력은 읽기 좋은 폭(≤760)으로 제한해 “칸이 화면 끝까지 늘어나는” 문제를 막는다 — GitHub · Stripe 설정에서 가져올 원칙은 ‘목차’가 아니라 이것이다.
- Codex 안에서 가져온 것: **다섯 탭 바깥 폭 통일**, **저장 막대 메시지에 바뀐 범위**, 표 최소 폭 검증, 화면 안내를 탭 줄로, 마이페이지 동시 적용.

## 3. 레이아웃 규칙

### 3.1 폭 예산 (px)
| 요소 | 1920 (본문 1875) | 1600 (본문 1560) | 규칙 |
|---|---|---|---|
| 좌우 여백 | 20 + 20 | 20 + 20 | `.pad` |
| 라벨 칸 | 240 | 240 | 고정. 이름 14px/500 + 설명 12px(2줄까지) |
| 간격 | 24 | 24 | |
| 입력 칸 | **760** | **760**(최소 480) | `minmax(480px, 760px)`. 입력 두 개 나란히 = 각 368 |
| 간격 | 32 | 32 | |
| 보조 칸 | 남는 폭 ≈ 819(글자 최대 520) | ≈ 504 | 12px, `--fg-2` |
| 넓은 행(표) | 입력 + 보조 합침, **최대 1200** | 1200 | `.set-row.wide` |
| 표 탭 | 본문 전체 1875 | 1560 | 목록 + 오른쪽 패널 420 / 380 |
| 저장 막대 | 창 폭, 내용은 본문 양끝 | 같음 | 56px, 변경 있을 때만 |

1600 미만: 보조 칸을 아래로 접지 않고 가로 스크롤(최소 폭 20 + 240 + 24 + 480 + 32 + 280 + 20 = 1096).

### 3.2 설정 행(`.set-row`) 해부
```
┌ 라벨 240 ──────┬ 입력 ≤760 ─────────────────────┬ 보조 (남는 폭, 글자 ≤520) ─────────┐
│ 자기 승인       │ (•) 허용 — 사유 필수             │ 마지막 변경 11-18 이데이터          │
│ 역할을 겸한 …   │ ( ) 비허용 — 다른 결재자가 승인  │ 다음 신청부터 적용 · 감사 로그 ↗   │
└────────────────┴─────────────────────────────────┴─────────────────────────────────────┘
행 구분선(1px --border)은 본문 끝까지 · 행 위아래 16
```
- **라벨 칸**: 이름 + 짧은 설명만. 상태 · 이력은 넣지 않는다.
- **입력 칸**: 한 줄 텍스트는 240 ~ 368, 긴 텍스트 최대 640, 숫자는 72 + 단위 + 허용 범위.
- **보조 칸 순서**: ① 마지막 변경(시각 · 사람) ② 적용 시점(“다음 신청부터”) ③ 영향 범위 · 경고(+[영향 미리보기]) ④ 관련 화면 링크. 내용이 없으면 비워 둔다(구분선이 행을 이어서 빠진 것으로 보이지 않음).
- **탭 끝 경고 띠 금지** — 경고는 해당 행의 보조 칸으로.

### 3.3 묶음 · 넓은 행 · 표 탭
- 탭 안 행이 5개를 넘거나 주제가 둘 이상이면 **소제목 묶음**(15px/600, 위 32 · 아래 8). 앵커 목차는 쓰지 않는다 — 탭이 목차다.
- 표가 들어가는 행(결재선 템플릿 · 데이터타입 매핑 · 시스템 컬럼 · 검수 규칙)은 **넓은 행**: 라벨 오른쪽을 표가 다 쓰고 최대 1200. 열 비교가 1200에서도 어려우면 표 영역 안에서만 가로 스크롤.
- **표 탭**(사용자 · 역할 · 권한표)은 본문 전체. 목록 + 상세는 결재함처럼 테두리 상자 없이 끝까지, 상세 패널 420 / 380. 권한표는 역할 열 고정 120 · ‘할 수 있는 일’ 약 480 · 참고 열이 나머지.

### 3.4 저장 · 안내 · 정렬
| 항목 | 규칙 |
|---|---|
| 저장 | **저장 단위 = 화면**, 하단 저장 막대 하나(`.setbar` 56px, 변경 있을 때만). 메시지 = “● 기관 2곳 바뀜 [변경 보기]”, 버튼 [되돌리기][저장]. 탭에 미저장 점(낭독 이름 포함). 탭 안에 [저장]을 따로 두지 않는다. 즉시 실행 동작(비밀번호 변경 · 테스트 발송 · 사용자 등록)은 막대 대상이 아니다 |
| 영향 큰 저장 | DBMS · 명명 템플릿 · 검수 기준은 [저장] 때 확인 창에 영향 요약(보조 칸 경고와 같은 문구) |
| 화면 안내 | 탭이 있으면 **탭 줄 오른쪽**, 없으면 머리 오른쪽. 펼친 안내는 탭 줄 아래 전체 폭 |
| 정렬 | **왼쪽 정렬** — 머리 · 탭 · 본문 왼쪽 끝 x20. 가운데 정렬 금지 |
| 공통 CSS | `.set-row` · `.set-row.wide` · `.setbar` · `.lastchg` · 숫자 입력을 각 화면 `<style>`에서 `app.css`로 올림 |

## 4. 화면별 적용

### 4.1 설정 — 기관 탭 (1920)
```
│ [기관•] 시스템  사용자 · 역할  권한표  검수 기준                              [ⓘ 화면 안내] │
│ 기관 정보 ─────────────────────────────────────────────────────────────────────────────── │
│ 기관            │ [기관명 368] [기관 사전 이름 368]       │ 상단 바 · 산출물 머리에 표시       │
│ 결재 ─────────────────────────────────────────────────────────────────────────────────── │
│ 사전 신청 최종 승인 │ [x] 사용 · 기관 담당자 2명           │ 마지막 변경 11-20 · 다음 신청부터  │
│ 결재선 템플릿 (넓은 행) │ ┌ 사전 신청 1 DA 승인 · 2 최종 승인 ┐ ┌ 모델 확정 … ┐ (≤1200)          │
│ 자기 승인       │ (•) 허용 ( ) 비허용                     │ 마지막 변경 · 감사 로그 ↗          │
│ 운영 목표       │ 목표 준수율 [90]% 결재 기한 [3]일       │ 다음 신청부터 · 진행 중 기한 유지  │
│ 알림 · 연결 ──────────────────────────────────────────────────────────────────────────── │
│ 메일 알림       │ [SMTP] [발신 주소] [테스트 발송]        │ 발송 대상: 결재 요청 → 지금 차례 … │
│ 도메인그룹 · 분류 │ 표준 사전 › 도메인 그룹 · 분류에서 관리 ↗ │ 그룹 DA 직접 · 분류 품의        │
│ ● 기관 2곳 바뀜 [변경 보기]                                            [되돌리기] [저장] │
```
### 4.2 설정 — 시스템 · 검수 기준
- 시스템: 위에 [시스템 고르기] + [+ 시스템 추가]. 묶음 ‘DBMS · 명명’(대상 DBMS 보조 칸에 ⚠ 컬럼 n개 재점검 + [영향 미리보기]) · ‘타입 · 컬럼’(매핑 · 시스템 컬럼 = 넓은 행) · ‘결재 · 업무 영역’.
- 검수 기준: 정책 버전 안내 띠 두 개를 표 위 한 줄 요약(“검수 기준 v3 · 저장하면 v4, 다음 신청부터”)으로 합치고, 규칙 표 · 변경 이력 = 넓은 행, 표준 제외 규칙은 일반 행.
### 4.3 설정 — 사용자 · 역할 · 권한표
- 인증 방식 띠는 본문 전체 폭. 목록 + 계정 패널(420 / 380)은 상자 테두리 없이 본문 끝까지.
- 권한표: 역할 열 120 고정, 참고 열이 나머지 — 지금처럼 참고 열이 694px까지 늘지 않게.
### 4.4 마이페이지
- 프로필 · 알림 설정 · 보안 · 환경 = 설정 행(라벨 240으로 통일, 220 폐기), 탭 안 [저장] → 하단 저장 막대.
- 내 신청 · 내 작업 = 표 탭(본문 전체), 요약과 결재함 링크 유지.
- [ⓘ 화면 안내]를 탭 줄 오른쪽에 추가(설정과 같은 부품).

## 5. 점검 항목 (17 퍼블리싱 점검에 추가)
1. 폼 탭 오른쪽 빈 폭이 본문의 **25%를 넘지 않는다**(보조 칸 포함).
2. 탭을 바꿔도 본문 왼쪽 · 오른쪽 끝이 같다.
3. 저장 막대 메시지에 바뀐 탭 · 항목 수가 있다.
4. 넓은 행의 표가 1200을 넘지 않고, 넘치면 표 안에서만 가로 스크롤.
5. 1920 · 1600 × 다섯 탭 × 안내 펼침 · 계정 상세 열림 상태를 따로 연다.
