## 0. 결정 사항

| 항목 | 결정 | 영향 |
|---|---|---|
| 표기법 | **IE(까마귀발)** | 식별 관계 실선, 비식별 점선, 다수 쪽 까마귀발, 선택성은 원(○)·막대(｜) |
| 규모 | **업무 영역 편집(수십 개) + 시스템 전체 조회(수백 개)** | 편집 캔버스와 별도로 "시스템 전체 ERD" 조회 보기. 수백 개에서는 상세도 자동 축소(LOD)·미니맵·검색 이동 필수 |
| 논리/물리 | **별도 캔버스** | 논리 다이어그램과 물리 다이어그램을 따로 두고 배치도 따로 저장(DA# 방식). 물리 캔버스에 들어갈 때 게이트 A. 위치 맞추기는 명시적 명령 |
| 속성 편집 | **우측 패널 + 캔버스 인라인** | 상세는 PN-33 표에서, 캔버스에서는 더블클릭으로 이름 수정·Enter로 다음 속성 추가 |
| 화면 기준 | 1920 기본 · 최소 1600 | 1600에서 캔버스 약 760px(3단 배치) |

## 1. 원칙 (DA#에서 배운 것)

| # | 원칙 | 해결하는 DA# 문제 |
|---|---|---|
| 1 | **관계는 출발 → 도착 두 단계, 미리보기 선과 함께** | 한 번 클릭으로 재귀 관계가 생김 (U-11) |
| 2 | **엔터티 박스는 내용에 맞춰 항상 자동 크기**(사용자가 크기를 고정한 경우만 예외) | 속성 추가 후 박스가 안 커짐, FK 추가 때만 커지는 불일치 (U-12) |
| 3 | **관계선은 엔터티를 피해 직각으로, 라벨은 겹치지 않게** | 관계선이 엔터티 관통·라벨 겹침 (U-14) |
| 4 | **표시 정보는 줌에 따라 자동 축소** | 도메인 값 박스가 속성 가림 (U-13), 물리 뷰 잘림 (U-15) |
| 5 | **편집창 대신 패널·인라인**, 다른 모니터·모달로 튀지 않음 | 편집창이 다른 모니터에 열림 (F-36), 탭 전환 저장 확인 (U-16) |
| 6 | **자동으로 바뀐 것은 반드시 알린다** | FK 이름 자동 개명이 로그에만 (F-37), 논리→물리 조용한 반영 (F-41) |
| 7 | **표준 상태가 캔버스에서 바로 보인다** | 표준 정보가 편집창 안에 숨어 있음 (F-14·U-07) |

|---|---|
| 캔버스 툴바 | 상단 가운데 떠 있는 바. 도구 4개(선택 V · 엔터티 E · 관계 R ▾ · 메모 M), 정렬 묶음, 자동 배치, 실행 취소/다시 실행. 도구 선택 상태는 잉크색 채움 |
| 관계 ▾ | 1:N 비식별(기본) · 1:N 식별 · 1:1 · M:N · 재귀. 마지막 사용 유형을 기억 |
| 줌 컨트롤 | 좌하단. 25~200%, 전체 맞춤(Shift+1), 선택 맞춤(Shift+2), **표시 ▾**(이름만·키만·전체 속성·도메인 표시·코드값 표시) |
| 미니맵 | 우하단 180×120. 현재 보이는 영역 사각형을 끌어 이동. 엔터티 상태 색 점 표시. 접기 가능 |
| 빈 캔버스 | "엔터티를 추가하세요 · E 또는 더블클릭" + [엑셀·DDL 가져오기] |
| 우측 패널 | 선택이 없으면 **업무 영역 요약**(엔터티·관계 수, 미준수 엔터티 목록, 최근 변경). 엔터티 선택 → 속성 표(PN-33), 관계 선택 → 관계 속성, 여러 개 선택 → 일괄 편집(분류·주제영역·색) |

## 3. 엔터티 박스 (IE)

```
┌ M  산출물기본                ● ┐  ← 분류 배지(K/M/A) · 이름 · 표준 상태 점(엔터티 용어)
├────────────────────────────────┤
│ ● # 산출물ID        DLVRBL_ID  │  ← PK 구역 (#), 굵게
├────────────────────────────────┤
│ ●   산출물명        DLVRBL_NM  │  ← 일반 속성
│ ●   산출물제출일      —         │     상태 점: ✓녹 · ＋파랑 · !주황 · ◆보라 · –회색
│ ●   요구사항ID (FK) DEMND_…   │  ← FK는 (FK) + 이탤릭
│ ◇   AK: 산출물명               │  ← 대체키 표시 (F-33)
└────────────────────────────────┘
```

| 항목 | 규칙 |
|---|---|
| 크기 | 너비 = 가장 긴 줄(최소 180, 최대 320 → 넘으면 말줄임 + 툴팁). 높이 = 내용. **항상 자동**. 사용자가 손잡이로 크기를 바꾸면 "크기 고정" 표시가 붙고 자동이 꺼짐 |
| 논리 캔버스 | 왼쪽 논리명(Pretendard), 오른쪽 물리명(Geist Mono, 회색) — 표시 ▾에서 물리명 숨김 가능 |
| 물리 캔버스 | 컬럼명(Geist Mono) + 타입(`VARCHAR2(10)`) + NN. 제목은 테이블명(논리명 작게) |
| 서브타입 | 슈퍼타입 박스 아래에 붙은 하위 박스 묶음(구분 속성 표시). 중첩 박스 대신 **아래로 펼침**, 겹치지 않게 자동 정렬 (F-35) |
| 코드값·도메인 | 기본은 숨김. 표시 ▾에서 켜면 속성 줄 오른쪽에 작게 표시(속성을 가리지 않음, U-13) |
| 선택 | 2px 잉크 테두리 + 크기 손잡이 4개. 여러 개는 Shift/드래그 사각형 |
| 상태 점 | 속성 줄 왼쪽 8px 점. 디자인 가이드 §2.3 매핑. 엔터티 제목 오른쪽 점 = 엔터티 용어 상태 |

### 3.1 상세도 자동 축소 (LOD, 수백 개 대응)

| 줌 | 엔터티 표시 | 관계선 |
|---|---|---|
| 75% 이상 | 전체(제목·PK·속성·상태 점) | 선 + 관계명 + 까마귀발 |
| 40~75% | 제목 + PK + 속성 수("+ 8개") | 선 + 까마귀발, 관계명 숨김 |
| 40% 미만 | 제목 블록만(상태 색 띠) | 가는 선 |
| 15% 미만(시스템 전체) | 주제영역별 묶음 상자 + 엔터티 수 | 영역 간 관계 수 굵기 |

## 4. 관계 (IE)

| 유형 | 선 | 끝 표시 |
|---|---|---|
| 1:N 비식별 | 점선 | 부모 ｜｜(필수) 또는 ｜○, 자식 까마귀발 + ○(선택)/｜(필수) |
| 1:N 식별 | 실선 | 자식 PK에 FK가 # 로 들어감 |
| 1:1 | 실선/점선 | 양쪽 ｜｜ |
| M:N | 점선, 가운데 "M:N 해소 필요" 배지 | 양쪽 까마귀발 |
| 재귀 | 엔터티 오른쪽 위로 도는 고리 | 까마귀발 |

**생성 흐름** (원칙 1)

```mermaid
flowchart LR
  A[관계 도구 R · 유형 선택] --> B[부모 엔터티 클릭<br/>테두리 강조 · 상태 안내 '자식을 클릭하세요 · Esc 취소']
  B --> C[마우스를 따라오는 미리보기 선]
  C --> D{자식 클릭}
  D -- 다른 엔터티 --> E[관계 생성 · FK 자동 추가]
  D -- 같은 엔터티 --> F[확인: '재귀 관계를 만들까요?' 인라인 버튼]
  D -- 빈 곳 / Esc --> G[취소]
  E --> H{FK 이름 충돌·AK 존재?}
  H -- 예 --> I[인라인 팝오버: 역할명 입력 · PK/AK 선택<br/>예: 요구사항ID → 원요구사항ID]
  H -- 아니오 --> J[토스트 '요구사항ID (FK)가 추가됐습니다' · 실행 취소]
```

- 드래그(부모에서 자식까지 끌기)도 같은 결과다.
- 관계선 클릭 영역은 선 양쪽 8px로 넓게 잡는다. 선택하면 우측 패널에 관계 속성(관계명·유형·선택성·FK 매핑)이 열린다.
- **M:N 해소**: 관계 선택 → [M:N 해소] → 미리보기 팝오버(교차 엔터티명 제안 `요구사항+리스크+관계` → 표준 용어 확인, **식별 관계 기본**) → 적용 (F-31).
- **라우팅**: 직각선, 엔터티를 피해 감. 같은 두 엔터티 사이 여러 관계는 간격을 둔다. 사용자가 꺾임점을 끌면 그 선은 수동 모드가 된다.

## 5. 편집 동작

| 동작 | 방법 |
|---|---|
| 엔터티 추가 | E 후 클릭, 또는 빈 곳 더블클릭 → 이름 칸이 바로 편집 상태(자동완성 = 엔터티 용어) |
| 이름 수정 | 엔터티/속성 줄 더블클릭 → 인라인 입력. Enter 확정, Esc 취소 |
| 속성 추가 | 엔터티 선택 후 Enter → 마지막 줄 아래 새 줄 편집 상태. 입력 중 **용어 자동완성**(02-flows 5.2). Enter로 다음 줄, Esc로 끝 |
| 속성 이동 | 줄을 끌어 순서 변경, 다른 엔터티로 끌면 이동(확인) |
| PK 지정 | 줄 위에서 `#` 단축키 또는 우클릭 → PK 구역으로 이동 |
| 삭제 | Delete. 관계가 걸린 엔터티는 "관계 2개와 FK 2개도 삭제됩니다" 인라인 확인 |
| 복사·붙여넣기 | Ctrl+C/V. 붙여넣으면 이름 뒤에 `_복사` + 표준 상태 재검사 |
| 실행 취소 | Ctrl+Z / Ctrl+Shift+Z. 표준 맞추기 일괄 적용도 한 번에 취소 가능 |
| 정렬 | 여러 개 선택 → 왼쪽·가운데·위 정렬, 간격 맞춤 |
| 자동 배치 | 계층(부모 위)·방사형. **미리보기 → 적용**, 선택한 것만 배치 가능, 위치 고정 엔터티 존중 |
| 우클릭 메뉴 | 위쪽에 자주 쓰는 것: 편집 · 표준 맞추기 · 사용처 · 사전에서 보기 · 속성 추가 · 관계 시작. 나머지는 묶음(정렬 ▸, 유형 ▸, 표시 ▸). **하위 메뉴는 호버로 열리고 화면 밖으로 나가면 반대쪽으로** (DA# 하위 메뉴가 안 열리던 문제) |

## 6. 논리·물리 별도 캔버스

```mermaid
flowchart LR
  L[논리 캔버스<br/>배치 L] -- 물리 탭 클릭 --> G[게이트 A 점검 패널]
  G --> P[물리 캔버스<br/>배치 P · 처음엔 L 복사]
  L -. 논리 변경 .-> S[물리 동기화 대기 배지<br/>'논리 변경 5건 · 반영']
  S --> G
```

| 항목 | 규칙 |
|---|---|
| 배치 | 논리와 물리의 배치는 **따로 저장**한다. 물리 캔버스를 처음 열면 논리 배치를 복사한다 |
| 동기화 | 논리 변경은 물리에 **자동 반영하지 않고** 상단에 "논리 변경 5건 대기 · [미리보기] [반영]" 배지 (F-41 해소). 반영 전 게이트 A |
| 위치 맞추기 | 명령으로만: "논리 배치를 물리에 적용" / "물리 배치를 논리에 적용" (선택 엔터티 또는 전체) |
| 물리 전용 | 시스템 컬럼·인덱스·파티션 등은 물리 캔버스에서만 보이고, 논리에는 영향 없음 |
| 전환 | 헤더 [논리 \| 물리] 전환. 줌·스크롤 위치는 캔버스마다 기억 |

## 7. 시스템 전체 ERD (조회 전용)

- 진입: 시스템 홈(SC-30) [전체 ERD 보기], 모델 화면 표시 ▾ [시스템 전체로 보기].
- 모든 업무 영역의 엔터티를 **주제영역 묶음 상자**로 표시한다. 영역 간 관계는 굵기로 개수를 나타낸다.
- 확대하면 묶음이 풀리며 엔터티가 나타난다(LOD).
- 검색(Ctrl+F): 엔터티·속성 이름 → 결과 목록 → 선택하면 그 위치로 이동하며 강조한다.
- 필터: 업무 영역 · 표준 상태(미준수만) · 분류(K/M/A).
- **편집 불가**. 엔터티를 더블클릭하면 해당 업무 영역 편집 캔버스로 이동한다.
- 다른 영역의 엔터티를 현재 영역에 "참조로 추가"할 수 있다(같은 엔터티를 여러 영역에서 보기, 01 DG-02).

## 8. 표준 연동 (캔버스에서)

| 상황 | 캔버스 표시 / 동작 |
|---|---|
| 속성 입력 | 인라인 자동완성(용어명·약어·도메인·상태). 선택하면 물리명·타입 채움 |
| 미준수 | 속성 줄 상태 점 + 엔터티 제목 옆 미준수 수 배지. 준수율 바 숫자 클릭 → 해당 엔터티로 이동·강조 |
| 미등록 단어 | 줄에 `!` 점, 마우스를 올리면 "후보 등록" 빠른 버튼 |
| 예외 | 보라 ◆ 점, 툴팁에 사유 |
| 사전 패널에서 끌어 놓기 | 용어를 엔터티 위에 놓으면 속성 추가, 기존 속성 위에 놓으면 용어 적용 |

## 12. ERD-Q1 비교 — erd-editor vs React Flow

조사일 2026-11-17, 각 저장소 README 기준.

| 기준 | erd-editor (`@dineug/erd-editor`, MIT, ★1.8k, v5.1) | React Flow (`@xyflow/react`, MIT) |
|---|---|---|
| 성격 | **완성된 ERD 편집기**를 custom element 하나(`<erd-editor>`)로 제공. 조회 전용 `<erd-viewer>`도 있음 | **노드·엣지 캔버스 툴킷**. 엔터티 박스·관계·도구는 직접 만듦 |
| 바로 쓸 수 있는 기능 | 테이블·컬럼·메모·그룹, 관계 카디널리티 4종, AK, 자동 배치(ELK), DDL 가져오기(SQL·DBML 등)와 DDL 내보내기(Oracle·PostgreSQL·MySQL/MariaDB 등 8종), PNG·SVG, undo·히스토리·diff, 논리명/물리명, 단어·용어·도메인 사전 탭(CSV) | 팬·줌·선택·드래그·미니맵·컨트롤, 커스텀 노드/엣지, 서브플로. 레이아웃은 elkjs·dagre와 함께 씀 |
| 화면 맞춤 | **closed shadow root**라 내부 DOM에 손댈 수 없음. 바꿀 수 있는 것은 테마 토큰·단축키·언어 정도 | 노드가 React 컴포넌트라 **설계안 그대로** 구현 가능(§3 상태 점·LOD, §6 게이트·대기 배지, §8 표준 표시) |
| 데이터 모델 | 자체 `.erd.json`. 사전도 자체 모델(CSV) | 우리 모델을 그대로 씀(노드·엣지는 화면 표현일 뿐) |
| 우리 사전·결재와의 관계 | 사전·표준 검사가 **SWS 기반 사전(30-metadata-design)과 겹치고 다름**. 양방향 동기화나 내장 사전 숨기기가 필요하고, 숨길 API가 없으면 포크해야 함 | 우리 사전 API와 자동완성(PN-33)을 그대로 붙임 |
| 실시간 공동 편집 | 편집을 액션 스트림으로 공유, `getSharedStore()`와 Yjs 바인딩(`@dineug/erd-editor-yjs`) **제공**. erd-editor.io 세션은 WebRTC·호스트 브라우저 기반이라 사내 운영에는 자체 전송 계층을 붙여야 함 | 기본 제공 없음. **Yjs + 자체 WebSocket 서버(예: Hocuspocus)** 를 직접 붙임. React Flow 공식 예제에 협업 패턴이 있음 |
| 기술 스택 | 자체 렌더링 프레임워크(React 아님), 21개 패키지 모노레포, 1인 메인테이너 중심 | React 생태계, 사용자 많음, 팀이 유지보수 |
| 포크했을 때 부담 | 큼 — 우리 화면 규칙(표준 상태·결재·게이트)을 넣으려면 내부를 고쳐야 하고, 이후 상위 저장소 변경 따라가기가 어려움 | 해당 없음 |
| 초기 속도 | 매우 빠름(붙이면 바로 동작) | 느림(엔터티 박스·관계 도구·라우팅을 만들어야 함) |
| 설계안 적합도 | 낮음~중간: IE 표기·자동완성 같은 기본은 맞지만 §3·§6·§8의 표준화 규칙은 넣기 어려움 | 높음 |

**의견 (추천: React Flow + Yjs)** — 이 제품의 차별점은 캔버스 위에서 표준을 지키게 하는 것(상태 점, 자동완성, 게이트, 결재 연동)입니다. erd-editor는 완성도가 높지만 닫힌 컴포넌트에 자체 사전까지 들고 있어 그 차별점을 넣을 자리가 없습니다. 대신 erd-editor는 **기능 점검 목록과 동작 기준**으로 활용합니다: DDL 내보내기 옵션, 가져오기 배치(grid/auto), 액션 단위 협업 구조, diff 뷰어.

**대안 — 부분 사용**: `<erd-viewer>`를 결재 문서·외부 공유용 조회 화면에만 쓰는 방법도 있습니다. 다만 우리 모델을 `.erd.json`으로 바꾸는 변환기가 필요하고, 화면 표기가 편집기와 달라집니다.

**결정 (2026-11-17): React Flow + Yjs.**

**구현 착수 시 기술 검증(1~2일)** — 결과가 기준에 못 미치면 해당 부분만 대안(자체 SVG 렌더링 등)을 검토합니다.
1. 엔터티 300개·관계 500개에서 60fps로 이동, LOD 전환.
2. elkjs 직각 라우팅과 자동 배치를 미리보기 후 적용.
3. Yjs(Hocuspocus)로 브라우저 두 개 동기화, 사용자별 undo(Y.UndoManager), 접속자 표시(awareness).
4. PNG·SVG·PDF 내보내기(ERD-Q2).

## 13. 실시간 공동 편집 (ERD-Q3 확정)

| 항목 | 설계 |
|---|---|
| 편집 단위 | **업무 영역 × 논리/물리** 마다 공유 문서 하나. 같은 영역을 여는 사람은 모두 같은 문서에 접속 |
| 서버 | 사내 WebSocket 서버(Yjs 프로토콜, 예: Hocuspocus). 외부 시그널링이나 P2P는 쓰지 않음. 6~20명 규모라 서버 프로세스 하나로 충분 |
| 참여 권한 | 그 시스템의 모델 편집 권한자는 편집자, 그 외는 조회자(커서만 보임) |
| 접속자 표시 | 페이지 헤더에 아바타 묶음, 캔버스에 상대 커서와 이름표, 상대가 선택한 엔터티에 색 테두리와 "홍길동 편집 중" 표시 |
| 충돌 | CRDT가 자동 병합. 같은 칸을 동시에 고치면 마지막 입력이 남고 진 쪽에 토스트("홍길동이 이 이름을 바꿨습니다 · 내 값 보기"). 다른 사람이 편집 중인 엔터티를 지우면 확인 대화상자 |
| 실행 취소 | **사용자별** undo — 내 편집만 되돌림 |
| 표준·결재와의 경계 | 사전 신청·승인은 공유 문서 밖(서버 API). 모델 확정 신청이 들어가면 그 버전은 **모두에게 조회 전용**으로 고정되고, 이후 편집은 다음 작업 버전(UX-Q2)에 들어감 |
| 게이트·준수율 | 서버가 병합된 상태를 기준으로 다시 계산해서 모든 접속자에게 같은 값을 보여줌 |
| 저장 | 변경을 계속 서버에 반영하고, 주기적으로 그리고 버전을 저장할 때 스냅숏을 DB에 남김. 히스토리 패널에 "누가·무엇을" 기록 |
| 연결 끊김 | 배너 "연결 끊김 — 편집 내용은 이 브라우저에 보관하고, 다시 연결되면 병합합니다". 오래 끊긴 뒤 충돌이 많으면 변경 요약을 보여줌 |
| 배치 | 엔터티 위치도 공유. 자동 배치는 전원에게 적용되므로 실행 전에 확인 대화상자("접속 중인 3명의 화면도 바뀝니다") |
| 영향 | 백엔드에 WebSocket 서버와 스냅숏 저장소가 추가됨. 20-priority의 W1 모델 편집 범위에 협업 기반이 들어감(일정 재산정 필요) |
