## 0. 결정 사항

| 항목 | 결정 | 영향 |
|---|---|---|
| 표기법 | **IE(까마귀발)** | 식별 관계 실선, 비식별 점선, 다수 쪽 까마귀발, 선택성은 원(○)·막대(｜) — 표현 방식 전체 목록과 다른 표기법 비교는 [23-erd-notation.md](23-erd-notation.md) |
| 규모 | **업무 영역 편집(수십 개) + 시스템 전체 조회(수백 개)** | 편집 캔버스와 별도로 "시스템 전체 ERD" 조회 보기. 수백 개에서는 상세도 자동 축소(LOD)·미니맵·검색 이동 필수. **확정 숫자 (2026-11-18, [23 §6](../spec/da-feature-spec/23-performance-spike.md))**: 업무 영역 **권장 상한 300 엔터티**(넘으면 경고만, 막지 않음). 시스템 전체 ERD는 **영역 묶음 보기가 기본**이며 1,000 엔터티까지 확인했다. 상세도 전환은 **0.35배 미만 요약 · 0.2배 미만 영역 묶음**이고 확대가 멈춘 뒤(약 150ms) 바꾼다. 화면 밖 노드는 그리지 않는다. 자동 배치는 Worker에서 돌리고 진행 표시와 취소를 둔다. 1,000개 이상은 영역 단위로만 배치한다 |
| 논리/물리 | **별도 캔버스** | 논리 다이어그램과 물리 다이어그램을 따로 두고 배치도 따로 저장(DA# 방식). 물리 캔버스에 들어갈 때 게이트 A. 위치 맞추기는 명시적 명령 |
| 속성 편집 | **우측 패널 + 캔버스 인라인 (인라인은 추가·이름만, 2026-11-18 한정)** | 카드 안에서는 **속성 추가(Enter)와 이름 바꾸기만**. 타입·키·NULL·용어 적용·보안 속성은 오른쪽 패널(PN-33)에서만 편집한다. 카드 높이 흔들림·줄바꿈 문제를 피한다(SWS가 카드 안 편집을 Drawer로 옮긴 경험, 22 §6-7) |
| 화면 기준 | 1920 기본 · 최소 1600 | 1600에서 캔버스 약 760px(3단 배치) |
| SWS 비교 반영 (2026-11-18) | **채택** — [22 §6](../spec/da-feature-spec/22-sws-comparison.md) | ① **컬럼 단위 관계선**: 관계선이 FK 속성 행에 붙는다. LOD로 속성이 숨으면 엔터티 가장자리로 돌아간다. ② **PK를 끌어다 키 전달**: 부모 PK를 자식 엔터티에 놓으면 관계와 FK가 생긴다. 관계 도구(R)도 그대로 둔다. ③ **복합 FK 묶음**: 한 관계에서 온 FK 속성들을 묶음 ID로 관리한다. 식별 관계로 바꾸면 묶음 전체가 PK·NOT NULL이 된다. 관계를 지울 때는 FK를 유지할지 삭제할지 고른다. ④ **자동 정렬은 Web Worker**에서 돌리고 취소할 수 있게 한다. 좌표가 있는 엔터티는 그대로 둔다. ⑤ **축소 요약**에서는 노드 크기와 연결점을 고정해 선이 흔들리지 않게 한다. 화면 밖 노드는 그리지 않는다. 내보낼 때는 요약을 끈다 |

## 1. 원칙 (DA#에서 배운 것)

| # | 원칙 | 해결하는 DA# 문제 |
|---|---|---|
| 1 | **관계는 출발 → 도착 두 단계, 미리보기 선과 함께** | 한 번 클릭으로 재귀 관계가 생김 (U-11) |
| 2 | **엔터티 박스는 내용에 맞춰 항상 자동 크기**(사용자가 크기를 고정한 경우만 예외) | 속성 추가 후 박스가 안 커짐, FK 추가 때만 커지는 불일치 (U-12) |
| 3 | **관계선은 엔터티를 피해 직각으로, 라벨은 겹치지 않게** | 관계선이 엔터티 관통·라벨 겹침 (U-14) |
| 4 | **표시 정보는 줌에 따라 자동 축소** | 도메인 값 박스가 속성 가림 (U-13), 물리 뷰 잘림 (U-15) |
| 5 | **편집창 대신 패널·인라인**, 다른 모니터·모달로 튀지 않음 | 편집창이 다른 모니터에 열림 (F-36), 탭 전환 저장 확인 (U-16) |
| 6 | **자동으로 바뀐 것은 반드시 알린다** | FK 이름 자동 개명이 로그에만 (F-37), 논리→물리 조용한 반영 (F-41) |
| 7 | **표준 상태가 캔버스에서 바로 보인다** | 표준 정보가 편집창 안에 숨어 있음 (F-14·U-07) |

## 2. 화면 구성

```
┌ 페이지 헤더: 요구사항관리 › 요구사항 · 프로젝트 [논리 | 물리]  v5 작업 중   [가져오기][DDL][확정 신청] ┐
├ 준수율 바 (02-flows)                                                                              ┤
├────────────┬──────────────────────────────────────────────────────────┬──────────────────────┤
│ PN-32 사전  │ ┌ 캔버스 툴바 (떠 있음, 상단 가운데) ─────────────────┐   │ PN-33 속성 패널        │
│ 280 / 240  │ │ 선택 · 엔터티 · 관계▾ · 메모 │ 정렬 · 자동 배치 │ ↶ ↷ │   │ (선택 없으면 업무 영역  │
│            │ └──────────────────────────────────────────────────┘   │  요약: 엔터티 수·관계·  │
│            │                                                          │  미준수 목록)          │
│            │          엔터티 박스 · 관계선 (IE)                         │                      │
│            │                                                          │                      │
│            │ ┌ 좌하단: 줌 −  76%  + · 전체 맞춤 · 표시 ▾ ┐  ┌ 우하단 ┐ │                      │
│            │ └────────────────────────────────────────┘  │ 미니맵 │ │                      │
└────────────┴──────────────────────────────────────────────────────────┴──────────────────────┘
```

| 요소 | 내용 |
|---|---|
| 캔버스 툴바 | 상단 가운데 떠 있는 바. 도구 4개(선택 V · 엔터티 E · 관계 R ▾ · 메모 M), 정렬 묶음, 자동 배치, 실행 취소/다시 실행. 도구 선택 상태는 잉크색 채움 |
| 관계 ▾ | 1:N 비식별(기본) · 1:N 식별 · 1:1 · M:N · 재귀. 마지막 사용 유형을 기억 |
| 줌 컨트롤 | 좌하단. 25~200%, 전체 맞춤(Shift+1), 선택 맞춤(Shift+2), **표시 ▾**(이름만·키만·전체 속성·도메인 표시·코드값 표시) |
| 미니맵 | 우하단 180×120. 현재 보이는 영역 사각형을 끌어 이동. 엔터티 상태 색 점 표시. 접기 가능 |
| 하단 조작부 항상 보임 (2026-11-23) | 줌 · 맞춤 · 표시 단계 · 범례 · 미니맵은 **보이는 캔버스의 아래쪽**에 붙는다 — 창이 낮거나 1920/1600 고정 프레임 · 페이지 스크롤로 캔버스가 창 밖으로 넘치면 넘친 만큼 위 · 왼쪽으로 올라온다. 범례 · 미니맵은 접기/펼치기(사용자별 기억), 캔버스 폭 760 미만이면 미니맵 자동 접힘. 단축키 Ctrl + `+` / `-` / `0`(100%), Shift+1 맞춤, 100% 표시를 두 번 누르면 100%. 시스템 전체 ERD도 같은 줌 · 맞춤 · 미니맵 · 범례(영역 묶음 설명)로 조작한다(표시 단계만 숨김). 맞춤 프레임 최소 높이 720 → 600 |
| 맞춤 · 배치 · 저장 (2026-11-24, ERD 리뷰 P1) | 맞춤은 노드 경계 상자를 **가려지지 않는 사각형**(도구 막대 · 안내 띠 아래, 하단 조작부 위)에 맞춘다. 캔버스 위 조작 UI(범례 · 미니맵 · 줌 · 띠 · 버튼)에서 두 번 눌러도 엔터티가 생기지 않는다. 엔터티 도구 뒤 **Enter = 보이는 곳 가운데 빈 자리**에 배치. 한글 조합 중 Enter는 확정하지 않는다. 저장 표시는 쓰기 성공 뒤에만 ‘저장됨’, 실패하면 ‘저장 안 됨 [다시 시도]’. 역할명을 묻는 관계는 확정 전까지 저장하지 않는다. 미준수 수는 주 버튼 · 영역 화면 배지가 같은 계산을 쓴다. 안내 띠는 ‘단어 승인 대기’ 속성만 단어별로, 예외는 건별 사유(`review/resolution-erd-review.md` P1 적용 기록) |
| 머리 · 도구 막대 · 패널 분담 (2026-11-24, ERD 리뷰 P2) | 머리 = 경로 · 영역 화면 메뉴 · 상태(버전 · 저장 · 접속) · ⋯(DDL 가져오기 · 이미지 · 확정본 비교) · 주 버튼 **[확정 신청 ⓝ]**(남은 항목이 있으면 오른쪽 ‘확정 전 점검’ 패널에서 건별로 고치기 · 예외). 캔버스를 바꾸는 것([다이어그램 \| 표] · [논리 \| 물리] · 보기 · 자동 배치 · 되돌리기)은 도구 막대. 1920 미만은 오른쪽 패널이 선택을 따라 열리고 접힌다. 자동 상세도는 화면 글자 크기 기준(11px↑ 전체 · 9~11 키만 · 9 미만 이름만). 노드는 키보드로 오간다(방향키 · Shift+방향키 · F2 · Shift+2) |
| 하단 한 줄 · 관계 종류 (2026-11-24, ERD 리뷰 P3) | 하단 조작부는 한 줄 — 범례는 줌 막대 [ⓘ] 팝오버(처음엔 열림, 닫으면 기억), 미니맵 색도 범례 · 툴팁에 글자로. 자식 고르기 팝업 위 관계 종류 칩(1 비식별 · 2 식별 · 3 1:1) |
| 빈 캔버스 | "엔터티를 추가하세요 · E 또는 더블클릭 · E 뒤 Enter" + [엑셀·DDL 가져오기] |
| 우측 패널 | 선택이 없으면 **업무 영역 요약**(엔터티·관계 수, 미준수 엔터티 목록, 최근 변경). 엔터티 선택 → 속성 표(PN-33), 관계 선택 → 관계 속성, 여러 개 선택 → 일괄 편집(분류·주제영역·색) |

## 3. 엔터티 박스 (IE)

```
┌ M  산출물기본                ● ┐  ← 분류 배지(K/M/A) · 이름 · 표준 상태 점(엔터티 용어)
├────────────────────────────────┤
│ ● PK 산출물ID       DLVRBL_ID  │  ← 키 구역 + 작은 고정폭 ‘PK’ 글자, 굵게(‘#’는 쓰지 않는다 — M-8)
├────────────────────────────────┤
│ ●   산출물명        DLVRBL_NM  │  ← 일반 속성
│ ●   산출물제출일      —         │     상태 점: ✓녹 · ＋파랑 · !주황 · ◆보라 · –회색
│ ●   요구사항ID (FK) DEMND_…   │  ← FK는 (FK) + 이탤릭
│ ◇   AK: 산출물명               │  ← 대체키 표시 (F-33)
└────────────────────────────────┘
```

| 항목 | 규칙 |
|---|---|
| 크기 | 너비 = 가장 긴 줄(최소 180, 최대 320 → 넘으면 말줄임 + 툴팁. **물리 캔버스(테이블 ERD)는 최대 약 560**, 통합은 520). 높이 = 내용. **항상 자동**. 사용자가 손잡이로 크기를 바꾸면 "크기 고정" 표시가 붙고 자동이 꺼짐 |
| 논리 캔버스 | 왼쪽 논리명(Pretendard), 오른쪽 물리명(Geist Mono, 회색) — 표시 ▾에서 물리명 숨김 가능 |
| 물리 캔버스 = **테이블 ERD** (M-8) | 한 줄 6칸: **PK/FK**(24, ‘PK’ · ‘FK’ 글자) · **컬럼명**(Mono, 최대 180) · **타입**(72) · **길이**(36, 오른쪽 정렬) · **소수점**(28, 오른쪽 정렬) · **속성명**(Pretendard, `--fg-3`, 최대 160). 칸은 노드 안에서 세로로 맞춘다. 제목은 테이블명(논리명 작게). 표시 ‘키만’에서는 3 ~ 6칸을 숨긴다. 범례에 열 순서를 적는다. 노드가 넓어지므로 저장된 물리 배치는 가로로 펼쳐 보여 준다(통합 보기와 같은 방식, 저장 좌표는 그대로) |
| 줄 높이(캔버스 밀도, M-8) | **마이페이지 › 환경 › 캔버스 밀도**: 촘촘 16 · 기본 20 · 넓게 24px. 글자는 12px 그대로. 촘촘에서는 줄에 마우스를 올리면 강조하고 상태 배지는 글자색만 쓴다([01 §6.4-1](01-design-guide.md)) |
| 서브타입 | 슈퍼타입 박스 아래에 붙은 하위 박스 묶음(구분 속성 표시). 중첩 박스 대신 **아래로 펼침**, 겹치지 않게 자동 정렬 (F-35) |
| 코드값·도메인 | 기본은 숨김. 표시 ▾에서 켜면 속성 줄 오른쪽에 작게 표시(속성을 가리지 않음, U-13) |
| 선택 | 2px 잉크 테두리 + 크기 손잡이 4개. 여러 개는 Shift/드래그 사각형 |
| 상태 점 | 속성 줄 왼쪽 8px 점. 디자인 가이드 §2.3 매핑. 엔터티 제목 오른쪽 점 = 엔터티 용어 상태 |

### 3.1 상세도 자동 축소 (LOD, 수백 개 대응)

| 줌 | 엔터티 표시 | 관계선 |
|---|---|---|
| 글자 11px 이상(약 92% 이상) | 전체(제목·PK·속성·상태 점) | 선 + 관계명 + 까마귀발 |
| 글자 9 ~ 11px(약 75 ~ 92%) | 제목(15px) + PK + 속성 수("+ 8개"). 테이블 ERD는 PK 줄의 PK/FK · 컬럼명만 | 선 + 까마귀발, 관계명 숨김 |
| 글자 9px 미만(약 75% 미만) | 제목만(줄 자리는 그대로 두어 크기 · 선 끝이 흔들리지 않는다) | 가는 선 |
| 20% 미만 | 토스트로 [시스템 전체](영역 묶음 보기)를 안내한다 | — |

> 기준은 **화면에 보이는 속성 글자 크기(12px × 배율)** 다 — 목업 값으로 맞췄다(2026-11-25, M-8). 이전 표의 75% · 40% 기준은 쓰지 않는다. ‘표시’ 목록(자동 · 전체 속성 · 키만 · 요약)으로 고정할 수 있다.

## 4. 관계 (IE)

| 유형 | 선 | 끝 표시 |
|---|---|---|
| 1:N 비식별 | 점선 | 부모 ｜｜(필수) 또는 ｜○, 자식 까마귀발 + ○(선택)/｜(필수) |
| 1:N 식별 | 실선 | 자식 PK(키 구역)에 FK가 들어감 — `PK 전표번호 (FK)` |
| 1:1 | **식별이면 실선, 비식별이면 점선**(선 모양은 식별 여부만 따른다 — M-8) | 양쪽 ｜｜ |
| M:N | 점선, 가운데 "M:N 해소 필요" 배지 | 양쪽 까마귀발 |
| 재귀 | 엔터티 오른쪽 위로 도는 고리 | 까마귀발 |

**생성 흐름** (원칙 1)

```mermaid
flowchart LR
  A[관계 도구 R · 유형 선택] --> B[부모 엔터티 클릭<br/>테두리 강조 · 상태 안내 '자식을 클릭하세요 · Esc 취소']
  B --> C[마우스를 따라오는 미리보기 선]
  C --> D{자식 클릭}
  D -- 다른 엔터티 --> E[관계 생성 · FK 자동 추가]
  D -- 같은 엔터티 --> F[재귀 관계 · 중복 속성 해소 창에서 역할명(상위○○) 한 번 확인]
  D -- 빈 곳 / Esc --> G[취소]
  E --> H{자식에 같은 이름의 속성(논리명 또는 물리명) · 같은 방향 두 번째 관계?}
  H -- 예 --> I[중복 속성 해소 창: 기존 속성을 FK로 사용 / 새 이름으로 만들기<br/>Enter 확정 · Esc 연결 취소 — 확정 전에는 아무것도 바뀌지 않음]
  H -- 아니오 --> J[토스트 '요구사항ID (FK)가 추가됐습니다' · 실행 취소]
```

> 연결 · 관계 패널 · ON DELETE · 삭제 조건 표의 확정안은 [18-relation-scenario.md](18-relation-scenario.md)를 따른다(2026-11-20, Codex·Claude 교차 검토 반영).

- 드래그(부모에서 자식까지 끌기)도 같은 결과다.
- 관계선 클릭 영역은 선 양쪽 8px로 넓게 잡는다. 선택하면 우측 패널에 관계 속성(관계명·유형·선택성·FK 매핑)이 열린다.
- **M:N 해소**: 관계 선택 → [M:N 해소] → 미리보기 팝오버(교차 엔터티명 제안 `요구사항+리스크+관계` → 표준 용어 확인, **식별 관계 기본**) → 적용 (F-31).
- **라우팅**: 직각선, 엔터티를 피해 감. 같은 두 엔터티 사이 여러 관계는 간격을 둔다. 사용자가 꺾임점을 끌면 그 선은 수동 모드가 된다.

## 5. 편집 동작

| 동작 | 방법 |

| 속성 추가 | 엔터티 선택 후 Enter → 마지막 줄 아래 새 줄 편집 상태. 입력 중 **용어 자동완성**(02-flows 5.2). Enter로 다음 줄, Esc로 끝 |
| 속성 이동 | 줄을 끌어 순서 변경, 다른 엔터티로 끌면 이동(확인) |

| 복사·붙여넣기 | Ctrl+C/V. 붙여넣으면 이름 뒤에 `_복사` + 표준 상태 재검사 |

| 정렬 | 여러 개 선택 → 왼쪽·가운데·위 정렬, 간격 맞춤 |
| 자동 배치 | 계층(부모 위)·방사형. **미리보기 → 적용**, 선택한 것만 배치 가능, 위치 고정 엔터티 존중 |
| 우클릭 메뉴 | 위쪽에 자주 쓰는 것: 편집 · 표준 맞추기 · 사용처 · 사전에서 보기 · 속성 추가 · 관계 시작. 나머지는 묶음(정렬 ▸, 유형 ▸, 표시 ▸). **하위 메뉴는 호버로 열리고 화면 밖으로 나가면 반대쪽으로** (DA# 하위 메뉴가 안 열리던 문제) |

## 6. 논리·물리 별도 캔버스

```mermaid
flowchart LR
  L[논리 캔버스<br/>배치 L] -- 물리 탭 클릭 --> G[게이트 A 점검 패널]
  G --> P[물리 캔버스<br/>배치 P · 처음엔 L 복사]
  L -. 논리 변경 .-> S[물리 동기화 대기 배지<br/>'논리 변경 5건 · 반영']
  S --> G
```

| 항목 | 규칙 |
|---|---|
| 배치 | 논리와 물리의 배치는 **따로 저장**한다. 물리 캔버스를 처음 열면 논리 배치를 복사한다 |
| 동기화 | 논리 변경은 물리에 **자동 반영하지 않고** 상단에 "논리 변경 5건 대기 · [미리보기] [반영]" 배지 (F-41 해소). 반영 전 게이트 A |
| 위치 맞추기 | 명령으로만: "논리 배치를 물리에 적용" / "물리 배치를 논리에 적용" (선택 엔터티 또는 전체) |
| 물리 전용 | 시스템 컬럼·인덱스·파티션 등은 물리 캔버스에서만 보이고, 논리에는 영향 없음 |
| 전환 | 헤더 [논리 \| 물리] 전환. 줌·스크롤 위치는 캔버스마다 기억 |

## 7. 시스템 전체 ERD (조회 전용)

- 진입: 시스템 홈(SC-30) [전체 ERD 보기], 모델 화면 표시 ▾ [시스템 전체로 보기].
- 모든 업무 영역의 엔터티를 **주제영역 묶음 상자**로 표시한다. 영역 간 관계는 굵기로 개수를 나타낸다.

## 12. ERD-Q1 비교 — erd-editor vs React Flow

조사일 2026-11-17, 각 저장소 README 기준.

| 기준 | erd-editor (`@dineug/erd-editor`, MIT, ★1.8k, v5.1) | React Flow (`@xyflow/react`, MIT) |
|---|---|---|
| 성격 | **완성된 ERD 편집기**를 custom element 하나(`<erd-editor>`)로 제공. 조회 전용 `<erd-viewer>`도 있음 | **노드·엣지 캔버스 툴킷**. 엔터티 박스·관계·도구는 직접 만듦 |
| 바로 쓸 수 있는 기능 | 테이블·컬럼·메모·그룹, 관계 카디널리티 4종, AK, 자동 배치(ELK), DDL 가져오기(SQL·DBML 등)와 DDL 내보내기(Oracle·PostgreSQL·MySQL/MariaDB 등 8종), PNG·SVG, undo·히스토리·diff, 논리명/물리명, 단어·용어·도메인 사전 탭(CSV) | 팬·줌·선택·드래그·미니맵·컨트롤, 커스텀 노드/엣지, 서브플로. 레이아웃은 elkjs·dagre와 함께 씀 |
| 화면 맞춤 | **closed shadow root**라 내부 DOM에 손댈 수 없음. 바꿀 수 있는 것은 테마 토큰·단축키·언어 정도 | 노드가 React 컴포넌트라 **설계안 그대로** 구현 가능(§3 상태 점·LOD, §6 게이트·대기 배지, §8 표준 표시) |
| 데이터 모델 | 자체 `.erd.json`. 사전도 자체 모델(CSV) | 우리 모델을 그대로 씀(노드·엣지는 화면 표현일 뿐) |
| 우리 사전·결재와의 관계 | 사전·표준 검사가 **SWS 기반 사전(30-metadata-design)과 겹치고 다름**. 양방향 동기화나 내장 사전 숨기기가 필요하고, 숨길 API가 없으면 포크해야 함 | 우리 사전 API와 자동완성(PN-33)을 그대로 붙임 |
| 실시간 공동 편집 | 편집을 액션 스트림으로 공유, `getSharedStore()`와 Yjs 바인딩(`@dineug/erd-editor-yjs`) **제공**. erd-editor.io 세션은 WebRTC·호스트 브라우저 기반이라 사내 운영에는 자체 전송 계층을 붙여야 함 | 기본 제공 없음. **Yjs + 자체 WebSocket 서버(예: Hocuspocus)** 를 직접 붙임. React Flow 공식 예제에 협업 패턴이 있음 |
| 기술 스택 | 자체 렌더링 프레임워크(React 아님), 21개 패키지 모노레포, 1인 메인테이너 중심 | React 생태계, 사용자 많음, 팀이 유지보수 |
| 포크했을 때 부담 | 큼 — 우리 화면 규칙(표준 상태·결재·게이트)을 넣으려면 내부를 고쳐야 하고, 이후 상위 저장소 변경 따라가기가 어려움 | 해당 없음 |
| 초기 속도 | 매우 빠름(붙이면 바로 동작) | 느림(엔터티 박스·관계 도구·라우팅을 만들어야 함) |
| 설계안 적합도 | 낮음~중간: IE 표기·자동완성 같은 기본은 맞지만 §3·§6·§8의 표준화 규칙은 넣기 어려움 | 높음 |

**의견 (추천: React Flow + Yjs)** — 이 제품의 차별점은 캔버스 위에서 표준을 지키게 하는 것(상태 점, 자동완성, 게이트, 결재 연동)입니다. erd-editor는 완성도가 높지만 닫힌 컴포넌트에 자체 사전까지 들고 있어 그 차별점을 넣을 자리가 없습니다. 대신 erd-editor는 **기능 점검 목록과 동작 기준**으로 활용합니다: DDL 내보내기 옵션, 가져오기 배치(grid/auto), 액션 단위 협업 구조, diff 뷰어.

**대안 — 부분 사용**: `<erd-viewer>`를 결재 문서·외부 공유용 조회 화면에만 쓰는 방법도 있습니다. 다만 우리 모델을 `.erd.json`으로 바꾸는 변환기가 필요하고, 화면 표기가 편집기와 달라집니다.

**결정 (2026-11-17): React Flow + Yjs.**

**구현 착수 시 기술 검증(1~2일)** — 결과가 기준에 못 미치면 해당 부분만 대안(자체 SVG 렌더링 등)을 검토합니다.
1. 엔터티 300개·관계 500개에서 60fps로 이동, LOD 전환.
2. elkjs 직각 라우팅과 자동 배치를 미리보기 후 적용.
3. Yjs(Hocuspocus)로 브라우저 두 개 동기화, 사용자별 undo(Y.UndoManager), 접속자 표시(awareness).
4. PNG·SVG·PDF 내보내기(ERD-Q2).

## 13. 실시간 공동 편집 (ERD-Q3 확정)

| 항목 | 설계 |
|---|---|
| 편집 단위 | **업무 영역 × 논리/물리** 마다 공유 문서 하나. 같은 영역을 여는 사람은 모두 같은 문서에 접속 |
| 서버 | 사내 WebSocket 서버(Yjs 프로토콜, 예: Hocuspocus). 외부 시그널링이나 P2P는 쓰지 않음. 6~20명 규모라 서버 프로세스 하나로 충분 |
| 참여 권한 | 그 시스템의 모델 편집 권한자는 편집자, 그 외는 조회자(커서만 보임) |
| 접속자 표시 | 페이지 헤더에 아바타 묶음, 캔버스에 상대 커서와 이름표, 상대가 선택한 엔터티에 색 테두리와 "홍길동 편집 중" 표시 |
| 충돌 | CRDT가 자동 병합. 같은 칸을 동시에 고치면 마지막 입력이 남고 진 쪽에 토스트("홍길동이 이 이름을 바꿨습니다 · 내 값 보기"). 다른 사람이 편집 중인 엔터티를 지우면 확인 대화상자 |
| 실행 취소 | **사용자별** undo — 내 편집만 되돌림 |
| 표준·결재와의 경계 | 사전 신청·승인은 공유 문서 밖(서버 API). 모델 확정 신청이 들어가면 그 버전은 **모두에게 조회 전용**으로 고정되고, 이후 편집은 다음 작업 버전(UX-Q2)에 들어감 |
| 게이트·준수율 | 서버가 병합된 상태를 기준으로 다시 계산해서 모든 접속자에게 같은 값을 보여줌 |
| 저장 | 변경을 계속 서버에 반영하고, 주기적으로 그리고 버전을 저장할 때 스냅숏을 DB에 남김. 히스토리 패널에 "누가·무엇을" 기록 |
| 연결 끊김 | 배너 "연결 끊김 — 편집 내용은 이 브라우저에 보관하고, 다시 연결되면 병합합니다". 오래 끊긴 뒤 충돌이 많으면 변경 요약을 보여줌 |
| 배치 | 엔터티 위치도 공유. 자동 배치는 전원에게 적용되므로 실행 전에 확인 대화상자("접속 중인 3명의 화면도 바뀝니다") |
| 영향 | 백엔드에 WebSocket 서버와 스냅숏 저장소가 추가됨. 20-priority의 W1 모델 편집 범위에 협업 기반이 들어감(일정 재산정 필요) |

### 13.1 재확인 (2026-11-18) — SWS 비교 후에도 W1 실시간 유지

**결정: W1부터 Yjs 실시간 공동 편집을 유지한다** (사용자 결정, [22-sws-comparison §4·§6-1](../spec/da-feature-spec/22-sws-comparison.md)).

- 검토한 근거: SWS는 실시간 엔진(서버 op log + 필드 버전, WebSocket은 알림만)을 만든 뒤 2026-11-02 사용자 확정으로 **문서 단위 단독 편집(90초 lease + 저장 버전 검사)** 으로 돌아갔다. 동시 편집은 범위에서 제외했다. 기술 실패가 아니라 업무 방식 선택이었다.
- 검토한 대안: "W1 단독 편집 lease, W2 실시간", "엔터티 단위 잠금". 둘 다 채택하지 않았다.
- 결과: 같은 업무 영역을 여러 명이 동시에 편집하는 것이 W1 범위다. 아래 6가지는 CRDT 흐름에 맞춰 **구현 설계에서 반드시 정한다** (06 §4.7 (b) 1·2·3번과 같은 묶음).

| # | 정할 것 | 기준 |
|---|---|---|
| 1 | **쓰기 권한을 서버에서** | 접속할 때 권한·영역 상태를 확인한다(조회자는 읽기 전용 연결). 서버는 변경을 받을 때마다 다시 확인하고, 권한이 없거나 영역이 검토 중·확정이면 그 변경을 거절한다. 역할이 바뀌면 연결을 끊는다. 브라우저 검사만으로는 우회할 수 있다(SWS R13과 같은 위험) |
| 2 | **확정 신청 = 서버 고정** | 확정 신청이 들어오면 서버가 그 버전의 공유 문서를 읽기 전용으로 바꾸고 상태를 인코딩해 **내용 해시와 함께 결재 문서에 고정**한다. 신청 직전에 들어온 변경은 고정 시점 기준으로 포함 여부가 결정되고, 신청자 화면에 그 시점을 표시한다 |
| 3 | **스냅숏·버전** | 공유 문서는 업무 영역 × 버전 단위로 둔다. 주기 스냅숏과 확정 스냅숏을 분리하고, 다음 버전은 확정 스냅숏에서 새 공유 문서로 시작한다(목업 v7의 버전별 저장과 같은 구조) |
| 4 | **준수 판정·게이트의 기준 상태** | 서버가 병합된 상태로 계산한다. 결재 승인 때는 고정된 스냅숏으로 다시 계산한다(목업 v7과 같은 규칙) |
| 5 | **사용자별 undo와 표준 맞추기 일괄 적용** | 일괄 적용(여러 속성 변경)은 하나의 트랜잭션 묶음으로 넣어 한 번에 되돌릴 수 있게 한다. 다른 사람이 그사이 같은 속성을 바꿨으면 되돌리기 결과를 알린다 |
| 6 | **성능·운영** | 착수 스파이크에서 두 브라우저 동기화, 300 엔터티 문서의 초기 로딩·병합 시간, 서버 재시작 후 복구, 오래 끊긴 클라이언트 병합을 측정한다. 실패하면 이 결정을 다시 연다 |

## 14. 고객 모델 요청 반영 (2026-11-25, M-1 · M-5 · M-6 · M-8)

- **중복 속성 해소 창**(M-1): 관계 생성 · PK 추가(확인란 · Space · 트리 메뉴 · 키 구역으로 끌어 놓기) · 식별 전환 · FK 짝 · M:N 해소 · FK 복구가 **같은 창 하나**를 쓴다. 규칙은 [18 §1-1](18-relation-scenario.md).
- **PK 삭제 · 끄기**(M-5): 한 동작 — 자식 FK는 일반 속성으로 남고 관계는 유지된다. 규칙은 [16 §3.2](16-attribute-edit-grid.md) · [18 §3-1](18-relation-scenario.md).
- **모델 검증**(M-6): 준수율 막대의 [모델 검증 막음 n · 경고 n]과 [확정 신청 n]이 **같은 패널**을 연다. 예전 [검토](PN-39) · [확정 전 점검] · 게이트 A(PN-35) 창을 하나로 합쳤다.

| 묶음 | 항목 | 등급 |
|---|---|---|
| 표준 | 테이블명 미정 · 엔터티 이름 규칙 · 표준이 아닌 속성(조합 가능 · 미등록) · 속성 이름 규칙 | 막음 |
| 표준 | 표준 외 타입 | 경고(위반 아님) |
| 이름 · 설명 | 엔터티 정의 없음 · 속성 설명 없음 | **막음**(기본. 정책 › 모델 입력 규칙에서 경고로 바꿀 수 있다) |
| 이름 · 설명 | 정의 · 설명이 이름과 같음 · 5자 미만 | **경고**(기본. 막음 · 검사 안 함으로 바꿀 수 있다. 글자 수도 정책 값) |
| 이름 · 설명 | 명칭 중복(FK가 아닌데 다른 엔터티에 같은 이름) | 경고 |
| 구조 | **불변식 위반** — 엔터티 안 컬럼 물리명 중복 · 같은 영역 안 테이블 물리명 중복(둘 다 대소문자 무시) · 엔터티명 중복(공용 `modelInvariants(model)`, 게이트 B와 같은 함수) | 막음 |
| 구조 | 식별자 없음 · **관계의 FK 누락**(관계는 있는데 FK가 성립하지 않음 — 관계 패널 · DDL과 같은 판정) · **PK인데 필수가 꺼짐** | 막음 |
| 구조 | M:N 미해소 · 관계 없는 FK 후보 컬럼(엑셀에서 참조 오류로 관계 없이 들어온 컬럼) · 미매핑 · 타입 미정(게이트 A) · 관계 없는 엔터티 | 경고 |

  - **[확정 신청]은 막음이 0건일 때만** 열린다. 버튼 배지 = 막음 건수. 제출 직전에도 같은 판정으로 다시 검사한다.
  - 모델 입력 규칙의 출처는 하나다 — **정책 본문(`modelInput`) → 없으면 저장 키(`neodb.modelInputRules`) → 기본값**(`getModelInputRules()`). 편집 · 신청 · 결재가 같은 값을 쓴다.
  - 정의 · 설명 판정은 공용 함수 `descJudge(name, desc, rules)` 하나다(빈칸 · 이름과 같음(공백 · 대소문자 무시) · 글자 수 미만) — 정책 화면의 예시 · 영향 미리보기와 같은 결과가 나온다.
  - 확정 신청 문서에 **그때의 검증 결과**(`check: {block, warn, rulesVer}`)와 **제출 사본의 SHA-256 해시**(`hash`)를 저장한다. DDL · 결재 · 산출물이 같은 해시를 쓴다.
  - 패널의 [확정 신청 계속]은 확정 신청 권한(`model.submit`)이 없으면 **숨긴다**. 권한은 있는데 지금 못 하는 경우(막음 남음 · 검토 중 · 확정본)는 흐리게 하고 이유를 버튼에 연결한다(29 R-17).
  - 판정은 공용 함수 하나(`modelCheck(model, policy)` — 구현은 `packages/rules`)를 편집 중 표시 · 확정 신청 · 서버 재검사 · 승인 재검사에서 함께 쓴다. 신청 시점의 모델 입력 규칙을 결재 문서에 남긴다.
  - 정의 · 설명 항목은 목록에서 [입력]으로 **제자리에서** 채운다(Enter 저장 · Esc 취소). 표준 항목은 [고치기](표준 맞추기) · [예외…].
  - 물리 보기로 처음 갈 때(게이트 A)는 같은 패널이 열리고 아래 버튼이 [경고 확인 후 계속]으로 바뀐다. 진행은 막지 않는다.
  - **엔터티 정의**: 엔터티 탭의 ‘정의’ 칸에 적는다(엑셀 정의서의 테이블 설명이 여기에 들어온다). 테이블 정의서와 테이블 주석(COMMENT)에 쓴다.
- **표기 · 테이블 ERD · 캔버스 밀도**(M-8): §3 · §3.1 · §4에 반영. 표기 규칙은 [23](23-erd-notation.md).
