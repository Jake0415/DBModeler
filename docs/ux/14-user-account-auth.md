# 사용자 계정 · 인증 (독립 인트라넷)

> 2026-11-19 · 상태: **적용 완료(목업)**
> 사용자 요청: 사용자 등록은 정보를 입력하는 형태로 한다. 기본 항목은 회사명 · 부서명 · 이름 · 전화번호 · 이메일 · ID/PW다. 운영 환경은 독립된 인트라넷이라 **SSO는 옵션**으로만 동작한다.

## 1. 인증 방식 (설정 → 사용자 · 역할 맨 위)
| 방식 | 로그인 화면 | 계정 관리 |
|---|---|---|
| **ID · 비밀번호 (기본)** | ID · 비밀번호 입력 | 이 시스템에서 등록 · 수정 · 중지 · 삭제 |
| ID · 비밀번호 + SSO 선택 | ID · 비밀번호 입력 + "또는 [사내 SSO로 로그인]" 버튼 | 계정은 여기서 관리한다. SSO는 로그인 수단만 더한다 |
| SSO만 | [사내 SSO로 로그인] 버튼만 | **관리자(Admin)만** "SSO 장애 · 관리자 비상 로그인"으로 ID · 비밀번호를 쓸 수 있다 |

- SSO를 켜려면 프로토콜(SAML 2.0 · OIDC)과 IdP 주소를 넣어야 저장된다. 바꾸면 감사 로그에 "이전 → 이후"가 남는다.
- 정책(목업 기본값):

  | 항목 | 값 |
  |---|---|
  | 비밀번호 | 9자 이상 · 영문 · 숫자 · 특수문자 포함 · ID 미포함 · 같은 문자 3번 연속 금지 |
  | 변경 주기 | 90일 |
  | 잠금 | 5회 실패 시 10분 잠김 |
  | 세션 | 입력 없이 30분이 지나면 만료 |

## 2. 사용자 등록 (Admin)
설정 → 사용자 · 역할 → **[사용자 등록]** → 오른쪽 패널 입력 양식.

| 항목 | 필수 | 규칙 |
|---|---|---|
| 회사명 | ✓ | 기본값은 기관명. 외주사 직원은 회사명을 바꿔 입력한다 |
| 부서명 | ✓ | |
| 이름 | ✓ | |
| 전화번호 | ✓ | 숫자만 쳐도 `010-1234-5678` 형식으로 맞춘다. 형식이 틀리면 막는다 |
| 이메일 | ✓ | 형식 검사, **다른 사용자와 중복 금지**(결재 알림 메일 주소) |
| ID | ✓ | 영문 소문자로 시작 · 소문자 · 숫자 · `.` `_` `-` · 4~20자 · **중복 금지** · 등록 뒤 바꿀 수 없음 |
| 비밀번호 · 확인 | ✓ | §1 규칙. 입력하는 동안 규칙마다 ✓가 켜진다. 두 칸이 같아야 한다 |
| 첫 로그인 때 변경 | 기본 켬 | 켜면 처음 로그인할 때 새 비밀번호를 정해야 들어갈 수 있다 |
| 역할 | 하나 이상 또는 "조회만" | 모델러 · DA · 기관 담당자 · Admin을 겸할 수 있다. "조회만"은 역할 없이 보기만 한다 |
| 담당 시스템 | 하나 이상 | 전체 · 요구사항관리 · 통합ERP |

- 틀린 칸마다 아래에 이유가 나오고, 첫 번째 틀린 칸으로 포커스가 간다. 낭독기는 `aria-invalid`와 오류 문구를 함께 읽는다.
- **비밀번호는 평문으로 저장하지 않는다.** 목업은 솔트를 넣은 해시만 남긴다. 실제 서버는 bcrypt · argon2 같은 느린 해시를 쓴다. 저장한 비밀번호는 누구에게도 다시 보여 주지 않는다.
- 등록하면 감사 로그에 "사용자 등록 · 회사 · 부서 · 역할 · 담당 시스템"이 남는다.

## 3. 수정 · 계정 관리
| 동작 | 누가 | 규칙 |
|---|---|---|
| 회사 · 부서 · 이름 · 연락처 수정 | Admin(모든 사용자), 본인(연락처만, 마이페이지) | 이메일은 중복 금지 |
| 역할 · 담당 시스템 변경 | Admin, 본인은 불가 | **마지막 Admin의 Admin 역할은 뺄 수 없다**. 역할 변경 요청이 있으면 처리 뒤 요청자에게 알린다 |
| 비밀번호 초기화 | Admin | 규칙에 맞는 12자 임시 비밀번호를 만들어 **한 번만** 보여 준다(복사 버튼). 다음 로그인 때 바꿔야 한다. 잠긴 계정이면 잠금도 풀린다 |
| 잠금 해제 | Admin | 5회 실패로 잠긴 계정 |
| **사용 중지** | Admin, 본인 · 마지막 Admin은 불가 | 사유 필수(퇴사 · 전출 · 휴직). 로그인이 막히고 이력은 그대로 남는다. 그 사람 차례인 결재는 같은 역할의 다른 담당자에게 넘어간다고 안내한다. [다시 사용]으로 되돌린다 |
| **삭제** | Admin | **업무 이력이 없는 계정만** 삭제할 수 있다. 업무 이력은 결재 문서 · 결재 처리 · 엑셀 묶음 · 후보 · 업무 감사 기록이다. 로그인 · 비밀번호 변경 같은 계정 기록은 세지 않는다. 이력이 있으면 이유(예: "결재 문서 3 · 후보 2")를 보여 주고 사용 중지를 권한다. 삭제는 되돌릴 수 없고 확인을 한 번 더 받는다 |

- 목록에서 이름 · ID · 회사 · 부서로 찾고, 상태(사용 · 중지 · 잠김)로 거른다. 열은 이름 · ID · 회사 · 부서 · 역할 · 담당 시스템 · 인증 · 상태 · 마지막 접속이다.
- 저장하지 않은 입력이 있으면 다른 사용자로 옮기거나 화면을 떠날 때 묻는다.
- 모든 변경은 감사 로그에 남는다(등록 · 정보 수정 · 역할 변경 · 비밀번호 초기화 · 잠금 해제 · 중지 · 다시 사용 · 삭제 · 인증 방식 변경).

## 4. 로그인 (login.html)
- ID와 비밀번호를 입력한다.
  - 없는 ID와 틀린 비밀번호는 **같은 문구**("ID 또는 비밀번호가 맞지 않습니다")로 알려 계정을 짐작할 수 없게 한다. 틀린 횟수(1/5)를 보여 준다.
  - 5번째 실패에서 10분 동안 잠그고 감사 로그에 남긴다.
  - 중지된 계정은 "사용이 중지된 계정"으로 안내한다.
- 임시 비밀번호이거나 변경 주기(90일)가 지났으면 **새 비밀번호 단계**가 나온다. 새 비밀번호는 규칙 검사를 하고, 이전 비밀번호와 같으면 막는다. 바꾸면 원래 가려던 화면으로 간다.
- 세션이 만료되면 원래 주소로 돌아가는 기존 동작은 그대로다.
- 목업 기본 계정: kim · park · lee · hyun · choi / `Neodb!2026`. 로그인 화면의 "목업 안내"를 펼치면 보인다.

## 5. 마이페이지
- **기본 정보**: 회사 · 부서 · 이름 · ID는 읽기 전용이다(관리자가 바꾼다).
- **연락처**: 전화번호 · 이메일은 본인이 고친다. 형식 검사와 이메일 중복 검사를 한다.
- **보안**:
  - 자체 계정은 지금 비밀번호 → 새 비밀번호 · 확인으로 바꾼다. 규칙과 이전 비밀번호 비교를 거친다.
  - SSO 계정은 "기관 통합 인증에서 바꿉니다"로 안내한다.

## 6. 남긴 것 (RBAC 다음 단계)
- 역할 × 기능 권한표를 하나로 정리하는 일(지금은 화면 코드 곳곳에서 검사한다)과 **담당 시스템이 실제 편집 권한을 막는 규칙**. 지금 담당 시스템은 표시와 홈 필터에만 쓰인다.
- 결재 위임: 사용 중지할 때 그 사람 차례 결재를 다른 담당자에게 넘긴다는 안내는 있지만, 실제로 넘기는 동작은 아직 없다.
- 비밀번호 재사용 금지(최근 n개), 접속 IP 제한, 휴면 계정(장기 미접속 자동 중지)은 정책 항목으로 추가할 수 있다.
