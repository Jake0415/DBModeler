# 사용자 계정 · 인증 (독립 인트라넷)

> 2026-11-19 · 상태: **적용 완료(목업)**
> 사용자 요청: 사용자 등록은 정보를 입력하는 형태로 한다. 기본 항목은 회사명 · 부서명 · 이름 · 전화번호 · 이메일 · ID/PW다. 운영 환경은 독립된 인트라넷이라 **SSO는 옵션**으로만 동작한다.

## 1. 인증 방식 (설정 → 사용자 · 역할 맨 위)
| 방식 | 로그인 화면 | 계정 관리 |
|---|---|---|
| **ID · 비밀번호 (기본)** | ID · 비밀번호 입력 | 이 시스템에서 등록 · 수정 · 중지 · 삭제 |
| ID · 비밀번호 + SSO 선택 | ID · 비밀번호 입력 + "또는 [사내 SSO로 로그인]" 버튼 | 계정은 여기서 관리한다. SSO는 로그인 수단만 더한다 |
| SSO만 | [사내 SSO로 로그인] 버튼만 | **관리자(Admin)만** "SSO 장애 · 관리자 비상 로그인"으로 ID · 비밀번호를 쓸 수 있다 |

- SSO를 켜려면 프로토콜(SAML 2.0 · OIDC)과 IdP 주소를 넣어야 저장된다. 바꾸면 감사 로그에 "이전 → 이후"가 남는다.
- 정책(목업 기본값):

  | 항목 | 값 |
  |---|---|
  | 비밀번호 | 9자 이상 · 영문 · 숫자 · 특수문자 포함 · ID 미포함 · 같은 문자 3번 연속 금지 |
  | 변경 주기 | 90일 |
  | 잠금 | 5회 실패 시 10분 잠김 |
  | 세션 | 입력 없이 30분이 지나면 만료 |

## 2. 사용자 등록 (Admin)
설정 → 사용자 · 역할 → **[사용자 등록]** → 오른쪽 패널 입력 양식.

| 항목 | 필수 | 규칙 |
|---|---|---|
| 회사명 | ✓ | 기본값은 기관명. 외주사 직원은 회사명을 바꿔 입력한다 |
| 부서명 | ✓ | |
| 이름 | ✓ | |
| 전화번호 | ✓ | 숫자만 쳐도 `010-1234-5678` 형식으로 맞춘다. 형식이 틀리면 막는다 |
| 이메일 | ✓ | 형식 검사, **다른 사용자와 중복 금지**(결재 알림 메일 주소) |
| ID | ✓ | 영문 소문자로 시작 · 소문자 · 숫자 · `.` `_` `-` · 4~20자 · **중복 금지** · 등록 뒤 바꿀 수 없음 · **삭제된 계정의 ID는 영구 예약**(다시 쓸 수 없음). 로그인 때는 대소문자를 구분하지 않는다 |
| 비밀번호 | — | **관리자가 정하지 않는다.** 등록하면 시스템이 규칙에 맞는 12자 임시 비밀번호를 만들어 한 번만 보여 준다. 사용 기한은 24시간이고, 첫 로그인 때 새 비밀번호로 바꿔야 한다. SSO만 쓰는 모드에서는 비밀번호를 만들지 않는다 |
| 역할 | 하나 이상 또는 "조회만" | 모델러 · DA · 기관 담당자 · Admin을 겸할 수 있다. "조회만"은 역할 없이 보기만 한다 |
| 담당 시스템 | 하나 이상 | 전체 · 요구사항관리 · 통합ERP |

- 틀린 칸마다 아래에 이유가 나오고, 첫 번째 틀린 칸으로 포커스가 간다. 낭독기는 `aria-invalid`와 오류 문구를 함께 읽는다.
- **비밀번호는 평문으로 저장하지 않는다.** 목업은 솔트를 넣은 해시만 남긴다. 실제 서버는 bcrypt · argon2 같은 느린 해시를 쓴다. 저장한 비밀번호는 누구에게도 다시 보여 주지 않는다.
- 등록하면 감사 로그에 "사용자 등록 · 회사 · 부서 · 역할 · 담당 시스템"이 남는다.

## 3. 수정 · 계정 관리
| 동작 | 누가 | 규칙 |
|---|---|---|
| 회사 · 부서 · 이름 · 연락처 수정 | Admin(모든 사용자), 본인(연락처만, 마이페이지) | 이메일은 중복 금지 |
| 역할 · 담당 시스템 변경 | Admin, 본인은 불가 | **마지막 Admin의 Admin 역할은 뺄 수 없다**. 역할 변경 요청이 있으면 처리 뒤 요청자에게 알린다 |
| 비밀번호 초기화 | Admin | 규칙에 맞는 12자 임시 비밀번호를 만들어 **한 번만** 보여 준다(복사 버튼). 다음 로그인 때 바꿔야 한다. 잠긴 계정이면 잠금도 풀린다 |
| 잠금 해제 | Admin | 5회 실패로 잠긴 계정 |
| **사용 중지** | Admin, 본인 · 마지막 Admin은 불가 | 사유 필수(퇴사 · 전출 · 휴직). 로그인이 막히고 이력은 그대로 남는다. 그 사람 차례인 결재는 같은 역할의 다른 담당자에게 넘어간다고 안내한다. [다시 사용]으로 되돌린다 |
| **삭제** | Admin | **업무 이력이 없는 계정만** 삭제할 수 있다. 업무 이력은 결재 문서 · 결재 처리 · 엑셀 묶음 · 후보 · 업무 감사 기록이다. 로그인 · 비밀번호 변경 같은 계정 기록은 세지 않는다. 이력이 있으면 이유(예: "결재 문서 3 · 후보 2")를 보여 주고 사용 중지를 권한다. 삭제는 되돌릴 수 없고 확인을 한 번 더 받는다 |

- 목록에서 이름 · ID · 회사 · 부서로 찾고, 상태(사용 · 중지 · 잠김)로 거른다. 열은 이름 · ID · 회사 · 부서 · 역할 · 담당 시스템 · 인증 · 상태 · 마지막 접속이다.
- 저장하지 않은 입력이 있으면 다른 사용자로 옮기거나 화면을 떠날 때 묻는다.
- 모든 변경은 감사 로그에 남는다(등록 · 정보 수정 · 역할 변경 · 비밀번호 초기화 · 잠금 해제 · 중지 · 다시 사용 · 삭제 · 인증 방식 변경).

## 4. 로그인 (login.html)
- ID와 비밀번호를 입력한다.
  - 없는 ID와 틀린 비밀번호는 **같은 문구**("ID 또는 비밀번호가 맞지 않습니다")로 알려 계정을 짐작할 수 없게 한다. 틀린 횟수(1/5)를 보여 준다.
  - 5번째 실패에서 10분 동안 잠그고 감사 로그에 남긴다.
  - 중지된 계정은 "사용이 중지된 계정"으로 안내한다.
- 임시 비밀번호이거나 변경 주기(90일)가 지났으면 **새 비밀번호 단계**가 나온다. 새 비밀번호는 규칙 검사를 하고, 이전 비밀번호와 같으면 막는다. 바꾸면 원래 가려던 화면으로 간다.
- 세션이 만료되면 원래 주소로 돌아가는 기존 동작은 그대로다.
- 목업 기본 계정: kim · park · lee · hyun · choi / `Neodb!2026`. 로그인 화면의 "목업 안내"를 펼치면 보인다.

## 5. 마이페이지
- **기본 정보**: 회사 · 부서 · 이름 · ID는 읽기 전용이다(관리자가 바꾼다).
- **연락처**: 전화번호 · 이메일은 본인이 고친다. 형식 검사와 이메일 중복 검사를 한다.
- **보안**:
  - 자체 계정은 지금 비밀번호 → 새 비밀번호 · 확인으로 바꾼다. 규칙과 이전 비밀번호 비교를 거친다.
  - SSO 계정은 "기관 통합 인증에서 바꿉니다"로 안내한다.

## 6. 남긴 것 (RBAC 다음 단계)
- 역할 × 기능 권한표를 하나로 정리하는 일(지금은 화면 코드 곳곳에서 검사한다)과 **담당 시스템이 실제 편집 권한을 막는 규칙**. 지금 담당 시스템은 표시와 홈 필터에만 쓰인다.
- 결재 위임: 사용 중지할 때 그 사람 차례 결재를 다른 담당자에게 넘긴다는 안내는 있지만, 실제로 넘기는 동작은 아직 없다.
- 비밀번호 재사용 금지(최근 n개), 접속 IP 제한, 휴면 계정(장기 미접속 자동 중지)은 정책 항목으로 추가할 수 있다.

## 7. 교차 검토 반영 (u1: codex-u1 15건 · claude-u1 15건)
| 지적 | 반영 |
|---|---|
| 로그인이 계정 유무 · 상태 · Admin 여부를 드러냄 | **비밀번호를 먼저 확인**한다. 틀리면 없는 ID · 잠긴 계정 · 중지 계정 · SSO 계정 모두 같은 문구("ID 또는 비밀번호가 맞지 않습니다. 계속 틀리면 계정이 잠길 수 있습니다")를 보이고, 횟수도 보이지 않는다. 계정 상태(중지 · 잠김 · SSO만)는 비밀번호가 맞았을 때만 알린다 |
| 잠금 시간이 지나도 실패 횟수가 남음 | 잠금 시간이 지나면 상태와 실패 횟수를 처음으로 돌린다. 다시 사용 · 초기화 때도 지운다 |
| 삭제한 ID를 다시 쓸 수 있음 | 삭제한 ID는 영구 예약한다 |
| SSO만으로 바꾸면 모두 잠길 수 있음, 비상 로그인 통제 없음 | 비상 로그인할 수 있는 관리자(사용 중 · ID · 비밀번호 계정)가 없으면 SSO만으로 바꿀 수 없다. 비상 로그인은 **사유를 꼭 적어야** 하고, 감사 로그에 남기며 다른 관리자에게 알린다. SSO 로그인은 로컬 잠금을 풀지 않고, 중지 계정은 막는다 |
| 관리자가 사용자 비밀번호를 알게 됨 | 등록 · 초기화 모두 **시스템이 만든 임시 비밀번호**(암호학적 난수, 24시간)만 쓴다. 기한이 지나면 로그인할 수 없다. 초기화하면 본인에게 알림을 보내고 기존 세션을 끝낸다 |
| 중지 · 초기화 · 비밀번호 변경 · 역할 회수 뒤에도 세션이 남음 | 세션 종료 시각을 기록해, 그보다 먼저 시작한 세션은 다음 화면을 열 때 로그인 화면으로 보낸다("계정 상태나 비밀번호가 바뀌어 로그아웃됐습니다"). 본인이 비밀번호를 바꾸면 다른 세션만 끝나고 지금 세션은 남는다 |
| 임시 비밀번호 창 | 열면 [복사]에 포커스가 가고, 닫으면 값을 지운다. 클립보드를 비우라고 안내한다. 로그인 중 변경 단계에서는 계정이 그사이 중지되거나 다시 발급되지 않았는지 확인한다 |
| 결재 인계를 다 한 것처럼 안내 | "자동으로 넘어가지 않습니다 — 중지 전에 처리하거나 결재선 담당자를 바꾸세요"로 바꿨다 |
| 입력값이 HTML로 해석됨 | 감사 기록은 글자로만 남기고, 목업 역할 전환 목록의 이름도 글자로 넣는다. 중지된 계정은 역할 전환 목록에서 뺀다 |
| 비밀번호 특수문자 규칙이 공백 · 한글도 인정 | 특수문자는 ASCII 기호(`!@#$` 등)만 센다. 공백은 쓸 수 없다 |
| 전화번호 · 이메일 · ID 정규화 | 서울(02) 번호를 지원한다. 13자를 넘게 칠 수 없다. 이메일은 공백을 없애고 소문자로 저장 · 비교하며, 형식 검사를 강화했다(연속 점 · 도메인). ID는 소문자로 저장하고 로그인 때 대소문자를 무시한다 |
| 오류 낭독 · 연결 | 칸마다 있던 `role=alert`를 없애고, 맨 위 **요약 한 곳**("입력을 확인하세요 — 부서명 · 이름 …")만 읽는다. 필수 칸에 `aria-required`를 붙이고, 역할 · 담당 시스템 그룹은 오류와 연결한다. 로그인 · 마이페이지 오류도 입력에 연결한다 |

## 8. 서버 구현 요건 (목업이 흉내만 내는 것)
목업은 브라우저 저장소로 동작을 보여 줄 뿐이다. 실제 제품은 아래를 **서버에서** 지킨다.

| 영역 | 요건 |
|---|---|
| 비밀번호 저장 | 계정별 무작위 솔트 + **Argon2id 또는 bcrypt**. 평문과 검증값을 로그 · 응답 · 브라우저 저장소에 두지 않는다. 인증 요청은 TLS로만 받는다 |
| 기본 계정 | 운영 배포에 목업 계정(`Neodb!2026`)을 넣지 않는다. 첫 관리자는 설치 때 일회용 절차로 만든다 |
| 세션 · 권한 | ME(현재 사용자)는 서버가 검증한 세션에서만 만든다. 모든 읽기 · 변경 요청에서 계정 상태 · 역할 · 담당 시스템 범위를 검사한다. 중지 · 삭제 · 초기화 · 역할 회수 때 세션을 즉시 폐기한다. 목업의 역할 전환 도구는 데모 환경에만 둔다 |
| 시도 제한 | 계정 단위 잠금에 더해 **접속 출처(IP) 단위** 제한을 둔다. 실패 응답의 문구 · 코드 · 처리 시간을 같게 맞춘다 |
| 임시 비밀번호 | 일회용 · 24시간 · 발급 버전을 가진다. 변경 전용 세션에서만 바꿀 수 있고, 바꾸는 순간 원자적으로 소비한다 |
| SSO | IdP 응답(서명 · 발급자 · 대상)을 서버가 검증하고, 불변 사용자 식별자로 계정을 연결한다. 비상 로그인은 미리 지정한 개인 관리자만, 허용 접속 경로에서, 추가 인증과 경보를 함께 쓴다 |
| 마지막 관리자 | 역할 회수 · 중지 · 삭제 · 인증 방식 전환은 **확정하는 트랜잭션 안에서** 남는 관리자와 복구 경로를 다시 검사한다(동시 변경 대비) |
| 사용자 식별 | 모든 이력은 **불변 사용자 키**와 당시 이름을 함께 남긴다. 삭제 가능 판정은 업무 이벤트 유형 · 키로 하고, 이름으로 하지 않는다 |
