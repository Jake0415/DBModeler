## 1. 사용자와 사용 환경

| 항목 | 답 | 설계 영향 |
|---|---|---|
| 1-1 주 사용 상황 | **기관 내부 상시 운영** | 기관 표준 사전 하나를 계속 관리하는 것이 중심. 프로젝트별 세트(MD-40·41)는 비중을 낮추고, 첫 화면·내비게이션을 "기관 사전 + 여러 시스템 모델" 구조로 |
| 1-2 동시 사용 인원 | **중규모 (6~20명)** | DA 1~3명, 모델러 여러 명. 결재 대기함·담당 구분 필요, 실시간 동시 편집까지는 불필요(잠금 수준) |
| 1-3 역할 겸임 | **흔함** | 모델러 겸 DA가 일반적. 작성 → 신청 → 승인이 한 흐름에서 끊기지 않게(자기 승인 동선 짧게), 역할별 화면을 따로 두기보다 권한에 따라 버튼이 늘어나는 구조 |
| 1-4 화면 환경 | **데스크톱 전용, 1920 기본 · 최소 1600** (UX-Q1, 잠정 — 목업 배치 후 확정) | 정보량이 많아 크게 줄이지 않는다. 1600~1919는 패널 폭만 축소, 1600 미만은 최소 폭 유지 + 권장 배너. 목업은 1920 기준 + 1600 확인 프레임 |
| 1-5 모델 단위 | **시스템 > 업무 영역 2단계** | 내비게이션 트리: 기관 → 시스템(대상 DB) → 업무 영역(주제영역). 표준 기준(DBMS·명명 템플릿)은 **시스템 단위**로 지정 |
| 1-6 사전 구성 | **공통표준(읽기 전용) + 기관 사전 1개** | 사전 세트 선택 UI 불필요(모든 시스템이 같은 사전). MD-40·41은 "기관 사전 = 기관 세트 1개 고정"으로 단순화. 공통 우선·공통 충돌 거부 규칙은 유지 |
| 1-7 대상 DBMS | **Oracle·PostgreSQL·Tibero·MySQL/MariaDB** | 시스템마다 DBMS 지정. 타입 매핑·이름 길이·예약어 정책을 4종 모두 준비 (인벤토리 OQ-4 해소: 1차 4종) |
| 1-8 주 업무 | **현행 표준화와 신규 설계 비슷하게** | 표준 맞추기 진입점이 두 갈래: ① 리버스(엑셀·DDL) 직후 일괄 ② 설계 중 수시. 둘 다 1급 흐름으로 설계. DDL 리버스(RV-R01) 우선순위 W2→W1 상향 검토 |

## 2. 디자인 기준과 산출물 형태

| 항목 | 답 | 설계 영향 |
|---|---|---|
| 2-1 디자인 시스템 | **Vercel 디자인 md 파일을 참조해 DBModeler 디자인 가이드를 새로 작성** | 화면 흐름 설계 전에 `docs/ux/01-design-guide.md`(토큰·타이포·컴포넌트·밀도 규칙)를 먼저 만든다. docuCBD Blueprint는 쓰지 않음 |
| 2-2 산출물 수준 | **클릭 가능한 목업까지** | 흐름도 → 와이어 → HTML 목업(주요 화면 클릭 이동). 목업은 디자인 가이드 토큰을 적용 |
| 2-3 기본 작업 방식 | **목록 + 우측 패널** | 상세·편집은 우측 패널(비모달). 모달은 파괴적 확인·파일 선택 등 최소한만 (LG-R01, 공통 UI 규칙) |
| 2-4 참고 스타일 | **최신 SaaS 스타일** | dbdiagram·Linear·Vercel 대시보드처럼 간결·여백·키보드 중심. DA# 리본 UI·SWS 팝업 패턴은 따르지 않음 |
| 2-5 디자인 md 출처 | **공개 DESIGN.md 모음의 Vercel 파일** | 디자인 가이드 작성 시 해당 파일을 찾아 읽고 토큰·원칙을 추출. 원문을 그대로 옮기지 않고 DBModeler 규칙으로 재정리 |
| 2-6 테마 | **라이트 기본 + 다크 지원** | 색상은 전부 토큰으로 정의, 두 테마 값 제공 |
| 2-7 정보 밀도 | **촘촘하게** | 행 높이 약 32px, 사전 수천~수만 건 목록에 맞춤. 패널·여백은 SaaS 스타일 유지 |
| 2-8 글꼴 | **Pretendard + Geist Mono** | 본문·UI는 Pretendard, 물리명·약어·코드·DDL은 Geist Mono |

## 3. 사전 관리

| 항목 | 답 | 설계 영향 |
|---|---|---|
| 3-1 초기 사전 | **공통표준 적재 + 기관 사전 빈 상태** | 설치 직후 공통표준(읽기 전용) 조회 가능. 첫 화면에 "기관 사전이 비어 있음 → 단어 추가/엑셀 가져오기" 빈 상태 안내 |
| 3-2 모델러 조회 위치 | **모델 편집 화면 사이드 패널** | 사전 패널이 모델러의 주 진입점(검색·적용·후보 등록). 별도 사전 관리 화면은 DA 중심(등록·이력·검수 기준) |
| 3-3 신청 주체 | **모델러도 신청, DA 승인 + 발주처 최종 승인(옵션)**. 결재는 일반적인 결재 기능으로 설계 | Q-2(단일 결재) 변경 → **결재선 설정형**: 1단계 DA 승인 필수 + 2단계 발주처 최종 승인 선택. 상세는 4단계 |
| 3-4 엑셀 일괄 등록 | **자주 (모델러도 사용)** | 엑셀 가져오기 진입점을 사전 목록 상단·모델 사전 패널 양쪽에 노출. 5색 검증 결과·정상 건만 신청 흐름(MD-08)을 1급 화면으로 |
| 3-5 사전 첫 화면 | **검색창 + 통합 결과** | 단어·도메인·용어·코드 통합 검색, 종류는 필터 칩. 검색어 없으면 최근 변경 목록(빈 검색 0건 문제 F-08 해소) |
| 3-6 출처 구분 | **한 목록 + 출처 배지** | `공통`/`기관` 배지·필터. 공통 항목은 수정·삭제 버튼 없음(읽기 전용) |
| 3-7 상세 패널 내용 | **연관 항목 · 모델 사용처 · 변경 이력 · 진행 중 신청** (모두) | 우측 패널 = 기본 정보 + 탭 4개. 모델 사용처는 시스템 > 업무 영역 > 테이블 > 컬럼 경로로 표시 |

## 4. 결재

| 항목 | 답 | 설계 영향 |
|---|---|---|
| 4-1 결재 대상 | **사전 등록·변경·삭제 + 모델 확정** | 결재 엔진은 "결재 문서 유형" 2종으로 시작(사전 신청, 모델 확정), 유형 추가 가능한 구조. 게이트 예외·산출물 배포는 결재 대상 아님 |
| 4-2 결재선 구성 | **템플릿 + 신청 시 추가** | 관리자가 유형별 기본 결재선 템플릿 설정. 신청자는 기본 단계를 지울 수 없고 참조자·추가 결재자만 더할 수 있음 |
| 4-3 발주처 승인 적용 | **시스템(모델) 단위 설정** | 시스템 설정에 "최종 승인 단계 사용" 토글. 모델 확정 결재는 해당 시스템 설정을 따름 |
| 4-4 발주처 승인자 | **기관 담당자 역할 겸용** | 별도 외부 계정 없음. 역할 "기관 담당자(최종 승인)"를 사용자에게 부여. 역할 겸임이 흔하므로(1-3) 권한 기반 버튼 노출 |
| 4-5 사전 신청의 최종 승인 | **기관 설정 하나로** | 기관 사전 설정에 "사전 신청 최종 승인 사용" 토글. 모델 확정만 시스템 단위(4-3) |
| 4-6 추가 결재 기능 | **참조·열람** | 참조자 지정(결재권 없음, 알림·열람). 대결·위임·일괄 승인·반려 단계 지정은 1차 범위 밖 — 반려는 신청자에게 돌아감 |
| 4-7 자기 승인 | **허용 + 사유 필수** | 자기 신청을 승인하면 사유 입력 필수, 결재 이력·감사 로그에 "자기 승인" 표시. 모든 단계에 동일 적용 |
| 4-8 알림 | **앱 + 메일** — 메일은 **결재선 담당자에게만** (UX-Q3) | 결재 요청은 지금 차례인 결재자에게, 결과·회수는 신청자와 앞 단계 결재자에게 메일로 보낸다. 참조자·후보·재검토 알림은 앱만. 메일 서버 설정 화면 필요(관리자) |
| 4-0 정책 변경 | Q-2 "단일 결재" → **설정형 결재선**(1단계 DA 필수 + 최종 승인 선택, 참조자, 자기 승인 사유) | 30-metadata-design MD-20~22, 20-priority Q-2 확정안 갱신 필요 |

## 5. 표준 맞추기·게이트

| 항목 | 답 | 설계 영향 |
|---|---|---|
| 5-1 진입 시점 | **입력 즉시 + 가져오기 직후** | ① 속성 입력 시 자동완성·상태 배지(LG-R03) ② 엑셀·DDL 가져오기 완료 시 표준 맞추기 일괄 화면 자동 오픈. 별도 메뉴 진입도 제공 |
| 5-2 처리 규모 | **업무 영역 단위 (수십 테이블)** | 일괄 화면 범위 기본값 = 현재 업무 영역. 4상태 필터·상태별 일괄 처리, 가상 스크롤까지는 불필요 |
| 5-3 게이트 예외 | **모델러가 사유 기록 → 모델 확정 결재에서 DA 검토** | 예외는 즉시 허용(사유 필수). 모델 확정 결재 상세에 "표준 예외 목록" 섹션 필수 표시 |
| 5-4 미등록 단어 기본 동작 | **후보 큐 등록** | 표준 맞추기의 "미등록 단어 포함" 항목 기본 버튼 = [후보 등록]. 모델 작업은 멈추지 않음. 직접 신청은 보조 메뉴 |
| 5-5 모델 확정 신청 조건 | **미준수 0건 (사유 있는 예외 제외)** | [확정 신청] 버튼은 미준수 0건일 때만 활성. 비활성일 때는 남은 미준수 건수와 [표준 맞추기 열기] 표시(비활성 사유 규칙) |
| 5-6 게이트 A 실행 시점 | **물리 모델을 열거나 동기화할 때** | 논리→물리 반영 직전 점검 패널(미매핑·타입 미정·엔터티 용어 미지정) → [예외 사유 입력] 또는 [표준 맞추기로 이동] |
| 5-7 준수율 표시 위치 | **모델 편집 화면 상단만** | 상단 바에 현재 업무 영역 준수율·미준수·예외·미산정 건수. 시스템 목록·기관 대시보드 준수율은 1차 범위 밖 |

## 7. 설계에 미치는 영향 요약

### 7.1 기존 설계 문서와 달라지는 결정

| 기존 | 변경 | 갱신할 문서 |
|---|---|---|
| 프로젝트별 사전 세트 선택(MD-40·41) | **기관 사전 1개 고정**(공통표준 + 기관). 표준 기준(DBMS·명명 템플릿)은 시스템 단위 | 30-metadata-design §2·§3.4 |
| 단일 결재(DA 또는 Admin), 자기 승인 허용 (Q-2) | **설정형 결재선**: 1단계 DA 필수 + 최종 승인(기관 담당자) 선택 — 사전은 기관 설정, 모델 확정은 시스템 설정. 참조자 지정. 자기 승인은 **사유 필수**. 앱 + 메일 알림 | 30 MD-20~22, 20-priority §3.2 Q-2 |
| 결재 대상 = 사전 신청 | **사전 신청 + 모델 확정** (게이트 예외는 결재 대상 아님 — 확정 결재에서 검토) | 30 §3.2, 20 Q-3 |
| 1차 DBMS 미결 (OQ-4) | **Oracle·PostgreSQL·Tibero·MySQL/MariaDB** | 20 §3.1 |
| DDL 리버스 W2 (RV-R01) | 현행 표준화와 신규 설계 비중이 같음 → **W1 상향 검토** | 20 W1/W2 표 |
| 준수율 표시 위치 미정 | **모델 화면 상단만**(대시보드 1차 제외) | 20 ST-R08 |

### 7.2 설계할 화면 목록 (흐름도·목업 대상)

| 영역 | 화면 | 핵심 입력 근거 |
|---|---|---|
| 공통 | 앱 셸(상단 바·좌측 내비: 사전 / 결재 / 시스템 > 업무 영역 / 설정), 알림 | 1-5, 4-8 |
