# U1 검토: Claude (커밋 b73a45f · 사용자 계정·인증)

> 대상: `git show b73a45f`(`app.js` USERS·인증 함수, `login.html`, `mypage.html`, `settings.html` 사용자·역할 탭)와 [14-user-account-auth.md](../14-user-account-auth.md)
> 방법: 코드만 읽고 판단했다(브라우저 미사용). 줄 번호는 지금 작업 사본 기준이다. 코드는 고치지 않았다.

## 총평

요청한 입력형 등록(회사·부서·이름·전화·이메일·ID/PW)과 "ID/PW 기본, SSO는 옵션" 구조가 잘 들어갔다.
- 칸별 오류 문구, `aria-invalid`, 첫 오류 칸으로 포커스
- 임시 비밀번호는 한 번만 보이고, 첫 로그인 때 바꾸게 함
- 마지막 Admin 보호, 본인 중지·역할 변경 금지
- 이력 있는 계정은 삭제 대신 중지
- 모든 변경을 감사 로그에 기록

관리자 흐름은 이해하기 쉽다.

보안에서 세 가지는 설계 단계에서 고쳐야 한다. 목업이라도 그대로 개발 사양이 되기 쉽다.
1. 로그인 판정 순서 때문에 **계정이 있는지 드러난다**(계정 열거).
2. 삭제한 ID를 다시 쓸 수 있다.
3. SSO만 모드로 바꿀 때 **비상 로그인할 Admin이 실제로 있는지** 확인하지 않는다.
