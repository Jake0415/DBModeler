# DBModeler 클릭 목업 r16 최종 확인

## 2. 새 상 발견

| ID | 화면 | 문제 | 재현 | 고칠 방향 |
|---|---|---|---|---|
| CX16-01 | T5·T8 모델 확정 | 시드에 추가된 연결로, 지도에서 안내한 0014를 마쳐도 0013이 최종 승인을 막는다(`assets/app.js:53,133`, `index.html:43,47`, `approvals.html:170,250–255`). | 초기화 → 기본 적용 → 남은 미준수 처리 → 모델 확정 신청 → 0014와 기본 적용에서 만든 용어 신청을 완료 → 모델 최종 승인. 0013이 진행 중이라 차단된다. | 제출 모델이 참조하는 선행 신청 전체를 완료할 수 있도록 지도와 확정 문서에서 연결한다. |
| CX16-02 | 모델 재진입 → 확정 신청 | 새로 연결된 시드 0013을 반려·회수한 뒤 편집 모델을 열면 연결만 지워지고 미승인 물리명 `DLVRBL_M`은 준수로 남는다. 그 뒤 제출하면 승인 재검사에서도 종료된 링크를 찾지 못한다(`assets/app.js:133,391–395`, `model.html:384–388,651–660,1127–1131`, `approvals.html:257`). | 초기화 → 0013 반려 또는 회수 → 편집 모델 열기 → 나머지 미준수와 연결 신청 처리 → 모델 확정 신청 및 승인. 산출물기본을 재처리하지 않아도 해당 엔터티는 통과한다. | 종료된 엔터티 용어 연결을 해제할 때 엔터티를 재처리 대상으로 돌리고, 재처리가 끝날 때까지 확정 신청을 막는다. |
| CX16-03 | 과거 확정본 → 시스템 전체 ERD | 미준수 집계에 테이블 물리명 누락이 추가되면서, 최신 작업본에 물리명 없는 엔터티만 추가한 경우에도 과거 확정본에서 연 전체 ERD 카드와 최신 작업본에서 연 카드의 미준수 수가 달라진다(`model.html:313–323,1104–1105,1120–1124`, `system.html:47,55–58`). | 모델을 확정하고 다음 버전을 시작 → 새 작업본에 물리명 없는 엔터티 추가 → 과거 확정본을 열고 [시스템 전체] 선택. 카드에는 새 작업 버전이 표시되지만 물리명 누락 1건은 반영되지 않는다. | 영역별 카드의 상태·버전·집계를 동일한 현재 사본에서 읽는다. |

## 3. 시나리오 T1~T10

- T1 통과 — 초기 적재에서 만든 문서로 자기 승인과 최종 반영에 도달한다.
- T2 통과 — 미등록 단어를 모델에서 후보로 등록하면 후보 큐에 표시된다.
- T3 통과 — 가져온 DDL을 새 영역에서 표준화하고 시스템 홈에서 영역을 열 수 있다.
- T4 통과 — 후보를 단어 신청으로 전환하고 승인한 뒤 모델을 재검토할 수 있다.
- T5 막힘 — 안내된 0014 완료 후에도 연결 신청이 남아 최종 확정에 도달하지 못한다(CX15-06, CX16-01).
- T6 통과 — 동시 수정·연결 끊김과 검토 중 조회 전용 경로가 이어진다.
- T7 통과 — 타인 승인, 사유가 있는 자기 승인, 최종 승인 역할 전환과 설정 권한 제한 경로가 이어진다.
- T8 막힘 — 연결 신청이 남아 확정본과 다음 작업 버전에 도달하지 못한다(CX15-06, CX16-01).
- T9 통과 — 정상 업로드에서 만든 문서로 승인·반영본·공표에 도달한다. 검색 범위의 잔여 문제는 CX14-05에 기록했다.
- T10 통과 — 검색, 403에서 역할 요청, 요청 역할 부여, 감사 로그, 로그인 후 복귀 경로가 이어진다.

## 4. 종료 가능 여부

종료 불가 — T5·T8이 막혀 있고, 엔터티 용어 재제출의 결재 규칙 위반과 화면 간 집계 불일치가 남아 있다.
