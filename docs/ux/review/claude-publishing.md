## 요약

부품별 한 곳으로 합치기, 상태 배지 하나(`tag()` → `.badge`), 12px 미만 0, 굵기 700 0, 문자 아이콘 정리는 확인됐다. P1에서 우선순위가 걸린 규칙을 표본으로 대조했는데 원래 마지막 값이 유지됐다(아래 "확인함").

문제는 네 가지다.
1. **점검 도구가 재는 범위가 좁고 부작용이 있다.** 버튼 부품만 세고, 처음 보이는 상태만 재며, `?as=`로 사용자 역할을 바꿔 놓는다.
2. **표 밀도(D1)가 모델 화면의 표에는 적용되지 않는다.**
3. **진행 중(파랑 채움)이 내 차례(파랑 테두리)보다 진하게** 보여 행동할 문서가 오히려 묻힌다.
4. **`!important` 유틸리티**가 4px 간격 규칙 밖의 값을 굳히고, 이름이 기존 클래스와 겹친다.

## 확인함 (문제 없음)
- **P1 합침 표본 대조**(옛 963줄 → 새 737줄, 같은 특정도·순서가 걸린 규칙)
  - 다크 `.btn.primary:hover #ccc`(옛 497 → 새 375)
  - 선택 행 `blue-100` + 다크 `blue-200`(옛 616-617 → 474-475), 첫 칸 2px blue-700 막대(옛 766 → 476)
  - `.modal .btn.danger`(옛 624·763의 마지막 값 red-800 → 381)
  - 입력 포커스 후광 `--focus-halo`(옛 761 → 403)
  - 토스트 150ms(옛 437 → 577 `tin .15s`)
  - 다크 빈 상태 아이콘(옛 768-769 → 505-506)
  - 탭 패딩 14px(옛 648 → 542)

  모두 옛 파일의 **마지막 값**과 같다. 바뀐 것은 `kbd` 글자 13 → 12px 하나다(P1 기록의 "차이 1건"으로 보인다).
- **12px 미만**: app.css·화면 HTML·app.js에서 `font-size:10/11px`, `font: … 1x px` 0건. 굵기 `b, strong` 600, `h1~h4` 600.
- **상태 배지**: `tag()`가 모두 `.badge` 계열로 그려지고 글자를 함께 쓴다(색만으로 전달하지 않음). 다크에서 `b-info`(#52a8ff on #10233d)·`b-warning`(#f2a20d on #331b00)·`b-mine`(테두리 blue-700, 글자 blue-900) 모두 글자 대비가 충분하다.
- **사전 탭 줄**: `nav aria-label="사전 화면"` + 링크 + `aria-current="page"`. 탭 역할을 흉내 내지 않아 맞다.
- **결재함 상세 패널**: `.rpanel`(wide 아님) → 420/380, D3와 같다.
- **유틸리티와 `hidden` 충돌**: `d-flex` 등 `!important` 표시 유틸리티가 `hidden` 속성 요소에 붙은 곳은 찾지 못했다.

결론: #1·#2(점검 도구의 부작용과 맹점), #3(밀도 미적용), #5(진행/내 차례 색 위계)를 고친 뒤 기준으로 확정하기를 권합니다.
