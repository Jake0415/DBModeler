## 높음

### UI-01 통합에서 [자동 배치]를 누르면 논리 배치가 겹친다
- 심각도: 높음
- 근거: `model.html:1609`(`setPos(e, 60 + c[0] * 380, 60 + c[1] * 250)`), `model.html:281`(통합이면 `x / SX`, `y / SY`로 나눔)
- 문제: 자동 배치 간격 380 · 250은 논리 노드(약 240px) 기준 값이다. 통합에서는 이 값이 배율로 나뉘어 저장되므로, SX가 2이면 논리 간격이 190이 되어 **논리 화면에서 노드가 겹친다**. 통합 화면에서도 노드 너비가 520px까지라 380 간격이면 겹친다. 자동 배치는 접속자 모두의 화면을 바꾸므로 피해가 크다.
- 고칠 방법: 통합에서 자동 배치를 할 때는 **논리 좌표로 바로 계산해서 저장**한다(`setPos`의 나누기를 거치지 않는 `setLogical(e, x, y)`를 따로 두기). 그다음 통합은 그 결과를 펼쳐 보여 준다. §7-1 “[자동 배치]도 같다”는 ‘결과가 논리에 저장된다’는 뜻으로 읽는 것이 맞다.

### UI-02 통합에서 물리 메모를 끌면 물리 화면의 메모 위치가 바뀐다
- 심각도: 높음
- 근거: `model.html:1301`(물리 메모는 `sx = sy = 1`로 `drag.memo.x/y`를 그대로 고침), `model.html:474`(물리 메모에도 `data-mdrag`가 붙음)
- 문제: §7-1 “물리 배치(px, py)는 통합에서 **절대** 바뀌지 않는다”를 어긴다. 사용자는 통합에서 옮긴 줄만 알고, 물리 화면에 가면 메모가 엉뚱한 곳에 가 있다. 알림도 없다.
- 고칠 방법: 통합에서 물리 메모는 **위치를 옮길 수 없게** 한다(`data-mdrag`를 빼고 커서는 기본 모양, 제목 줄에 ‘물리 화면에서 옮기세요’ 툴팁). 내용 고치기는 지금처럼 해도 된다.

## 중간

### UI-03 물리 메모를 물리 좌표 그대로 펼친 논리 배치 위에 두는 것은 맞지 않다 (검토 요청 3)
- 심각도: 중간
- 근거: `model.html:472`(`memoXY` — 물리 메모는 `m.x, m.y` 그대로), `model.html:474`
- 문제: 물리 좌표는 물리 배치에 맞춘 값이라, 펼친 논리 배치 위에서는 **아무 의미 없는 자리**다. 메모가 상관없는 노드를 가리거나, 다른 엔터티 옆에 붙어 잘못 읽힌다(“이 메모가 이 테이블 얘기인가?”).
- 고칠 방법: 통합에서는 물리 메모를 캔버스에 흩어 놓지 말고 **한곳에 모은다** — 캔버스 왼쪽 위에 ‘물리 메모 n’ 칩을 두고, 누르면 목록이 펼쳐지며 각 줄에 [물리에서 보기](물리로 바꾸고 그 메모로 이동)를 단다. 나중에 메모가 엔터티에 붙는 구조가 되면, 그 엔터티 옆에 두는 방식으로 바꾼다.

### UI-04 노드 하나의 크기가 바뀌면 캔버스 전체가 움직인다
- 심각도: 중간
- 근거: `model.html:463-471`(`render` 때마다 `spreadAfter`가 노드 최대 너비 · 높이로 SX · SY를 다시 계산하고, 0.04 넘게 바뀌면 다시 그림)
- 문제: 배율이 **가장 넓은 노드 하나 · 가장 긴 노드 하나**로 정해진다. 그래서 속성 추가(입력 칸 150px + ‘물리 → …’ 미리 보기), 이름 바꾸기, 속성 몇 개 추가만으로 그 노드가 최대가 되면 **모든 노드 위치가 한꺼번에 밀린다**. 편집 중에 화면이 출렁여 보고 있던 곳을 놓친다.
- 고칠 방법: 배율은 **통합으로 들어갈 때 · 영역(또는 보기)을 바꿀 때만** 계산하고, 통합에 있는 동안은 고정한다. 최대값 대신 90번째 백분위 너비 · 높이를 쓰면 튀는 노드 하나에 끌려가지 않는다(겹치는 몇 개는 감수하거나 [자동 배치]로 풀기).

### UI-05 논리 · 통합 모두 render마다 전체 노드를 다시 재서 300개 규모에서 느려진다
- 심각도: 중간
- 근거: `model.html:463-471`(논리에서도 `spreadAfter`가 돌아 `LW/LH`를 잼), `model.html:465`(LOD 클래스를 뺐다 넣어 전체 레이아웃을 강제로 두 번 계산)
- 문제: 선택 · 편집 · 확대 단계 바뀜 등 render가 불릴 때마다 노드 300개의 `offsetWidth/Height`를 읽고 LOD 클래스를 바꿔 **강제 레이아웃이 두 번** 일어난다. 이전에 노드를 바뀐 것만 갈아 끼워 150ms를 줄인 최적화(`model.html:491` 주석)를 되돌리는 셈이다. 논리 보기에도 회귀가 생긴다. IV-18 측정 대상이다.
- 고칠 방법: 재기는 UI-04처럼 정해진 때에만 한다. 논리 크기(LW · LH)도 그때 한 번만 잰다. LOD 클래스를 빼는 대신, 측정용으로 숨긴 견본 노드 몇 개만 그려 재는 방법도 있다.

### UI-06 선택이 없을 때 보기를 바꾸면 보던 곳을 잃는다
- 심각도: 중간
- 근거: `model.html:1617-1622`(`keep`이 있을 때만 `panX/panY` 보정)
- 문제: §7-1(IV-04)은 “선택한 엔터티와 **화면 가운데 위치**를 유지”다. 선택이 없으면 보정이 없어, 논리 → 통합에서 좌표가 최대 2.4배 커지므로 화면이 엉뚱한 곳으로 간다.
- 고칠 방법: 선택이 없으면 바꾸기 전 화면 가운데의 월드 좌표를 논리 좌표로 바꿔(통합이면 ÷SX · SY) 두고, 새 보기 좌표로 다시 바꿔(통합이면 ×SX · SY) 가운데에 맞춘다. 물리로 갈 때는 가운데에 가장 가까운 엔터티를 기준으로 삼는다.

### UI-07 통합에서 [점검 보기] → [경고 확인 후 계속]을 누르면 물리로 넘어간다
- 심각도: 중간
- 근거: `model.html:100`(통합에서도 `b-gate` 보임), `model.html:150`(`gate-go` ‘경고 확인 후 계속’), `model.html:1650`(`gate-go`는 무조건 `setMode('P')`)
- 문제: 통합 사용자가 경고 목록을 보고 ‘계속’을 누르면, 뜻하지 않게 **물리 보기로 바뀐다**. 패널 제목 ‘물리 반영 전 점검’ · 설명도 통합 맥락과 맞지 않는다. 결정 4(통합으로 갈 때 창 없음)의 취지가 흐려진다.
- 고칠 방법: 통합에서 연 점검 패널은 아래 버튼을 [닫기]로 두고, 옆에 [물리로 열기]를 따로 둔다. `gate-go`는 지금 보기가 통합이면 보기를 바꾸지 않게 한다.

### UI-08 표 보기에서 물리명으로 찾은 행은 [보이는 행 바꾸기]로 바뀌지 않는다
- 심각도: 중간
- 근거: `model.html:1038`(통합이면 `a.p`로도 행을 찾음), `model.html:1085-1087`(바꾸기는 `a.n.includes(fv)`만 처리)
- 문제: ‘보이는 행 12건’이라 보여 주고 버튼도 켜지지만, 물리명으로만 걸린 행은 실제로 바뀌지 않는다. 결과 알림 숫자가 화면 숫자와 달라 사용자가 무엇이 빠졌는지 모른다.
- 고칠 방법: 바꾸기 칸이 열려 있으면 찾기는 **논리명만** 대상으로 한다고 안내하고(placeholder ‘찾기 (논리명) — 바꾸기는 논리명만’), 물리명으로만 걸린 행 수를 따로 보여 준다(‘물리명으로 찾은 3건은 바꾸지 않음 — 물리명은 용어에서 만들어집니다’).

### UI-09 엔터티 이름을 바꿀 때 물리명 미리 보기가 없다
- 심각도: 중간
- 근거: `model.html:452`(`ren-in` 입력 칸에 미리 보기 없음) ↔ `model.html:446`(속성 입력 칸에는 `.pv` 있음)
- 문제: §7-2(IV-06)는 “캔버스에서 이름을 바꾸면(두 번 클릭 · F2) 논리명, 입력하는 동안 물리명 자리에 자동 변환 결과를 미리”다. 속성만 되고 엔터티 제목(테이블명)은 안 된다. 테이블명이 가장 중요한 물리명이다.
- 고칠 방법: 통합에서 `ren-in` 옆(노드 머리의 `.sub` 자리)에 ‘물리 → XXX_M’을 `aria-live="polite"`로 보이고, `input` 이벤트에서 `decompose(v).abbr` + 분류어 접미로 갱신한다.

### UI-10 노드 줄의 낭독 순서가 규칙과 다르다
- 심각도: 중간
- 근거: `model.html:449`(줄에 `aria-label` 없음, 글자 순서 ‘# 논리명 (FK) 물리명 타입’)
- 문제: §7-5(IV-17)는 낭독 순서를 ‘논리명, 물리 물리명, 타입, PK’로 정했다. 지금은 화면 읽기 프로그램이 ‘샵 사원번호 괄호 FK EMP_NO VARCHAR2(10)’처럼 읽어 어떤 값이 무엇인지 알기 어렵다.
- 고칠 방법: 통합 줄에 `aria-label="사원번호, 물리 EMP_NO, VARCHAR2(10), PK, FK"`를 달거나, ‘#’와 ‘(FK)’는 `aria-hidden`으로 감추고 물리명 앞에 `<span class="sr-only">물리</span>`, 끝에 PK · FK를 `sr-only`로 붙인다.

### UI-11 엔터티 패널의 서브타입 설명에 ‘한 테이블로 통합’이 남아 있다
- 심각도: 중간
- 근거: `model.html:922`(`물리 변환: 한 테이블로 통합(기본)`)
- 문제: §7-4(IV-15)는 ‘통합’ 보기와 헷갈리지 않게 ‘합침’으로 바꾸기로 했다. 노드 안 문구는 바꿨지만 오른쪽 패널 ‘엔터티’ 탭 문구는 그대로라, 통합 보기에서 ‘통합(기본)’이 다른 뜻으로 읽힌다.
- 고칠 방법: ‘물리 변환: 한 테이블로 합침(기본)’으로 바꾼다. 같은 말이 `ddl.html` 등 다른 화면에도 있는지 한 번에 찾아 맞춘다.

### UI-12 긴 물리명 · 타입이 노드 밖으로 넘친다
- 심각도: 중간
- 근거: `assets/model.css:51`(`.ar`는 `white-space:nowrap`), `assets/model.css:267-268`(통합 노드 `max-width:520px`, `.pp`에 줄임 처리 없음)
- 문제: 논리명 + 물리명 + 타입 세 열이 한 줄이라, 긴 이름(예: ‘산출물검수이력상세’ + `DLVRBL_INSP_HIST_DTL_SN` + `NUMBER(10)`)은 520px를 넘어 노드 테두리 밖으로 삐져나오거나 옆 노드와 겹친다. 1920 화면에서 노드가 많을 때 가장 먼저 눈에 띄는 문제다.
- 고칠 방법: `.n`과 `.pp`에 `min-width:0; overflow:hidden; text-overflow:ellipsis`를 주고 잘린 줄에는 `title`로 전체 이름을 보인다. 타입 열(`.p`)은 줄이지 않는다.

## 낮음

### UI-13 통합에서 오른쪽 패널 탭 이름이 ‘테이블’이다
- 근거: `model.html:918`(`mode === 'L' ? '엔터티' : '테이블'`)
- 고칠 방법: 통합이면 ‘엔터티 · 테이블’로 쓴다(IV-13 — ‘속성 · 컬럼’과 맞춤).

### UI-14 노드 머리에서 테이블명이 없으면 ‘—’만 보인다
- 근거: `model.html:460`(`.sub`에 `e.p`를 그대로 출력)
- 고칠 방법: 통합에서 `e.p === '—'`이면 ‘— 미매핑’(기울임, `.um`)으로 보인다. 줄과 같은 규칙(IV-17, 흑백 인쇄).

### UI-15 ‘미매핑 n’ 배지가 회색이라 눈에 덜 띈다
- 근거: `assets/model.css:272`(`gray-200` 바탕 · `fg-2` 글자) ↔ ‘미준수’는 주황(`:43`)
- 문제: 결정 4로 창이 없으니 배지가 거의 유일한 신호인데, 멀리서(LOD low) 보면 일반 표시처럼 보인다.
- 고칠 방법: 게이트 띠와 같은 주황 계열 테두리(바탕은 연하게)로 하거나 앞에 경고 아이콘을 붙인다. ‘미준수’와 구별되게 모양(테두리만)으로 나눈다.

### UI-16 관계선 ‘FK 누락’에 이유가 안 보인다
- 근거: `model.html:566`(`fkOf`의 `why`를 쓰지 않음)
- 고칠 방법: `<text>` 안에 `<title>${fk.why}</title>`를 넣어 마우스를 올리면 ‘부서기본 PK 물리명 없음’처럼 보이게 한다. 관계 이름이 비어 있으면 FK 이름표를 13px 아래가 아닌 원래 자리에 둔다.

### UI-17 통합에서 끌면 논리 배치가 8px 격자에서 벗어난다
- 근거: `model.html:1302`(통합 좌표로 8에 맞춘 뒤), `model.html:281`(SX로 나눔)
- 고칠 방법: 나눈 다음 논리 좌표를 8에 맞춘다(`Math.round(x / SX / 8) * 8`). 그래야 논리 화면에서 정렬이 깨지지 않는다.

### UI-18 처음 옮김 알림이 자동 배치 알림과 겹치고, 새로 고침마다 다시 나온다
- 근거: `model.html:282`(`aMoveTold`는 페이지 변수), `model.html:1609`
- 고칠 방법: 알림 여부를 `dbmStore`에 사용자별로 저장하고, 자동 배치에서는 자동 배치 알림 한 줄에 ‘논리 배치에도 반영’을 합친다.

### UI-19 마지막 보기가 ‘물리’면 게이트 A를 건너뛴다
- 근거: `model.html:1633`(`m0 === 'P'`이면 `gateSeen = true`)
- 문제: §7-3(IV-12)은 ‘물리로 갈 때 창, 그 세션에서 이미 열었으면 생략’이다. 새 세션인데 생략된다. 띠는 보이므로 크지는 않다.
- 고칠 방법: 기억한 보기로 열 때 띠는 보이고, 경고가 있으면 띠를 한 번 강조(깜빡임 없이 굵게)한다. 또는 이 예외를 28 §7-3에 적어 둔다.

### UI-20 Alt+1/2/3이 macOS에서 안 된다
