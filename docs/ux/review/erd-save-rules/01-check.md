# ERD 저장 · 검사 · 이동 · 결재 규칙 — 현재 시나리오 점검 (2026-11-27)

> 대상 규칙(사용자 2026-11-27)
> 1. 편집하면 자동 저장 — 카드 이동 · 컬럼 수정 · 복합 FK 연결을 **마친 뒤** 작업본 저장. 중복 이름 · 미완성 FK · 표준 미준수가 있어도 작업본을 남김.
> 2. ERD 화면에서 언제든 검사 — 자동 저장을 기다리지 않고 **화면에 적용된 편집본**의 구조 오류 · 표준 준수 확인, 오류를 고르면 해당 테이블 · 컬럼으로 이동.
> 3. 다른 모델로 이동했다가 이어서 작업 — **서버 저장 또는 브라우저 복구 사본 보관이 확인되면** 오류가 있어도 이동, 서버에 저장되지 않았으면 화면에 **복구 사본의 보관 위치** 표시.
> 4. 결재할 때 검증한 버전을 고정 — 신청 시 **구조 · 표준 · 논리 · 물리 동기화** 검사, 최종 승인 시 **같은 신청본을 최신 기준으로** 다시 확인.
>
> 근거: 목업 `model.html` · `approvals.html` · `assets/app.js` 코드, 설계 `docs/arch/01-backend-architecture-v1.md` §13.1.

## 요약
| 규칙 | 판정 | 핵심 |
|---|---|---|
| 1 자동 저장 · 오류 있어도 저장 | **대체로 맞음 · 설계 문서 충돌 1** | 목업은 편집마다 자동 저장하고 저장 때 검사로 막지 않음. 그러나 설계 §13.1 ‘쓰기 검증’이 **중복 이름(모델 불변식)을 서버에서 거부**하도록 적혀 있어 규칙 1과 반대 |
| 2 언제든 검사 · 오류로 이동 | **맞음 · 보완 1** | [모델 검증] 패널이 메모리의 현재 편집본으로 판정하고, 항목을 누르면 테이블 · 컬럼으로 이동. 단 ‘논리 · 물리 동기화’ 항목이 없음(규칙 4와 같은 빈틈) |
| 3 이동 · 복구 사본 | **없음(빈틈)** | 화면을 떠날 때 저장 확인 · 복구 사본 · 보관 위치 표시가 전혀 없음. 저장 실패 · 충돌 · 권한 회수 상태에서 이동하면 편집이 사라짐. ‘연결 끊김’ 띠의 “브라우저에 보관하고 병합” 문구는 실제 동작 없는 약속 |
| 4 신청 고정 · 최종 승인 재확인 | **대체로 맞음 · 빈틈 1** | 신청 시 사본 고정(해시) · 검수 기준 버전 저장, 승인 때(DA · 최종 모두) 같은 사본을 오늘 기준으로 재검사. 단 **논리 · 물리 동기화 검사가 없음**(‘논리 변경 n건 대기’ 띠는 숫자가 고정된 시연용) |

## 규칙별 상세

### 규칙 1 — 자동 저장
| 확인 | 현재 | 판정 |
|---|---|---|
| 편집마다 자동 저장 | `snap()`이 dirty를 켜고 그리기(`render`) 끝에 `saveData()` (model.html:425 · 520). 카드 끌기 · 컬럼 수정 · 정의 입력 모두 같은 경로 | 맞음 |
| ‘마친 뒤’ 저장 | 복합 FK · 관계 연결은 중복 해소 창이 떠 있는 동안 저장을 보류(`holdSave`)하고 확정 때 한 번에(298 · 765). 입력 중인 속성 · 이름 없는 새 엔터티는 저장본에서 뺌(310) | 맞음 |
| 오류가 있어도 저장 | `saveData()`는 구조 · 표준 검사를 하지 않음(299~316). 편집기도 중복 이름을 막지 않음(이름 바꾸기 `commitRename`) | 맞음 |
| 저장 실패 | ‘저장 안 됨 + 다시 시도’, 편집은 화면에 남음(313 · 319) | 맞음 |
| **설계 문서** | arch §13.1 ‘쓰기 검증’에 **모델 불변식(엔터티 안 컬럼 물리명 유일 · 테이블/엔터티명 유일)을 갱신 전에 검사해 거부**한다고 적힘(고객 요청 M-1 때 넣음) | **충돌 — 고쳐야 함** |
| 예외(의도) | 엑셀 가져오기 · 엑셀 값 고르기(xDiff)는 새 중복을 만들면 막음 — 편집 저장이 아니라 일괄 반영이라 유지해도 됨(문서에 구분 명시) | 확인 |

## 고칠 것 (제안)

### A. 설계 · 문서 (규칙 1)
- **A-1** arch §13.1 ‘쓰기 검증’: 갱신 거부는 **참조 무결성 · 문서 구조 손상**(지운 엔터티를 가리키는 관계, 참조 사본 수정, 형식 오류)만. **중복 이름 · 미완성 FK · 표준 미준수는 저장 허용**, 모델 불변식은 `modelCheck`의 ‘막음’으로 **신청 · 승인 단계에서만** 막음. 엑셀 가져오기 · 일괄 반영은 별도 규칙(새 중복을 만들면 막음)으로 구분해 적기.
- **A-2** 02-flows · 03 · 18에 규칙 1 ~ 4 문장을 그대로 ‘저장 · 검사 원칙’ 절로.

### B. 논리 · 물리 동기화 (규칙 2 · 4)
- **B-1** `modelCheck`에 ‘논리 · 물리 동기화’ 묶음: 물리에 아직 반영 안 된 논리 변경(이름 · 타입 · 키 · 관계 · 엔터티 추가/삭제) 건수 · 위치, 물리명 미정 · 타입 미정(지금 게이트 A 경고)과 함께. 신청 시 **막음**(물리 반영 전에는 DDL이 틀리므로), 편집 중에는 경고.
- **B-2** 물리 보기의 ‘논리 변경 n건 대기’ 띠를 실제 계산으로, [물리에 반영] · [변경 보기]가 같은 목록을 씀. 검증 항목을 누르면 그 테이블 · 컬럼으로.

### C. 이동 · 복구 사본 (규칙 3)
- **C-1** 저장 상태 4단계를 화면 상단 저장 표시에 명시: ‘저장됨(서버)’ / ‘저장 중’ / ‘브라우저에 보관됨(서버 미저장)’ / ‘저장 안 됨’.
- **C-2** 서버 저장이 확인되지 않은 편집(저장 실패 · 연결 끊김 · 충돌 · 권한 회수 · 중복 해소 창 대기)은 **브라우저 복구 사본**(사용자 · 영역 · 버전 · 기준 리비전 · 시각, IndexedDB/로컬 저장)에 즉시 보관.
- **C-3** 다른 모델로 이동(트리 · 왼쪽 칸 · 링크 · 탭 닫기)할 때: 서버 저장 확인 → 그냥 이동 / 복구 사본 보관 확인 → 이동 + 토스트 ‘서버에 저장되지 않은 편집 n건을 이 브라우저에 보관했습니다 — 보관 위치: 마이페이지 › 복구 사본(영역 · 버전 · 시각)’ / 둘 다 실패 → 이동 전 확인 창(‘보관하지 못했습니다 — 머무르기 · 버리고 이동’). 오류(구조 · 표준)는 이동을 막지 않음.
- **C-4** 그 모델을 다시 열 때 복구 사본이 있으면 띠: ‘서버에 저장되지 않은 편집이 이 브라우저에 있습니다(시각 · n건) — [비교] · [적용] · [버리기]’. 서버본이 그 사이 바뀌었으면 [비교] 먼저(덮어쓰기 금지).
- **C-5** 마이페이지에 ‘복구 사본’ 목록(영역 · 버전 · 시각 · 상태, 열기 · 지우기). 확정 · 신청으로 버전이 잠기면 해당 사본은 ‘적용 불가 — 새 버전에서 비교’로.
- **C-6** 연결 끊김 띠 문구를 실제 동작(C-2 · C-4)에 맞추기.
- **C-7** 설계 §13.1에 ‘클라이언트 복구 사본’ 절(보관 시점 · 키 · 보존 기간 · 개인정보(브라우저 저장)) 추가, 시나리오(S-05 동시 편집 근처)에 ‘저장 실패 → 다른 모델 이동 → 복귀 → 복구’ 추가.

### D. 결재 (규칙 4)
- **D-1** 신청 차단 목록에 B-1 동기화 ‘막음’ 포함, 신청 사본의 `check`에 동기화 결과 저장, 승인 재검사도 같은 묶음.
- **D-2** 결재 검사 탭에 ‘신청 시점 · 오늘 기준’ 비교를 동기화 항목까지 표시(지금은 막음 · 경고 수만).
