# NeoDB UX 목업 코드 리뷰 — 속성 편집 그리드 · 모델 트리 T2 메뉴

검토 대상은 `a562ebb`, `6c37672`와 설계 16, 12 §4.3·§9.2다. 심각도는 목업에서 저장되는 모델과 생성 DDL에 미치는 영향을 기준으로 매겼다. 근거는 소스 추적과 Node.js에서 실행한 함수 단위 재현이다. 브라우저와 낭독기의 실제 동작은 검증 범위에 포함하지 않았다.

## 1. 높음 · 복합 FK가 잘못된 부모 컬럼을 참조할 수 있음

- **위치** `model.html:agMove`, `assets/app.js:fkOf`, `ddl.html:119`
- **문제** 관계 그룹의 자식 컬럼과 부모 PK를 각각 배열 순서로 읽어 위치로 대응시킨다.
- **재현 또는 근거** 그룹 FK `(ORG_A, ORG_B)`가 부모 PK `(A, B)`를 받는 상태에서 부모 PK 순서를 `(B, A)`로 바꿨다. 실제 `fkOf`는 `ok`와 함께 자식 `(ORG_A, ORG_B)`, 부모 `(B, A)`를 반환했다. DDL은 두 목록을 그대로 출력한다. 자식 FK만 순서를 바꿔도 대응이 틀어진다.
- **권장 수정** 관계 그룹에 부모 속성별 대응을 저장하고, 부모 PK 순서에 맞춰 자식 컬럼 목록을 구성한다. 대응이 빠지거나 중복되면 FK 누락으로 표시한다.

## 2. 높음 · 역할명 FK와 재귀 FK가 PK 변경 영향에서 빠짐

- **위치** `model.html:655–675`, `assets/app.js:229–248, 391–399`
- **문제** 전파와 영향 계산이 재귀 관계를 건너뛰고, 컬럼 매칭은 원래 이름과 `ORG_` 접두사만 인정한다. 반대로 비그룹 `fkOf`는 `ORG_`조차 인정하지 않는다.
- **재현 또는 근거** 부모 `A`, 그룹 FK `FROM_A`, 같은 엔터티의 재귀 FK `UP_A`를 넣고 실제 `pkReach`를 실행하면 영향이 0건이다. 그룹 FK는 변경 전 `fkOf`에서 정상일 수 있지만, 부모의 PK 해제·삭제 후 자식 컬럼이 남는다. 비그룹 관계는 PK 전파 중 이름이 충돌해 `ORG_A`가 생성돼도 `fkOf`가 `A`만 찾는다.
- **권장 수정** 기존 그룹·역할명 FK를 부모 속성에 연결하고, 전파·해제·삭제·DDL이 같은 대응을 사용하게 한다. 재귀 FK도 해당 엔터티의 종속 컬럼으로 처리하며 동일 대응의 재방문만 차단한다.

## 3. 높음 · 두 식별 경로가 같은 엔터티를 지나면 손자 전파가 누락됨

- **위치** `model.html:pkReach`, `model.html:pkSpread`
- **문제** 방문 여부를 엔터티 ID 하나로 기록해, 같은 엔터티의 서로 다른 식별 FK를 한 경로로 취급한다.
- **재현 또는 근거** 부모 `A`가 두 식별 관계로 자식 `A`와 `ORG_A`에 들어가고, 자식의 두 PK가 손자의 `A`와 `ORG_ORG_A`로 내려가는 예를 구성했다. 실제 `pkReach` 결과에는 자식 FK 두 개와 손자 `A`만 있었다. `pkSpread`에도 같은 방문 조건이 있다.
- **권장 수정** 관계와 속성의 대응 단위로 순회하고 중복 처리를 막는다. 동일 자식으로 가는 복수 식별 관계와 합류 경로를 검증한다.

## 4. 중간 · ‘일반 속성으로 유지’를 선택해도 자식 FK가 PK에 남음

- **위치** `model.html:agDel`, `model.html:agPkOff`
- **문제** 유지 분기가 `fk`와 `fkg`만 제거한다. 식별 관계에서 내려온 컬럼은 PK로 남고, 관계까지 삭제할 때 남은 같은 그룹 FK에도 같은 처리가 적용된다.
- **재현 또는 근거** 차입금기본에서 속성을 PK로 지정한 뒤 차입금상환내역에 전파된 식별 FK를 확인한다. 부모 PK를 끄고 [자식 FK는 일반 속성으로]를 선택하면 자식의 PK 체크와 DDL의 PRIMARY KEY 구성에 해당 컬럼이 남는다. 설계 16 §3.2의 선택 문구와 결과가 다르다.
- **권장 수정** 일반 속성 전환 시 PK도 해제하고 일반 속성 묶음으로 옮긴다. 필수 여부를 유지할지도 동작과 문구에 명시한다.

## 5. 높음 · T2 관계 전환이 PK 순서와 하위 FK를 갱신하지 않음

- **위치** `model.html:runTreeCmd`, `model.html:1311`
- **문제** T2의 식별/비식별 전환이 연결하는 기존 핸들러는 바로 아래 자식 FK의 플래그만 바꾼다.
- **재현 또는 근거** 자식 배열 끝에 비식별 FK가 있고 자식에게도 하위 관계가 있는 경우, T2에서 식별로 전환하면 배열 끝의 FK가 PK가 된다. 기존 일반 속성보다 뒤에 남고, 손자에 새 PK의 FK가 생기지 않는다. 반대 전환 역시 손자에 남은 FK를 정리하지 않는다.
- **권장 수정** 관계 전환에서 PK 배치와 하위 영향 계산을 그리드의 PK 편집과 공유하고, 전환 전체를 한 번의 실행 취소로 되돌릴 수 있게 한다.

## 6. 높음 · 속성 이름 변경이 FK 대응과 도메인 고정을 깨뜨림

- **위치** `model.html:lockWhy`, `model.html:agRename`, `model.html:commitAttr`
- **문제** 용어를 선택하는 이름 변경은 물리명·타입·도메인을 덮어쓰면서 연결된 컬럼을 갱신하지 않는다. FK의 도메인 고정도 이 경로에는 적용되지 않는다.
- **재현 또는 근거** 이름으로 매칭하는 관계의 부모 PK를 F2로 열고 물리명이 다른 용어를 선택하면 자식은 기존 이름을 유지해 `fkOf`가 누락으로 판정한다. FK 자체를 F2로 바꿔도 같은 문제가 생기며, 그룹 관계에서는 부모와 자식 타입이 달라져도 `fkOf`의 개수 검사를 통과한다.
- **권장 수정** PK 이름 변경에 관계 대응과 타입·도메인 갱신을 포함한다. FK의 역할명 변경을 허용하는 경우 부모 대응과 상속 필드를 유지한다.

## 7. 높음 · 트리 명령이 다른 버전 또는 다른 배열 위치의 객체를 편집함

- **위치** `assets/app.js:src/editWhy/runCmd`, `model.html:1429, 1560–1588`
- **문제** 트리에서 편집 대상으로 넘기는 정보가 엔터티 ID와 `ai`·`rel` 인덱스에 그친다. 명령 출처의 버전과 스냅숏은 전달하지 않는다. `gPend`도 확인할 대상을 인덱스로 보관한다.
- **재현 또는 근거** DDL·산출물의 과거 확정본 트리에서 현재 작업 중인 영역의 속성을 삭제하면, 메뉴는 사본의 인덱스를 현재 작업본에 전달한다. 두 버전에서 같은 위치의 컬럼이 다르면 다른 컬럼이 대상이 된다. 작업본에서도 대상 앞의 입력 중 줄을 시작 시 제거하면 같은 문제가 발생한다. 배열 재현에서 앞의 입력 행을 제거한 직후 기존 인덱스가 그다음 컬럼을 가리켰다. 관계 배열 역시 `R[d.rel]` 존재만 확인한다.
- **권장 수정** 편집 명령과 보류 확인에 속성·관계의 안정적인 식별자 및 출처 버전 정보를 포함한다. 대상이나 버전이 달라졌으면 최신 작업본에서 해당 대상을 다시 선택하게 한다.

## 8. 높음 · 이미 열린 모델의 권한 회수와 이름 저장 시점을 재검사하지 않음

- **위치** `assets/app.js:39–42, 99, 586, 1186–1197, 1236–1239`, `model.html:guard/saveData/commitAttr/commitRename`
- **문제** 메뉴 선택은 열 때 계산한 `it.why`를 재사용한다. 모델의 `guard`는 새 결재 상태와 사용자 ID 변경을 검사하지만 동일 사용자 ID에서 다른 탭이 회수한 편집 역할·담당 시스템은 다시 읽지 않는다. 이름 편집을 연 뒤 실제 저장하는 함수에도 `guard` 호출이 없다.
- **재현 또는 근거** 설정은 `dbm-users`에 변경한 권한을 저장한다. 이미 열린 탭의 `can`은 시작 시 로드한 사용자 객체를, `guard`와 `saveData`는 시작 시 결정한 `viewOnly`를 사용한다. 사용자 ID와 버전이 그대로면 권한을 회수한 뒤에도 해당 탭에서 저장 경로에 도달한다. 유효한 제출본·확정본이나 처음부터 조회 전용인 계정의 직접 `?cmd=` 편집은 모델의 가드에 걸리는 것을 소스에서 확인했다.
- **권장 수정** 메뉴 실행과 실제 모델 변경·저장 시점에 최신 권한과 잠금을 공통 검사한다. 이름 입력을 이미 열었다면 금지 상태에서 커밋을 막고 입력을 정리한다.

## 9. 중간 · 실행 취소 토스트가 이후 변경을 되돌릴 수 있음

- **위치** `model.html:424, 505–518, 1229–1234`
- **문제** 토스트는 작업의 식별자 대신 이력 길이로 해당 작업이 최신인지 판단한다. Esc 입력 취소도 입력 시작 당시의 이력 항목 대신 현재 마지막 항목을 무조건 제거한다.
- **재현 또는 근거** 실제 `undoAction`을 50개 이력으로 실행한 뒤 새 작업을 넣고 가장 오래된 이력을 빼면 길이가 그대로다. 먼저 만든 토스트가 새 작업을 취소하는 것을 확인했다. 소스상 입력 중 다른 작업이 이력을 추가하면 Esc의 `hist.pop()`도 그 다른 작업의 항목을 제거한다.
- **권장 수정** 이력 항목에 고유 ID를 붙여 토스트의 대상을 확인한다. 미완료 입력의 이력을 실제 커밋과 연결하고 Esc는 해당 입력에 대응하는 항목만 정리한다.

## 10. 중간 · 정의·기본값 저장이 다음 클릭을 잃게 함

- **위치** `model.html:agEdit`, `model.html:795–814`, `model.html:panel`
- **문제** 상세 입력의 `change`에서 패널 전체를 다시 그려, 방금 누른 후속 컨트롤을 클릭 완료 전에 교체한다.
- **재현 또는 근거** 정의를 바꾼 뒤 같은 상세의 [삭제]나 다른 행을 바로 누르는 경로다. 기존 입력이 포커스를 잃을 때 `change → agEdit → render → panel`이 실행되고, 위임된 클릭 핸들러가 참조할 기존 버튼·행이 교체된다.
- **권장 수정** 정의·기본값의 저장에서는 입력 주변 DOM을 유지하고, 후속 포커스 이동이나 클릭이 완료된 뒤 필요한 부분을 갱신한다.

## 11. 중간 · 그리드에서 키보드만으로 필수·도메인을 편집할 수 없음

- **위치** `model.html:attrGrid`, `model.html:815–831`
- **문제** 두 편집 컨트롤 모두 Tab 순서에서 제외됐고, 행 단축키는 PK·이동·이름·삭제·추가·정의만 다룬다. 행에 Tab으로 진입해도 첫 행이 선택되지는 않아 처음 Enter는 행 선택에만 쓰인다.
- **재현 또는 근거** Tab으로 행에 들어가 방향키로 편집 가능한 행을 선택해도 해당 행의 필수 체크박스와 도메인 선택으로 포커스를 옮기는 구현이 없다. 설계 16 §4는 행 단축키를 키보드 편집 경로로 안내한다.
- **권장 수정** 행 포커스 하나를 유지하면서 셀 편집 모드로 들어가고 나오는 경로를 제공하거나, 선택 행의 편집 가능한 칸을 Tab 순서에 포함한다. 행 포커스와 선택도 동기화한다.

## 12. 중간 · 메뉴의 마우스·키보드 접근 경로가 포커스 모델과 어긋남

- **위치** `assets/app.js:1121, 1166–1178, 1261–1289`
- **문제** ⋯는 프로그램과 마우스로 포커스 가능한 버튼인데 `aria-hidden="true"`다. 트리 행에는 메뉴 팝업 상태가 없고, 스크롤·크기 변경으로 `closeMenu(false)`가 실행되면 메뉴 포커스의 복귀 대상이 없다. 바로가기 링크에서 Shift+F10·메뉴 키도 `preventDefault()`를 먼저 호출해 브라우저 기본 메뉴를 막는다.
- **재현 또는 근거** 생성 DOM과 키 핸들러에서 확인했다. 메뉴 자체는 `role=menu`와 비활성 이유를 제공하고 Esc·Tab·←는 트리 행으로 복귀시킨다.
- **권장 수정** ⋯를 행의 마우스용 표시로 처리하고 트리 행을 식별 가능한 메뉴 트리거로 노출한다. 메뉴가 포커스를 가진 채 스크롤·크기 변경으로 닫히면 해당 행으로 돌려보내고, 링크에서는 기본 메뉴 키를 소비하지 않는다.

## 13. 낮음 · 영향 확인과 목업 표시가 실제 동작보다 넓게 안내함

- **위치** `model.html:agPend/agRestore`, `assets/app.js:menuOf/openMenu`
- **문제** 확인 띠의 초기 포커스가 첫 번째 실행 버튼에 놓이며 자식 FK 삭제가 첫 버튼인 경우가 있다. 또한 [FK 만들기] 목업은 그리드에서 FK 컬럼을 맞추라고 안내하지만 그리드에는 FK 대응을 지정하는 칸이 없다. 전체 보기의 [보기에서 빼기]는 비활성 대신 실행 가능한 목업 항목 모양으로 나타난다.
- **재현 또는 근거** PK 해제 확인 띠에서 `agRestore`가 첫 번째 `[data-pend]`인 [자식 FK도 삭제]를 선택한다. `menuOf`는 [보기에서 빼기]에 `mock`만 지정하고, `openMenu`는 `why`가 있을 때만 비활성으로 노출한다. 설계 16 §7은 역할명 FK를 맞추는 칸을 후속 범위로 기록한다.
- **권장 수정** 영향 확인의 초기 포커스를 취소에 두고 선택지 순서와 표현을 캔버스 확인과 맞춘다. 전체 보기에서 금지된 명령은 이유와 함께 비활성화하고, FK 목업은 현재 지원하는 조치만 안내한다.

## 14. 중간 · 정의가 테이블 정의서와 기존 테이블의 ALTER 출력에 반영되지 않음

- **위치** `outputs.html:108`, `ddl.html:109–115`, 설계 16 §3.5
- **문제** 정의서 미리보기는 `desc`를 읽지 않는다. DDL은 비교 기준에 이미 있는 테이블의 ALTER 분기에서 조기 반환하므로 정의와 기본값 변경이 출력되지 않는다.
- **재현 또는 근거** 기존 테이블 속성의 정의와 기본값만 변경하면 CREATE 미리보기에는 `DEFAULT`와 컬럼 COMMENT가 생성되지만, 확정본 대비 ALTER 분기는 이름·타입 변화와 새 컬럼만 검사한다. 해당 분기의 새 컬럼 ADD에도 기본값이 없다.
- **권장 수정** 정의서의 컬럼 설명에 `desc`를 연결한다. ALTER에는 기존·신규 컬럼의 기본값 설정과 기존 값 해제, 변경·삭제한 컬럼 주석의 출력을 반영한다.

## 15. 낮음 · 논리명에 작은따옴표가 있으면 컬럼 COMMENT 문이 깨짐

- **위치** `ddl.html:92, 115`, `model.html:commitAttr`
- **문제** COMMENT의 문자열에 붙는 정의만 SQL 작은따옴표를 이스케이프하고 논리명에는 HTML 이스케이프만 적용한다.
- **재현 또는 근거** 유효한 물리명이 있는 기존 속성을 `O'Brien`으로 이름을 바꾼다. 용어 없이 입력하면 물리명은 유지된다. 주석 포함 CREATE는 `IS 'O'Brien'` 형태를 출력한다. 정의에 입력한 작은따옴표는 두 개로 바뀐다.
- **권장 수정** 논리명과 정의를 합친 전체 주석 문자열에 SQL 리터럴 이스케이프를 적용하고, 화면 출력용 HTML 이스케이프도 적용한다.
