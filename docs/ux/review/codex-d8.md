# NeoDB 목업 셸 재설계 d8 검토

기준은 [메뉴 재설계·브랜드 계획](../11-navigation-brand-plan.md)과 사용자 결정 네 가지다. 목업 변경분과 관련 기존 코드를 정적으로 대조했다. Edge 헤드리스 실행은 환경 권한 오류로 종료되어 1600px 렌더와 겹침은 CSS와 DOM 구조로 판단했다.

## 일치한 항목과 1600px 점검

- 로고의 연결된 N, 홈 링크와 접근 가능한 이름, SVG 파비콘을 확인했다. 홈과 모델 계열은 왼쪽 트리를 쓰고, 사전 계열·결재함·설정·감사 로그·마이페이지는 단일 열 전체 폭을 쓴다. [app.js:604](../mockups/assets/app.js#L604), [app.js:717](../mockups/assets/app.js#L717), [app.js:743](../mockups/assets/app.js#L743), [app.css:773](../mockups/assets/app.css#L773)
- 활성 탭은 DDL·산출물·표준 맞추기·DDL 가져오기가 `model`, 업로드 이력이 `excel`, 변경 내역이 `dictionary`인 실제 `data-page` 값을 사용하므로 매핑 누락이 없다. 관리는 드롭다운 하나이며 DA는 감사 로그, Admin은 설정과 감사 로그를 보고 나머지 역할은 트리거가 숨겨진다. [app.js:712](../mockups/assets/app.js#L712), [app.js:715](../mockups/assets/app.js#L715), [app.js:729](../mockups/assets/app.js#L729)
- 1600px에서 상단 바는 로고·기관명·최대 네 메뉴·260px 검색·알림·사용자로 구성된다. 목업 도구를 옮긴 뒤 정적 폭에서 넘침 징후는 없다. 실제 폰트 렌더링과 최대 메뉴 구성에서 사용자 버튼이 프레임 안에 남는지는 브라우저에서 확인이 필요하다. [app.css:49](../mockups/assets/app.css#L49), [app.css:776](../mockups/assets/app.css#L776), [app.css:796](../mockups/assets/app.css#L796)
