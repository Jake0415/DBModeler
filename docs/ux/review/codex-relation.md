# NeoDB ERD 관계 연결·설정·삭제 UX 검토

설계 §4와 작업 트리 목업을 대조했다. 검토 중 목업이 갱신되어 아래 근거에는 갱신본을 반영했다. 미리보기 URL은 HTTP 200을 반환했다. 검토 근거는 소스이며 브라우저 조작은 검증하지 않았다. 문구와 기본값은 권장안이다.

## 1. 높음 · 설정 적용 단위

- **문제** 관계명·유형·매핑·삭제 규칙이 입력 직후 각각 반영된다. 연결된 설정을 조정하는 중간 상태에서도 키가 바뀔 수 있다.
- **근거** 갱신본은 설정을 즉시 저장하고, 식별 해제 시 하위 FK 컬럼을 즉시 정리한다. [관계 설정](../mockups/model.html#L1767)
- **권장 수정안** 수정 내용을 임시로 유지하고 [적용]으로 한 번에 반영한다. 구조가 바뀌면 같은 패널에 영향 비교를 표시한다. [취소]로 임시 변경을 폐기하고 적용 후 Ctrl+Z 한 번으로 복원한다.
## 2. 높음 · 모델 삭제와 DB 행 삭제 규칙

- **문제** ‘삭제 규칙’이 관계 삭제 확인창과 관계 설정에 함께 나타나면 DB 행 삭제의 효과를 편집기 동작으로 오해할 수 있다.
- **근거** 모델 편집은 FK 제약과 컬럼 정의를 바꾼다. ON DELETE는 참조 중인 부모 행을 DB에서 삭제할 때 적용된다. 갱신본은 물리 설정과 모델 삭제를 분리하고 Oracle용 CASCADE와 SET NULL을 출력한다. [DDL 목업](../mockups/ddl.html#L130) · [PostgreSQL FK 제약](https://www.postgresql.org/docs/18/ddl-constraints.html)
- **권장 수정안** 패널 하단의 별도 액션은 **[모델에서 관계 삭제]**로 쓰고 확인창은 ‘모델에서 관계와 FK 제약을 제거합니다. 이 작업으로 DB 행은 변경되지 않습니다.’로 시작한다. 설정은 **부모 행 삭제 시 (ON DELETE)** 아래 ‘참조 중이면 삭제 차단’, ‘참조하는 자식 행도 삭제’, ‘자식 FK를 비움’을 지원 SQL 키워드와 함께 표시한다. 신규 기본은 삭제 차단이다. 기존 미지정 값은 ‘DBMS 기본값’으로 보존한다. CASCADE를 고르면 적용 영역에서 자식 행 영향을 알린다. SET NULL은 이 규칙이 비울 FK 컬럼 전체가 NULL을 허용할 때만 활성화한다. 대상 DBMS의 지원 문법으로 DDL을 만들고 정의서의 ‘부모 행 삭제 규칙’ 열에 동일한 유효 설정을 표시한다.

## 3. 중간 · 일반 연결과 기본값

- **문제** ‘PK 자동 할당’은 부모의 식별자까지 추정한다는 뜻으로 읽힐 수 있다. 연결마다 이름과 설정을 받으면 반복 작업이 느려진다.
- **근거** §4의 정상 경로는 부모 → 자식 → FK 자동 추가이며, 갱신본은 비식별을 선택 FK로 생성하고 부모 PK가 없으면 대기 상태를 안내한다. [ERD 설계 §4](../03-erd-editor.md#4-관계-ie)
- **권장 수정안** R의 기본은 **1:N 비식별**, 부모 한 건당 자식 **0..N**, 자식 한 건당 부모 **1**(FK 필수)로 제안하고 화면에 보여 준다. 이미 지정된 부모 PK 전체를 자식 FK로 복제하고, 식별을 명시적으로 고른 경우 자식 PK에도 넣는다. 정상 경로의 확인은 0회로 하고 ‘주문 → 주문항목 · FK 2개 추가’에 [설정] [실행 취소]를 붙인다. 이름·선택성·카디널리티·삭제 규칙은 이후 편집한다. 부모에 PK가 없으면 임의 PK를 만들지 않고 ‘부모 식별자 대기’ 초안과 [식별자 지정]을 제공한다. 부모 키 지정 시 영향 미리보기에 대기 관계를 포함하고, 완성 전까지 해당 FK DDL을 보류한다. 클릭과 드래그는 같은 흐름을 쓰며 복합 PK 한 줄을 끌어도 키 전체가 전달된다는 점을 표시한다.

## 4. 높음 · 이름 충돌, 두 번째 관계, 재귀

- **문제** 자동 접두사는 출발·도착 같은 업무 역할을 표현하지 못한다. 이름이 같은 기존 컬럼의 재사용도 업무적으로 틀릴 수 있다.
- **근거** 요청의 자동 명명 흐름과 달리 설계는 역할명 입력을 요구한다. 갱신본은 재귀 확인 후 관계를 먼저 만들고 역할명 팝오버를 연다. 팝오버에서 Esc도 편집값을 확정한다. [ERD 설계 §4](../03-erd-editor.md#4-관계-ie) · [재귀 확인](../mockups/model.html#L1283) · [FK 만들기](../mockups/model.html#L1727)
- **권장 수정안** 충돌·동일 방향 두 번째 관계·재귀는 적용 전 확인을 **한 번**만 연다. ‘이 관계의 역할을 정하세요’ 아래 출발창고, 도착창고, 상위부서처럼 수정 가능한 제안과 전체 컬럼 결과를 표시한다. 기존 컬럼은 사용자가 명시적으로 고른 호환 컬럼만 재사용한다. 같은 역할과 매핑이면 ‘이미 연결되어 있습니다’와 [기존 관계 열기]를 제공한다. 재귀의 방향 확인은 역할명과 한 화면에서 처리하고, 최상위 행을 위해 부모 0..1을 제안한다. 적용 전 모델은 그대로 둔다.

## 5. 높음 · 복합 PK와 FK 매핑

- **문제** 순서나 이름으로만 짝을 추론하면 일부 짝이 틀린 관계가 정상으로 표시되거나 다른 역할 FK가 수정될 수 있다.
- **근거** fkOf는 물리명 fkp로 부모 컬럼을 찾고 일부 기존 그룹은 배열 순서로 대체한다. [공통 FK 판정](../mockups/assets/app.js#L240)
- **권장 수정안** ‘부모 키 컬럼 → 자식 FK 컬럼’ 표는 부모 키 순서로 표시하고 짝은 안정적인 컬럼 ID로 유지한다. 1:1 대응과 타입·도메인 호환을 검증한다. ‘완료’, ‘부모 식별자 대기’, ‘매핑 미완성 1/2’, ‘FK 제외’, ‘M:N 해소 필요’를 구별한다. 기존 짝이 모호하면 후보를 보여 주고 확인 전 해당 FK의 DDL을 보류한다. 선택형 복합 FK는 기본적으로 전부 비우거나 전부 채우는 단위로 표현하고, 대상 DBMS에서 이를 보장할 제약을 확인한다. [복합 FK의 NULL 판정](https://www.postgresql.org/docs/18/ddl-constraints.html)

## 6. 중간 · 관계 패널의 순서와 표현

- **문제** ‘부모 필수 · 자식 선택’은 어느 쪽 한 건을 기준으로 읽는지 모호하다. 식별 여부와 1:1을 같은 목록에 두면 두 설정을 독립적으로 선택하기 어렵다.
- **근거** §4는 식별 여부와 끝점 기호를 함께 설명한다. erwin은 비식별 관계의 NULL 옵션을 별도로 다룬다. [ERD 설계 §4](../03-erd-editor.md#4-관계-ie) · [erwin 비식별 관계 NULL 옵션](https://bookshelf.erwin.com/bookshelf/public_html/12.1/Content/PDFs/Implementation%20Guide.pdf)
- **권장 수정안** DA#·ERwin에 익숙한 사용자가 부모·자식과 키 편입을 먼저 확인하도록 다음 순서를 사용한다.

  1. **부모 → 자식, 상태, 관계명**. 관계명은 선택 입력이며 비어 있으면 두 엔터티 이름을 표시한다.
  2. **식별 여부**. 식별 / 비식별과 ‘부모 키를 자식 PK에 포함’이라는 효과를 표시한다.
  3. **카디널리티와 선택성**. ‘자식 1건이 참조하는 부모’ 0..1 / 1과 ‘부모 1건에 연결되는 자식’ 0..1 / 1 / 0..N / 1..N을 보여 준다. 수치 옆에 ‘부모 없이 저장 가능’처럼 문장으로 설명한다. 식별 관계의 부모 필수는 고정한다. 부모당 자식 최소 1은 FK만으로 보장할 수 없어 ‘업무 규칙’으로 표시한다.
  4. **참조 키와 FK 매핑**. 키 이름, 대응 컬럼, 역할명, 완성 상태를 보여 준다.
  5. **물리 제약**. FK 필수 여부, 1:1 유일성, ‘부모 행 삭제 시 (ON DELETE)’ 순으로 둔다. 하단은 [취소] [적용]을 두고 별도 영역에 [모델에서 관계 삭제]를 배치한다.

## 7. 높음 · 유형 변경과 1:1 유일성

- **문제** 식별 전환이나 1:1 전환은 자식 PK, 하위 FK, UK까지 바꿀 수 있다. 1:1 선만으로는 FK 값 중복을 막을 수 없다.
- **근거** §4는 1:1을 표기하고 M:N을 교차 엔터티로 해소하도록 한다. [ERD 설계 §4](../03-erd-editor.md#4-관계-ie)
- **권장 수정안** 적용 전 PK·NULL·UK·하위 FK 차이를 보여 준다. 1:1은 **FK 컬럼 조합 전체**에 유일성을 부여한다. 기존 PK나 UK가 유일성을 이미 보장하면 재사용하고 유형을 바꿀 때 이 관계 전용 자동 UK만 정리 후보로 제시한다. 선택형 1:1은 대상 DBMS의 다중 NULL 행 처리를 확인한다. 설정 변경으로 SET NULL이 불가능해지면 이유를 표시하고 유효한 규칙을 선택하게 한다. M:N 해소 전에는 FK·ON DELETE를 비활성화하고, 교차 엔터티 미리보기와 적용 후 양쪽 관계 설정으로 연결한다. 배타 묶음은 관계 그룹에서 설정하고 구성 관계를 삭제할 때 묶음 영향도 표시한다.

## 8. 높음 · 관계 삭제 조건과 기본 선택

- **문제** ‘일반 속성으로 유지’가 자식 PK를 남기면 문구와 결과가 어긋난다. ‘FK 삭제’는 하위 FK를 남기거나 다른 역할 컬럼을 지울 수 있다.
- **근거** 갱신본은 식별 관계에서 자식 PK 유지와 하위 FK 삭제를 선택지로 표시한다. 컬럼이 없으면 확인 없이 삭제한다. 현재 테이블 삭제는 물리명으로 FK를 찾아 삭제를 기본 선택한다. [테이블 삭제](../mockups/model.html#L1215) · [속성 삭제·PK 해제](../mockups/model.html#L832)
- **권장 수정안** 표의 처리를 기본 선택하고 [관계 삭제]를 눌러야 적용한다. 최초 포커스는 [취소]에 둔다. ‘일반 컬럼으로 남김’은 PK 편입을 해제한다는 뜻이고 ‘자체 PK로 남김’은 현재 자식 PK를 유지한다는 뜻이다.

| 관계 유형 | FK 상태 | 하위 영향 | 기본 선택 | 추가 선택 |
|---|---|---|---|---|
| M:N 또는 FK 없는 관계 | 컬럼 없음, FK 제외 또는 식별자 대기 | 없음 | 관계만 삭제 | 취소 |
| 비식별 1:N / 1:1 | 전용 매핑 완료 | 없음 | 컬럼을 남기고 FK 해제 | 전용 컬럼도 삭제 |
| 비식별 또는 식별 | 부분 매핑·미확정 | 일부 또는 불명 | 확인된 매핑만 해제하고 컬럼 보존 | [FK 매핑 확인]. 영향 확정 전 컬럼 삭제 비활성 |
| 식별 1:N / 1:1 | 매핑 완료 | 하위 참조 없음, 남는 PK 유효 | PK에서 빼고 일반 컬럼으로 남김 | 자체 PK로 남김 / 전용 컬럼도 삭제 |
| 식별 1:N / 1:1 | 매핑 완료 | 자식 PK가 비거나 하위 FK 변경 | 자체 PK로 남기고 이 관계 해제 | [자식 키와 하위 FK 정리 검토]. 대체 키와 하위 매핑 확인 후 적용 |
| 재귀·역할명·동일 방향 복수 관계 | 매핑 완료 | 해당 역할에 위 조건 적용 | 해당 관계의 매핑에 위 기본값 적용 | 해당 역할 전용 컬럼만 삭제 가능 |

공유 FK·PK·UK 등의 사용처를 표시하고 다른 관계·제약에 필요한 컬럼의 삭제는 비활성화한다. 하위 정리는 경로별로 영향 계산 후 중복 컬럼을 한 번만 집계한다. 속성 삭제·부모 PK 해제·테이블 삭제·참조 해제에도 같은 영향 판정을 사용하며 제목과 액션은 시작한 명령에 맞춘다. ‘속성만 삭제’로 관계가 남으면 ‘매핑 미완성’으로 표시하고 해당 물리 FK 생성을 보류한다.

## 9. 높음 · 삭제 미리보기와 실행 취소

- **문제** 개수만으로 결과를 예측하기 어렵고 확인 중 공동 편집이 반영되면 화면에 보이는 대상과 적용 결과가 달라질 수 있다.
- **근거** 테이블 삭제는 이름과 개수를 일부 표시한다. 설계는 실시간 공동 편집과 실행 취소를 지원한다. [테이블 삭제](../mockups/model.html#L1215) · [ERD 설계](../03-erd-editor.md)
- **권장 수정안** 한 화면 상단에 ‘주문 → 주문항목 · 관계 1개, FK 제약 1개 제거’를 표시한다. 선택을 바꾸면 ‘남기는 컬럼’, ‘삭제하는 컬럼’, ‘PK·UK·하위 FK 변경’을 엔터티별 전후 표로 갱신한다. 제약과 컬럼의 DDL 차이는 펼침 영역으로 제공한다. 적용 직전 대상 버전·권한·영향을 다시 확인하고 변경이 있으면 미리보기를 갱신한다. 관계·키·컬럼·제약을 한 번에 적용하고 [실행 취소]나 Ctrl+Z 한 번으로 복원한다. 다른 사용자의 후속 수정과 겹치면 충돌을 표시하고 영향 재검토 후 복원한다.

## 10. 높음 · 부모 PK 변경 뒤 기존 관계

- **문제** 이름·순서·타입 변경은 키 구성 변경과 영향이 다르다. 이름 중심 매칭은 역할명과 하위 경로를 놓칠 수 있다.
- **근거** 그리드에서 하위 컬럼 이름과 타입을 갱신하며 FK 판정에는 이름 기반 대응이 남아 있다. [PK 전파](../mockups/model.html#L1159) · [FK 판정](../mockups/assets/app.js#L240)
- **권장 수정안** 순서만 바뀌면 짝을 보존하고 FK와 참조 컬럼을 같은 순서로 출력한다. 이름 변경 시 자동 이름은 갱신하되 수동 역할명은 유지한다. 타입·도메인과 키 구성 변경은 영향 표에서 한 번 확인한다. 확실한 새 매핑은 제안하고 모호한 짝·공유 컬럼·타입 불일치는 [다시 매핑]으로 해결한다. 해결 전 모델·트리·DDL에서 동일한 매핑 상태를 표시한다.

## 11. 높음 · 참조 엔터티, 결재 중·조회 전용

- **문제** 로컬 관계 편집과 원본 편집 권한이 섞이기 쉽다. 확인창을 연 뒤 결재 상태가 바뀔 수도 있다.
- **근거** 참조 관계는 이 영역 소유이며 사용자가 새 원본 확정본으로 갱신한다. 목업은 결재 중 버전과 가시성을 구분한다. [참조 설계 §3.2](../12-model-tree-plan.md) · [결재 상태 배너](../mockups/model.html#L1576)
- **권장 수정안** 참조 엔터티는 부모로 선택하게 하고 ‘회계관리 v5 확정본 기준’을 표시한다. 로컬 자식의 FK를 편집한다. 원본에 새 확정본이 나오면 [갱신 검토]에서 PK 차이와 로컬 FK 재매핑을 함께 확인한다. 참조 해제도 로컬 관계 삭제 미리보기를 거친다. 조회 전용에서도 관계 선택·설정 조회·원본 열기를 허용하고 ‘결재 중인 제출본 · 편집할 수 없습니다’ 또는 ‘v5 확정본 · 조회 전용’을 표시한다. 편집 제약을 클릭·드래그·트리·키보드 진입과 적용 시점에 동일하게 적용한다.

## 12. 중간 · 키보드·접근성·실수 방지

- **문제** 선 위주의 연결은 가까운 대상을 구별하기 어렵다. 전역 Delete·Enter와 삭제 버튼 초기 포커스는 의도치 않은 작업으로 이어질 수 있다.
- **근거** §9는 단축키를 정의하고 관계 삭제는 310ms 뒤 삭제 버튼으로 포커스를 옮긴다. [키보드 설계](../03-erd-editor.md#9-키보드) · [삭제 포커스](../mockups/model.html#L1824)
- **권장 수정안** R → 트리 또는 캔버스에서 부모 선택 Enter → 자식 선택 Enter를 제공한다. 트리 관계 항목에서 Enter는 패널, Delete는 확인창만 연다. 텍스트 입력·한글 조합 중에는 편집기 전역 단축키를 멈춘다. Esc는 현재 팝오버나 연결부터 취소하고 포커스를 호출 위치로 복원한다. 삭제 후에는 인접 관계나 자식 엔터티로 포커스를 옮긴다. 부모 선택, 다음 단계, 적용 결과를 라이브 영역으로 알리고 역할·선택성·오류를 색과 선 외에 텍스트로도 표시한다. 선의 클릭 영역을 넓히고 가까운 관계는 역할명이 있는 트리에서도 선택할 수 있게 한다.

## 권장 최종 시나리오

### 연결

1. [관계] 또는 R을 누르면 현재 기본 유형과 ‘부모를 선택하세요’를 표시한다.
2. 부모가 선택되면 강조·미리보기 선과 ‘자식을 선택하세요 · Esc 취소’를 표시한다.
3. 정상 경로는 자식 선택 즉시 부모 PK 전체를 FK로 연결한다. PK가 없으면 ‘부모 식별자 대기’, M:N은 ‘해소 필요’로 표시한다. 충돌·두 번째 관계·재귀는 역할명과 결과 컬럼을 한 번 확인한다.
4. 생성 결과에 [설정]과 [실행 취소]를 제공한다.

### 설정

1. 선 또는 트리에서 관계를 연다. 관계명 → 식별 여부 → 양 끝 다중성 → FK 매핑 → 물리 제약 순으로 편집한다.
2. PK·FK·UK 또는 하위 관계에 영향이 있으면 전후 차이를 표시한다. [적용] 한 번으로 반영하고 DDL·정의서에 같은 ON DELETE 설정을 표시한다.

### 삭제

1. 관계를 선택하고 [모델에서 관계 삭제] 또는 Delete로 확인창을 연다.
2. 역할과 조건별 기본안을 표시한다. 선택을 바꾸면 자식·하위 컬럼, 키, 제약, DDL 영향을 갱신한다.
3. [관계 삭제]에서 권한과 영향을 재확인하고 한 번에 적용한다. [실행 취소]로 같은 변경 단위를 복원한다.
