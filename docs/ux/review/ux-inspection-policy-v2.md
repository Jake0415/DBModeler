> 대상: [31-inspection-policy-v2.md](../31-inspection-policy-v2.md) v0.1 · 요청서 [brief-inspection-policy-v2](brief-inspection-policy-v2.md)
> 본 것: `mockups/rules.html`(SC-43) · `assets/app.js` `checkItem`(866~900) · 소비 화면의 검수 기준 연결(`grep rules.html`) · 01 §11 문구 기준 · 24 설정형 화면 가이드 · 30 퍼블리싱 2차 · SWS `FieldRuleSettings.tsx` · `SpecialCharacterOptions.tsx`

## 0. 한 줄 결론

방향(사전 종류 × 필드 표 + 행 펼침 편집 + 영향 미리보기)은 맞다. 다만 다섯 가지를 플랜에 넣어야 한다.
1. **기본값과 다른 곳을 보여 주는 장치.**
2. **필드끼리 서로 어긋나는 설정을 저장 전에 잡는 장치.** 예: 단어 약어에는 `-`를 허용했는데 용어 약어에서는 막힌 경우, 또는 구분자가 허용 문자에 없는 경우.
3. **null · [] · all을 화면에 드러내지 않는 선택지 문구.**
4. **모델러가 오류 문구에서 검수 기준의 해당 줄 · 버전으로 바로 가는 길.** 지금은 소비 화면 어디에도 `rules.html` 링크가 없다.
5. **"모델러에게 자유도"라는 요청을 A안이 어떻게 채우는지 화면에 설명하는 일.** 기준 변경 제안 흐름이 필요하다.

## 1. 심각도 높음

### UX-01 (높음) 필드끼리 서로 어긋나는 설정을 저장 전에 막는 장치가 없다
- **근거**: §3 `fields.word.abbr` · `fields.term.abbr` · `naming.sep`은 서로 따로 고친다. 그런데 `checkItem`(app.js:893)은 용어 약어를 "단어 약어 + 구분자"로 만든다. 그래서 다음 세 경우에 저장하는 순간 기존 용어가 전부 걸린다.
  - 단어 약어에 `-`나 소문자를 허용했는데 용어 약어 허용 문자에 그것이 없다.
  - 구분자를 `-`로 바꿨는데 용어 · 엔터티 약어의 특수문자에 `-`가 없다.
  - 단어 약어 최대 길이 × 평균 단어 수가 용어 약어 상한(30)을 넘는다.

  DA는 탭(단어 → 용어 → 명명 규칙)을 오가며 고치므로 이 어긋남을 알아채기 어렵다.
- **고칠 방법**:
  - 저장 막대 위 또는 영향 미리보기 맨 위에 **"서로 맞지 않는 설정" 목록**을 둔다(차단 · 경고로 나눔). 예: "구분자를 `-`로 바꿨지만 용어 영문약어명의 특수문자에 `-`가 없습니다 → [용어 영문약어명에 `-` 추가]".
  - 바로 고치는 버튼을 함께 준다.
  - 명명 규칙 묶음의 구분자 선택지 옆에도 같은 경고를 그 자리에서 보인다(24 §3.2: 경고는 해당 행 보조 칸).
  - `policy-cases.js`에 이 조합 사례를 넣는다.

### UX-02 (높음) 모델러가 "어느 기준 · 어느 버전 때문에 막혔는지" 찾아갈 길이 없다
- **근거**:
  - `grep rules.html` 결과 링크가 있는 곳은 `settings.html`뿐이다. 사전 등록 그리드 · 엑셀 검사 · 표준 맞추기 · 결재함 · 단어 마법사 오류에서는 검수 기준으로 갈 수 없다.
  - 오류 문구 형식도 제각각이다.
    - `영문약어명 7자 초과(검수 기준 v3)`(app.js:881): 버전은 있다.
    - `영문약어명은 대문자 · 숫자, 숫자로 시작 불가`(881): 기준 · 버전이 없다.
    - `30자 초과(대상 DBMS)`(894): 출처가 검수 기준이 아니라고 읽힌다.
    - `엔터티 분류어(…)로 끝나지 않음`(899): 기준 · 버전이 없다.
  - 플랜 §5는 "판정 사유에 검수 기준 vN 표시"를 모델 쪽에만 적었다.
- **고칠 방법**:
  - `ruleProblems()`가 돌려주는 값에 `{field, ruleKey, ver}`를 넣는다.
  - 모든 소비 화면의 오류 문구를 한 형식으로 맞춘다: **`{무엇이} {어떻게 어김} — 기준: {필드} {규칙 요약} · 검수 기준 v4 [기준 보기]`**.
    예: `영문약어명에 '-'를 쓸 수 없습니다 — 기준: 단어 영문약어명 · 영문 대문자 · 숫자 · _ · 검수 기준 v4 [기준 보기]`
  - [기준 보기]는 `rules.html?k=word&f=abbr&v=4`로 간다. 해당 칩 · 줄을 열고 강조(2초 배경색 + 포커스)한다.
  - `v`가 지금 버전과 다르면, 그 버전을 조회 전용으로 보이고 "지금 기준(v5)과 다른 점"을 위에 한 줄로 보인다.
  - 결재 문서에서 신청 때 버전과 승인 때 버전이 다르면 "신청 v3 · 지금 v4 — 바뀐 규칙 2개 [차이 보기]"를 보인다. 이것이 §5 "버전 차이 안내"의 구체적인 모양이다.
  - 변경 이력 행을 누르면 그 버전의 규칙 표를 볼 수 있어야 한다. 지금은 한 줄 요약뿐이다.

### UX-03 (높음) null · [] · all이 화면 문구로 바뀌는 규칙이 없다
- **근거**:
  - §3 `chars: null = 제한 없음` · `special: [] | [...] | 'all'` · `max: null`. 같은 null이 글자 종류에서는 "모두 허용", 길이에서는 "검사 안 함"을 뜻한다.
  - SWS는 이 때문에 "기존 특수문자 기준 유지" 같은 사용자가 알기 어려운 상태 문구를 남겼다(`SpecialCharacterOptions.tsx` 15행 `value == null`).
  - 체크박스와 "모두 허용"을 섞어 둔 SWS 방식은 "모두 허용을 끄면 네 문자가 다시 선택되는" 숨은 동작이 있다(같은 파일 21행).
- **고칠 방법**: 화면은 null을 모르게 한다. 상태마다 **라디오 하나 + 결과 한 줄**로 보인다.

  | 저장값 | 컨트롤 | 요약 칸 · 결과 문구 |
  |---|---|---|
  | `special: []` | (•) 쓰지 않음 | "특수문자를 쓸 수 없습니다" |
  | `special: ['_','-']` | (•) 고른 것만 → 칩 | "`_` `-`만 쓸 수 있습니다" |
  | `special: 'all'` | (•) 모든 기호 | "모든 기호를 쓸 수 있습니다(공백 · 외국 글자는 제외)" |
  | `chars: null` | 글자 종류 체크 5개 모두 켬 + "모든 글자" 표시 | "글자 종류 제한 없음" |
  | `max: null` | 숫자 칸 비활성 + [ ] 길이 제한 없음 | "길이 제한 없음" |

  - "고른 것만"인데 칩이 0개면 저장할 수 없게 한다. 칸 아래에 "기호를 하나 이상 고르거나 ‘쓰지 않음’을 고르세요"라고 보인다. 이렇게 하면 `[]`로 가는 길이 하나로 모인다.
  - 옛 v3 값은 읽을 때 위 세 상태 중 하나로 정해서 보인다. "기존 기준 유지" 같은 제4의 상태는 만들지 않는다.
  - 공백은 특수문자가 아니라 글자 종류(체크)에 둔다는 것을 칩 영역 아래 한 줄로 알린다.

### UX-04 (높음) "모델러에게 자유도" 요청과 A안 사이의 간극이 화면에서 설명되지 않는다
- **근거**:
  - 사용자 요청은 "모델러가 자신이 표준을 세우고 그에 맞게 모델링"이다.
  - 플랜 §6은 A(DA · Admin만 고침)를 먼저 목업하고, 모델러에게는 "읽기 + 기준 변경 제안"을 준다. 그런데 **제안 화면 · 흐름이 §4 · §7 어디에도 없다.**
  - 모델러로 들어오면 지금처럼 "조회 전용" 띠만 보게 된다(rules.html:27). 요청자가 보기에는 바뀐 것이 없다.
- **고칠 방법**:
  - A안을 고르더라도 모델러 화면에 **[이 기준 변경 제안]**(줄마다 펼친 영역 안)을 둔다.
    - 제안 내용: 필드 · 바꾸고 싶은 값 · 사유 · 예시 값.
    - 제안은 DA 결재함의 "확인 요청"으로 간다. 01 §11 용어대로 거절 · 요청 취소를 쓴다.
    - DA는 제안을 열어 **그 값으로 시험해 보기 · 영향 미리보기**를 바로 돌려 본다.
  - 띠 문구를 "조회 전용 — 기준은 DA · Admin이 고칩니다. 바꿔야 하면 줄을 펼쳐 [변경 제안]을 보내세요"로 바꾼다.
  - 플랜 §1의 목표 문장도 "기관이 정한 넓은 범위 안에서 모델러가 고르고, 더 필요하면 제안한다"로 고쳐 요청자와 기대를 맞춘다. 결정은 Q1에서 사용자에게 확인한다.

## 2. 심각도 중간

### UX-05 (중간) 편집 방식 — 표 행 펼침이 낫다. 단, 조건이 붙는다
- **근거**:
  - SWS 카드 격자(`FieldRuleSettings.tsx` 66행 `criteria-card-grid`)는 필드마다 카드 하나에 컨트롤 3~4묶음을 늘 펼쳐 둔다. 그래서 필드끼리 "길이 · 허용 문자"를 가로로 비교하기 어렵고, 읽기만 하는 모델러에게도 편집 컨트롤이 보인다.
  - 드로어는 24 §2 D안(오른쪽 고정 도움말 열)을 기각한 이유와 같다. 표 맥락이 가려지고 필드 하나씩만 볼 수 있다.
  - 표 + 행 펼침은 24 §3.3 "넓은 행 ≤1200"과 지금 화면 구조(rules.html:33)를 그대로 잇는다. 요약 칸은 모델러가 읽을 화면 역할도 한다.
- **고칠 방법**(행 펼침의 조건):
  1. 펼치기 단추는 줄 끝의 [고치기](모델러는 [자세히])로 둔다. `aria-expanded` · `aria-controls`를 달고, 펼치면 첫 컨트롤로 포커스를 옮긴다. Esc로 접고 단추로 포커스를 돌린다.
  2. 여러 줄을 동시에 펼칠 수 있게 하되, 접힌 줄에도 **바뀐 줄 표시**(왼쪽 3px 파랑 + "바뀜" 글자)를 둔다. 탭 세그먼트에도 미저장 점을 단다(24 §3.4 `.tabdot`).
  3. 펼친 영역은 24 행 3칸을 따른다. 왼쪽 컨트롤(≤760), 오른쪽 보조 칸에는 **시험해 보기 + 공통표준 기본값 + [이 줄만 기본값으로]**.
  4. 고정 줄(필수 · 중복 · 참조)은 펼치지 않는다. 자물쇠 아이콘과 함께 "항상 검사 — 사전 참조가 깨지지 않게 끌 수 없습니다" 같은 이유를 글자로 보인다(아이콘만으로 알리지 않음).
  5. 지금 도메인 탭의 "데이터 타입 · 길이 / 도메인 그룹 · 분류" 줄(rules.html:36-37)은 고정 줄로 분류한다. 편집 줄과 보기가 섞이지 않게 표 아래쪽에 모은다.

### UX-06 (중간) "기본값에서 출발해 고치기" 흐름이 이진 표시(public / custom)로는 약하다
- **근거**: §3 `preset: 'public' | 'custom'` · §4-1 "출발점(공공데이터 공통표준 기본 / 기관 직접)". 한 곳만 고쳐도 "기관 직접"이 되면, DA는 "무엇이 공통표준과 다른지" 알 수 없다. 감리 · 다음 담당자도 마찬가지다.
- **고칠 방법**:
  - 머리 요약을 "검수 기준 v4 · **공통표준 기본값에서 3곳 바꿈** [다른 곳만 보기]"로 바꾼다.
  - 표의 각 값 옆에 기본값과 다르면 작은 "기본값 6자" 회색 글자를 둔다.
  - [다른 곳만 보기]를 켜면 모든 탭에서 다른 줄만 남긴다.
  - [기본값으로 되돌리기]는 확인 창으로 묻는다(무엇이 몇 곳 돌아가는지).
  - 첫 진입(아직 기관이 고친 적 없음) 때는 표 위에 한 줄을 둔다: "지금은 공공데이터 공통표준 기본값입니다. 기관에 맞게 줄을 펼쳐 고치세요 — 저장 전에 영향을 보여 드립니다".
  - `preset` 값은 화면에 쓰지 않고 바뀐 곳 수로 대신한다.

### UX-07 (중간) 특수문자 칩 + 직접 입력의 세부 동작이 정해지지 않았다
- **근거**: §2 "칩 `_ - / , . ( ) &` + 직접 입력(문자 한 개씩) + 모두 허용". 문제가 되는 경우는 넷이다.
  - 붙여넣기("@#")
  - 전각 · 비슷한 모양 문자(`－` `‐` `–`, `，`)
  - 글자 · 숫자 · 공백 입력
  - 이미 칩에 있는 문자

  `.` `,` `-`는 칩 안에서 보기 힘들 만큼 작다.
- **고칠 방법**:
  - 자주 쓰는 칩은 토글 단추(`aria-pressed`)로 만든다. 고정폭 글꼴로 크게(16px) 쓰고 이름을 함께 단다: `_ 밑줄` · `- 하이픈` · `/ 빗금` · `, 쉼표` · `. 마침표` · `( ) 괄호` · `& 앰퍼샌드` → 쉬운 말로 "그리고 기호".
  - 직접 입력 칸 규칙:
    - Enter나 붙여넣기 때 글자를 하나씩 나눠 칩으로 만든다.
    - 글자 · 숫자 · 공백 · 이미 있는 문자는 버리고, 칸 아래에 이유를 한 줄로 보인다("‘A’는 글자라 뺐습니다 — 글자 종류에서 고르세요").
    - 전각 · 비슷한 모양 문자는 반각으로 바꿀지 묻는다("‘－’(전각)을 ‘-’로 바꿀까요?").
    - 만든 칩은 [× ‘@’ 빼기] 단추로 지운다. Backspace로 마지막 칩을 지운다.
  - `( )`처럼 짝이 있는 문자는 칩 하나로 묶는다.
  - **구분자로 쓰는 문자**(`naming.sep`)가 빠지면 UX-01 경고를 그 자리에 보인다.

### UX-08 (중간) 위반 처리가 `on`과 `lvl` 두 값으로 나뉘어 컨트롤이 겹친다
- **근거**: §3 `Rule = { on, …, lvl: 'block' | 'warn' }`인데 §4-2는 "위반 시: 차단 / 경고 / 끔"으로 한 컨트롤이다. 두 값이 따로 있으면 "끔인데 lvl=block"처럼 화면에 보이지 않는 상태가 생긴다. SWS도 "입력 형식 검사 사용/미사용"과 개별 값이 따로 있어, 미사용일 때 아래 컨트롤이 흐리게 남는다(84행).
- **고칠 방법**:
  - 화면은 세그먼트 하나로 둔다: **[막기] [경고만] [검사 안 함]**. "차단"보다 "막기"가 쉽고, "끔"보다 "검사 안 함"이 무엇이 꺼지는지 분명하다.
  - 데이터도 `lvl: 'block' | 'warn' | 'off'` 하나로 합치기를 Codex 쪽에 권한다.
  - "검사 안 함"을 고르면 그 줄의 다른 컨트롤을 흐리게 두고 "이 필드는 길이 · 글자를 검사하지 않습니다(필수 · 중복은 계속 검사)"를 보인다.
  - Q2 의견: "검사 안 함"은 판정만 빼고 준수율 분모에는 남기는 쪽이 이해하기 쉽다. 빠지는 것이 "표준 제외 규칙"(rules.html:58)과 같은 뜻이 되면 두 기능이 헷갈린다. 결정하면 보조 칸에 한 줄로 적는다.

### UX-09 (중간) "시험해 보기"가 필드 하나에만 묶여 있어, 바뀐 기준의 효과를 비교하기 어렵다
- **근거**: §4-2 "값 한 개를 넣으면 이 필드 판정을 바로 보여 줌". DA가 실제로 묻는 것은 "이 값이 **지금 기준에서는 통과하는데 바뀐 기준에서는 걸리나?**"이다. 또 용어 약어처럼 단어 · 구분자 · 길이가 함께 걸리는 판정은 필드 하나로는 다 보이지 않는다.
- **고칠 방법**:
  - 펼친 줄 보조 칸의 시험 칸은 그대로 둔다. 결과는 **두 줄**로 보인다: `지금(v4): 통과` / `바꾼 뒤: 막힘 — '-'를 쓸 수 없음`. 막힘 · 경고 · 통과는 색과 글자를 같이 쓴다.
  - 시험 칸 아래에 사전에서 뽑은 예시 3개를 칩으로 두고, 누르면 채운다. 빈 칸에서 무엇을 넣을지 고민하지 않게 하려는 것이다.
  - 표 위(탭 세그먼트 오른쪽)에 [이름 하나로 시험]을 둔다. 용어명을 넣으면 분해 → 약어 조합 → 길이 · 문자 · 끝 단어 검사를 한 번에 돌려 줄마다 결과를 보인다. 결과에서 줄 이름을 누르면 그 줄을 펼친다.
  - 결과 영역은 `aria-live="polite"`로 두고, 입력 300ms 뒤에 갱신한다.

### UX-10 (중간) 명명 규칙 미리보기는 "예시 하나"로는 부족하고, 구분자 없음 · 하이픈의 결과를 미리 보여야 한다
- **근거**: §4-3 "각 줄에 지금 사전의 예시가 새 구분자로 바뀐 모습". 구분자 `''`은 단어 경계가 사라져 읽기 어렵다(`RISKRSPNSCMPTNYMD`). `-`는 대부분의 DBMS에서 따옴표 없이는 컬럼 이름으로 쓸 수 없다. Q3의 영향이 여기서 처음 보인다.
- **고칠 방법**:
  - 명명 규칙 묶음 오른쪽(보조 칸)에 **미리보기 상자 하나**를 둔다. 예시 줄마다 `이전 → 이후`를 보이고, 모든 선택지(구분자 · 접미어 · 소수점 · 소문자)에 바로 반응한다.
    - 용어 1: `리스크대응완료일자 RISK_RSPNS_CMPTN_YMD → …`
    - 엔터티 1: `고객기본 CUST_M → …`
    - 도메인 1: `금액N15,2 → …`
    - 모델 물리명 1
  - 구분자 선택지는 라디오에 결과 예시를 붙인다: `(•) 밑줄 _ — RISK_RSPNS` · `( ) 하이픈 - — RISK-RSPNS · DB에서 따옴표 필요` · `( ) 없음 — RISKRSPNS · 단어 경계가 안 보임`.
  - `-` · 없음을 고르면 보조 칸에 "기존 용어 1,284건 · 모델 물리명 3,920개가 새 기준과 달라집니다 [영향 미리보기]"를 그 자리에서 보인다(24 §3.2 ③).
  - 엔터티 분류어 · 접미어 표는 [줄 추가]와 줄마다 [× 빼기] 단추로 고친다. 분류어 · 접미어 중복이나 빈 값은 칸 아래에 오류로 보인다.

### UX-11 (중간) 영향 미리보기 창의 정보 구조
- **근거**: 지금 PC-02 창(rules.html:95)은 바뀐 값 1개 + 안내 3줄이다. §4-4는 "바뀐 항목 목록 + 다시 걸리는 수 4종"으로 늘린다. 변경이 여럿이면 창이 길어지고, 숫자만 있으면 "그래서 무엇이 걸리는지"를 알 수 없다. 반대로 **새로 풀리는 것**(완화)도 의미가 있는데 빠져 있다.
- **고칠 방법**: `.modal.xwide`(760) 하나에 다음 순서로 둔다(01 §11.2: 제목 = 동작).
  1. **제목**: "검수 기준을 v4 → v5로 올립니다".
  2. **서로 맞지 않는 설정**(UX-01). 있으면 맨 위에 빨강으로 두고, 하나라도 "막기"면 [저장]을 끈다.
  3. **바뀐 규칙** 표: `항목 · 필드 · 이전 → 이후`. 5줄이 넘으면 접고 "외 n개"로 줄인다.
  4. **새 기준으로 다시 보면**: 대상(사전 항목 · 진행 중 신청 · 모델 속성 · 엑셀 묶음)마다 `막힘 n · 경고 n · 새로 통과 n`. 줄마다 [예시 3개 보기]를 펼쳐 실제 이름을 보이고, [목록 열기]로 해당 화면에 필터를 건 링크를 준다.
  5. **적용 방식**: "기존 데이터는 자동으로 고치지 않습니다 — ‘다시 검사 필요’로 표시합니다 · 다음 신청부터 · 진행 중 신청은 승인할 때 새 기준으로 다시 검사합니다 · 감사 로그에 남습니다".
  6. 큰 영향(구분자 · 소문자 변경이거나 막힘이 1,000건 이상)일 때만 확인 체크 "[ ] 영향을 확인했습니다"를 두고, 켜야 [검수 기준 저장]이 켜진다.
  7. 단추: [취소] … [검수 기준 저장](01 §11.2의 구체적 동사).

  숫자를 세는 동안에는 줄마다 "세는 중"을 보이고, 끝나는 대로 채운다(창을 막지 않음). 저장 막대 문구도 24 §3.4대로 "검수 기준 4곳 바뀜 [변경 보기]"로 바꾼다. 지금 rules.html:88은 한 값만 문장으로 쓴다.

### UX-12 (중간) 엔터티 탭의 자리가 애매하다 — 사전 종류가 아니라 모델 기준이다
- **근거**:
  - §2 표는 "엔터티 검수 기준(모델 입력 제한) — 나중"이라고 한다.
  - 그런데 §3 `fields.entity` · §4-2는 엔터티를 사전 칩 옆에 추가한다.
  - `checkItem`에서 엔터티는 용어와 이름을 함께 검사한다(app.js:872 `sameKind`).

  모델러는 "엔터티도 사전에 신청하는 것인가"로 오해할 수 있다.
- **고칠 방법**:
  - 세그먼트를 `단어 · 도메인 · 용어 · 코드 │ 엔터티(모델)`로 나누고, 엔터티 탭 위에 한 줄을 둔다: "모델의 엔터티 이름을 검사합니다 — 사전 신청에는 쓰지 않습니다".
  - 이번 범위가 "판정만"이라면, 엔터티 분류어 · 접미어는 명명 규칙 묶음에만 두고 엔터티 탭은 다음 차수로 미루는 편이 덜 헷갈린다.

### UX-13 (중간) 권한 §6 A / B / C에 대한 UX 의견
- **A(추천, 지금)**: UX-04의 [변경 제안]을 붙이는 조건이다. 기관 공용 사전이 하나라서 "같은 이름은 같은 기준으로 검사"가 사용자의 기대와 맞는다. 오류 문구에 출처도 하나(검수 기준 vN)뿐이라 설명이 쉽다.
- **B(나중, 범위를 좁혀서)**:
  - 시스템별 조정은 **모델 검증(물리명 · 엔터티)에만** 적용하고, **좁히기만** 허용하는 것을 권한다.
  - 사전 항목은 시스템에 속하지 않으므로, 시스템마다 넓히면 "어느 시스템 모델러가 신청했느냐"에 따라 같은 단어가 통과하거나 막힌다. 이것은 결재자(DA)가 가장 설명하기 어려운 상황이다.
  - B를 하면 판정 사유에 출처 배지를 붙인다: `기준: 기관 v4` · `기준: ○○시스템(기관 v4에서 좁힘)`. 검수 기준 화면에는 "이 시스템에서 다른 곳 n개" 비교 보기가 필요하다. 설정 › 시스템 탭에 자리만 잡는 것은 좋지만, 화면 문구는 "준비 중"으로 분명히 해야 한다.
- **C(반대)**: 같은 사전에 모델러마다 다른 기준이 생겨 검수 결과를 믿을 수 없다. 모델러가 원하는 "자유"는 C가 아니라 **기관이 넓게 허용 + 제안 흐름 + 기존의 직접 지정 비대상(사유 필수, rules.html:67)** 으로 채울 수 있다.

### UX-14 (중간) 고정 · 예외 항목의 표시(Q4)
- **근거**: Q4 "공통표준(행정안전부) 항목은 기관 기준 위반이어도 예외". 기관이 소문자 금지 · 구분자 변경을 하면 공통표준에서 들여온 항목이 그리드에서 빨갛게 보일 수 있다. 사용자는 고칠 수 없는 것을 오류로 보게 된다.
- **고칠 방법**:
  - 예외로 두는 쪽을 권한다. 그리드 · 엑셀 결과에서는 오류 대신 회색 배지 "공통표준 — 기관 기준 예외"를 붙이고, 툴팁에 어긴 규칙을 적는다.
  - 검수 기준 화면에는 "공통표준 항목은 이 기준으로 막지 않습니다(n건이 기관 기준과 다름 [목록])"를 보조 칸에 한 줄로 적는다.
  - 영향 미리보기 숫자에서도 따로 센다.

### UX-16 (낮음) 접근성 · 폼 세부
- 펼친 영역의 컨트롤 묶음마다 `fieldset` + `legend`를 둔다(허용 문자 · 특수문자 · 길이 · 추가 조건 · 어기면). 스크린리더가 "단어 영문약어명, 특수문자, 고른 것만"처럼 읽게 한다.

### UX-17 (낮음) Q3 · Q5에 대한 화면 쪽 의견
- **Q3(구분자 없음 · 하이픈)**: 기존 데이터가 크게 불일치해진다. "경고 후 허용"을 하되 UX-11의 확인 체크를 붙인다. 또 영향 창에서 **[일괄 변경 신청 만들기]**는 선택 사항으로만 둔다(저장과 분리). 신청을 자동으로 만들면 결재함이 수천 건으로 넘친다.
- **Q5(소문자)**:
  - 소문자를 허용하면 미리보기 상자(UX-10)에 "사전: `custNo` → DDL: `CUSTNO`" 줄을 추가해 대문자로 바뀌는 것을 미리 보인다.
  - 대소문자만 다른 약어(`CustNo` vs `CUSTNO`)는 중복으로 본다고 고정 줄에 적는다.
  - 대소문자를 그대로 둘지는 시스템 탭의 DBMS 설정과 묶어 보조 칸에서 안내한다.

### UX-18 (낮음) 변경 이력 · 화면 안내
- 변경 이력은 버전 한 줄에 여러 변경이 생긴다. "단어 영문약어명 6 → 8자 외 3곳 [펼치기]"로 쓰고, 펼치면 `항목 · 필드 · 이전 → 이후`를 보인다. 줄을 누르면 그 버전을 조회한다(UX-02).

## 4. 단계(§7)에 대한 UX 쪽 제안
- P3(편집 UI)보다 먼저 **오류 문구 형식 + [기준 보기] 연결(UX-02)** 을 P2에 넣는다. 판정을 바꾸는 P2에서 사유 객체 모양이 정해지기 때문이다.
- P3 안 순서: 요약 표(조회 전용 · 모델러) → 행 펼침 편집 → 서로 맞지 않는 설정 검사 → 명명 규칙 미리보기 → 영향 창 → 변경 제안.
- 브라우저 확인에 다음 상태를 추가한다: 모델러가 오류 → [기준 보기] → 해당 줄 강조 · 옛 버전 조회, DA가 구분자 `-` 선택 → 경고 → 영향 창 확인 체크.

## 5. 요약 표

| # | 심각도 | 한 줄 |
|---|---|---|
| UX-01 | 높음 | 필드 · 명명 규칙 사이 어긋남(구분자 ↔ 허용 문자 · 단어 ↔ 용어 약어 · 길이 합)을 저장 전에 잡고 바로 고치게 |
| UX-02 | 높음 | 모든 오류 문구에 `기준: 필드 · 규칙 · 검수 기준 vN [기준 보기]` + 해당 줄 강조 · 옛 버전 조회 |
| UX-03 | 높음 | null · [] · all을 숨기고 "쓰지 않음 / 고른 것만 / 모든 기호" 라디오 + 결과 한 줄 |
| UX-04 | 높음 | A안이라도 모델러용 [변경 제안] 흐름 — 요청 "모델러 자유도"와 기대 맞추기 |
| UX-05 | 중간 | 표 행 펼침 채택(카드 · 드로어 대신) — 바뀐 줄 표시 · 접근성 · 고정 줄 규칙 |
| UX-06 | 중간 | "공통표준 기본값에서 n곳 바꿈" + 다른 곳만 보기 + 첫 진입 안내 |
| UX-07 | 중간 | 특수문자 칩 이름 · 붙여넣기 분리 · 전각 처리 · 글자 거르기 |
| UX-08 | 중간 | `on` + `lvl` → [막기][경고만][검사 안 함] 하나, Q2는 분모에 남기기 |
| UX-09 | 중간 | 시험해 보기 = 지금 / 바꾼 뒤 두 줄 + 예시 칩 + 이름 하나로 전체 시험 |
| UX-10 | 중간 | 명명 미리보기 상자(용어 · 엔터티 · 도메인 · 물리명), 구분자 선택지에 결과 예시 |
| UX-11 | 중간 | 영향 창: 어긋남 → 바뀐 규칙 → 막힘 · 경고 · 새로 통과 + 예시 · 목록 링크 → 적용 방식 |
| UX-12 | 중간 | 엔터티 탭은 "(모델)"로 구분하거나 다음 차수로 |
| UX-13 | 중간 | 권한: A + 제안 추천, B는 모델 검증 · 좁히기만 · 출처 배지, C 반대 |
| UX-14 | 중간 | 공통표준 항목은 회색 "기관 기준 예외" 배지 |
| UX-15 | 낮음 | 쉬운 말 표(막기 · 검사 안 함 · 단어 사이 기호 · DB가 쓰는 낱말 …) |
