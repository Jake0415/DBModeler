# 검토 요청: 표준 사전 — 화면 작성 · 품의 · 모델러 생산성 (교차 검증 + UX 전문가 기능 검토)

NeoDB는 데이터 표준 · 모델링 웹 도구입니다(사용자: DA# · ERwin에 익숙한 데이터 모델러 · DA · 표준화 담당자). 지금은 **FE 목업 단계**이고 서버가 없습니다(localStorage 상태). 미리보기: http://localhost:5178 (실행 중).

## 업무 흐름 (이번 검토의 기준)

1. **표준화 담당자가 표준 사전을 먼저 만든다** — 행안부 공통표준을 바탕으로 기관 단어 · 도메인그룹 · 도메인분류 · 도메인 · 용어 · 엔터티 용어 · 코드 · 코드값을 **화면에서 직접 작성 · 수정**한다(엑셀은 보조).
2. 모든 추가 · 변경 · 미사용 · 삭제는 **품의(결재)** 를 거친다 — 결재선 DA(필수) → 최종 승인(기관 설정). 수정이 매우 많아 표준화가 오래 걸리므로, 여러 건을 빠르게 담아 한 번에 품의하는 것이 핵심이다.
3. 그다음 **ERD에서 모델링**하며 사전 용어를 쓴다(사전 패널 · 자동완성 · 표준 맞추기 · 용어 자동분석 마법사). 모델링 중 없는 용어는 바구니 · 후보 큐로 사전에 되돌린다.

## 부탁하는 것

1. **교차 검증(구현 검증 · 시험)**: 위 설계(30 §3.6, 20 §4)가 목업에 맞게 구현됐는지, 아래 시나리오가 실제로 되는지. 브라우저를 쓸 수 있으면 **새 탭**에서만 시험하고(다른 사람과 localStorage 공유 — 시험 전 백업 · 끝나고 복원), 아니면 코드 추적으로 판정하고 그렇다고 밝힌다.
   - S1 표준화 담당자 초기 구축: 도메인그룹 추가(DA) → 분류 신청 → 형식단어 단어 → 도메인 → 용어 · 엔터티 용어 → 코드 · 코드값을 화면(폼 · 화면 일괄 작성)으로 작성 → 바구니 1건으로 품의 → DA · 최종 승인 → 사전 반영(버전 · 이력)
   - S2 대량 수정: 목록 다중 선택 → 같은 값 일괄 변경 / 표에서 고치기 → 품의 → 부분 반려 → 반려 항목이 신청자 바구니로 → 보완해서 재신청
   - S3 이름 · 타입 변경: 단어명 · 용어명 · 도메인명 변경(과거 이름 · 사용처 재검토 안내), 사용 중 항목 삭제 차단
   - S4 모델링 연계: 모델 사전 패널 → 바구니 / 용어 자동분석 → 바구니 · 바로 신청 · 모델 반영
   - S5 엑셀 보조: 단어 · 도메인 · 코드값 엑셀 → 바구니로 보내 직접 입력과 한 품의
   - S6 권한: 모델러(신청만) · DA(결재 · 그룹 관리) · 기관 담당자(최종 승인) · 조회 전용
2. **UX 전문가 기능 검토**: 표준화 담당자가 사전을 먼저 만들고 ERD로 넘어가는 흐름에서
   - 화면 구성 · 진입점 · 정보 구조(사전 메뉴 탭이 많아졌다: 통합 검색 · 화면 일괄 작성 · 도메인 그룹 · 분류 · 엑셀 · 업로드 이력 · 후보 큐 · 변경 내역) — 찾기 쉬운가, 중복 · 혼동은 없는가
   - 바구니 · 초안 · 품의 개념이 사용자에게 명확한가(용어 · 문구 · 상태 표시), 많은 건수에서 빠른가(클릭 수 · 키보드)
   - 검증 피드백(즉시 · 신청 · 승인 시점)의 일관성과 이해도, 오류에서 고치는 길
   - DA의 결재 부담(항목별 반려 · 집계)과 신청자의 추적
   - DA# · SWS 사용자의 기대와 다른 부분, 빠진 기능, 줄여야 할 기능
3. **남은 문제와 수정안** — 심각도(높음 · 중간 · 낮음) · 대상(파일:줄) · 문제 · 근거 · 권장 수정안.

## 형식

- 한국어. 구성: ① 요약 ② 시험 결과 표(S1~S6 + 추가, 통과 · 실패 · 판정 불가 + 재현 절차) ③ UX 기능 검토(화면 · 흐름별) ④ 지적 목록(20건 이내, 심각도 순) ⑤ 권장 최종 흐름(표준화 담당자 → 모델러).
- 코드는 고치지 말고 결과 파일만 쓴다.
