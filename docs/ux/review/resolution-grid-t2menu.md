# 검토 반영: 속성 편집 그리드(16) + 트리 T2 메뉴(12 §9.2)

> 2026-11-19 · 검토 [codex-grid-t2menu](codex-grid-t2menu.md) 15건 · [claude-grid-t2menu](claude-grid-t2menu.md) 14건
> 두 검토는 겹치는 지적이 많아 묶어서 처리했다.

## 반영

| 묶음 | 지적 | 반영 |
|---|---|---|
| **대상을 위치로 넘김** | Codex 7 · Claude 1 · 6 | 트리 명령은 속성 이름(논리명 · 물리명), 관계 양 끝(부모 · 자식 · 종류 · 그룹)을 함께 넘긴다. 모델 화면은 위치가 아니라 이름으로 다시 찾고, 찾지 못하면 실행하지 않는다. 확인 띠는 속성 **객체 자체**를 기억하고 실행 직전에 다시 찾는다. 기다리는 동안 순서가 바뀌거나 지워지면 "찾지 못했습니다"로 끝낸다 |
| **주소만으로 모델이 바뀜** | Claude 2 | `?cmd=`를 없앴다. 다른 화면의 명령은 **이 탭의 1회용 토큰**(sessionStorage, 15초, 같은 사용자 · 같은 영역)으로 넘기고, 도착하자마자 지운다. 링크 · 북마크 · 새로 고침으로는 편집되지 않는다 |
| **다른 버전을 보는 화면** | Codex 7 · Claude 1 | DDL · 산출물이 확정본 · 제출본을 보이는 중이면 그 화면 트리의 편집 명령은 비활성으로 두고 이유를 단다: "이 화면은 v4 확정본을 보여 줍니다 — 작업본(v5) 모델 화면에서 편집하세요" |
| **FK 대응** | Codex 1 · 2 · Claude 4 | FK 컬럼에 `fkp`(받아 온 부모 컬럼)를 기록한다(그리드 전파 · 캔버스 관계 · 재귀 관계).<br>공통 `fkOf`는 위치가 아니라 `fkp` → 같은 이름 → `ORG_` 역할명 순서로 짝을 찾는다. 짝이 비거나 겹치면 누락이다. 부모 PK 순서를 바꿔도 짝이 유지된다.<br>역할명(이름 충돌)으로 전파할 때 관계에 그룹이 없으면 그룹을 만들고 기존 FK에도 붙인다. 그래서 전파 직후 "FK 누락"이 나오지 않는다 |
| **두 경로 · 재귀** | Codex 2 · 3 · Claude 5 | 방문 기록을 엔터티 단위에서 **관계 + 컬럼** 단위로 바꿨다. 같은 자식으로 가는 두 번째 관계와 손자로 가는 두 번째 경로도 따라간다. 같은 자식으로 관계가 둘이면 그룹을 만들어 역할명으로 전파한다. 재귀 관계의 역할명 FK(`UPR_`)도 PK 해제 · 삭제 영향에 넣는다(전파는 역할명을 사람이 정해야 해서 하지 않음) |
| **일반 속성으로 유지** | Codex 4 | 자식 FK를 일반 속성으로 남기면 PK에서도 빼고 일반 묶음으로 옮긴다(`toPlain`) |
| **관계 전환** | Codex 5 | 식별/비식별 전환이 그리드의 PK 편집과 같은 규칙을 쓴다. PK 묶음으로 옮기고, 식별이면 손자에 FK를 전파하며, 비식별이면 손자 FK를 정리한다. 한 번의 실행 취소로 되돌린다 |
| **이름 변경** | Codex 6 | PK 이름을 용어로 바꾸면 자식 FK의 물리명 · 타입 · 도메인 · 짝(`fkp`)이 함께 바뀐다. FK 이름을 바꿔도 부모를 따르는 타입 · 도메인과 짝은 유지한다(역할명 허용) |
| **권한 재확인** | Codex 8 | 다른 탭에서 저장한 계정 정보를 다시 읽는 `liveCanEdit`를 둔다. 모델의 `guard` · `canEdit` · 저장(`saveData`)이 매번 확인한다. 트리 메뉴는 실행할 때 항목 상태를 다시 계산한다. 이름 입력을 연 뒤 잠기면 확정하지 않고 원래대로 되돌린다 |
| **실행 취소 대상** | Codex 9 · Claude 12 | 기록마다 번호를 붙였다. 토스트의 [실행 취소]는 자기 번호가 마지막일 때만 되돌린다(50개 상한에서도 정확). 입력 칸 Esc나 "바뀐 것 없음"은 그 입력이 만든 기록만 지운다 |
| **정의 저장 후 클릭 유실** | Codex 10 | 정의 · 기본값은 패널을 다시 그리지 않고 제자리에서 저장한다 |
| **키보드로 필수 · 도메인** | Codex 11 · Claude 3 | 선택한 행의 상세에 도메인 선택과 필수 체크를 두었다(Tab으로 닿음). 행 단축키 `N` = 필수, `Enter` = 상세의 첫 칸으로 |
| **정의 칸 Esc** | Claude 8 | Esc는 저장된 값으로 되돌린 뒤 빠져나간다 |
| **기본값 · 주석** | Claude 9 · Codex 14 · 15 | 기본값 검사:<br>• 문자 타입이면 따옴표를 붙인다.<br>• 숫자 타입은 숫자만 받는다.<br>• 날짜 타입은 SYSDATE · TO_DATE만 받는다.<br>컬럼 주석은 "논리명 — 정의" 전체를 SQL 문자열로 이스케이프한다.<br>ALTER 출력:<br>• 새 컬럼에 DEFAULT · NOT NULL · 주석을 붙인다.<br>• 기본값 변경 · 해제는 MODIFY DEFAULT로 낸다.<br>• 이름 · 정의 변경은 주석으로 낸다.<br>산출물 정의서 미리보기에 기본값 · 정의 열을 넣었다 |
| **메뉴 접근성** | Claude 10 · Codex 12 | 트리 줄에 `aria-haspopup="menu"`를 넣었다.<br>⋯는 포커스되지 않는 마우스 표시로 바꿨다(키보드는 Shift+F10).<br>바로가기 링크에서는 메뉴 키를 가로채지 않는다.<br>비활성 항목은 Enter · 클릭해도 토스트를 내지 않는다(이유는 이미 이름에 있음).<br>메뉴에 포커스가 있을 때 스크롤 · 창 크기 변경으로 닫히면 그 줄로 돌아간다 |
| **확인 띠 · 문구** | Codex 13 · Claude 14 | 확인 띠의 첫 포커스와 왼쪽 위치는 [취소]로 하고, 위험한 버튼은 오른쪽 끝에 둔다.<br>버튼 이름을 바꿨다:<br>• [속성만 삭제 (관계 유지)] · [관계까지 삭제]<br>• 메뉴 [객체 삭제] → [엔터티 삭제] · [테이블 삭제]<br>[보기에서 빼기]는 목업이 아니라 이유와 함께 비활성으로 둔다. [FK 만들기] 목업 문구는 지원하지 않는 조치를 안내하지 않게 고쳤다 |
| **단축키** | Claude 13 | 추가 단축키를 `Alt+Enter`로 하고(Insert도 유지), 안내 kbd를 12px로 했다 |
| **문서** | Claude 11 | 12 §7.2 T2 끝난 기준과 §9.2를 구현에 맞췄다. [보기에서 빼기]는 T3로 옮겼다. 영역 [결재 이력] → [결재함 열기]. 아래 남긴 것을 적었다 |

## 남긴 것

- **Claude 7** 트리 속성 노드 id가 위치 기준인 점: 순서 변경 · 삭제 뒤에는 모델 화면이 새 위치로 선택을 다시 보내 트리가 따라간다(확인함). 펼침 기억은 엔터티 단위라 영향이 없다. 노드 키를 이름 기준으로 바꾸는 것은 T3 보기 작업 때 함께 한다.
- 영역 메뉴의 [이름 바꾸기 · 정의 · 내보내기 · 확정 신청 · 객체 정보], 엔터티 [보기에 배치…] · [객체 정보]는 T3 이후로 둔다. 용어 [사전 변경 신청]은 지금 사전 검색으로 연결된다.
- 오래된 시드의 역할명 그룹(`fkp` 없음)은 그린 순서로 짝을 짓는다. 그 관계를 다시 그리거나 PK를 전파하면 `fkp`가 채워진다.
