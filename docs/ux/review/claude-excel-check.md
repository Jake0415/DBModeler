- 방법: 내장 브라우저에서 1600×900 · 1920×1080으로 실제 클릭·키보드(Tab · Enter · Esc · F8 · Ctrl+H · Ctrl+Z)로 6단계를 따라감.

  - 내려받기 두 종류는 Blob 내용을 잡아서 CSV 본문을 확인함
  - 결재 재검사 함수(`checkDictDoc`)를 콘솔에서 따로 불러, 5단계 판정과 신청 직전 판정이 같은지 비교함

## 요약

이번에 넣은 **자동 수정 미리보기**와 **찾아 바꾸기**는 뼈대가 좋습니다.

- 행마다 고르기, 규칙별로 걸러 보기, 미리보기 표, 건너뜀 사유, 결재 대기·충돌·빠짐 행 제외, 계산 칸 제외, Esc를 누르면 연 버튼으로 포커스 복귀, 포커스 가둠이 모두 동작합니다.

가장 큰 문제는 **5단계가 '통과'·'신규'라고 보여 준 행을 신청 직전 결재 재검사가 막는 경우가 여러 갈래로 생긴다**는 점입니다.

- 수정 제안 값이 공통 단어의 약어와 겹침
- 이름을 바꿔도 단어 분해를 다시 하지 않음
- 예시 행이 공통표준 전체 적재 이후의 사전과 맞지 않음

이 화면의 약속은 "여기서 고치면 신청이 통과한다"입니다. 이 약속이 깨지면 수천 행 작업에서 신뢰가 무너집니다.

그다음 문제는 **되돌리기 수단이 12초짜리 알림 하나뿐**이라는 점과 **보정본이 엑셀 원본을 대신할 수 없는 모양**이라는 점입니다.

## 발견 사항

### CL-01 · 높음 · 수정 제안·자동 수정이 사전 규칙을 다시 확인하지 않아, 겹치는 약어를 '신규'로 통과시킴
- **위치:** `excel-import.html:494-498` `fixRow`, `:583-585` 자동 수정 적용, `:263-264` 단어 예시의 `fix`
- **문제:**
  - 표준단어 6행 '납품'의 수정 제안은 `DLVR`, 7행 '정비'의 자동 수정은 `MNTN`입니다. 그런데 사전에 공통 단어 '배송'(W-C0981, DLVR)과 '유지보수'(W-C1936, MNTN)가 이미 있습니다.
  - [제안 적용]이나 자동 수정을 적용하면 행이 바로 **신규**가 되고, 오류 바에서도 사라집니다.
  - 같은 값을 찾아 바꾸기로 넣으면 '약어 DLVR을 다른 단어가 씀'으로 **건너뜀**이 됩니다(`:606`). 표에 직접 쳐도 `cellOk`(`:504`)가 거부합니다. 같은 값이 고치는 경로에 따라 통과하기도 하고 막히기도 합니다.
  - 자동 수정 미리보기에는 찾아 바꾸기와 달리 **'검사' 열이 없습니다.** 그래서 바뀐 값이 규칙을 통과하는지 미리 알 수 없습니다.
- **확인 방법:**
  - park · 표준단어 5단계에서 자동 수정 1건을 실제로 적용했더니 7행이 '신규 · 자동 수정(W-ABBRLEN)'이 되었습니다.
  - 6행 [제안 적용] 결과도 '신규'였습니다.
  - 콘솔에서 `checkDictDoc`(정비/MNTN)을 불렀더니 "약어 MNTN를 '유지보수'가 씀"이 나왔습니다. 신청 단계에서는 막힙니다.
- **제안:**
  - 제안 적용, 자동 수정, 찾아 바꾸기, 표에서 직접 고치기가 모두 **같은 칸 검사 함수 하나**(`cellOk`, 최종적으로는 결재 재검사와 같은 원천)를 거치게 하세요.
  - 자동 수정 미리보기에도 '검사(통과/건너뜀·사유)' 열을 넣으세요. 통과하지 못하는 행은 기본으로 고르지 않게 하세요.
  - 제안 값을 만들 때 이미 쓰는 약어는 피해서 후보를 만드세요(예: DLVR → DLVRY 등).

### CL-02 · 높음 · 이름을 바꿔도 단어 분해를 다시 하지 않음 — 미등록 단어가 들어간 용어가 '통과'

  - 표준용어에서 찾아 바꾸기로 '요구사항'을 사전에 없는 말 '허허'로 바꿨습니다. 5행(변경)·6행(동일)·14행(오류)의 용어명이 모두 **통과**로 바뀌었습니다.
  - 6행은 동일에서 **변경**이 되어 '허허ID'로 이름을 바꾸는 신청이 되었습니다. 약어는 `DEMND_MATER_ID` 그대로 남아 이름과 약어가 서로 맞지 않습니다.
  - 6단계 요약에는 '신청 6건'에 그대로 포함됩니다.
  - 기존 항목의 이름을 바꾸는 것은 영향이 큰 변경입니다(모델 사용처). 그런데 경고도 없습니다.
- **확인 방법:**

  - 콘솔 `checkDictDoc`은 두 행 모두 "미등록 단어: 허허"로 막습니다.
- **제안:**
  - 용어명을 바꾸면 행 상태와 관계없이 분해·약어 재계산·미등록·승인 대기 판정을 다시 하세요. 미리보기 '검사' 열에 결과를 보여 주세요.
  - 기존 항목의 **이름 변경**은 찾아 바꾸기 대상에서 기본으로 빼거나, '이름 변경 N건 — 사용처 영향' 경고와 확인을 따로 받으세요.

### CL-03 · 높음 · 5단계 판정과 결재 재검사가 다름 — 예시 행이 공통표준 적재 이후 사전과 맞지 않음
- **위치:** `:258-266` 단어 예시(검수 · 점검 · 정비 · 납품을 '신규'로 둠), `:223` 용어 11행 '수령자명'을 '선행 승인 필요'로 고정, `:315` `openCheck`
- **문제:**
  - 공통표준 전체 적재(커밋 45a6361) 뒤에는 검수(W-C0182) · 점검(W-C2310) · 정비(W-C2342) · 납품(W-C0578)이 **이미 공통 단어**입니다. 수령자명도 공통 용어 T-C05992로 이미 있습니다.

- **제안:**
  - 예시 행에 고정해 둔 상태(st)를 그대로 믿지 말고, `seedRows` 단계에서 **결재 재검사와 같은 함수**로 다시 판정하세요. 예시 값도 지금 사전에 맞게 바꾸세요.
  - 구조로 보면 5단계의 '신규·변경' 판정 = `checkItem`/`checkDictDoc` 결과여야 합니다(07 §3 E3 "엑셀·화면·서버 같은 문장").

### CL-04 · 높음 · 되돌리기 수단이 12초짜리 알림 하나뿐 — 대량 바꾸기 뒤에 되돌릴 길이 없음
- **위치:** `:490-493` `afterEdit`, `assets/app.js:1974` (작업이 붙은 알림은 12초 뒤 사라짐)
- **문제:**
  - 찾아 바꾸기·자동 수정 뒤의 [실행 취소]는 알림 안에만 있습니다. 미리보기 표를 다시 살펴보는 사이 알림이 사라지면 **되돌릴 수 없습니다.**
  - Ctrl+Z도 동작하지 않습니다. 툴바에 되돌리기 버튼이나 작업 기록도 없습니다.
  - 필터를 건 상태에서 바꾸면 바뀐 행이 필터에서 빠져(예: 동일 → 변경) 화면에서 사라집니다. 그래서 무엇이 바뀌었는지 바로 확인하기도 어렵습니다.
- **확인 방법:**
  - kim · 용어에서 찾아 바꾸기 뒤 6단계를 다녀오는 사이 [실행 취소] 버튼이 없어졌습니다(ref stale). 이어서 Ctrl+Z를 눌렀지만 값이 그대로였습니다.
  - 코드값 '동일' 필터에서 A→Z로 바꾼 뒤에는 3행이 목록에서 사라졌습니다.
- **제안:**
  - 툴바에 **[되돌리기 ▾ (작업 N)]** 을 두세요. 작업 이름·건수·시각이 보이는 기록에서 마지막 작업부터 되돌리게 하고, Ctrl+Z를 연결하세요.
  - 대량 작업 뒤에는 '방금 바꾼 N행만 보기' 필터를 자동으로 켜세요.

### CL-05 · 높음 · 코드값 찾아 바꾸기가 짝짓기 키(코드값)를 바꿔 '변경'으로 표시함
- **위치:** `:604-605` `frOk`(코드 'v' 칸), `:648-651`, `:660-667` 코드 `buildItems`
- **문제:**
  - 코드값은 **코드+코드값**으로 짝을 찾습니다(행 패널에도 그렇게 적혀 있음).
  - 그런데 '동일' 행 3행(A 분석)의 코드값을 Z로 바꾸면 '변경 · 찾아 바꾸기로 바뀐 칸'이 되고, 패널의 짝도 '값 Z'로 바뀝니다.
  - 실제 신청 항목은 `vals`에서 Z를 찾지 못해 **Z 분석을 새로 추가하고 A는 그대로 둡니다.** 화면에 '변경'이라고 보인 것과 실제 결과가 다릅니다.
- **확인 방법:** kim · 코드값에서 동일 필터 → Ctrl+H → 코드값 칸 · 칸 전체 일치로 A→Z를 실행했고, 패널에서 '현재 사전 A / 파일 Z · 짝 값 Z'를 확인했습니다.
- **제안:**
  - 짝짓기 키 칸(코드값, ID가 있는 행의 이름)은 찾아 바꾸기 대상에서 빼세요.
  - 꼭 바꿔야 하면 '값 A 미사용 + 값 Z 추가'로 풀어서 미리보기에 보여 주세요.

### CL-07 · 중간 · 보정본이 엑셀 원본을 대신할 수 없음 — 빠진 행 · 숨김 열 없음
- **위치:** `:544-547` `dl-fix`, `:354` `applyScope`
- **문제:**
  - 보정본 CSV에 **항목 ID · 버전 · 기준본 숨김 열이 없습니다.** 다시 올리면 이름으로만 짝을 찾게 되어 왕복 계약(07 E2 짝짓기 ①)이 깨집니다.
  - 기준본 범위 밖이라고 비교에서 뺀 행(용어 4행 '요청부서명')과 '파일에서 빠짐' 행도 보정본에서 **빠집니다.** 화면 문구는 "엑셀 원본을 이것으로 맞추세요"인데, 그대로 따르면 원본에서 행을 잃습니다.
  - '상태' 열이 앞에 끼어 있어 열 순서가 원래 양식과 다릅니다.
- **확인 방법:** 보정본 Blob 본문을 확인했습니다. 첫 행은 `원본 행,상태,용어명,약어,도메인,설명,변경점`이고, 2·3·5·6…15행만 있고 4행이 없었습니다.
- **제안:**
  - 원래 양식 열 순서 + 숨김 열(갱신된 버전·기준본) + **파일의 모든 행**을 그대로 담으세요.
  - 변경점은 별도 시트나 끝 열로 두세요(설계 E4 · §4 "보정본·반영본은 내려받은 양식 버전 그대로").
  - CSV라서 시트를 나눌 수 없다면, 목업 문구에 'XLSX 2시트(본문 · 변경점)'라고 명시하세요.

### CL-09 · 중간 · 오류 알림(danger)이 고친 뒤에도 계속 남음
- **위치:** `:514` `revalidate` 실패 알림, `assets/app.js:1974` (danger는 자동으로 닫히지 않음)
- **문제:**

## 꼭 고칠 것 Top 5

1. **5단계 판정 = 결재 재검사로 하나로 통일 (CL-01 · CL-02 · CL-03)**
   - 제안 적용, 자동 수정, 찾아 바꾸기, 직접 입력, 예시 행 판정이 모두 `checkItem`/`checkDictDoc`과 같은 함수를 쓰게 하세요.
   - 자동 수정 미리보기에도 '검사' 열을 넣으세요.
   - "화면에서 통과 → 신청에서 막힘"을 없애는 것이 이 화면의 핵심 약속입니다.
2. **오래 남는 되돌리기 (CL-04):** 툴바에 작업 기록과 되돌리기를 두고 Ctrl+Z를 연결하세요. 대량 작업 뒤에는 '방금 바꾼 행만 보기'를 켜세요.
3. **짝짓기 키·이름 변경 보호 (CL-05 · CL-02):** 코드값과 ID가 있는 행의 이름은 찾아 바꾸기에서 빼세요. 꼭 바꿔야 하면 미사용 + 추가로 풀어 보여 주고, 사용처 영향 경고를 띄우세요.
4. **보정본을 원본 대체용으로 (CL-07):** 원래 양식 열 순서, 숨김 열(ID · 버전 · 기준본), 파일의 모든 행, 변경점 시트를 담으세요.
5. **상태 표시 일관성 (CL-06 · CL-08 · CL-09 · CL-12):** 행 패널에 파일 값과 보정 값을 따로 보여 주세요. 하단 오류 수와 진행률을 갱신하고, 지난 오류 알림과 이전 단계 차단 문구를 정리하세요.
