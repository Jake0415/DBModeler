# 리뷰 결과 — 모델 트리의 업무 영역 메뉴 구조 (Claude)

## 한 줄 총평
트리는 **객체를 찾는 곳**, 화면 이동은 **화면 머리**가 맡아야 한다. 지금은 화면 이동 4개가 트리 안 회색 글자로 숨어 있고, 지금 영역에만 보여서 영역마다 모양이 다르다. 바로가기 줄과 설명 줄을 트리에서 빼고, 화면 머리의 경로 옆에 **'영역 화면' 세그먼트(아이콘 + 글자 + 미준수 배지)** 를 두기를 권한다.

## 지적

**CL-01 · 높음 · 선택 메뉴가 메뉴로 보이지 않는다**
- 근거: `app.css:325-329` — 13px `--fg-2` 글자, 테두리 · 바탕 없음, 밑줄은 hover 때만, 현재 화면은 굵기(500)만 다르다. 설명 줄(`app.css:334`, 12px 회색) 바로 아래에 있어 설명의 연속으로 읽힌다.
- 권고: 버튼 규격(가이드 `01-design-guide.md:144`, 28/32)을 따르는 컨트롤로 바꾼다. 굵기만으로 현재 위치를 표시하지 않는다.

**CL-02 · 높음 · 지금 영역과 다른 영역의 모양이 다르다**
- 근거: `app.js:1335` `showDesc`(기본 `'cur'`, `app.js:1332`), `app.js:1374`(바로가기 · **다이어그램 폴더까지** 조건 안에 있다), `app.js:1517`. 다른 영역은 펼쳐도 다이어그램 폴더조차 없다.
- 권고: 펼친 영역은 모두 같은 자식 구조를 갖는다(다이어그램 · 엔터티 · 관계 · 사용한 표준). 지금 영역은 모양이 아니라 **표시**(왼쪽 3px 파랑 막대 + `aria-current="true"`)로 구분한다.

**CL-03 · 중간 · 트리 안에 링크가 섞여 의미 구조가 흐려진다**
- 근거: `app.js:1512` `<a role="treeitem">`가 형제 수(`aria-posinset/setsize`)에 들어간다. 그래서 Enter/Space(`app.js:1572-1573`), 우클릭(`app.js:1727`), F2/Delete(`app.js:1576`)에 예외 처리가 필요하다. 낭독기는 "모델, 1/8"처럼 읽어 객체로 오해한다.
- 권고: 트리에는 객체 노드만 둔다. 이동은 `<nav>` 안 링크로 옮긴다. 예외 분기는 지운다.

**CL-04 · 중간 · 같은 목적지가 세 곳에 흩어져 역할이 겹친다**
- 근거: 영역 ⋯ 메뉴(`app.js:1616` 모델 열기 · 표준 맞추기 · DDL 만들기 · 산출물), 경로의 영역 링크(→ model.html, `ddl.html:21`, `standardize.html:27`, `outputs.html:28`), 트리 바로가기(`app.js:1377`).
- 권고: 역할을 나눈다(아래 '역할 분담').

**CL-05 · 중간 · 설명 줄이 트리 공간과 주의를 차지한다**
- 근거: `app.js:1517`, `app.css:334`. 영역 설명은 한 번 읽으면 끝나는 정보인데, 트리에 늘 한 줄을 차지한다. 거르기 메뉴에는 '영역 설명' 설정이 따로 있다(`app.js:1460`).
- 권고: 설명은 영역 행 툴팁(`title`)과 `aria-describedby`로 옮기고, 시스템 홈 영역 카드에 정식으로 둔다. 거르기의 '영역 설명' 설정은 없앤다.

**CL-06 · 낮음 · 가이드의 탭 쓰임과 맞지 않는다**
- 근거: `01-design-guide.md:157-164`(구역 전환 = 밑줄 탭, 보기 전환 = 세그먼트), `01-design-guide.md:131 · 213`(사전 하위 화면은 머리 아래 '사전 탭 줄'로 묶는다). 모델 계열 4화면은 '같은 영역의 다른 화면'이라 사전 탭 줄과 같은 성격인데, 지금은 트리 링크로 따로 놀고 있다.
- 권고: 한 역할 = 한 부품(`01-design-guide.md:20`). 화면 머리에서 같은 위치 · 같은 부품으로 전환한다.

### '영역 화면' 세그먼트 표현
- 마크업: `<nav aria-label="인사관리 화면">` 안 `<a>` 4개, 현재 화면은 `aria-current="page"`. 이동이므로 `aria-pressed` 버튼이 아니라 링크다. 모양만 `.seg`를 쓴다. 이 구분을 가이드 §6.3에 한 줄 추가한다.
- 크기: 높이 **28**(`.sm`, 머리 안), 항목 가로 여백 8, 아이콘 16 Lucide(모델 `flow` · 표준 맞추기 `check` 계열 · DDL `code` · 산출물 `file-text`) + 14px 글자. 글자를 지우지 않는다. 항목 클릭 영역은 28px 이상이다.
- 미준수 배지: `표준 맞추기` 뒤 알약 배지 `5`(12px mono, amber-900 글자 · amber 연한 바탕, 4.5:1 이상). 0이면 숨긴다. 이름은 "표준 맞추기, 미준수 5"로 읽는다.
- h1: 보이는 제목은 세그먼트의 현재 항목이 대신한다. 낭독용 `<h1 class="sr-only">인사관리 — DDL</h1>`은 남긴다.

| 상태 | 표시 |
|---|---|
| 현재 화면 | 흰 바탕 + 1px 링 + 글자 `--fg` 500 + 아이콘 `--fg`. 굵기 외에 **바탕 · 링**으로 구분(색만 쓰지 않음) |
| 기본 | 바탕 없음, 글자 `--fg-2`(4.5:1 이상), 묶음 바깥 1px 테두리(3:1) |
| hover | gray-100 바탕, 글자 `--fg`. 밑줄 없음 |
| focus | 안쪽 2px `--focus` 링(`01-design-guide.md:113`의 세그먼트 규칙). 링크 4개가 각각 Tab 정지점이다(4개라 부담이 적다). ←→ 이동은 넣지 않는다 |
| 조회 전용 · 스냅숏 | 링크에 `snap`을 이어 붙인다(`app.js:1376` 규칙 유지). `표준 맞추기`만 작업본 기준이므로 툴팁 · 이름에 "작업본 기준"을 붙이고 배지는 작업본 수를 보인다. 상태 배지는 "v4 확정본 · 조회"로 바뀐다 |
| 권한 없음 | 숨기지 않고 비활성(gray-100 · gray-700) + 툴팁으로 이유 |

### 역할 분담
| 자리 | 맡는 일 |
|---|---|
| 머리 세그먼트 | **지금 영역**의 4화면 사이 전환(주 경로) |
| 경로 | 위로 가기만: 시스템 → 시스템 홈, 영역 → 시스템 홈의 그 영역 카드. 영역 링크가 model.html로 가는 중복은 없앤다 |
| 영역 행 ⋯ | **어느 영역이든** 열기 · 표준 맞추기 · DDL · 산출물 + 결재함 · 보기 추가 · 복제(지금처럼, `app.js:1616`). 홈 · 시스템 홈처럼 머리 세그먼트가 없는 화면의 이동 수단 |
| 영역 행 클릭 · Enter | 펼치기/접기(지금처럼, `app.js:1536`). 더블클릭 = 모델 열기 |
| 트리 | 객체만. 설명은 툴팁 · 시스템 홈 카드 |

## 적용 범위 · 순서
1. **트리 정리**: `app.js:1374-1381`에서 바로가기를 빼고 다이어그램 폴더는 모든 영역에 둔다. `app.js:1517` 설명 줄 → 영역 행 `title` · `aria-describedby`. `app.js:1332 · 1335 · 1460 · 1751-1753`의 '영역 설명' 설정 삭제. `app.js:1510-1512 · 1550 · 1572-1576 · 1727`의 링크 예외 정리. `app.css:325-334` 삭제.
2. **지금 영역 표시**: 영역 행에 3px 파랑 막대 + `aria-current`.
3. **머리 세그먼트**: 공통 부품 하나를 app.js에서 만들어 model · standardize · ddl · outputs 머리에 넣는다. 경로 영역 링크의 목적지를 바꾼다.
4. **문서**: `12-model-tree-plan.md` §4 · §4.1 · §9.4의 바로가기 줄 결정을 고치고, `01-design-guide.md` §5 페이지 헤더 · §6.3에 '영역 화면' 세그먼트(링크형)를 추가한다.
5. **검증**: 퍼블리싱 점검 1920 · 1600으로 머리 폭이 넘치지 않는지 확인한다(넘치면 1600에서 아이콘 + 글자 유지, 보조 버튼을 ⋯로 접기). 낭독기로 트리와 nav를 확인하고, 다크 테마 대비도 확인한다.
