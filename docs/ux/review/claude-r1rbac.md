# R1 RBAC 검토: Claude (커밋 0d4ce24 · 15-rbac.md)

> 대상: `git show 0d4ce24`(`app.js` PERMS·canUser·can·canActOn, `approvals`·`audit`·`candidates`·`dictionary`·`import`·`model`·`settings`·`standardize`·`system`)와 [15-rbac.md](../15-rbac.md)
> 방법: 코드만 읽고 판단했다(브라우저 미사용). 줄 번호는 지금 작업 사본 기준이다. 코드는 고치지 않았다.

## 총평

권한표를 `PERMS` 한 곳에 두고, 설정 권한표 탭·사용자 "할 수 있는 일"·화면 검사가 같은 데이터를 쓰는 구조가 좋다. 결재 대기·대기 표시·문서 보기 판단을 `canActOn`/`can('appr.viewall')`로 묶은 것도 맞는 방향이다.

다만 문제가 넷 있다.
1. 담당 시스템을 판정하는 `sysOfArea`가 **새로 만든 영역의 시스템을 잘못 읽는다.**
2. 표에 있는 권한 가운데 **실제로 검사하지 않는 것**(사전 신청)이 있다.
3. 담당 시스템 제한 때문에 **아무에게도 가지 않는 결재**를 막을 장치가 없다.
4. 결재 알림은 여전히 역할만 보고 보낸다.
