## 0. 한 줄 결론
배치는 두 화면 모두 가이드대로 맞았다. 1920 기준으로 입력은 x284 ~ 1044, 보조 칸은 x1076 ~ 1596, 오른쪽 빈 폭은 16%다. 화면 안내 버튼은 두 화면 모두 탭 줄 오른쪽 끝(x1810)에 있다.
**문제는 저장 동작에 몰려 있다.**
- 마이페이지는 프로필에 형식 오류가 하나만 있어도 알림 설정 · 환경까지 **말없이 저장하지 않는다**.
- 테마 버튼(바로 적용)을 누르면 **페이지가 새로 고침되어** 저장하지 않은 변경이 위험해진다.
- 오류를 처리하는 방식이 설정(전부 막음 + 토스트)과 마이페이지(탭 순서대로 저장하다 멈춤, 토스트 없음)에서 다르다.
- 탭 미저장 점은 CSS 충돌로 6px가 아니라 **12px**로 그려진다. 화면 낭독기에는 이 점이 전혀 전달되지 않는다.

## 1. 항목 (우선순위 순)

### UP-01 · 높음 — 마이페이지 부분 실패: 첫 오류 탭에서 멈추고, 다른 탭도 말없이 저장하지 않음
- **근거**
  - `mypage.html:219-223`: 바뀐 탭을 DT 순서(프로필 → 알림 설정 → 환경)대로 저장하다가, 처음 실패한 곳에서 `return`한다.
    - 프로필만 실패할 수 있고 프로필이 맨 앞이다. 그래서 ‘앞서 저장된 탭만 기준값 갱신’ 분기(`done.length` > 0)는 실제로는 실행될 일이 없다.
    - 실제 동작은 **오류 하나가 나머지 전부를 막는 것**이다.
  - 실측(재현)
    - 바꾼 값: 전화번호 `010-12`, 알림 1칸, 시작 화면 ‘결재함’
    - 환경 탭에서 [저장]을 누르자 프로필 탭으로 넘어가고, 칸 아래에 빨간 글자가 나타났다.
    - **토스트 없음** — `done`이 비어 있어 `toast`를 부르지 않는다(221행).
    - 막대는 그대로 “4건 · 프로필, 알림 설정, 환경”이다. 알림 · 환경도 저장되지 않았다는 사실을 따로 알려 주지 않는다.
    - 포커스는 [저장] 버튼에 남는다(UP-06).
  - 사용자는 알림을 껐다고 생각하고 화면을 떠날 수 있다. 막대가 남아 있지만, 이유가 프로필에만 표시되어 연결 짓기 어렵다.
- **제안**
  1. 저장할 때 **먼저 전부 검사**하고, 오류가 없는 탭은 저장한다.
  2. 결과를 한 문장으로 알린다(토스트 + 막대 메시지).
     - 예: “알림 설정 · 환경을 저장했습니다 — 프로필은 전화번호 형식 오류로 저장하지 않았습니다”
  3. 막대에는 남은 변경만 남긴다.
     - 예: “저장하지 않은 변경 2건 · 프로필 — 오류 1”
  4. 오류 탭을 연 **다음에** 첫 오류 칸으로 포커스를 옮긴다.
  5. 이 규칙(S-7)을 17 §6.5에 ‘오류 없는 탭은 저장’이라고 분명히 적는다. 설정과의 통일은 UP-02에서 다룬다.

### UP-02 · 높음 — 바로 적용인 [테마]가 페이지를 새로 고침해 저장하지 않은 변경과 충돌
- **근거**
  - `mypage.html:171`: 테마 버튼이 `location.reload()`를 부른다.
  - 같은 화면에 `beforeunload`(228행)가 있다. 그래서 프로필 · 알림에 저장하지 않은 변경이 있을 때 [다크]를 누르면 브라우저 기본 경고(“사이트에서 나가시겠습니까?”)가 뜬다.
    - 사용자는 ‘테마를 바꿨을 뿐인데 왜 나가냐’고 묻게 된다.
    - [나가기]를 누르면 변경이 사라진다.
  - 보조 칸에는 “누르면 바로 적용됩니다”라고 적혀 있다. 하지만 실제로는 ‘페이지를 다시 연다’이고, 탭 위치도 프로필로 돌아간다(해시 없음).
- **제안**
  - 테마는 새로 고침 없이 `data-theme`만 바꾼다.
  - 목업에서 새로 고침이 꼭 필요하면, 미저장 변경이 있을 때 앱 확인 창을 띄운다. 문구: “저장하지 않은 변경 n건이 있습니다 — [저장하고 바꾸기] [버리고 바꾸기] [취소]”. 그리고 `#env`로 다시 연다.

### UP-03 · 높음 — 두 화면의 실패 처리 · 검사 시점이 다르다
| | 설정(`settings.html:316-324`) | 마이페이지(`mypage.html:216-226`) |
|---|---|---|
| 오류 하나 | **모두 저장 안 함** + 토스트 “저장하지 않았습니다 — 허용 범위를 벗어난 값 1건…” | 앞 탭은 저장하고 오류 탭에서 멈춤, 뒤 탭도 저장 안 함, 토스트 없음 |
| 포커스 | 탭을 연 뒤 오류 칸으로(실측 `org-goal`) | 오류 칸 포커스를 먼저 시도해 실패 → [저장]에 남음 |
| 검사 시점 | 입력 · 칸 떠날 때 바로(233행) | [저장] 때만 |
| 오류 표시 | 칸 옆 `.ferr` + `aria-invalid` | 행 아래 캡션 하나(전화 · 이메일 공용), `aria-invalid` 없음, 표시 이름은 토스트만 |
- 요청서 1번 ‘같은 규칙으로 동작’에 정면으로 어긋난다.
- **제안**: 두 화면을 같은 규칙으로 맞춘다.
  - 실패 처리는 UP-01의 규칙(먼저 전부 검사 → 오류 없는 탭 저장 → 결과 한 문장)으로 맞춘다.
    - 설정은 탭끼리 묶여 영향이 큰 값(결재선 · 정책 버전)이 있다. 그래서 ‘하나라도 틀리면 전부 안 함’도 받아들일 수 있다.
    - 그렇게 하려면 마이페이지도 같은 방식으로 바꾸고, 17 S-7 문구를 그에 맞게 고친다. 어느 쪽이든 **하나로 정해 S-7에 적는다**.
  - 검사 시점은 ‘칸을 떠날 때 + 저장 때’로 통일한다.
  - 오류 표시는 칸마다 `.ferr` + `aria-invalid`로 통일한다.

### UP-04 · 중간 — 탭 미저장 점이 12px로 그려짐(CSS 충돌)
- **근거**
  - `app.css:329-333`의 트리용 전역 규칙 `.tdot:not(.ok):not(.half):not(.ex) { width:12px; height:12px }`는 명시도가 (0,4,0)이다.
  - 공통 묶음의 `.tabs .tdot { width:6px; height:6px }`(896행, 명시도 0,2,0)보다 높아서 탭 점에도 12px가 적용된다.
  - 실측: 마이페이지 · 설정 둘 다 computed 크기가 `12px × 12px`다. 의도한 크기의 2배라 탭 글자(14px)와 거의 같은 무게로 보인다.
  - 공통 CSS로 옮기면서 생긴 **다른 규칙과의 충돌**이다(요청서 5번).
  - 그 밖에 `.set-row` · `.setbar` · `.aside` · `.lastchg`를 쓰는 파일은 `mypage.html` · `settings.html` 둘뿐이다.
    - `.aside`는 `.set-row > .aside`로 범위가 한정되어 있어, app.js가 만드는 `<aside class="scr-panel">`과 충돌하지 않는다.
- **제안**
  - 클래스 이름을 `.tabdot`처럼 따로 쓰거나, `.tabs button .tdot.sdot`처럼 명시도를 올린다.
  - 색 `#f5a623`은 흰 바탕에서 대비가 약 1.9:1이다. 그래픽 대비 기준(3:1)에 못 미치므로 `--ds-amber-700` 이상으로 올린다.

### UP-05 · 중간 — 탭의 현재 위치 · 미저장 상태가 화면 낭독기에 전달되지 않음
- **근거**
  - 탭이 `role="tab"` · `aria-selected` · `aria-current`가 없는 평범한 버튼이다. 현재 탭은 `class="on"`으로만 표시된다(`app.js:2263`).
  - 점은 `aria-hidden="true"`이고, 미저장 상태는 `title`(`mypage.html:190`, `settings.html:276`)로만 알린다. `title`은 낭독기에서 읽히지 않는 경우가 많다.
  - 가이드 §3.4의 ‘탭에 미저장 점(**낭독 이름 포함**)’을 지키지 못했다.
- **제안**
  - 점 옆에 `<span class="sr-only">· 저장하지 않은 변경 1건</span>`을 넣는다.
  - 탭 줄은 `role="tablist"` + `aria-selected`로 바꾸거나, 최소한 `aria-current="true"`를 붙인다.
  - 공통 탭 처리(`app.js:2260`)에서 한 번에 넣으면 두 화면에 함께 적용된다.

### UP-06 · 중간 — 마이페이지 오류의 접근성(포커스 · 낭독 · 표시)
- **근거** (`mypage.html:150-154, 221`)
  - 다른 탭에 있다가 [저장]을 누르면 `saveProfile()`이 **숨은 칸**에 `focus()`를 먼저 부르고, 그다음에 탭을 연다. 포커스는 실패하고 [저장]에 남는다(실측 `activeElement = sb-save`).
  - `#p-cerr role="alert"`의 글자가 **숨은 탭 안에서** 바뀐다. 이런 경우 낭독기가 알림을 읽지 않을 수 있다.
  - `aria-describedby`는 전화번호에만 붙는다. 이메일 오류는 칸과 이어져 있지 않다.
  - `aria-invalid`를 쓰지 않는다. 설정은 쓴다.
  - 표시 이름이 비었을 때는 토스트만 뜬다. S-7(‘칸 아래 이유’)에 어긋난다.
- **제안**
  - 순서를 ‘탭 열기 → 오류 문구 → 포커스’로 바꾼다.
  - 칸마다 오류 문구를 두고 `aria-invalid` + `aria-describedby`를 붙인다.
  - 표시 이름 오류도 칸 아래에 보인다.

### UP-07 · 중간 — 저장 막대 메시지가 글자를 칠 때마다 다시 낭독될 수 있음
- **근거**: 두 화면 모두 `content`의 `input` 이벤트마다 `refreshBar()`가 `#sb-msg`(`aria-live="polite"`)의 `innerHTML`을 통째로 바꾼다(`mypage.html:193, 227`, `settings.html:279, 311`).
  - 전화번호를 칠 때마다 낭독기가 “저장하지 않은 변경 1건 · 프로필”을 반복해 읽을 수 있다.
- **제안**
  - 건수나 탭 목록이 **바뀔 때만** 문구를 다시 쓴다.
  - 또는 live 영역을 짧은 상태 문구(“저장하지 않은 변경 생김” / “저장됨”)로 따로 분리한다.

### UP-08 · 중간 — ‘바로 적용’ 표시가 동작한 칸에서 멀고, 문구가 제각각이며, 하나는 빠짐
- **근거**
  - 시선 이동(1920 실측)
    - 테마 · 표 밀도 버튼은 x284 ~ 500, 단축키 체크는 x284 ~ 300, 시작 화면은 x284 ~ 524에 있다.
    - 보조 칸은 x1076에서 시작한다. 그래서 누르는 순간 알아야 하는 정보(‘저장 안 해도 됨’)가 **약 550 ~ 780px 오른쪽**에 있다.
  - 문구가 넷으로 갈린다.
    - “누르면 바로 적용됩니다”(테마 · 밀도)
    - “바로 적용됩니다”(단축키)
    - “이 버튼으로 바로 바뀝니다 — 아래 저장 막대와 따로입니다”(비밀번호)
    - 세션 [로그아웃]은 표시가 **없다** — S-6 위반(`mypage.html:77`).
  - 설정 쪽 바로 동작([테스트 발송] `settings.html:88`, 매핑 [기본값으로] 114행, [영향 미리보기])에도 표시가 없다.
    - 특히 [기본값으로]는 값을 덮어쓰는 동작처럼 보이는데, 저장 막대와 어떤 관계인지 알 수 없다.
- **제안**
  1. 바로 적용되는 컨트롤 **바로 옆**(입력 칸 안)에 작은 회색 태그 `바로 적용`을 붙인다. 문구는 이 한 가지로 고정한다.
  2. 보조 칸에는 결과 설명만 남긴다.
     - 예: 단축키 “화면 낭독기 · 음성 입력을 쓰면 끄세요”
  3. 세션 행 보조 칸 첫 줄을 “[로그아웃]은 바로 적용 · 그 기기는 다시 로그인해야 합니다”로 쓴다.
  4. 설정의 [기본값으로]는 막대 대상으로 넣는다(화면 값만 바꾸고 [저장] 때 반영). 그게 아니면 확인 창을 띄운다.

### UP-09 · 중간 — 환경 탭이 ‘바로 3개 + 저장 1개’로 섞여 있음
- **근거**: 환경 4행 가운데 시작 화면만 막대 대상이다(`mypage.html:84`, 174행).
  - 앞의 세 행에서 ‘누르면 된다’를 배운 사용자가 시작 화면도 바로 된다고 여기고 떠나기 쉽다.
  - 떠나기 직전 브라우저 경고를 보고서야 저장이 필요하다는 것을 알게 된다.
  - 시작 화면은 ‘다음 로그인부터’라 미리 볼 것도 없고 위험도 낮다.
- **제안**
  - 시작 화면도 **바로 적용**으로 바꾼다. 토스트: “다음 로그인부터 ‘결재함’으로 시작합니다”.
  - 그러면 환경 · 보안 탭은 모두 바로 적용, 프로필 · 알림 설정은 모두 저장 막대로 **탭 단위로 갈린다**. 혼동이 가장 크게 줄어든다.
  - 이 경우 환경 탭의 점 · 막대 대상(DT)에서 `env`를 뺀다.
  - 화면 안내 env 탭 문구(`app.js:1318`)도 함께 고친다.

### UP-10 · 중간 — 짧은 컨트롤이 760으로 늘어남(테마 · 표 밀도 · 표시 이름)
- **근거**
  - 실측: `.seg`(테마 · 표 밀도)가 그리드 칸 안에서 늘어나 **760px 테두리 상자** 안에 버튼 3개가 왼쪽에 몰려 있다(환경 탭 캡처). 빈 테두리가 입력칸처럼 보인다.
  - 표시 이름 입력도 760px다(`.input { width:100% }`). 가이드 §3.2의 ‘한 줄 텍스트 240 ~ 368’을 넘는다. 10자 남짓한 이름에 760px 칸은 지나치다.
- **제안**
  - `.set-row > :nth-child(2)`에 `justify-self:start`를 주거나, `.seg`에 `width:max-content`를 준다. 이렇게 하면 두 화면 공통으로 해결된다.
  - 표시 이름은 `u-w-368`으로 한다.
  - 시작 화면 행의 칸 위 라벨 “로그인 후 첫 화면”은 행 라벨과 겹친다. `aria-label`로 옮긴다.

### UP-11 · 중간 — 알림 설정 표가 ‘좁아’ 보이는 게 아니라 너무 넓어 체크칸이 라벨에서 멀다
- **근거**

  - ‘넓은 행 = 표를 1200까지 **허용**’이지 ‘1200으로 늘리기’가 아니라고 가이드 §3.3에 적는다.

### UP-12 · 중간 — 보조 칸 문구의 말투 · 길이 · 용어가 두 화면에서 갈림
- **근거**
  - 말투
    - 설정은 명사형 종결이 섞여 있다(“저장하면 다음 신청부터 적용 · …”, “다음 DDL 만들기 · 물리 반영부터 적용”).
    - 마이페이지는 ‘-ㅂ니다’다.
  - 적용 시점 표현
    - 설정: “저장하면 다음 신청부터 적용”
    - 마이페이지: “아래 [저장] 뒤 다음 로그인부터 적용됩니다”
  - 길이: 알림 보조 칸(`mypage.html:61`)은 한 `<span>`에 사실 세 개를 마침표 · 가운뎃점을 섞어 붙였다.
  - 용어
    - 같은 문장 안에서 “관리자가 바꿉니다 — 틀렸으면 **Admin**에게”(36행)라고 섞어 쓴다.

  - 빠진 정보: 연락처 · 표시 이름 · 알림은 **언제 반영되는지**(저장 즉시)가 없다. 바로 적용과 대비되는 기준이 화면에 없다.
  - 순서
    - 가이드 §3.2의 ①마지막 변경 → ②적용 시점 → ③영향 → ④링크 순서를 마이페이지는 따르지 않는다(연락처: 대상 → 감사 로그).
    - ‘마지막 변경’이 와야 할 `.lastchg` 자리(`#nt-state`)에 “앱 알림 끔: …” 같은 **현재 상태 요약**이 들어간다.
- **제안** (말투는 ‘-ㅂ니다’로 통일하고, 한 줄에 한 가지 사실만)

| 행 | 지금 | 제안 |

### UP-23 · 낮음 — 내 신청 · 내 작업 표가 본문 전체(1880)이고 두 탭의 꼴이 다름
