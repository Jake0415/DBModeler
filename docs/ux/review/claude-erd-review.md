# ERD(모델) 화면 리뷰 — Claude UX (2026-11-23)

확인 방법: 브라우저 1600×900에서 `?as=kim&audit=1` · `as=hyun&area=risk`를 직접 열고, 핵심 작업(엔터티 → 속성 → 관계)을 키보드·마우스로 따라 했다. 측정값은 DOM 실측이다. 근거는 `docs/ux/mockups/model.html`(이하 `M`), `assets/model.css`(이하 `C`).

## 한 줄 총평
캔버스 안 편집 흐름(E → 이름 → Enter → 속성 → R → 자식 고르기)은 DA#·ERwin보다 빠르고 키보드로 끝까지 된다. 문제는 **캔버스 바깥**이다. 같은 목적지(표준 맞추기)로 가는 길이 5개나 되고, 머리는 한 줄에 8덩어리를 넣다가 영역 이름이 세로로 깨진다. 맞춤은 노드를 조작부 아래에 숨긴다. 1600에서 캔버스는 816px뿐이다.

## 지적

### UX-01 · P1 · 맞춤(Shift+1)이 노드를 띠·조작부 밑에 숨긴다
- 근거: `fit()`은 원점(0,0)부터 최대 좌표까지만 재고, 위 80 · 아래 60px만 비운다(`M:1310`). 실측으로는 도구 막대 37 + 미준수 띠 47 = 84px이라 위쪽 4px가 가려진다. 아래는 범례·줌(816~888)과 미니맵(1028~1208 × 768~888)이 132px를 차지한다. 그 결과 산출물이력 노드(481~632 × 783~869)는 범례·줌 밑에, H노드(1030~1180 × 657~776)는 미니맵 밑에 깔렸다. 시스템 보기 `sysFit()`은 띠 높이를 빼고 계산한다(`M:1301`). 모델 보기만 빠져 있다.
- 권고: `fit()`이 경계 상자(min~max)를 쓰게 한다. 위 여백은 `toolbar + .cv-banner 실제 높이 + 12`, 아래 여백은 `조작부 실제 높이 + 12`로 잡고, 미니맵이 펼쳐져 있으면 오른쪽 아래 구역도 비운다. 띠가 접히거나 펼쳐지면 다시 맞춘다.

### UX-02 · P1 · 빈 곳 두 번 누르기가 범례·버튼 위에서도 엔터티를 만든다
- 근거: 두 번 누르기 제외 목록에 `.legend` · `.mini-open` · `.side-tab` · `.rp-tab`이 없다(`M:1181`). 엔터티 도구의 클릭 제외 목록도 같다(`M:1154`). 실측: 범례 글자를 두 번 누르니 노드가 8 → 9개가 되고 이름 입력 칸이 열렸다.
- 권고: 제외 기준을 "캔버스 위에 뜬 조작 UI 전체"로 바꾼다. 예를 들어 `.cv-ui` 공통 클래스를 달거나 `ev.target !== cv && !ev.target.closest('#world')`로 거른다.

### UX-03 · P1 · '남은 미준수' 띠가 모든 미등록 속성을 '수령자' 문제로 안내하고, 한 번에 예외로 돌린다
- 근거: `candAttrs()`는 미등록 속성을 모두 모은다(`M:326`). 그런데 띠 문구와 예외 대화상자는 "단어 ‘수령자’가 아직 승인 전"으로 고정돼 있다(`M:364`, `M:860`). 실측: 새로 넣은 `교육과정.과정ID`도 "수령자 승인 전"으로 표시되고 [3건 예외로 유지] 대상에 들어갔다. 숫자도 맞지 않는다. 띠는 3건인데 준수 막대·주 버튼은 5건이었다(엔터티 용어 미준수 포함). 사유 하나로 여러 건을 예외로 돌리면 DA 검토가 부실해진다.
- 권고: 띠는 "승인 대기 단어에 걸린 속성"만 세고, 단어별로 묶어 보여 준다. 일괄 예외 버튼은 띠에서 빼고 표준 맞추기(건별 사유)로 보낸다. 미준수 숫자는 한 곳에서 계산한 값 하나만 쓴다.

### UX-04 · P1 · 머리 영역 이름 h1이 세로로 깨진다 (O1 확인)
- 근거: 실측 h1 폭 45px · 높이 112px. `.page-header` 한 줄에 경로 · h1 · 영역 화면(355) · 버전 · 저장 · 접속자(162) · 동작(314)이 다 들어 있다. h1에는 `min-width`도 `nowrap`도 없다.
- 권고: h1에 `white-space:nowrap; min-width:max-content`(상한 넘으면 말줄임 + 툴팁)를 준다. 접속자 글자 "3명 접속 · 2명 편집"은 아바타 툴팁으로 옮긴다(아래 배치안).

### UX-05 · P2 · 표준 맞추기로 가는 길 5개, 확정 신청은 숨는다 (O2 확인)
- 근거: ① 영역 화면 '표준 맞추기 3' ② 준수 막대 '미준수 3' 링크 ③ 준수 막대 [표준 맞추기](`M:52`) ④ 주 버튼 "미준수 3건 해결"(`M:354`, `M:360`) ⑤ 미준수 띠. 주 버튼 이름이 미준수 수에 따라 '해결 ↔ 확정 신청'으로 바뀐다. 그래서 이 화면의 목표인 확정 신청이 미준수 0이 되기 전까지 보이지 않는다. 다이어그램|표(머리)와 [표 보기](도구 막대, `M:84`)도 겹친다.
- 권고: 주 버튼은 늘 **[확정 신청]**으로 두고 미준수 수 배지를 붙인다. 미준수가 있을 때 누르면 오른쪽 패널에 '확정 전 점검'(남은 항목 + 건별 [고치기]/[예외 사유])을 연다. 페이지를 떠나지 않는다. ③ · ⑤의 이동 버튼은 없앤다. ②는 패널 열기로 바꾼다. [표 보기]는 머리 '표'와 하나로 합친다.

### UX-06 · P2 · 1600 폭 예산 — 캔버스 816px (O3 확인)
- 근거: 트리 396~404 + 패널 380. 설계는 "1600에서는 모델 화면이 접힌 채 시작"(`12-model-tree-plan.md:277`)과 "캔버스 약 760"(`03-erd-editor.md:15`)인데, 실제 1600 창에서는 트리가 펼쳐진 채 시작했다.
- 권고: 1600에서는 트리를 아이콘 칸(48)으로 시작하거나 상한 280으로 둔다. 오른쪽 패널은 선택이 없으면 접는다. 업무 영역 요약은 시스템 홈·툴팁으로 옮긴다. 이렇게 하면 캔버스가 1,200px 안팎이 된다.

### UX-07 · P2 · 맞춤 배율의 글자 8.8px — 읽을 수 없는 상세도
- 근거: `.node` 12px(`C:28`) × 0.74 = 8.9px. 자동 단계는 0.35배 미만에서만 요약으로 바뀐다(`M:504`).
- 권고: 자동 단계 경계를 실제 글자 크기 기준으로 바꾼다. 실효 ≥11px이면 전체, 9~11px이면 키만(속성 줄 숨김, 제목 15px), 그 미만이면 이름만. 선택 이름 "표시: 자동(0.35배 미만 요약)"은 "표시: 자동"으로 줄인다.

### UX-08 · P2 · 속성 자유 입력의 출구가 '미매핑'뿐
- 근거: 사전에 없는 이름을 치면 자동완성에 "‘과정ID’ 그대로 입력 (미매핑)" 하나만 뜬다(실측). 후보 등록은 왼쪽 사전 칸 버튼에만 있다(`M:64`).
- 권고: 자동완성 맨 아래에 [단어 후보 등록] · [비슷한 용어 n개]를 둔다. 미준수가 생기는 그 자리에서 막는다.

### UX-09 · P2 · 캔버스 키보드 조작 공백
- 근거: 노드에 `tabindex`·`role`이 없다(`M:446-451`). 키보드만으로 엔터티를 고르려면 트리를 거쳐야 한다. 설계에 있는 Shift+2(선택 맞춤) · Ctrl+K · `?` 도움말 · 화살표 이동(`03-erd-editor.md:183-185`)은 구현되지 않았다. Ctrl+F는 캔버스 찾기가 아니라 표 보기를 연다(`M:1211`). 100% 표시는 `span`이어서 두 번 누르기로만 동작한다(`M:122`, `M:1309`).
- 권고: 노드를 `tabindex=0 role="group" aria-label="엔터티 ○○, 속성 n, 미준수 n"`로 만든다. 화살표로 8px씩, Shift+화살표로 32px씩 옮기고, F2로 이름을 바꾼다. `?`로 단축키 표를 연다. 100%는 `button`으로 바꾼다.

### UX-10 · P3 · 관계 종류 바꾸기에 2클릭이 더 든다
- 근거: 종류는 도구 버튼 ▾ 메뉴에서만 고른다(`M:73-81`). 자식 고르기 팝업은 "유형: 1:N 비식별"을 보여 주기만 한다(실측).
- 권고: 자식 고르기 팝업 위쪽에 종류 칩(비식별 · 식별 · 1:1)을 둔다. 고른 뒤 팝업 안에서 1:2:3 키로도 바꾼다.

### UX-11 · P3 · 하단 조작부 두 줄 · 범례 상시 노출
- 근거: 범례(816) + 줌(848)이 두 줄을 쓴다. 범례는 상태 점 설명이라 익숙해지면 필요 없다.
- 권고: 줌 한 줄(36px)로 줄인다. 범례는 줌 옆 [ⓘ] 팝오버로 옮기고, 처음 쓸 때만 펼친다.

## 핵심 작업 클릭 수 (실측, 미준수 1건 고치는 경우)

```

├ 쪽 머리 44 (한 줄, 줄바꿈 없음) ─────────────────────────────────────────────────────────┤
```

- 머리: 화면 이동(영역 화면) + 목표 하나(확정 신청)만 둔다. ⋯ 안에는 DDL 가져오기 · 이미지 내보내기 · v4 비교만 남긴다. DDL 만들기 · 산출물은 영역 화면과 겹치므로 뺀다.
- 도구 막대: 캔버스를 바꾸는 것 전부(도구 · 보기 · 논리/물리 · 되돌리기). 다이어그램|표, 논리|물리는 머리에서 이리로 옮긴다.
- 오른쪽 패널: 선택한 대상 편집, 그리고 '확정 전 점검'. 요약·도움말 문구(`이 화면에서 해 보기`)는 `?` 도움말로 옮긴다.
- 띠: 한 번에 한 줄. 조회 전용 · 검토 중은 띠 대신 머리 상태 배지와 도구 흐림(`C:81`)으로 충분하다.
