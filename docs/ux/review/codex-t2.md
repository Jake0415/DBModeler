# T1 읽기 트리 구현 검토

**판정: T1 완료 보류.** 작업 사본의 변경분을 계획서 §3.2, §4, §7.2, §8과 정적으로 대조했다. 엔터티를 고르는 기본 경로와 논리·물리 폴더 전환은 연결되어 있다. 객체 종류와 열린 버전에 따라 선택이 달라지는 경우, 키보드 포커스, 캔버스 최소 폭은 보완이 필요하다. 브라우저 실행, 역할 4개 × 1600/1920 키보드 검증, 성능 측정은 수행하지 않았다.

위치 표기는 `docs/ux/mockups/` 기준이다. 보기 전환과 배치·참조 변경은 T3, 편집 메뉴와 F2·Delete 명령은 T2 범위로 판단했다.

## 높음

1. **양방향 선택이 엔터티 ID 하나로 축소된다** (§4.2, §7.2). `model.html:513`, `model.html:976`, `model.html:1289`, `assets/app.js:825`, `assets/app.js:865`. 다른 엔터티의 속성을 트리에서 고르면 우측 행은 강조되지만, 캔버스에서 돌아온 이벤트가 트리 선택을 부모 엔터티로 덮는다. 이미 같은 엔터티가 선택된 경우에는 그 이벤트가 생략되어 화면 결과가 달라진다. 캔버스에서 속성을 대상으로 한 조작도 트리에 속성 경로를 전달할 수 없다. 관계 줄을 골라도 `d.rel`을 무시하고 자식 엔터티와 관계 탭만 연다. **수정** — 객체 종류·ID·속성 또는 관계 식별자를 담은 선택 상태를 두 화면이 공유하고, 트리에서 시작한 선택을 되돌려 보낼 때 세부 선택을 유지한다. 캔버스에서 선택한 속성의 조상만 펼치고, 필터에 가려진 선택은 상태를 유지하며 숨겨진 이유를 표시한다. 우측 행 강조도 선택 상태에서 그려 후속 렌더에서 유지한다.

2. **스냅숏·산출물 기준 버전과 트리가 다른 객체를 보여 준다** (§4, §5, §7.2). `assets/app.js:661`, `assets/app.js:708`, `model.html:1312`, `ddl.html:77`, `outputs.html:95`, `outputs.html:100`, `outputs.html:123`. 모델 화면만 트리에 실제 데이터 원본을 제공한다. DDL은 `snap`을 읽고 산출물은 버전 선택기를 따라가지만 트리는 현재 영역의 작업본 또는 잠금 문서를 읽는다. 산출물은 선택 ID가 해당 버전에 없으면 첫 테이블을 보여 준다. 바로가기 재렌더도 `snap` 없는 주소를 다시 쓰므로 모델 초기화 시 한 번 수행하는 링크 보정이 유지되지 않는다. **수정** — 각 화면이 현재 기준 데이터와 버전 ID를 트리에 제공하고 기준 변경 시 갱신한다. 스냅숏을 지원하는 바로가기는 그 ID로 생성하고, 표준 맞추기처럼 현재본을 쓰는 화면은 목적지를 명시한다. 산출물에서 대상 객체가 없으면 해당 버전에 없다고 안내한다.

3. **복합 FK 일부만 일치해도 반영 처리되어 잘못된 DDL을 만든다** (§4.1, §8.1). `assets/app.js:154`, `ddl.html:112`, `model.html:961`, `model.html:1069`. 부모 PK가 두 컬럼인데 자식 FK 이름이 하나만 일치하면 `cols.length`가 양수라 반영된다. DDL은 그 일부를 자식과 부모 양쪽 컬럼 목록에 사용한다. 기존 관계 그룹 `r.g/a.fkg`를 무시하므로 역할명 컬럼이나 동일 부모를 향하는 복수 관계도 잘못 매칭할 수 있다. **수정** — 관계별로 부모 PK 전체에 대한 자식 컬럼 대응을 검증한다. 그룹 정보가 있는 데이터는 그 정보를 우선하고, 기존 데이터는 대응이 유일한 경우에만 반영한다. 부모·자식 컬럼을 별도로 반환해 각 절에 사용하고, 같은 테이블 쌍의 제약 이름도 구분한다.

## 중간

4. **FK 상태와 실제 출력 대상이 화면마다 다르다** (§4.1, §8.1). `assets/app.js:158`, `assets/app.js:168`, `assets/app.js:720`, `ddl.html:81`, `ddl.html:112`, `model.html:599`, `model.html:1114`. 재귀 관계는 트리에서 빈 컬럼 목록과 함께 반영으로 표시되지만 DDL·우측 제약 패널·제약 목록은 건너뛴다. 참조가 연결된 관계도 트리에서 반영될 수 있지만 DDL은 참조 테이블을 후보에서 제외한다. 게이트 A는 FK 공통 판정을 호출하지 않는다. **수정** — 재귀·참조 관계의 출력 가능 여부와 사유까지 공통 판정에서 결정하고 트리·DDL·우측 패널·게이트 A에 적용한다. DDL 옵션과 출력 범위로 생긴 생략은 모델의 FK 상태와 구분한다. 참조 연결 관계의 영역 소유권은 유지한다.

5. **펼침·선택·스크롤을 버전별로 복원하지 못한다** (§4.5). `assets/app.js:643`, `assets/app.js:655`, `assets/app.js:682`, `assets/app.js:822`, `assets/app.js:868`, `model.html:1289`. 펼침만 사용자 키 아래 영역·버전별로 저장한다. 시스템 식별자가 빠져 있고, 같은 확정본을 일반 경로와 `snap` 경로로 열면 키가 달라질 수 있다. 선택과 스크롤은 메모리 또는 DOM에만 남고, 역방향 따라가기의 자동 펼침은 즉시 저장하지 않는다. **수정** — 사용자·시스템·영역·실제 버전으로 상태 키를 통일하고 펼침·선택·스크롤을 함께 복원한다. 작업본과 제출 사본의 데이터 원본이 다르면 각각의 식별자를 사용한다.

6. **바로가기 줄이 트리의 형제 위치와 계층을 깨뜨린다** (§4.5). `assets/app.js:749`, `assets/app.js:805`, `assets/app.js:853`. 내부 노드 하나를 DOM의 링크 treeitem 네 개로 그리면서 링크끼리 별도 `posinset/setsize`를 매긴다. 같은 레벨의 폴더와 위치가 겹치고 네 링크가 같은 `data-id`를 공유해 재렌더하면 첫 링크로 돌아간다. 평탄 DOM에 부모 treeitem의 자식 `group` 소유 관계도 없다. **수정** — 바로가기는 독립 내비게이션으로 제공하거나, 각 링크를 고유한 노드로 모델링해 같은 부모의 형제 수·순서와 roving tabindex에 포함한다. 실제 자식 그룹의 소유 관계를 노출하고 `aria-expanded`는 자식이 있는 노드에만 설정한다.

7. **포커스 복구가 사라진 줄의 위치를 따라가지 않는다** (§4.2, §4.5). `assets/app.js:797`, `assets/app.js:818`, `assets/app.js:895`, `assets/app.js:906`. 포커스 대상이 사라지면 기존 위치와 무관하게 선택 줄이나 첫 업무 영역으로 돌아간다. 검색 결과가 비면 트리 밖 대체 초점이 없고, 트리에서 용어를 Enter로 열면 모델 탭을 숨기면서 사전으로 포커스를 넘기지 않는다. 재렌더가 같은 줄을 복구할 때도 스크롤을 허용한다. **수정** — 이전 행의 조상이나 인접 행을 찾고 빈 결과는 검색 입력으로 복구한다. 탭 전환으로 현재 줄을 숨길 때 활성 탭 또는 사전 검색으로 초점을 옮긴다. 일반 재렌더는 스크롤을 유지하고 키 탐색과 화면 밖 선택에만 필요한 범위로 스크롤한다.

8. **찾기 결과 수와 필터 결과가 실제 표시 대상과 맞지 않는다** (§4.4). `assets/app.js:671`, `assets/app.js:689`, `assets/app.js:734`, `assets/app.js:815`. 용어만 일치하면 용어 줄이 표시되어도 `found`가 증가하지 않아 낭독기에 결과 없음이 전달될 수 있다. 물리명으로 찾은 논리 속성은 표시 이름에 검색어가 없으면 강조되지 않고, 부모 줄에 속성 일치 요약도 없다. 거르기에 ‘지금 보기에 있는 것만’과 결과 수가 없고, 사용 표준은 거르기를 통과한 엔터티 집합 대신 `s.E` 전체에서 집계된다. 검색으로 자동 펼친 분기는 접기를 눌러도 열린다. **수정** — 표시할 일치 결과에서 결과 수·강조·부모 요약을 계산한다. 보기 필터는 T1의 전체 보기 기준으로 동작시키고 적용 조건과 개수를 표시한다. 검색 중 사용자가 접은 분기도 반영한다.

9. **두 번 누르기와 위치 맞춤이 불안정하다** (§4.2). `assets/app.js:827`, `assets/app.js:835`, `model.html:805`. 첫 클릭에서 트리 DOM을 교체하므로 두 번째 클릭과 `dblclick`이 원래 객체에 도달하지 않을 수 있다. 도달하더라도 `focusEnt`는 현재 확대율에서 중앙으로 이동만 한다. 펼침 표시를 두 번 누르면 두 번째 클릭을 거르기 전에 접기를 처리한다. **수정** — 선택 표시를 기존 행에 갱신해 포인터 대상을 유지하고 펼침 표시와 객체 더블클릭을 분리한다. 객체 위치 맞춤은 캔버스의 확대·이동 처리를 재사용한다.

10. **전역 단축키가 트리와 사전 입력에 개입한다** (§4.2, §7.2). `model.html:744`, `model.html:749`, `model.html:1002`, `model.html:1297`. Ctrl+F가 포커스 검사보다 먼저 실행되어 트리·사전 검색 중에도 그리드를 열고, 트리 행에서 Ctrl+Z/Y는 캔버스 편집 기록을 실행한다. 그리드가 열린 상태에서 트리 객체를 선택하면 `closeGrid()`가 포커스를 ERD 버튼으로 가져간다. 일반 Enter/Delete와 V/E/R/M은 기존 가드로 차단된다. **수정** — 왼쪽 칸의 포커스를 전역 단축키보다 먼저 검사하고, 트리 선택으로 그리드를 닫을 때 트리 포커스를 유지한다. 조회 전용 상태에서도 읽기 선택을 허용하고 기존 편집 가드는 유지한다.

11. **사전 탭 통합이 표준 맞추기와 캔버스 속성 편집에 연결되지 않는다** (§4.6, §5). `assets/app.js:754`, `assets/app.js:898`, `model.html:975`, `model.html:1279`. 탭은 `#side`가 있는 화면에서만 생겨 표준 맞추기에 사전 탭이 없다. 캔버스에서 기존 속성을 편집할 때는 사전 탭을 열지 않는다. 기존 `side.closed` 초기화와 그리드의 닫기 로직도 남아 있지만 새 CSS는 이동한 패널에서 이 상태를 무시한다. **수정** — 두 화면의 한 칸 탭을 지원하고 기존 사전 검색·끌어 놓기와 속성 편집 시작을 탭 동작에 연결한다. 왼쪽 칸 접기와 탭 표시를 같은 상태에서 처리한다.

12. **폭 상한과 접기 기준이 화면 크기 변경을 따라가지 않는다** (§4.6, §8 #4). `assets/app.js:884`, `assets/app.js:888`, `assets/app.js:895`, `assets/app.js:971`, `assets/app.css:49`, `assets/app.css:866`. 수동 폭은 `curW`가 있으면 재검사하지 않아 우측 패널을 열거나 창을 줄이면 760px를 침범할 수 있다. 상한 계산이 240px 미만이어도 240px를 강제해 우선 접기가 없다. 1920px 창에서 1600 프레임을 선택하면 초기 접기 판정이 창 크기만 보며, 홈·시스템 홈에도 내용 맞춤과 손잡이가 적용된다. **수정** — 실제 콘텐츠 폭과 우측 패널 점유 폭이 바뀔 때 저장한 선호 폭을 현재 상한으로 제한하고, 240px가 들어가지 않으면 접는다. 초기 접기는 실제 목업 프레임으로 판단하고 홈·시스템 홈은 240px로 고정한다.

13. **닫힌 가지까지 재구성해 규모가 커지면 입력 지연 위험이 있다** (§4.6). `model.html:513`, `assets/app.js:688`, `assets/app.js:720`, `assets/app.js:726`, `assets/app.js:797`, `assets/app.js:887`. 캔버스 렌더마다 트리 갱신을 예약하고, 트리는 닫힌 영역과 엔터티의 속성까지 계산한다. 물리 모드에서 테이블별 관계 순회와 반복 엔터티 조회를 하고, 전체 트리 DOM을 교체한 후 행 폭을 다시 잰다. 프레임 단위 병합은 있지만 표시 데이터가 같은 경우도 다시 작업한다. **수정** — 데이터 변경·선택 변경을 구분해 필요한 행만 갱신하고, 검색을 제외하면 열린 가지의 자식만 만든다. 엔터티 ID와 관계를 한 번 인덱싱하고 폭은 보이는 행이 달라질 때 측정한다. 300개 엔터티·500개 관계에서 펼치기·키 이동·검색·캔버스 드래그를 측정한다.

## 낮음

14. **참조 노드가 원본 정보 없이 일반 엔터티처럼 펼쳐진다** (§3.2, §4.1, §7.1). `assets/app.js:688`, `assets/app.js:699`, `model.html:871`. 기존 참조 데이터가 있어도 일반 엔터티처럼 속성 자식을 만들고 원본 영역을 ‘공통’으로 고정한다. 기본 모델 트리에서 확인할 수 있는 원본 영역·확정 버전이 붙은 참조 시드도 보이지 않는다. **수정** — T1에는 읽기 전용 참조 시드를 마련해 실제 원본 영역·확정 버전을 표시하고 참조 줄은 말단으로 둔다. 참조를 준수율 집계에서 제외하는 기존 처리는 유지한다.

15. **DDL·표준 맞추기에서 이동 대상이 화면에 드러나지 않는 경우가 있다** (§5). `ddl.html:105`, `ddl.html:130`, `standardize.html:140`, `standardize.html:157`. DDL은 CREATE TABLE 텍스트로 줄을 찾아 ALTER 출력에서는 해당 테이블의 SQL이 있어도 없다고 안내한다. 표준 맞추기는 필터로 숨겨진 DOM 행도 이동 후보에 넣어 첫 일치 행이 숨겨져 있으면 스크롤이 동작하지 않는다. **수정** — DDL 생성 시 객체 ID를 블록에 붙여 CREATE·ALTER 모두 같은 ID로 이동한다. 표준 맞추기는 보이는 일치 행으로 이동하고, 모든 일치 행이 가려졌다면 필터를 해제할 수 있게 안내한다.
