# 정리 — ERD(모델) 화면 전체 리뷰 · 편의성 검토 (2026-11-23)

- 방법: ① 직접 브라우징(1600×900 · 1920, 상태 5종) 관찰 O1~O8(`brief-erd-review.md`) → ② Codex 코드 리뷰 `codex-erd-review.md`(ERD-01~11) → ③ Claude UX 편의성 검토 `claude-erd-review.md`(UX-01~11, 1600에서 실측 · 핵심 작업 따라 하기).
- 총평: **캔버스 안 편집 흐름은 빠르고 키보드로도 된다**(E → 이름 → Enter → 속성 → R → 자식). 문제는 **캔버스 바깥**과 **신뢰성**이다 — 머리가 한 줄에 8덩어리를 넣다 영역 이름이 깨지고, 표준 맞추기로 가는 길이 5개, 맞춤이 노드를 조작부 밑에 숨기며, 저장 실패 · 일괄 편집 대상 · 한글 조합 Enter 같은 결함이 있다.
- 상태: **P1 적용 완료(2026-11-24)** · P2 · P3는 적용 전. 적용 기록은 맨 아래 「P1 적용 기록」.

## 엇갈린 의견과 판단
- **영역 화면 메뉴 자리:** Codex는 머리 아래 둘째 줄, UX는 머리 한 줄(h1 말줄임). → **한 줄 유지**(세로 공간 보존, 설계 9.5와 같음) + P1-1로 h1 깨짐 해결. 1600에서도 남는 폭은 P2-10 · 11로 머리에서 덜어 내 확보.
- **주 버튼:** Codex는 "미준수 n건 해결" 흐름 유지하되 숫자 중복만 피하자, UX는 늘 [확정 신청] + 점검 패널. → **UX 안**(목표 행동이 늘 같은 자리에 보이고 페이지 왕복이 없음). 점검 패널의 [고치기]는 표준 맞추기의 해당 행으로 가는 길도 함께 둔다.

## P1 적용 기록 (2026-11-24)
| # | 바뀐 것 | 위치 |
|---|---|---|
| 1 | 머리에서 **영역 이름만 줄어든다**: 한 줄 · 최소 72 ~ 최대 320px · 넘치면 … + 툴팁. 다음으로 버전 배지 · 저장 상태가 한 줄 말줄임으로 줄어든다(‘저장 안 됨 [다시 시도]’는 줄지 않음). 경로 · 영역 화면 메뉴 · 접속자 · 동작은 줄지 않는다. ‘3명 접속 · 2명 편집’ 글자는 아바타 툴팁 + 낭독 전용 | `app.css` `.page-header` · `model.css` `.avs .cap` |
| 2 | 맞춤 = 노드 **경계 상자(최소~최대)** 를 **가려지지 않는 사각형**(도구 막대 · 안내 띠 아래, 범례 · 줌 · 미니맵 위, 창 안)에 맞추고 가로 가운데 정렬. `viewRect()`를 키보드 배치도 함께 쓴다 | `model.html` `viewRect` · `fit` |
| 3 | 캔버스 위 조작 UI 전체(`CV_UI`: 도구 막대 · 띠 · 범례 · 줌 · 미니맵 · 펼침 버튼 · 옆 탭 · 팝오버 · 모든 버튼 · 링크 · 선택 상자)에서는 클릭 · 두 번 누르기가 아무것도 놓지 않는다 | `CV_UI` |
| 4 | 띠는 **‘단어 승인 대기 n’** — 후보 단어가 있는 속성(`a.cand`)만, **단어별로** 묶어 보여 주고 속성 이름을 누르면 **건별 예외 사유** 창. 일괄 예외 창(`mo-ex2`)은 없앴다. 나머지 미등록은 주 버튼 수에 들어가고 표준 맞추기에서 처리. 영역 화면 메뉴 배지는 캔버스가 다시 셀 때마다 **주 버튼과 같은 수**로 갱신(`areaNavBad`) | `candAttrs` · `app.js` `areaNavBad` |
| 5 | 한글 조합 중 Enter · Esc는 입력기 몫(`isComposing`/229): 엔터티 · 속성 이름, 역할명 · 자식 고르기 · 보기 이름 팝오버, 오른쪽 패널. 표 보기 찾기 · 바꾸기는 조합 중에는 다시 그리지 않고 `compositionend`에 갱신 | 캔버스 · 팝오버 · 표 |
| 6 | 표 보기 선택은 **속성 객체 키**(메모리 전용)로 추적 — 순서 이동 · 삭제 뒤에도 같은 속성. 지워졌거나 되돌리기로 새로 만들어진 속성은 선택에서 빠진다. 선택 범위에 대상 이름 툴팁, 적용 알림에 대상 이름 · 제외 수 | `gKey` · `gFind` |
| 7 | 저장은 **쓰기가 성공한 뒤에만** 리비전 증가 · ‘저장됨’. 실패하면 ‘저장 안 됨 [다시 시도]’ + 알림(편집은 화면에 유지). 목업 확인용 `?failsave=1`. 메모는 첫 실제 입력에 되돌리기 기록, 메모를 벗어날 때 저장 | `saveData` · `retrySave` · 메모 focusout |
| 8 | 엔터티 이름 확정 직전 권한 · 버전 재검사(실패하면 저장된 이름으로 돌아가고, 새 엔터티는 취소). 역할명을 묻는 관계는 창이 닫힐 때까지 **저장 보류**(‘저장 대기 · 역할명 확정 전’) — 새로고침해도 임시 관계가 남지 않는다. 그 사이 다른 편집이 있었으면 [연결 취소]는 이 관계와 FK 컬럼만 뺀다(식별 관계는 Ctrl+Z 안내) | `commitRename` · `holdSave` · `rolePop` |
| 9 | 엔터티 도구(E · 도구 막대 · 트리 ‘새 엔터티’) 뒤 **Enter = 보이는 곳 가운데 빈 자리에 배치**. 버튼 · 링크 · 메뉴 항목 위의 Enter · Space는 그 버튼 몫(전역 ‘속성 추가’로 새지 않음), 속성 추가 Enter는 캔버스에 포커스가 있을 때만. 도구 버튼 `aria-pressed`, 안내 문구 `role=status` | `placeEntityKeyboard` · 전역 keydown |

확인: 1600 · 1920에서 26개 화면 × 2역할 머리 줄바꿈 · 넘침 없음, 맞춤 뒤 조작부와 겹치는 노드 0, 범례 · 미니맵 두 번 누르기 엔터티 0, E → Enter 배치(겹침 없음), 조합 중 Enter 무시, 저장 실패 → 다시 시도 → 저장, 속성 이동 뒤 표 선택 유지. 띠의 ‘단어 승인 대기’는 이 브라우저 데이터에서 ‘수령자’가 이미 승인돼 화면으로 재현하지 못했다(코드 경로만 확인).

## 참고 — 리뷰 중 부작용
UX 검토가 실측하면서 시험 엔터티 '교육과정'을 브라우저 저장소에 만들었다가 지웠다. 정리 후 확인: 요구사항 · 프로젝트 엔터티 7개 · 검토 4 · 저장된 모델 데이터 없음(원래 상태).
