# 클릭 목업 v3 UX 교차 검토 — Claude (2차, codex-r1 검토)

> 대상: `docs/ux/review/codex-r1.md`(CX-01~CX-50). CX 항목마다 근거로 든 목업 코드를 직접 열어 확인했습니다. 줄 번호는 따로 적지 않으면 `docs/ux/mockups/` 기준입니다.

## 1. 총평

- CX 결과는 근거가 정확하고, 제가 놓친 **실제 데이터 손실 경로**를 찾았습니다. 기존 속성 편집 중 Esc를 누르면 속성이 삭제되고(CX-20), 표 보기 '모두 바꾸기'는 필터 밖까지 바꾸며(CX-23), 엔터티를 삭제해도 자식 FK가 남습니다(CX-25). 셋 다 코드에서 확인했습니다.
- 반대할 항목은 없습니다. 다만 목업 특성상 하드코딩·토스트만 있는 동작까지 '상'으로 매긴 경우가 있어 14건은 심각도를 낮추거나 범위를 좁힐 것을 제안합니다. 저장 실체, 다운로드 실체, 고정 교차 엔터티 등이 그렇습니다.
- 두 결과의 겹침은 크고(31쌍), 보완 관계도 분명합니다. 권한 상승(CL-38)과 결재함의 '지금 내 차례' 판정(CL-05)은 제 쪽이, 논리/물리 경계(CX-22)와 준수율 재계산(CX-21)은 CX 쪽이 더 구체적입니다.

## 5. 합의 우선순위 제안 Top 10

1. **CL-38/CX-47 권한 경계** — 비Admin이 설정에 들어가 자기에게 Admin을 줄 수 있습니다. 보안 감사에서 바로 걸립니다.
2. **CX-20 Esc가 기존 속성을 삭제하고 되돌리기 기록까지 버림** — 되돌릴 수 없는 데이터 손실입니다. 고치기도 쉽습니다.
3. **CL-04·CL-05/CX-10·CX-11 결재 대상·자기 승인 판정과 필수 사유** — 겸임이 흔한 조직에서 잘못된 승인과 사유 없는 처리가 감사 기록에 남습니다.
4. **CX-18·CX-21/CL-31 준수율·표준 적용 정합성** — 사유 없는 예외로 만든 100%와 재계산되지 않는 준수율이 확정·DDL 판단을 무효로 만듭니다. 일괄 적용에 확인과 되돌리기가 필요합니다.
5. **CL2-02 + CX-12/CL-03 모델 확정 결재의 검토 수단과 완료 흐름** — DA가 내용을 못 보고 승인하며, 최종 승인 → 확정본 → 다음 작업본까지 이어지지 않습니다.
6. **CL-21·CL-22/CX-26·CX-25 ERD 구조 편집 완결성** — 속성 상세·관계 편집/삭제가 없고, 엔터티를 지우면 고아 FK가 남습니다.
7. **CL-01·CL-02·CL-33/CX-19·CX-24 사유 필수 규칙의 일관 적용** — 반려·후보 반려·예외·비대상(일괄 포함)이 모두 같은 규칙으로 사유를 요구해야 합니다.
8. **CL-43·CL-44/CX-43·CX-44 사용자 메뉴·알림 센터** — 모든 사용자의 기본 동선이고, "알림으로 알려 준다"는 흐름의 도착점입니다.
9. **CX-22·CX-23 논리/물리 경계와 일괄 변경 범위** — 반영 전이라고 믿은 구조가 바뀌거나, 보지 않은 행까지 바뀌는 사고를 막아야 합니다.
10. **CL-45~47/CX-39~42 접근성 기반(라이브 영역·키보드·라벨·대화상자·대비)** — 공공기관 웹 접근성 인증 대상일 가능성이 높아 공통 컴포넌트 단계에서 잡아야 합니다.
