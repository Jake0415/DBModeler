# 결재함 결재선 가로 스테퍼 — UX 리뷰 (Claude)

- 대상: `approvals.html` `line(d)` → `<ol class="approval-line h">`, `assets/app.css` 705–724
- 확인 환경: http://localhost:5178, 1600×900 · 1920×1000, 역할 kim · hyun, 문서 REQ-2026-0016(DA 차례) · 0011(모델, DA 차례) · 0010(최종 승인 차례) · 0001(자기 승인 + 최종 승인 완료) · 0007(최종 승인 생략)
- 측정: 높이 58px(세로형 약 150px), 너비 642px(1600) / 727px(1920), 단계당 214px / 242px. 지금 시드 데이터로는 글자가 잘리는 곳이 없음
- 시드에 반려 · 회수 · `line:['da']` 문서가 없어서, 이 상태들은 코드를 읽고 판단함
- 결재함에서 승인 · 반려를 누르지 않음. localStorage도 바꾸지 않음

## 한 줄 총평

가로로 바꾼 것은 맞는 결정입니다. 상세 내용이 약 90px 위로 올라왔고, 3단계가 패널 너비에 고르게 나뉘어 한눈에 읽힙니다. 다만 세 가지가 남았습니다.
- 반려 · 회수 · 생략 상태를 **글자로 알려 주지 않습니다.**
- **모양만으로는 상태를 잘못 보여 주는 경우**가 있습니다(0007 생략이 '완료'로 보임).
- 툴팁에만 있는 정보는 키보드 · 터치 사용자가 볼 수 없습니다.

## 지적

### AL-01 · P1 · '최종 승인 생략' 문서가 '완료 ✓ 시스템'으로 보이고, 툴팁은 정반대를 말함
- **근거:** REQ-2026-0007의 이력은 `final:최종 승인 생략(기관 설정: 사전 최종 승인 끔 당시)`입니다. 그런데 스테퍼에는 `최종 승인 ✓ / 시스템 · 11/17 11:58`이 보이고, 툴팁에는 "기관 설정: 사전 신청 최종 승인 **사용**(신청 당시)"가 나옵니다. 원인은 두 가지입니다.
  - `ok()`의 정규식이 `/승인/`이고 `실패|취소`만 걸러서, '승인 생략'을 승인으로 셉니다.
  - 이 문서에는 `d.line`이 없어서 `hasFinal()`이 기본값(`['da','final']`)을 씁니다.
- **권고:**
  - `ok`에서 생략도 거릅니다: `!/실패|취소|생략/.test(x.act||'')`
  - 이력에 `final:…생략`이 있으면 `skip`으로 그립니다: `stepOf('skip','최종 승인 생략','신청 당시 설정: 최종 승인 끔', …)`
  - 시드 0007에 `line:['da']`를 넣습니다.
  - `note`는 `hasFinal(d)`가 참일 때만 붙입니다(지금도 그렇지만, 데이터가 맞아야 의미가 있음).

### AL-02 · P1 · 반려를 글자로 알리지 않음(✕ 모양과 빨강만)
- **근거:** 반려 단계 캡션은 `who(rj)` = `김모델 · 11/16 17:40`뿐입니다. '반려'라는 글자는 화면에도 스크린리더에도 없습니다. 지금은 ✕ 아이콘(aria-hidden)과 빨간 테두리만 상태를 알려 줍니다. WCAG 1.4.1(색만으로 정보 전달 금지)과 1.3.1에 걸립니다.
- **권고:** 캡션 앞에 상태 글자를 붙입니다.
  ```js
  const who = (x, s) => x ? `${x === rj ? '<b class="u-danger">반려</b> · ' : ''}${x.who} · ${x.at}…` : …
  ```

### AL-03 · P1 · 반려 · 회수 뒤의 단계가 '대기 ○'처럼 보임
- **근거:**
  - 반려 문서: `cls('final')`이 `''`가 되어 빈 원 + `기관 담당자`로 그려집니다. 앞으로 처리될 단계처럼 보입니다.
  - 회수 문서(`step:'withdrawn'`): DA 단계도 빈 원 + `DA`로 그려집니다. 회수되었다는 표시가 스테퍼 어디에도 없습니다.
- **권고:** 끝난 문서에서 처리되지 않은 단계는 `skip`(점선)으로 그리고, 캡션에 이유를 씁니다.
  - 반려 뒤 단계: `진행 안 함 · 반려로 종료`
  - 회수: 신청 단계 캡션을 `김모델 · 11/16 09:20 · 회수 11/16 10:02`로 하고, 나머지 단계는 `진행 안 함 · 회수`

### AL-04 · P2 · 단계 상태를 스크린리더가 읽지 못함
- **근거:** `aria-current="step"`이 있어 '지금' 단계만 알 수 있습니다. 완료 · 대기 · 반려 · 사용 안 함은 읽히지 않습니다. 실제로는 "DA 승인, 김모델 · 11/16 17:40"처럼 읽혀서, 완료인지 반려인지 구분되지 않습니다.
- **권고:** 각 `li` 맨 앞에 sr-only 상태 글자를 넣습니다.
  ```js
  const ST = { done:'완료', cur:'진행 중', rej:'반려', skip:'사용 안 함', '':'대기' };
  … `<li …>${pt(c)}<span class="sr-only">${ST[c]}: </span><div class="al-t">…`
  ```
  `ol`에 단계 수도 알려 줍니다: `aria-label="결재선 3단계"`

### AL-05 · P2 · 툴팁에만 있는 정보는 키보드 · 터치로 볼 수 없음
- **근거:** `title`이 포커스를 받지 못하는 `li`에 붙어 있습니다. 마우스를 올려야만 보이므로, 눈으로 보는 키보드 사용자나 태블릿 사용자는 "신청 당시 설정 기준" 문구를 볼 방법이 없습니다. 스크린리더에는 sr-only와 `title`이 둘 다 있어서 같은 문장을 두 번 읽을 수 있습니다.
- **권고:** `title`을 빼고, 스테퍼 아래에 **한 줄 각주**를 둡니다. 화면 높이는 18px만 늘어납니다.
  ```html
  <div class="caption faint al-note">ⓘ 결재선은 신청 당시 설정 기준 — 기관 설정: 사전 신청 최종 승인 사용</div>
  ```
  - 문서마다 다른 내용(생략 · 없음 사유)은 해당 단계 캡션에 직접 씁니다(AL-01 · AL-03).
  - 꼭 툴팁으로 남기려면, 단계 라벨 옆에 `<button class="btn ghost xs" aria-describedby=…>ⓘ</button>` 토글팁을 둡니다(클릭 · Enter · Esc로 열고 닫음).

### AL-06 · P2 · '(자기 승인)'이 캡션 끝에 있어서 말줄임에 먼저 잘림
- **근거:** `이데이터 · 10/02 14:00 (자기 승인)`은 지금 약 190px로 214px 안에 들어갑니다. 하지만 이름이 4자 이상이거나 패널이 좁아지면(1280 해상도, 패널을 줄였을 때) 가장 중요한 표시인 '자기 승인'이 맨 먼저 `…`로 사라집니다. 다른 화면에서는 자기 승인을 보라 플래그 배지로 보여 주는데, 여기서는 회색 글자라 일관성도 깨집니다.
- **권고:** 라벨 줄로 올리고 배지로 바꿉니다. `<b>DA 승인 <span class="badge b-violet sm">자기 승인</span></b>`
  - 그러면 캡션은 `이름 · 일시`만 남아 짧아집니다.
  - 잘린 캡션은 sr-only 전체 문장으로 보완합니다. 마우스 사용자용 보조로는 `al-t`에 `title`을 두는 대신, 잘렸을 때만 펼쳐지는 `:focus-within`/hover 처리를 쓸 수 있습니다.

### AL-07 · P2 · 대기 원 · 점선(사용 안 함)의 대비가 낮음
- **근거:** 대기 점 테두리 `--border-strong` #c9c9c9는 흰 바탕에서 약 1.6:1로, 비텍스트 대비 기준 3:1에 못 미칩니다. 점선 1.5px은 거의 실선처럼 보여서 '대기'와 '사용 안 함'이 구별되지 않습니다. 이 상태들을 알려 주는 글자도 없어서(AL-04) 모양에 기대는 비중이 큽니다.
- **권고:**
  ```css
  .approval-line.h .al-step:not(.done):not(.cur):not(.rej) .pt { border-color:var(--fg-3); }
  .approval-line.h .al-step.skip .pt { border:1.5px dashed var(--fg-3); background:transparent; }
  .approval-line.h .al-step.skip b { text-decoration:none; color:var(--fg-3); }
  ```

### AL-08 · P3 · 연결선이 뜻하는 바가 약함
- **근거:** 완료 뒤 연결선은 #666, 그 밖은 #ebebeb입니다. 완료 → 지금 구간과 완료 → 완료 구간이 같은 색이라 진행 위치는 점으로만 보입니다. 나쁘지는 않지만, 반려 다음 구간도 연한 회색이라 '여기서 멈춤'이 드러나지 않습니다.
- **권고:** 반려 뒤 구간은 점선으로 그립니다.
  ```css
  .approval-line.h .al-step.rej:not(:last-child)::before { background:none; border-top:1px dashed var(--border-strong); height:0; }
  ```

### AL-09 · P3 · 2단계와 3단계의 정렬
- **근거:** `flex:1 1 0`이라 2단계 문서는 단계 하나가 패널의 절반(약 320px)을 차지합니다. 연결선이 길어지고 오른쪽이 비어 보입니다.
- **권고:** `.approval-line.h .al-step { flex:0 1 240px; }`처럼 최대 폭을 두고 왼쪽에 붙입니다. 마지막 단계에는 `flex-grow:0`.
  - 지금 구조처럼 '최종 승인 없음'을 점선 단계로 늘 3칸으로 두는 방식도 좋습니다. 결재함에서는 이 방식을 유지하길 권합니다(문서끼리 비교하기 쉬움).

### AL-10 · P3 · 일시에 연도가 없음
- **근거:** `11/16 09:20` 형식입니다. 참조함이나 감사 화면에서 작년 문서를 열면 언제인지 헷갈립니다.
- **권고:** 올해가 아니면 `2025-11-16 09:20`으로 씁니다. 화면 전체의 일시 규칙과 맞춥니다.

## 다른 화면 적용 권고

| 화면 | 지금 | 권고 | 이유 |
|---|---|---|---|
| 결재함 상세 | 가로 | **가로 유지** | 진행 상태를 추적하는 곳. 위 지적만 고치면 됨 |
| 사전 › 바구니 · 품의 패널 (dictionary.html) | 세로 2단계 | **세로 유지**. 상태 토큰과 '신청 당시 설정' 문구는 맞춤 | 좁은 오른쪽 패널(약 400px)이고, 단계마다 `da-cnt` · `ow-cnt` 같은 건수 설명 줄이 붙어 가로로는 잘림. 결재선을 **미리 보여 주는** 곳이라 추적용과 모양이 달라도 됨 |
| 모델 › 확정 신청 패널 (model.html) | 세로 2단계 | **세로 유지** | 위와 같음(좁은 패널, 아래 참조자 줄과 함께 읽힘) |
| 엑셀 가져오기 6단계 신청 (excel-import.html) | 세로 2단계 | **가로로 바꿈**(결재함과 같은 `.h`, 첫 칸 `신청 · 나`) | 넓은 본문이고 단계마다 설명이 짧음. 위쪽 마법사 단계 표시와 결재선이 둘 다 세로로 쌓여 사유 칸이 아래로 밀림. 가로로 바꾸면 결재함에서 볼 모양을 미리 보게 되어 일관됨 |
| styleguide.html | 세로 | **두 모양을 모두** 싣고, 쓰는 곳을 정함 | "추적 = 가로(결재함), 신청 미리보기 · 좁은 패널 = 세로" |

공통 규칙(01-design-guide 6.8에 추가 제안):
- 상태는 모양과 **글자** 두 가지로 알린다(반려 · 생략 · 회수는 캡션에 글자로).
- 설정에 따른 설명은 툴팁이 아니라 보이는 각주로 둔다.
- 신청 화면의 미리보기에도 첫 칸으로 `신청(나)`를 둘지 정해서, 결재함과 단계 수를 맞춘다.

## 우선순위

1. **AL-01** 생략 문서가 완료로 보이는 문제(데이터와 정규식)
2. **AL-02 · AL-03** 반려 · 회수를 글자로 알리고, 그 뒤 단계를 점선으로
3. **AL-04 · AL-05** sr-only 상태 글자, `title` 대신 보이는 각주
4. **AL-06 · AL-07** 자기 승인을 배지로, 대기 · 점선 대비 높이기
5. 엑셀 6단계를 가로로, 스타일가이드에 두 모양을 정리
6. **AL-08 ~ AL-10** 다듬기
