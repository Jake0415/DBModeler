# ERD 관계 연결 · 설정 · 삭제 사후 검토

## ① 요약

커밋 `e034427`을 [확정 설계 §1~4](../18-relation-scenario.md#1-연결) 및 [R1~R6 결정](resolution-relation.md#엇갈린-것과-결정)과 대조했다. 일반 연결의 기본값, 식별 키 전파, 삭제 선택지와 일괄 복원, 기본 CREATE DDL 및 결재 화면의 물리 변경 분리는 확인했다. 우선 수정할 사항은 결재 비교의 관계 오인, 식별 전환 후 유효하지 않은 SET NULL, 복합 PK에서 1:1 유일성 손실, FK 재매핑의 다른 관계·하위 키 훼손이다. 미리보기는 HTTP 200이었으나 헤드리스 Chrome 디버깅 포트에 연결할 수 없었다. Node 26에서 원본 함수와 최소 엔터티 픽스처로 데이터 동작을 실행하고 DOM 연결·DDL·결재 화면은 코드로 추적했다. 브라우저 포커스 실동작과 스크린리더 발화는 미검증이며 시험 중 localStorage를 쓰지 않았다. 검토 도중 작업 트리에 생긴 별도 `app.js` 변경은 결과의 기준에 포함하지 않았다. 아래 줄 번호는 `e034427` 기준이다.

## ③ R1~R6 평가

DA#의 세부 키 동작과 기본값은 공식 공개 제품 페이지에서 확인하지 못했다. 평가는 DA#·erwin에 익숙한 모델러의 키 전파와 업무 역할 편집 흐름을 기준으로 했다. erwin의 식별/비식별 키 이동과 비식별 기본 NULL 설정은 공식 안내에서 확인했다. [DA# 제품 소개](https://www.en-core.com/product/da) · [erwin 관계 유형](https://bookshelf.erwin.com/bookshelf/public_html/15.0/Content/PDFs/Navigator%20Edition%20User%20Guide.pdf) · [erwin 비식별 기본 NULL 설정](https://bookshelf.erwin.com/bookshelf/public_html/15.0/Content/User%20Guides/erwin%20Help/Set_the_Default_Null_Option_for_a_Non_Identifying_Relationship_1.html)

| 결정 | 평가 | 이유와 보완 |
|---|---|---|
| R1 컬럼 보존 우선·취소 포커스 | **동의** | 모델러가 자동 이관 컬럼 정리를 기대하더라도 역할명·설명·하위 키 복구 비용이 크다. 보존 기본과 취소 포커스를 유지하고 보존 후 남는 NOT NULL·PK를 선택지 근처에 보여 준다. |
| R2 Esc 취소·Enter 확정 | **동의** | 역할 입력을 한 번으로 끝내는 흐름에 맞는다. 제안 선택은 입력에서 Enter를 눌렀을 때 적용하고, 버튼·링크에서는 해당 요소의 동작을 유지한다. 확정 시점에만 모델·히스토리를 바꾸면 Esc가 실제 취소가 된다. |
| R3 즉시 반영과 식별 전환 미리보기 | **보완** | 이름 같은 단일 변경은 속성 패널과 일관된다. 식별 관계의 FK 짝 변경도 PK·하위 전파를 바꾸며 1:1 및 SET NULL 변경은 물리 제약을 바꾼다. 변경 항목 이름보다 실제 영향으로 미리보기 여부를 정하고, 작은 변경은 한 번에 Undo할 수 있게 한다. |
| R4 비식별 신규 기본 ‘반드시’ | **보완** | 초기 제품 기본값으로 사용할 수 있다. 업무 관계의 선택성을 모델러가 판단할 수 있도록 첫 연결에서 결과를 보여 주고, 패턴이 다른 프로젝트에는 모델 기본값을 검토한다. 재귀의 부모 0..1 기본 및 기존 관계의 유효 선택성은 유지한다. [erwin 모델 기본값](https://bookshelf.erwin.com/bookshelf/public_html/15.0/Content/User%20Guides/erwin%20Help/Set_the_Default_Null_Option_for_a_Non_Identifying_Relationship_1.html) |
| R5 식별 삭제 세 가지 | **보완** | 다른 PK가 있고 전파가 없을 때 일반 컬럼으로 남기는 선택은 기존 모델의 정리 흐름과 맞는다. 삭제 후 남을 PK 조합을 보여 주고, PK가 사라지는 선택은 그 영향을 버튼 앞에서 명시한다. |
| R6 CASCADE와 막기 분리 | **보완** | 식별은 키 구성, CASCADE는 DB 삭제 규칙이다. 실제 DDL이 생성되는 FK만 따라가고 ID로 분기·순환을 추적한다. 막기에는 ‘참조 행이 남아 있으면 실패할 수 있음’을 표시한다. |

## ④ 지적 목록

1. **높음 · 결재 비교가 같은 관계를 추가·삭제로 분류한다.** 옛 확정본은 방향+이름, 정규화한 작업본은 `g`로 비교한다. `g`는 FK 묶음이며 구버전에서 새로 부여된다. 이름·카디널리티·FK 짝의 변경도 별도로 읽지 않는다. 관계 자체의 영속 ID를 두고, 구버전은 양쪽에 같은 이행 규칙으로 유일하게 판별되는 경우에만 짝짓는다. 유효 설정과 매핑을 비교하고 추가·삭제 시 UK도 DB 묶음에 포함한다. [비교](../mockups/assets/app.js#L693) · [정규화](../mockups/model.html#L1667)
2. **높음 · FK 재매핑이 다른 관계와 하위 키를 변경한다.** 후보에 다른 FK와 이미 사용한 짝도 들어가며 `fkg/fkp`를 덮는다. 기존 식별 짝의 PK 해제와 신규 PK 승격은 `pkReach/pkSpread`를 호출하지 않는다. 관계별 점유·복합 키 1:1 대응을 먼저 검증하고, 식별 매핑은 영향 미리보기 후 하위 정리·전파를 원자적으로 적용한다. 타입·도메인 검사 자체는 설계 §5의 유예 항목이다. [후보](../mockups/model.html#L1740) · [실행](../mockups/model.html#L1818)
3. **높음 · 식별 FK에 SET NULL이 남는다.** 식별 적용이 `opt`와 PK를 바꾸지만 `del`은 유지한다. 재매핑으로 일반 관계의 FK에 기존 PK를 지정해도 옵션 판단은 `opt`만 본다. 실제 매핑 컬럼이 하나라도 PK/NOT NULL이면 차단하고, 식별 전환에서는 막기 복귀를 미리보기·적용·Undo에 함께 포함한다. [검사](../mockups/model.html#L1814) · [식별 적용](../mockups/model.html#L1798) · [DDL](../mockups/ddl.html#L130)
4. **높음 · 자식 복합 PK가 FK 조합의 유일성을 보장하지 않는다.** `syncUk`는 식별이면 UK를 무조건 없앤다. FK 조합이 자식 PK 전체를 포함하거나 별도의 유일 제약으로 보호되는 경우에만 중복 제약을 생략한다. `0..1`도 물리 최대 하나로 보장할지 명시하고, ‘정확히 1개’의 최소 하나는 FK+UK만으로 강제되지 않음을 패널에 표시한다. [UK](../mockups/model.html#L1673) · [도움말](../mockups/model.html#L1753)
5. **높음 · 역할 팝오버 확정 전 저장과 히스토리 노출.** 관계·FK 생성과 성공 토스트가 역할 확인보다 앞서고, 이름 수정은 스냅샷을 하나 더 쌓는다. 취소는 전역 Undo라 Redo에 가등록 관계를 남긴다. 팝오버에서 변경 초안을 유지하고 확정할 때 생성·역할명·전파·저장을 한 번에 커밋한다. [생성·팝오버](../mockups/model.html#L1686) · [저장](../mockups/model.html#L456) · [스택](../mockups/model.html#L550)
6. **높음 · 반복 역할에서 중복 물리 컬럼명이 생긴다.** 생성은 동일 논리명 충돌에 ORG_/UPR_ 고정 접두사를 쓰고 확정은 논리명만 바꾼다. 기존 컬럼과 제안 컬럼 전체의 물리명 유일성을 검증하고 고유 제안을 제시한다. 여러 기존 관계는 안정 ID로 선택한다. [생성](../mockups/model.html#L1692) · [확정](../mockups/model.html#L1712)
7. **높음 · 기존 FK 묶음 정규화가 모호한 후보를 소유할 수 있다.** `find`는 후보 하나를 먼저 집고 관계 순서대로 묶음을 확정한다. 매칭 후보가 여러 개여도 첫 후보를 붙이며 그룹 없는 경로는 다른 관계가 가져간 컬럼도 재사용할 수 있다. 기존 그룹 우선, 미소유 후보 다중성 검사, 애매한 경우 재매핑 전까지 파괴적 작업 보류가 필요하다. [정규화](../mockups/model.html#L1663) · [공통 판정](../mockups/assets/app.js#L239)
8. **높음 · M:N 해소가 현재 관계에 맞지 않는 테이블을 즉시 생성한다.** 범용 버튼의 동작이 고정 예제에 묶여 있어 현재 부모 PK와 다른 컬럼을 만들고 반복 시 `rr`가 겹친다. 두 부모 PK를 읽어 실제 교차 엔터티와 2개 식별 관계를 미리보기하고 적용한다. [버튼](../mockups/model.html#L1757) · [해소](../mockups/model.html#L1409)
9. **중간 · PK 대기 해소가 기존 관계 설정을 따르지 않는다.** `pkSpread`는 비식별 신규 컬럼에 `nn=0`을 쓰며 UK 재계산 및 재귀 대기 해소를 생략한다. 최초 생성과 같은 유효 선택성·그룹·UK 규칙으로 FK를 보충하고, 재귀에는 기존 역할 확인 흐름을 재사용한다. [대기](../mockups/model.html#L1690) · [전파](../mockups/model.html#L732)
10. **중간 · CASCADE 안내가 실제 제약보다 넓다.** `fkOf`가 누락/제외로 판정한 관계까지 탐색하고, 막기 부모를 표시명으로 찾으며 분기를 일렬 화살표로 잇는다. 유효 FK로 구성한 그래프에서 ID로 탐색하고 분기와 조건부 실패를 구분한다. [연쇄](../mockups/model.html#L1677) · [경고](../mockups/model.html#L1761)
11. **중간 · 삭제 영향 예측이 실제 결과와 다르다.** FK 제외·누락도 제약 1개 감소라 표시하고, 최종 PK 제거나 공유 UK 보존을 따로 계산하지 않는다. 실행과 동일한 영향 계산으로 FK/UK 실감소와 남을 PK 조합을 그린다. 기존 독립 UK와 관계 생성 UK의 소유권도 구분한다. [미리보기](../mockups/model.html#L1830) · [실행](../mockups/model.html#L1850) · [UK](../mockups/model.html#L1673)
12. **중간 · 키보드와 보조기기 경로의 초점이 끊긴다.** 자식 선택기의 닫기 동작은 요소만 제거하고 역할 취소의 복귀 대상은 재렌더 전 노드 참조다. Enter 가로채기는 입력으로 제한하고, 재렌더 후 안정적인 캔버스·패널 컨트롤로 포커스를 돌린다. 목록 입력과 활성 옵션을 ARIA로 연결하고 M:N·대기 생성도 알린다. 식별 전환 취소는 이전 활성 유형 대신 호출 버튼으로 돌린다. [노드 재생성](../mockups/model.html#L603) · [선택기](../mockups/model.html#L1712) · [전환 띠](../mockups/model.html#L1793)
13. **중간 · 결재 비교 기준본과 산출물 범위가 제한된다.** 결재 비교는 `ver-1` 저장본을 채택해 실제 직전 확정본이 더 이르거나 사본이 없는 경우 정확한 기준을 보장할 수 없다. 제출 시 기준 확정 문서 ID를 고정한다. 재귀를 엔터티 제약 목록에도 포함하고, ALTER 범위에서 FK/UK 변경을 다룰지 명확히 표시한다. [기준본](../mockups/approvals.html#L186) · [제약 목록](../mockups/model.html#L933) · [DDL](../mockups/ddl.html#L111)
14. **낮음 · 읽기 전용과 대기 상태의 안내가 겹친다.** 권한·확정·결재 중에 같은 설명을 내고, 조회 전용에서도 [식별자 지정]을 노출하며 ‘FK 대기’ 아래 ‘FK 누락’도 나온다. 현재 잠금 이유에 맞춘 한 줄을 보여 주고 공통 FK 상태에서 대기를 분리해 트리와 패널의 용어를 일치시킨다. [패널](../mockups/model.html#L1746) · [대기 안내](../mockups/model.html#L1754)
