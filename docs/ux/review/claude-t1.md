# T1 기획서 검토: Claude (12-model-tree-plan, DA#식 모델 트리)

> 대상: [12-model-tree-plan.md](../12-model-tree-plan.md)
> 대조한 자료
> - DA# 기능정의서: 00-index(M-C04~C08, M-B01), 01(DG-01·02, DG-R01), 03(F-38)
> - 03-erd-editor(§0·§2·§7·§8), 11(§2.2·결정 #2)
> - 목업: `model.html`(왼쪽 사전 패널 `.side`, 전역 키 처리), `app.js`(`drawTree`)
>
> 코드와 기획서는 고치지 않았다.

## 총평

방향은 맞다. 화면 이동 메뉴였던 트리를 객체 탐색기로 바꾸고, DA#에서 막혀 있던 것들을 개선 항목으로 잡았다.
- 용어 폴더·관계 노드에 메뉴가 없던 문제(M-C08, U-08)
- FK 제약조건이 없어도 알 수 없던 문제(F-38)
- 표준 상태가 트리에 없던 문제(F-14·15)

다만 다섯 가지가 기획 단계에서 정리되어야 한다.
1. DA#의 "주제영역 = 같은 모델의 여러 보기"를 NeoDB의 "업무 영역 = 버전·결재 단위"에 옮기면서, **참조와 보기의 경계, 버전과의 관계**가 정의되지 않았다.
2. 모델 화면 왼쪽에 이미 있는 **사전 패널(PN-32)과 트리가 두 칸으로 겹친다.**
3. 트리가 5단계로 깊어져 1600px에서 버틸 수 없다.
4. 트리 줄 안의 ⋯ 버튼과 가상화(보이는 줄만 그리기)가 ARIA tree 규칙과 충돌한다.
5. 목업 범위가 한 번에 너무 넓다.

## 결정 4가지에 대한 의견

| 결정 | 의견 |
|---|---|
| 1. 보기(여러 다이어그램) | **둔다에 동의(조건부).** 보기 = 배치 전용 표시 단위로 정의하고(#11), 배치/참조 용어를 고정한 뒤(#1) T3에서 넣는다. 그전까지 목업은 `전체` 하나로 둔다. |
| 2. 속성까지 트리에 | **엔터티까지만(권장안과 반대).** DA# 객체 목록에도 속성은 없다(DG-01). 속성은 오른쪽 패널·캔버스·찾기 결과로 충분하고, 깊이와 성능 부담이 크다(#4). |
| 3. 물리 객체 폴더 | **이번에 넣는 데 동의.** 단, 물리 모드일 때만 보이게 하고(#4), 제약조건은 "PK 6 · FK 0 ⚠ 관계 6" 같은 요약 줄과 [FK 만들기]로 시작한다(F-38). 회색 기준을 정의한다(#10). |
| 4. 트리 폭 | **280 기본 + 조절에는 조건이 있다.** 사전 패널과 한 칸으로 합치는 것이 먼저다(#3). 합치면 기본 264px, 240~360px 조절, 1600에서는 접힌 채 시작한다. 합치지 않으면 240 고정이 낫다. |
