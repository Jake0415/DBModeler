# DBModeler 클릭 목업 교차 검토 — Codex 2차

## 1. 총평

상대의 CL-01~CL-50을 HTML·이벤트 처리·공통 CSS와 직접 대조했으며, 핵심 업무 단절과 접근성 지적 대부분에 동의한다.
다만 실제 권한 상승·물리명 변경·선택 항목 처리로 단정한 표현, 패널 폭·체크 수, 후속 차수 기능의 우선순위는 수정해야 한다.
아래 판정은 코드 경로 검토 결과이며 브라우저 클릭·1600 렌더링·보조기기 실측이나 서버 검증은 하지 않았다. 새 문제 2건을 추가한다.

근거 경로는 별도 표시가 없으면 `docs/ux/mockups/` 기준이다. 심각도는 상=손실·잘못된 승인/판정·핵심 업무 차단, 중=업무 지연·운영/접근성 누락, 하=국소 일관성·후속 설계 보완이다. 가짜 데이터·비영속성 자체보다 입력 무시와 잘못된 완료 피드백을 판단했다. ‘수정 동의’의 심각도는 합의 제안값이다.

## 5. 합의 우선순위 제안 Top 10

1. **취소·일괄 수정·조회 전용 경계의 손실 방지 — CX-20·23, CX2-01·02.** 기존 속성 Esc 삭제, 필터 밖 바꾸기, 참조/전체 보기에서의 의도하지 않은 변경을 먼저 차단한다.
2. **표준 판정과 확정 조건의 정합성 — CX-18·19·21 / CL-31~33.** 모든 미등록을 예외로 바꾼 100%와 선택 무시를 없애야 승인·DDL 판단이 유효하다.
3. **결재 대상·역할·필수 사유 — CX-10·11·47 / CL-01·04·05·38.** 문서 ID·현재 단계·사용자 역할을 맞추고 자기 승인/반려 사유를 검사한다. 실제 서버 취약점으로 단정하지 않는다.
4. **승인·반려·회수의 업무 종료 — CX-12·13·31 / CL-03·06·08·09·29.** 신청 ID·버전·건수를 유지하고 최종 반영·잠금 해제·보완·다음 작업본까지 상태를 연결한다.
5. **ERD 구조 편집과 논리→물리 반영 — CX-22·25~28·30 / CL-21~24·27.** 속성/관계·정의 편집, FK 영향, M:N 미리보기와 물리 반영 경계를 완성한다.
6. **사전·엑셀·후보 신청 흐름 — CX-01~08·14~17 / CL-02·10~20.** 실제 입력·파일·후보 확인·검증 타이머·결과 집계가 신청 대상과 맞아야 표준 공급 흐름이 이어진다. 코드값 전용 관리 전체는 명시된 후속 범위를 따른다.
7. **가져오기 대상과 출력 결과물 — CX-32~34·36 / CL-34~37.** 선택한 영역·상태를 보존하고 SQL/파일을 옵션과 연결한다. 후속 DBMS 접속 관리(CL-41)는 현재 핵심 흐름을 막는 필수 작업으로 올리지 않는다.
8. **저장·인증·연결 장애와 결과 재진입 — CX-29·44·47 / CL-43·50.** 로컬 보관 약속·재인증·오류 후 복구와 비동기 작업 알림을 검증 가능한 흐름으로 만든다.
9. **기본 조작 접근성과 1600 작업 공간 — CX-37~42 / CL-15·16·25·26·28·30·45~48.** 패널을 닫고 다시 열며, 키보드로 같은 업무를 수행하고 상태·오류를 인지할 수 있게 한다. 픽셀 잘림과 보조기기 동작은 후속 실측으로 확인한다.
10. **운영 탐색과 기본 제품 기능 — CX-35·43·45·46·48~50 / CL-39·40·42·44·49.** 마이페이지·제품 버전/빌드·도움말·감사 조회·검색·사전 내보내기와 백업을 도입 범위에 맞게 보완한다. 내보내기와 복원 가능한 백업은 별도로 정의한다.
