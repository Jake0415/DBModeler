# t1 모델 트리 기획서 검토

대상은 [12 모델 트리 재기획](../12-model-tree-plan.md)이다. 영역·버전·참조의 경계와 물리 반영 규칙을 먼저 확정하고, 목업에서 객체 선택과 권한 제한을 한 흐름으로 검증하는 것을 권한다. 아래 내용은 명세와 목업 소스 대조 결과다.

## 지적 사항

1. **높음 · 시스템과 업무 영역의 역할을 명시해야 한다.** §3은 시스템 하나를 모델 하나로 간주하지만 §4.3은 DA#의 모델 단위 명령을 업무 영역에 일괄 대응시킨다. 시스템은 DBMS·명명 기준과 영역 목록의 범위, 업무 영역은 모델링·버전·결재의 범위로 정의한다. 모델 메뉴 항목별로 실행 범위를 정하고, DA#의 ‘모델로 내보내기’와 NeoDB의 DDL·정의서 내보내기는 결과물이 다르므로 별도 대응으로 기록한다. 목업의 시스템 전환 검증은 실제 데이터가 있는 요구사항관리 시스템으로 한정한다. [기획 §2~3·4.3](../12-model-tree-plan.md#3-neodb-개념과-맞추기) · [DA# M-C04·05](../../spec/da-feature-spec/00-index.md#L177) · [내비게이션 §2.2](../11-navigation-brand-plan.md#22-왼쪽--모델-트리-모델-설계-집중) · [목업 SYSTEMS](../mockups/assets/app.js#L617)

2. **높음 · 트리와 캔버스가 같은 버전을 열어야 한다.** 현행 트리는 최신 `m.ver`로 검색하고 객체 링크에 `focus`만 보낸다. 확정본이나 이력 조회 중 최신 초안의 객체가 섞이면 이름·준수율·선택 대상이 달라진다. 객체 선택과 펼침 상태의 기준을 시스템·영역·버전으로 정하고, 이력 화면에서는 열린 버전의 객체와 상태를 표시한다. 메뉴·F2·Delete·드롭 모두 실행 시 권한과 버전 잠금을 확인한다. [기획 §4.2·4.5](../12-model-tree-plan.md#42-트리에서-하는-일-동작) · [기존 편집기 결재 경계](../03-erd-editor.md#L247) · [drawTree](../mockups/assets/app.js#L618) · [목업 canEdit](../mockups/model.html#L372)

3. **높음 · 보기 배치와 영역 간 참조에 서로 다른 명령이 필요하다.** DG-02의 드래그는 같은 모델 객체를 여러 다이어그램에 배치하는 동작이다. NeoDB에서 같은 영역의 다른 보기는 기존 객체의 배치를 추가하고, 다른 영역에는 대상 영역이 원본을 가리키는 읽기 전용 참조를 추가한다. 참조 행은 현재 캔버스의 참조를 선택하고 메뉴에서 원본을 연다. 참조 가능한 원본 버전과 갱신 시점, 중복 배치, 참조 해제 시 관계 영향을 정의하고 드래그와 메뉴에 동일한 제약을 적용한다. [기획 §3·4.1~4.3](../12-model-tree-plan.md#3-neodb-개념과-맞추기) · [DA# DG-02](../../spec/da-feature-spec/01-model-diagram.md#dg-02-주제영역-m-c05-주제영역목록-우클릭-) · [편집기 §7](../03-erd-editor.md#7-시스템-전체-erd-조회-전용) · [목업 참조 해제](../mockups/model.html#L884)

4. **높음 · FK 누락 판정과 물리 반영을 같은 데이터에 연결해야 한다.** F-38은 FK 컬럼과 물리 제약조건 객체의 차이다. 시드의 `a.fk`는 컬럼 표시이고, DDL 목업은 관계와 컬럼을 조합해 FK를 생성한다. 따라서 플래그 개수로 제약조건 수를 계산하면 복합 FK를 중복 집계하고 ‘FK 0’ 경고와 DDL이 어긋날 수 있다. 게이트 A를 거친 물리 상태에서 관계별 FK 생성 여부를 판정해 DDL과 공유하고, 미반영·의도적 제외·실제 누락을 구분한다. M:N 미해소와 복합 FK를 검증 사례로 둔다. [기획 §4.1·4.3·6·7](../12-model-tree-plan.md#41-노드-종류와-표시) · [DA# PH-03·F-38](../../spec/da-feature-spec/03-physical.md#L44) · [편집기 §6](../03-erd-editor.md#6-논리물리-별도-캔버스) · [MODEL_SEED](../mockups/assets/app.js#L126) · [DDL 산출](../mockups/ddl.html#L110)

5. **중간 · DA# 객체 목록에서 옮길 항목과 연결할 기존 화면을 명확히 한다.** DG-01의 물리 Relation이 §4.1에 빠져 있어 물리 관계와 FK 제약조건을 따로 찾을 수 없다. 물리 관계의 조회 경로를 두고, M-C04의 엔터티·테이블 관리에 해당하는 P0 일괄 편집은 기존 그리드와 연결 범위를 적는다. M-B01의 현재 다이어그램 객체 범위는 ‘현재 보기’ 필터로 제공하고, 표준 관리·미니맵은 기존 사전 패널·캔버스 경로를 명시한다. 태그 관리 등 뒤로 미룰 기능도 범위표에 기록한다. [기획 §2·4.1·4.4](../12-model-tree-plan.md#2-da-모델-트리-확인한-기능) · [DA# DG-01·DG-06](../../spec/da-feature-spec/01-model-diagram.md#L8) · [DA# M-C04·M-B01](../../spec/da-feature-spec/00-index.md#L177) · [인벤토리 §3.5](../../planning/web-data-modeler-feature-inventory-v1.md#35-편집편의) · [목업 그리드](../mockups/model.html#L736)

6. **중간 · 표준 사전 명령의 업무 흐름을 구별한다.** M-C06에서 확인한 업데이트와 더블클릭 강조는 용어 기능이다. M-C07의 도메인은 표준 정보와 객체 정보만 확인됐고, M-C08은 용어·도메인 폴더에 메뉴가 없던 사례다. 용어의 사용처 강조를 메뉴로도 제공하고, 도메인 강조는 NeoDB 추가 기능으로 명시한다. §4.3의 ‘표준 정보 업데이트 신청’은 사전 변경 신청인지 모델의 표준 재적용인지 구분해 기존 경로에 연결한다. 트리의 사용 표준은 사용처 조회, 사전 패널은 검색·속성 추가·기존 속성에 용어 적용을 담당하도록 정한다. [기획 §2·4.2~4.3](../12-model-tree-plan.md#42-트리에서-하는-일-동작) · [DA# M-C06~08](../../spec/da-feature-spec/00-index.md#L179) · [편집기 §8](../03-erd-editor.md#8-표준-연동-캔버스에서)

7. **높음 · 선택·펼침·편집과 화면 이동의 우선순위가 필요하다.** 엔터티는 선택과 펼침을 모두 지원하고, 한 번 누르면 우측 패널이 열리며 두 번 누르면 이동한다. 캔버스의 두 번 누르기는 이름 편집이다. 펼침 버튼과 행 활성화를 구분하고, 트리의 위치 맞춤은 메뉴에서도 제공한다. 트리 선택은 캔버스와 우측 상세를 함께 갱신하되 역방향 동기화는 트리의 포커스를 빼앗지 않게 한다. 현재 보기에 객체가 없거나 물리 반영 대기 중이면 배치 상태와 가능한 이동을 안내한다. §4.2의 화면 이동과 §5의 화면 내 이동은 화면별로 통일하고, 확정 산출물에 대상 행이 없을 때의 이동도 명시한다. [기획 §4.1~4.2·5](../12-model-tree-plan.md#42-트리에서-하는-일-동작) · [편집기 §2·5~6](../03-erd-editor.md#5-편집-동작) · [목업 focusEnt](../mockups/model.html#L798)

8. **높음 · 공통 객체 명령을 공유하고 배치 명령에는 대상을 표시한다.** §4.3은 캔버스와 같은 메뉴를 약속하지만 LG-04의 관계 객체 삭제와 ‘관계선만 삭제’, 편집기의 M:N 해소를 구분하지 않는다. 편집·객체 삭제·사용처는 양쪽에서 같은 확인·저장·실행 취소를 사용한다. 현재 보기에서 제거, 선 숨기기, 참조 해제, 모델 객체 삭제는 대상과 영향이 다른 명령으로 명시한다. [기획 §4.3](../12-model-tree-plan.md#43-우클릭-메뉴-da-메뉴를-정리) · [DA# LG-04·05](../../spec/da-feature-spec/02-logical.md#L67) · [편집기 §4~5](../03-erd-editor.md#4-관계-ie) · [목업 삭제 확인](../mockups/model.html#L874)

9. **중간 · 1600px에서 패널 폭 우선순위와 행 표시 기준이 필요하다.** 현재 CSS 기준으로 트리 280 + 사전 240 + 우측 확대 560이면 캔버스에 최대 520px이 남는다. 세 패널을 동시에 열 때 우측을 기본 380px로 줄여도 트리 400px에서는 최대 580px이다. 트리 확장·사전 열기·우측 확대마다 640px를 지키도록 폭 상한과 접을 패널의 순서를 정하고, 검토·게이트 패널에서도 확인한다. 28px 행과 16px 들여쓰기에서는 깊은 속성 행의 이름과 상태부터 확보하고, 보조 물리명은 상세에서 확인할 수 있게 한다. 1600px 기본 접힘은 사용자 선택 이력이 없을 때 적용한다. [기획 §4.6·7](../12-model-tree-plan.md#46-크기성능) · [내비게이션 §7.2](../11-navigation-brand-plan.md#L127) · [목업 1600px 폭](../mockups/assets/app.css#L49) · [우측 확대 폭](../mockups/assets/app.css#L300)

10. **높음 · 가상화와 줄 메뉴까지 포함해 ARIA 트리의 포커스 규칙을 정의한다.** 트리에 접근 가능한 이름을 주고, 실제 부모에만 `aria-expanded`, 선택 가능한 행에만 `aria-selected`를 둔다. 가상화로 형제가 DOM에 일부만 있으면 `aria-level`, `aria-posinset`, `aria-setsize`를 명시한다. 스크롤로 포커스 행이 사라지지 않게 하고, 필터·삭제·접기 후에는 보이는 항목이나 펼침 버튼으로 포커스를 복구한다. 행마다 ⋯가 Tab 정지점을 추가하지 않게 하고, Shift+F10과 메뉴 닫기 후 복귀를 검증한다. 메뉴에서 위치 맞춤·사용처 강조·보기 배치·참조 추가도 실행할 수 있게 한다. [기획 §4.3~4.6](../12-model-tree-plan.md#45-키보드접근성-wai-aria-tree-view) · [W3C Tree View Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)

11. **높음 · 목업 적용 순서를 공유 셸의 회귀와 실제 검증 흐름 중심으로 바꾼다.** §7 단계 2는 참조 드롭 연결을 요구하고 단계 5는 참조 추가를 토스트로 처리한다. 현행 `drawTree`는 전역 셸에서 화면 링크·검색·최근 항목·접힘 상태를 담당하고, 캔버스 드롭은 사전 용어를 처리한다. 먼저 기존 셸의 링크와 상태를 보존하면서 실제로 열린 버전의 엔터티 하나를 트리↔캔버스↔상세에서 연결한다. 다음으로 보기 배치·참조·용어의 드롭 유형과 실제 동작 범위를 정하고, 최소 한 가지 참조 흐름을 추가→선택→해제까지 검증한다. 이후 물리 목록·표준화/DDL 이동·가상화를 붙인다. 산출물·가져오기를 공통 셸 회귀 목록에 포함하고, 역할·잠금·키보드 검증에서 토스트 동작은 시연으로 기록한다. [기획 §5·7](../12-model-tree-plan.md#7-목업-적용-범위와-순서) · [drawTree·buildShell](../mockups/assets/app.js#L618) · [목업 사전 드롭](../mockups/model.html#L1011) · [내비게이션 적용 범위](../11-navigation-brand-plan.md#22-왼쪽--모델-트리-모델-설계-집중)

## §8 결정 4건

12. **높음 · ① 업무 영역 안에 보기를 둔다.** 기본 ‘전체’와 예시 보기 하나로 시작한다. 보기는 객체 배치와 표시 범위를 저장하며, 업무 영역의 버전·결재를 따른다. 각 보기에서 논리·물리 모드를 전환하고 각각의 배치를 복원하는지 검증한 뒤 보기 관리 메뉴를 연다. 13. **중간 · ② 속성까지 펼친다.** 기본은 접고, 검색 결과 또는 펼침 요청 시 속성 경로를 연다. 클릭하면 캔버스의 엔터티와 우측 패널의 해당 속성 행을 찾아준다. DG-01이 확인한 것은 논리 객체 목록이므로 속성 하위 노드는 NeoDB의 탐색 개선으로 설명한다. 14. **중간 · ③ 물리 객체 폴더는 이번에 넣되 확인 가능한 상태부터 연다.** 우선 테이블·컬럼 탐색을 연결하고, 관계와 제약조건 목록·경고는 실제 물리 상태와 DDL이 일치하는 표본으로 확인한 뒤 연다. FK 만들기·명명 규칙 재적용은 게이트와 저장 흐름을 검증할 수 있는 단계에 둔다. 15. **중간 · ④ 280px 기본과 폭 조절을 채택한다.** 1600px에서는 캔버스 640px를 확보하는 동적 상한을 적용한다. 손잡이에는 키보드 폭 조절과 현재 폭 안내를 제공한다. 240·280·400px에서 긴 한글 논리명, 영문 물리명, 깊은 속성 행을 확인하고, 400px는 패널 조합에 여유가 있을 때 허용한다.
