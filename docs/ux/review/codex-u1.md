# u1 사용자 계정·인증 검토

`b73a45f`의 변경과 관련 화면을 정적 검토했다. 파일과 줄 번호는 해당 커밋 기준이다. 심각도는 확인된 목업 동작이 운영에 반영되거나 설계 누락이 그대로 구현될 때의 영향을 기준으로 정했다. 운영 서버 동작과 브라우저·보조기기 동작은 검증 범위 밖이다.

기본 모드의 로컬 계정 등록은 회사명·부서명·이름·전화번호·이메일·ID·비밀번호를 직접 입력받는다. 독립 인트라넷의 기본은 ID·비밀번호이며 SSO는 선택할 수 있다. 근거는 `docs/ux/14-user-account-auth.md:9`, `docs/ux/mockups/settings.html:275`, `docs/ux/mockups/settings.html:296`이다.

- **문제** 일반 등록 입력은 오류와 연결하지만 역할·담당 시스템은 그룹 오류와 연결되지 않는다. 로그인·비밀번호 변경·연락처의 공용 오류는 해당 입력에 연결되지 않는다. 초기화 모달을 직접 열어 진입 포커스를 주지 않고, 다시 그리기에서 기존 열기 버튼을 제거해 닫은 뒤 복귀할 대상도 사라진다.
- **수정** 입력과 체크박스 그룹에 오류 ID를 연결하고 오류 해소 시 상태를 정리한다. 임시 비밀번호 모달을 열 때 내부의 안정적인 요소에 초점을 두고, Tab 순환과 Esc·닫기 시 재생성된 열기 버튼으로의 복귀를 키보드와 낭독기로 검증한다.

### 15. 중간 · 공공기관 운영에 필요한 계정·감사 통제 명세가 부족함

- **근거** `docs/ux/14-user-account-auth.md:55`, `docs/ux/14-user-account-auth.md:76`, `docs/ux/mockups/assets/app.js:540`
- **문제** 변경 감사 이벤트를 열거하지만 보존·위변조 방지·점검 절차가 없고 목업은 브라우저에 최근 300건만 남긴다. 개인별 계정 발급과 공유 금지, 최소 권한과 인사 변동 시 즉시 회수, 정기 권한 점검, 접속지 제한과 외부 접속 인증의 적용 기준도 명시되지 않았다.
- **수정** 개인정보처리시스템에 해당하면 고시 제5~8조를 기준으로 개인별 계정, 권한 부여·변경·말소 이력과 접속기록의 구분, 적용 보존 기간, 위변조 방지와 점검 책임을 명세한다. 외부 접속을 허용하면 적용 대상에 안전한 인증수단과 접근 통제를 설계한다. 고시상 지정 공공시스템이면 제14~17조의 추가 점검·분석 요건을 확인한다. 배포 기관의 자체 지침에서 정한 계정 실사 주기, 비밀번호 재사용·초기 비밀번호, 관리자 접속 경로 기준도 확인해 반영한다.
