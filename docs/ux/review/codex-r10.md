# 클릭 목업 v6 교차 검토 · Codex r10

## 1. 총평

- 합의 제안은 Top 10 **0/10 닫힘**, S1~S6 **0/6 닫힘**이다. Top 10의 10번은 엑셀 포커스 복귀와 SC-16 필드 비교가 남아 부분으로 본다.
- CL9 새 발견 25건을 모두 검토했다. v7의 우선순위는 승인한 값의 실제 반영, 정확한 확정본 재진입, 반려·회수 후 보완, 엑셀 반영본 확인이다.
- 목업 코드의 실행 경로를 기준으로 판정했다. v7에서 대표 왕복을 통과하면 목업 반복을 마무리하고 구현 설계로 넘어가는 데 동의한다.

## 2. 판정이 다른 행

파일과 줄은 `docs/ux/mockups/` 기준이다. v5 ID는 원 발견의 증상으로 맞췄으며, 양쪽에 판정이 있는 행 중 차이가 있는 행만 실었다. S1~S6은 전부 부분으로 일치한다. CL9 총평의 CL7-04 ‘닫힘’과 상세표의 ‘부분’은 상세표를 기준으로 비교했다. CL9의 CL7-06/CX7-16은 CX9에서 CL7-06(고정 신청)과 CL7-07/CX7-16(선택 항목 인계)으로 나눠 기록했다.

닫힘은 입력→결재→반영→재진입이 이어지는 항목만 분자에 넣었다. v5 발견의 개별 개선은 이 수에 별도로 더하지 않았다.

### (a) v7 목업에서 더 할 것 Top 6

1. **사전 승인·보완 왕복** — 신규·변경·미사용과 필드값을 문서와 사전에 일치시키고 대상 미존재·중복·건수 불일치를 화면에서 차단한다. 반려·회수 시 대기와 후보 상태를 풀고 보완 재신청을 연결한다.
2. **확정본·다음 작업 버전** — 결재에서 실제 영역·문서 사본·이전 확정본을 연다. 제출본 기준 검사와 오래 열린 탭의 다음 버전 차단을 시연하고 예시·공동 편집 데모를 정상 작업에서 격리한다.
3. **표준 맞추기 왕복** — 영역·버전·행 ID로 처리와 사유를 전달하고 용어 문서와 후보를 실제 생성한다. 잠금 변경 시 선택을 보존하고 승인·반려 뒤 모델 상태를 보여 준다.
4. **엑셀 제출·반영본·보류 왕복** — 기준본과 신청 행·선택·사유를 심사자가 그대로 확인한다. 실제 반영 행 비교 결과를 기록하고 보류만 재검증해 새 신청으로 연결한다. 없는 묶음과 파일 교체도 명시적으로 처리한다.
5. **확인 범위와 입력 복구** — 가시 행 자동 보정, 실패 값 복원, 경고 확인, 후보 약어, 사전 필수값, 보정 후 포커스를 정리한다. 공표는 확인한 항목으로만 진행하고 SC-16에서 같은 필드 전후를 조회한다.
6. **열람·실행 경계와 복구 안내** — 역할 전환 뒤 낡은 모달, 타인 묶음·문서 직접 주소, 오래 열린 제출 버튼의 대표 실패 경로에 동일한 차단 이유와 복귀 동작을 둔다.

### (b) 구현 설계로 넘길 것 Top 6

1. **제출 스냅숏과 멱등 처리** — 모델·엑셀·사전 문서의 불변 제출 자료, 묶음과 활성 문서의 관계, 같은 제출 재시도와 보완 재신청의 식별자 및 원자적 링크 갱신.
2. **서버 권한·상태 전이** — 사용자 세션과 역할, 문서·파일 조회 범위, 승인·반려·회수·다음 버전의 예상 단계·개정 조건, 충돌 시 오류 응답.
3. **모델 개정·확정·동시 편집** — 영역별 개정과 확정본 승계, 제출본·규칙 버전이 지정된 재검사, 동시 저장 충돌과 병합 요구.
4. **사전 반영 트랜잭션** — 타입이 있는 필드별 변경, 진행 신청까지 포함한 식별자·유일성 검사, 원자적 반영·대기 해제·이력, 후보와 사용처 재판정.
5. **기준본·업로드·반영본 비교** — 범위·항목 값·버전·양식에 연결되는 서버 기준본, 반영본 재검증과 왕복 완료 기록, 보류 행의 후속 처리.
6. **공표·감사·알림 이벤트** — 공표 대상 이벤트 집합과 차수 경쟁 제어, 실제 필드 전후·작업자·신청번호·사용처 이력, 영향받은 사용자에 대한 재처리 가능한 알림.

**마무리 판단은 조건부 찬성이다.** v7에서 ① 모델 제출→승인→확정본 재진입→다음 버전, ② 표준 맞추기·사전 신청→정확한 값 반영 또는 반려·회수→보완, ③ 엑셀 기준본→보정·결재→반영본 확인·보류 재검증을 확인한다. 여기에 잘못된 주소, 역할 변경, 오래 열린 탭에서 쓰기·완료 오인이 발생하지 않는 대표 실패 경로까지 통과하면 목업 반복을 마무리할 수 있다. 이 검증은 화면과 상태 전이의 계약을 확정하기 위한 것이며, 동시성·트랜잭션·실제 파일 처리는 구현 설계에서 다룬다. 실패 경로가 남으면 해당 시나리오만 재검증한 뒤 전환한다.
