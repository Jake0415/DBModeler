# SC-13 표준 사전 엑셀 가져오기 · 오류 확인 · 보정 사용성 리뷰

2026-11-23 · 표준화 담당자와 모델러의 엑셀 왕복 업무 기준

**검토 근거** — `docs/ux/mockups/excel-import.html`, 같은 폴더의 `assets/app.js`와 `assets/app.css`, `docs/ux/07-dict-excel-roundtrip.md` §2 E1~E4 및 §4를 직접 대조했다. 미리보기 URL의 HTTP 200 응답을 확인했다. 아래 조작 결과는 소스 추적에 근거하며, 브라우저 조작·화면 낭독·1600/1920 실측·대량 성능 측정은 수행하지 않았다. 위치의 파일명은 위 경로 기준이다. 실제 파일 파싱과 서버 검증이 예시로 대체된 범위에서는 구현 인수 기준을 제시한다.

**총평** — 방식·종류 선택부터 신청까지 경로가 이어진다. 5단계의 규칙별 오류 필터, 행 상세의 수정 안내, 전후 미리보기와 보호 행 제외는 반복 보정에 도움이 된다. 현재는 미리보기에서 확인한 범위와 실제 일괄 반영 범위가 어긋날 수 있고, 신청 재검사 결과를 해당 행으로 돌려보내는 연결이 약하다. 보정본 형식도 설계의 왕복 계약과 다르다.

### CX-01 · 높음 · 5단계 자동 수정 미리보기
**위치** — `excel-import.html:567`, `excel-import.html:573`, `excel-import.html:577`, `excel-import.html:583`, `excel-import.html:588`  
**문제** — 표준용어의 전체 보기에서 자동 수정 미리보기를 열면 13행 공백과 14행 앞자리 0이 모두 선택된다. 창에서 공백 규칙만 골라도 14행은 선택된 채 숨겨진다. 상단 체크박스는 보이는 규칙에만 작동하고 적용 버튼은 숨겨진 선택까지 반영한다. 첫 포커스도 적용 버튼이다.  
**제안** — 처음에는 선택을 비우고 미리보기 제목이나 첫 선택 컨트롤에 포커스를 둔다. 규칙 필터를 바꿔도 선택을 유지한다면 전체 선택 수와 현재 보기 밖 선택 수를 버튼 옆에 표시하고, 적용 전 선택 행만 모아 확인할 수 있게 한다.

### CX-02 · 높음 · 5단계 찾아 바꾸기 범위와 실행
**위치** — `excel-import.html:620`, `excel-import.html:622`, `excel-import.html:625`, `excel-import.html:635`  
**문제** — 미리보기는 최초 200칸에서 잘리지만 버튼과 실행에는 그 이후 일치 건도 포함된다. 잘렸다는 안내가 없고 건너뛸 칸도 200칸 한도를 차지한다. 찾을 값 입력 중 Enter가 바로 실행되어 전후 값을 확인하기 전에 바꿀 수 있다. 이전 검색값과 입력 옵션도 다시 열 때 남을 수 있다.  
**제안** — 상태·규칙 필터와 후보/적용/건너뜀 건수를 표시하고, 전체 후보를 페이지 또는 가상 스크롤로 검토할 수 있게 한다. Enter는 검색에 사용하고 실행 버튼을 명시적으로 눌러 적용하게 한다. 범위가 바뀌면 이전 입력의 재사용 여부를 명확히 알린다.

### CX-03 · 높음 · 5단계 보정 검증과 6단계 재검사
**위치** — `excel-import.html:241`, `excel-import.html:494`, `excel-import.html:596`, `excel-import.html:639`, `excel-import.html:749`, `assets/app.js:715`  
**문제** — 찾아 바꾸기는 일반 코드값의 길이만 검사한다. 예시 코드값의 4행 `D`를 기존 3행의 `A`로 바꾸면 길이 검사는 통과하고, 신청 항목을 만들 때 기존 `A`의 코드값명과 순서를 덮을 수 있다. 개별 제안 적용은 저장 전에 셀 검사를 호출하지 않으며, 새 용어의 분해 검사에서 오류나 보류가 되어도 통과 알림을 띄운다. 신청 재검사에서 막히면 알림에 처음 세 항목만 나오고 표의 상태와 위치는 갱신되지 않는다.  
**제안** — 미리보기에서는 일괄 변경 후의 행 집합으로 중복·참조·계산값을 검사하고, 저장과 제출에 같은 검증 결과를 사용한다. 결과 메시지는 실제 상태를 반영하고, 마지막 재검사에서 발견한 문제는 규칙·행·칸에 연결해 5단계로 직접 이동시킨다.

### CX-04 · 높음 · 5단계 실행 취소와 저장 피드백
**위치** — `excel-import.html:380`, `excel-import.html:487`, `excel-import.html:490`, `assets/app.js:1966`, `assets/app.js:1973`  
**문제** — 실행 취소는 기본 12초 뒤 사라지는 알림에만 있고, 뒤따른 보정이 있으면 이전 작업을 취소할 수 없다. 전체 행을 작업마다 복제하므로 대량 작업에서는 편집 횟수에 따라 비용이 쌓인다. 다른 탭 변경으로 저장에 실패해도 보정 성공 알림이 이어져 무엇이 보존됐는지 헷갈린다.  
**제안** — 하단에 마지막 작업의 변경 건수와 지속되는 실행 취소 버튼을 둔다. 변경한 칸과 행 상태 단위로 복원하고, 이전 작업 취소가 불가능하면 해당 버튼을 즉시 비활성화한다. 저장 실패는 적용 결과와 구분해 화면에 유지하고 고친 값을 회수할 수 있게 한다.

### CX-05 · 높음 · 5단계 내려받기와 엑셀 원본 동기화
**위치** — `excel-import.html:539`, `excel-import.html:544`, `excel-import.html:550`, `07-dict-excel-roundtrip.md:95`, `07-dict-excel-roundtrip.md:154`, `07-dict-excel-roundtrip.md:159`  
**문제** — 오류 파일은 화면 필터와 무관하게 남은 오류 전체를 CSV로 내보낸다. 원본 행과 수정 방법은 유용하지만 오류 및 수정 가이드 시트와 셀 메모가 없다. 보정본도 표시 열 위주의 CSV라 양식 버전·ID·항목 버전·기준본을 유지하지 못하며, 엑셀에서 앞자리 0이 다시 사라질 수 있다. 그런데 완료 문구는 이 파일로 원본을 맞추라고 한다.  
**제안** — 버튼에서 파일 형식과 대상 범위를 먼저 알린다. 오류용 XLSX에는 원본 행·셀 메모·가이드 시트를 넣고, 재업로드용 XLSX에는 원래 양식과 보호 열, 텍스트 서식, 변경점 시트를 보존한다. CSV를 제공하는 동안에는 ‘보정 내역 CSV’로 표시한다.

### CX-06 · 높음 · 1~4단계 기준본 확인과 파일 교체
**위치** — `excel-import.html:353`, `excel-import.html:388`, `excel-import.html:419`, `excel-import.html:422`, `excel-import.html:774`, `assets/app.js:1033`, `07-dict-excel-roundtrip.md:43`  
**문제** — 예시 비교는 사용자 최신 내려받기 기록에 의존한다. 같은 사람이 범위가 다른 엑셀을 여러 개 받으면 현재 올리는 파일과 어느 기준본이 연결됐는지 검증하는 흐름을 확인할 수 없다. 보정·선택이 없으면 파일 교체 시 기존 묶음과 행 상태를 초기화하는 분기를 타지 않는다.  
**제안** — 올린 파일의 기준본 ID를 서버 기록과 연결하고 종류·범위·기준 시각을 검증 전에 보여 준다. 기준본을 확인할 수 없으면 빠짐 판정을 중단하고 다음 작업을 안내한다. 파일 교체는 항상 새 입력으로 처리하고 이전 묶음은 이력에서 이어갈 수 있게 한다.

### CX-07 · 높음 · 5→6단계 일부 신청과 보류
**위치** — `excel-import.html:462`, `excel-import.html:464`, `excel-import.html:690`, `excel-import.html:697`, `excel-import.html:722`, `07-dict-excel-roundtrip.md:97`  
**문제** — 오류·미선택 후보를 제외한 일부 신청이 가능하지만 결과 화면 하단과 신청 요약에 제외 이유가 흩어져 있다. ‘제외’에 오류와 미변경 행이 함께 집계되며, 보류 행 안내가 약속하는 재검증으로 바로 이어지는 버튼은 해당 패널에 없다. 코드값의 요약은 주로 행 수를 보여 주고 결재 단위인 그룹 수는 제출 전에 드러나지 않는다.  
**제안** — 신청 전 ‘신청 대상·보류·오류로 제외·변경 없음’을 별도로 집계하고 각 숫자를 해당 행 목록에 연결한다. 오류를 남긴 일부 신청은 제외 건수를 항목별로 명시한다. 코드값은 행 수와 결재 항목 수를 함께 보여 주고, 보류 상태에서 이력의 해당 묶음과 재검증으로 연결한다.

### CX-08 · 중간 · 5단계 오류 요약, 행 패널과 수동 보정
**위치** — `excel-import.html:227`, `excel-import.html:241`, `excel-import.html:432`, `excel-import.html:445`, `excel-import.html:458`, `excel-import.html:465`, `excel-import.html:522`  
**문제** — 중복 ID는 숨김 필드여서 붉은 편집 칸이 없고, 분해 중 발견한 미등록 단어는 규칙과 오류 칸이 비어 오류 요약이나 패널에 `null`·`undefined`가 나타날 수 있다. 잘못 고친 값은 포커스를 벗어나면 되돌아가고 빈 입력은 검증에서 건너뛴다. 보정 후 행 패널의 ‘파일’ 열에는 보정값이 표시되어 출처가 모호하다.  
**제안** — 규칙 ID, 이유, 수정 방법, 조치할 위치를 각 오류에 연결한다. 중복 ID와 미등록 단어는 패널의 조치 버튼으로 이동시키고, 수동 수정에서 검증 실패한 입력과 피드백을 함께 유지한다. 패널의 값 비교에는 ‘현재 사전·파일 원본·보정 값’을 표시한다.

### CX-09 · 중간 · 5단계 계산 칸과 파생 변경
**위치** — `excel-import.html:238`, `excel-import.html:303`, `excel-import.html:432`, `excel-import.html:593`, `excel-import.html:622`, `excel-import.html:645`, `07-dict-excel-roundtrip.md:44`  
**문제** — 도메인명은 찾아 바꾸기 대상에서 제외되지만, 오류가 나면 직접 편집 가능하고 가이드도 직접 고치라고 안내한다. 타입·길이를 일괄 보정하면 도메인명이 따라 바뀌는데 그 파생 변경은 찾아 바꾸기 미리보기에 없다. 분류도 바꿀 수 있지만 분류만 바꿀 때는 해당 재계산 분기가 실행되지 않는다.  
**제안** — 계산 칸의 입력 정책을 전 과정에서 통일하고 분류·타입·길이 또는 구성 단어를 조치 위치로 안내한다. 파생 값을 사전에 계산해 미리보기와 변경 건수에 포함한다.

### CX-10 · 중간 · 5단계 키보드와 화면 낭독
**위치** — `excel-import.html:447`, `excel-import.html:521`, `excel-import.html:524`, `excel-import.html:530`, `excel-import.html:582`, `excel-import.html:650`, `assets/app.js:2059`  
**문제** — 공용 코드에 Tab 가두기, Escape 닫기, 행 키보드 활성화가 있다. 다만 필터나 행을 고르면 해당 DOM이 다시 그려져 현재 포커스가 사라질 수 있다. F8은 편집 칸 없는 중복 ID 오류에서 포커스 이동을 완료하지 못한다. 모달이 열려 있어도 F8이 배경 표를 갱신하고 Ctrl+H가 다른 모달을 열 수 있다. 결과 행마다 Tab 정지점이 있어 대량 탐색 비용도 크다.  
**제안** — 필터 다시 그리기 후 해당 버튼에 포커스를 유지하고, 행 선택 결과를 낭독할 수 있게 한다. F8은 오류 칸·행·상세 조치 중 사용 가능한 첫 대상에 초점을 둔다. 모달이 열린 동안에는 배경 단축키를 중지하고, 결과 표는 행 탐색과 조치 영역으로 이동하는 짧은 키보드 경로를 제공한다.

### CX-11 · 중간 · 1600×900 · 1920×1080 결과 배치와 대량 처리
**위치** — `excel-import.html:48`, `excel-import.html:132`, `excel-import.html:442`, `excel-import.html:447`, `excel-import.html:576`, `excel-import.html:633`, `excel-import.html:699`, `assets/app.css:58`, `assets/app.css:339`, `assets/app.css:513`, `07-dict-excel-roundtrip.md:152`  
**문제** — 두 프레임 모두 행 상세 패널이 열려 있고 접기 버튼이 없다. 1600에서는 380px 패널, 줄바꿈하는 상태·다운로드 도구 모음과 별도 오류 요약 때문에 표 공간이 줄어들 수 있다. 1920의 추가 폭도 긴 설명과 규칙을 읽는 데에는 도움이 되지만, 표 전체 재생성, 자동 수정 전체 렌더링, 찾아 바꾸기 입력마다 전체 범위 검사, 6단계의 전체 이름 나열 비용은 남는다.  
**제안** — 오류 탐색과 주요 작업을 고정하고, 상태 필터를 그룹화하고, 행 상세를 키보드로 접을 수 있게 한다. 설계대로 결과·미리보기 표를 가상화하고 검색 입력의 갱신 빈도를 제한한다. 신청 요약은 건수와 상세 보기로 구성한다. 두 해상도에서 긴 한글 값과 여러 규칙을 넣고 버튼 위치·표 스크롤·포커스 복귀를 실측한다.

### CX-12 · 중간 · 1~4단계 업로드와 열 매핑 복구
**위치** — `excel-import.html:75`, `excel-import.html:105`, `excel-import.html:295`, `excel-import.html:399`, `excel-import.html:407`, `excel-import.html:717`, `excel-import.html:736`, `excel-import.html:763`  
**문제** — 파일 선택과 검증 진행률은 예시 기반이다. 열 매핑의 ‘확인 필요’ 선택은 값 변경을 후속 검증에 전달하지 않아 사용자에게 처리 결과가 보이지 않는다. 필수 열 누락·서식 변환·CSV 문자가 깨진 경우의 복구 흐름도 확인할 수 없다. 방식 선택 카드는 라디오를 별도 포커스 가능한 버튼에 중첩한다.  
**제안** — 방식 선택은 기본 라디오와 레이블로 구성한다. 업로드에서는 파일명·시트·행 수·실패 원인을 지속 표시하고, 매핑에서는 무시·연결 결과를 실제 검증에 반영한다. 필수 매핑이 빠지면 해당 항목과 복구 방법을 표시하고 검증 시작을 제한한다.

### CX-13 · 중간 · 역할별 1~5단계 행동 안내
