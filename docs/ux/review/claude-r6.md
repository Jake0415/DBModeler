## 1. 총평 (3줄)

1. Codex의 인용 35건을 모두 원문에서 다시 확인했고 **틀린 근거는 없었다**. 반대 0 · 동의 27 · 수정 동의 8건이다. 두 결과는 핵심 진단이 같다. 즉 기준본(내려받기 기록)·행 식별·빈 칸/형 변환·칸 단위 3방향 비교·반려 후 복귀·⛔📝⚠ 분리·업로드 묶음 신원이다.
2. Codex만 잡은 것 가운데 중요한 것이 있다. ① MD-08의 **파랑 '동일 대기' / 주황 '대기와 다름' 구분이 07에서 사라짐**(CX5-07). ② **5만 행은 MD-08 근거가 아님**(CX5-35). ③ 같은 제출의 재시도를 구분하지 않아 생기는 문서 중복(CX5-22). ④ 결재 목업이 **사전 최종 승인마다 '제정 13차'를 띄움** — 두 검토자의 Q4 결론과 정면으로 어긋난다(CX5-32). ⑤ ST-R03의 '빈 검색=전체'와 UX의 '최근 변경'이 충돌함(CX5-25).
3. 열린 질문 4개는 **방향이 모두 같다**. 차이는 Q2의 문서 크기 상한, Q4의 W1 범위뿐이다. 둘 다 놓친 것으로 **초기 적재 경로, 대량 자기 승인, 신청 중 항목의 내려받기 값, 반영 후 재검토 알림 폭주, CSV 인코딩** 5건을 추가한다(CL6-01~05).

## 6. 합의

### 6.1 플랜(07)에 추가할 것

1. **왕복 계약** — 서버 내려받기 기록(기준본 ID·기관·종류·필터·포함 ID·버전)을 둔다. 파일에는 기준본 ID와 행 ID만 넣고, 서명은 메타데이터 훼손 검출용으로만 쓴다. 서명 없는 파일·CSV·구 양식은 '신규·명시 검토' 경로로 보내고, 3방향 비교와 빠짐 판정을 끈다(CL5-11, CX5-03·35).
2. **자료형·빈 값 규칙** — 빈 칸 = '값 지움'(별도 강조). 매핑되지 않은 열 = 기존 값 유지. 수식은 평가하지 않음. 텍스트 서식, 앞자리 0, NULL·빈 문자열·0을 구분한다. 목록 칸은 집합으로 비교하고, 비교 전 정규화한다(CL5-08·09·38, CX5-04).
3. **식별 규칙** — 유효 ID 우선. ID 중복은 ⛔. 종류별 자연키를 쓰고, 이름 변경은 하위 표시(⚠+영향)한다. 서명이 손상된 행은 이름 매칭으로 우회하지 않는다(CL5-10·39, CX5-05).
4. **W1 = 한 종류 편집 파일.** 통합 문서는 참고용이고, 다중 시트 반입은 W2(CX5-02 합의).
5. **상태·판정 체계** — 상태 라벨: 신규·변경·동일·동일 대기(파랑)·대기와 다름(주황 ⛔)·버전 충돌·확인 필요·후보 선택·오류·파일에서 빠짐. 이와 별도로 **검사 수준 열 ⛔/📝/⚠/✓**을 둔다. ⚠ 확인과 📝 사유는 행·규칙에 묶어 결재로 넘긴다. 30 MD-08의 "5색" 문구를 개정한다(CL5-04·05·07, CX5-07·11·12).
6. **낡은 제출 차단 + 칸 단위 3방향** — 서버는 문서를 만들 때 버전·대기 상태를 원자적으로 검사한다. 화면은 다시 비교하고 달라진 행만 다시 확인받는다. 필드별 A/B/C를 비교하고 합친 결과 전체를 재검증한다(CL5-06·13, CX5-06·08).
7. **영향과 재검증 범위** — 변경 행에 MD-11 영향(용어·분류·코드·모델 사용처)을 표시한다. 행을 편집하면 그 행에 의존하는 행도 다시 검사한다. 계산 칸(용어 약어·도메인명)은 편집 대상이 아니다(CL5-14·15, CX5-10·13).
8. **일괄 보정** — 기본은 체크한 행이다. 규칙 단위 [모두 적용]은 '현재 필터 결과 전체'라고 범위를 명시하고, 대상 수와 전후 미리보기를 보여 준다. 작업 ID 단위로 취소할 수 있다(CL5-18, CX5-14).
9. **주기 닫기** — 보정본은 원래 기준본을 유지한다. 반영본은 승인 스냅숏에서 만든다. 남은 작업(제외·보류·반려 행) 파일을 따로 받을 수 있다. 반려·회수 → [이 업로드 다시 열기](새 번호·재검증). 결재 대기 행은 보류 목록에 둔다. 오류 행만 고쳐 다시 올리면 같은 묶음에 병합한다(CL5-01·12·19·20, CX5-17·18·19).
10. **결재 단위·멱등성** — 업로드 1회 = 묶음 1개. W1 기본은 문서 1건이고, 코드값은 그룹별, 분류는 도메인과 함께 묶는다. 같은 제출을 재시도하면 기존 문서를 돌려준다. 행 상한은 부하 측정 후 정한다(Q2, CX5-22·34, CL5-33).
11. **초기 적재 모드**(CL6-01), **대량 자기 승인 안전장치**(CL6-02), **신청 중 열**(CL6-03), **재검토 알림 묶음**(CL6-04), **CSV 인코딩**(CL6-05).
12. **권한·감사·보관** — 소유자·참조자·결재자·DA의 열람/편집 범위를 정한다. 공유 링크는 열람자 권한으로 다시 조회한다. 내려받기·업로드를 감사 기록에 남긴다. 초안 30일과 원본 파일 보관을 따로 정의한다(CL5-32, CX5-20·21·28).
13. **버전·제정차수** — 결재 = 항목 Vn, 공표 = 제정차수(Q4). 타임라인에 V0와 반려 시 버전 유지를 표시한다. 과거 버전 파일은 열람용 표식(CX5-23, CL5-25).
14. **문서 개정 목록** — 30: MD-08(색·완화·변경 행·5만 행 근거 제거), MD-10(엑셀 경로). 02 §1: SC-15·16 추가, W2 목록에서 '버전별 이력 전체 화면'을 SC-16으로 옮김. 02 §3.1·§3.3: 복귀 경로. 20: ST-R03(빈 검색 = 최근 변경), ST-R04(왕복 설명), 새 요구 ID, SC-16은 W1 기본/W2 고급(CL5-26, CX5-25·26·35).
15. **최소 검증 시나리오** — 반영본을 다시 올리면 전부 '동일'로 판정되는지 확인하는 것을 W1 완료 조건으로 한다. 여기에 두 사용자 동시 편집(다른 칸/같은 칸), 필터 파일에서 한 줄 제거, 경고 확인 후 규칙 변경, 코드값 1건 충돌, 반려 후 재개를 포함한다(CX5 §4).
