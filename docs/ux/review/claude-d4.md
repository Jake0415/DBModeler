# D4 최종 일관성 검토: Claude (전 화면 결정 반영)

> 대상: 마지막 커밋 이후 작업 사본(16개 파일). app.css v13 블록, 전 화면 인라인 정리, 산출물 미리보기, 로그인
> 기준: 08 §11, 09(§3 보류 포함), 01 §5, 이전 d2·d3 검토
> 방법: 코드만 읽고 판단했다(브라우저 없음). 등급은 상(레이아웃 깨짐·기능 고장), 중(결정 위반·화면 간 불일치), 하(다듬기)다.

## 총평

일괄 치환은 대체로 안전하다.
- 입력 높이 26/28을 지우고 공통 32로 맞췄다.
- 반경 8/12를 토큰으로 바꿨다.
- 그림자 shadow-4/5를 menu-shadow로 바꿨다. 화면 HTML에서 shadow-4/5는 0건이다.
- 표에 인라인으로 준 이중 테두리를 지웠다(mypage·settings).

JS 문자열이 손상된 곳은 없다. 지운 자리에 `style=""`과 `style="width:160px;"`의 끝 세미콜론만 남았다.

새 회귀는 하나다. 로그인 버튼에 붙인 `lg` 클래스가 로그인 화면의 상자 클래스 `.lg`와 이름이 겹친다. 나머지 지적은 같은 역할의 요소가 화면마다 다르게 생긴 경우다: 표 모양, 예외 표시, 지표 요약.

**하 (5개)**
- `dictionary.html:55-58`: 필터 선택 상자에만 인라인 `font-size:13px`이 남아 다른 화면 도구 막대(14px 점선 알약)와 글자 크기가 다르다. 인라인을 지운다.
- 제목 크기·자간이 화면마다 다르다: 로그인 h1 24px/−0.4(`login.html:13`), 오류 h1 24px/기본(`error.html:14`), 시스템 홈 머리 20px/−0.3 인라인(`system.html:16`), 페이지 h1은 공통값. 독립 화면 제목을 한 규칙(예: 24/600/−0.3)으로 묶고 system의 인라인은 공통 h1 규칙으로 옮긴다.
- 오류 화면(`error.html:12-17`)은 로그인과 달리 상자가 없는 전용 배치이고 공통 빈 상태(`.empty`, 54px 아이콘 칸)도 쓰지 않는다. d2 Codex D2-13에서 남은 부분이다.
- 치환 뒤 `style=""`(approvals 35, model 162)과 `style="width:160px;"` 끝 세미콜론이 남았다. 기능에는 영향이 없다.
- `model.html:12` 공동 편집자 색 `#de1d8d`(분홍)·`#0a72ef`가 고정값이다. 08 §11의 `--ds-*` 단계(예: amber-700, blue-700)로 바꾼다.

## 확인했고 문제 없음
- 높이 26/28을 지운 입력·선택이 들어간 표 칸(settings 타입 매핑, standardize 후보 선택, excel-import 열 매핑)은 행 높이 44px 안에 32px로 들어간다. 모델 표 보기는 `#grid select.input { height:28px }`(model 120)가 계속 이긴다.
- `select multiple size=1`(ddl 91)은 높이를 지워도 공통 32px로 그대로다.
- `.caption { color:inherit }`는 원래 색 지정이 없던 것과 같아 변화가 없다. `.kv`·`.card`·`.section-t` 공통 규칙은 기존 인라인과 충돌하지 않는다(settings 79·dictionary 91처럼 바탕을 덮어쓴 카드는 의도한 미리보기 상자).
- 산출물 미리보기(`outputs.html:18-21`)는 Geist 머리줄(gray-100·14/400·좌우 16·40px)로 바뀌었다. 문서 서식 미리보기라 행 높이 40은 받아들일 수 있다.
- JS 템플릿 문자열(ddl 91, standardize 124)은 `height`만 빠졌고 따옴표·백틱 짝이 맞다.
