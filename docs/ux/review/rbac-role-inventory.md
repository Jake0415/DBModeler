# 역할 × 화면 동작 목록 (자동 수집, 2026-11-24)

> 방법: 단일 역할 시험 계정 5개로 23개 화면을 1920×1000에서 열고, 보이는 버튼 · 탭 · 입력(⛔ = 꺼짐, 괄호 = 꺼진 이유)과 안내 띠를 모았다. 아래는 **역할마다 다른 것만** 적었다(모두 같은 것은 생략). 오류(`__errs`)는 115회 모두 0건.
> 시험 계정: tadm = Admin만 · tda = DA만(담당 통합ERP) · tmod = 모델러만(외주 회사, 담당 통합ERP) · town = 기관 담당자만 · tview = 역할 없음(조회만). 목업 데이터의 업무 영역: e_hr = 통합ERP › 인사관리, rq = 요구사항관리 › 프로젝트.

## 화면별 차이
| 화면 | 역할에 따라 다른 것 |
|---|---|
| 홈 | Admin: 기관 전체 기한 넘긴 결재 4건 띠 · [오래 머무는 결재 보기]. DA · 기관 담당자: [결재함 열기] 띠. 모델러만 왼쪽 트리가 펼쳐져 있음. **조회만 · Admin에게 할 일 안내 없음.** |
| 시스템 홈 | Admin: [시스템 설정] · [영역 모두 옮기기 · 복제] · [업무 영역]. 모델러: [업무 영역]. **DA · 기관 담당자 · 조회만: [업무 영역] 꺼짐**(“모델러 · Admin만”). |
| 모델 (담당 시스템) | 모델러만 [확정 신청] 켜짐. 나머지 역할은 편집 도구가 흐리게 꺼지고(CSS) 머리 저장 상태에 ‘조회 전용’ — 띠는 없음(ERD P2-14 결정). **다만 도구에 aria-disabled가 없어 화면 낭독기는 켜진 버튼으로 읽는다.** |
| 모델 (담당 밖) | 모델러: ‘조회 전용 — 내 담당 시스템(통합ERP)에 요구사항관리가 없습니다 · [담당 시스템 추가 요청]’ 띠 — 담당 밖에서는 잘 안내됨. |
| DDL 출력 · 산출물 | **모든 역할이 같음** — 조회만 계정도 DDL · 산출물(보안 컬럼 포함)을 내려받음, 기록 없음. |
| 표준 맞추기 · DDL 가져오기 | 모델러 외 ‘조회 전용 — 모델러 역할만’. **외주 모델러(담당 통합ERP)는 첫 화면이 요구사항관리 영역으로 열려 ‘담당 시스템이 아니라 조회만’이 먼저 보임.** |
| 표준 사전 검색 · 변경 내역 | DA만 [공표]. Admin · DA: [영구 삭제 로그]. |
| 직접 등록(dict-grid) | DA · 모델러 편집. Admin · 기관 담당자 · 조회만은 모든 칸 꺼짐 + ‘읽기 전용’ 띠. |
| 도메인 그룹 | Admin · DA: [그룹 추가]. DA · 모델러: [분류 추가 신청]. **Admin은 그룹은 바로 만들지만 분류 신청은 못 함.** |
| 데이터 타입 · 축약명 | Admin · DA: [타입 등록] · 요청 탭(1). 모델러: [타입 추가 요청]. 기관 담당자 · 조회만: [타입 추가 요청] 꺼짐인데 요청 탭은 보임. |
| 후보 큐 | DA만 [반려] · [기존 표준어 사용 안내] · [단어 신청으로 전환]. |

| 엑셀 가져오기(사전) | Admin · 기관 담당자 · 조회만: ‘열람 전용 — 검증 결과 보기까지’. |

| 용어 자동분석 | 모델러 외 ‘분석만 가능’. |

## 직접 확인한 것
- 조회만(tview)으로 `model.html?area=e_hr`: `body.viewonly`, 편집 도구 opacity .35 · pointer-events none, 저장 상태 ‘조회 전용’. aria-disabled 없음. (자동 수집은 disabled 속성만 봐서 처음에 ‘켜짐’으로 잘못 읽었다.)
- 외주 모델러(tmod) 홈 · 표준 맞추기의 시스템은 통합ERP인데, 표준 맞추기 · DDL 가져오기의 기본 영역은 요구사항관리.
- 기관 담당자(town) 데이터 타입: [타입 추가 요청](`#b-req`) 꺼짐 + ‘타입 추가 요청’ 탭 보임.
