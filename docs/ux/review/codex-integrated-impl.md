# 통합 보기 구현 리뷰

브리프와 설계 28 §6·§7을 기준으로 목업 3개 파일의 작업 트리 diff와 호출 경로를 검토했다. 아래 재현 조건은 코드에서 추적했다. 브라우저 접근 오류로 1920×1080 화면, 실제 낭독·대비, 300 엔터티·500 관계의 응답 시간은 실측하지 못했다.

### IM-01 · 높음 · 자동 배치 도중 전환하면 다른 배치가 저장된다

- **근거** `docs/ux/mockups/model.html:1598`, `docs/ux/mockups/model.html:1609`, `docs/ux/mockups/model.html:281`. 통합에서 자동 배치를 승인하고 1.2초 이내 물리로 전환하면 콜백의 `setPos`가 실행 시점의 모드를 읽어 물리 좌표를 덮어쓴다. 같은 경로에서 사용자 정의 보기까지 바뀌면 다른 보기의 위치를 수정할 수 있다. 저장과 Ctrl+Z도 잘못 적용된 배치 전체를 대상으로 한다.
- **고칠 방법** 작업 시작 시 모드·보기·배율을 보존하고 해당 배치에만 적용하거나, 실행 시 달라졌으면 스냅샷을 만들기 전에 작업을 취소한다. 통합에서 실행한 자동 배치의 저장·재열기·되돌리기에서 물리 좌표가 유지되는지 확인한다.

### IM-02 · 높음 · 통합에서 논리 메모를 끌면 위치가 튄다

- **근거** `docs/ux/mockups/model.html:472`, `docs/ux/mockups/model.html:1289`, `docs/ux/mockups/model.html:1301`. 메모는 펼친 좌표에 그리지만 드래그 시작 오프셋은 저장 좌표로 계산한다. 예를 들어 논리 X가 100이고 SX가 2면 X=200에 그린 메모를 잡는 순간, 이동 핸들러는 입력 이동량이 거의 없어도 X≈100으로 다시 그린다. 틀어진 논리 좌표가 저장되며 Ctrl+Z로 되돌리기 전까지 논리 보기에도 반영된다.
- **고칠 방법** 시작 오프셋은 `memoXY`의 표시 좌표에서 구하고, 이동 목표는 같은 배율로 역변환한다. 드래그 중 보기 전환은 취소하거나 제스처 시작 기준을 유지한다.

### IM-03 · 중간 · 새 엔터티가 클릭하거나 키보드로 고른 자리에 놓이지 않는다

- **근거** `docs/ux/mockups/model.html:1330`, `docs/ux/mockups/model.html:1340`, `docs/ux/mockups/model.html:1357`. 마우스와 키보드가 넘기는 통합 표시 좌표를 `placeEntity`가 그대로 논리 좌표에 넣는다. 다음 렌더에서 배율을 한 번 더 적용하므로 클릭 자리나 키보드가 탐색한 빈자리에서 벗어난다.
- **고칠 방법** 생성 전에 통합 표시 좌표를 논리 좌표로 변환하고, 새 엔터티의 물리 초기 위치는 기존 초기화 규칙으로 결정한다. 마우스·키보드 생성, 저장 후 재열기, Ctrl+Z를 확인한다.

### IM-04 · 중간 · 펼침 배율이 현재 논리 배치의 간격을 보장하지 않는다

- **근거** `docs/ux/mockups/model.html:255`, `docs/ux/mockups/model.html:463`, `docs/ux/mockups/model.html:1598`. 분모는 마지막으로 보였던 논리 렌더의 최대 크기다. 통합에서 속성을 추가하거나 사용자 정의 보기를 바꾸면 통합 쪽만 새로 재고 이전 논리 크기를 사용한다. 영역 최대 크기의 비율과 상한만으로는 서로 가까운 노드의 간격을 보장할 수 없다. 자동 배치도 통합 노드 최대 너비 520px에 380px 열 간격을 사용한다. 재진입 가드는 동기 재귀를 한 번으로 제한하지만 배율이 바뀌는 렌더에서는 캔버스를 두 번 그리고 모든 노드 크기를 읽는다.
- **고칠 방법** 동일한 데이터와 보기의 논리·통합 크기를 측정하고 노드 간격과 비교한다. 자동 배치의 행·열 간격에는 실제 노드 크기를 반영한다. 배율 갱신은 내용·보기 변경 시에만 하고 좌표를 최종 배율로 한 번 적용한다. 300/500에서 전환·드래그·LOD 전환 시간을 기록한다(IV-03·18).

### IM-05 · 중간 · 전환 시 뷰포트 중심을 유지하지 못한다

- **근거** `docs/ux/mockups/model.html:1617`, `docs/ux/mockups/model.html:1622`. 선택이 있으면 노드의 좌상단만 보정하므로 노드 크기가 바뀌면 중심은 이동한다. 선택이 없으면 보정이 없어서 논리→통합에서 같은 화면 중심이 다른 논리 위치를 가리킨다.
- **고칠 방법** 선택이 있으면 노드 중심의 화면 좌표를, 선택이 없으면 가용 캔버스 중심의 모델 좌표를 전환 앵커로 쓴다. 최종 배율과 안내 띠를 반영한 뒤 pan을 한 번 보정한다(IV-04).

### IM-06 · 중간 · 물리 메모의 원본 좌표를 통합에 그대로 표시한다

- **근거** `docs/ux/mockups/model.html:278`, `docs/ux/mockups/model.html:472`, `docs/ux/mockups/model.html:1301`. 통합 노드는 논리 배치에서 오고 물리 메모만 물리 캔버스의 절대 좌표에서 온다. 물리 보기에서 대상 테이블 옆에 둔 메모가 통합에서는 엉뚱한 엔터티 옆에 보일 수 있다. 통합에서 이를 끌면 원래 물리 메모 배치까지 달라진다. IV-05는 출처 표시를 요구하며 좌표 변환 방식은 정하지 않았다.
- **고칠 방법** 현재처럼 연결 정보가 없는 메모는 통합에서 별도 목록에 표시하고 원래 물리 보기에서 위치를 편집하게 한다. 명시적으로 연결된 메모가 있다면 해당 통합 노드 기준으로 표시한다. 좌표만으로 연결 대상을 추측하지 않는다.

### IM-07 · 중간 · 물리 게이트를 건너뛰는 진입 경로가 있다

- **근거** `docs/ux/mockups/model.html:1629`, `docs/ux/mockups/model.html:1632`. 툴바 경유 시만 게이트가 동작한다. 첫 진입이 `?mode=P` 또는 기억한 P이면 점검 창을 열기 전에 `gateSeen`을 참으로 설정한다. 이후 통합→물리에서도 해당 세션의 첫 점검이 생략된다.
- **고칠 방법** 버튼·단축키·초기 모드 복원에 같은 진입 함수를 쓰고 P에만 점검 규칙을 적용한다. A는 점검 창 없이 열고 점검 완료 여부를 바꾸지 않는다(IV-12).

### IM-08 · 중간 · 통합 내보내기의 표제란이 초기 모드에 고정된다

- **근거** `docs/ux/mockups/model.html:33`, `docs/ux/mockups/model.html:1632`, `docs/ux/mockups/model.html:1682`, `docs/ux/mockups/model.html:1691`. 표제란을 초기화할 때 한 번 만들며 URL의 A 모드도 이후 타이머에서 적용된다. 따라서 통합 파일명을 알리는 토스트와 공식 표제란의 모드가 달라진다. 실제 파일 생성과 A3 가로·출력 범례 경로가 없어 IV-19의 결과물을 확인할 수 없다.
- **고칠 방법** 메뉴를 열 때 현재 보기에서 파일명과 표제란을 함께 계산한다. PDF·인쇄 경로에 통합 A3 가로와 세 열·미매핑 범례를 연결하고 산출물로 검증한다.

### IM-09 · 중간 · 논리명 입력 미리보기와 물리 편집 범위가 요구에 미달한다

- **근거** `docs/ux/mockups/model.html:446`, `docs/ux/mockups/model.html:452`, `docs/ux/mockups/model.html:1374`, `docs/ux/mockups/model.html:703`, `docs/ux/mockups/model.html:707`. F2가 여는 엔터티 이름 입력에는 물리명 미리보기가 없다. 속성 미리보기는 입력 옆에 붙고 기존 물리명 칸을 대체하지 않는다. 오른쪽 속성 그리드에서는 물리명과 타입이 보조 텍스트로 묶여 있으며 도메인만 바꿀 수 있다.
- **고칠 방법** 엔터티·속성의 기존 변환 규칙을 각각 재사용해 물리명 위치에서 입력 결과를 보여 준다. 그리드에 논리·물리 머리글을 붙이고 물리명과 타입의 편집 위치 및 잠금 상태를 드러낸다(IV-06~08).

### IM-10 · 중간 · 물리명으로 찾으면 결과 건수와 바꾸기 대상이 어긋난다

- **근거** `docs/ux/mockups/model.html:1038`, `docs/ux/mockups/model.html:1044`, `docs/ux/mockups/model.html:1050`, `docs/ux/mockups/model.html:1085`. 물리명으로만 일치한 행이 표에는 뜨지만 ‘보이는 행 0건’으로 표시된다. 바꾸기는 논리명만 검사하며 현재 페이지의 300행 범위도 적용하지 않는다.
- **고칠 방법** 찾기 건수는 양쪽 이름으로 일치한 결과에서 계산한다. 바꾸기의 범위와 버튼 문구는 논리명 및 실제 표시 행에 맞춘다.

### IM-11 · 중간 · 속성 낭독과 1920 화면에서 세 열을 따라가기 어렵다

- **근거** `docs/ux/mockups/model.html:449`, `docs/ux/mockups/model.html:497`, `docs/ux/mockups/assets/model.css:267`, `docs/ux/mockups/assets/app.js:1664`, `docs/ux/mockups/assets/app.js:1825`. PK는 논리명 앞의 # 기호로만 나오고, 속성 물리명에는 구분 낭독이 없다. 트리는 통합에서도 전체를 ‘논리’로 안내하며 속성 항목 이름에서 물리명과 타입이 빠진다. 캔버스의 물리명 시작점은 행별 내용과 자동 여백에 좌우되어 긴 논리명·상태 배지·타입이 섞이면 열을 비교하기 어렵다.
- **고칠 방법** 시각 열 시작점을 맞추고 긴 값의 전체 이름을 키보드로도 확인할 수 있게 한다. 접근성 트리에서 ‘논리명, 물리 물리명, 타입, PK’ 순서를 제공하고 트리 보기 이름에도 ‘통합’을 적용한다. 1920×1080에서 양쪽 패널과 배너를 연 상태로 긴 이름·타입, 확대 단계, 경고 텍스트 대비를 확인한다(IV-17).

### IM-12 · 낮음 · 동기화 띠와 행별 반영 상태가 연결되지 않는다

- **근거** `docs/ux/mockups/model.html:102`, `docs/ux/mockups/model.html:448`, `docs/ux/mockups/model.html:1621`. 브리프에 명시된 잔여 항목이다. 통합에서 고정 ‘2건 대기’ 띠를 볼 수 있지만 어느 속성이 대기 중인지 확인할 수 없다.
- **고칠 방법** 목업용 대기 항목에 속성 식별자와 변경 전후 물리명을 두고 같은 목록에서 띠의 건수와 행별 표시를 만든다(IV-09).

### IM-13 · 중간 · 시스템 전체 보기에서 모드 전환이 중간에 실패한다

- **근거** `docs/ux/mockups/model.html:1618`, `docs/ux/mockups/model.html:1620`, `docs/ux/mockups/model.html:1626`, `docs/ux/mockups/model.html:1704`. 시스템 전체 보기가 범례 내용을 통째로 교체해 `lg-int`를 제거한다. 이 상태에서 Alt+1/2/3으로 모드를 바꾸면 `lg-int.hidden`에서 예외가 나며 모드·버튼·저장값만 먼저 변경될 수 있다. 시스템 전체에서 돌아올 때도 최초 캐시의 범례가 복원된다.
- **고칠 방법** 시스템 전체에서는 모드 단축키와 전환 컨트롤을 잠그고, 영역 보기 복귀 시 현재 모드로 범례 가시성을 다시 적용한다.

### IM-14 · 낮음 · 물리 보기에도 통합용 미매핑 배지가 추가된다

- **근거** `docs/ux/mockups/model.html:460`, `docs/ux/mockups/assets/model.css:45`. 배지 조건이 `mode !== 'L'`이라 기존 물리 제목에도 미매핑 배지가 추가된다. 배지가 폭을 차지하면 함께 표시되는 논리 엔터티명이 더 빨리 잘린다.
- **고칠 방법** 통합 노드의 미매핑 배지를 `mode === 'A'`로 제한하고 물리 보기의 기존 제목 밀도를 유지한다.
