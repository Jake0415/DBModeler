# 리뷰 요청 — 엑셀로 ERD 시작하기(26) 목업

## 대상
- 기준 문서: `docs/ux/26-erd-excel-import.md`. 결정은 §6에 있다.
  - 병합이 기본이다.
  - 참조 오류는 SWS처럼 막는다.
  - 관계명 열은 두지 않는다. ERD에서 사용자가 입력한다.
  - 다른 영역 참조는 미리보기에서 고른다.
  - 용어는 ‘필수’로 쓴다.
- 새 화면: `docs/ux/mockups/import-excel.html` — http://localhost:5178/import-excel.html?area=e_hr&as=kim
  - 4단계: 파일 → 검사 · 미리보기 → 가져올 위치 → 완료.
  - SheetJS로 실제 `.xlsx`를 읽고 쓴다(양식 내려받기, 검사 결과 엑셀).
  - 파일 없이 시험할 수 있는 예시 3개가 있다(정상 · 오류 · 다른 영역 참조).
- 진입점
  - 모델 ⋯ 메뉴 [엑셀로 가져오기]
  - 트리 아래 링크
  - `import.html`의 [엑셀 정의서]
  - 시스템 홈 새 영역 창의 [엑셀로 만들기]
- 비교 기준: 표준 사전 엑셀 가져오기 `excel-import.html`, DDL 가져오기 `import.html`, [18 관계 시나리오](../18-relation-scenario.md).
- SWS 참고(코드 공유 없음): `D:\project\sws-data-governance\backend\app\services\modeling_excel\`(parser · validation · template).

## 검토 요청
1. **검사 규칙** — 26 §3과 SWS 파서에 비추어 빠지거나 틀린 검사가 있는가.
   - 중복 · 논리명 불일치 · 참조(없음 · PK 아님 · 타입) · 예전 양식(‘NULL 허용 여부’ 반대 의미) · 이어받기
   - 경고(PK 없음 · 길이 · 매핑에 없는 타입 · 이름 길이 · 예약어)
2. **관계 만들기** — 26 §4와 18의 결과가 같은가.
   - 같은 자식 → 부모 묶음, 두 번째 관계(같은 부모 컬럼이 다시 나오면 새 관계), 식별 · 비식별, 선택성, 재귀
   - 복합 PK 일부 참조, 다른 영역 참조 엔터티(확정본 사본 · 끄면 일반 컬럼)
3. **병합 · 덮어쓰기** — 아래가 안전하고 이해되는가.
   - 같은 물리명 매칭, 컬럼 값 충돌 선택, 엑셀에 없는 테이블 보존(병합) · 제거(덮어쓰기, 두 번 확인)
   - 기존 관계 중복 방지, 위치 배치, 저장 실패 처리, [가져오기 취소]
4. **사용자 흐름 · 문구** — 단계 이동, 오류일 때 다음 행동(검사 결과 엑셀), 완료 뒤 다음 순서 안내, 권한 · 잠금 막힘 이유.
5. **접근성** — 끌어 놓기 영역의 키보드, 탭 · 표, 단계 표시, 포커스 이동.
6. 개선점은 번호 · 심각도(높음/중간/낮음) · 근거(파일:줄) · 제안으로 쓰고, 우선순위 순으로 정리하라. 고칠 필요가 없는 것은 ‘유지’로 적어라.
