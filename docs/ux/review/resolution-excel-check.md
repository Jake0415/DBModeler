## 구현 단계로 넘기는 것 (목업 범위 밖)

- 결과 · 미리보기 표 가상화와 입력 갱신 빈도 제한(CL-13 · CX-11). 설계 23 §6-3 그대로입니다.
- 실제 XLSX 생성(셀 메모 · 가이드 시트 · 보호 열)(CX-05). 목업은 CSV로 내용과 열 구성만 보여 줍니다.
- 서버 기준본 검증 · 파일 교체 시 새 묶음 강제(CX-06), 열 매핑 '가져오지 않음' 처리 · 필수 열 누락 복구(CX-12).

## 처리 결과

파일은 모두 `docs/ux/mockups/excel-import.html`입니다(줄 번호는 수정 뒤 기준). 공용 `app.js` · `app.css`는 고치지 않았습니다.

- **E-01** — 재판정 함수 `rejudge()` 하나로 모았습니다(:267–359). 결재 재검사(`checkDictDoc`)와 공용 검사(`checkItem`: 칸 · 경고 · 같은 파일 행)를 함께 쓰고, 용어는 이름이 사전 값과 다르면 다시 분해합니다(미등록 → 오류, 승인 전 단어 → 선행 승인, 변경 행은 약어 변경까지 기록). 이 함수를 쓰는 곳은 시드(:417), 칸 입력(`commitCell` :666), 제안 적용(`fixRow` :649), 자동 수정(:746–), 찾아 바꾸기(:780 · :826), 다시 검증입니다. 미리보기는 `simRow`(:344)로 복사본을 판정합니다. 자동 수정 창에 '검사' 열을 넣고(:196 · :751), 통과하지 못하는 행은 처음에 고르지 않습니다. 수정 제안 카드에도 검사 결과를 보여 줍니다(:592–). 신청 직전 재검사에서 막힌 항목은 해당 행을 오류로 돌리고 5단계를 엽니다(:946).
- **E-02** — 예시 행을 공통표준 전체 적재 기준으로 바꿨습니다(:235–, :361–). 단어: 검수 → 검측, 납품 → 인도물(제안 DVITM), 정비 → 검교정(제안 CLVRF), 수령자 → 품질검토(REQ-2026-0014, 같은 내용 결재 중), 점검 → 수검, 완화 약어 MTGT → MITG. 용어: 수령자명 → 품질검토일자(선행 승인), 검사결과내용 → 검사결과의견내용(후보 선택). 변경 행 T-0412는 T-0425로 바꿨습니다. T-0388은 시드 그대로 '변경'으로 둡니다. 시험 중 만든 품의가 이 항목을 처리 중이면, 그때는 `rejudge`가 '다른 내용 결재 중'으로 판정합니다(시드 문서가 아닌 품의에 기대지 않도록 조정자가 되돌림). 도메인: 코드C3 → 코드C6, 번호V5 → 번호V7. 시드의 신규 · 변경 행은 `rejudge`를 거칩니다(:417).
- **E-03** — 라벨이 붙은 작업 기록을 넣었습니다(`pushUndo` · `undo` :632–). 도구 줄에 [되돌리기 (n)]과 '마지막 작업' 표시를 두고(:562–), Ctrl+Z를 연결했습니다(:696, 입력 칸 · 창이 열려 있으면 동작 안 함). '방금 바꾼 행만' 칩을 두었고, 일괄 작업 뒤에는 자동으로 켭니다. 알림의 [실행 취소]도 같은 기록을 씁니다. 뒤에 작업이 더 있으면 몇 개인지 알려 줍니다.
- **E-04** — `isKey`(:779)를 두었습니다. 사전에 있는 코드값(동일 · 변경 행)과 항목 ID가 있는 행의 이름은 찾아 바꾸기 미리보기에 '건너뜀 · 짝짓기 키라 바꾸지 않음'으로 나오고, 창 안내 문구에도 적었습니다.
- **E-05** — 보정본에 파일의 모든 행을 넣었습니다(범위 밖은 `outRows` :460, 빠짐 행 포함, 상태 열로 구분). 원래 열 순서 뒤에 숨김 열(항목 ID · 버전 · 기준본)과 변경점 열을 붙였습니다(:721–). 버튼 title과 알림에 'CSV · 목업, 실제는 XLSX(본문 + 변경점 시트 · 텍스트 서식)'를 적었습니다. 오류 가이드 버튼에 '전체 n행'을 표시하고, '확인 필요' 행(경고 · 후보 · 보류 · 충돌)과 '항목 ID(숨김 열)' 라벨을 추가했습니다.
- **E-06** — 행 패널 값 비교를 현재 사전 · 파일 원본 · 보정 값 세 칸으로 나눴습니다. 보정한 칸은 강조하고, 패널 폭에 맞게 줄바꿈합니다(:592, 스타일 :58–).
- **E-07** — 고칠 때마다 하단 안내를 다시 그립니다(`drawHint` :897). 오류 바에 '처음 오류 n →'을 붙였고, 오류가 없으면 실제 남은 확인 수(`leftText` :559)를 보여 줍니다. 칸 입력 실패는 붉은 알림 대신 칸과 `#cellmsg`(:153)에 표시합니다.
- **E-08** — 실패한 입력은 칸에 남기고(붉은 칸 · aria-invalid · 사유) 저장하지 않습니다. Enter를 누르면 포커스가 칸에 남고, Esc를 누르면 파일 값으로 돌아갑니다. 빈 값도 실패로 봅니다(`commitCell` :665–).
- **E-09** — 권한이 없거나 남의 묶음일 때 그 이유(`roReason` :473)를 1단계부터 띠로 보여 줍니다(:482). 5단계 고치기 도구는 aria-disabled와 이유 title로 막고, 하단 안내와 행 패널에도 이유를 적습니다.
- **E-10** — 6단계가 아닐 때는 `.needs-msg[data-btn="next"]`를 지웁니다(:915).
- **E-11** — 6단계 요약을 신청 대상 · 미사용 · 보류 · 오류로 제외 · 후보 미선택 · 변경 없음으로 나눴습니다(`plan` :871, `drawSubmit` :881). 코드값은 행 수와 결재 항목(코드 그룹) 수를 요약과 [신청] 버튼에 함께 보여 줍니다.
- **E-12** — `derive()`(:342)가 분류 · 타입 · 길이 중 하나만 바뀌어도 도메인명을 다시 계산합니다. 찾아 바꾸기 미리보기에 '도메인명(계산)' 파생 행과 '도메인명 n칸이 따라 바뀝니다'를 표시합니다(:797).
- **E-13** — 상태 칩 · 규칙 버튼 · 자동 수정 규칙 칩을 누르면 다시 그린 뒤에도 같은 버튼에 포커스가 남습니다(:700, `drawAuto` 클릭 처리). 편집 칸이 없는 오류에서는 F8이 패널의 조치 버튼([ID 지우고 새 항목으로] 등)으로 갑니다(:691).
- **E-14** — 찾아 바꾸기 창을 열 때 바로(동기로) 포커스를 줍니다. Ctrl+H 직후 친 글자가 찾을 값에 들어가는 것을 확인했습니다. 다시 열어도 칸 선택을 유지하고(`frColLast` :801), 미리보기 위에 '범위: … 칸 · 일치 방식 · 대소문자' 요약 줄을 둡니다.
- **E-15** — '약어은'을 `josa()`로 고쳤습니다. 바뀐 칸의 옛 값은 aria-hidden으로 두고 '파일 값 … , 고친 값' 숨김 텍스트를 넣었습니다. 3단계 '미사용 열' 배지를 '확인 필요'로 통일했습니다. '사유 · 규칙' 열은 한 줄 말줄임 + title로 바꿨습니다. 5단계에서는 알림을 행 패널 왼쪽에 띄웁니다(`.x5 .toasts` :73). '같은 내용 결재 중' · '다른 내용 결재 중'으로 용어를 맞췄고, 1단계 계산 값 안내 범위를 고쳤습니다(:117). 범위 안내의 인라인 style은 클래스로 옮겼습니다.
