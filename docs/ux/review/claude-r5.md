## 1. 총평 (5줄)

1. 방향은 옳다. "엑셀이 원본"이라는 업무 현실을 처음으로 정면에서 다뤘고, 편집용 내려받기·차이 비교·3방향 충돌·보정본·이력·검색까지 반복 주기 ①~⑥을 한 번에 엮었다(07:13, 07:35~106).
2. 그러나 **주기의 끝이 열려 있다** — 반려·회수 후 돌아가는 길, 한 파일 안의 단어→용어 의존, 결재 대기로 "제외"된 사용자의 수정이 사라지는 길이 정의되지 않아 엑셀 원본과 시스템이 다시 어긋난다.
3. **설계 문서와 충돌하는 곳이 5군데 이상** 있다: MD-08 ⛔ 완화(07:63 ↔ 30:96), 5색 체계 확장(07:51~60 ↔ 30:96), 삭제 신청 W1 노출(07:60 ↔ 30:187 삭제=W2), ⚠ 상태와 MD-09 후보 선택 누락(07:51~60 ↔ 30:154, 30:97), 제정차수를 사전 단위로만 표현(07:90 ↔ 30:62·65·66 항목 속성).
4. 엑셀 고유 위험(숨김 열 훼손·행 복사로 ID 중복·앞자리 0·빈 칸의 뜻·여러 값 칸 순서)이 거의 다뤄지지 않았다. 차이 비교는 "빈 칸 = 지움인가 그대로인가" 하나만 틀려도 대량 오변경을 만든다.
5. v5 근본 원인 중 R2(문서·묶음 신원)·R3(보이는 행만)·R4(한 판정·한 숫자)·R6(작업 단위 취소)이 이 기능에서 그대로 재발할 구조다. 현재 목업도 업로드 묶음 하나의 숫자가 화면마다 다르다(120/112, 파일명 1차/2차). **"업로드 묶음(Batch)"을 공통 상태 계층의 1급 객체로** 두는 것이 이 플랜의 성패를 가른다.

## 3. 열린 질문 권고안

### Q1. 파일에서 빠진 행의 기본 처리 → **'무시'(기본) 유지, 행 삭제로는 미사용 신청을 만들지 않음**
- 근거 ① 빠짐의 원인 대부분은 의도가 아니다: 필터 내려받기, 회의용으로 행을 지운 사본, 시트 분할, 정렬 중 실수(07:37, 07:60). ② 미사용은 MD-11에서 사용 중 하위가 있으면 ⛔이고(30:99), 승인되면 모델 컬럼이 '미승인·미사용' 판정(30:139)으로 대량 미준수가 된다 — 실수 한 번의 비용이 너무 크다. ③ 의도가 있는 미사용은 이미 **사용상태 열(선택 목록)**이라는 명시적 통로가 있다(07:40, MD-12 30:100).
- 그래서: 빠짐은 기본 '무시', 체크로만 '미사용 신청' 선택(대상 건수·영향 표시, 사유 필수). 삭제 신청은 W2(CL5-16). 서버 내려받기 기록과 연결되지 않은 파일은 빠짐 판정 자체를 끈다(CL5-11).

### Q2. 업로드 1회의 결재 문서 수 → **묶음 1개 · 결재 문서는 종류별로 분리(코드값은 코드 그룹별), 문서당 행 상한**
- 근거 ① MD-20은 매 단계 재검사 실패 시 그 단계 승인을 통째로 취소(30:106), MD-31은 코드값 하나라도 충돌하면 전체 중단(30:120) — 혼합 대형 문서는 한 행 때문에 전부 멈춘다. ② DA는 단어(약어 체계)와 용어(조합 결과)를 다른 관점으로 검토한다. ③ 코드값은 MD-31이 이미 "같은 코드의 코드값 = 1건 품의"로 단위를 정했다.
- 그래서: 업로드 1회 = **묶음 ID 1개**(업로드 이력·알림·반영본의 단위), 그 아래 결재 문서는 단어 / 도메인 / 용어 / 코드(그룹별)로 생성하고 결재함에서 묶음으로 함께 보인다. 같은 묶음의 선행 문서(단어)가 승인돼야 후행(용어)이 재검사를 통과하는 의존 표시(CL5-02). 문서당 상한(예 1,000행)을 넘으면 자동 분할. 신규·변경·미사용은 한 문서 안에서 섞어도 된다(동작 열로 구분).
- 대안(소규모 기관): 기관 설정 "업로드 1회 = 문서 1건"을 허용하되 기본은 꺼짐.

### Q3. 초성·과거 이름 검색의 범위 → **초성: 공통 포함 / 과거 이름: 기관 전체 + 공통은 '적재 차수 간 변경'만(후속)**
- 근거 ① 사용자는 기관 고유어를 만들기 전에 공통표준에서 먼저 찾아야 한다(00:53, 공통 우선 해석 30:38). 초성 검색에서 공통을 빼면 중복 등록을 유도한다. 초성은 현재 값 색인이라 비용이 작다. ② 공통 세트는 읽기 전용 시드라 시스템 안의 승인 이력이 없다. 과거 이름은 시드 재적재(2025.11 → 다음 판) 차분이 있어야만 의미가 있다(30:193 원본 폐기 행은 미사용 보존).
- 그래서: W1 = 초성(공통+기관), 과거 이름(기관 History). 공통의 과거 이름은 시드 재적재 차분 보관이 정해진 뒤(W2). 결과에서 출처 배지로 구분.

### Q4. 제정차수를 언제 올리나 → **DA의 명시적 '공표' 동작으로 올림(결재 반영마다 아님)**
- 근거 ① 30은 제정차수를 "시스템 버전과 별개인 원문 메타데이터"로 정의(30:78) — 결재 반영마다 올리면 항목 버전(V)과 같은 것이 되어 별개일 이유가 사라진다. ② 공공기관 표준사전의 '차수'는 공식 공표·배포 단위로 쓰인다(07:90 "공식 공표 단위"). ③ 07 E5 자체가 세 층을 "이름과 자리를 다르게" 두는 원칙(07:84).
- 그래서: SC-16(또는 사전 헤더)에 DA 전용 **[공표]**: 지난 공표 이후 승인된 변경 목록 확인 → 차수 +1 → 그 시각을 이름 붙은 기준 시각으로 기록 → 이번 차수에 바뀐 항목의 **항목 제정차수**를 갱신(30:62·65·66 속성과 정합). 공표는 결재가 아니라 이름표이므로 Q-7(불변 개정 묶음 미채택, 30:79)과 충돌하지 않게 "as-of 시각 + 라벨"로만 저장(CL5-27). 공표 시 '사전 변경 내역 보고서'를 자동 생성해 산출물 표지(06:166)와 연결.

12. **공표(제정차수) 동작**과 as-of 기준 시각 비교(Q4, CL5-27).
13. **권한·감사** — 업로드 가능 역할(모델러·DA), 묶음 편집은 소유자만, 내려받기·업로드 감사 기록, 원본 파일 보관 기간(CL5-32).
