# Codex 리뷰 — 바로잡기(25) 남은 네 가지

검토 기준은 커밋 `8a95d24`와 [25 §8](../25-correction-flows.md#8-남은-네-가지-반영-2026-11-24)이다. 근거 경로는 저장소 루트 기준이다. 정적 검토와 Node에서 추출한 원본 함수 실행으로 확인했다. 브라우저에서의 화면 조작과 스크린리더 실측은 수행하지 않았다.

### CQ-01 — 결재와 모델 권한에 시스템 이름이 여전히 쓰인다

- **심각도** · 높음
- **근거** · `docs/ux/mockups/assets/app.js:90–109,163,180–185,1065–1069`, `docs/ux/mockups/model.html:986`, `docs/ux/mockups/import.html:80`, `docs/ux/mockups/home.html:78–89`, `docs/ux/mockups/settings.html:293–300,313–320`. 결재는 사본에 저장된 `sysAt.code`를 건너뛰고 제출 당시 이름인 `d.sys`를 우선한다. 이름을 바꾸면 담당자가 결재 문서를 보거나 처리하지 못할 수 있고, 이전 이름을 다른 시스템이 쓰면 그 시스템의 담당자가 결재선으로 판정될 수 있다. 모델·홈·가져오기도 이름을 넘긴다. 등록 규칙은 다른 시스템 코드와 동일한 이름을 허용하고, `sysCodeOf`는 코드를 먼저 찾으므로 이때 범위가 다른 시스템으로 해석된다. Node에서 이름 변경 및 이름·코드 충돌 조건의 판정 실패를 재현했다.
- **제안** · 영역의 시스템 코드, 가져오기의 `curSys().code`, 결재의 `sysAt.code`를 각 권한 호출에 전달한다. 코드가 없는 구형 문서는 영역 코드 등 확인 가능한 식별자를 우선하고, 이름은 출처를 확인할 수 있는 이관 경로에서만 해석한다.

### CQ-02 — 일괄 처리에서 저장 실패를 성공으로 집계한다

- **심각도** · 높음
- **근거** · `docs/ux/mockups/assets/app.js:8–11,194–198,232,258–284`, `docs/ux/mockups/system.html:203–215`. 저장소 용량 초과나 차단 시 저장 함수는 `false`를 반환한다. 이동은 구조 저장과 시스템 변경의 반환값을 확인하지 않고, 복제는 영역 등록·구조 저장을 확인하지 않은 채 새 ID를 반환한다. 뒤이어 원본 사용 중지를 실행할 수 있다. 사용 중지나 참조 다시 잇기의 저장 결과도 성공 문구에 반영되지 않는다. 처리 중 예외가 발생하면 앞서 저장한 영역은 남고 나머지 처리와 결과 표시는 중단된다.
- **제안** · 복제본의 영역·구조 저장이 확인된 뒤에만 원본을 사용 중지한다. 영역별 저장 단계와 실패를 반환하고, 부분 저장은 되돌리거나 재개할 수 있게 한다. 실제 완료·실패·건너뜀을 결과와 감사 로그에 표시한다.

### CQ-03 — 참조 다시 잇기가 결재 잠금과 확정 버전을 건너뛴다

- **심각도** · 높음
- **근거** · `docs/ux/mockups/assets/app.js:196–198,263–284,1072,1082`, `docs/ux/mockups/model.html:2169–2179`, `docs/ux/mockups/system.html:202–210`. 일괄 실행 뒤 다시 잇기는 대상 시스템의 모든 활성 영역을 훑는다. 이번 실행과 무관하거나 결재·확정 상태인 영역도 현재 버전의 저장 데이터를 바꿀 수 있다. 결재 중인 영역은 화면에서 제출 사본을 보므로 저장 구조와 화면이 갈라진다. 복제 대상은 확정본 없는 v1인데 참조는 `refArea`와 `refName`만 바꿔 원래의 `refVer`를 유지한다. 비교도 `refVer`만 확인해 대상 변경을 놓친다. 순환 참조는 실행 예정 집합을 기준으로 보존하므로 예정된 영역이 실패하면 원래 시스템을 가리킬 수 있다. 같은 원본의 활성 복제본이 여럿이면 마지막 항목이 선택된다.
- **제안** · 현재 실행에서 실제로 성공한 영역의 원본→대상 ID 대응표로 이번에 옮기거나 만든 작업본만 갱신한다. 대상 엔터티·버전과 편집 상태를 확인하고, 확정본을 기다리는 참조와 실패·충돌로 연결할 수 없는 참조를 결과에 명시한다. 비교에 참조 대상의 변경도 포함한다.

### CQ-04 — 빈 매핑과 잘못된 매핑이 컬럼 타입을 손상시킨다

- **심각도** · 높음
- **근거** · `docs/ux/mockups/settings.html:279,404–408,428`, `docs/ux/mockups/assets/app.js:248–256`. 설정은 입력을 잘라 그대로 보관하며 행별 타입 검증이 없다. 대상 가변 문자 칸을 비우면 `VARCHAR2(40)`이 빈 문자열로 바뀐다. Node에서 재현했다. 괄호 없는 대상은 원본 길이·정밀도를 버리고, 중복 물리 타입은 첫 행에 매칭된다. 배열 길이만 맞으면 잘못된 값도 읽어 들이며, 미리 보기 함수는 변환 예외를 0건으로 표시한다.
- **제안** · 저장 전 빈 칸·DBMS별 타입 구문·인자·행 모호성을 검증하고 첫 오류 셀에 포커스를 둔다. 기존 저장값도 변환 전에 검증하고, 원본 인자를 유지할 수 없는 경우 해당 속성을 미리 보기에 표시해 처리 전에 해결하게 한다.

### CQ-05 — 다음 작업 버전이 이전 이동을 다시 사용한다

- **심각도** · 중간
- **근거** · `docs/ux/mockups/assets/app.js:303–309,1075–1082`, `docs/ux/mockups/model.html:986,1689,2265–2277`. 다음 작업 버전은 직전 확정 사본의 `moves`를 그대로 복사한다. 이후 동일 ID가 다시 나타났다가 삭제되거나 다시 이동하면 비교가 첫 이동 기록을 골라 오래된 목적지를 표시할 수 있다. 새로 나타난 엔터티 쪽도 이전의 `movedFrom`만으로 이동 판정을 내릴 수 있다. 구형 사본의 전역 로그 조회는 출발 영역이나 비교 시점을 확인하지 않으므로 나중에 발생한 이동이 이전 비교에 들어갈 수 있다.
- **제안** · 확정 사본의 로그는 고정하고 새 작업 버전은 빈 이동 목록으로 시작한다. 비교는 해당 구간·방향의 실제 이동 이벤트를 사용하고, 구형 전역 기록은 출발 영역과 시점을 확인할 수 있을 때만 적용한다.

### CQ-06 — 기존 담당 시스템 이관과 계정 편집에서 할당이 사라질 수 있다

- **심각도** · 중간
- **근거** · `docs/ux/mockups/assets/app.js:46,180–186`, `docs/ux/mockups/settings.html:442,507,549–564`. 페이지 초기화에서 기존 이름을 코드 우선 조회로 바꿔 사용자 목록 전체를 저장한다. 기존 이름이 다른 시스템의 코드와 같으면 잘못된 코드가 저장되고, 이름 변경으로 매칭할 수 없는 값은 해소 없이 남는다. 계정 편집은 활성 시스템만 체크박스로 만들고 저장 시 체크된 값 전체로 교체한다. 다른 사람의 연락처만 고쳐도 기존 보관 시스템 할당이 빠지고 세션이 해지될 수 있다. 등록은 보관 시스템까지 포함해 이름 중복을 막지만 이름 수정은 최신 목록에 쓰는 시점에 다시 검사하지 않는다(`settings.html:294–300,313–320`).
- **제안** · 구형 할당만 이관한다는 표시를 두고, 이름과 코드가 충돌하거나 해석되지 않는 값은 확인 대상으로 남긴다. 최신 사용자 데이터를 기준으로 이관하고 저장 성공을 확인한다. 계정 편집에서는 기존 보관 할당을 표시하거나 명시적으로 제거할 때까지 보존하고, 이름 중복은 최신 목록에 쓰기 직전에 다시 검사한다.

### CQ-07 — 일괄 미리 보기와 결과로 다음 행동을 정하기 어렵다

- **심각도** · 중간
- **근거** · `docs/ux/mockups/system.html:48–54,193–215`. 결재 이력만 있어 복제하는 영역도 ‘복제(확정본 있음)’으로 표시된다. 참조 열은 대상 영역 수만 보여 주어 이어질 참조와 제외될 참조를 구별하기 어렵다. 이름 충돌은 건너뜀으로 표시하지만 충돌 영역이나 다음 조치로 연결되지 않는다. 남은 활성 영역이 하나라도 있으면 성공한 복제본이나 대상 시스템으로 이동할 링크도 사라진다. 처음 화면의 ‘모든 영역’은 보관 영역을 포함하지 않는다(`assets/app.js:190`).
- **제안** · 복제·건너뜀 사유를 실제 조건에 맞게 표시하고, 참조 결과와 충돌 대상을 미리 보여 준다. 부분 성공 시에도 대상 시스템 링크를 제공하고 남은 영역을 해당 조치로 연결한다. 작업 범위를 ‘사용 중인 영역’으로 안내한다.

### CQ-08 — 매핑 표에서 적용 시스템과 DBMS별 조건이 불명확하다

- **심각도** · 낮음
- **근거** · `docs/ux/mockups/settings.html:107–112,266–280,388`. 시스템을 바꾸면 값과 DBMS 열 머리글은 바뀌지만 Oracle 기준 길이와 비고는 고정이다. 같은 DBMS를 쓰는 두 시스템을 전환하면 표 머리글만으로 현재 편집 중인 시스템을 식별하기 어렵다. 변경 보기에는 시스템 이름이 표시된다.
- **제안** · 표 제목에 선택한 시스템 이름과 코드를 표시한다. 길이·비고는 현재 DBMS에 맞게 표시하고, 해당 조건이 없는 경우에는 생략한다.

### CQ-09 — 일괄 처리 완료 후 결과가 키보드 포커스에 연결되지 않는다

- **심각도** · 낮음
- **근거** · `docs/ux/mockups/system.html:48–54,198–215`, `docs/ux/mockups/assets/app.js:2361–2362,2396–2402`. 창을 열 때는 대상 선택으로 포커스를 옮기지만, 완료 시 포커스가 있던 실행 버튼을 숨기고 결과를 삽입한다. 결과에 포커스나 상태 알림을 주지 않아 완료 및 다음 링크가 즉시 전달되지 않는다. 결과에서 [닫기]는 새로고침하지만 Escape는 공용 닫기만 실행하므로 갱신 전 목록이 남을 수 있다.
- **제안** · 결과 요약을 알림으로 제공하거나 결과 제목으로 포커스를 옮긴다. 완료 후 Escape와 [닫기]에서 같은 목록 갱신·포커스 복귀 처리를 사용한다.

### CQ-10 — 유지 · 기본 권한과 입력 조작

- **심각도** · 유지
- **근거** · `docs/ux/mockups/settings.html:108–112,241,279–280,301,378,388,404–405`, `docs/ux/mockups/system.html:48–54,191,198–201`, `docs/ux/mockups/assets/app.js:85–87,213–219,2361–2362,2396–2402`. 일괄 작업은 관리자 권한을 화면과 실행 시에 확인하며, 영역 작업은 결재 진행 여부를 다시 확인한다. 설정은 관리자만 진입하며 매핑의 기본값·변경 보기·되돌리기가 연결되어 있다. 입력에 접근 가능한 이름이 있고, 대화상자는 네이티브 입력·버튼, 제목 연결, 초기 포커스, Tab 순환과 Escape를 제공한다.
- **제안** · 이 동작을 유지한다.
