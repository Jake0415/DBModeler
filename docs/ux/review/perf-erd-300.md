# ERD 화면 속도 측정 — 300 엔터티 · 500 관계 (2026-11-24)

- 목표(03 · ERD 리뷰 P2-18): 300 엔터티 · 500 관계에서 이동 · 확대 · 끌기는 **한 프레임 16ms 안**(60fps), 클릭 · 편집 반응은 **100ms 안**.
- 측정 모델: `model.html?area=rq&perf=300&rels=500` — 엔터티 300(속성 8개씩, 관계 FK 포함 2,900행) · 관계 500, 편집은 메모리에서만(저장 안 함). 측정 훅 `window.__perf`(이 모드에서만).
- 환경: 1600×900, 앱 안 브라우저(Chromium). 측정 중 다른 프로그램이 CPU를 100%까지 쓰는 구간이 있어, 같은 동작을 5~15번 재서 **최솟값 · 중앙값**을 보고 CPU 기준 루프(3천만 회 더하기)가 평소 값(약 20~30ms)일 때의 수치만 썼다.
- 한계: 앱 안 브라우저 창이 숨겨진 상태라 requestAnimationFrame이 멈춰 **실제 프레임 간격(fps)은 재지 못했다** — 각 동작의 처리 시간(그 프레임에 들어가는 일)을 쟀다.

## 남은 것 · 구현 단계 메모
- 실제 fps(창이 보이는 상태)는 구현 단계에서 브라우저 성능 도구로 다시 잰다. 처리 시간이 프레임 예산의 1/4 수준이라 여유가 있다.
- 논리 ↔ 물리 전환 · 표 보기 행 추가처럼 화면 전체가 바뀌는 1회성 동작은 200~350ms — 필요하면 구현 단계에서 화면 밖 노드 지연 그리기(가상화)를 검토한다.
- 엔터티 300개는 업무 영역 권장 상한(23 §6-2)이며, 넘으면 안내 띠가 뜬다.
