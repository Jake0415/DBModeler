# D6 확인 검토: Claude (개선 #1~#7 적용분)

> 대상: 작업 사본 18개 파일(10-design-improvements.md 적용 기록 #1~#7)
> 방법: 코드만 읽고 판단했다(브라우저 없음). 등급은 상(기능 고장·눈에 띄는 깨짐), 중(의도와 다르게 동작하거나 접근성·일관성 문제), 하(다듬기)다.

## 총평

일곱 가지 개선은 모두 의도한 방향으로 들어갔다. 상 등급은 없다.
- **#1 사전**: 도구 줄이 `검색 + 도움말 + 종류 구간 선택 + 필터(개수)`로 줄었다. 상세 패널은 행을 고를 때만 열린다.
- **#2 결재**: 처리하면 다음 문서가 열린다. J/K/A/R 단축키는 입력 칸·대화상자·Ctrl 조합에서 막혀 있다. 탭은 `role=tab`과 `aria-selected`를 갖췄다.
- **#3·#4 모델**: 보기 전환(`aria-pressed`)과 ⋯ 메뉴가 생겼다. "미준수 N건 해결" 버튼은 주 버튼이면서 `aria-disabled`를 떼도록 처리됐고, 표준 맞추기 줄의 버튼은 보조로 내렸다. 배너는 우선순위 순으로 한 자리에 두고 "안내 N건 더"로 접는다.
- **#5 엑셀**: 폭 960 고정(`!important`), 아래 동작 줄, 단계별 버튼 이름("파일 올리기", "검증 시작"…)이 들어갔다.
- **#6 머리줄**: 경로 / 제목 / 배지 1개 구조가 전 화면에 퍼졌다.

남은 문제는 네 가지다.
- 결재 되돌리기의 범위와 토스트가 두 개 뜨는 것.
- 목록 뼈대가 모든 목록 화면에 들어갈 때마다 깜빡이는 것.
- 처리 중 버튼이 키보드로 두 번 눌리는 것.
- 한 글자 단축키를 끌 수 없는 것.

**하 (5개)**
- `model.html:157-166`: ⋯ 메뉴에 "이미지로 내보내기"가 있는데 머리줄에 `내보내기 ▾` 버튼도 남아 있어 같은 기능으로 가는 길이 둘이다. ⋯ 버튼과 `▾`는 글자 기호다. 머리줄 버튼을 지우거나 ⋯ 항목을 지우고, `icon('down')`과 `more` 아이콘(Lucide ellipsis)을 쓴다. dictionary `내려받기 ▾`도 같다.
- `model.html:168` 외 `.has-tip`: 불가 이유 툴팁이 `:hover`에서만 보인다. 버튼은 `aria-label`로 이유를 읽어 주지만, 키보드로 보는 사람에게는 보이지 않는다. `.has-tip:focus-visible::after`를 더한다.
- `uploads.html` h1, `ddl.html` h1: 부연 문구를 `title` 속성으로 옮겼는데, h1은 포커스를 받지 않아 키보드·터치로는 볼 수 없다. 필요한 안내라면 `?` 도움말 버튼(사전 `q-help-b` 방식)으로 바꾼다.
- `dictionary.html:242`: 상세 패널 머리 한 줄에 배지가 3개(출처·종류·상태)다. 출처·종류는 글자(`muted`)로, 배지는 상태 하나로 줄인다(#6 머리줄 규칙과 같게). 상세 패널이 행 선택 때만 열리면서 표 폭이 380/420px씩 바뀌어 도구 줄이 다시 배치된다. 패널 자리는 비워 둔 채 "항목을 고르세요" 빈 상태를 보이는 방식도 검토할 만하다.
- `app.css` 빈 상태 아이콘(`tr.er.none/first/done`): 선 색이 `%23666`·`%23297a3a` 고정값이라 다크에서 대비가 약 3.2~3.4로 낮다. `mask-image` + `background-color:var(--fg-2)` 방식으로 바꾸면 테마를 따른다. `import.html` 경로의 "모델"도 다른 화면처럼 업무 영역 이름으로 맞춘다.

## 확인했고 문제 없음
- 단축키 처리기는 `input/textarea/select/[contenteditable]`, 열린 대화상자, Ctrl·Meta·Alt를 제외한다. 모델 캔버스 단축키(v/e/r/m)와는 화면이 달라 겹치지 않는다.
- 모델 배너를 다시 배치하는 MutationObserver는 `style` 속성만 지켜본다. 노드 이동과 클래스 변경은 다시 부르지 않아 무한 반복이 없다.
- `confirm-btn`: 해결 가능한 상태(미준수 있음)는 주 버튼 + `aria-disabled` 제거 + 이동 안내가 들어간 `aria-label`이고, 불가한 상태는 이유를 `aria-label`에 담는다.
- 엑셀 가져오기: 4단계(검증 중)는 이전·다음이 모두 막히고, 5단계 F8로 다음 오류로 간다. 끝난 단계는 버튼으로 돌아갈 수 있다(4단계 제외).
- 1600px: 모델 머리줄 요소 합이 약 1150px로 본문 1376px 안에 들어간다. 사전 도구 줄은 한 줄이다. 엑셀 단계 줄은 약 720px다.
- 다크: 뼈대(gray-100 #1a1a1a), 저장 상태 점, kbd는 토큰을 따른다.

## 사용자 확인에 올려도 되는가

사용자 확인에 올려도 되는가: 예. 상 등급이 없고 개선 일곱 가지가 모두 의도대로 동작합니다. 다만 D6-02(토스트 두 개)와 D6-03(목록 뼈대 깜빡임)은 확인하는 사람이 바로 느끼므로 올리기 전에 고치기를 권합니다. D6-01·D6-05는 실제 제품 설계 결정으로 함께 안내합니다.
