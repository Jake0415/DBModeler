# DBModeler v7.2 교차 검토 합의안 · CX13

## 1. 총평

T1~T4는 첫 적재 상태, 후보 등록, 가져오기 대상, 승인 후 재판정이 끊긴다. 수정 차수에서는 각 화면이 실제로 생성한 묶음·문서·영역·속성을 다음 화면에서 다시 열 수 있게 한다.  
T5·T7·T9는 실패, T8은 조건부 통과를 제안한다. T8은 확정본에서 다음 버전을 열 수 있으나, 결재 상세에서 연결 용어의 진행 상태를 확인할 수 없다.  
아래 18개 묶음은 CX12와 CL12를 바탕으로 한 합의 제안이다. 현행 판정은 코드 추적 결과이며, 클릭 경로는 수정 후 인수 기준이다.

## 7. 이번 차수 제외(구현 설계로)

- SC-10 목록·SC-13 결과 표의 가상화. 행 재사용, 스크롤과 선택 상태, F8 및 키보드 포커스 계약이 필요하다.
- FK 행의 실제 연결점, 부모 PK 끌어다 키 전달, 자동 배치 Worker와 안전한 취소, ERD 편집 완결. 관계·키 변경과 실행 취소, 노드 렌더링과 배치 좌표의 단위를 함께 설계해야 한다.
- 모델 제출 사본의 서버 고정·내용 해시, 조회자 서버 쓰기 차단, 동시 편집의 동시성 보장. 제출 시각·버전·조회 UX와 잠금 시연은 위 목록에 들어가며, 실제 무결성·권한은 서버 계약에 속한다.
- 대용량 파일의 실제 파싱·상한 집행, 기준본/검증 토큰의 서버 위변조 방지, DDL 전체 방언 검증 및 실제 엑셀·공식 ERD 렌더 파일 생성. 이번 차수의 클릭 시연은 범위·판정·실패·재진입을 확인하며 엔진과 파일 호환성은 구현 단계에서 검증한다.
- V0 영구 삭제의 실제 데이터 제거·참조 무결성·감사 보존, 표준코드/코드값의 독립 신청, 엑셀 정의서→ERD 초안(W2). 보존 정책과 처리 모델이 필요하다.
- 신청 중 용어의 일괄 확정 차단 정책, 메일 수신·발송 규칙, 실제 인증과 전역 검색 색인. 목업에서 확인할 상태 표시는 포함하고, 정책 및 연동 계약은 구현 설계에서 확정한다.
- T11 산출물·T12 운영 테마의 전체 시나리오. 이번 목록의 개별 결함은 고치며, 역할별 시작 상태·실패·복구·완료 조건을 먼저 정의한 뒤 별도 시연 범위를 정한다.
