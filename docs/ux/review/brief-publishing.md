## 볼 것

1. **가이드 v2와 구현의 일치**
   - 토큰 · 글자 단계 · 버튼 3크기 · 탭 3종 · 상태 배지 의미표 · 표 밀도(D1) · 패널 폭(D3) · 경로 규칙(D4)이 문서와 `app.css` · 화면에서 같은가
   - 문서에는 있는데 구현에 없는 것, 또는 그 반대
2. **P1 합침의 정확성**: 원래 의도(마지막 규칙)와 다르게 합쳐진 규칙. 특히 같은 특정도에서 순서가 바뀐 경우, 다크 테마 규칙, `!important`
3. **유틸리티 클래스 방식**: 인라인을 `!important` 유틸리티로 바꾼 것의 부작용(부품의 상태 규칙을 덮음, 다크 테마, 화면 JS가 `style`을 덮어쓰던 곳), 이름 체계
4. **상태 배지 통일**
   - `tag()` → `.badge` 매핑이 의미표와 맞는가(진행 중 = `b-info`가 너무 많아 파랗게 보이는지, 내 차례 `b-mine`의 구분)
   - 다크 대비, 색만으로 전달하지 않는가
5. **접근성**: 사전 탭 줄(링크 + `.tabs`), 세그먼트로 바꾼 결재함 상자(`role=tablist` 유지), 밀도 전환, 최소 12px, 포커스 표시
6. **점검 도구(`audit.js` · [퍼블리싱 점검])**: 측정 방식의 맹점. 예: 버튼 부품만 세기, 캔버스 제외, 시각 표시 노이즈, 캐시
7. **업무 도구로서의 UX**
   - 36px 밀도가 데이터 모델러 업무(표준 맞추기 · 사전)에 적절한가
   - 사전 탭 줄과 상단 메뉴 '사전▾'의 중복
   - 견본이 기준 역할을 하는가
