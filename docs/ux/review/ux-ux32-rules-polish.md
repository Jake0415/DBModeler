# UX 리뷰 — 검수 기준 32차 정리(문구 · 줄 · 간격)

- 대상: `docs/ux/mockups/rules.html`(작업 중 사본) · `assets/app.js` 검수 기준 함수 · 변경분 `review/ux32-rules-polish.diff`
- 기준: `01-design-guide.md` §1 · §4 · §6 · §11, `24-settings-layout-guide.md` §3, ui-ux-pro-max(폼 · 피드백 · 일관성 규칙)
- 확인 방법: 브라우저 1920×1080, `?as=lee`(DA) · `?as=park`(모델러) · `?as=lee&k=term`. 표 · [수정] 펼침 · 명명 규칙 · 설정 충돌 · [저장] 영향 창을 열었고, 영향 창은 [취소]로 닫았습니다. localStorage 크기는 조작 전후 같았습니다(88,519자).
- 결론: 32차로 표 열 폭(두 표 같은 colgroup, 1200px 넓은 행), 자물쇠 제거, 라벨 96 · 간격 12/16, 주요 동사(차단 · 경고 · 미적용 · 수정 · 제안)가 가이드에 맞게 정리됐습니다. 남은 문제는 **app.js 공통 문구(충돌 메시지 · 권한 이름 · 옛 화면 안내)**에 옛말이 남은 것, **준수율 설명이 실제 판정과 다른 것**, 그리고 **저장 막대 · 읽기 전용 표시가 공통 부품과 다른 것**입니다.

심각도: **높음** = 틀린 안내이거나 사용자에게 내부 표기가 보임 · **중간** = 기준어 · 부품 불일치, 바로 눈에 띔 · **낮음** = 다듬기

## A. 남은 어색한 문구(번역투 · AI스러운 말)

### A-1 [높음] 설정 충돌 메시지에 옛 동사 · 내부 표기가 남아 있음 (`app.js` `policyConflicts`)
- 근거: 화면에서 DA가 직접 보는 문장입니다. 32차에서 화면의 ‘막기’를 ‘차단’으로 바꿨지만 충돌 목록 · 저장 막대 · 영향 창 ①에는 아직 이렇게 나옵니다.
  - ‘단어 구분자 ‘-’를 용어 영문약어명이 허용하지 않습니다 — **모든 용어 약어가 막힙니다**’
  - ‘… 용어 영문약어명은 **막습니다** — 그 단어로 만든 용어가 모두 **막힙니다**’
  - ‘단어 영문약어명이 허용하는 **기호**를 용어 영문약어명이 **막습니다**’
  - ‘따옴표가 필요한 문자(**모든 기호** · **모든 글자**)를 허용했습니다 — 물리명에는 쓸 수 없습니다**(Q5)**’ — 내부 결정 번호가 화면에 보임
  - ‘단어 약어 8자 × 4개 + **기호면** 35자 — 용어 약어 상한…’
- 고칠 방법(문구만 교체):

| 지금 | 바꿀 말 |
|---|---|
| 모든 용어 약어가 막힙니다 | 모든 용어 영문약어명이 차단됩니다 |
| …를 허용하는데 용어 영문약어명은 막습니다 — 그 단어로 만든 용어가 모두 막힙니다 | …를 허용하지만 용어 영문약어명은 허용하지 않습니다 — 이 단어가 들어간 용어는 모두 차단됩니다 |
| 단어 영문약어명이 허용하는 기호를 용어 영문약어명이 막습니다 | 단어 영문약어명에서 허용한 특수문자를 용어 영문약어명이 허용하지 않습니다 |
| (모든 기호 · 모든 글자) … (Q5) | (특수문자 전체 · 문자 제한 없음) … ‘(Q5)’ 삭제 |
| 단어 약어 8자 × 4개 + 기호면 35자 — 용어 약어 상한 30자를 넘을 수 있습니다 | 단어 영문약어명 8자 × 4개 + 구분자 3자 = 35자 — 용어 영문약어명 최대 길이 30자를 넘을 수 있습니다 |

### A-2 [높음] ‘미적용’ 설명이 실제 판정과 다름
- 근거: 편집 영역 힌트 ‘미적용: 판정하지 않으며 **준수율 계산에서도 빠집니다**(대상 수는 유지)’. 그런데 판정 사례(`policy-cases.js` Q2)는 ‘분모 그대로 · 통과’입니다. 즉 대상에서 빠지는 게 아니라 **위반으로 세지 않을 뿐**입니다. ‘빠집니다’와 ‘대상 수는 유지’가 한 문장에서 서로 어긋나 읽힙니다. `?f=off` 배너의 ‘준수율 대상 수는 유지합니다’도 같은 문제입니다. 표준 제외 규칙의 ‘준수율 계산에서 빠집니다’(이쪽은 실제로 빠짐)와 같은 말을 써서 둘이 구분되지 않습니다(01 §1-7 결과는 항상 보인다).
- 고칠 방법: 힌트 → ‘미적용 규칙은 판정하지 않습니다. 준수율에서는 위반으로 세지 않고 대상 수는 그대로입니다.’ / 배너 → ‘미적용 규칙 n개 — 판정하지 않으며, 준수율 대상 수는 그대로입니다.’

### A-3 [중간] 권한 이름 · 옛 화면 안내에 ‘고치기 · 허용 글자 · 정책 버전’이 남음 (`app.js`)
- 근거: 설정 › 권한표와 결재 · 감사에서 쓰는 권한 이름이 `rules.edit: '검수 기준 고치기'`(app.js:96)입니다. 이 화면의 버튼은 [수정], 안내는 ‘DA · Admin 수정’이라 같은 일을 두 말로 부릅니다. 또 `settings.rules` 화면 안내(app.js:1683~1685)에 ‘허용 글자’, ‘[저장] — **정책 버전**이 하나 오르고’(§11.1에서 금지), ‘재검증’이 남아 있습니다(검수 기준이 표준 사전으로 옮겨져 이 안내가 쓰이지 않으면 삭제).
- 고칠 방법: 권한 이름 → ‘검수 기준 수정’. 옛 안내는 삭제하거나 ‘허용 문자’ · ‘검수 기준 버전이 하나 오르고’ · ‘재검사’로 바꿉니다.

### A-4 [중간] 명명 규칙의 보조 설명이 기호(=, →)와 명사 조각으로 되어 있음
- 근거: ‘용어 영문약어명 **=** 구성 단어 약어 연결’, ‘엔터티명 끝 단어 **→** 테이블명 접미어’, ‘용어 · 엔터티 약어의 단어 연결’, ‘정밀도 · 소수점 도메인’. 수식 같은 압축 표현이 AI스럽게 읽히고, 무엇을 검사하는지 문장으로 드러나지 않습니다. 같은 칸의 다른 줄(‘용어 마지막 단어가 형식단어(…)’)과 끝맺음도 제각각입니다.
- 고칠 방법(모두 ‘~인지 검사’ 형식으로 통일, 24 §3.2 라벨 칸 ‘이름 + 짧은 설명’):

| 규칙 | 설명 바꿀 말 |
|---|---|
| 단어 구분자 | 용어 · 엔터티 영문약어명에서 단어 사이에 넣는 문자 |
| 용어 약어 조합 일치 | 용어 영문약어명이 구성 단어의 영문약어명을 이은 값과 같은지 |
| 형식단어 종결 | 용어의 마지막 단어가 형식단어(일자 · 코드 · 명 등)인지 |
| 1음절 분해 의심 | 한 글자 단어로 나뉜 용어가 있는지 |
| 엔터티 분류어 종결 | 엔터티명이 분류어로 끝나는지 |
| 도메인 소수점 구분자 | 소수점이 있는 숫자 도메인 이름에서 정밀도와 소수 자릿수를 나누는 문자 |
| 엔터티 분류어(표) | 엔터티명의 마지막 단어와 그에 맞는 테이블명 접미어 |

### A-5 [중간] 같은 화면에서 ‘변경 전/후’를 세 가지로 부름
- 근거: 값 검사 ‘현재 기준(v3) / 변경 후’, 명명 미리보기 ‘변경 전 → 변경 후’, 영향 창 ‘새 기준 적용 시 영향’. 또 ‘변경 항목만 보기’는 **공통표준 기본값과 다른 행**을 거르는데, 행의 [변경] 배지는 **저장 전 바꾼 행**을 뜻합니다. 같은 ‘변경’이 두 기준을 가리킵니다.
- 고칠 방법: 비교 라벨은 ‘현재 기준 → 변경 후’ 하나로(미리보기 설명도). 거르기 버튼은 ‘기본값과 다른 항목만’(aria-pressed 토글, 라벨은 바꾸지 않음 — B-6 참고). 머리 문구 ‘공통표준 기본값 대비 0건 변경’ → 0건이면 ‘공통표준 기본값과 같음’, 그 밖엔 ‘공통표준 기본값과 다른 규칙 n건’.

### A-6 [중간] 표준 제외 규칙 구역의 구어 · 금지어
- 근거:
  - ‘표준 제외 규칙은 **지금** 기관 기본값을 **보여 줍니다** — **고치는** 기능은 구현 단계에서 **정책 버전**과 함께 저장합니다.’(§11.1 ‘정책 버전’ 금지, 구어체)
  - ‘속성·컬럼’, ‘유형·이름으로 제외’ — 나열 표기 ‘ · ’(앞뒤 띄움) 위반(§11.3)
  - ‘체크한 유형의 엔터티는 자동으로 비대상이 되어 준수율 계산에서 빠집니다.’ — ‘체크한’ · ‘되어’ 번역투
  - ‘*는 아무 글자입니다.’
  - ‘FK(부모가 표준이면 상속)’ 라벨과 보조 칸 ‘FK는 부모 속성이 표준이면 그 판정을 물려받습니다’가 같은 말 반복
- 고칠 방법: ‘표준 제외 규칙은 기관 기본값이며 이 목업에서는 조회만 됩니다. 수정은 구현 단계에서 검수 기준 버전에 포함합니다.’ / ‘속성 · 컬럼’, ‘유형 · 이름으로 제외’ / ‘선택한 유형의 엔터티는 표준 대상에서 제외하고 준수율 계산에서도 뺍니다.’ / ‘*는 0자 이상의 임의 문자입니다. 예: TMP_*는 TMP_로 시작하는 컬럼’ / 라벨은 ‘FK’로 줄이고 설명은 보조 칸에만.

### A-7 [낮음] 영향 창 문구
- 근거(`?as=lee`, 단어 영문약어명 6→8자 · 구분자 _→없음으로 열어 봄):
  - 제목 ‘검수 기준을 v4로 **올립니다**’ — §11.2 확인 창 제목 = 동작
  - ‘② 변경 규칙’ 줄이 규칙 전체를 두 번 씀: ‘6자 · 영문 대문자 · 숫자 · 차단 → 8자 · 영문 대문자 · 숫자 · 차단’
  - ‘재검증 대상 엑셀 묶음’ ↔ 같은 창의 ‘재검사 대상’ · ‘재검사합니다’
  - 단위가 ‘건’(사전 · 신청) · ‘개’(모델 속성 · 엑셀 묶음) · ‘쌍’으로 섞임, ‘용어 약어’ ↔ ‘용어 영문약어명’ 혼용
  - 저장 기록 요약 ‘… 외 n**곳**’(규칙에 ‘곳’은 어색)
- 고칠 방법: 제목 ‘검수 기준 v4 저장’. 변경 줄은 바뀐 부분만 — ‘단어 영문약어명 · 최대 길이: 6자 → **8자**’(diffs가 RK 항목별 from/to를 내도록). ‘재검사’로 통일(업로드 이력 배지 ‘재검증 필요’도 함께 맞출지 결정 필요 — 다른 화면에 퍼져 있으면 §11.1에 기준어로 추가). 단위는 항목 = 건, 묶음 = 개로 고정하고 모델 속성은 ‘건’. ‘외 n건’.

### A-8 [낮음] 반복 안내 · 메아리 힌트
- 근거: 특수문자 ‘허용 안 함’을 고르면 바로 아래 힌트가 ‘특수문자를 허용하지 않습니다.’, ‘전체 허용’이면 ‘모든 특수문자를 허용합니다…’ — 고른 값을 다시 읽어 주는 문장입니다. 머리의 ‘v3 · 적용 2026-11-10 09:00 · 이데이터’가 바로 아래 ‘기준 버전’ 행에서 그대로 반복됩니다.
- 고칠 방법: 힌트는 ‘선택한 문자만’일 때 ‘허용: _ -’ 또는 ‘선택한 문자가 없습니다’만 남기고, ‘전체 허용’은 ‘공백은 허용 문자에서 정합니다.’만. 머리에는 배지 v3만 두고 적용 시각 · 사람은 ‘기준 버전’ 행 한 곳에.

### A-9 [낮음] 대상 DB ↔ 설정의 ‘대상 DBMS’
- 근거: 설정 › 시스템은 ‘대상 DBMS’ · ‘DBMS’를 씁니다. 이 화면은 ‘대상 DB’, ‘모델 물리명은 시스템 설정의 DB를 우선합니다’.
- 고칠 방법: ‘대상 DBMS’ / ‘모델 물리명은 시스템마다 설정한 DBMS를 따릅니다.’

## B. 줄 · 간격 · 정렬 · 시각 위계

### B-1 [중간] 저장 막대가 공통 부품(`.setbar`)이 아님
- 근거: 설정 · 마이페이지는 `.setbar`(role="region", aria-label ‘저장하지 않은 변경’, `aria-live` 메시지, [변경 보기] 팝오버, [되돌리기] 툴팁)를 씁니다. 이 화면은 자체 `.savebar2`로 같은 역할을 다시 그렸고(01 §1-8 한 역할 = 한 부품, 24 §3.4 공통 CSS), 낭독 영역 · [변경 보기]가 없습니다.
- 고칠 방법: `.setbar.show` 마크업으로 바꾸고 메시지는 24 §3.4 형식 ‘● 2건 변경 — 저장하면 검수 기준 v4 [변경 보기]’. [변경 보기]는 영향 창 ② 목록을 팝오버로 재사용.

### B-2 [중간] 설정 충돌 안내가 바꾼 자리에서 보이지 않음
- 근거: 명명 규칙(페이지 아래쪽)에서 구분자를 ‘-’로 바꾸면 충돌 상자는 페이지 맨 위 `#r-ban`에만 생깁니다. 사용자는 저장 막대의 ‘충돌 보기’를 눌러야 압니다. 24 §3.2 ‘경고는 해당 행의 보조 칸으로’와 다릅니다. 또 같은 ‘확인’ 문장이 테이블명 · 컬럼명으로 두 줄 반복됩니다.
- 고칠 방법: 충돌이 있는 규칙 행(명명 규칙의 단어 구분자 보조 칸, 표의 해당 행)에 한 줄 사유를 함께 표시하고, 위 요약 상자는 그대로 둡니다. 두 ‘확인’은 ‘테이블명(물리) · 컬럼명(물리)’로 한 줄에 합칩니다.

### B-3 [중간] [수정] 펼침 안의 순서가 표 열 순서와 다름
- 근거: 표는 ‘필수 → 최대 길이 → 허용 문자 → 기타 조건 → 위반 시’인데 편집 영역은 ‘허용 문자 → 특수문자 → 최대 길이 → 기타 조건 → 위반 시’입니다. 요약 행과 편집 영역을 오가며 눈이 돌아갑니다.
- 고칠 방법: 편집 순서를 ‘최대 길이 → 허용 문자 → 특수문자 → 기타 조건 → 위반 시 → 값 검사’로 맞춥니다.

### B-4 [낮음] ‘기타 조건’ 열이 모델 표에서 말줄임으로 잘림
- 근거: 테이블명(물리) · 컬럼명(물리)의 ‘숫자로 시작 금지 · 특수문자 연속 금지 · 예약어 금지’가 248px에서 ‘… 예약…’으로 잘립니다. 허용 문자 열은 가장 긴 값(‘한글 · 영문 대문자 · 영문 소문자 · 숫자’ 약 300px)보다 넓게 남습니다(1920에서 406px).
- 고칠 방법: `col.c-x` 248 → 320(허용 문자 열이 약 334로 줄어도 들어감). 또는 ‘기타 조건’ 칸만 `white-space:normal`.

### B-5 [낮음] 단어 구분자 라디오 세로 정렬 어긋남
- 근거: 첫 옵션(‘_ (밑줄)’, 위험 문구 없음)은 22px 높이로 가운데 정렬돼 y=438, 나머지 둘은 44px로 y=427에서 시작합니다. 라디오 원이 11px 엇갈려 보입니다.
- 고칠 방법: 감싸는 `.flex`에 `align-items:flex-start`(부품 규칙으로 — `.radio-top` 부모에 `.radio-row { align-items:flex-start }`).

### B-6 [낮음] 토글 버튼 라벨이 바뀜
- 근거: [변경 항목만 보기]가 누르면 [전체 보기]로 글자가 바뀌면서 `aria-pressed`도 함께 바뀝니다. 낭독기는 ‘전체 보기, 눌림’으로 읽어 뜻이 반대가 됩니다.
- 고칠 방법: 라벨 고정 ‘기본값과 다른 항목만’ + `aria-pressed`만 전환(또는 같은 목록의 보기 전환이므로 `.seg` ‘전체 | 기본값과 다른 항목’).

### B-7 [낮음] 편집 영역 라벨 13px
- 근거: §3 글자 단계에서 13은 Geist Mono(물리명 · 코드) 크기입니다. 한글 라벨은 14 또는 캡션 12입니다.
- 고칠 방법: `.pol-ed .lab` 14px(`--fg-2`) 유지하거나 12px 캡션으로. 표 본문(14)과 맞추려면 14 권장.

### B-8 [낮음] 조회 전용(모델러)에서 입력 칸이 그대로 보임
- 근거: `?as=park`에서 엔터티 분류어 표는 비활성 입력 칸 10개, 명명 규칙은 비활성 라디오 · 세그먼트로 보입니다. 고칠 수 있는 칸처럼 보이고 회색 글자 대비가 낮습니다. 사전 · 모델 규칙 표는 글자로 보여 주는데 이 두 구역만 다릅니다.
- 고칠 방법: 조회 전용이면 분류어 표는 글자 칸(‘기본 | M’), 명명 규칙은 선택값만 글자로(‘단어 구분자: _ (밑줄)’). 위쪽 조회 전용 띠는 01 §6.3대로 화면 안내에 합칠지 함께 정리.

### B-9 [낮음] 특수문자 ‘허용 안 함’일 때 비활성 칩 8개 노출
- 근거: 고를 수 없는 칩이 한 줄 내내 흐리게 보여 편집 영역이 무거워집니다(01 §1-4 촘촘하되 답답하지 않게).
- 고칠 방법: ‘선택한 문자만’일 때만 칩 줄을 그리고, ‘전체 허용’은 칩 대신 힌트 한 줄.
