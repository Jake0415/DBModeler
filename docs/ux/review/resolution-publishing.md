# 검토 반영: 퍼블리싱 정리 P0~P4 (17)

> 2026-11-20 · 검토 [claude-publishing](claude-publishing.md) 12건 · [codex-publishing](codex-publishing.md) 15건 — 겹치는 지적이 많아 묶어서 처리했다. FE 목업만 바꿨다.

## 반영

| 묶음 | 지적 | 반영 |
|---|---|---|
| **P1 합침 회귀** | Codex 1 | 도구 줄 선택 칸(`.toolbar select.input`)과 오류 입력 칸(`.input.err`)에서 포커스 후광이 사라졌던 순서 문제를 고쳤다. 포커스 규칙을 입력 규칙 가운데 맨 뒤로 옮겼다(같은 특정도에서 마지막이 이김 — 합치기 전과 같은 결과) |
| **점검 도구 부작용** | Claude 1 · Codex 9 | `?audit=1`로 연 화면은 주소의 역할을 **저장하지 않는다**(검토자의 사용자가 바뀌지 않음, 확인: lee → 점검 → lee). 점검 전 `dbm-*` 저장소를 기억해 두고, 끝나면 되돌린다. [퍼블리싱 점검]은 매번 최신 `audit.js`를 불러오고, 결과에 테마 · 프레임 · 밀도 조건을 찍는다. 대상은 19개 화면(목업 지도 · ERD 별칭 제외)으로 가이드와 맞췄다 |
| **점검 범위** | Claude 2 · Codex 7 · 8 | 이름 검사를 모든 조작 요소(`button` · `[role=button/tab/menuitem]` · 링크)로 넓혔다. `aria-labelledby`를 읽고, 숨김 글자만 있는 경우도 구분한다. 입력 라벨 검사에 체크박스 · 라디오를 넣었다. 문자 아이콘은 요소 자체 글자만 본다. 투명 요소는 제외한다. 인라인 수는 **HTML 원문 기준**(정적)과 실행 후(동적)를 나눠 보인다. 가이드 §9에 "처음 보이는 상태만 잰다 — 패널 · 메뉴 · 모달 · 다른 탭은 따로 확인"을 적었다 |
| **표 밀도** | Claude 3 · Codex 5 | 모델 표 보기 · 속성 그리드 행이 `--row`를 따른다(36 · 34 고정 제거). 패널 입력은 공통 32px · 14px다. 마이페이지 안내를 "목록 · 표(모델 표 보기 · 속성 그리드 포함)", "사전 · 표준 맞추기는 촘촘 권장 · 두 줄 칸은 내용만큼 높아짐"으로 고쳤다. 가이드 §6.4의 위치를 "마이페이지 › 환경 › 표 밀도"로 바로잡았다 |
| **상태 위계** | Claude 5 · Codex 3 | **내 차례 = 파랑 채움**(`b-info`, 가장 눈에 띔), **진행 중 = 회색**(`.badge`)으로 바꿨다. `b-mine`은 없앴다. 결재함 대기함 행도 상세와 같은 `docTag()` — "DA 승인 · 내 차례"를 보이게 쓴다. "자기 승인"은 배지가 아니라 회색 글자 `(자기 승인)`이다. 가이드 §2.3 · 견본 상태표도 고쳤다 |
| **결재함 세그먼트** | Claude 6 · Codex 2 | `role="tablist/tab"` → `role="group"` + 버튼 `aria-pressed`(다른 세그먼트와 같음). 세그먼트 버튼에 틀 안쪽 2px 포커스 링을 넣었다. 남은 인라인 여백은 유틸리티로 옮겼다 |
| **유틸리티** | Claude 4 · Codex 11 | 이름을 `u-*`로 분리했다(397곳). 4px 단위 밖의 값은 가장 가까운 단계로 옮겼다(mt-2 → 4, 6 → 8, 10 → 12, gap-6 → 8 등). `.wrap` 충돌은 사라졌다(`td.wrap`은 그대로 부품). 가이드 §4에 목록과 계약을 적었다 — "`!important`는 인라인 대체라서, 스크립트 · 상태가 바꾸는 속성에는 쓰지 않는다" |
| **패널 넓히기** | Claude 8 · Codex 6 | 넓히기와 넓은 작업 패널 모두: 1920 이상 560 · 1600~1919 480(캔버스 760 확보). 모델의 넓히기(`.wide2`)도 같은 규칙을 따른다. 가이드 §5를 고쳤다 |
| **포커스 · 죽은 규칙** | Claude 9 | 포커스 링을 2px · 바깥 2px 하나로 통일했다. 아무 화면도 쓰지 않는 옛 왼쪽 메뉴(`.nav*`) · `.btn.md` · `.utabs` 규칙을 지웠다 |
| **대비** | Codex 4 | 알림 숫자 바탕 `--count-bg`(흰 글자 5.1:1). 다크에서 예외 · 기관 배지 테두리를 gray-600(3:1 이상)으로 바꿨다 |
| **가이드 · 견본** | Claude 10 · Codex 12 · 13 · 15 | 가이드:<br>• 제공하는 색 단계만 적었다.<br>• `.lg` 버튼(16px · 8px)을 명시했다.<br>• 없는 `.opt-list`를 지웠다(두 줄 카드형 버튼 금지 · 밑줄 탭은 높이 규칙 밖).<br>견본:<br>• 밀도 미리보기는 견본 페이지에만 적용하고 저장하지 않는다.<br>• 화면 · 패널 제목은 실제 부품(`.page-header h1` · `.rp-head h2`)으로 그린다.<br>• 배너 5종 · 토스트 · 모달을 넣었다. |
| **기타** | Claude 11 · Codex 10 · 7 | `b-end`도 배지 여백(12)을 쓴다.<br>가져오기 화면 경로는 시스템만 둔다(대상 영역은 화면 안에서 고름).<br>사전 신청 패널의 '보안 속성' · '형식단어'에 라벨을 연결했다. |
| **메뉴 중복** | Claude 7 · Codex 14 | 가이드 §9에 역할을 적었다. 사전 탭 줄은 사전 화면 안의 위치 표시와 이동, `사전▾`는 다른 화면에서 사전 업무로 바로 가는 길이다. 엑셀 가져오기의 단계 줄은 진행 표시라 탭과 겹치지 않는다(그대로 둠) |

## 남긴 것
- **Claude 12 · Codex 5**: 화면별 기본 밀도(목록형 32)는 개인 설정 · 안내로 대신하고 사용자 관찰 뒤 다시 본다.
- **Codex 8**: 의사 요소 · 좌표 · hover 상태 비교, 안정적인 요소 식별자는 점검 도구 다음 개선으로 둔다.
- **Codex 12**: 공동 편집자 색 토큰(`--p-1…`)과 모델 캔버스 스타일 이전은 17 §6.2의 남은 일과 같다.
- **포커스 확인 방법**: 미리보기 창에 포커스가 없어 `:focus`는 화면에서 재지 못했다. 규칙 순서(포커스 규칙이 도구 줄 규칙보다 뒤, 같은 특정도)로 확인했다.
