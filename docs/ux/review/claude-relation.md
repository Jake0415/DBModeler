## 요약

보완안의 방향(관계 패널 편집, 조건별 삭제, 영향 미리보기)은 맞다. 다만 그대로 만들면 세 가지가 사용자를 헷갈리게 한다.
1. **관계 삭제(모델 구조)와 ON DELETE(DB 행 규칙)가 같은 "삭제"라는 말로 한 패널에 놓인다.**
2. **선택성 · 카디널리티 · FK NULL**이 따로 노는 칸으로 보인다. 모델러에게 이 셋은 한 가지 사실이다.
3. **식별 관계 삭제의 두 선택지가 결과를 설명하지 않는다.** 지금 구현은 "유지"면 자식 PK 표시가 남고, "삭제"면 손자 FK가 남는다.

아래 15건은 이 셋을 중심으로 정리했고, 마지막에 권장 최종 시나리오를 붙였다.

### 삭제 조건 표 (#4 · #5)

| 관계 유형 | FK 상태 | 하위 영향 | 묻는가 | 기본(첫 버튼) | 다른 선택 |
|---|---|---|---|---|---|
| M:N | FK 없음 | 없음 | 묻지 않음 | 바로 삭제 + 실행 취소 | — |
| 비식별 | FK 0개(누락) | 없음 | 묻지 않음 | 바로 삭제 | — |
| 비식별 | FK n개 | 없음 | 띠 1회 | FK 컬럼도 삭제 | 컬럼은 일반 속성으로 남김 |

## 권장 최종 시나리오

**연결**
1. 관계 도구 `R`을 누르고 유형을 고른다(기본 1:N 비식별, 마지막 선택 기억). 키보드: 엔터티 선택 → `R`.
2. 부모를 누른다 → 미리보기 선과 안내 "자식을 클릭하세요 · Esc 취소".
3. 자식을 누른다 → **묻지 않고** 관계를 만든다. 부모 PK가 모두 자식 FK가 되고(식별이면 자식 PK + 필수, 손자까지 전파), FK 묶음·짝을 기록한다.
   - 이름이 겹치면 선 옆 팝오버에 역할명 제안을 채워 띄운다. Enter·Esc 모두 제안값 확정이고, 타이핑하면 바꾼다.
   - 같은 엔터티면 재귀 확인 → 부모 PK 모두에 역할명(상위○○) 컬럼, FK NULL 허용.
   - 부모 PK가 없으면 관계만 만들고 "FK 대기 · [식별자 지정]"을 안내한다.
   - M:N이면 FK 없이 만들고 [M:N 해소]를 보인다.
   - 1:1이면 식별은 PK 공유, 비식별은 FK에 UK를 자동으로 붙인다.
4. 토스트 "고객 → 주문 관계 · FK 1개 추가 [실행 취소]"를 띄우고, 관계 패널을 연다(포커스는 옮기지 않음).

**설정** (관계 패널, 나중에 고친다)
5. 관계명(동사구) → 유형(식별/비식별) → 카디널리티·선택성 문장 두 줄(부모 쪽 값이 FK 필수를 정함) → FK 짝 표(역할명·대응 수정)를 고친다. 바뀌면 선 기호·그리드 자물쇠·DDL이 함께 바뀐다.
6. 물리 보기에서 **「DB 반영」** 구역을 펼쳐 "부모 행을 지울 때(ON DELETE)"를 고른다(기본 막기, SET NULL은 선택 관계만, CASCADE는 연쇄 경로 경고). FK 제약 이름·인덱스도 여기서 고친다.

**삭제** (모델에서 관계 삭제)
7. 관계를 선택하고 패널 맨 아래 [모델에서 관계 삭제]를 누르거나 Delete를 누른다.
8. 삭제 조건 표에 따라 바로 삭제하거나, 패널 안 띠를 **한 번만** 띄운다. 띠에는 세 줄 영향 요약(자식 · 손자 · DDL)과 [자세히], 결과로 이름 붙인 버튼 두 개(기본 = 함께 정리), [취소(Esc)]가 있다. ON DELETE는 이 띠에 나오지 않는다.
9. 실행 → 캔버스에서 정리된 엔터티를 잠깐 강조하고, 토스트 "관계를 삭제했습니다 · 컬럼 4개 정리 [실행 취소]"를 띄운다.
10. 잠긴 영역·조회 전용에서는 7~9가 비활성(이유 표시)이다. 결재 비교에는 관계 변경과 DB 동작 변경이 따로 묶여 나온다.
