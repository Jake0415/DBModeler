# 검토 요청: NeoDB 전체 목업 사용성 검토 (UX 전문가)

NeoDB는 데이터 표준(표준 사전) · 데이터 모델링(ERD) · 결재를 한 곳에서 하는 웹 도구입니다. 지금은 **FE 목업 단계**입니다(서버 없음, 브라우저 저장소 상태). 사용자는 DA# · ERwin · SWS에 익숙한 실무자입니다. 표준화와 모델링은 수정이 많고 오래 걸리는 일이라 **반복 작업의 속도와 실수 방지**가 중요합니다.

- 미리보기: http://localhost:5178 (실행 중) · 목차 `index.html` · 사용자 바꾸기 `?as=kim`(모델러 겸 DA) · `park`(모델러) · `lee`(관리자 겸 DA) · `hyun`(기관 담당자 · 최종 승인) · `choi`(기관 담당자 겸 모델러) — 검토용으로 `&audit=1`을 붙이면 역할이 저장되지 않음
- 화면: `docs/ux/mockups/*.html` (홈 · 시스템 · 모델 · 표준 맞추기 · 용어 자동분석 · DDL 가져오기 · DDL · 산출물 · 사전 통합 검색 · 화면 일괄 작성 · 도메인 그룹 · 분류 · 공통표준 · 행정표준코드 · 엑셀 가져오기 · 업로드 이력 · 후보 큐 · 변경 내역 · 결재함 · 감사 로그 · 설정 · 마이페이지 · 로그인 · 오류 · 견본)
- 설계 기준: `docs/ux/01-design-guide.md`(디자인 가이드 v2), `02-flows.md`, `03-erd-editor.md`, `12-model-tree-plan.md`, `15-rbac.md`, `16-attribute-edit-grid.md`, `18-relation-scenario.md`, `20-dictionary-modeler-comparison.md`, `21-dictionary-check-guide.md`(직접 확인 안내), `docs/spec/da-feature-spec/30-metadata-design.md`
- 앞선 검토 결과는 `docs/ux/review/*`에 있습니다. **이미 고친 지적을 다시 내지 말고**, 지금 상태에서 사용자가 실제로 겪을 문제에 집중하세요.

## 사용자와 대표 과업 (이 순서로 걸어 보세요)

| 사용자 | 과업 |
|---|---|
| 표준화 담당자(DA) | ① 첫 로그인 → 사전 구조 파악 ② 도메인그룹 · 분류 준비 ③ 단어 · 도메인 · 용어 · 코드값을 화면 일괄 작성으로 20건 작성 → 품의 ④ 공통표준 · 행정표준코드 확인 ⑤ 결재함에서 50건 품의 중 2건 항목 반려 · 승인 ⑥ 공표 |
| 모델러 | ① 시스템 → 업무 영역 → 모델 열기 ② ERD에 엔터티 · 속성 추가(사전 자동완성 · 끌어 놓기) ③ 관계 연결 · 설정 · 삭제 ④ 표준 맞추기 / 용어 자동분석으로 미준수 정리 ⑤ 없는 용어를 바구니에 담아 품의 ⑥ DDL · 산출물 ⑦ 모델 확정 신청 |
| 기관 담당자 | 최종 승인 대기 문서 찾기 → 판단 근거(전후 값 · 검사 · 영향) 확인 → 승인 |
| Admin | 사용자 · 역할 · 결재선 · 검수 기준 설정, 감사 로그 확인 |

## 부탁하는 것

1. **과업별 걷기(cognitive walkthrough)**: 각 단계에서 사용자가 다음 행동을 알 수 있는가, 결과를 이해하는가, 막히는 곳 · 헤매는 곳 · 클릭이 많은 곳.
2. **휴리스틱 평가(Nielsen 10)**: 상태 가시성, 실제 세계 언어(DA# · 실무 용어), 사용자 통제 · 실행 취소, 일관성 · 표준, 오류 예방, 기억보다 인식, 유연성 · 효율(키보드 · 일괄), 미니멀 디자인, 오류 인식 · 복구, 도움말.
3. **정보 구조 · 내비게이션**: 상단 메뉴, 사전 탭 묶음, 모델 트리, 패널 구조, 화면 간 이동 · 되돌아오기, 빵 부스러기.
4. **화면 디자인 · 접근성**: 밀도(1920 · 1600 업무 화면), 시각 위계, 버튼 · 배지 · 문구 일관성, 키보드 · 포커스 · 스크린리더, 대비.
5. **개선 제안**: 각 문제에 심각도(높음 · 중간 · 낮음) · 노력(작음 · 중간 · 큼) · 대상(파일:줄 또는 화면) · 근거 · **구체적 수정안**(문구 · 배치 · 흐름). **빨리 효과 보는 것(Quick win)** 을 따로 표시.
6. **유지할 강점**도 짧게.

브라우저를 쓸 수 있으면 **새 탭**에서만 시험하고(다른 사람과 저장소 공유 — 시험 전 `dbm-` 키 백업, 끝나면 복원), 쓸 수 없으면 코드 추적으로 판정하고 그렇다고 밝힙니다. 코드는 고치지 말고 결과 파일만 씁니다.

## 형식

한국어. ① 요약(한 단락 + 가장 중요한 5가지) ② 과업별 걷기 결과(사용자 × 과업 표: 통과 · 마찰 · 막힘 + 근거) ③ 휴리스틱별 발견 ④ 정보 구조 · 디자인 · 접근성 ⑤ 개선 목록(25건 이내, 심각도 순, Quick win 표시) ⑥ 유지할 강점.
