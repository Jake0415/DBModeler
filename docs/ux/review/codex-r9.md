# 클릭 목업 v6 독립 UX 검증 · Codex r9

## 1. 총평

- 06 §4.5 기준 **Top 10 닫힘 0/10**(부분 10), **S1~S6 닫힘 0/6**(부분 6). 화면별 개선이 있어도 입력·결재·반영·재진입 중 하나가 끊기면 부분으로 판정했다.
- 문서별 집계, 영역·버전별 모델 저장, 사전 항목별 이력은 실제 연결됐다. 결재자의 표시값과 실제 반영값, 승인 대상 버전과 검사 대상 버전에는 차이가 남는다.
- 가장 큰 완료 오인은 값이 그대로인데 버전이 오르는 사전 승인, 검증 없이 성공하는 반영본 확인, 제출본과 다른 모델로 판단하는 승인이다.
- 범위는 06 §4.5~4.6 및 07 v1.0. 화면의 실행 경로는 코드로 추적했고 공통 상태 함수의 대표 사례 5건은 Node의 메모리 저장소에서 재현했다. 브라우저 클릭·포커스 체감은 미검증이다.

## 5. 다음 단계

### (a) 목업에서 더 할 것 Top 5

1. **한 묶음의 왕복을 끝까지 연결.** 편집용 기준본→행 비교·보정→선택 행과 사유가 보이는 결재→항목별 반영→반영본 동일 확인→보류 행 재진입을 한 시나리오에서 확인한다.
2. **모델 확정본 보기와 승인 대상을 일치.** 리스크와 요구사항 각각의 제출본·기준본·확정본 링크, 다음 작업 버전, 예시 격리를 보여 준다. 실데이터 검사 전에는 어떤 스냅숏을 검사할지 화면에서 검증한다.
3. **오래 열린 탭과 열람 전용의 복구 UX 검증.** 문서 단계·역할·모델 버전·묶음 상태를 바꾼 뒤 예전 화면에서 실행한다. 거절 이유, 최신 상태 보기, 입력 보존, 포커스 복귀를 확인한다.
4. **행별 처리 결과를 신청·반영 상세까지 연결.** 표준 맞추기의 예외·비대상·후보, 사전 변경/미사용, 엑셀 분해와 경고 확인을 실제 행과 사유로 표시한다.
5. **운영자의 확인 범위 정리.** 자동 보정의 보이는 대상, 공표 대상, SC-16 W1 목록·필드 전후·보고서 집계를 화면 사이에서 맞춘다.

### (b) 구현 설계로 넘길 것 Top 5

1. **서버 실행 권한과 상태 전이 계약.** 인증 주체·대상 소유권·업무 영역 접근·결재 단계·해당 문서의 신청자 조건을 쓰기 시점에 검사한다. 권한 오류와 낡은 기대 상태를 화면에서 구별할 응답으로 정의한다.
2. **불변 제출과 멱등성 계약.** 모델/엑셀 제출 스냅숏, 행의 선택·사유·검사·결재선, 고정 요청 키와 재신청 계보를 정의한다. 묶음·문서 링크까지 일관된 재시도 결과를 반환한다.
3. **왕복 비교 및 최종 승인 직전 재검사.** 기준본/양식/필드값, 현재 사전·대기·선행 의존성, 입력 행의 칸 단위 병합, 모델 스냅숏과 규칙 버전을 API 계약에 둔다.
4. **사전·모델 반영의 원자성.** 신청 항목의 안정 ID와 기대 버전을 검증하고 승인·항목 변경·이력·대기 해제 및 모델 버전 승계를 정합적으로 처리한다. 공표는 미리보기 대상 토큰과 기대 차수에 묶는다.
5. **반영 결과·이력·통지 조회 계약.** 묶음과 문서별 성공/보류/제외, 항목별 전후와 사용처, 역할별 파일 접근, 담당자 알림의 중복 제거와 딥링크를 정의한다.
