## 2. 부딪히는 점
1. 최소 검증 ↔ 업로드 오류 10종 · 참조 오류 막기(26:101). 경고로 내리면 관계 없는 FK 후보 컬럼이 들어오므로 모델 검증에 그 항목이 있어야 안전.
2. 엔티티 추가(막기) ↔ 병합 기본(갱신). 새 엔터티가 기존 엔터티를 부모로 참조하는 것은 중복이 아님 → ‘중복(추가 안 함)’과 ‘기존 부모 참조(연결)’ 배지 구분.
3. ‘덮어쓰기’가 두 뜻(엑셀 영역 갈아엎기 / 팝업의 기존 속성 사용) → 팝업 쪽은 ‘기존 속성을 FK로 사용’.
4. PK 삭제 시 FK만 끊기 ↔ 18의 선택형 띠. 실행 취소는 유지.
5. PK 추가 팝업 ↔ ‘연결은 묻지 않음’(18:9) — ‘겹칠 때만 묻는다’로 유지. 자식이 여럿이면 창 하나에서 일괄 처리.
6. 신청 시점 스냅샷은 이미 있음(제출 사본 · 해시, T-P2-601). DDL 기본값이 작업본인 것만 부딪힘.
7. 표준화 순서 다름 + 표준화로 이름이 바뀌면 엔티티 추가 중복 판정 기준을 정해야 함(Q4).
8. 테이블 ERD 6칸(노드 약 1.6배 넓어짐, 추측) ↔ 속성 최대 표시. 열 표시 고르기 + LOD로 열 줄이기.

## 3. UX 세부
### 3-1. IE 표기 · 범례
- 1:1 비식별이 실선(model.html:566) → 식별 여부로만 실선/점선.
- 범례 둘째 줄 = 조합 4종(‖ · ○‖ · ‖< · ○<) + 식별/비식별, 재귀 · 배타는 셋째 줄. 키 구역 · (FK) 설명 추가.
- `#`(Barker 출신) → 키 구역 + ‘PK’ 작은 글자 검토.
- 관계선을 FK 행에 붙이기(23 §4-1)를 6칸과 같은 차수에.

### 3-2. 밀도 · 클릭 영역
- 캔버스 밀도 촘촘 16px(글자 12px). 16px은 WCAG 2.5.8 24px 미만이지만 오른쪽 그리드(36px)라는 대안이 있어 예외. 촘촘 모드 hover 행 강조, 배지는 글자색만.
- 이름은 표 밀도와 같게(촘촘 · 기본 · 넓게), 설정 한 곳.

### 3-3. 테이블 ERD 열
| 순서 | 칸 | 폭 | 정렬 · 글꼴 |
|---|---|---|---|
| 1 | PK / FK | 24 | 가운데, ‘PK’ · ‘FK’ 글자 |
| 2 | 컬럼명 | 내용(최대 180) | 왼쪽, Mono |
| 3 | 타입 | 72 | 왼쪽, Mono |
| 4 | 길이 | 36 | 오른쪽, Mono |
| 5 | 소수점 | 28 | 오른쪽, Mono |
| 6 | 속성명 | 내용(최대 160) | 왼쪽, Pretendard, `--fg-3` |
- 100% 이상에서 노드 안 작은 머리줄 또는 범례에 열 순서. ‘키만’ LOD에서 3~6칸 숨김, 열 표시 고르기.

### 3-4. 중복 해소 창(관계 생성 · PK 추가 공통)
- 1건 = 팝오버, 2건 이상 · 자식 여럿 = 모달(640). 제목 ‘자식 엔터티에 같은 이름의 속성이 있습니다 (n건)’.
- 행마다 `자식 기존 속성(물리명 · 타입)` ↔ `부모 키` + 라디오 [기존 속성을 FK로 사용](바뀌는 타입 · 도메인 · 필수 미리보기) / [새 이름으로 만들기](‘원○○ · ORG_’ 제안).
- 기본 선택: 물리명 같고 타입 맞고 다른 FK가 아니면 ‘기존 사용’, 아니면 ‘새 이름’. 기존 속성이 PK · 다른 FK · 타입 계열 다르면 ‘기존 사용’ 흐리게 + 이유.
- 일괄 [모두 기존 속성 사용] · [모두 새 이름], 새 이름끼리 겹침 즉시 검사(지금은 model.html:2006에서 조용히 무시).
- 취소: 관계 생성이면 관계 · FK 통째로, PK 추가면 PK 지정까지 통째로 되돌림. 버튼 문구 ‘연결 취소’ / ‘PK 지정 취소’.
- 첫 포커스 첫 행 라디오, Enter 확정 · Esc 취소, 토스트 하나 + 실행 취소 한 번.

### 3-5. 엑셀 최소 검증 · 엔티티 추가 표시
- 요약 ‘등록 가능 n · 등록 불가 n(중복)’ / ‘경고 n — 가져온 뒤 모델 검증에서 다시 봄’.
- 중복 묶음 표시(‘엔티티명 사원기본 — 12행 · 40행’), 근거(논리명 일치 / 물리명 일치) 표시.
- 엔티티 추가 중복: ‘이미 있음 — 추가 안 함’ 배지 + 안내 띠 + [모델에서 ○○ 열기] + [다시 검사](파일 다시 고르지 않음).

### 3-6. 검증 → 신청 → 승인 → DDL
- [검토] · [확정 전 점검] · 게이트 A · 준수율이 다른 숫자를 보일 수 있음 → [모델 검증] 하나, 신청 버튼 배지 = ‘막음’ 건수.
- 모델 검증 → [확정 신청] → 결재 문서(제출 사본 항목 표 · 변경분 · ERD) → 승인 토스트 [확정본 보기] · [DDL 생성] → ddl.html?snap=확정본.
- 승인자 항목 표와 모델러 표 보기는 같은 부품.

## 4. 질문 (권장안)
1. `#` PK 기호를 없앨까? → 논리 캔버스는 키 구역 + ‘PK’, 테이블 ERD는 PK 칸.
2. 최소 검증 중복 오류 시 파일 전체를 막을까? → 처음 업로드는 전체 막음, 엔티티 추가는 중복만 빼고 추가.
3. ‘PK 삭제 시 FK 관계만 끊기’ → 자식 FK는 일반 속성, 관계는 ‘FK 대기’로 유지. ‘FK도 삭제’ 제거.
4. 엔티티 추가 중복 기준 → 논리명 또는 물리명 하나라도 같으면, 지금 작업본 이름 기준.
5. 기존 영역 업로드 병합 · 덮어쓰기 → W1은 ‘추가만’, 병합 · 덮어쓰기는 W2(26:100 수정).
6. 작업본 DDL 내려받기 → 미리보기 허용, 내려받기는 확정본 · 제출 사본만.
7. ‘설명 제대로 입력’ 기준 → 비어 있음 = 막음, 이름과 같음 · 5자 미만 = 경고, rules에서 기관이 조정.

## 5. 개선 제안
1. 겹침 해소 경로(관계 생성 · PK 추가 · 끌어 놓기 · M:N 해소 · FK 복구)를 창 하나로.
2. 모델 검증 목업 고정값(model.html:953) 제거.
3. 관계선을 FK 행에 붙이기를 6칸과 같은 차수에.
4. 가져온 직후 ‘처음 할 일’ 진행 띠(자동 배치 ✓ · 표준 맞추기 · 모델링 · 모델 검증 · 신청).
5. 승인 검토 표에 ‘변경분만’ 필터와 바뀐 칸 강조.
