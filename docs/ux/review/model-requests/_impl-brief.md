## 규칙
1. **맡은 파일만 고친다**(아래 각자 범위). 범위 밖이 필요하면 고치지 말고 최종 보고에 ‘요청’으로 적는다. 특히 `assets/app.js`는 모델 화면 담당만 고친다.
2. 기존 목업 스타일 · 부품 · 클래스를 그대로 쓴다(새 CSS는 최소, 기존 토큰 사용). 권한 판정은 기존 `can(...)` 방식 그대로 — **권한표(PERMS)는 바꾸지 않는다.**
3. 결정 범위만 바꾼다. 결정과 관계없는 동작은 건드리지 않는다.
4. 맡은 UX 문서에 해당 절을 고치고, 문서 끝에 `## 변경 기록 — 고객 모델 요청 반영 (2026-11-25)` 표(무엇 · 왜(M-n) · 목업 위치)를 단다.
5. 맡은 `docs/impl/trace/behaviors/<화면>.json`을 목업에 맞춘다: 바뀐 동작은 해당 행의 trigger · expected 수정, 없어진 동작은 행 삭제가 아니라 expected를 새 동작으로 바꾸거나(같은 자리) 정말 없어졌으면 삭제, 새 동작은 **기존 마지막 번호 다음 번호**로 추가(번호 재정렬 금지). JSON 유효성 유지(`node -e "JSON.parse(require('fs').readFileSync(f,'utf8'))"`).
6. 확인: 고친 HTML의 인라인 스크립트가 문법 오류 없이 도는지 확인한다. 목업 서버 `http://localhost:5178/<화면>`이 떠 있으니 가능하면 브라우저 도구(mcp__Claude_Browser__*)로 열어 콘솔 오류가 없고 바뀐 동작이 보이는지 확인한다(데모 사용자 `?as=kim|park|lee|hyun|choi`). 브라우저를 못 쓰면 `node`로 스크립트 추출 후 `new Function` 문법 검사라도 한다.
7. 최종 보고: 바꾼 내용(결정 번호별) · 파일:줄 · 추가/수정한 BH id · 확인 결과 · 남은 문제 · 범위 밖 요청. 짧고 구체적으로.
