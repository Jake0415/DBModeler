## 1. 한 줄 결론

IE 표기, 부모 PK → 자식 FK, 신청 시점 스냅샷은 이미 설계돼 있다. 손볼 곳은 다섯 덩어리다.
1. **중복 속성 해소 창**(관계 생성 · PK 추가 공통)
2. **엑셀 최소 검증과 ‘추가만’ 업로드**
3. **모델 검증을 하나로 묶고 신청 조건에 연결**
4. **승인본 기준 DDL과 제출 사본 항목 검토 표**
5. **테이블 ERD 6칸과 길이 · 소수점 분리 저장**

모두 P2 범위(T-P2-30x · 40x · 50x · 60x · 70x)라서 P1 시작은 막지 않는다.

## 4. 제안 변경 (사람 확인 뒤)

### A. 중복 속성 해소 창 — ERD-3b · 3c (+ PK 끌어 놓기 · M:N 해소 · FK 복구도 같은 창으로)
**대상과 판정**
- 겹침 판정: 논리명 또는 물리명 중 하나라도 같으면 겹침(대소문자 무시). 표준화 뒤에는 같은 용어 id도 겹침으로 본다.

**창의 모양**
- 1건이면 팝오버, 2건 이상이거나 자식이 여럿이면 모달(640)로 띄운다.
- 행마다 두 가지 중 하나를 고른다.
  - [기존 속성을 FK로 사용]: 이름 · 정의 · 예외 사유는 그대로 두고, 타입 · 길이 · 도메인 · 필수는 부모 키에 맞춘다. 바뀌기 전과 후를 보여 준다.
  - [새 이름으로 만들기]: ‘원○○ · ORG_’를 제안한다.
- 일괄 처리 버튼 [모두 기존 속성 사용] · [모두 새 이름]을 둔다.

**기본 선택과 막는 경우**
- 기본 선택: 물리명이 같고, 타입 계열이 맞고, 다른 관계의 FK가 아니면 ‘기존 속성 사용’. 아니면 ‘새 이름’.
- 기존 속성이 PK이거나 다른 관계의 FK이면 ‘기존 속성 사용’을 흐리게 하고 이유를 보인다.

**취소**
- 관계를 만들던 중이면 관계를 통째로 되돌린다.
- PK를 추가하던 중이면 PK 지정까지 통째로 되돌린다.

**저장 방식(공동 편집)**
- 창이 떠 있는 동안에는 Yjs에 쓰지 않는다. 확정한 뒤 **한 Y 트랜잭션**으로 적용한다(18 §5 · T-P2-402/403 계약에 적는다).
- 서버 쓰기 검증에 ‘엔터티 안 물리명 유일’을 넣는다.

**용어**
- 엑셀의 ‘덮어쓰기’와 헷갈리지 않도록 이 창에서는 ‘덮어쓰기’ 대신 ‘기존 속성을 FK로 사용’이라고 쓴다.
- RV-R04(W3 제외)와 겹치지 않도록 ‘사용자가 선을 그었을 때만’으로 한정한다.

### B. PK 삭제 — ERD-3d
- 한 가지 동작만 한다: 자식 FK 컬럼을 일반 속성으로 남기고 관계는 유지한다. 부모 PK가 하나도 없으면 ‘FK 대기’가 된다.
- 식별 관계에서는 18 §3과 같게, 자식 PK에 남긴다(손자까지 연쇄로 풀리는 것을 막는다).
- [자식 FK도 삭제]는 띠에서 빼고, 토스트의 [이 컬럼도 지우기]로만 둔다. 실행 취소는 유지한다.

### C. 엑셀 업로드 — XL-1 · P-1 · ADD-1
**막는 것**
- 파일을 읽을 수 없음
- 필수 머리글 없음
- 빈 테이블명 · 컬럼명
- **엔티티명/테이블명 중복**(신규)
- **같은 엔티티 안 속성명/컬럼명 중복**(속성명 검사는 신규)
- 대소문자만 다른 테이블명

**경고로 내리고 가져오는 것**
- 참조 오류 · 타입 불일치 · 행마다 다른 논리명/설명 · 복합 PK 일부 참조
- 참조 오류 행은 관계를 만들지 않고 컬럼만 가져온다.
- 대신 모델 검증에 ‘관계 없는 FK 후보 컬럼’ 항목을 반드시 둔다.

**기존 영역에 올릴 때**
- W1은 ‘추가만’ 방식 하나로 한다. 병합 · 덮어쓰기는 W2로 미룬다(26 §6-1 수정).
- 중복 행에는 ‘이미 있음 — 추가 안 함’ 배지를 단다.
- 안내: ‘모델에서 ○○을 삭제한 뒤 다시 올리세요’ + [모델에서 열기] · [다시 검사].
- 새 엔터티가 기존 엔터티를 부모로 참조하는 것은 중복이 아니다 → ‘기존 부모 참조(연결)’ 배지로 따로 보인다.
- 삭제 후 다시 추가하면 운영 DDL이 DROP/CREATE로 바뀔 수 있다는 경고를 붙인다. ALTER 짝짓기는 물리명 · 안정 id로 보강한다(F 참고).

**완료 화면**
- [표준 맞추기]를 주 버튼으로 한다.
- 안내 순서: ‘자동 배치 ✓ → 표준 맞추기 → 모델링 → 모델 검증 → 신청’.

### D. 모델 검증 → 신청 — P-5 · P-6
**화면**
- 상단에 [모델 검증] 패널 하나를 둔다. 지금의 검토 · 확정 전 점검 · 게이트 A의 항목을 표준 · 이름/설명 · 구조로 나눠 담고, 각각 막음/경고 등급을 붙인다.
- 엔터티 탭에 ‘정의’ 칸을 넣는다. 엑셀의 테이블 설명도 여기에 보인다.
- 정의 · 속성 설명 누락은 실제 데이터로 판정한다.
- rules.html에 ‘모델 입력 규칙’(막기/경고)을 둔다. 기관이 바꿀 수 있다.

**판정 공용화**
- `packages/rules`에 `modelCheck(snapshot, policy)` 하나를 둔다.
- 이것을 편집 중 표시 · 확정 신청 · 서버 재검사 · 승인 재검사에서 함께 쓴다.
- 신청 시점의 검수 기준 버전을 스냅샷에 넣는다.
- [확정 신청] 배지 숫자 = ‘막음’ 건수.

### E. 승인 검토 · 승인본 DDL — P-7
- 결재 상세에 [제출 사본 항목] 탭을 둔다: 엔터티 · 테이블 · 속성 · 컬럼 · 타입 · 길이 · 소수점 · 설명, ‘변경분만’ 필터. 모델 표 보기 부품을 다시 쓴다.
- DDL 기본 기준 = 최신 확정본.
  - 작업본은 ‘미리보기 — 승인 전’으로 낮춘다.
  - 내려받기 · 공식 산출물은 확정본만 허용한다.
  - 결재 중에는 결재선 · 신청자에게 제출 사본 DDL을 연다.
- 승인 완료 토스트와 결재 상세에 [이 확정본으로 DDL]을 둔다.
- 감사 기록에 결재 문서 ID와 스냅샷 해시를 남긴다.
- 설계 §5.5에 ‘공식 DDL = 확정 스냅샷’을 적는다.

### F. 테이블 ERD · 표기 · 밀도 — ERD-1 · 2 · 4
- 물리 캔버스를 ‘테이블 ERD’로 한다.
  - 한 줄 = PK · 컬럼명 · 타입 · 길이 · 소수점 · 속성명(UX 리뷰 §3-3 폭 안).
  - 노드 최대 너비는 약 560으로 늘리고, 열 표시를 고를 수 있게 한다.
- model-doc 속성을 `{type, len, scale}`로 나눠 저장한다(T-P2-402).
- ALTER · 결재 비교 짝짓기를 안정 속성 id + 물리명 보조로 바꾼다.
- 표기 정리
  - `#` 대신 키 구역 + ‘PK’ 글자를 쓴다.
  - 1:1 선은 식별 여부를 따른다.
  - 범례는 IE 조합 4종 + 실선/점선 + 키 · (FK)로 바꾼다.
  - 관계선을 FK 행에 붙이는 일도 같은 차수에 한다.
- 캔버스 밀도 ‘촘촘 16px’을 둔다(글자 12px 유지). 표 밀도 설정과 묶고, 줌 기준은 문서와 목업을 하나로 맞춘다.

| M-3 | 처음 업로드에 중복이 있으면 파일 전체를 막을까? | 처음 업로드는 전체를 막는다. 엔티티 추가는 중복만 빼고 추가한다 |
| M-4 | 기존 영역 업로드: 병합 · 덮어쓰기(26 §6-1)를 없애고 ‘추가만’으로 할까? 중복 비교 범위는? | W1은 ‘추가만’, 병합 · 덮어쓰기는 W2. 범위 = 같은 시스템 전체, 지금 작업본 이름 기준 |
| M-5 | PK 삭제 시 ‘FK만 끊기’의 뜻 | 관계는 유지하고 자식 컬럼은 일반 속성으로 남긴다. 식별 관계는 자식 PK에 남긴다. [FK도 삭제]는 없앤다 |
| M-6 | ‘설명이 제대로 입력됨’의 기준과 등급 | 비어 있음 = 막음. 이름과 같음 · 5자 미만 = 경고. 기관이 rules에서 조정한다 |
| M-7 | 작업본(승인 전) DDL 내려받기 | 미리보기만 허용. 내려받기 · 공식은 확정본(결재 중에는 제출 사본은 결재선만) |
| M-8 | `#` PK 기호 · 테이블 ERD 범위 | `#`를 없애고 ‘PK’로. 테이블 ERD = 물리 캔버스 6칸. 통합 보기는 그대로 |
| M-9 | 우선순위 변경(20-priority) | LG-R07(FK 상속 이름 충돌)과 LG-R05(키 표시 통일)를 W2/P5에서 **W1(P2)**로 올린다. DG-R02(자동 배치 버튼)는 W2 유지(가져올 때 배치로 충분) |
