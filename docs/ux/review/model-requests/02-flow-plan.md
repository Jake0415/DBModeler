> 목표 흐름(사용자 확인 2026-11-26). 각 단계가 끝나면 **다음 단계로 가는 길이 화면에 바로 보이고**, 앞 단계의 결과가 다음 단계에 그대로 이어지게 한다.
>
> ```
> 0. 사전 준비      공통표준 + 기관 사전 엑셀 일괄(SC-13) → 결재 → 사전 확정
> 1. 모델 등록      모델 정의서 엑셀 업로드(SC-36a) — 이름 중복 · 필수만 막고 일단 등록
> 2. 표준 입히기    표준 맞추기(SC-34) — 사전에 있는 용어는 일괄 적용
> 3. 남은 것 처리   용어 자동분석(SC-35) — 사전에 없는 단어 · 용어를 한 번에 신청 → 모델 반영
> 4. 모델링 · 검증  자동완성으로 표준 용어 입력 → 모델 검증 → 확정 신청
> ```
>

## 1. 지금 연결 상태

| 넘어가는 곳 | 지금 | 판정 |
|---|---|---|
| 0 → 1 사전 일괄 끝 → 모델 등록 | 사전 엑셀 일괄(excel-import.html)은 신청 → 결재함으로 끝나고, 모델 쪽으로 가는 안내가 없다. 홈의 빈 영역 ‘다음 행동’은 `모델 시작`(model.html, home.html:142)이고, 빈 모델 캔버스에는 엑셀로 시작하는 안내가 없다. 엑셀 정의서 가져오기는 모델 화면 ‘더 보기’ 메뉴(model.html:24)와 시스템 화면 업무 영역 만들기 [엑셀로 만들기](system.html:45)에만 있다 | **끊김** |
| 1 업로드 미리보기 | 구조 검사(이름 중복 · 필수)만 보인다. 표준 상태(사전에 있는 용어가 얼마나 되는지)는 가져온 뒤 SC-34에서 처음 보인다. 사전 신청이 결재 중이면 결과가 ‘신청 중’으로 나오는데 그 안내도 없다 | 부분 |
| 1 → 2 업로드 완료 → 표준 맞추기 | 완료 화면 주 버튼 [표준 맞추기](import-excel.html:467) — 좋음. 그런데 SC-34가 **“DDL 가져오기가 끝나 자동으로 열었습니다”**라고 쓰고(standardize.html:101), 결과 요약을 읽는 `dbm-import-last`는 DDL 가져오기(import.html:137)만 남겨 엑셀 결과 요약이 안 보인다 | **결함** |
| 2 SC-34 안에서 3으로 | [용어 자동분석]은 머리 도구줄의 작은 버튼(standardize.html:31 · 99) 하나. 미등록 단어 · 조합 가능이 많이 남아도 그 자리에서 권하지 않는다. SC-34도 조합 가능 → 용어 신청 묶음, 미등록 → 후보 등록을 직접 해서(standardize.html:265~273) **마법사와 역할이 겹친다** — 어느 쪽을 써야 할지 모름 | 부분 · 혼란 |
| 2 적용 뒤 | 적용하면 모델 화면으로 돌아가고(standardize.html:274 `dbm-apply` → model) 끝. ‘남은 할 일 n건 — 용어 자동분석으로’ 같은 다음 안내가 없다 | 끊김 |
| 3 마법사 끝 → 4 | ⑤ 모델 반영 → [모델에서 보기](term-wizard.html:713). 신청 용어가 승인되면 모델 항목이 ‘재검토 가능’으로 알림(02-flows T4) — 좋음. 표준 맞추기 · 모델 검증으로 돌아가는 진행 맥락은 없다 | 부분 |
| 4 모델 검증 | 표준 항목은 ‘표준 맞추기에서 한꺼번에’ 링크가 있다(model.html:1109). 그러나 **업로드 때 경고로 넘긴 구조 문제(FK 후보 · 타입 불일치 · 논리명/설명 불일치 · 정의 누락)는 한 건씩만** 고칠 수 있다(정의는 [입력], FK 후보는 관계를 하나씩) | **빈틈** |
| 전체 | 지금 어느 단계인지, 다음에 뭘 할지 보여 주는 곳이 없다. 모델 화면 사전 패널의 [엑셀 가져오기](model.html:62)는 **사전** 일괄이고 ‘더 보기’의 [엑셀 정의서 가져오기]는 **모델** 가져오기라 이름이 헷갈린다 | 혼란 |

## 2. 개선 항목

### A. 꼭 할 것 — 흐름이 끊기거나 틀린 곳

| ID | 단계 | 개선 | 화면 · 파일 |
|---|---|---|---|
| A-1 | 1 → 2 | SC-34 진입 문구를 출처별로: 엑셀이면 ‘엑셀 정의서 가져오기가 끝나 열었습니다 — 테이블 n · 컬럼 n · 경고 n’. 엑셀 가져오기도 `dbm-import-last`(출처 `excel` 표시)를 남긴다 | standardize · import-excel |
| A-2 | 전체 | **‘처음 표준화’ 진행 띠**: 가져오기로 만든(또는 아직 확정 전인) 영역의 모델 · SC-34 · SC-35 위에 `① 모델 등록 ✓ → ② 표준 입히기 → ③ 남은 용어 → ④ 검증 · 신청` 띠. 지금 단계만 주 버튼, 끝난 단계는 ✓ + 건수, 숫자는 실제 계산(표준 미준수 · 미등록 · 막음). 닫으면 그 영역에서 다시 안 뜸(마이페이지에서 다시 켜기) | model · standardize · term-wizard · app.js(공용 띠) |
| A-3 | 2 → 3 | SC-34 역할 정리: **SC-34 = 사전에 있는 것을 입힘**(표준 · 사전에 있음 일괄 적용, 예외 · 비대상). **조합 가능 · 미등록 단어가 남으면 마법사로 보낸다** — 할 일 칩 옆에 ‘사전에 없는 단어 · 용어 n건 — [용어 자동분석으로 한 번에]’(지금 고른 행 · 필터를 마법사 ①의 대상으로 넘김). SC-34의 ‘용어 신청 묶음’ · ‘후보 등록’은 1~2건용 빠른 처리로 남기되 10건 이상이면 마법사를 권하는 안내 | standardize |
| A-4 | 2 적용 뒤 | 적용 토스트/모델 복귀 띠에 ‘남은 할 일 n건(사전에 없음 n) — [용어 자동분석]’ · [표준 맞추기로 돌아가기] | standardize · model |
| A-5 | 4 | **모델 검증 일괄 처리** — 업로드 경고를 묶음 단위로 한 번에: ① FK 후보 n건 → 엑셀이 가리킨 부모 · 키로 [관계 한 번에 만들기](겹치면 중복 해소 창 한 번에), ② 타입 불일치 → [부모 키 타입으로 맞추기], ③ 정의 · 설명 누락 → **표로 한 번에 입력**(엔터티 · 속성 · 정의 칸, 붙여넣기) + [정의 채울 엑셀 받기] → 채운 파일 다시 올리기(정의 칸만 반영), ④ 논리명 · 설명 불일치 → 행별 값 고르기 | model · app.js |
| A-6 | 0 → 1 | 빈 영역 · 빈 모델에서 시작 안내: 빈 캔버스 가운데 ‘엑셀 정의서로 시작 · DDL로 시작 · 직접 그리기’, 홈 ‘다음 행동’의 빈 영역도 `엑셀로 시작`을 함께. 사전 엑셀 일괄 완료(신청 · 결재 끝) 화면에 ‘사전이 준비되면 모델을 가져오세요 — [엑셀 정의서 가져오기]’ | model · home · excel-import |
