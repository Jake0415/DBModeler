# 고객 요청 — 모델 관련 요청사항 (2026-11-25 접수)

> 원문(이미지)을 그대로 옮긴 것. 결정: **표기법은 IE(정보공학) 방식으로 통일** (사용자 2026-11-25).

## [ERD 작성]
1. 엔티티와 관계의 Notation 일치 (Barker 또는 IE 표기법 하나로 통일) → **IE로 결정**
2. 엔티티의 속성은 최대한 표시할 수 있도록 할 것 (상하 폭을 줄여서 표시)
3. 관계선은 엔티티(PK 기준집합) ➔ 자식엔티티(FK속성)에 대한 관계임
   - 관계선을 그릴 때 자식에 중복된 속성이 있는 경우 Popup을 통해 기존 중복 속성을 덮어쓰거나 다른 이름으로 변경해서 만들 수 있도록 할 것
   - PK속성이 추가될 때 FK속성이 추가되도록 한다. 이때 중복된 속성이 있으면 Popup을 통해 동일하게 해소한다.
   - PK속성이 삭제되면 FK관계만을 끊도록 한다. (삭제는 이 정도 수준에서 정리)
4. 테이블 ERD에서는 PK, 컬럼명, 타입, 길이, 소수점, 속성명을 표시하도록 한다.

## [모델 Excel 업로드]
1. 검증은 최소한으로 하여 등록하도록 한다.
   - 엔티티명 / 테이블명 중복 검사
   - 같은 개체 내 속성명 / 컬럼명 중복 검사

## [최초 프로세스]
1. 모델을 Excel로 업로드 한다. (위의 기본 검증만 통과하면 등록 가능하도록 함)
2. 자동배치를 통해 초기 Layout을 잡는다.
3. 표준등기화(표준화) 작업을 통해 표준을 입히도록 한다.
4. 모델링 작업을 진행한다.
   - 속성 입력 시 표준용어를 사용하여 모델링 진행
5. [모델검증] 모델에 대한 검증 작업을 진행한다.
   - 표준을 모두 준수하고 있는지 검증
   - 엔티티명/엔티티설명이 제대로 입력되어 있는지 검증
   - 속성설명이 제대로 입력되어 있는지 검증
   - 기타 검증 추후 확인
6. [모델신청] 위 5번을 통과하는 경우 모델신청이 가능하도록 한다.
7. [모델승인] 신청된 시점의 엔티티/테이블/속성/컬럼 정보에 대한 검토기능 필요
   - 검토 후 승인이 되면 승인된 기준의 DDL생성 기능 필요

## [엔티티 추가 프로세스]
1. 추가된 엔티티를 Excel 업로드 하도록 한다.
   - 기존에 중복된 엔티티가 있는 경우 중복여부를 표시하고 추가하지 못하도록 한다.
   - 삭제 후 추가할 수 있도록 가이드 예정
