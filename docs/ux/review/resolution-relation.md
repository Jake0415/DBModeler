## 두 검토가 같은 것 (그대로 반영)

| 주제 | 반영 |
|---|---|
| 연결은 묻지 않고 부모 PK 전체를 FK로 | makeRel · 확인 0회 · 토스트 [실행 취소] |
| 부모 PK 없으면 막지 말고 ‘FK 대기’ | 관계만 생성 · [식별자 지정] · 패널 경고 |
| 재귀는 PK 전체 · 역할명 · 그룹 · 선택 0..1 | `UPR_` 컬럼 전체 · `fkg` · 선택성 ‘없어도 된다’ |
| ON DELETE는 물리 · 모델 삭제와 분리 | 패널 ‘DB 반영 (물리)’ 접힘 영역 · 삭제 띠에 ‘DB 행은 바뀌지 않습니다’ |
| SET NULL은 FK가 비울 수 있을 때만 | 선택지 비활성 + 이유 · 선택성 ‘반드시’로 바꾸면 ‘막기’로 되돌림 |
| 1:1 비식별은 FK 조합에 UK | syncUk · DDL `UNIQUE` · 1:N으로 바꾸면 UK 삭제 |
| 삭제는 조건 표 · FK 묶음 기준 | relDelete · 옛 데이터 normalizeGroups(`gAuto`) |
| 영향 미리보기 · 한 번에 실행 취소 | 세 줄 요약 + [자세히] · 엔터티 강조 · snap 한 번 |
| 키보드 경로 · 라이브 알림 | `R` → 자식 고르기 목록 · `Delete` · agLive |
| 결재 비교에 DB 동작 따로 | ‘DB 동작 변경’ 묶음 · CASCADE 경고 배지 |

## 엇갈린 것과 결정

| # | 주제 | Claude | Codex | 결정 | 이유 |
|---|---|---|---|---|---|
| R1 | 삭제 기본값 · 포커스 | 컬럼도 정리가 기본(DA#·ERwin), 기본 버튼 포커스 | 컬럼 보존이 기본, 처음 포커스 [취소] | **Codex.** 첫 버튼(primary) = 컬럼을 남김, 삭제는 danger, 포커스 [취소] | 실행 취소가 있어도 컬럼 삭제는 손자까지 번진다. 남긴 컬럼은 나중에 지우기 쉽지만 지운 컬럼의 역할명·설명은 되살리기 어렵다 |
| R2 | 역할명 팝오버의 Esc | 제안값으로 확정(흐름 유지) | 적용 전 확인, 취소 가능 | **Esc = 연결 취소.** Enter = 제안값 확정 | Esc는 어디서나 ‘취소’로 배운다. 속도는 Enter 한 번으로 지킨다. 재귀 확인 팝오버는 없애서 확인은 한 번 |
| R3 | 패널 적용 단위 | 즉시 반영 + 실행 취소 | 임시 변경 후 [적용] | **나눔.** 단일 값(이름·카디널리티·선택성·ON DELETE·FK 짝)은 즉시, **식별 전환**은 미리보기 띠 + [적용] | 엔터티 속성 패널과 같은 즉시 반영 습관을 지킨다. 손자 PK까지 바뀌는 전환만 먼저 보여 준다 |
| R4 | 비식별 기본 선택성 | (명시 없음, 목업은 ‘없어도 된다’) | 자식 1건당 부모 1(FK 필수) | **Codex.** 기본 ‘반드시 있다’, 재귀만 ‘없어도 된다’ | 업무 테이블 FK 대부분이 필수다. 기본 ‘막기’와도 맞고 SET NULL 오용을 막는다 |
| R5 | 식별 삭제의 선택지 | 키 정리 / 식별자로 남김 2개 | PK 유지 / 일반 컬럼 / 삭제 3개 | **Codex.** 자식에 다른 PK가 있고 손자가 없을 때만 ‘PK에서 빼고 일반 컬럼으로 남김’ 추가 | 남는 PK가 없거나 손자가 있으면 그 선택은 키를 깨뜨린다 |
| R6 | CASCADE 경고 | 이어지는 테이블 목록 | 자식 행 영향 알림 | **보강.** CASCADE로만 따라가고, 그 아래 ‘막기’ 테이블은 ‘삭제 전체가 실패’로 따로 알림 | 처음 목업은 식별 관계도 연쇄로 셌다. 막기인 식별 자식은 연쇄가 아니라 실패를 부른다 |

## 목업 확인 (2026-11-20, 인사관리 영역)
