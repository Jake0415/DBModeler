# 목업 v6 독립 검증 — Claude (r9)

> 대상: `docs/ux/mockups/` v6 (공통 `assets/app.js` 상태 계층 + 화면별 HTML). 기준: [06 §4.5](../06-ux-review-plan.md) 합의 Top 10·S1~S6, v6 주장 범위 06 §4.6, 엑셀 왕복 기준 [07](../07-dict-excel-roundtrip.md).
> 판정 기준(합의): **닫힘 = 입력부터 결재·반영·재진입까지 끝까지 이어질 때.** 서버 없음·가짜 데이터·파일 생성 같은 목업 한계는 지적하지 않고, 입력 무시·완료 오인·잘못된 권한/판정·화면 간 불일치만 봅니다. 모든 근거는 HTML/JS를 직접 읽은 파일:줄입니다.
> 새 ID 접두어: **CL9**. Codex r9는 읽지 않았습니다.

## 1. 총평

1. **v6 Top 10 닫힘 1/10**(#10 마무리), 나머지 9개는 부분입니다. **S1~S6 닫힘 0/6**(모두 부분)이고, 가장 가까운 것은 S3(엑셀·사전의 덮어쓰기 문제는 닫힘)과 S1(엑셀·사전 제출 고정은 닫힘)입니다.
2. 실제로 좋아진 것: 엑셀 묶음의 문서별 `sub`·`items` 고정과 신청 묶음 열람 전용(CL7-01·02·04 닫힘), `updateNeeds`+`setBlock`(CL7-03 닫힘), 사전 항목이 상태 계층에 올라감(승인 → V1/V+1·항목별 변경 내역, CL8-01·02 닫힘), 모델 영역·버전별 저장과 확정 스냅숏, 다음 버전 승계, 모델 편집의 `dbm-role` 재확인.
3. 남은 핵심은 **"끝"이 아직 한쪽만 이어진다**는 점입니다. 승인 쪽은 이어졌지만 **반려·회수 쪽은 사전 항목의 진행 중 표시를 풀지 않고**(CL9-07), **표준 맞추기 용어 신청은 항목이 없는 빈 문서**라 승인돼도 사전·모델이 바뀌지 않습니다(CL9-09). `applyDictDoc`는 없는 항목 ID를 만나면 실패 대신 **새 항목을 만듭니다**(CL9-08).
4. v6 변경이 만든 문제: **예시 주소와 저장의 충돌**(`?state=confirmed`면 편집이 저장되지 않고 사라짐, `?state=resolved`에서 확정 신청이 가능해 예시 데이터가 공식 스냅숏이 됨 — CL9-01·02), **같은 버전을 두 탭이 편집하면 마지막 저장이 덮음**(CL9-03), 없는 묶음을 재개하면 안내와 반대로 새 묶음을 저장(CL9-13).
5. 다음 단계: 목업에서는 **반려·회수 경로, 표준 맞추기 → 사전 → 모델 왕복, 예시 주소의 읽기 전용화**만 마무리하면 됩니다. 실행 시점 권한(결재함은 페이지 로드 때의 `ME`로 판정), 동시 편집, 반영 트랜잭션·이름 유일성은 목업으로 고칠 수 없으므로 **구현 설계(서버 판정·API)로 넘길 때**입니다.
