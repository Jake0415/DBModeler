# 리뷰 — 목록 화면 표준 v0.1 (Claude · UX 관점)

**총평:** 방향(사전 기준 통일 · 주소 저장 · 빈 결과 3종)은 맞다. 그러나 ① 처리 큐의 현재 동작(첫 행 자동 선택 · 다음 문서 자동 이동)을 '기본 닫힘'으로 되돌리려 하고, ② 키보드 · 화면낭독기 규칙이 거의 없으며, ③ 검색 규칙 중 '2글자 앞부분 일치'가 AND 낱말 검색 · 감사 로그와 충돌한다. 이 셋을 고치면 쓸 만한 표준이 된다.

## 지적 목록

### CL-01 · 높음 · 처리 큐는 이미 '첫 행 자동 선택'이다 — L-9 '기본 닫힘'은 퇴보
- 근거: 결재함은 들어올 때와 함을 바꿀 때 첫 문서를 고른다(`approvals.html:742`, `:711`). 처리 뒤에는 다음 문서로 넘어가고 "대기함을 모두 처리했습니다"라고 알린다(`:698-699`). 후보 큐(`candidates.html:66`, 패널 `:31`)와 업로드 이력(`uploads.html:42`)도 첫 행을 고른다. §0 표에는 이 사실이 없다.
- 권고: 과업으로 나눈다. **처리(triage)** 화면은 첫 행 자동 선택 + 처리 뒤 다음 행으로 이동. **찾기 · 감사** 화면은 기본 닫힘. Q3 답으로 L-9에 적는다.

### CL-02 · 높음 · 모든 행이 Tab 정지점 — 500행이면 패널까지 Tab 500번
- 근거: `wire()`가 모든 `tr.click`에 `tabIndex = 0`을 준다(`app.js:2075`). 사전은 500행까지 그린다(`dictionary.html:290`). 패널은 표 뒤에 있다(`dictionary.html:106`). 행에 `aria-selected`도 없다.
- 권고: 행은 **로빙 tabindex**(고른 행만 0, 나머지 -1). 표에서 Tab 한 번이면 패널로 간다. 고른 행에 `aria-selected="true"`를 준다(표는 `role="grid"` 또는 목록 패턴 중 하나로 통일).

### CL-03 · 높음 · 건수 알림이 시끄럽다 — 건수 줄 전체가 live region
- 근거: 사전 건수 줄은 `aria-live="polite"`(`dictionary.html:93`)인데, 매 입력마다 버튼 · 조건 칩 · 키 안내까지 통째로 다시 그린다(`:303-305`). 변경 내역(`dict-history.html:28`), 도메인 그룹(`domain-groups.html:80`)도 같다. 감사 로그 건수 줄은 live가 없다(`audit.html:37`). `filterRows`는 건수를 아예 고치지 않는다(`app.js:2082-2086`).
- 권고: 건수 줄과 별도로 **숨은 알림 칸 하나**(`role="status"`)에 "12건"만, 입력이 멈춘 뒤(약 500ms) 알린다. 건수가 같으면 다시 알리지 않는다.

### CL-04 · 높음 · '2글자 이하 앞부분 일치'가 AND 낱말 · 짧은 이름과 충돌
- 근거: 사전은 2글자면 이름 첫머리만 본다(`dictionary.html:264`, `:278`). L-2는 이를 모든 화면에, 낱말별 AND와 함께 쓰라고 한다. 그러면 "고객 번호"는 '번호'가 첫머리가 아니라서 '고객번호'를 못 찾는다. 감사 로그에서 '철수'로 '김철수'를, 결재함에서 '12'로 'REQ-0012'를 못 찾는다.
- 권고: 앞부분 일치는 **1.6만 건 화면(사전 · 공통표준)만**, 그것도 낱말 하나일 때만. 그 밖은 포함 일치. 한국어 띄어쓰기 차이는 **공백을 지운 값끼리도 비교**해 흡수한다.

### CL-05 · 높음 · 빈 결과의 머리줄 숨김은 '행 숨김' 방식에서 동작하지 않는다
- 근거: CSS는 `tr.er`가 **유일한 자식**일 때만 머리줄을 숨긴다(`app.css:486`). 감사 로그(`audit.html:72-78`), 마이페이지(`mypage.html:122`), `filterRows`(`app.js:2084`)는 행을 `display:none`으로 숨기므로 빈 행이 유일 자식이 아니다. L-6 "지금 CSS 그대로"는 틀렸다.
- 권고: 목록은 숨기지 말고 **다시 그린다**(listView). 또는 표에 `.is-empty` 클래스를 붙여 머리줄을 숨긴다.

### CL-06 · 중간 · §0 조사 오류 · 빠진 화면
- 근거:
  - 감사 로그에는 이미 `er none` + '필터 지우기'가 있다(`audit.html:73`). 칩은 8개(> L-1 상한 7, `:25-32`)이고, 내보내기가 "현재 필터 기준"으로 동작한다(`:83`).
  - 마이페이지에도 `er none`이 있다(`mypage.html:122`). 칩은 span이다(`:47`).
  - 사전 '종류'는 칩이 아니라 `.seg`이다(`dictionary.html:76`). 팝오버 버튼 이름은 '조건'이 아니라 '필터'이다(`:78`). 검색어는 적용된 조건 칩에 들어가지 않는다(`:298-303`).
  - 사전 검색도 L-2와 다르다. 첫 번째로 맞은 칸만 보고, 설명은 대소문자를 구분한다(`dictionary.html:250-260`). L-2는 기준 화면 정리가 아니라 **새 규칙**이다.
  - 빠진 화면: 결재 문서 안 **항목 목록**(검색 · 필터 · 건수, `approvals.html:275`, `:302`), 사전 그리드(`dict-grid.html:134`).
- 권고: §0을 고치고 L-2 앞에 "사전도 맞춰 고친다"를 적는다.

### CL-07 · 중간 · 숨은 선택은 '표시'가 아니라 '적용 범위'의 문제
- 근거: 모델 표는 "표시된 선택 n · 숨겨진 선택 m"을 보이고, 기본 행동은 **표시된 n개만** 적용한다. 숨은 행까지는 두 번 눌러야 적용된다(`model.html:1120-1125`). 찾아 바꾸기도 "숨긴 행은 그대로"이다(`:1150`). L-10은 문구 표시만 옮겼다.
- 권고: 이 동작을 L-10 규칙으로 올린다(아래 '추가 규칙' R-6).

### CL-08 · 중간 · 감사 로그는 L-1의 예외가 필요하다
- 근거: 감사는 '누가 · 언제 · 무엇을'을 좁히는 일이다. L-1은 기간을 팝오버에 넣으라고 한다. 감사 로그는 기간이 주축이고 기본값이 '전체'이다(`audit.html:34`). 5년 보존 로그에 기본 '전체'는 무겁다. 사용자 · 대상 거르기도 없다.
- 권고: "화면의 **주축 조건 하나**는 도구줄에 둘 수 있다"를 예외로 둔다. 감사 로그 기본은 최근 30일로 하고, 사용자 · 대상은 칸별 검색으로 찾게 한다.

### CL-09 · 중간 · Esc · Enter 우선순위가 없다
- 근거: L-2는 "Esc = 검색어 지우기", L-9는 "Esc = 패널 닫기"라고 한다. 전역 Esc는 대화상자를 닫는다(`app.js:2064`). 사전은 한글 조합 중 Enter를 막는데(`dictionary.html:404` `isComposing`), 표준에는 이 내용이 없다.
- 권고: R-3으로 순서를 정한다.

### CL-10 · 중간 · 기존 주소 키와 충돌 — 링크가 깨진다
- 근거: 이미 `doc`(결재함, `approvals.html:741`), `b`(업로드, `uploads.html:35`), `c` · `f`(후보, `candidates.html:56`), `user`(설정, `settings.html:310`), `pub`(변경 내역), `as` · `audit` · `ret`(검토 모드 · 되돌아가기, `app.js:2092`, `:2104`)를 쓴다. 감사 로그는 `approvals.html?doc=`로 링크한다(`audit.html:51`).
- 권고: `sel`로 바꾸더라도 옛 키는 **별칭으로 계속 읽는다**. `as/audit/ret`은 listView가 지우지 않는다.

### CL-11 · 중간 · §3 listView 하나로 모두 묶는 것은 위험
- 근거: 트리(도메인 그룹 `←→`, `domain-groups.html:535`), 칸 편집 · 되돌리기(엑셀 5단계), 캔버스와 같이 쓰는 표(모델)는 같은 틀에 맞지 않는다.
- 권고: 작은 부품으로 나눈다. `listMatch` · `urlState` · `countLine` · `emptyRow` · `rovingRows`. listView는 이것들을 조합한 얇은 껍데기로 두고, 화면은 필요한 부품만 쓴다.

### CL-12 · 낮음 · 부품 선택 기준이 감각에 기댄다 · 용어가 섞인다
- 근거: '다른 집합'(세그먼트)과 '거르기'(칩)의 경계가 모호하다. 사전 '종류'는 세그먼트로 남기고 도메인 그룹 '상태'는 칩으로 바꾸는데, 그 이유가 적혀 있지 않다. 용어도 '조건'(L-1) · '필터'(`dictionary.html:78`) · '조건 초기화'(L-4)가 섞여 있다.
- 권고: 판정 기준을 하나 둔다. "**열 · 행 행동 · 기본 정렬이 바뀌면** 세그먼트, 같은 열에서 행만 줄면 칩". 용어는 사용자에게 익숙한 '필터' 하나로 정한다(버튼 '필터', 팝오버 안 '필터 초기화').

## 표준에 추가할 규칙 (그대로 붙여 넣기용)

**R-1 접근성.** 행은 로빙 tabindex를 쓴다(고른 행만 Tab 정지). 고른 행에는 `aria-selected="true"`를 준다. 정렬 칸은 `<th aria-sort>` 안의 `<button>`으로 만든다. 칩 묶음은 `role="group"` + `aria-label`을 갖는다. 결과 건수는 숨은 `role="status"` 칸에 "n건"만, 입력이 멈춘 뒤 한 번 알린다.

**R-2 패널 포커스.** 행을 눌러 패널이 열려도 포커스는 행에 남는다. 표에서 Tab 한 번이면 패널로 간다. 패널을 닫으면 그 행으로 포커스를 돌려준다.

**R-3 키 우선순위.** Esc는 대화상자 → 팝오버 → (검색 칸에 글자가 있으면) 검색어 지우기 → 패널 닫기 순으로 하나만 처리한다. 한글 조합 중(`isComposing`)의 Enter · 화살표는 무시한다.

**R-4 한국어 검색.** 공백을 지운 값끼리도 비교한다(띄어쓰기 차이 흡수). 초성과 완성 글자가 섞인 입력(예: "고ㄱ")도 글자별로 비교한다. 영문 약어는 대소문자를 무시한다. 앞부분 일치는 1만 건 이상인 화면에서, 낱말 하나일 때만 쓴다.

**R-5 내보내기.** 내보내기는 '현재 조건에 맞는 전체'(그리기 상한과 무관)를 대상으로 한다. 버튼이나 확인 문구에 건수를 적고("128건 내보내기"), 파일 첫 줄에 적용 조건을 남긴다.

**R-6 숨은 선택 · 전체 선택.** 일괄 행동의 기본 대상은 **보이는 선택**이다. 숨은 선택을 포함하려면 별도 버튼과 두 번째 확인을 거친다. 머리줄 체크로 보이는 행을 모두 고르면 건수 줄에 "조건에 맞는 전체 n건 고르기"를 보인다.

**R-7 실시간 갱신.** 보고 있는 동안 들어온 새 항목은 목록에 끼워 넣지 않는다. 건수 줄에 "새 항목 n건 · 새로 고침"으로 알린다. 처리해서 조건에서 빠진 행은 다음 행으로 넘어간 뒤에 사라진다.

**R-8 로딩 · 오류.** 첫 로딩은 표 모양 뼈대로 보인다(`?skel=1` 방식). 다시 거를 때는 기존 행을 유지한 채 건수 줄에 '불러오는 중'을 표시한다. 실패하면 `er` 자리에 "불러오지 못했습니다 · [다시 시도]"를 보이고, 조건은 지우지 않는다.

**R-9 열.** 가로로 넓은 표(엑셀 5단계 · 모델 표)는 식별 칸(이름 · ID)을 왼쪽에 고정한다. 열 너비 조절 · 숨김은 사용자별로 브라우저에 저장하고, 주소에는 넣지 않는다.

**R-10 기본 보기.** 화면마다 '조건 없는 기본 상태'를 정의하고 건수 줄에 적는다(예: 사전 = 최근 변경 8건, 결재함 = 내 차례 우선, 후보 = 대기, 감사 = 최근 30일). '모두 지우기'는 이 상태로 돌아간다.
