## ① 요약

사전 검토의 핵심이 거의 그대로 들어갔다.
- 묻지 않는 연결, FK 대기
- 문장 두 줄의 카디널리티 · 선택성(FK NOT NULL과 연동, 그리드 FK 필수 칸 잠금)
- 「DB 반영(물리)」에 ON DELETE를 분리하고, 삭제 띠에 "운영 DB의 행은 바뀌지 않습니다"를 넣음
- FK 묶음 기준 삭제 조건 표, 300ms · 취소 포커스 · 한 번 실행 취소
- Oracle 막기 = 절 생략, 1:1 UK와 DDL `UNIQUE`, 결재 비교의 "DB 동작" 묶음

T1 · T2 · T9는 통과다. 실패 · 부분 통과는 다섯 갈래다.
1. **나중에 부모 PK를 정할 때(T5) 채워지는 FK가 관계의 선택성(기본 '반드시')을 따르지 않고 NULL 허용으로 생긴다.**
2. **역할명 팝오버의 Esc가 포커스 위치에 따라 결과가 다르다.** 팝오버 안에서는 연결 취소, 캔버스에서는 팝오버만 닫히고 관계가 남는다. 취소가 `undo()`라 다시 실행으로 되살아난다.
3. **재귀 · 세 번째 관계에서 제안 이름이 기존 컬럼과 같아** 같은 물리명 컬럼이 두 개 생길 수 있다.
4. **결재 비교의 선택성 비교가 저장된 원본 값만 봐서** 잘못된 행이 나온다. FK 짝 변경은 비교에 나타나지 않는다.
5. **카디널리티 '0~1개'는 1:1과 같은 제약이 필요한데 UK가 붙지 않는다.**

## ③ R1~R6 평가

| # | 결정 | 평가 | 사용자 입장의 장단 · 보완 |

| R1 | 삭제 첫 버튼 = 컬럼을 남김, 포커스 [취소] | **보완** | 장점: 실수로 Enter를 두 번 눌러도 아무것도 지워지지 않고, 역할명 · 설명이 보존된다. 단점: DA# · ERwin 습관대로 "관계 지우기 = 이주된 FK도 사라짐"을 기대한 사용자는 primary를 눌러 **부모 PK와 이름이 같은 '일반 컬럼'**을 남긴다. 겉으로는 FK처럼 보여 다음 사람이 헷갈리고, 표준 맞추기에서도 FK가 아닌 중복 컬럼으로 남는다. **보완**: ① 남긴 컬럼에 "관계 없음 · 이전 FK" 표시(그리드 보조 줄 · 트리 거르기 "관계 잃은 컬럼")를 붙여 나중에 정리하기 쉽게 한다. ② 토스트에 [이 컬럼도 지우기] 바로가기를 둔다(실행 취소와 같은 줄). ③ 사용자별로 마지막 선택을 기본으로 기억하는 설정은 두지 않는다(실수 방지 원칙 유지). |
| R2 | 역할명 팝오버 Esc = 연결 취소, Enter = 제안값 확정 | **보완** | 장점: Esc의 뜻이 어디서나 같고, Enter 한 번이면 흐름이 이어진다. 단점: 사용자는 연결이 **이미 끝난 뒤** 질문을 받는다. 팝오버가 모달이 아니라서 Esc를 어디서 누르느냐에 따라 결과가 갈린다(T3 실패 1). 연결 취소가 다시 실행으로 되살아난다(실패 2). **보완**: ① 팝오버가 떠 있는 동안 전역 Esc도 cancel 경로로 보낸다(또는 포커스를 팝오버에 가둔다). ② cancel은 `undo()` 대신 makeRel의 snap id로 `dropHist` + 상태 복원을 하고 redo에 넣지 않는다. ③ 팝오버 밖을 누르면 "제안값으로 확정"으로 처리하고 토스트에 알린다(묵시적 확정을 보이게). |
| R3 | 단일 값은 즉시, 식별 전환만 미리보기 + [적용] | **동의** | 엔터티 그리드와 같은 즉시 반영 습관에 맞고, 손자까지 바뀌는 것만 멈춰 세우는 기준이 분명하다. 보완 한 가지: 미리보기 처음 포커스를 [적용]이 아닌 [취소] 또는 띠 제목으로(지적 #8). |
| R4 | 비식별 기본 '반드시 있다' | **동의(구현 보완)** | 업무 FK 대부분과 맞고 SET NULL 오용을 줄인다. 다만 FK 대기 뒤 채워지는 FK(T5)와 옛 관계(nn 기반)에서 이 기본이 지켜지지 않는다. pkSpread가 `relOf(r).opt`를 따라야 한다. |
| R5 | 식별 삭제 3안은 조건부 | **동의** | "남는 PK가 없거나 손자가 있으면 PK에서 빼기를 숨김"은 키를 깨는 선택을 원천 차단해 좋다. 버튼 문구도 결과를 말한다. |
| R6 | CASCADE는 CASCADE로만 따라가고, 아래 '막기'는 실패로 따로 알림 | **보완** | 연쇄 아래의 막기는 잘 잡는다. 같은 부모의 **형제 관계**(다른 자식이 막기)도 부모 행 삭제를 실패시키므로 함께 알려야 한다(T7). 이름(`ent.n`)이 아닌 id로 모으면 동명 엔터티에도 안전하다. |
