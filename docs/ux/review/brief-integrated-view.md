## 구현 요약
- 노드 한 줄 = 논리명 │ 물리명(없으면 ‘— 미매핑’) │ 타입(없으면 ‘— 타입 미정’). 미매핑 n 배지. 서브타입은 ‘물리: 한 테이블로 합침’.
- 배치: 통합 위치 = 논리 위치 × SX · SY(영역별로 노드 최대 크기를 재서 계산, 1 ~ 2.4 / 1 ~ 1.8). 통합에서 옮기면 나눠서 논리 위치에 저장, 물리 배치는 그대로. 첫 이동 때 한 번 알림.
- 이름 편집 = 논리명, 아래에 ‘물리 → XXX’ 미리 보기.
- 관계선에 FK 이름표(FK 누락 · FK 제외 표시).
- 메모: 논리 · 물리 메모를 함께 보이고 ‘논리’ · ‘물리’ 표시. 통합에서 만든 메모는 논리 메모.
- 패널 · 그리드: ‘속성 · 컬럼’, 제약 · 인덱스 탭, 시스템 컬럼, ‘속성명 / 물리명 · 타입’.
- 게이트 · 동기화 띠는 물리 · 통합에서 보임. [다음 미매핑으로] 버튼(통합만).
- 마지막 보기를 사용자 · 영역별로 기억, `?mode=` 로 열기. 전환 때 선택과 화면 위치 유지.
- 내보내기 제목 ‘논리 · 물리 통합’, 표 보기 찾기는 물리명도 찾음, 트리 속성 줄에 물리명.
- 남김: 줄별 ‘반영 대기’ 표시(동기화 데이터가 목업 고정값이라 하지 않음).

## 검토 요청
1. 28 §6 · §7 규칙과 구현이 다른 곳(빠짐 · 틀림).
2. 버그: 모드 전환 · 저장 · 되돌리기(Ctrl+Z) · 드래그 · 키보드 이동 · 메모 · 펼침 계산(SX/SY) 재계산 루프, 다른 보기(논리 · 물리) 회귀.
3. 통합에서 물리 메모를 논리 펼침 위에 물리 좌표 그대로 두는 것이 맞는가.
4. 읽기 쉬움 · 접근성(대비, aria, 키보드), 1920 화면 밀도.
5. 결과는 심각도(높음 · 중간 · 낮음) · 근거(파일:줄) · 고칠 방법으로, 한국어로.
