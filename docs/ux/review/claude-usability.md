# 사용성 검토: NeoDB 전체 목업 (Claude · UX 전문가)

- 요청: `brief-usability.md` · 기준 커밋 235763c(+ 시험 당시 작업 트리)
- **시험 방법: 브라우저 실사용.** 내장 브라우저의 새 탭(`tab-1`)에서만 조작했고, 화면 크기는 **1600×900**으로 맞췄습니다. 주소 형식은 `<화면>.html?as=<역할>&audit=1`입니다. 클릭 · 타자 · Tab/Enter · 붙여넣기로 과업을 실제로 수행했고, 근거는 그 순간의 화면(스크린샷 · read_page · DOM 측정)입니다.
- **저장소**
  - 시험 전에 `dbm-` 키 31개를 백업했습니다.
  - 시험 중 다른 탭(코디네이터)도 같은 저장소를 쓰고 있었습니다(REQ-2026-0018 신청 · 승인, 역할 변경). 그래서 백업을 통째로 되돌리지 않고 **제가 만든 것만 되돌렸습니다.**
    - 지운 것: `dbm-grid-lee`, `dbm-basket-lee`
    - `dbm-docs`에서 뺀 것: 제가 올린 REQ-2026-0019와 그 알림
    - 백업 값으로 되돌린 것: `dbm-mdata-rq-v5`, `dbm-comp-rq`, `dbm-tree3-park`
  - 나머지 차이(`dbm-dict` · `dbm-changes` · `dbm-idseq` · `dbm-role` · `dbm-basket-kim` · `dbm-grid-kim` · REQ-0018)는 다른 탭이 만든 것이라 그대로 두었습니다.
- **시험 제약**
  - 검토 모드(`&audit=1`)에서는 저장된 역할(다른 탭이 `hyun`으로 바꿈)과 주소의 역할이 다르면 처리 버튼이 모두 막힙니다(⑤ #16).
  - 그래서 엔터티 추가 · 표준 맞추기 단계에서는 **제 탭 안에서만** `window.liveRoleChanged=()=>false`로 막힘을 풀고 진행했습니다. 코드 파일은 고치지 않았습니다.
  - 자기 승인 최종 클릭은 이 막힘 때문에 끝까지 가지 못했습니다(판정 불가로 표시).
- 제외: `resolution-*.md`에 기록된 지적, 그리고 시험 도중 작업 트리에서 이미 고쳐지고 있던 것(상단 바구니 아이콘 `undefined` 표시, "신청 바구니" 문구)은 다시 내지 않습니다.
- 참고: 브리프는 `choi`를 Admin으로 적었지만, 목업 데이터에서 choi는 **owner · modeler**입니다(설정 · 감사 로그 403). Admin 과업은 `lee`(DA · Admin)로 시험했습니다.

## ① 요약

사전 작성(화면 일괄 작성)과 모델 편집의 **입력 경험은 높은 수준**입니다.
- 붙여넣기로 행이 자동으로 늘어납니다.
- 약어가 대문자로 바뀝니다.
- 작성 중인 단어로 용어를 분해해 칩으로 보여 줍니다.
- 같은 바구니 안의 의존을 판정합니다.
- 속성 자동완성에 기관 · 공통 · 신청 중 배지가 붙습니다.

반면 **결과를 확인하고 판단하는 화면이 업무 폭을 감당하지 못합니다.** 1600 화면에서 다음이 일어납니다.
- 결재 상세 패널(380px)에서는 항목 표의 글자가 한 자씩 세로로 끊깁니다. 반려 사유 칸은 24px입니다. 최종 승인자는 변경 전후 값을 읽을 수 없습니다.
- 바구니 패널에서는 표가 패널보다 두 배 넓어, 검사 결과와 [고치기 · 빼기]가 화면 밖에 있습니다.
- DA가 50건 품의에서 2건을 반려하는 과업에서는 다음 세 가지가 함께 겹쳐 실수 위험이 큽니다. 반려 표시가 새로고침하면 사라집니다. "함께 반려" 제안은 몇 초 뒤 사라지는 토스트입니다. 120건 문서에는 필터가 없습니다.

모델러 쪽에서는 다음 때문에 "다음에 무엇을 할지"가 흐려집니다.
- 미준수 해결 버튼을 누르면 미준수가 아니라 전체 목록이 열립니다.
- 캔버스 안내 배너를 닫을 수 없습니다.
- DDL 차단 항목에서 고칠 곳으로 가는 길이 없습니다.

**가장 중요한 5가지**
1. **결재 상세 패널을 넓히고 항목 표를 다시 짤 것.** 380px에서 항목 · 전후 값 · 반려 사유가 판독 불가입니다.
2. **바구니 패널의 표 넘침을 고칠 것.** 검사 열과 행 작업이 1600 화면 밖에 있습니다.
3. **바구니를 열면 바구니가 먼저 보이게 할 것.** 지금은 입력 폼이 위를 차지해 담긴 8건이 첫 화면에 없습니다.
4. **최종 승인자에게 영향(사용처)과 전후 비교를 줄 것.** 판단 근거 3요소 중 '영향'이 없습니다.
5. **DA의 항목 반려 작업을 보존하고 의존 반려 제안을 화면에 고정할 것.** 반려 표시가 새로고침에 사라지고, "함께 반려"가 토스트로 사라집니다.

## ③ 휴리스틱별 발견 (Nielsen 10)

| 휴리스틱 | 발견 |
|---|---|
| 1 상태 가시성 | 좋은 점: 화면 일괄 작성의 행 상태(빈 행 · 정상 · 경고 · 오류 · 담김), 하단 집계, 단계 탭 숫자, '자동 저장됨 14:26'. 아쉬운 점: 바구니의 검사 열이 화면 밖이라 **품의 전에 검사 상태를 볼 수 없습니다.** 결재 패널의 반려 표시는 저장되지 않는데도 저장된 것처럼 보입니다. |
| 2 실제 세계 언어 | '게이트 B', 'T-COMB', 'W-PEND', 'X-EX' 같은 내부 코드가 진단 열과 DDL 배너에 그대로 나옵니다. 도메인 타입 `C/V/N/D/T`에는 설명이 없습니다(DA# 사용자는 익숙하지만 신규 표준화 담당자는 아님). |
| 3 사용자 통제 · 실행 취소 | 담김 행의 [다시 고치기], 바구니 [빼기], 회수는 좋습니다. 결재 중 반려 표시가 새로고침에 날아가는 것은 통제를 잃는 경험입니다. |
| 4 일관성 · 표준 | 메뉴와 탭의 순서가 다릅니다. 도메인그룹 관리 정책이 설정(신청)과 사전(직접)에서 다릅니다. 단건 폼은 "마지막 형식단어 기준 도메인 추천"을 하는데 표 입력은 하지 않습니다. 엑셀 관례(Tab으로 채운 뒤 Enter하면 시작 열로)와 다릅니다. |

## ④ 정보 구조 · 디자인 · 접근성

- **상단 메뉴 · 사전 탭**
  - 4묶음 구분은 좋아졌습니다.
  - 순서는 메뉴와 탭이 같아야 합니다. 권장 순서: 찾기 · 작성(통합 검색 · 화면 일괄 작성) | 가져오기(엑셀 · 업로드 이력) | 흐름 · 이력(후보 큐 · 변경 내역) | 기준정보(도메인 그룹 · 분류 · 공통표준).
  - 설정의 도메인그룹 표는 링크로 바꿔 한 곳만 남기세요.
- **모델러의 도구 동선**
  - '표준 맞추기'(상태별 일괄 처리)와 '용어 자동분석'(모델 → 용어 → 모델 마법사)이 같은 미준수를 다룹니다.
  - 표준 맞추기를 허브로 두고, 자동분석은 그 안의 [용어 일괄 만들기 ▸]로 부르는 것이 덜 헷갈립니다.
- **패널 구조 (가장 큰 디자인 문제)**
  - 오른쪽 패널(`--panel` 380px, 1919px 이하 · app.css:106)에 표를 넣는 화면이 늘었습니다(결재 항목, 바구니). 이 폭에서 5열 표는 성립하지 않습니다.
  - 작업 화면에서는 다음 두 가지 중 하나를 권합니다.
    - (a) 상세를 wide2(≥ 640px)로 열고 목록 열을 줄입니다.
    - (b) 항목을 2줄 카드형(위: 구분 · 이름 · 약어, 아래: 바뀌는 칸 · 사유 · 작업)으로 바꿉니다.
  - 결재 목록은 1600 화면에서 오른쪽 40%가 비어 있어, 넓히기 여유가 있습니다.
- **밀도**
  - 1600 화면에서 화면 일괄 작성 · 표준 맞추기 · 산출물은 적정합니다.
  - DDL의 점검 결과(379px)는 오른쪽 절반을 비워 둡니다(코드와 좌우 분할이 낫습니다).
- **키보드 · 스크린리더**
  - 좋은 점: 그리드 입력의 aria-label('단어명 2행' 등), 반려 사유 aria-label('고객 반려 사유').
  - 아쉬운 점:
    - 시스템 홈의 영역 표 행이 링크 · 버튼으로 드러나지 않습니다(read_page interactive 목록에 없음).
    - native select의 접근성 이름이 현재 값('선택', '—')으로 읽히는 도구가 있습니다. 도구에 따라 달라 확인이 필요합니다.
- **대비**
  - 토스트가 나타나고 사라지는 동안 흐린 상태가 길어(스크린샷 3회 모두 반투명), 행동 버튼이 있는 토스트는 읽기 전에 사라집니다. 행동이 있는 토스트는 최소 8~10초 머물고, 마우스를 올리면 멈추게 하세요.

  - 약어가 자동으로 대문자가 됩니다.
  - 행 상태와 하단 집계가 있습니다.
  - [담김] · [다시 고치기]가 있습니다.
  - 단어 분석 칩('작성 중')으로 같은 바구니 안의 의존을 즉시 보여 줍니다.
- **중복 · 유사 판정**
  - "비슷한 약어 산출물 DLVRBL — 다르면 중복 허용 사유"처럼 원인과 다음 행동을 함께 줍니다.
  - "같은 이름이 사전에 있음 — [변경으로]" 링크가 있습니다.
- **속성 자동완성**: 기관 · 공통 · 신청 중 배지와 '그대로 입력'이 있고, 비표준 입력 즉시 미준수 집계와 머리 버튼이 바뀝니다.
- **결재선 표시**(신청 → DA → 최종, 내 차례)와 **자기 승인**(확인 체크 + 사유 필수 + 감사 표시)이 있습니다.
- **J/K/A/R 결재 단축키**, **다른 탭 변경 감지**(상태 · 역할 바뀜 토스트 + 새로고침)가 있습니다. 다만 검토 모드와의 충돌은 #16에서 다룹니다.
- **표준 맞추기 상태 칩**(표준 · 조합 가능 · 신청 중 · 미등록 단어 · 예외)과 하단의 '선택 적용 / 예외로 표시' 일괄 바가 있습니다.
- **DDL 게이트**(물리명 · 타입 없는 컬럼 차단)와 **산출물 화면**(양식 · 기준 버전 · 미리보기 · 최근 이력)이 있습니다.
