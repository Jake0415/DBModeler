# DBModeler 클릭 목업 v7.3 최종 확인 검토

## 1. 총평

r13 두 합의표의 공통 18개 묶음을 대조한 결과 반영 3개, 일부 15개, 미반영 0개입니다. 각 행에 Claude 합의표의 대응 번호를 병기했습니다.  
후보 큐에는 이전 초기화 코드가 남아 신규 후보 전환을 막고, 모델 결재는 진행 중인 연결 용어가 있어도 확정할 수 있습니다. 엑셀 보정·재검증, 산출물 대상, 계정·감사에서도 상 결함을 확인했습니다.  
정적 코드 판독과 Node 격리 실행으로 검토했습니다. 인라인 스크립트 40개 구문과 초기 적재 3행 반영, DDL 예시 3개 테이블 파싱, 후보 초기화 덮어쓰기, 삭제 후 ID 충돌을 확인했습니다. 브라우저 조작은 생략했습니다.

## 3. 시나리오 T1~T10 판정

지도(index.html:34–53)의 클릭 흐름을 기준으로 판정했습니다. 결재 규칙을 위반한 완료는 막힘으로 집계했습니다.

| 시나리오 | 판정(통과/막힘) | 막히는 지점 |
|---|---|---|
| T1 설치 직후 첫 사용 | 통과 | 빈 사전 → 엑셀 초기 적재 → **생성된 번호**로 자기 승인 → 이현업 최종 승인 → 새 기관 용어 확인. 지도 마지막 바로가기는 기존 시드 문서용입니다(index.html:35, excel-import.html:169–174, :414–420, approvals.html:254–274). |
| T2 신규 설계 중 표준 맞추기 | 막힘 | 모델에서 등록한 새 후보를 시나리오 끝의 후보 큐에서 확인할 수 없습니다(CX14-01). |
| T3 현행 DB 표준화 | 통과 | 예시 DDL 3개 테이블 → 새 영역 → 표준 맞추기 → 같은 영역 모델 및 시스템 홈에서 확인(import.html:109–120, standardize.html:194–205, system.html:47–58). |
| T4 후보 → 사전 → 모델 | 막힘 | 새 후보가 목록에 없고 기존 행의 전환도 PN-12 대신 구버전 직접 제출을 실행합니다(CX14-01). |
| T5 모델 확정 | 막힘 | 진행 중인 연결 용어가 남아 있는 제출본을 최종 승인할 수 있습니다(CX14-02). |
| T6 같은 업무 영역 동시 편집 | 통과 | 충돌·연결 끊김 시연과 리스크 검토 중 조회 전용이 연결됩니다(model.html:321–343, :584–585, :788–824, :1188–1192). |
| T7 겸임자 결재 | 통과 | 0009 타인 승인, 0014 자기 승인, 김모델의 0010 조회와 이현업 최종 승인, 박설계 대기함 제한, 이데이터 자기 역할 잠금 경로가 있습니다(assets/app.js:51–56, approvals.html:90–110, :224–258, settings.html:148, :176–184). |
| T8 모델 확정 끝까지 | 막힘 | 0014가 진행 중이어도 확인 체크만으로 확정·다음 버전에 도달해 합의한 선행 승인 조건을 검증할 수 없습니다(CX14-02). |
| T9 엑셀 왕복 편집 | 막힘 | 중복 ID 행의 제공 보정 경로가 빈 변경을 제출해 DA 승인에서 전체가 정지합니다. 새 기준본으로 바꿔도 결과 차분은 고정입니다(CX14-04, CX14-05). |
| T10 계정·검색·관리 | 막힘 | 엔터티·속성 검색이 0건이고 역할을 저장해도 신청자에게는 요청 중이 남습니다. 기본 세션 만료 링크의 복귀는 연결됩니다(CX14-08, CX14-09, error.html:34, login.html:38–44). |
