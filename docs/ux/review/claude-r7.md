## 1. 총평

1. **v4 Top 10은 4/10 닫힘**(2 신청 신원, 3 실행 전 재확인, 6 편집 검사, 10 셸·1600·키보드), 6개는 부분입니다. 회귀는 없고, v4에서 회귀였던 CX-13·CX-31·CL-29와 열림이던 CL-19·CX-17, CX4-01·02가 모두 닫혔습니다.
2. **07 Top 10은 3/10 닫힘**(7 브라우저 보정, 9 검색·항목 이력, 10 SC-15·16 뼈대)입니다. 기준본은 토스트로만 있고 상태 계층에 기록되지 않습니다. 멱등 제출과 반영 후 묶음 알림도 비어 있습니다.
3. 공통 상태 계층(`createDoc`·`addHist`·`modelLock`·`getBatches`)은 결재·모델에서는 제대로 동작합니다. 하지만 **사전 항목·후보·홈·시스템·확정 신청 패널은 여전히 고정값**이라서, 결재가 끝난 뒤 화면끼리 어긋납니다.
4. 새 문제 중 가장 큰 것은 세 가지입니다. ① 엑셀 묶음을 `?resume=`·`?step=5`로 열기만 해도 숫자가 덮이거나 새 묶음이 생깁니다. ② `updateNeeds()`가 다른 비활성 조건을 풀어 버려 사유 없는 미사용·0건 신청이 통과합니다. ③ 표준 맞추기의 처리 방식·예외·비대상이 모델에 넘어가지 않습니다.
5. 다음 차수에는 화면 패치보다 **사전 항목·기준본·후보를 상태 계층에 올리고, 버튼 활성 조건을 함수 하나로 묶는 일**을 먼저 해야 합니다.

## 5. 다음 차수 우선순위 Top 10

1. **사전 항목·기준본을 상태 계층에 올리기**: `dbm-items`(Vn·pending·제정차수·이력)와 `dbm-baselines`(내려받기 기록)를 둡니다. 결재 반영·공표·업로드 비교가 모두 이것을 읽고 씁니다. (CL7-05·21·23, 07 T1·T9)
2. **엑셀 묶음 무결성**: 멱등 키 `batch:ID`, 신청된 묶음은 열람 전용으로 열기, 시드 묶음에 `draft/sub` 넣기, 예시 주소는 새 묶음을 만들지 않기. (CL7-01·02·04·24)
3. **버튼 활성 조건 단일화**: `updateNeeds`가 다른 비활성 사유를 덮지 않게 합니다. 자동 대체값·미리 채운 사유를 없앱니다. 신청 사유를 감사 로그로 넘깁니다. (CL7-03·10, R7)
4. **표준 맞추기 hand-off 완성**: 처리 방식·예외·비대상·사유를 넘기고, `area`를 주고받고, 취소 시 생성 문서도 처리합니다. (CL7-08·09·11·12, R3·R6)
5. **사전 신청 폼을 실제 입력으로**: 대기 목록 배열, 선택 항목 변경 폼, MD-10 진행 중 중복 차단. (CL7-06·07)
6. **남은 고정 상태 표시 제거**: 홈·시스템·확정 신청 패널·결재 링크·제품 정보 사전 버전을 `modelLock`·`lastComp`·`getPub`에서 계산하고 index 예시를 정리합니다. (CL7-13~16·21, R1·R4)
7. **결재 재검사 범위 확장**: 사전·엑셀 문서의 낡은 제출 재비교, 대량 자기 승인 요약·권고. (CL7-17·19, 07 T2)
8. **반영 후 후속 연결**: 선행 승인 자동 재검증, 묶음 단위 모델 재검토 알림 1건, [보류 행 다시 검증] 실제 동작. (CL7-27, 07 §4 반영 후 알림)
9. **후보·감사 영속화**: 후보 처리 결과 저장과 수 계산, 감사 필터 결합, 고정 행을 시드 이력으로. (CL7-20·22, R8)
10. **권한·탭·포커스 마무리**: `?doc=` 가시성 403/404, 실행 직전 권한 재검사, `storage` 이벤트, 처리 후 포커스 복귀. (CL7-18·28·30)
