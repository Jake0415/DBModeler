# 엑셀로 ERD 시작하기(26) Codex 리뷰

시나리오 26 §6의 결정을 우선 적용했다. 관계 결과는 시나리오 18과 모델 목업, 엑셀 호환성은 SWS 파서·검증·양식과 대조했다. Node에서 목업 함수 두 곳을 그대로 실행해 시트 간 테이블명 이어받기와 덮어쓰기 후 FK 짝 누락을 재현했다. 나머지는 정적 검토이며 브라우저 조작과 실제 .xlsx 왕복은 검증 범위에 포함하지 않았다.

## 개선 항목

### XE-01 최종 대상과 충돌 선택을 기준으로 참조 재검증

- **심각도** 높음
- **근거** 기존 영역 참조가 있는 파일을 새 영역 기본값으로 열면, 기존 영역을 선택하기 전에 참조 오류로 다음 단계가 막힐 수 있다. 3단계에서 새 영역이나 가져오는 방식을 바꾸면 계획만 다시 그리고, 영역 선택을 바꿔 오류가 생겨도 적용 직전에 오류를 막지 않는다. 덮어쓰기로 삭제한 부모 ID를 관계에 다시 쓸 수 있고, 병합에서 ‘지금 값’으로 남긴 타입·PK도 검사 및 관계 유형 계산에 반영되지 않는다. [미리보기](../mockups/import-excel.html#L247) · [대상 변경](../mockups/import-excel.html#L314) · [관계 적용](../mockups/import-excel.html#L332) · [적용 버튼](../mockups/import-excel.html#L346)
- **제안** 대상과 무관한 파일 오류는 먼저 막고, 대상 의존 오류는 위치를 정한 뒤 해결할 수 있게 한다. 최종 대상·방식·충돌 선택을 적용한 결과에서 참조와 기존 관계를 다시 검사하고, 실패하면 미리보기에서 수정할 위치를 보여 준다.

### XE-02 덮어쓰기에서 실제 삭제 범위와 FK 짝 일치

- **심각도** 높음
- **근거** 양 끝 테이블이 남으면 기존 관계도 남지만 덮어쓴 컬럼의 FK 표시와 짝은 전부 지운다. 부모 P와 자식 C를 모두 다시 올리고 참조 칸을 비우면 관계선만 남는 것을 재현했다. 삭제 예고에는 빠지는 테이블에 걸린 관계 수만 나온다. 기존 테이블의 사라지는 컬럼과 그 컬럼에 걸린 관계는 확인할 수 없다. [삭제 예고](../mockups/import-excel.html#L310) · [덮어쓰기](../mockups/import-excel.html#L323) · [모델의 FK 짝 조회](../mockups/model.html#L631) · [시나리오 26](../26-erd-excel-import.md#L34)
- **제안** 적용과 미리보기에 동일한 삭제·보존 계획을 사용한다. 빠지는 컬럼·관계 목록을 보여 주고, 보존하기로 한 관계는 유효한 짝을 유지한다. 두 번째 확인은 대상과 계획이 같을 때만 받도록 한다.

### XE-03 병합 시 기존 FK 묶음 보존과 중복 판정

- **심각도** 높음
- **근거** 중복 판정은 부모·자식과 컬럼별 fkp만 비교한다. 동일 관계의 묶음인지, 짝 전체가 일치하는지는 확인하지 않고 자식 컬럼 찾기에도 대소문자 기준이 다르다. 매칭에 실패하면 기존 FK 컬럼의 fkg를 새 값으로 덮어 기존 관계에서 짝이 빠진다. [가져오기 FK 중복·기록](../mockups/import-excel.html#L336) · [ERD의 짝 선택 제한](../18-relation-scenario.md#L65)
- **제안** 정규화된 식별자와 관계별 FK 짝 전체로 중복을 판정한다. 기존 관계에 속한 컬럼을 다른 관계에 쓰려는 경우 충돌을 표시하고, 같은 파일을 두 번 병합해도 관계와 FK 묶음이 한 번 적용한 상태를 유지하는지 확인한다.

### XE-04 새 영역 저장 실패와 되돌리기 처리

- **심각도** 높음
- **근거** 새 영역은 등록과 구조 저장의 성공을 확인하지 않은 채 완료를 호출한다. 기존 영역의 최초 저장은 실패를 확인하지만, 취소는 새 영역 삭제·기존 버전 복원 결과를 확인하지 않고 성공 토스트와 감사 로그를 남긴다. 완료 화면을 열어 둔 사이 다른 탭에서 수정한 내용도 스냅샷 복원으로 덮일 수 있다. [저장 반환값](../mockups/assets/app.js#L8) · [영역 생성](../mockups/assets/app.js#L195) · [복제 화면의 실패 확인 선례](../mockups/assets/app.js#L281) · [저장](../mockups/import-excel.html#L352) · [취소](../mockups/import-excel.html#L369)
- **제안** 등록·구조 저장이 모두 성공했을 때 완료와 감사를 기록한다. 부분 실패는 정리하고 재시도 상태를 제공한다. 취소는 같은 버전과 가져오기 직후 리비전에서만 허용하고 복원 성공을 확인한다.

### XE-05 예전 양식의 이어받기 경계와 논리명 일관성

- **심각도** 높음
- **근거** 이어받는 테이블명이 통합 문서 전체에서 유지된다. 예전 양식의 두 번째 시트 첫 행에 테이블 물리명이 비어 있으면 앞 시트의 마지막 테이블에 컬럼이 붙는 것을 재현했다. ‘NULL 허용 여부’ 열만 있어도 이어받기를 허용하지만 SWS는 표준·원천 헤더로 구형을 구분한다. 새 양식은 첫 행에 논리명이 있고 이후 빈 행인 경우 통과하며, 첫 행이 비면 물리명을 논리명 비교 기준으로 써서 시트 원문과 다른 기준으로 오류를 표시한다. 구형 표준·원천 값은 읽지만 모델에 저장되는 필드에는 포함되지 않는다. [헤더와 행 읽기](../mockups/import-excel.html#L171) · [이어받기와 일관성 검사](../mockups/import-excel.html#L187) · [저장 필드](../mockups/import-excel.html#L319) · `D:/project/sws-data-governance/backend/app/services/modeling_excel/parser.py:137–145,162–195,248–283`
- **제안** 시트마다 이어받기를 초기화하고 형식 판정과 NULL 값 해석을 독립시킨다. 새 양식의 논리명·설명은 빈 값을 포함한 원본으로 비교하고, 구형의 반복 생략 허용 범위를 명시한다. 표준·원천 열을 참고 보존한다는 안내는 실제 보존 범위에 맞춘다.

### XE-06 다른 영역 참조의 확정본과 선택 상태

- **심각도** 높음
- **근거** 다른 영역의 현재 작업본에서 이름을 먼저 검색하고 첫 일치 영역을 고른다. 확정본에만 남은 테이블을 놓치거나, 확정본이 없는 첫 후보가 참조 가능한 다른 후보를 가릴 수 있다. 저장할 사본은 PK·‘명’ 컬럼을 합쳐 6개로 잘라 뒤에 있는 PK까지 잃을 수 있다. 미리보기 재계산 시 체크박스가 기본 켬으로 돌아오고, 끈 순간에는 문제 탭에 경고가 추가되지 않는다. [후보 찾기](../mockups/import-excel.html#L209) · [선택 처리](../mockups/import-excel.html#L247) · [참조 사본](../mockups/import-excel.html#L334) · [시나리오 26](../26-erd-excel-import.md#L104)
- **제안** 확정본으로 후보를 찾고 동명이면 영역을 표시해 선택받는다. PK 전체를 보존하고, 기존 참조 사본 재사용 시 실제 버전과 키를 검사한다. 동일 후보의 선택은 뒤로 가기와 재검사 후에도 유지하고, 끄면 일반 컬럼으로 남는다는 경고와 적용 관계 수를 즉시 갱신한다.

### XE-07 참조 키와 타입 계열의 판정 범위

- **심각도** 높음
- **근거** 목업은 단일 UNIQUE를 거부하고 복합 PK의 각 컬럼을 개별 통과시킨다. SWS는 단일 PK 또는 단일 UNIQUE를 허용하며, 26은 복합 FK도 명시한다. 목업은 복합 PK 일부만 참조해도 경고 뒤 관계를 저장하지만 ERD는 부모 PK 전체의 짝을 기대한다. 타입도 문자열·숫자·날짜 세 계열 외에는 비교를 건너뛴다. [행 검사와 부분 키 경고](../mockups/import-excel.html#L221) · [관계 저장](../mockups/import-excel.html#L338) · [시나리오 26](../26-erd-excel-import.md#L48) · [시나리오 18](../18-relation-scenario.md#L65) · `D:/project/sws-data-governance/backend/app/services/modeling_excel/validation.py:25–39`
- **제안** 완전한 복합 PK 묶음과 단일 UNIQUE를 구분해 검사한다. 부분 참조는 누락된 부모 키를 표시하고, 완전한 관계로 저장하려면 짝을 채우도록 한다. ERD와 DDL까지 UNIQUE 짝을 지원하는 기준을 맞추고, DBMS별 알려진 타입 계열과 미등록 타입 경고의 경계를 명시한다.

### XE-08 관계 유형·선택성·두 번째 관계

- **심각도** 중간
- **근거** 같은 부모 컬럼이 반복되면 새 묶음을 여는 규칙은 구현돼 있다. 다만 복합 키 참조 행이 교차 배열되면 일부 묶음이 의도와 다를 수 있고, 같은 테이블 쌍의 두 번째 관계에 역할명이 표시되지 않는다. 재귀는 자식 PK·필수 값과 관계없이 비식별·선택으로 저장한다. 일반 복합 FK에서 필수와 선택 컬럼이 섞이면 관계 선택만 ‘없어도 된다’로 표시하고, 카디널리티는 자식 UK와 관계없이 항상 0..N이다. [관계 묶음](../mockups/import-excel.html#L225) · [미리보기](../mockups/import-excel.html#L257) · [관계 저장](../mockups/import-excel.html#L339) · [시나리오 26](../26-erd-excel-import.md#L69) · [시나리오 18](../18-relation-scenario.md#L27)
- **제안** 반복 키로 분리한 묶음에 부모↔자식 짝과 역할을 표시하고 모호한 복합 묶음의 입력 순서를 안내한다. 18의 재귀 기본값과 26의 원본 보존·필수 규칙이 충돌하는 입력은 적용 전에 드러낸다. 자식 키 조합과 선택성을 ERD와 같은 기준으로 계산하고 식별 관계의 후손 영향도 검사한다.

### XE-09 파일 읽기 제한과 상태

- **심각도** 중간
- **근거** 확장자와 10MiB 입력 크기를 검사하지만 압축 해제 크기나 통합 문서 형식 검증 없이 SheetJS에 넘긴다. 진행 표시, FileReader 실패 처리, 늦게 끝난 읽기가 새 선택을 덮지 못하게 하는 처리가 없다. [업로드](../mockups/import-excel.html#L275) · [사전 검증 진행 UI](../mockups/excel-import.html#L185) · [시나리오 26](../26-erd-excel-import.md#L32) · `D:/project/sws-data-governance/backend/app/services/modeling_excel/parser.py:52–69`
- **제안** 지원 형식과 압축 해제 한도를 파싱 전에 검사한다. 읽는 중 상태와 실패 이유를 알리고, 읽기 실패 후 같은 파일을 다시 고르거나 새 선택으로 교체할 수 있게 한다.

### XE-10 검사 결과 엑셀을 고쳐 다시 올리는 경로

- **심각도** 중간
- **근거** 원본 시트를 한 장으로 재구성하므로 시트·행·열 위치와 원본 열이 사라지고, 문제 셀의 색·메모도 없다. 헤더 오류가 있던 시트는 데이터 추출에서 빠진다. 별도로 생성한 ‘파일 문제’ 시트는 재업로드 시 데이터 시트로 검사되어 필수 헤더 오류를 낸다. 문제 표에서도 원본 행으로 이동할 수 없다. [데이터 시트 판정](../mockups/import-excel.html#L168) · [문제 목록](../mockups/import-excel.html#L254) · [검사 결과 내보내기](../mockups/import-excel.html#L264) · [시나리오 26](../26-erd-excel-import.md#L33)
- **제안** 원본 통합 문서에서 셀을 표시하고, 요약 시트를 추가한다면 재검사에서 건너뛰도록 한다. 오류 예시와 헤더 오류 파일을 각각 내려받아 수정 후 재업로드하고, 문제 표에는 해당 시트·행을 여는 액션을 제공한다.

### XE-11 경고와 원본 값 보존

- **심각도** 중간
- **근거** 명명 템플릿 검사가 없고 테이블 예약어는 검사하지 않는다. 예약어 집합과 길이 비교는 DBMS별 식별자 규칙을 충분히 표현하지 못하며 CHAR는 매핑에 없어도 통과한다. 길이·소수점 값은 별도 필드로 보존하지 않아 이미 괄호가 있는 타입과 함께 입력하면 손실될 수 있다. [경고 설정](../mockups/import-excel.html#L182) · [컬럼 경고와 규격 변환](../mockups/import-excel.html#L199) · [시나리오 26](../26-erd-excel-import.md#L53)
- **제안** 프로젝트의 DBMS·명명 설정을 기준으로 실제 위반 위치를 경고하고, 타입과 길이·소수점 원문을 되살릴 수 있게 보존한다. 경고만 있는 경우 계속 진행하는 동작은 유지한다.

### XE-12 배치·표준 판정·완료 수치

- **심각도** 중간
- **근거** 덮어쓰기는 새 엔터티를 기존 위치와 무관하게 같은 원점에서 배치한다. 새 영역은 빈 보기 배열을 저장하고 ‘가져온 테이블’ 보기를 만들지 않는다. 새 속성은 표준을 판정하지만 병합한 기존 속성의 논리명이 바뀌어도 표준 상태는 다시 산출하지 않는다. 완료·감사는 실제 생성한 관계 대신 선택된 관계 후보 수를 사용한다. 위치 단계에서 모델 화면을 연다고 안내하지만 실제 경로는 완료 화면이다. [새 영역 안내](../mockups/import-excel.html#L296) · [표준·배치](../mockups/import-excel.html#L319) · [완료 집계](../mockups/import-excel.html#L360) · [시나리오 26](../26-erd-excel-import.md#L35)
- **제안** 기존 좌표를 피해서 새 엔터티를 배치하고 가져온 테이블 보기를 만든다. 갱신된 속성의 표준 판정을 다시 계산한다. 완료와 감사에는 생성·유지·제외 결과를 실제 저장 기준으로 집계하고, 위치 단계는 완료 화면으로 이동한다고 안내한다.

### XE-13 권한·잠금 안내와 진입 맥락

- **심각도** 중간
- **근거** 영역 목록에 결재 중·확정본·권한 없음 이유가 있지만, 잠긴 모델에서 들어오면 해당 영역이 자동 선택에서 빠져 새 영역 기본값으로 남는다. 가져오기 버튼은 권한이 없어도 눌리며, 진입 이후 잠금이 바뀌면 공통 오류만 보인다. 시스템 홈의 ‘엑셀로 만들기’는 새 영역 창에서 입력한 이름을 넘기지 않는다. [잠금 선택지와 초기 대상](../mockups/import-excel.html#L288) · [적용 시 권한 확인](../mockups/import-excel.html#L349) · [시스템 홈 진입](../mockups/system.html#L45)
- **제안** 출발 영역이 잠겨 있으면 그 맥락과 이유를 계속 표시하고 허용된 대상을 명시적으로 고르게 한다. 권한이 없으면 적용을 비활성화하되 양식과 검사는 유지하고, 확정본은 새 작업 버전을 시작하는 경로를 안내한다. 시스템 홈에서 입력한 이름이 있으면 새 영역 이름으로 넘긴다.

### XE-14 탭·표·단계 이동의 키보드와 포커스

- **심각도** 중간
- **근거** tablist 안 버튼에 tab 역할·선택 상태·패널 연결이 없고 방향키 이동이 없다. 관계 표의 반복 체크박스 이름은 동일하고, 문제 행은 정적 텍스트다. 업로드 후 타이머는 스크롤만 하며, 뒤로 가기와 취소 후 숨겨진 화면에서 새 단계로 포커스를 옮기지 않는다. [탭 마크업](../mockups/import-excel.html#L71) · [표와 탭 동작](../mockups/import-excel.html#L254) · [업로드 후 이동](../mockups/import-excel.html#L275) · [완료와 뒤로 가기](../mockups/import-excel.html#L368)
- **제안** tab·tabpanel을 연결하고 선택 상태와 방향키 이동을 제공한다. 관계 체크박스는 부모·자식으로 구분되는 이름을 쓰고, 문제 표에는 키보드로 실행 가능한 행 상세 버튼을 둔다. 단계 전환·뒤로 가기·취소 시 새 제목이나 돌아온 컨트롤로 포커스를 옮긴다.
