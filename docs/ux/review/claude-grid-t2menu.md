# 검토: 속성 편집 그리드(a562ebb) + 모델 트리 T2 메뉴(6c37672) · Claude

> - 현재 작업 사본의 `assets/app.js`(fkOf · drawTree · menuOf · runCmd)와 `model.html`(attrGrid 외)

## 요약

설계 원칙은 그대로 들어갔다. 영향 있을 때만 패널 안 확인 띠, 실행 취소, PK는 맨 위, 고정 칸은 자물쇠와 이유, 트리 명령은 그리드·캔버스와 같은 함수를 부르고 실행할 때 `guard()`로 다시 확인한다.

문제는 세 갈래다.
1. **배열 인덱스(`ai`·`rel`)를 주소로 넘겨 명령을 실행하는 구조**: 다른 버전·순서 변경 뒤에 엉뚱한 속성에 실행될 수 있고, 링크 하나로 모델이 바뀐다.
2. **PK 전파가 역할명(`ORG_`) 컬럼을 만들 때** 공통 `fkOf`가 이를 인정하지 않아 곧바로 "FK 누락"이 된다.
3. **그리드의 필수·도메인 칸은 키보드로 고칠 방법이 없다.**

## 확인했고 문제 없음
- 편집 경로마다 `guard()` · `refGuard()` · `lockWhy()`를 실행할 때 다시 부른다(agEdit · agDelAsk · agMove · agRename · runTreeCmd의 newent/newrel/rename/addattr/delete/관계 명령). 메뉴를 열 때는 `editWhy`로 비활성과 이유를 보인다.
- 참조 엔터티는 그리드가 읽기 전용(`ro = … || e.ref`)이고, 트리 메뉴는 [참조 해제]만 둔다. pkSpread·pkReach는 참조 자식을 건너뛴다(`c.ref`).
- 순서 불변식: PK 켜기·끄기 뒤 `placeAttr`로 PK 묶음 끝/일반 맨 앞에 다시 놓고, agMove는 같은 묶음(PK끼리·일반끼리) 안에서만 바꾼다.
- 영향 없는 변경은 바로 적용 + 실행 취소, 영향 있는 PK 끄기·PK/FK 삭제는 패널 안 띠(16 원칙대로). 마지막 PK 삭제 경고가 있다.
- 입력 중이던 줄 정리(`dataReady` 뒤)와 새 속성 Esc 취소 저장(`dirty = true`)은 의도대로다.
- 트리 메뉴: 우클릭·⋯·Shift+F10·메뉴 키, 방향키·Home·End·글자 이동, 닫으면 같은 줄로 포커스 복귀.

결론: #1·#2(인덱스와 주소 기반 명령)와 #3(필수·도메인 키보드 경로)을 고친 뒤 사용자 확인에 올리기를 권합니다.
