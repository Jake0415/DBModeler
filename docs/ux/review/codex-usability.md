# NeoDB 전체 목업 사용성 검토

기준 커밋 `235763c` · 2026-11-20

검토 종료 시 작업 트리에서 상단 바구니 아이콘과 배지 갱신의 별도 변경을 확인했다. 이 변경은 보고서 작성 범위 밖이며 개선 목록에서 제외했다.

## ① 요약

NeoDB는 사전 검색에서 모델 적용, 품의, 승인, 공표까지 업무 순서를 따라갈 수 있다. 반복 작업에서 가장 큰 부담은 여러 행을 붙여 넣거나 검토한 뒤 사용자가 **어떤 값이 바뀌었고 어떤 항목을 처리할지 다시 확인해야 한다는 점**이다. 특히 붙여넣기가 잘못된 선택 값을 기본값으로 바꾸는 경로와 결재 검사 결과에서 해당 행으로 바로 갈 수 없는 경로를 우선 개선할 필요가 있다. 관리 과업은 안내된 사용자와 실제 권한이 달라 시작부터 막힌다.

가장 중요한 5가지

1. **붙여넣은 적용 범위와 코드 유형을 보존한다.** 알 수 없는 선택 값은 오류로 표시하고 넘친 셀 수를 알려 준다. **U01**
2. **Admin 검토 진입을 바로잡는다.** 현재 시드에서 `choi`는 기관 담당자·모델러이고 `lee`는 DA·Admin이다. **U02**
3. **50행 품의에서 검사 실패 → 해당 행 → 반려 → 남은 승인 수 확인**을 한 흐름으로 연결한다. **U06**
4. **공통표준 현재 판을 모든 화면에서 같은 상태로 표시한다.** 홈과 통합 검색은 새 판 승인 뒤에도 기존 판을 표시한다. **U03**
5. **용어 자동분석에서 바구니로 갔다가 돌아와도 분석 선택을 이어 간다.** 단계·분해 대안·선택 행을 복구한다. **U05**

**검토 방법.** 화면 HTML과 공용 JS/CSS에서 링크, 초기값, 이벤트, 권한 조건, 저장·복구 경로를 사용자 과업 순서대로 추적했다. 브라우저 연결 도구가 브라우저 목록을 제공하지 않아 요구된 새 탭 백업·복원을 보장할 수 없었다. 브라우저와 저장소는 변경하지 않았다. 표의 판정은 코드 경로 기준이며, 20건 입력·50행 승인 실측, 1920/1600 렌더링, 실제 한글 IME·키보드·스크린리더 테스트는 수행하지 못했다. 이전 사전·관계·속성 그리드·퍼블리싱 교차 검토와 반영 기록을 대조했다. 판정에는 디자인 가이드 v2의 밀도·포커스 기준, 역할·권한표, 모델 트리·관계·속성 그리드 설계, 사전 직접 확인 안내와 메타데이터 설계의 신청·검증 흐름을 적용했다. 반영 기록의 기존 브라우저 측정은 별도로 표시했다.

50건을 **서로 다른 문서 50개**로 해석하는 경우에는 한 문서씩 여는 다른 과업이 된다. 이 보고서는 일부 항목 반려가 가능한 **한 문서의 50항목**을 기준으로 봤다. 역할별 상태 변경을 재검증할 때는 저장소 백업 뒤 각 사용자로 세션을 전환해야 한다. `audit=1`은 URL의 역할 저장만 건너뛰며, 실행 시 현재 저장된 역할과 비교하는 동작은 그대로다(`assets/app.js:58–60,815`). 기본 시드의 엑셀 120건 문서는 대표 3행만 담고 있으며 화면에서 그 사실을 밝힌다. 실제 50행의 사용성은 독립적인 50항목으로 다시 검증해야 한다. `assets/app.js:126–127`, `approvals.html:249`

## ③ Nielsen 10 휴리스틱별 발견

| 원칙 | 관찰 |
|---|---|
| 1. 시스템 상태 가시성 | 모델 저장 상태, 대기 단계, 공표 차수가 드러난다. 공통표준 판 표시가 화면마다 다른 값을 보이고, 50행의 검사 실패와 반려 예정은 검토 영역에 모이지 않는다. U03·U06 |
| 2. 실제 세계와의 일치 | DA#의 업무 영역·엔터티·속성·식별 관계와 사전의 제정차수 등 익숙한 개념을 쓴다. 기관 사전 구축 순서와 직접 저장·품의 구분은 각 작업 위치에서 설명할 여지가 있다. U08 |
| 3. 사용자 통제와 자유 | 관계 편집 실행 취소, 항목 반려 취소, 결재 처리 직후 되돌리기가 있다. 표 다중 셀 덮어쓰기와 분석 화면 이탈에서는 같은 수준의 복구를 기대하기 어렵다. U01·U05 |
| 4. 일관성과 표준 | 사전 화면의 메뉴와 로컬 탭 역할이 구분되어 있다. 설정의 해시 링크 계약, 서로 다른 화면의 판 표시, 다운로드 성공 표현은 실제 동작과 통일할 필요가 있다. U03·U04·U10 |
| 5. 오류 예방 | 차단 오류 품의 방지, 승인 시 재검사, FK 삭제 선택 확인이 있다. 표 붙여넣기의 기본값 대체와 설정 범위를 벗어난 입력의 자동 보정은 사용자가 값을 확인하기 어렵게 한다. U01·U12 |
| 6. 기억보다 인식 | 업무 영역·보고 있는 버전·연결 문서가 표시된다. 검사 항목의 위치와 자동분석 선택 맥락은 페이지나 탭을 옮긴 사람이 기억해야 한다. U05·U06·U09 |
| 7. 유연성과 효율 | TSV, Tab/Enter/Ctrl+Enter, 트리 키보드, 코드값 하위 표가 있다. 결재는 검사·전후 비교·반려를 오가는 비용이 항목 수에 따라 증가한다. U06 |
| 8. 미니멀 디자인 | 주 업무와 상세를 패널로 나누고 유지할 규칙을 본문에서 설명한다. 480px 결재 패널의 마지막 열은 전후 값과 여러 줄의 조작을 동시에 맡아 50항목에서 세로 탐색이 길어질 수 있다. U06·U11 |
| 9. 오류 인식·진단·복구 | 품의 차단은 수정 대상 행으로 안내하고, 반려는 바구니로 되돌린다. 검사 실패를 확인한 승인자는 검사 탭과 항목 탭을 오가며, 500 견본의 다시 시도는 오류 페이지를 다시 불러온다. U06·U15 |

## ④ 정보 구조 · 디자인 · 접근성

- **상단 메뉴·사전 탭.** 시스템·사전·결재·관리와 전역 바구니는 주 업무의 위치를 드러낸다. 사전 탭은 찾기·작성, 가져오기, 흐름·이력, 기준정보 네 묶음으로 나뉘고 업로드 이력은 엑셀 흐름에서 찾는다. 분류는 도메인 그룹 화면의 하위 작업이며 행정표준코드는 공통표준 화면의 다른 보기다. 첫 사용 안내에는 이 계층과 작업 순서만 표시하면 된다. 목업 지도와 견본은 검토용 입구로 읽었다. `assets/app.js:1721–1763`, U08

- **1920·1600 업무 밀도.** 공용 CSS의 기본 행은 36px이고 사용자 밀도 설정은 32/44px이다. 넓은 패널은 1920에서 560px, 1600 맞춤 프레임에서 480px이다. 이전 퍼블리싱 반영 기록의 라이트·맞춤·기본 밀도 19화면×2 조건은 넘침과 조작 요소의 이름 검사를 통과했다. 이 기록은 20행 입력/50행 결재와 동시 패널을 연 상태의 시각적 효율을 측정하지 않는다. 현재 코드의 결재 5열 마지막 칸은 전후 값·사유·반려 액션이 함께 들어간다. 1600에서는 예외 요약과 행 바로가기, 1920에서는 근거를 펼쳐 놓고 비교하는 작업의 효율을 각각 확인할 가치가 있다. `assets/app.css:58–60,105,511–520`, [퍼블리싱 반영 기록](resolution-publishing.md)

- **키보드·스크린리더.** 트리는 관리되는 포커스와 현재 항목 표기를, 그리드는 셀 이동과 반려 폼의 Enter/Esc를 제공한다. 승인 확인 창은 직접 열리는 경로에서 초기 포커스 이동이 빠져 있다. 그리드 종류 탭의 선택 상태는 표시하지만 편집 중 탭 내용이 다시 그려지므로 탭·셀·코드값 하위 표 연결과 IME 동작을 실제 보조기술로 재현할 필요가 있다. 감사 로그 필터 칩은 공용 코드가 버튼 역할, Enter/Space, 선택 상태를 보완한다. `assets/app.js:1419,1998–2003`, `dict-grid.html:495–539,664–670`, `approvals.html:392–399,451–457`, U14

ERD 별칭은 모델 화면으로 안내한다. 파일 자체와 장애 복구 결과를 확인하려는 시연에서는 U10·U15가 남는다. `import.html:73–103`, `uploads.html:48–70`, `error.html:30–42`, `erd.html:9`

## ⑥ 유지할 강점

- 바구니를 전역에서 열 수 있고, 화면 일괄 작성과 사전 폼의 제출 검사가 연결된다. 의존 순서 정렬, 차단 오류의 행 이동, 반려 사유와 바구니 복귀는 많은 항목을 다룰 때 실수를 줄인다.
- 모델 트리·캔버스·속성 편집의 접근 경로가 여럿 있다. 관계 삭제에서 FK를 남기는 선택과 제거하는 선택을 명시하고, 취소에 먼저 포커스를 두는 동작은 유지할 가치가 있다.
- 모델 결재에서 제출한 사본, 표준 예외, 연결 용어 신청을 확인할 수 있다. 공표에서 항목 버전과 기관 차수의 효과를 구분하고, 대상 변경 시 다시 확인하게 한다.
- 행정표준코드에서 ‘원문 일부’ 상태와 연결 용어·소관기관을 드러낸다. 기준정보의 불완전성을 사용자가 알아볼 수 있다.
