# NeoDB 퍼블리싱 P0~P4 검토

검토 범위는 `d61d4aa`~`a0109d6`의 정적 FE 목업이다. 디자인 가이드 v2를 판정 기준으로 삼고, 17번 문서의 계획과 적용 기록을 대조했다. 아래 목업 경로는 `docs/ux/mockups/` 기준이다.

근거는 소스와 Git 변경분, CSS 토큰의 대비 계산, 로컬 서버 응답 헤더, Chrome 다크 결재함 접근성 트리다. 헤드리스 Edge가 권한 오류로 종료되어 19개 화면 전체의 전후 계산 스타일, 실제 행 높이, 키보드 시나리오는 재실행하지 못했다. 행 높이 분석은 CSS 내용에서 계산한 값이다.

### 1. 중간 | P1에서 도구 모음 선택 입력의 포커스 후광이 사라짐

- **위치** `assets/app.css:403,416,418` · `approvals.html:41`의 `#f-step`
- **문제** CSS를 합치는 과정에서 도구 모음 선택 입력의 포커스 표현이 바뀌었다.
- **근거** P1 직전 `d61d4aa`에서 `select.input:focus`의 마지막 후광 선언(761줄)은 `.toolbar select.input { box-shadow:none }`(534줄) 뒤에 있다. 두 선택자의 특정도는 `0,2,1`이다. P1에서는 순서가 뒤집혀 라이트·다크의 후광이 모두 사라진다. 별도 `:focus-visible`의 2px 외곽선은 적용된다. 같은 재배치로 기본 `input.input.err`의 포커스 시 그림자도 잉크 후광에서 빨강 링으로 바뀐다.
- **권장 수정** 포커스 상태의 우선순위를 명시하고, 가이드에 맞춰 정상·오류 및 일반·도구 모음 입력을 두 테마에서 비교한다.

### 2. 중간 | 결재함 세그먼트의 탭 의미와 키보드 동작이 어긋남

- **위치** `approvals.html:34,114,387–401` · `assets/app.css:392,436–441`
- **문제** 세그먼트가 탭으로 노출되지만 탭 그룹의 키보드 동작과 콘텐츠 연결이 빠져 있다.
- **근거** Chrome 접근성 트리는 대기함·내 신청·참조함을 탭으로 노출했다. 소스에는 `aria-selected`와 클릭 후 포커스 복원은 있지만, 탭의 좌우 화살표 이동, 단일 Tab 진입점, 제어 대상 연결이 없다. 화살표 처리는 표 행에만 있다. 공통 포커스 규칙에는 삭제된 `.utabs`가 남고 `.seg button`의 가이드 링은 빠져 브라우저 기본 포커스 표시를 사용한다. 마이페이지 밀도 세그먼트에는 `role=group`과 `aria-pressed`가 있다.
- **권장 수정** 같은 목록의 보기 전환으로 유지한다면 레이블이 있는 버튼 그룹과 `aria-pressed`를 사용한다. 탭 의미를 유지한다면 키보드 이동과 패널 연결을 구현한다. 공통 세그먼트에 테두리 안쪽에서도 보이는 포커스 링을 적용한다.

### 3. 중간 | 처리할 결재의 강조가 목록과 상세에서 다름

- **위치** `approvals.html:123,206,265` · `assets/app.js:814–833`의 `tag()`, `docTag()`
- **문제** 대기함 행은 내 차례를 일반 진행 상태와 같은 파란 채움으로 그린다.
- **근거** `run → b-info`, `mine → b-mine` 매핑 자체는 가이드와 일치한다. 대기함은 `tag('run', STEP_NAME[d.step])`을 직접 호출하고 ‘내 차례’를 숨김 텍스트로만 덧붙인다. 상세는 `docTag()`로 파랑 테두리와 보이는 ‘내 차례’를 쓴다. DA 다크 미리보기에서 접근성 트리로 대기함 6건의 ‘DA 승인 내 차례’와 상세의 ‘DA 승인 · 내 차례’를 확인했다. 처리할 6건 모두 일반 진행 상태의 파랑 채움을 쓰는 것은 이 분기로 설명된다.
- **권장 수정** 대기함 행도 `docTag()`를 사용해 처리 주체를 배지 문구와 테두리로 표현한다. 일반 대기의 파랑 채움은 상태표에 정의된 의미에 유지한다.

### 4. 중간 | 다크 배지 글자 대비는 충분하지만 일부 경계와 알림 숫자는 부족함

### 5. 중간 | 32·36·44px가 표준 맞추기의 실제 데이터 행 높이를 보장하지 않음

- **위치** `assets/app.css:29,59–60,468–470` · `standardize.html:14,152` · `mypage.html:80,157–158`
- **문제** 밀도 값을 줄여도 표준 맞추기의 현재값·제안값 비교 행에는 같은 압축 효과가 생기지 않는다.
- **근거** `--row`가 머리글과 셀 높이에 적용된다. 표준 맞추기의 `.cv`에 두 줄이 표시되면 줄 높이 18px × 2와 상하 여백 12px만으로 48px가 필요하다. 사전의 단일 줄 목록은 같은 두 줄 구조가 없다. 두 화면을 같은 행 높이 수치로 설명하는 설정 문구와 차이가 있다.
- **권장 수정** 사전의 단일 줄 목록에는 36px 기본을 유지하고, 표준 맞추기는 두 값의 가독성을 유지한 채 밀도별 실제 표시 행 수를 확인한다. 다중 줄 행은 내용에 따라 높아진다는 규칙을 가이드와 설정에 적는다.

### 6. 중간 | D3의 넓히기 폭이 화면마다 다름

- **위치** `assets/app.css:105,521–524` · `model.html:668` · `ddl.html:42` · `dictionary.html:88`
- **문제** 1600~1919px에서 넓은 패널이 480px와 560px로 나뉜다.
- **근거** 가이드는 넓히기 560px를 공통으로 규정한다. 자동 맞춤 모드에서 `.rpanel.wide`는 1919px 이하에서 480px이고, 고정 1600 모드도 480px다. DDL 비교와 사전 신청이 `.wide`를 사용한다. 모델의 [넓히기]는 `.wide2`를 토글하기 때문에 560px다. 견본의 틀 설명에는 560px만 표시된다.
- **권장 수정** 패널 폭 토큰과 확장 상태를 통일한다. 일부 작업 패널에 480px가 필요하면 그 용도와 폭을 가이드에 명시한다.

### 7. 중간 | 점검 결과가 열린 양식과 비표준 버튼을 놓침

- **위치** `assets/audit.js:6,35–44`의 `PAGES`, `measure()` · `approvals.html:17` · `dictionary.html:112,119`
- **문제** ‘이름 없음 0’과 ‘버튼 높이 3종’을 기본 화면 밖까지 보장하는 지표로 읽을 수 있다.
- **근거** 점검은 보이는 `.btn, .iconbtn, .cv-toolbar .tb, .chip`만 검사해 결재함의 24px `.sumlink`와 각종 세그먼트를 건너뛴다. 입력 검사에서 체크박스·라디오를 제외하며, 사전 신청 패널의 ‘보안 속성’·‘형식단어’는 `label`과 `select`가 나란히 있지만 연결할 `for`·`id`가 없다. 기본 화면만 열어서는 발견되지 않는다. 이름 계산은 `aria-labelledby`를 읽지 않고 숨김 자식까지 포함한 `textContent`를 사용한다.
- **권장 수정** 컨트롤 발견과 치수 검사를 구분한다. 네이티브 컨트롤과 역할 기반 컨트롤의 접근 가능한 이름을 확인하고, 결재·사전의 열린 패널을 시나리오에 포함한다. 높이 예외는 허용할 부품별로 지정한다.

### 8. 중간 | 12px 검사와 계산 스타일 비교에 공통 사각지대가 있음

- **위치** `assets/audit.js:7,10–25,35–40`의 `PROPS`, `vis()`, `snapshot()`, `compare()`, `measure()`
- **문제** 캔버스의 100% 기준, 상태별 표현, 아이콘과 빈 상태의 일부 변화는 현재 결과로 확인할 수 없다.
- **근거** 글자 점검에서 `#world`를 배율과 무관하게 제외한다. `vis()`는 양의 크기와 `visibility`만 확인해 클리핑된 요소나 투명 요소가 집계될 수 있다. 문자 아이콘 정규식은 버튼 문구 속 정상적인 기호도 검출할 수 있고 대상 클래스 밖의 아이콘은 놓친다. 스냅숏은 의사 요소와 실제 좌표·변환을 수집하지 않으며, DOM 배열 인덱스로 비교해 요소 삽입 시 후속 차이가 연쇄로 보고된다. 기본 실행에는 hover·키보드 포커스 전환이 없다.
- **권장 수정** 100% 캔버스 검사를 추가하고, 시각 검사용 표본에서 변환·위치·의사 요소와 상태별 비교를 보강한다. 문자 아이콘은 아이콘 자리 기준으로 검사하고, 비교는 안정적인 요소 식별자를 사용한다.

### 9. 중간 | 회귀 표의 실행 조건과 스크립트 버전이 고정되지 않음

- **위치** `assets/audit.js:6,9,33–46` · `assets/app.js:13–15,818–819,1562–1572` · `01-design-guide.md` §9 · `17-publishing-audit.md` §6.1
- **문제** 같은 1920·1600 결과 이름 아래 테마·프레임·밀도가 달라질 수 있고, 실행 중 수정한 점검 스크립트는 모달을 다시 열어도 갱신되지 않는다.
- **근거** iframe 주소는 역할과 `audit=1`만 지정하고 공통 초기화는 같은 출처의 저장 설정을 읽는다. 따라서 iframe 폭과 앱의 프레임 모드가 독립적이다. 도구는 `window.NeoAudit` 존재 시 스크립트를 다시 불러오지 않는다. 서버 응답은 `Cache-Control: no-store`였다. 페이지가 열린 동안의 전역 객체 재사용과 HTTP 캐시는 별개다. 가이드는 21개 화면을 요구하며 도구 목록은 견본을 포함해 19개다.
- **권장 수정** 실행 결과에 테마·프레임·밀도·대상 목록을 기록하고, 기준 실행은 조건을 명시적으로 지정한다. 저장소의 실제 21개 HTML 중 점검 대상과 제외 사유를 가이드에 맞춰 적는다. 코드 변경 후에는 새 버전을 로드하거나 페이지 새로고침이 필요함을 표시한다.

### 11. 낮음 | 유틸리티의 우선순위 계약과 이름 체계가 불명확함

- **위치** `assets/app.css:495–497,721–739` · `settings.html:289` · `assets/app.js:1743`
- **문제** 범용 `!important` 유틸리티가 일반 인라인 스타일과 다른 우선순위를 갖는데 이름과 적용 규칙에서 구분되지 않는다.
- **근거** `.d-flex`는 JS가 설정하는 일반 `style.display`보다 우선하고, `.p-24`는 더 구체적인 `.tbl > tbody > tr.er > td`의 중요 선언에 밀린다. 설정의 빈 사용자 행이 실제로 `p-24`와 해당 셀 규칙을 함께 사용한다. 확인한 공통 필터는 행의 `style.display`를 갱신하지만 그 행에 `.d-flex`가 함께 붙어 있는 사례는 확인하지 못했다. `.flex`와 `.d-flex`, 수치형 `.fs-12`와 의미형 `.caption`은 목적과 우선순위가 다르다.
- **권장 수정** 중요한 유틸리티는 고정 배치에 한정하고, 상태에 따라 변경되는 속성은 해당 부품 규칙에서 관리한다. 일반 유틸리티와 강제 덮어쓰기의 명명 규칙을 정하고, 빈 상태 셀 여백은 표 부품의 규칙으로 관리한다.

- **위치** `assets/app.css:371,384–386` · `styleguide.html:79–83` · `01-design-guide.md` §3–4, §6.1
- **문제** 버튼 높이 세 종류는 정의돼 있지만 40px 버튼에 문서화되지 않은 글자·반경 단계가 적용된다.
- **근거** 기본과 작은 버튼은 14px·6px이다. `.btn.lg`는 높이 40px, 글자 16px, 반경 `--r-lg`(8px)다. 가이드는 버튼 글자 14px와 반경 6px를 공통으로 지정하고, 큰 버튼의 예외는 높이·가로 여백에만 둔다. 견본은 실제 `.btn.lg`를 사용한다.
- **권장 수정** 큰 버튼을 공통 글자·반경에 맞추거나 현재 치수를 가이드의 크기 표에 명시한다.

### 14. 낮음 | 사전 진입 메뉴와 하위 화면 탭 줄의 목적지가 중복됨

- **위치** `assets/app.js:1465–1471,1494–1497`의 `#mn-dict`, `.dtabs` · `assets/app.css:548–552`
- **문제** 사전 안에서는 같은 다섯 목적지가 전역 드롭다운과 로컬 탐색에 반복된다.
- **근거** 두 영역이 통합 검색·엑셀 가져오기·업로드 이력·후보 큐·변경 내역을 같은 순서로 제공한다. 전역 메뉴는 다른 화면에서도 바로 갈 수 있고, 로컬 목록은 현재 위치를 항상 보여 준다. 로컬 목록은 `nav` 안의 링크와 `aria-current="page"`를 사용하고 포커스 링도 있어 페이지 탐색 의미에 맞는다. 실제 작업에서 중복이 방해되는지는 사용자 관찰 없이 단정하기 어렵다.
- **권장 수정** 사전 밖의 전역 바로가기와 사전 안의 로컬 이동이라는 역할을 가이드에 명시한다. 메뉴 단순화 여부는 다른 화면에서 사전 업무로 바로 이동하는 빈도를 확인해 결정한다.

### 15. 낮음 | 견본이 실제 부품을 재현하지 못하거나 업무 설정을 변경함

- **위치** `styleguide.html:29,41,48,62–68,120–121` · `assets/app.js:818`의 `setDensity()`
- **문제** 견본의 일부는 화면 부품의 회귀 기준으로 쓰기 어렵고, 밀도 ‘미리보기’는 다른 화면의 설정에 반영된다.
- **근거** 화면·패널 제목은 인라인 `font`로 재현하고 패널 폭은 문장으로만 표시한다. 따라서 공통 패널 제목이나 폭이 달라져도 해당 견본이 같이 변하지 않는다. 밀도 버튼은 마이페이지와 동일한 `setDensity()`를 호출해 `dbm-density`를 저장한다. 다음 화면의 초기화가 그 값을 읽는다.
- **권장 수정** 실제 패널 구조와 공통 클래스에 연결한 견본을 두고, 밀도 미리보기는 견본의 문서 속성만 바꾼다.
