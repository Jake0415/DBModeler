# 퍼블리싱 정합성 점검 2차 — Claude UX · UX 라이팅 리뷰 (2026-11-25)

> 기준: [01 디자인 가이드 v2](../01-design-guide.md) · [pub2 자동 측정](pub2-auto-check.md) · 견본 `mockups/styleguide.html`.
> 방법: 목업 서버(http://localhost:5178)에서 1920×1000으로 23개 업무 화면을 열고, 역할(`?as=kim · lee · hyun · park`)을 바꿔 DOM(헤더 구성 · 탭 · 주 버튼 · 패널 폭 · 빈 상태 · aria)을 쟀다. 문구는 HTML과 `assets/app.js`를 검색했다. 파일은 고치지 않았다. 저장 · 신청 · 승인 · 삭제 동작은 하지 않았다.
> 심각도: **높음** = 사용자가 헷갈리거나 잘못 행동할 수 있음 · **중간** = 부품이나 문구가 어긋나 구현 때 갈라짐 · **낮음** = 다듬기.

## A. 문구 · 용어

### UX-01 · 높음 — 같은 행위를 ‘품의’와 ‘신청’으로 섞어 부른다
- 근거: 표준 사전 헤더 주 버튼 `바구니 · 품의`, 패널 제목 `바구니 · 품의 올리기`, 라벨 `품의 사유 *`(dictionary.html:57 · :105, 17곳). 공통표준 31곳, 화면 안내(app.js 11곳: ‘새 판은 품의로 반영’), 설정 ‘분류는 결재(품의)를 거칩니다’(settings.html:95). 반면 결재함 상자 `내 신청`, 직접 등록 ‘등록을 **신청**’, 후보 큐 `단어 신청으로 전환`, 도메인 그룹 `분류 추가 신청`, 엑셀 가져오기 ‘추가 · 변경 **신청**’.
- 문제: 사용자는 ‘품의 올리기’로 보낸 문서를 결재함 ‘내 신청’에서 찾아야 한다. 같은 결재 문서에 이름이 두 개다.
- 고칠 방법: 화면 문구는 **신청**으로 통일한다(`바구니 · 신청` · `n건 신청하기` · `신청 사유`). ‘품의자’도 `신청자`로 바꾼다(model.html · ddl.html · approvals.html). ‘품의’는 기관 내부 문서 용어로만 기준표에 남긴다.

### UX-02 · 높음 — ‘엑셀 가져오기’(사전)와 ‘엑셀로 가져오기’(모델)가 한 글자 차이다
- 근거: 사전 탭 · 메뉴 `엑셀 가져오기`(excel-import.html, 표준 사전 일괄 신청). 모델 도구 막대 `엑셀로 가져오기`, 화면 `<title>` ‘엑셀로 가져오기’, h1은 `가져오기`(import-excel.html:6 · :39), 목차 ‘엑셀로 가져오기(테이블 설계 → 모델)’, 문서 26 제목 ‘엑셀로 ERD 시작하기’.
- 문제: 하는 일이 전혀 다른데(사전 항목 신청 / 테이블 설계를 모델로) 이름이 거의 같다. 전체 검색(Ctrl K)과 알림 · 문서에서 구분이 안 된다. 같은 화면이 제목 · 버튼 · h1에서 세 가지 이름으로 불린다.
- 고칠 방법: 모델 쪽은 화면 안 세그먼트 라벨과 같은 **‘엑셀 정의서 가져오기’**로 통일한다(모델 버튼 · `<title>` · 목차). h1 `가져오기` + 세그먼트 [엑셀 정의서 | DDL]은 둔다. 사전 쪽은 `엑셀 가져오기` 그대로 둔다.

### UX-03 · 높음 — 반려 · 거절 · 회수 · 철회 · 취소를 화면마다 다르게 쓴다
- 근거:
  - 결재 문서: `반려` · `회수`(approvals.html:275, 758 ‘신청자만 회수할 수 있습니다’).
  - 결재함 › 확인 요청: `거절` · `철회`(approvals.html:212).
  - 데이터 타입 요청: 버튼 `반려`, 상태 `반려`(datatypes.html:422 · 436). 취소는 `철회`라고 부른다.
  - 마이페이지 역할 변경 요청: `거절했습니다` · `요청을 취소했습니다`.
- 문제: 결재 문서가 아닌 요청 세 종류가 같은 동작을 서로 다른 동사로 부른다. ‘반려’는 결재 용어라 사용자가 결재 문서로 오해한다.
- 고칠 방법: 결재 문서는 **반려 · 회수**로 쓴다. 결재가 아닌 요청(타입 추가 · 역할 변경 · 관리 확인)은 **거절 · 요청 취소**로 쓴다. 이 규칙을 기준표에 넣는다.

### UX-04 · 중간 — 역할 이름 ‘Admin’과 ‘관리자’가 섞여 있다
- 근거: 역할 이름은 `Admin`이다(app.js:40 `ROLE_NAME.admin`). 그런데 화면 안내에는 ‘DA · 관리자’(app.js:1519 · 1530 · 1592), 토스트에는 ‘관리자만 할 수 있습니다’(settings.html:310 · system.html:215)로 나온다. 마이페이지는 ‘관리자가 바꿉니다’, 검수 기준은 ‘DA · Admin’으로 쓴다.
- 고칠 방법: 역할을 가리킬 때는 늘 **Admin**으로 쓴다. ‘관리자’는 역할이 아닌 일반 뜻(로그인 화면 ‘관리자에게 문의’)에만 남긴다. 권한 거부 토스트는 `{역할}만 {동작}할 수 있습니다` 한 형식으로 쓴다(예: ‘Admin만 저장할 수 있습니다’).

### UX-05 · 중간 — 역할을 이을 때 ‘·’ 띄어쓰기가 화면마다 다르다
- 근거: `DA · Admin`(rules · settings · domain-groups), `DA·Admin`(dictionary.html:388 · dict-history.html), 마이페이지 대리인 목록 ‘이데이터 · DA·Admin’, 목업 역할 전환 `join('·')`(app.js:2380). 검수 기준 표의 ‘속성·컬럼’ · ‘한글·영문·숫자’도 마찬가지다(rules.html).
- 고칠 방법: 화면에 보이는 나열은 모두 **‘ · ’(앞뒤 띄움)**으로 쓴다. 역할 배지 묶음은 `roleBadges()` 하나로 그린다.

### UX-06 · 중간 — ‘조회 전용’과 ‘읽기 전용’이 같은 뜻으로 섞여 있다
- 근거: 모델 · 사전 · DDL · 산출물은 `조회 전용`(model.html:1886 · 2048, dictionary.html:386)이다. 검수 기준 배너는 `읽기 전용 — …`(rules.html:27), 도메인 그룹 · 직접 등록 · 엑셀 가져오기도 `읽기 전용`이다.
- 고칠 방법: **조회 전용**으로 통일한다. 가이드에 있는 대로 띠는 화면 안내에 합친다(rules의 별도 배너 `#r-ro`는 없애고 화면 안내의 역할 변형으로 보인다).

### UX-07 · 중간 — 쓰지 않게 된 상태를 ‘미사용’과 ‘사용 중지’로 나눠 쓴다
- 근거: 사전 항목 · 도메인 그룹은 `미사용`이다(dictionary.html:453, domain-groups.html:69). 데이터 타입은 `사용 중지`, 상태 칸은 `사용`이다(datatypes.html:198, 칩 ‘사용 중지 포함’). 계정 · 시스템은 `사용 중지`다(settings · system).
- 문제: 데이터 타입은 사전과 같은 기준 데이터인데 계정과 같은 말을 쓴다. 상태 칸의 `사용`도 다른 화면의 `사용 중`과 다르다.
- 고칠 방법: 기준 데이터(사전 항목 · 그룹 · 분류 · 타입)는 **사용 / 미사용**으로 쓴다. 사람과 시스템(계정 · 시스템)은 **사용 중 / 사용 중지**로 쓴다.

### UX-08 · 중간 — ‘정책 버전’이 두 가지를 가리킨다
- 근거: 검수 기준 헤더 배지는 `v3`이고 안내에 ‘정책 버전이 하나 오르고’라고 쓴다(rules.html:24 · 30). 데이터 타입 배지는 `정책 v1 · 표준 7 · 추가 1`, 변경 이력은 ‘정책 버전 v1’이다(datatypes.html, `typeVer()`).
- 문제: 따로 올라가는 두 번호를 같은 이름으로 부른다. ‘정책 v1’은 검수 기준 v3과 어긋나 보인다.
- 고칠 방법: 이름을 대상과 함께 쓴다. **검수 기준 v3**, **타입 규칙 v1**. 배지에는 상태 하나만 둔다. 개수(표준 7 · 추가 1)는 목록 머리(listhead)로 옮긴다.

### UX-09 · 중간 — 이력 이름이 ‘변경 내역 · 변경 이력 · 처리 이력’으로 셋이다
- 근거: 사전 탭은 `변경 내역`(dict-history), 데이터 타입 탭 · 검수 기준 행 · 산출물은 `변경 이력`, 결재 문서 탭은 `처리 이력`이다. 파일명은 ‘사전변경내역_’이다(자동 측정).
- 고칠 방법: 뜻을 나눠 고정한다. 결재로 사전에 반영된 기록은 **변경 내역**(메뉴 이름 그대로). 설정 · 규칙을 직접 바꾼 기록은 **변경 이력**. 한 결재 문서 안의 단계 기록은 **처리 이력**. 이 셋을 기준표에 넣는다. 다른 말은 쓰지 않는다.

### UX-10 · 중간 — 같은 화면이 메뉴 · 탭 · 제목 · h1에서 다른 이름을 쓴다
- 근거:
  - 통합 검색: 탭 · 메뉴는 `통합 검색`, h1은 `표준 사전`, `<title>`은 ‘표준 사전 통합 검색’(dictionary.html:6 · 44).
  - 변경 내역: 탭은 `변경 내역`, h1은 `표준 사전 변경 내역`(dict-history.html:21).
  - 데이터 타입 · 검수 기준 · 후보 큐 등 다른 사전 화면은 h1이 탭 이름과 같다.
- 고칠 방법: 사전 하위 화면의 h1은 **탭 이름과 같게** 쓴다(`통합 검색` · `변경 내역`). ‘표준 사전’은 위쪽 메뉴와 탭 줄이 이미 보여 준다.

### UX-11 · 중간 — 토스트 문장의 뒷부분 구분이 ‘—’ · ‘·’ · ‘.’ 셋이다
- 근거: ‘저장했습니다 — 다음 신청부터 적용’(rules), ‘정보를 저장했습니다 · 감사 로그에 기록’(settings.html:641), ‘의견을 남겼습니다. 처리 이력에 보이며…’(approvals). 같은 화면 안에서도 섞여 있다(settings.html:315 ‘—’ / :641 ‘·’). 감사 로그 꼬리도 ‘감사 로그에 기록’ · ‘감사 로그에 남았습니다’ 두 가지다.
- 고칠 방법: **`{결과}했습니다 — {이어지는 영향}`** 한 형식으로 쓴다. 감사 꼬리는 `· 감사 로그에 남았습니다`로 고정한다. 실패는 `{동작}하지 못했습니다 — {이유}`로 쓴다(이미 ‘저장하지 못했습니다 — …’가 있다).

### UX-12 · 낮음 — 필수 값 안내 동사가 ‘입력하세요 · 넣으세요 · 정하세요 · 고르세요’로 갈린다
- 근거: ‘사업명 · 시작일 · 종료일(시작일 뒤)을 넣으세요’(settings.html:686), ‘대리인 · 시작 · 끝(시작 뒤)을 정하세요’(mypage.html:270 근처), ‘반려 사유를 입력하세요’와 ‘반려 사유를 입력해야 합니다’(approvals)가 함께 있다.
- 고칠 방법: 칸 종류로 동사를 정한다. 글자 칸은 **입력하세요**, 목록 · 날짜는 **고르세요**. ‘~해야 합니다’형은 없앤다.

### UX-13 · 낮음 — 기간 라벨이 ‘시작 · 끝’과 ‘시작일 · 종료일’로 다르다
- 근거: 마이페이지 결재 위임은 `시작` · `끝`이다(mypage.html, #dg-from · #dg-until). 설정 › 사업은 `시작일` · `종료일`이다(settings.html:684).
- 고칠 방법: **시작일 · 종료일**로 통일한다. 버튼도 `위임 끝내기` → `위임 종료`로 맞춘다.

### UX-14 · 낮음 — 개발 용어 ‘파싱’이 화면에 보인다
- 근거: DDL 가져오기 주 버튼 `파싱`, 제목 `파싱 미리보기`, 배지 `파싱 실패 · 파싱 완료`(import.html:34 · 106).
- 고칠 방법: 엑셀 정의서 쪽 말에 맞춘다. **읽기 · 검사 · 미리보기**, 배지는 `읽기 실패` · `읽음`.

### UX-15 · 낮음 — 날짜 · 범위 표기가 섞여 있다
- 근거:
  - 공표일: 사전 배지는 ‘(11/03 공표)’, 변경 내역은 ‘2026-11-03 10:00 공표’, 홈은 ‘11/19(목)’로 쓴다.
  - 범위: ‘2 ~ 10자’(rules 토스트)와 ‘허용 2~10’ · ‘2~3자’를 함께 쓴다.
- 고칠 방법: 표와 기록에는 `YYYY-MM-DD HH:mm`을 쓴다. 좁은 배지 · 홈 인사에만 `MM/DD`를 쓴다. 범위는 붙여 쓴다(`2~10자`). 기간(날짜~날짜)만 띄운다(`2026-03-01 ~ 2026-12-31`).

### UX-16 · 낮음 — 내보내기 버튼 이름이 제각각이다
- 근거: `내려받기 .sql`(ddl) · `양식 내려받기 (.xlsx)`(import-excel) · `엑셀 (10건)`(audit) · `엑셀 보고서 (2건)`(dict-history) · `엑셀로 내려받기`(model 검토) · `엑셀`(ddl 비교) · `검사 결과 표시된 엑셀 받기`(import-excel).
- 고칠 방법: **`{무엇} 내려받기 (.형식)`** 하나로 쓴다. 예: `감사 로그 내려받기 (.xlsx · 10건)`, `검사 결과 내려받기 (.xlsx)`. 동사 ‘받기’는 쓰지 않는다.

## B. 디자인 · 부품

### UX-17 · 높음 — 설정형 화면의 저장 방식이 다섯 가지다
- 근거:
  1. 설정 · 마이페이지: 공용 저장 막대 `.setbar`(변경 n건 · [변경 보기] · [되돌리기] · [저장], app.css:891).
  2. 검수 기준: 화면 전용 `.savebar2`(rules.html:15)에 [되돌리기] · [저장 — 정책 버전 올리기]. 변경 보기가 없다.
  3. 데이터 타입 › 시스템별 매핑: 도구 막대 오른쪽 [되돌리기] · [저장](datatypes.html:70대).
  4. 설정 › 기관 › 사업: 표 안 종료일을 바꾸면 **바로 저장**되고 토스트가 뜬다(`data-nodirty`, settings.html:684 · 689).
  5. 마이페이지 › 결재 위임: 칸 안 [위임 저장] 주 버튼으로 바로 저장한다(mypage.html:268).
- 문제: 4 · 5는 화면 아래 저장 막대가 있는 탭 안에 있는데 저장 막대와 상관없이 따로 저장된다. 4는 날짜만 바꿔도 계정 기한까지 함께 바뀐다. 5는 저장 막대가 뜨면 주 버튼이 두 개가 된다.
- 고칠 방법:
  - 설정형은 **`.setbar` 하나**로 저장한다. 검수 기준과 시스템별 매핑도 `.setbar`를 쓴다. 매핑 표의 바뀐 행 수를 ‘변경 n건’으로 보인다.
  - 바로 저장해야 하는 항목(사업 · 위임)은 ‘즉시 반영’ 묶음으로 나눈다. 버튼은 보조 버튼 + 확인 단계를 쓴다(사업 종료일 변경은 ‘계정 n명 기한도 함께 바뀜’ 확인). 24 가이드에 이 예외를 적는다.

### UX-18 · 높음 — 엑셀 정의서 가져오기(26)가 사전 엑셀 가져오기와 다른 단계 표시 부품을 쓴다

### UX-20 · 중간 — 엑셀 정의서 가져오기와 DDL 가져오기가 한 화면 탭인데 흐름이 다르다

### UX-22 · 중간 — 데이터 타입 요청 표에 행마다 주 버튼이 있다
- 근거: 타입 추가 요청 탭의 각 행에 `btn sm primary` [등록하기]가 있다(datatypes.html:423). 헤더에도 주 버튼 [타입 등록]이 있다.

### UX-23 · 중간 — 상태 배지 색이 가이드 상태표와 어긋난 곳이 있다
- 근거:
  - 데이터 타입 요청 `반려`가 `tag('end')`(흐린 글자)다(datatypes.html:422). 가이드는 반려 = `.b-danger`다.

## C. 화면 안내 · 접근성

### UX-30 · 높음 — 화면 안내 내용이 R-19 이후 바뀐 메뉴를 따라가지 못했다
- 근거:

### UX-31 · 중간 — 화면 안내의 [ ] 라벨이 실제 버튼 · 탭 이름과 다르다
- 근거: 데이터 타입 안내 ‘**[논리 타입]** 탭’ → 실제 탭은 `논리 타입 · 축약명`이다. 검수 기준 안내 ‘[저장]하면’ → 실제 버튼은 `저장 — 정책 버전 올리기`다. 가이드 §6.3에는 ‘`[ ]`는 화면 버튼 라벨 그대로’라고 되어 있다.
- 고칠 방법: 안내 문구를 실제 라벨로 고친다. 검수 기준 버튼은 다른 설정형과 같게 `저장`으로 줄이고, 결과(정책 버전 오름)는 저장 막대 문장에 쓴다.

### UX-32 · 중간 — 새 화면 엑셀 정의서 가져오기(26)와 모델 계열에 화면 안내가 없다
- 근거: `PAGE_GUIDE`에 import-excel.html · import.html · model 계열이 없다(app.js:1490~). 모델은 오른쪽 패널의 ‘이 화면에서 해 보기’ 목록이 비슷한 일을 한다. 가이드 표에는 화면 안내 적용 범위가 ‘사전 8개 · 결재함 · 설정 · 감사 로그’로만 적혀 있다(마이페이지 · 데이터 타입 · 검수 기준은 이미 적용).
- 고칠 방법: 엑셀 정의서 가져오기는 처음 쓰는 사람이 많은 단계형 화면이라 화면 안내를 붙인다. 모델 계열은 ‘이 화면에서 해 보기’를 쓰기로 가이드에 적는다. 적용 범위 표를 지금 상태로 고친다.

### UX-33 · 중간 — 버튼으로 만든 밑줄 탭에 탭 역할(aria)이 없다
- 근거: 설정 · 마이페이지 · 데이터 타입 · 공통표준 · 결재 문서 패널 탭은 `<button class="on">`만 쓰고 `role="tab"` · `aria-selected`가 없다(1920 측정: 직접 등록 `ktabs`만 `role="tablist"`). 화면 읽기 프로그램에는 지금 탭이 무엇인지 들리지 않는다.
- 고칠 방법: app.js의 공용 탭 처리에서 `role="tablist" / "tab" / "tabpanel"`, `aria-selected`, `aria-controls`, 좌우 화살표 이동을 한 번에 넣는다(직접 등록 방식 재사용).

### UX-34 · 중간 — 결재함 › 확인 요청으로 바꾸면 목록 머리 숫자가 그대로 남는다
- 근거: `?as=hyun`으로 대기함에서 [확인 요청]을 누르면 위에 ‘1건 · 내 차례 우선 · 오래 머문 순’이 남는다. 그런데 표는 ‘확인할 관리 변경이 없습니다’다. 주소로 바로 열면(`?box=confirm`) 이 줄이 없다. 확인 요청 세그먼트에는 개수가 없을 때 숫자 칸이 비어 있다(다른 상자는 `0`).
- 고칠 방법: 상자를 바꿀 때 목록 머리를 다시 그린다. 개수는 다른 상자처럼 `0`까지 보인다(원칙 7 ‘결과는 항상 보인다’).

### UX-35 · 낮음 — 설정 › 사업 추가 줄은 칸 이름이 placeholder뿐이다
- 근거: `사업명` · `용역사` · 시작일 · 종료일 입력은 보이는 라벨 없이 placeholder와 `aria-label`만 있다(settings.html:685). 날짜 칸은 placeholder도 보이지 않아 어느 쪽이 시작인지 알 수 없다.

### UX-36 · 낮음 — 필수 표시 ‘*’ 모양이 화면마다 다르다
- 근거: `종류 *`(datatypes 평문), `소속 <b>*</b>`(settings), `품의 사유 * <span…>`(dictionary), `업무 영역 이름 *`(import-excel).
- 고칠 방법: `<span class="req" aria-hidden="true">*</span>` + 입력 `aria-required="true"` 한 방식으로 쓴다. 폼 위에 ‘* 필수’를 한 번 적는다.

### UX-37 · 낮음 — 통합 보기 이름이 세 가지로 보인다
- 근거: 세그먼트 `통합`, 툴팁 ‘통합 — 논리 + 물리 (Alt+3)’, 패널 머리 ‘인사관리 · **논리 · 물리 통합**’(model.html:82 · 910). 28 §7에서 정한 ‘통합’ · ‘논리 · 물리 통합’ 표기를 따랐지만, 툴팁의 ‘+’는 다른 곳에서 쓰지 않는다.
- 고칠 방법: 툴팁을 ‘논리 · 물리 통합 (Alt+3)’로 바꾼다. 짧은 자리는 `통합`, 설명 자리는 `논리 · 물리 통합`으로 정해 기준표에 넣는다.

### UX-38 · 낮음 — 위쪽 메뉴 이름이 가이드 그림과 다르다
- 근거: 실제 위쪽 메뉴는 `표준 사전 ▾ · 모델 · 결재함 · 감사 로그`(DA)이고 가이드 §5는 `모델 · 사전▾ · 결재함 · 관리▾`다. 메뉴는 `업로드 이력`을 따로 보이는데 사전 탭 줄은 엑셀 가져오기 안에 묶는다.
- 고칠 방법: 가이드 그림과 순서를 실제 메뉴로 고친다. 업로드 이력 위치는 메뉴 · 탭 줄 중 한쪽 규칙으로 맞춘다.

## 확인한 것 중 문제없던 것
- 페이지 헤더 높이 56, 12px 미만 글자 없음, 이름 없는 버튼 없음, 표 행 36(기본) — 새 화면도 같았다.
- 새 화면(데이터 타입 · 검수 기준)은 사전 탭 줄과 화면 안내를 공용 함수로 붙였다.
- 통합 보기는 세그먼트 · 단축키 · 툴팁 · 게이트 띠가 기존 논리/물리 보기와 같은 부품을 쓴다. 오른쪽 패널은 1920에서 420px로 가이드와 같다.
- 결재함 확인 요청 · 설정 사업 · 마이페이지 위임 화면은 기존 `set-row` · `tbl` · `badge`를 썼다(위 UX-17 · 23 · 35를 뺀 나머지).
- 측정 안 함: 다크 테마, 1600 프레임 세부, 모든 모달 · 메뉴의 키보드 순서. 자동 측정에서 ‘검수 기준 이름 없는 입력 1’은 `?as=park`에서 재현되지 않았다(`?as=lee` 편집 상태에서 다시 볼 것).

## 문구 · 용어 기준표 (제안)

> 01 디자인 가이드에 ‘§10 문구 · 용어’로 넣을 것을 제안한다. 화면 · 토스트 · 화면 안내 · 문서에 모두 적용한다.

| 기준어 | 쓰지 않는 말 | 예 |
|---|---|---|
| 신청 · 신청자 · 신청 사유 | 품의 · 품의자 · 품의 올리기 | `바구니 · 신청`, `3건 신청하기`, ‘신청자만 회수할 수 있습니다’ |
| 반려 · 회수 (결재 문서) | 거절 · 철회 · 취소 (결재 문서에) | ‘REQ-2026-0016을 반려했습니다 — 신청자에게 알렸습니다’ |
| 거절 · 요청 취소 (결재 아닌 요청) | 반려 · 철회 | 타입 추가 요청 [거절], 역할 변경 [요청 취소] |
| 요청 · 요청자 (결재 아닌 것) | 신청 (결재 아닌 것에) | `타입 추가 요청`, `확인 요청` |
| 엑셀 가져오기 (사전 일괄 신청) | 엑셀 업로드 · 엑셀 등록 | 사전 탭 `엑셀 가져오기` |
| 엑셀 정의서 가져오기 (모델) | 엑셀로 가져오기 · 엑셀로 ERD 시작하기 | 모델 버튼 `엑셀 정의서 가져오기`, `DDL 가져오기` |
| 내려받기 | 다운로드 · 받기 · 엑셀(동사 없이) | `감사 로그 내려받기 (.xlsx · 10건)` |
| 올리기 (파일) | 업로드(버튼에), 파싱 | `파일 올리기`, 기록 화면 이름은 `업로드 이력` 유지 |
| 조회 전용 | 읽기 전용 · 보기 전용 | ‘조회 전용 — 검수 기준은 DA · Admin이 고칩니다’ |
| 사용 / 미사용 (기준 데이터) | 사용 중지 (타입 · 사전 항목에) | 데이터 타입 상태 `미사용`, 칩 `미사용 포함` |
| 사용 중 / 사용 중지 (계정 · 시스템) | 미사용 · 중지됨 | ‘박설계 계정을 사용 중지했습니다’ |
| 도메인 그룹 · 도메인 분류 | 도메인그룹 · 도메인분류 | 라벨 `도메인 그룹 · 분류` |
| 변경 내역 (결재로 사전에 반영된 기록) | 변경 이력 (사전에) | 사전 탭 `변경 내역` |
| 변경 이력 (설정 · 규칙을 직접 바꾼 기록) | 변경 내역 · 수정 기록 | 데이터 타입 탭 `변경 이력` |
| 처리 이력 (결재 문서 한 건의 단계) | 결재 이력 · 진행 내역 | 결재 문서 탭 `처리 이력` |
| 검수 기준 vN · 타입 규칙 vN | 정책 vN · 정책 버전(단독) | 배지 `검수 기준 v3` |
| Admin (역할) | 관리자 (역할을 가리킬 때) | ‘Admin만 저장할 수 있습니다’ |
| DA · Admin (앞뒤 띄운 ‘ · ’) | DA·Admin · DA Admin | ‘DA · Admin이 고칩니다’ |
| 실행 취소 (토스트 · 편집 되돌림) | 되돌리기 (토스트에) | 토스트 버튼 `실행 취소` |
| 되돌리기 (저장 전 값으로) | 초기화 · 취소 (저장 막대에) | 저장 막대 `되돌리기` · `저장` |
| 저장 (설정형 저장 막대) | 저장 — 정책 버전 올리기 · 위임 저장 | 결과는 문장으로: ‘저장하면 검수 기준 v4가 됩니다’ |
| 통합 / 논리 · 물리 통합 | 논리 + 물리 · 합친 보기 | 세그먼트 `통합`, 패널 ‘인사관리 · 논리 · 물리 통합’ |
| 시작일 · 종료일 | 시작 · 끝 · 기한(기간 칸에) | 위임 `시작일` `종료일`, [위임 종료] |
| 입력하세요 (글자) · 고르세요 (목록 · 날짜) | 넣으세요 · 정하세요 · 입력해야 합니다 | ‘반려 사유를 입력하세요’, ‘대리인을 고르세요’ |

**문장 형식**
- 성공 토스트: `{대상}을 {동작}했습니다 — {이어지는 영향}` + 필요하면 `· 감사 로그에 남았습니다`.
- 실패 토스트: `{동작}하지 못했습니다 — {이유}. {할 일}`(오류는 수동 닫기).
- 권한 거부: `{역할}만 {동작}할 수 있습니다`.
- 확인 창: 제목 = 질문(‘저장하지 않은 변경을 버릴까요?’), 주 버튼 = 동작(`버리고 이동`). ‘확인’ · ‘예’는 쓰지 않는다.
- 숫자 · 날짜: 기록 `YYYY-MM-DD HH:mm`, 좁은 자리 `MM/DD`, 범위 `2~10자`(붙임), 기간 `날짜 ~ 날짜`(띄움), 개수 `n건`(0건도 표시).
