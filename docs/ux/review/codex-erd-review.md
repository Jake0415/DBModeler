# ERD(모델) 화면 사용성 리뷰

편집에 필요한 기능은 갖춰져 있지만, 저장 실패와 일괄 편집 대상이 잘못 표시될 수 있어 작업의 신뢰성을 먼저 확보하고 머리와 캔버스의 공간을 재배분해야 한다.

## 브리프 관찰 대조

Chrome에서 `audit=1`로 기본 주소, 요구사항(`area=rq&w=1600`), 인사관리(`area=e_hr&w=1920&theme=dark`), 리스크(`area=risk`), 기관 담당자(`as=hyun`), 예시(`state=review`)의 화면과 접근성 트리를 확인했다. 기본 주소는 현재 브라우저에서 인사관리를 열었다. 요구사항을 명시하면 주 버튼은 **미준수 5건 해결**, 캔버스 띠는 **남은 미준수 2**를 표시했다. 아래 픽셀·배율·행 수는 브리프의 실측값으로, 이번에는 재계측하지 않았다. 신규 결함은 소스 실행 경로를 추적한 결과이며, 쓰기 작업과 부하 테스트는 실행하지 않았다. 소스 경로는 `docs/ux/mockups/` 기준이다.

## 지적 사항

### ERD-01 · P1 · 일괄 편집 선택이 다른 속성으로 옮겨 간다

**근거.** 표 선택은 엔터티 ID와 배열 인덱스로 보관된다. 표 닫기는 선택을 남기며, 속성 순서 이동과 삭제는 배열을 바꾼다. 표에서 B를 선택하고 닫은 뒤 B 앞의 속성을 지우거나 B를 이동하고 다시 열면, 같은 인덱스에 들어온 행으로 선택과 적용 대상이 옮겨갈 수 있다. 숨긴 행 적용의 재확인도 같은 키를 사용한다. `model.html:694–720`, `model.html:904–911`, `model.html:937`, `model.html:953–965`.

**권고.** 영속적인 속성 ID로 선택을 추적하고 삭제된 선택을 제거한다. 그 전에는 표를 나가거나 모델의 행 구조가 바뀌면 선택과 적용 확인을 초기화한다. 적용 전에 엔터티·속성 이름으로 대상과 제외 건수를 제시한다.

### ERD-02 · P1 · 저장에 실패해도 ‘저장됨’이 표시된다

**근거.** 공통 저장소는 쓰기 예외를 삼킨다. 모델은 쓰기 성공 여부 없이 메모리 리비전을 올리고 ‘저장됨’을 표시한다. 저장 공간 부족 등으로 한 번 실패하면 다음 편집 시 기존 저장본의 리비전과 어긋나 자체 충돌로 이어질 수 있다. 메모 입력 경로도 내용을 메모리에 갱신하고 focusin에서 스냅숏을 잡지만, 메모 blur에 저장 경계가 없어 후속 렌더 전에 새로고침하면 수정 내용이 유실될 수 있다. `assets/app.js:10`, `assets/app.js:121`, `assets/app.js:1065`, `model.html:291–302`, `model.html:440–457`, `model.html:1183–1206`.

**권고.** 성공 응답 뒤 리비전과 저장 표시를 갱신하고, 실패 시 편집을 유지한 채 미저장·재시도 상태를 보인다. 메모는 편집 종료 시 저장하고 첫 실제 변경에만 실행 취소 기록을 남긴다. 저장 실패를 주입한 뒤 재시도와 새로고침을 검증한다.

### ERD-03 · P1 · 이름 확정과 관계 역할명에 저장 경계가 불완전하다

**근거.** 속성 확정에는 권한 재검사가 있지만 엔터티 이름 확정에는 없다. 엔터티 이름 입력 도중 다른 탭에서 확정 신청하는 경우 로컬 이름이 먼저 바뀌고 저장 단계에서 차단된다. 이때 잠금 충돌 분기는 오류 토스트만 띄워 직전 저장 표시가 남는다. 관계는 역할명을 묻기 전에 FK와 함께 저장된다. 역할명 창을 띄운 채 새로고침하면 임시 관계가 남으며, 그 사이 다른 편집으로 마지막 이력 항목이 바뀌어도 취소가 관계를 되돌리지 못한다. `model.html:291–301`, `model.html:1012–1016`, `model.html:1031–1044`, `model.html:1662–1679`, `model.html:1694–1701`.

**권고.** 이름 확정 시 현재 버전·권한을 다시 검사하고 실패 시 제목과 저장 표시를 동시에 복구한다. 역할명이 필요한 관계는 확정 전까지 미리보기로 보관하고 FK 전파까지 한 번에 저장한다. 검토 신청 직전 재검사도 진행 중 입력과 임시 관계를 포함한다.

### ERD-04 · P1 · 한글 조합 Enter가 필드를 확정한다

**근거.** 엔터티명·속성명 keydown은 IME 조합 여부를 확인하지 않고 Enter/Esc를 처리한다. 조합 확정용 Enter가 이름 확정·다음 속성 추가에 쓰일 수 있다. 표 찾기/바꾸기 역시 입력마다 편집 중인 input을 교체해 조합 세션을 끊을 수 있다. `model.html:975–977`, `model.html:1188–1202`.

**권고.** 조합 중 Enter/Esc를 입력기에 맡기고, 검색에는 입력 DOM을 유지한 채 결과만 갱신한다. 한글 엔터티명·속성명·찾기 입력에서 조합 종료와 작업 확정이 각각 한 번씩 일어나는지 확인한다.

### ERD-05 · P1 · 키보드만으로 엔터티 배치를 마칠 수 없다

**근거.** E와 트리의 새 엔터티 명령은 도구로 전환하지만 실제 배치는 캔버스 click으로만 처리한다. Enter는 선택된 엔터티가 있을 때 속성 추가용이다. 캔버스 노드는 일반 div이며 툴바 선택 상태는 클래스에만 반영된다. Enter를 받은 캔버스 버튼에서도 전역 처리기가 속성 추가를 실행하고 기본 버튼 활성화를 막을 수 있다. `model.html:69–82`, `model.html:445–451`, `model.html:981–989`, `model.html:1161–1167`, `model.html:1208–1232`, `model.html:1984–1986`.

**권고.** 새 엔터티 명령 후 키보드로 현재 보기 중앙 또는 다음 빈 위치에 배치할 수 있게 한다. 전역 도구 키를 작업 영역에 한정하고 버튼·입력 및 처리된 이벤트를 제외한다. 도구 선택 상태와 관계 단계 안내를 보조 기술에 전달한다. 선택은 기존 트리 경로를 함께 유지한다.

### ERD-06 · P2 · 표 전환과 필터링 뒤 초점·스크롤이 끊긴다

**근거.** 헤더·툴바 진입은 `openGrid(false)`를 사용한다. 표 모드에서 캔버스 도구는 숨고 캔버스는 Tab 순서에서 빠지지만 검색으로 초점을 옮기는 것은 Ctrl+F 진입뿐이다. 닫을 때는 진입 위치에 관계없이 헤더 다이어그램 버튼으로 이동한다. 필터나 전체 선택은 표 전체를 교체하며 행 체크 경로에만 초점 복구가 있다. 칩은 `on` 클래스만으로 생성된다. 또한 렌더는 표준 처리와 사유 값만 읽어 두고 도메인·필수 선택은 보관하지 않는다. 도메인을 고른 뒤 표준 처리나 행 선택을 바꾸면 앞서 입력한 일괄 적용값이 초기화될 수 있다. `assets/model.css:130–136`, `model.html:907–939`, `model.html:944–947`, `model.html:968–978`, `assets/app.js:2133–2136`.

**권고.** 모든 진입에서 표 제목 또는 찾기에 초점을 주고 표를 닫으면 진입 버튼으로 복귀한다. 필터·전체 선택·행 선택에서 활성 요소, 표 본문 스크롤, 적용 대기 중인 값을 보존한다. 칩 선택 상태와 전체 선택의 일부 선택 상태를 표현하고, 22장의 건수·빈 결과·가로 스크롤 규칙을 적용한다.

### ERD-07 · P2 · 표준 판정 건수의 범위가 드러나지 않는다

**근거.** 주 버튼은 엔터티 미매핑과 속성 미준수를 합산한다. 영역 메뉴 배지는 초기 생성에서 한 번 읽고, 표 ‘미준수’는 comb/unreg 속성만 보여 주며, ‘남은 미준수’ 띠는 특정 후보 속성만 센다. 브라우저에서 확인한 5와 2를 모두 ‘미준수’라고 부르면 같은 범위로 읽힌다. `model.html:335–364`, `model.html:904–911`, `assets/app.js:1036–1044`.

**권고.** 영역 메뉴 배지와 확정 가능 여부에는 같은 작업본 집계를 사용한다. 속성 표와 후보 띠는 각각 ‘미준수 속성’, ‘선행 단어 승인 대기’처럼 범위를 표시하고 해당 대상에 연결한다. DA의 검토 중 화면과 기관 담당자 화면에는 잠금 사유, 버전, 가능한 다음 행동을 같은 위치에 둔다.

### ERD-08 · P2 · 머리 공간이 제목과 주 동작의 우선순위를 보장하지 않는다

**근거.** 제목의 28px 줄 높이와 단일 56px 머리, 줄바꿈 없는 영역 링크가 겹친다. 영역 이동·편집 상태·표 전환·DDL·비교·확정이 한 줄에 모여 있고 일부 동작이 툴바에도 있다. 트리 폭 상한은 패널을 고려하지만 오른쪽 패널 폭 전환을 창 resize처럼 처리하는 경로는 해당 트리 코드에 없다. `assets/app.css:203–210`, `assets/app.css:379–384`, `model.html:16–34`, `model.html:84–91`, `model.html:129`, `assets/app.js:1771–1792`.

**권고.** 아래 배치처럼 공통 영역 링크를 별도 줄에 고정하고 제목의 최소 폭과 말줄임을 보장한다. 12장 §9.4–9.5의 객체 트리와 영역 화면 이동 분담을 유지한다. 패널 열기·확장·트리 드래그에 같은 760px 바닥 폭 규칙을 적용한다.

### ERD-09 · P2 · 맞춤은 노드의 경계와 실제 가시 영역을 함께 쓰지 않는다

**근거.** 맞춤은 노드 최대 x/y만 사용하므로 음수 위치를 포함한 전체 경계를 구하지 못한다. 현재 창 밖에 있는 캔버스는 조작부 좌표에서만 보정하며, 미니맵 뷰포트는 캔버스 전체 크기를 사용한다. 자동 표시 모드는 35% 미만에서만 요약하고 키만 단계는 수동이다. LOD 적용은 지연되지만 시행 후 관계선과 미니맵 경계를 다시 계산하지 않는다. `model.html:501–517`, `model.html:1281–1311`, `assets/model.css:59–65`, `assets/model.css:92–95`, `assets/model.css:117`.

**권고.** 하단 조작부와 상단 띠를 제외한 가시 직사각형을 맞춤·선택 이동·미니맵이 공유하도록 한다. 최소/최대 좌표를 모두 사용한다. 03장 §2·§3.1에 맞춰 전체 맞춤과 선택 맞춤을 구분하고, 낮은 배율은 키 또는 이름 중심으로 보여 준다. 초기 기준으로 100% 편집, 85% 이상 전체 속성, 50–84% 키, 50% 미만 이름을 비교하고, 이름과 선택 강조는 화면 기준 11–12px 이상을 목표로 삼는다. 전환은 입력이 멈춘 뒤에 하고, 노드 경계가 바뀌면 선과 미니맵을 함께 갱신한다. 100% 복귀를 키보드로 누를 수 있는 버튼으로 제공한다.

### ERD-10 · P2 · 팬·드래그와 선택이 전체 도면 갱신 비용을 유발한다

**근거.** 선택도 모든 노드 DOM과 메모·관계선·우측 패널을 재구성한다. 드래그마다 관계선과 미니맵이 갱신되고, 팬에서도 미니맵은 모든 박스의 레이아웃을 두 번 읽고 SVG를 교체한다. 트리 갱신은 프레임으로 병합하지만 트리 자체는 DOM을 교체한다. 50개 이력에 전체 모델 JSON을 보관한다. 규모가 커질 때의 비용은 코드로 확인되며 프레임 지연은 계측하지 않았다. `model.html:386–406`, `model.html:440–459`, `model.html:474–517`, `model.html:1140–1150`, `assets/app.js:1513–1544`.

**권고.** 우선 팬에서는 미니맵 뷰포트만 움직이고 엔터티 드래그는 인접 관계만 프레임당 한 번 갱신한다. 선택 표시와 도면 변경을 분리한다. 03장 목표인 300 엔터티·500 관계 데이터로 팬·드래그 프레임과 저장 시간을 측정하고, 화면 밖 렌더링과 이력 메모리 개선은 측정 결과에 따라 적용한다.

### ERD-11 · P3 · 보조 조작부 이름과 색상 정보가 부족하다

**근거.** 논리/물리 버튼은 초기부터 눌림 상태를 전달하지 않는다. 범례는 텍스트가 있지만 노드의 상태 표시는 작은 점을 병용하고 미니맵은 색으로 상자 상태를 구분한다. 현재 배율 표시의 마우스 더블클릭 동작은 span에 붙는다. `model.html:21–22`, `model.html:121–125`, `model.html:409–427`, `model.html:510–517`, `model.html:1309`.

**권고.** 논리/물리의 선택을 프로그램으로 전달하고, 도면·미니맵의 상태를 우측 패널 또는 객체 트리에서 텍스트로도 확인할 수 있게 한다. 01장 접근성 기준으로 밝은/어두운 테마 모두에서 초점, 관계선, 상태 표시 명암을 점검한다.

## 권고 배치

```text

        │ 찾기 · 필터  ├────────────────────── 1336px ──────────────────────────┤
        │              │ 작업 영역 956px                       │ 속성 패널 380px│
        │ 엔터티       │ [다이어그램|표] [논리|물리] [보기 ▾] [⋯]│ 속성 · 보안   │

        │ 관계         │ 상태 띠는 잠금·충돌·예시 등 필요할 때    │ 선택 행 상세  │
        │              │           도면 가시 영역               │ 속성 추가     │
        │              │ [−][100%][+][맞춤 ▾][표시 ▾] [범례][맵]│               │
```

- **머리 1336px.** 좌우 여백 40px, 시스템·영역 제목 400px, 버전·저장·접속자 360px, 주 동작 260px, 간격 및 여유 276px. 영역 링크는 아래 줄에서 약 360px를 사용한다. 미준수 상태의 주 동작은 표준 맞추기로 한 번에 보내는 기존 흐름을 유지하되 영역 링크가 같은 건수를 표시하면 머리에 같은 숫자의 장문 버튼을 반복 배치하지 않는다. 해결 후에는 같은 위치에 확정 신청을 노출한다.
- **작업 영역 956px.** 보기 전환은 한 곳에 둔다. 도구 줄은 선택·생성·관계·메모·되돌리기 중심으로 유지한다. 빈도가 낮은 자동 배치·확정본 비교·이미지 내보내기는 작업 영역 ⋯에 둔다. DDL 생성과 산출물은 영역 링크로, DDL 가져오기는 트리의 기존 진입점으로 연결한다. 시스템 전체 조회는 트리의 시스템 전체 ERD 진입점에 둔다. 도구 줄은 좁을 때 기능 묶음 단위로 줄을 나누고 늘어난 높이를 도면 가시 영역에서 뺀다.
- **폭 바닥값.** 기본 264 + 956 + 380 = 1600. 상세 확장 시 264 + 776 + 560 = 1600. 트리가 404px로 넓어진 상태에서 패널을 확장하면 트리를 최대 280px로 일시 제한해 760px를 확보하고, 패널을 닫으면 사용자 폭을 복원한다. 1920 기준 기본 264 + 1276 + 380. 표의 최소 가독 폭을 확보할 수 없는 상태에서는 표 사용 중 우측 패널을 접을 수 있게 한다.
- **하단은 탐색 전용.** 높이 약 40px를 도면과 분리해 줌·맞춤·표시·범례·미니맵 진입에 사용한다. 미니맵을 펼치면 우하단의 실제 180×120 영역을 맞춤에서 제외하거나 접힌 상태에서 다시 맞춘다. 오른쪽 패널에는 선택 객체의 속성과 영향 확인을 모으고, 넓은 패널에서도 엔터티 편집 흐름과 캔버스 연결을 유지한다.
