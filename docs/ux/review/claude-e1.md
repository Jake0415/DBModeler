## 총평

예시가 커지면서 트리를 읽는 맛이 확실히 생겼다.
- 영업 → 재고·인사 참조
- 식별 관계로 이어지는 PK 전파(주문상세 = 주문번호 + 주문순번)
- 개인정보 자동 표시
- FK 제외(재고수불이력)와 누락(재귀) 사례

단어 사전으로 물리명·타입·도메인을 만드는 방식도 일관성 면에서 좋다.

다만 **업무 정확도에 구멍이 셋** 있다. 데이터 표준 도구의 시연 예시이므로 실무자가 보면 바로 걸리는 것들이다.
1. 주문 → 출하 → 매출 → 반품 흐름이 상세 단위에서 끊긴다.
2. BOM에 자품목이 없다.
3. "미등록 단어" 예시가 실제로는 등록된 단어의 조합이다.

예시 사전 안에 **약어 충돌**도 있다. 트리는 분류 묶음 기준(6개 초과)과 오른쪽 칸 의미가 흔들리고, 시스템 전환은 홈·설정과 엇갈린다.

## 트리 구조 제안 (요청 2)

처음 보는 사용자 기준으로는 **"분류 머리 구분선 + 물리명 늘 표시"**가 가장 읽기 쉽다.

```
▾ 영업관리                                   v3
    고객 · 견적 · 주문 · 출하 · 매출 · 반품        ← 설명 한 줄(12px)
    모델 · 표준 맞추기 3 · DDL · 산출물
  ▸ 다이어그램 3
  ▾ 엔터티 12
      ─ 기준 정보 ─
      ● 고객기본                 CUST_M
      ● 판매가격기본             SALE_PRC_M
      ─ 거래 ─
      ◐ 견적기본  미준수 1        QUOT_M
      ● 주문기본                 ORD_M
      ─ 이력 ─
      ◐ 주문상태이력  미준수 1     ORD_STTS_H
  ▸ 다른 영역에서 참조 3            품목 · 창고 · 사원
  ▸ 관계 16
  ▸ 표준 용어 · 도메인     사전 용어 58 · 사전에 없음 6
```

- 구분선은 `role="presentation"`의 머리 줄로 두면 트리 깊이(4단계)와 ARIA 단계가 그대로 유지된다.
- 참조 폴더 줄에 원본 엔터티 이름을 미리 보여 주면 펼치지 않고도 무엇을 가져왔는지 안다.
