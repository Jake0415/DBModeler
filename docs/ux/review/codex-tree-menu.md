# 모델 트리 업무 영역 메뉴 리뷰

**총평** — 모델·표준 맞추기·DDL·산출물은 현재 업무 영역의 화면 머리에 공통 탐색으로 두고, 트리는 영역과 객체 탐색에, 설명은 시스템 홈의 영역 요약에 둔다.

## 지적과 권고

### TM-01 · 높음 · 설명 설정이 화면 이동까지 숨긴다

- **근거** — 인사관리와 재무관리 모두 설명 데이터가 있다. 기본값 `cur`와 `showDesc`를 설명과 바로가기가 공유하고, 검색어가 있으면 둘 다 빠진다. 펼친 영역끼리 구성이 다른 이유는 표시 조건이다. `docs/ux/mockups/assets/app.js:341`, `docs/ux/mockups/assets/app.js:370`, `docs/ux/mockups/assets/app.js:1332`, `docs/ux/mockups/assets/app.js:1335`, `docs/ux/mockups/assets/app.js:1374`, `docs/ux/mockups/assets/app.js:1460`, `docs/ux/mockups/assets/app.js:1517`
- **권고** — 네 화면 머리의 같은 위치와 순서에 현재 영역 이름과 탐색 링크를 표시한다. 트리 찾기·거르기·접기와 독립적으로 유지한다. 모든 영역 행은 이름과 기존 상태 배지로 구성하고, 펼치면 영역별 객체 폴더가 나온다. 현재 화면의 영역 행에는 색과 함께 ‘현재 영역’ 표식을 둔다. 다른 영역을 펼치는 동작은 객체 탐색이며, 그 영역의 모델을 열면 머리의 영역과 메뉴 대상이 바뀐다. 시스템 홈과 시스템 전체 ERD에는 이 메뉴를 표시하지 않는다.

| 위치 | 장점 | 비용 |
|---|---|---|
| 펼친 영역의 트리 항목 | 여러 영역의 화면으로 바로 이동 | 네 링크가 영역마다 반복되고 객체 탐색 순서에 끼어든다. |
| 영역 행 자체 | 이름 옆에서 바로 실행 | 좁은 행에서 이름·상태·펼침·메뉴가 공간을 두고 경쟁한다. |
| 트리 위 ‘지금 영역’ 막대 | 현재 영역의 메뉴를 한 번만 표시 | 사이드바를 접으면 별도 노출 방식이 필요하고 트리 검색 공간을 차지한다. |
| **화면 머리 공통 탐색** | 영역 이름과 현재 화면을 함께 보여주며 사이드바를 접어도 접근할 수 있다. | 네 화면에 공통 배치가 필요하고, 다른 영역의 DDL 등으로 가려면 해당 영역 모델을 먼저 연다. |
| 영역 행 ⋯ 메뉴만 | 트리 밀도를 유지하고 다른 영역에도 바로 실행 가능 | 메뉴를 열기 전에는 목적지와 현재 화면이 보이지 않는다. |

### TM-02 · 높음 · 화면 이동이 보조 텍스트처럼 보이고 트리 탐색에 섞인다

- **근거** — 링크는 13px 회색 글자이며 밑줄은 호버에서, 현재 화면은 색과 굵기로 표시한다. 미준수 수는 작은 숫자로 붙지만 낭독 이름은 이미 ‘미준수’를 포함한다. 링크는 `treeitem`이라 형제 수에 포함되고 방향키로 이동한다. `docs/ux/mockups/assets/app.css:325`, `docs/ux/mockups/assets/app.css:330`, `docs/ux/mockups/assets/app.js:1377`, `docs/ux/mockups/assets/app.js:1436`, `docs/ux/mockups/assets/app.js:1512`, `docs/ux/mockups/assets/app.js:1564`
- **권고** — ‘업무 영역 화면’이라는 이름의 `nav` 안에 탭 모양의 페이지 링크 네 개를 둔다. 14px 글자, 최소 36px 클릭 높이, 너비가 좁을 때 줄바꿈을 적용한다. 아이콘을 쓰면 글자와 함께 표시하고 장식 아이콘은 낭독에서 제외한다. 현재 링크는 굵기와 하단선, `aria-current="page"`로 표시한다. 밝은·어두운 테마의 글자 대비는 4.5:1 이상, 상태를 구분하는 선과 포커스 링은 인접 배경과 3:1 이상을 목표로 한다. Tab·Shift+Tab으로 이동하고 Enter로 열며, 트리 방향키는 영역과 객체에만 적용한다.
- **미준수 배지** — ‘표준 맞추기’ 옆에 ‘미준수 5’처럼 의미를 표시하고 스크린리더가 수를 한 번만 읽게 한다. 현재 코드는 `compOf(s).bad`를 표시하지만 표준 맞추기는 작업본으로 연결한다. 배지도 목적지와 같은 작업본으로 집계하고, 스냅숏을 보고 있을 때는 ‘작업본 기준’을 화면과 낭독에 표시한다. 0건이면 배지를 생략한다. 모델·DDL·산출물의 영역 및 스냅숏 전달은 기존 링크 규칙을 따른다. `docs/ux/mockups/assets/app.js:1032`, `docs/ux/mockups/assets/app.js:1375`, `docs/ux/mockups/assets/app.js:1377`, `docs/ux/01-design-guide.md:203`

### TM-03 · 중간 · 업무 범위 설명이 객체 목록 앞에 반복된다

- **근거** — 설명은 영역 행의 `title`과 낭독 이름에도 들어가고, 펼친 영역에는 12px 회색 줄로 추가된다. 설계 문서 §9.4도 설명과 바로가기를 하나의 표시 옵션으로 묶는다. `docs/ux/mockups/assets/app.js:1421`, `docs/ux/mockups/assets/app.js:1516`, `docs/ux/mockups/assets/app.js:1517`, `docs/ux/mockups/assets/app.css:334`, `docs/ux/12-model-tree-plan.md:397`
- **권고** — ‘사원 · 부서 · 발령 …’은 영역을 고를 때 범위를 비교할 수 있도록 시스템 홈의 영역별 요약에 일반 텍스트로 둔다. 툴팁은 빠른 참고에 쓸 수 있지만 터치나 키보드에서 발견하기 어려워 설명의 주 위치로는 적합하지 않다. 별도 요약 패널은 설명 한 줄을 읽는 데 조작이 추가된다. 트리 행의 낭독 이름은 영역명과 상태 중심으로 짧게 구성한다.

### TM-04 · 중간 · 같은 화면 이동이 여러 조작으로 제시된다

- **근거** — 영역 ⋯의 ‘DDL 만들기’ 등 네 항목은 실제로 바로가기와 같은 화면으로 이동한다. ⋯는 행 호버·포커스 또는 Shift+F10으로 접근한다. DDL 머리의 경로는 시스템 홈과 영역 모델로 이어지며, 모델 화면에는 표준 점검 문맥의 이동 버튼도 있다. `docs/ux/mockups/assets/app.js:1616`, `docs/ux/mockups/assets/app.js:1672`, `docs/ux/mockups/assets/app.js:1575`, `docs/ux/mockups/assets/app.css:347`, `docs/ux/mockups/ddl.html:21`, `docs/ux/mockups/model.html:150`
- **권고** — 공통 탐색은 영역 내 화면 전환, 경로는 시스템 홈·영역 모델로 돌아가기, 영역 ⋯는 ‘모델 열기’와 결재함·보기 추가·영역 복제 등 행 문맥 작업에 쓴다. 공통 탐색을 붙인 뒤 영역 ⋯의 표준 맞추기·DDL·산출물 링크를 정리한다. 경고나 객체 선택에 딸린 이동은 그 문맥에서 다음 행동을 안내하므로 유지한다.

## 적용 범위 · 순서

1. 모델·표준 맞추기·DDL·산출물 머리에 공통 링크를 붙이고 영역, 현재 화면, 스냅숏 전달, 표준 맞추기 배지의 집계 기준을 맞춘다.
2. 시스템 홈에 영역 설명을 노출한 뒤 트리의 설명·바로가기 줄과 ‘영역 설명’ 설정을 함께 정리한다. 영역 ⋯의 중복 이동을 정리하고, 트리 설계 문서 §4·§9.4의 배치와 키보드 규칙을 갱신한다.
3. 인사관리·재무관리를 함께 펼치고 찾기·거르기·트리 접기, 좁은 폭, 작업본·스냅숏을 확인한다. 양쪽 테마의 대비를 재고, 키보드와 스크린리더로 현재 영역·현재 링크·배지 낭독 및 트리 형제 수를 확인한다.

검토는 목업 코드와 설계 문서의 정적 확인으로 진행했다.
