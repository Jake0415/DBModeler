# UX 전문가 리뷰 — 엑셀로 ERD 시작하기(26) 목업

> 대상: `docs/ux/mockups/import-excel.html` (기준 문서: `docs/ux/26-erd-excel-import.md`, 요청: `docs/ux/review/brief-excel-import.md`)
> 비교: `excel-import.html`(표준 사전 엑셀), `import.html`(DDL), `model.html` 관계 패널
> 확인 방법:
> - http://localhost:5178/import-excel.html?area=e_hr&as=kim 에서 직접 해 봤다.
>   - 예시 3개(정상 · 오류 · 다른 영역 참조), 직접 만든 .xlsx 2개(빈 행 · ‘예’/‘o’ 값 · 대상 영역 테이블 참조)
>   - 새 업무 영역, 기존 영역 병합, 덮어쓰기, 완료, [가져오기 취소], 가져온 뒤 모델 관계 패널
>   - `as=hyun`(조회 전용)도 확인했다.
> - 시작할 때 localStorage 50개 키를 백업했고, 끝난 뒤 그대로 복원했다(키 수 · 값 일치 확인).
> - 코드는 고치지 않았다.

상정한 사용자:
- (A) 모델러가 SWS 양식 엑셀을 처음 올려 ERD를 시작한다.
- (B) 고친 엑셀을 다시 올려 작업 중인 영역에 병합한다.

## 높음

### UX-01 가져올 위치를 바꿔도 검사 · 참조 판정을 다시 하지 않는다 — 자기 영역 테이블이 ‘참조 엔터티’로 들어간다
- **심각도:** 높음
- **근거**
  - `import-excel.html:248`: 2단계 검사(`preview`)는 그 순간 3단계 라디오에 골라져 있는 위치로 참조를 판정한다(대상 영역 / 다른 영역).
  - `:314`: 3단계에서 [새 업무 영역 ↔ 기존 업무 영역]을 바꾸면 `plan()`만 다시 돌고, 검사는 다시 하지 않는다. 영역 목록을 바꿀 때(`:315`)만 다시 검사한다.
  - 관찰:
    1. 새 업무 영역이 골라진 상태에서 `BNS_D.EMP_NO → EMP_M.EMP_NO` 파일을 올렸다. 관계 탭에 ‘인사관리 › 사원기본 — 참조로 가져오기’가 나왔다.
    2. 3단계에서 기존 영역 ‘인사관리’로 바꿔 가져왔다.
    3. 결과: 인사관리 안에 **자기 영역 EMP_M의 참조 엔터티(`e_hr_emp`)가 생겼다.** EMP_M이 둘이 되었다. 완료 화면에도 ‘다른 영역 참조 엔터티 1’로 나온다.
  - 반대 방향(기존 → 새 영역)은 코드상 `kind:'target'` 관계가 새 영역에 없는 엔터티 id로 이어진다(`:333`).
- **원인(흐름):** 참조 판정은 위치에 달려 있는데, 위치는 검사 **다음** 단계에서 고른다. 사용자는 2단계에서 본 판정이 최종이라고 믿는다.
- **제안**
  - 위치를 검사 앞으로 옮긴다. 1단계 ‘파일’ 카드 위에 ‘가져올 곳: 새 업무 영역 / 인사관리(지금 영역)’를 두는 것이 가장 단순하다. 모델에서 들어오면 이미 정해져 있다.
  - 3단계에 그대로 둔다면, 위치를 바꿀 때 다시 검사한다. 판정이 바뀌면 ‘위치를 바꿔 참조 판정이 달라졌습니다 — 관계 n건 다시 확인’ 띠를 두고 [관계 보기]로 2단계에 돌아가게 한다.
  - 같은 영역의 테이블을 ‘다른 영역 참조’로 판정하지 않도록 막는다(`findParent`에서 대상 영역 제외 조건을 위치와 묶는다).

### UX-02 덮어쓰기 안내에 ‘빠지는 컬럼’이 없다 — 기존 관계가 FK를 잃은 채 남고 새 관계와 겹친다
- **심각도:** 높음
- **근거**
  - `:311`: 안내에는 ‘엑셀에 없는 **테이블** n개가 빠집니다’와 ‘같은 물리명 테이블은 … 내용은 엑셀 값으로 바뀝니다’만 있다.
  - `:327`: 같은 물리명 테이블은 컬럼 목록을 엑셀 것으로 **통째로 바꾸고**, 모든 컬럼의 `fk · fkg · fkp`를 지운다.
  - `:323`: 양쪽 테이블이 남는 기존 관계는 지우지 않는다. 그 뒤 `:337`의 중복 검사가 `fkp`로 비교하므로, 지워진 FK 때문에 중복을 못 찾는다.
  - 관찰(정상 예시 → 인사관리 덮어쓰기):
    - EMP_M 컬럼이 13개에서 4개가 되었다. ENG_NM · BRDT · JBGD_CD 등 9개가 사라졌는데, 이 내용은 안내에 없다.
    - 관계가 `DEPT_M→EMP_M` 2개, `DEPT_M→DEPT_M` 2개가 되었다. 기존 것(`ga_dept_emp_1`, `g1`)은 FK 짝이 없는 ‘FK 누락’ 관계로 남았다.
  - 시나리오 (B)에서 일부 테이블만 담은 엑셀로 덮어쓰면 조용히 크게 잃는다.
- **제안**
  - 덮어쓰기 안내에 **테이블별 빠지는 컬럼**을 보인다. 예: ‘EMP_M: 컬럼 9개 빠짐(ENG_NM, BRDT …)’, 접어 둔 목록. 같은 물리명인데 바뀌는 컬럼 수도 함께 보인다.
  - 덮어쓰기는 엑셀에 있는 테이블 사이의 관계를 **엑셀 기준으로 바꾼다**. 남는 테이블 사이 기존 관계는 지우고 다시 만든다. ‘관계 n개 바뀜’으로 안내한다.
  - 확인 버튼(`덮어쓰기 확인`)을 위험 색으로 바꾼다. 경고를 발(`#xi-foot`)이 아니라 버튼 바로 옆이나 안내 띠 안에 둔다(UX-11과 함께).
  - 처음 올리는 영역이 아니면 병합을 권한다는 한 줄을 넣는다. 예: ‘일부 테이블만 고친 파일이면 병합을 쓰세요’.

### UX-03 ‘다른 영역 참조’ 선택이 잘 드러나지 않고, 고른 값이 사라진다
- **심각도:** 높음
- **근거**
  - 잘 드러나지 않는다:
    - `:72`: 2단계는 **문제 탭**으로 열린다. 다른 영역 참조 예시는 문제가 없어서 ‘문제가 없습니다’만 보인다.
    - 선택 칸은 관계 탭 비고 열에만 있다(`:259`). 사용자가 관계 탭을 열지 않으면 기본값(켬) 그대로 다른 영역 확정본 사본이 들어간다.
    - 26 §6-3의 결정 취지(‘사용자가 알고 고르는 편이 안전’)와 어긋난다.
  - 고른 값이 사라진다:
    - `:373`: [이전]으로 2단계에 돌아오면 `preview()`가 다시 검사하면서 `take`가 기본값(켬)으로 돌아간다. 관찰: 끄고 → 다음 → 이전 → **다시 켜져 있음**.
    - 영역 목록을 바꿀 때(`:315`)도 같다.
  - 끈 결과가 보이지 않는다:
    - 끄면 FK 컬럼만 남는다(26 §4: ‘끄면 FK 컬럼만 남기고 경고’). 그런데 요약의 관계 수, 문제 목록, 그 행의 표시가 바뀌지 않는다. 결과는 완료 화면(`:365`)에서야 알 수 있다.
    - 3단계 병합 미리보기에도 ‘참조 엔터티 추가: 재무관리 › 자금계획기본’이 나오지 않는다.
- **제안**
  - 요약 줄에 **‘다른 영역 참조 n — 골라 주세요’** 칸을 둔다. 문제 탭에도 ‘확인’ 등급 줄을 둔다(누르면 관계 탭의 그 행으로 간다). 참조가 있으면 2단계를 관계 탭으로 여는 것도 방법이다.
  - 선택은 (자식, 부모, FK 컬럼) 키로 저장한다. 다시 검사해도 유지한다.
  - 끄는 즉시 그 행의 유형 · 선택성 칸을 ‘관계 안 만듦 — FK 컬럼만 남김’으로 바꾸고, 경고 1건을 더한다. 요약의 관계 수에서도 뺀다.
  - 3단계 미리보기(새 영역 · 병합 모두)에 ‘참조 엔터티로 가져옴: 재무관리 › 자금계획기본(확정본 v1)’을 적는다.

## 중간

### UX-04 병합 미리보기에 관계가 없다 — 겹치는 관계가 생기고, 완료 화면의 관계 수가 틀린다
- **심각도:** 중간
- **근거**
  - `:305-308`: 병합 미리보기는 테이블 수와 ‘기존 관계는 그대로 두고 엑셀의 참조만 더합니다’만 말한다.
  - 관찰(정상 예시 → 인사관리 병합):
    - 엑셀은 재귀 FK를 `UPR_DEPT_CD`로, 기존 모델은 `UP_DEPT_CD`로 적었다. 결과 DEPT_M에 **재귀 관계가 2개**가 되었고, 비슷한 컬럼도 2개가 되었다. 미리보기에는 아무 표시가 없었다.
    - `DEPT_M→EMP_M`은 이미 있어서 건너뛰었다. 그래도 완료 화면은 ‘관계 3’이라고 했다. 실제로 더해진 관계는 2개다. `:361`이 `PRE.rels` 수를 쓴다.
- **제안**
  - 병합 미리보기에 관계 줄을 둔다. ‘새로 만듦 n · 이미 있음 n(건너뜀) · **같은 부모-자식 사이에 다른 관계가 이미 있음 n(확인)**’, 목록은 펼쳐 볼 수 있게 한다.
  - 완료 화면과 감사 로그에는 `build()`가 실제로 만든 관계 수를 쓴다.

### UX-05 병합 충돌: 기본값이 ‘엑셀 값’, 한꺼번에 고를 수 없고, 논리명 · 설명은 묻지 않고 바뀐다
- **심각도:** 중간
- **근거**
  - `:301`: 충돌은 타입 · PK · 필수만 잡는다. 기본은 모두 ‘엑셀 값’이다.
  - `:326`, `:328`: 테이블 논리명 · 설명, 컬럼 논리명 · 기본값 · 설명은 묻지 않고 엑셀 값으로 바뀐다. 논리명은 표준 판정의 기준이라 영향이 크다.
  - 시나리오 (B): 첫 가져오기 뒤 ERD에서 고친 값을, 예전 엑셀을 다시 올리면 기본값 그대로 되돌린다. 표준 사전 가져오기(`excel-import.html:673`)에는 기준값 · 현재 · 파일의 3방향 비교가 있는데, 여기에는 없다.
  - 관찰: `EMP_M.EMP_NO`가 `VARCHAR2(20) → VARCHAR2(10)`으로 줄어드는 PK 타입 변경도 다른 충돌과 같은 모양으로 보였다. FMLY_D 등 자식 FK와 맞지 않게 되는데, 그 영향이 표시되지 않는다.
  - ‘—’가 ‘필수 아님 / PK 아님’을 뜻하는데, 빈 값과 구분되지 않는다(`:304`).
  - 엑셀에 없는 기존 컬럼은 병합에서 그대로 남는다. 그런데 이것을 알려 주지 않는다.
- **제안**
  - 충돌 표 위에 [모두 엑셀 값] [모두 지금 값]을 둔다. 충돌이 많은 재업로드에 필요하다.
  - 논리명이 바뀌는 컬럼도 충돌 표에 넣는다. 최소한 ‘논리명 바뀜 n’으로 따로 센다.
  - **참조되는 PK 컬럼의 타입 · 길이가 줄어드는 경우**에는 행에 경고 아이콘을 달고 ‘자식 FK n개와 맞지 않게 됩니다’를 보인다.
  - ‘—’ 대신 ‘필수 아님’ · ‘PK 아님’으로 쓴다.
  - 갱신 줄에 ‘엑셀에 없는 컬럼 n개는 그대로 둠’을 더한다.
  - (구현 단계) 마지막 가져오기 스냅숏을 기준값으로 두고 3방향 비교를 하는 방안을 검토한다.

### UX-06 오류를 고치는 길: ‘검사 결과 엑셀’이 원본과 다르다
- **심각도:** 중간
- **근거**
  - `:266-270`: 검사 결과 파일은 원본에 표시하지 않는다. 읽은 행을 14열로 **다시 만든다**.
    - 빈 행을 건너뛰므로, 빈 행이 있으면 **문제 탭의 행 번호와 파일의 행 번호가 어긋난다.** 문제의 행 번호는 원본 기준(`:175` `i + 2`)이다. 빈 행 1개가 있는 파일로 확인했다.
    - 여러 데이터 시트를 ‘테이블 설계’ 한 장으로 합친다. 시트 이름 기준 위치도 깨진다.
    - 예전 18열 양식의 표준용어 · 원천 열이 사라진다. 26 §1의 원칙(‘원본 보존’)과 어긋난다.
    - 26 §2(문제 셀에 색과 메모)와 달리 끝에 ‘검사 결과’ 열 하나만 붙는다.
  - 26 §2: 문제 탭의 줄을 누르면 해당 행 미리보기로 가야 한다. 지금은 줄을 누를 수 없다(`:254`).
  - 메시지는 문제를 잘 말한다. 다만 무엇을 고칠지는 일부만 말한다. 예: ‘참조 테이블 ‘JOB_M’이 … 없습니다’에는 ‘JOB_M 행을 더하거나 참조 칸을 비우세요’가 없다.
- **제안**
  - 검사 결과는 **원본 통합 문서를 그대로 두고** 다음만 더한다.
    - 데이터 시트마다 오른쪽 끝에 ‘검사 결과’ 열을 붙인다.
    - 문제 셀에 색과 메모를 단다.
    - 맨 앞에 ‘검사 결과’ 요약 시트를 둔다.
  - 이것이 어렵다면 최소한 ‘원본 시트 · 원본 행’ 열을 넣는다.
  - 문제 줄을 누르거나 Enter를 누르면 테이블 탭에서 그 테이블 · 컬럼 줄을 강조한다.
  - 메시지마다 고치는 법을 한 마디씩 붙인다. 예: ‘— 참조 칸을 비우거나 JOB_M 행을 더하세요’, ‘— 자식 컬럼 타입을 VARCHAR2로 맞추세요’.

### UX-07 PK · 필수 칸의 Y 아닌 값을 묻지 않고 ‘아님’으로 읽는다
- **심각도:** 중간
- **근거**
  - `:206`: `toUpperCase() === 'Y'`만 참으로 읽는다.
  - 관찰: 필수 칸에 ‘예’와 ‘o’를 넣은 파일이 **문제 없음**으로 나왔다. 가져온 컬럼은 필수가 아니었다.
  - 현업 엑셀에는 ‘예 · O · ● · 1 · TRUE’가 흔하다. 원본을 고치지 않는다는 원칙이 있으니 더욱 알려야 한다.
- **제안**
  - `Y / N / 빈 칸` 밖의 값은 **오류**로 막는다. 예: ‘PK 칸은 Y 또는 빈 칸으로 쓰세요(‘예’)’.
  - 양식 내려받기의 PK · 필수 열에 데이터 유효성(Y 목록)을 건다.

### UX-08 [가져오기 취소]: 확인 없이 바로 되돌리고, 모델을 열면 사라진다
- **심각도:** 중간
- **근거**
  - `:366`, `:369-371`: 완료 카드의 [가져오기 취소]는 누르면 바로 되돌린다. 새 영역이면 **영역을 지운다.**
  - 관찰: 되돌린 뒤 포커스가 `body`로 빠졌다.

## 유지(고치지 않아도 됨)
- **4단계 구성과 단계 표시.** 파일 → 검사 · 미리보기 → 위치 → 완료가 짧고 분명하다. `aria-current="step"`와 완료 단계 체크 표시가 있다(`:239`).
- **오류가 있으면 [다음]이 꺼진다.** 발에 ‘오류 7건을 엑셀에서 고친 뒤 다시 올리세요 — [검사 결과 표시된 엑셀 받기]로 위치를 확인’이 있다. 이유와 다음 행동이 바로 보인다(`:242`). 상태 배지 ‘오류 있음 — 가져올 수 없음’도 좋다.
- **문제 표.** 오류가 먼저 나오고, 시트 · 행 · 열 · 내용 4가지가 있다. ‘대소문자만 다름’, ‘n행과 다름’처럼 위치를 가리키는 메시지가 26 §3-1과 맞다.
- **원본 보존 원칙 안내.** 1단계 띠에 ‘파일 · 구조 오류만 막고, 이름 · 타입은 고치지 않는다’가 있다(`:65`). 표준 사전 가져오기처럼 화면에서 고치게 하지 않은 것도 이 원칙에 맞다.
- **예시 3개와 양식 내려받기.** 예시 타입이 시스템 DBMS 매핑을 따르고(`:150`), 작성가이드 시트가 있다.
- **덮어쓰기 두 번 누르기와 빠지는 테이블 목록**(`:311`, `:355`). 컬럼 목록(UX-02)만 더하면 된다.
- **잠금 · 권한 사유를 영역 목록 항목에 붙인 것**(‘결재 중’, ‘확정본 — 새 작업 버전을 먼저 시작’, ‘편집 권한 없음’, `:289`). 조회 전용 띠(`:108`)도 좋다.
- **새 영역 이름 검사.** 빈 이름과 같은 이름(보관함 포함)을 막고, 입력란으로 포커스를 옮긴다(`:352`).
- **완료 화면.** 다음 순서(다듬기 → 표준 맞추기 → 구조 점검 → 확정 신청), [표준 맞추기] 바로가기, ‘관계명은 비어 있습니다 — 명사로 입력’ 안내가 26 §6-4와 맞다.
- **관계 만들기 기본 규칙.** 같은 자식 → 부모 묶음, 자식 PK면 식별, 필수면 ‘반드시 있다’, 같은 부모 컬럼이 다시 나오면 새 관계가 26 §4와 맞다. 모델 관계 패널의 FK 짝도 바르게 골라져 있다(`ATND_D.EMP_NO`, `DEPT_M.UPR_DEPT_CD`).
- **확정본 없는 다른 영역은 칸을 끄고 이유를 보인다**(`:215`, `:259`). 26 §6-3 결정과 맞다.
- **끌어 놓기 영역의 키보드.** `role=button` · `tabindex=0` · Enter/Space가 있다(`:57`, `:279`).
