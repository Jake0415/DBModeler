# 결재함 목록 '현재 단계' 미니 결재선 — UX 전문가 검토

> 검토 대상: `assets/app.js` `window.docSteps`, `assets/app.css` 끝 `.mstep`, `approvals.html` 목록(223행)
> 확인: `approvals.html?as=kim&audit=1`(대기함 · 패널 열림) · `&box=mine` · `&box=cc`, `as=hyun`(최종 승인 대기), `as=lee`, 1600×900 · 1920×1000. 시드에 없는 상태(DA 반려 · 최종 반려 · DA/최종 회수 · 2단계 결재선 · 반려 이력 없음)는 `docSteps()`에 가짜 문서를 넣어 렌더링 결과만 확인(저장소 변경 없음).
> 기준: `01-design-guide.md`, `22-list-standard.md` L-11(색만으로 구분 금지) · L-14(열 최소 너비), WCAG 1.4.1 · 1.4.11.

## 한 줄 총평

점을 태그 **앞**에 고정 폭(54px)으로 둔 배치는 옳고(행마다 점이 세로로 정렬되고 1600 패널 열림에서도 줄바꿈 없음), 태그와 역할도 잘 나뉜다(점 = 전체 중 위치, 태그 = 상태 · 누구 차례). 다만 **'진행 안 함' 점이 거의 안 보이고(1.6:1), 반려 점은 색으로만 구분되며, 회수 · 2단계 · 생략이 같은 모양으로 뭉개진다.** 스크린 리더 문구도 길고 태그와 겹친다. 모양 3가지와 문구를 고치면 그대로 써도 된다.

## 지적

### LS-01 · P1 · '진행 안 함' 점이 안 보인다 (WCAG 1.4.11)
- 근거: `.ms-dot.skip { border-color: var(--ds-gray-500) }` = #c9c9c9, 흰 배경 1.6:1 · 선택 행(#f0f7ff)에서 더 낮음 · 다크 ≈2:1. 1600 스크린숏에서 REQ-0007의 세 번째 점이 사실상 사라져 '두 단계짜리'로 보인다. 8px 원의 점선은 대비가 충분해도 실선과 구분이 안 된다(점선 무늬가 2~3조각뿐).
- 권고: '진행 안 함'은 **점선 원 대신 짧은 가로 막대(—)** 로. 모양으로 구분되고 대비 5.7:1.
```css
.mstep .ms-dot.skip { width:8px; height:2px; border:0; border-radius:1px; background:var(--fg-3); }
```

### LS-02 · P1 · 반려가 색으로만 구분된다 (WCAG 1.4.1, 22 L-11)
- 근거: `.rej`는 빨간 채움 8px 원, `.done`은 회색 채움 8px 원 — 모양이 같다. 흑백 · 색각 이상에서 '반려'가 '완료'로 읽힌다. 태그가 '반려됨'이라 정보는 남지만 **어느 단계에서** 반려됐는지는 점만 말한다.
- 권고: 반려 점을 ✕ 모양으로(상세 결재선의 ✕와 같은 뜻).
```css
.mstep .ms-dot.rej { position:relative; width:10px; height:10px; border:0; background:none; }
.mstep .ms-dot.rej::before, .mstep .ms-dot.rej::after { content:""; position:absolute; left:4px; top:-1px; width:2px; height:12px; border-radius:1px; background:var(--danger); transform:rotate(45deg); }
.mstep .ms-dot.rej::after { transform:rotate(-45deg); }
```

### LS-03 · P1 · 회수된 자리가 표시되지 않는다
- 근거: `withdrawn`이면 현재 단계가 `skip`이 되어 DA 회수 = ●─┄─┄, 최종 회수 = ●─●─┄. 후자는 '최종 생략 완료' · '2단계 완료'와 점이 같다. 회수 문서를 훑을 때 "어디까지 갔다가 멈췄나"가 이 열의 핵심 질문인데 답이 없다. 상세 패널은 '진행 안 함 · 회수'로 구분한다.
- 권고: 회수 시점의 단계를 **회색 굵은 고리(멈춤)** 로. 현재(파랑 고리)와 같은 모양, 색만 회색 — 태그 '회수됨'과 짝.
```js
// docSteps 안, st() 앞에
const wdAt = d.step === 'withdrawn' ? (okS('da') && !noFinal ? 'final' : 'da') : null;
// st() 첫 줄에 추가 (skip 판정보다 먼저, noFinal 판정 뒤)
if (s === wdAt) return 'halt';
// W 에 추가
halt: '회수(여기서 멈춤)'
// at 계산에 halt 포함
const at = S3.findIndex(x => ['cur', 'rej', 'halt'].includes(x[2]));
```
```css
.mstep .ms-dot.halt { width:10px; height:10px; border:3px solid var(--fg-3); }
```

### LS-04 · P2 · '최종 승인 없음'(2단계 결재선)과 '생략'이 같은 모양 · 같은 문구
- 근거: `noFinal = !hasFinal(d) || 생략 이력` 하나로 묶여 둘 다 세 번째 자리에 점선 + "최종 승인 없음 진행 안 함". 상세 패널은 '최종 승인 없음(DA 승인으로 완료)' / '최종 승인 생략(신청 당시 설정: 끔)'으로 나눈다. 목록이 상세와 다른 말을 쓴다.
- 권고:
  - **결재선에 최종이 없으면(`!hasFinal(d)`) 세 번째 자리를 그리지 않는다** — 단, 태그 정렬을 위해 자리는 남긴다(`visibility:hidden`). 2단계 결재선은 점 2개로 "원래 두 단계"임이 보인다.
  - **생략(이력에 '생략')** 은 LS-01의 가로 막대, 문구는 '최종 승인 생략'.
```js
const lineNoFinal = !hasFinal(d), skipF = h.some(x => x.step === 'final' && /생략/.test(x.act || ''));
// S3 세 번째 항목
['final', lineNoFinal ? '최종 승인 없음' : skipF ? '최종 승인 생략' : '최종 승인', lineNoFinal ? 'none' : skipF ? 'skip' : st('final')]
```
```css
.mstep .ms-dot.none, .mstep .ms-ln.none { visibility:hidden; }
```
  (마지막 연결선에도 `none` 클래스: `S3[i][2] === 'none' ? 'none' : …`)

### LS-05 · P2 · 스크린 리더 문구가 길고 태그와 겹친다
- 근거: 행(`tr tabindex=0`)에 포커스하면 셀을 차례로 읽는데, 현재 단계 칸에서 "그래픽, 결재 3단계 중 2단계 — 신청 완료, DA 승인 진행 중, 최종 승인 대기" + title(접근 가능한 설명으로 한 번 더) + 태그 "DA 승인 · 내 차례" — **'DA 승인'을 세 번** 듣는다. 대기함은 모든 행이 같은 문장이라 훑기 비용만 커진다. 각 단계 상세는 패널이 이미 준다.
- 권고:
  - `role="img"` + 긴 `aria-label` 대신 **점은 `aria-hidden`, 짧은 sr-only 한 마디**만. 태그가 상태를 말하므로 위치만 보탠다.
  - `title` 삭제(포커스 불가 요소의 툴팁은 키보드로 못 보고, 설명이 중복 낭독됨). 마우스 사용자도 같은 행 클릭으로 패널 결재선을 본다.
```html
<span class="mstep" aria-hidden="true">…점…</span><span class="sr-only">3단계 중 2단계, </span><span class="badge …">DA 승인 · 내 차례</span>
```
  sr-only 문구 규칙: 진행 `n단계 중 m단계` · 반려 `m단계에서 반려` · 회수 `m단계에서 회수` · 완료 `모든 단계 완료` (n은 결재선 실제 단계 수, 신청 포함). 태그가 뒤에 오므로 "3단계 중 2단계, DA 승인 · 내 차례"로 자연스럽게 이어진다.

### LS-06 · P2 · 빈 문구 결함 (반려인데 반려 이력이 없는 문서)
- 근거: `rj`가 없으면 `at = -1`이고 `d.step`이 done/withdrawn이 아니라서 aria-label이 **"결재  — …"**, 점은 ●─┄─┄(어디서 반려됐는지 없음). 이관 · 시드 · 오래된 데이터에서 생길 수 있다.
- 권고: `rejected`인데 `rj`가 없으면 반려 단계를 `hist`의 마지막 처리 단계(없으면 'da')로 추정하고, 문구 끝 분기에 `d.step === 'rejected' ? '반려'`를 넣어 빈 문자열이 나오지 않게.

### LS-07 · P3 · 1600 패널 열림에서 여유 4px — 폭을 줄여 둔다
- 근거: 대기함 · 패널 열림에서 칸 203px에 필요 199px. 태그 '최종 승인 · 내 차례'(110px)가 섞이면 204px로 넘쳐 제목 칸이 줄어든다(`u-nowrap`이라 줄바꿈은 없음). 22 L-14 "패널이 열려도 이름 · 식별자는 보인다"와 경쟁.
- 권고: 연결선 14 → 10px, 오른쪽 여백 8 → 6px(54+8 → 46+6, 10px 절약). 점 크기는 그대로.
```css
.mstep { margin-right:6px; }
.mstep .ms-ln { width:10px; height:1px; }   /* 1.5px는 1배율 화면에서 흐리게 번짐 */
.mstep .ms-ln.done { height:1px; }
```
  (참고: 연결선 #c9c9c9는 장식으로 보아 1.4.11 예외. 진행 정보는 점이 모두 갖는다.)

### LS-08 · P3 · 현재 · 대기 점의 차이가 작다
- 근거: 현재 = 10px · 3px 파랑 고리, 대기 = 8px · 1.5px #666 고리. 흑백에서 크기 2px · 두께 차이로만 구분된다. 태그가 함께 있어 치명적이지 않다.
- 권고: 상세 결재선과 맞추는 범위에서, 현재 점 가운데를 채워 '과녁' 모양으로(`background: radial-gradient(var(--ds-blue-700) 0 1.5px, var(--surface) 2px)`). 상세 결재선 `.pt`도 같은 모양이면 함께, 아니면 보류.

### LS-09 · P3 · 점 아래 단계 이름은 넣지 않는다 (현행 유지)
- 근거: 행 높이 32/36(01 §6.4)에 6~9px 글자를 넣으면 읽히지 않고 높이가 깨진다. 태그가 현재 단계 이름을, 머리줄 '현재 단계'가 축을 이미 말한다. 세 칸의 순서(신청 → DA → 최종)는 상세 패널 가로 결재선과 같아 한 번 보면 학습된다.
- 권고: 라벨 없음 유지. 대신 목록 위 건수 줄 옆 '화면 안내'에 한 줄: "현재 단계의 점 3개는 신청 → DA 승인 → 최종 승인입니다. ◎ 진행 중 · ● 완료 · ✕ 반려 · — 진행 안 함."

### LS-10 · P3 · 점은 태그 앞 (현행 유지), 정렬 기준은 단계 순서
- 근거: 앞에 두면 고정 폭이라 모든 행에서 점이 같은 x(측정값 동일)에 정렬되어 세로로 훑을 수 있다. 뒤에 두면 태그 길이(52~110px)에 따라 점이 들쭉날쭉해진다.
- 권고: 현행 유지. '현재 단계' 칸을 정렬 가능하게 한다면(22 L-8) 정렬 키는 글자가 아닌 **단계 순서**(DA → 최종 → 완료 → 반려 → 회수).

### LS-11 · 참고 · 대기함에서는 점이 정보를 거의 더하지 않는다
- 대기함은 결재자 역할별로 모든 행이 같은 단계(김 = 전부 ●─◎─○)라 점이 반복 무늬다. 가치는 **내 신청 · 참조함 · 전체(감사)** 처럼 단계가 섞인 함에서 크다. 일관성을 위해 대기함에도 두는 것은 찬성(행이 단계가 섞이는 순간 바로 쓸모가 생김). 단, LS-05대로 스크린 리더 문구는 짧게.

## 우선순위

1. **P1** — LS-01(진행 안 함 = 가로 막대), LS-02(반려 = ✕), LS-03(회수 자리 = 회색 고리). CSS 3줄 + `docSteps` 4줄.
2. **P2** — LS-04(2단계 결재선은 점 2개 · 생략 문구), LS-05(aria-hidden + sr-only 한 마디, title 삭제), LS-06(빈 문구 방지).
3. **P3** — LS-07(폭 10px 절약), LS-08(현재 점 과녁), LS-09(화면 안내 범례 한 줄), 마이페이지 적용 · 홈은 폭 확인 뒤.
