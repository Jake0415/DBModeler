# 정리 — 모델 트리 업무 영역 메뉴 구조 (설명 · 바로가기 위치)

- 요청: 사용자 피드백(2026-11-23) — 설명 · 바로가기가 지금 영역에만 있어 배치가 이상함, '모델 · 표준 맞추기' 같은 선택 메뉴의 가독성
- 리뷰: Codex `codex-tree-menu.md`(TM-01~04) · Claude UX `claude-tree-menu.md`(CL-01~06). 두 리뷰 모두 **같은 방향**: 트리는 객체만, 화면 이동은 화면 머리로, 설명은 시스템 홈 · 툴팁으로.
- 상태: **적용 완료(2026-11-23)** — 기록은 `12-model-tree-plan.md` §9.5. 확인: 4개 화면 1920 · 1600 머리 넘침 없음, 모든 영역 다이어그램 폴더, 44회 열기 오류 0, 디자인 점검 46/46.

## 1. 확인된 문제
| # | 문제 | 근거 |
|---|---|---|
| P1 | 바로가기(모델 · 표준 맞추기 · DDL · 산출물)가 13px 회색 글자 링크라 **메뉴로 보이지 않는다**. 바로 위 설명 줄(12px 회색)의 연속처럼 읽힌다 | `app.css` `.tlink` · `.tdesc` |
| P2 | 설명 · 바로가기가 **지금 영역에만** 보여 영역마다 모양이 다르다(직전 작업의 '영역 설명 = 지금 영역' 기본값) | `app.js` `showDesc` |
| P3 | **결함(직전 작업에서 생김):** 같은 조건 안에 '다이어그램' 폴더까지 들어가 **다른 영역은 펼쳐도 다이어그램 폴더가 없다** | `app.js` `if (!qq && showDesc(area))` 블록 |
| P4 | 바로가기가 `role=treeitem` 링크라 트리 형제 수에 들어가고 낭독기는 "모델, 1/8"처럼 객체로 읽는다. Enter · 우클릭 · F2 · Delete에 예외 처리가 필요하다 | `app.js` 링크 행 처리 |
| P5 | 같은 목적지가 세 곳(트리 바로가기 · 영역 ⋯ 메뉴 · 경로의 영역 링크)에 흩어져 역할이 겹친다 | `app.js` 영역 메뉴, `ddl.html` 등 경로 |

## 2. 결정 (두 리뷰 합의 + 엇갈린 점은 아래 판단)
| 항목 | 결정 |
|---|---|
| **트리** | **객체만 둔다.** 바로가기 줄 · 설명 줄을 트리에서 뺀다. 펼친 영역은 **모두 같은 구조**(다이어그램 · 엔터티 · 관계 · 서브타입 · 사용한 표준)다. 거르기 메뉴의 '영역 설명' 설정은 없앤다 |
| **지금 영역 표시** | 모양을 바꾸지 않고 **표시**로 구분한다 — 영역 행 왼쪽 3px 파랑 막대 + `aria-current="true"` + 낭독 "지금 영역" |
| **화면 이동 = 화면 머리 '영역 화면' 메뉴** | 모델 · 표준 맞추기 · DDL · 산출물 화면 머리의 경로 바로 옆에 같은 자리 · 같은 부품으로 둔다: `통합ERP / 인사관리 / [◇ 모델 │ ✓ 표준 맞추기 5 │ DDL │ 산출물]`. 세로 공간을 쓰지 않는다(Claude E안). Codex의 '머리 아래 탭 줄'은 모델 화면 캔버스가 48px 줄어 채택하지 않는다 |
| 메뉴 모양 · 가독성 | `<nav aria-label="인사관리 화면">` 안 링크 4개(이동이므로 버튼이 아니라 링크), 모양은 세그먼트. 높이 28, **아이콘 16 + 글자 14**(글자를 지우지 않음).<br>• 현재 화면: 흰 바탕 + 1px 링 + 글자 진하게 + `aria-current="page"`(굵기만으로 구분하지 않음)<br>• 기본: 글자 `--fg-2`(4.5:1 이상), 묶음 바깥 테두리(3:1)<br>• hover: 회색 바탕 / focus: 2px 포커스 링<br>• 각 링크가 Tab 정지점(←→ 없음) |
| 미준수 배지 | '표준 맞추기' 뒤에 알약 배지(호박색 연한 바탕 · 진한 글자, 4.5:1 이상). **0건이면 숨김.** 낭독은 "표준 맞추기, 미준수 5" 한 번. 배지는 목적지와 같은 **작업본 기준**으로 센다. 스냅숏을 볼 때는 "작업본 기준"을 툴팁 · 낭독에 붙인다 |
| 스냅숏 · 조회 전용 | 모델 · DDL · 산출물 링크는 지금처럼 `snap`을 이어 붙인다. 권한이 없는 화면은 숨기지 않고 비활성 + 이유 툴팁 |
| **설명** | 트리에서 빼고 ① 영역 행 툴팁 + `aria-describedby`, ② **시스템 홈 영역 카드**에 정식으로 둔다(두 리뷰 합의) |
| **영역 행 ⋯ 메뉴** | **어느 영역이든** 열기 · 표준 맞추기 · DDL · 산출물 + 결재함 · 보기 추가 · 복제를 유지한다(Claude 안). 홈 · 시스템 홈처럼 머리 메뉴가 없는 화면에서 다른 영역으로 가는 길이 필요하기 때문이다. (Codex는 ⋯에서 이동 항목을 빼자고 했으나 위 이유로 유지) |
| **경로** | 위로 가기만: 시스템 → 시스템 홈, 영역 → 시스템 홈의 그 영역 카드. 영역 링크가 모델 화면으로 가던 중복은 없앤다 |
| 영역 행 동작 | 클릭 · Enter = 펼치기/접기(지금처럼), 더블클릭 = 모델 열기 |

## 4. 적용 순서 (확인 후)
1. **트리 정리 + 결함 수정:** 바로가기 · 설명 줄 제거, 다이어그램 폴더를 모든 영역에(P3), '영역 설명' 설정 삭제, 링크 행 예외 처리 정리, 지금 영역 파랑 막대.
2. **머리 '영역 화면' 메뉴:** 공통 부품 하나를 만들어 모델 · 표준 맞추기 · DDL · 산출물 머리에 넣는다. 경로 영역 링크 목적지 변경.
3. **설명 이동:** 영역 행 툴팁 · `aria-describedby`, 시스템 홈 영역 카드에 설명 표시.
4. **문서:** `12-model-tree-plan.md` §4 · §9.4의 바로가기 줄 결정 갱신, `01-design-guide.md` §5 · §6.3에 '링크형 세그먼트(영역 화면)' 추가.
5. **검증:** 1920 · 1600에서 머리 폭이 넘치지 않는지 측정(넘치면 1600에서 보조 버튼을 ⋯로 접음), 두 영역을 함께 펼쳐 같은 구조인지, 찾기 · 거르기 · 트리 접기 · 스냅숏, 키보드 · 낭독, 라이트 · 다크 대비, 전체 화면 점검.
