# 종합 — RBAC 2차 검토 (역할별 화면 · 서비스 시나리오)

> 리뷰: Codex [codex-r2rbac](codex-r2rbac.md)(RB-01 ~ 11) · UX [claude-r2rbac](claude-r2rbac.md)(SC-01 ~ 26) · 역할별 화면 목록 [rbac-role-inventory](rbac-role-inventory.md). 요청은 [brief-rbac-r2](brief-rbac-r2.md).
> 상태: **합의 완료 — 구현 중**(2026-11-24). 협의: Codex [codex-r2rbac-agree](codex-r2rbac-agree.md) · UX [claude-r2rbac-agree](claude-r2rbac-agree.md). 아래 표는 초안이고, 협의로 바뀐 점은 맨 아래 **협의 결과**가 우선한다.

## 결론
권한을 `PERMS` 한 곳에서 정하고, 신청자 · 1단계 · 최종 승인자를 나누는 구조는 그대로 둔다. 다만 운영에 내보내려면 다섯 군데를 먼저 메운다.
1. **직무 분리를 끄는 스위치를 Admin 혼자 쥐고 있다**: 결재 정책 · 높은 역할 부여.
2. **결재 판정이 화면마다 다르다**: 자기 승인 · 결재 중 열람.
3. **외주 · 감리 계정의 범위 · 기간 · 회수 · 인계가 없다.**
4. **DDL · 산출물이 권한 · 기록 없이 나간다.**
5. **역할에 따라 첫 화면 · 안내가 맞지 않는 곳이 있다**: 기본 영역 · 할 일 안내 · 낭독.

## 합의안 (초안)
### A. 직무 분리
| # | 심각도 | 수정 | 근거 |
|---|---|---|---|
| R-01 | 높음 | **결재 정책 변경은 두 사람**: 최종 승인 사용 여부 · 자기 승인 정책은 Admin이 바꾸면 바로 적용하지 않는다. **‘기관 담당자 확인 대기’**로 두고, 기관 담당자가 결재함(대기함)에서 [확인] · [거절]한다. 바꾼 사람은 확인할 수 없다. 대기 중에는 설정에 띠를 보인다. 확인 · 거절 모두 감사 로그. | SC-01, RB-03 |
| R-02 | 높음 | **자기 승인 기본값은 비허용.** 허용하더라도 자기 승인한 문서는 최종 승인 단계를 자동으로 붙인다(최종 승인을 끈 결재선이어도). | SC-02 |
| R-03 | 높음 | **높은 역할 부여는 두 사람**: DA · 기관 담당자 · Admin · 감리 역할을 **새로 주는** 변경은 ‘기관 담당자 확인 대기’로 저장한다(빼는 것 · 모델러 · 조회만은 바로). 위험한 겸임(Admin + DA, Admin + 기관 담당자, DA + 기관 담당자)은 저장 전에 경고하고 사유를 받는다. | SC-06 · 15, RB-03 |
| R-04 | 중간 | **Admin은 표준 내용을 바꾸지 않는다**: `type.std` · `type.add` · `dict.group` · `dict.purge`는 DA만. Admin에는 `type.map`(시스템 DBMS 매핑 — 시스템 설정 성격)만 남긴다. | SC-10, RB-03 |
| R-05 | 중간 | **임시 비밀번호**: 새 계정 · 초기화의 임시 비밀번호는 화면에 한 번 보이고, 첫 로그인에서 바꾸기 전에는 결재 · 신청을 못 한다. | SC-07 |

### B. 결재 판정 하나로
| # | 심각도 | 수정 | 근거 |
|---|---|---|---|
| R-06 | 높음 | `canUserAct` · `approversFor` · `lineGaps` · 대기함 · 알림이 **자기 승인 정책**을 함께 본다. 비허용이면 자기 신청은 대기함 · 알림에 뜨지 않고, 신청할 때 “다른 DA가 없어 결재가 멈춥니다”를 먼저 알린다. 1단계 · 최종이 같은 사람뿐이면 신청 전에 막는다. | RB-02, SC-12 |
| R-07 | 높음 | **결재 중 사전 품의 열람**: 목록 · 상세 · 검색에 같은 판정(`canUserSeeDoc`)을 쓴다. 상세의 ‘사전 조회 권한이면 보기’ 예외를 없앤다. | RB-01 |
| R-08 | 중간 | **결재 위임(부재 대리)**: 마이페이지에서 기간 · 대리인(같은 역할 · 같은 범위)을 정한다. 기간 동안 대리인이 처리하고 이력에 ‘대리(원 담당자)’로 남는다. 대리인은 자기 신청을 대리 승인할 수 없다. | SC-13 |

### C. 외주 · 감리 계정
| # | 심각도 | 수정 | 근거 |
|---|---|---|---|
| R-09 | 높음 | 계정에 **소속 구분(내부 · 외주 · 감리)** · **사업명** · **사용 기한**을 둔다. 외주 · 감리는 기한 필수. 기한이 지나면 로그인할 수 없다(목업: 상태 ‘기한 만료’). 사용자 목록에 소속 · 기한 열과 ‘7일 안 만료’ 거르기. | SC-03 |
| R-10 | 높음 | **사업 단위 회수 + 인계**: 사용자 목록에서 사업명으로 묶어 [사업 종료 — 계정 일괄 중지]. 중지 전 인계 단계에서 진행 중 신청(회수 또는 인수자에게 넘김) · 영역 담당 · 엑셀 묶음을 인수자에게 넘긴다. 인수자가 없으면 DA가 대리 회수한다. | SC-04, SC-20 |
| R-11 | 높음 | **조회 범위**: 모델 · DDL · 산출물 · 시스템 전체 ERD 조회를 계정별로 ‘기관 전체’ 또는 ‘담당 시스템만’으로 정한다. **외주 · 감리 기본은 담당 시스템만**, 내부는 기관 전체. 표준 사전은 모두 기관 전체. | RB-04, SC-08 |
| R-12 | 중간 | **감리 역할(`auditor`)**: 읽기 전용 + 끝난 결재 문서 전체 + 감사 로그 + 산출물 내려받기. 진행 중 결재는 못 본다. 기한 필수. | SC-18 |
| R-13 | 낮음 | 외주에게 담당 ‘전체’를 고르면 “앞으로 등록되는 시스템도 포함됩니다” 확인. | SC-23 |

### D. 내보내기 · 감사
| # | 심각도 | 수정 | 근거 |
|---|---|---|---|
| R-14 | 높음 | **`out.export` 권한**: DDL · 산출물 · ERD 내려받기는 모델러 · DA · 기관 담당자 · 감리(조회 범위 안). 조회만은 보기만. 내려받을 때마다 감사 로그(파일 · 버전 · 보안 컬럼 수). 보안 컬럼이 있으면 사유를 받는다. | SC-05 |
| R-15 | 중간 | **기관 담당자 · 감리도 감사 로그 보기**(`audit.view`). | SC-17 |
| R-16 | 중간 | **역할 · 담당 변경 전에 영향 보기**: 저장 전에 늘고 주는 권한, 영향을 받는 진행 결재, 비는 결재 단계를 보인다. 감사에는 역할과 담당 시스템(코드)의 전후를 남긴다. | RB-09, SC-14 · 16 |

### E. 화면 사용성 (역할별)
| # | 심각도 | 수정 | 근거 |
|---|---|---|---|
| R-17 | 낮음 | **모델 화면 조회 전용 낭독**: 지금처럼 띠 없이 도구를 흐리게 끄되(ERD P2-14), 꺼진 도구에 `aria-disabled`와 이유 툴팁(‘모델 편집은 모델러 역할만’)을 붙인다. | 화면 목록 |
| R-18 | 중간 | **첫 화면은 내 담당 시스템**: 표준 맞추기 · DDL 가져오기 · 엑셀로 가져오기의 기본 영역을 담당 시스템의 영역으로 연다. | 화면 목록 |
| R-19 | 중간 | **DA도 업무 영역 만들기**(`area.create`, 담당 시스템). **DA는 설정 › 검수 기준**을 고칠 수 있다(`rules.edit` 새 권한, DA · Admin). DA가 설정을 열면 검수 기준 · 권한표 탭만 보인다. | SC-26 · 09 |
| R-20 | 중간 | **업무 영역 관리 권한 명시**: `area.manage`(이름 · 설명 · 담당 · 옮기기 · 복제 · 사용 중지 · 삭제). 이름 · 설명 · 담당은 담당 모델러 · Admin, 옮기기 · 복제 · 중지 · 삭제는 Admin. `areaActWhy`를 이 권한으로 바꾼다. | SC-11, RB-07 |
| R-21 | 낮음 | **권한표는 모두에게 읽기 전용**: 마이페이지 › 내 역할 옆 [권한표 보기]. | SC-22 |
| R-22 | 낮음 | 권한표 결재 두 줄은 ‘사전: 전체 · 모델: 담당 시스템’ 배지 두 개. 회수 · 영역 관리 · 내보내기 · 감리를 줄로 더한다. | SC-21, RB-08 · 10 |
| R-23 | 낮음 | 할 일 없는 역할의 홈: 조회만 · 감리 · Admin 홈에 역할에 맞는 안내(Admin: 만료 예정 계정 · 확인 대기 · 결재 공백). | 화면 목록 |
| R-24 | 낮음 | 데이터 타입: 요청 권한이 없으면 ‘타입 추가 요청’ 탭 숨김. | 화면 목록 |
| R-25 | 낮음 | 하드코딩 검사 → `can()`. 자기 계정 패널의 담당 시스템 체크 막기. 기관 담당자 수에서 중지 · 만료 계정 빼기. 중지 창의 ‘처리할 결재’는 이 사람이 빠지면 처리할 사람이 없는 문서만. | SC-19 · 24 · 25 · 20 |
| R-26 | 낮음 | 엑셀 ERD 가져오기 취소: 취소 시점에 권한 · 잠금을 다시 확인한다. | RB-05 |

## 하지 않는 것 (기록)
- 서버 트랜잭션 · 세션 강제 종료 · 실제 메일 발송: 구현 단계.
- 역할마다 다른 담당 시스템(겸임 시 역할별 범위, RB-04 일부): 계정 하나에 담당 시스템 하나로 둔다. 필요하면 계정을 나눈다.
- 타입 매핑 전파 권한 분리(RB-06): R-04로 Admin을 빼면 DA 범위만 남는다. 공통 타입 변경의 전파는 지금처럼 영향 확인 창으로 보인다.

## 협의 결과 (최종 — 초안보다 우선)
| # | 최종 결정 | 누구 의견 |
|---|---|---|
| R-01 | **통제가 느슨해지는 변경만** 확인을 받는다(최종 승인 끄기 · 자기 승인 허용으로 바꾸기). 세지는 변경은 바로 적용하고 기관 담당자에게 알린다. 결재함에 **‘확인 요청’ 탭**을 따로 두고 결재 기한 · 준수율 집계에서 뺀다. 확인 화면은 이전 → 이후 · 사유 · 영향을 한 장에. 신청자는 철회할 수 있고, 7일 동안 확인이 없으면 자동 취소. 확인 직전 다시 검사(값이 바뀌었으면 막고 재신청 안내). | UX · Codex |
| R-02 | **기본은 ‘허용 + 최종 승인 자동 부착’**, 비허용은 기관이 고르는 선택지(00-inputs 1-3 겸임 원칙 · DA 1명 기관). 자기 승인은 **독립된 최종 승인자(신청자 아님)가 있을 때만** 할 수 있다. | UX(기본값) · Codex(독립 최종) |
| R-03 | DA · 기관 담당자 · Admin · 감리를 **새로 주거나 그 역할의 담당 시스템을 넓히는** 변경은 확인 대기. 확인 전에도 다른 역할로는 일할 수 있고 ‘역할 확인 대기’ 배지. **신청자와 역할을 받는 사람은 확인할 수 없다.** 위험한 겸임은 경고 + 사유(막지 않음). | UX · Codex |
| R-04 | `type.std` · `type.add` · `type.map` · `dict.group` · `dict.purge`는 **DA만**. `dict.common`(품의 작성)은 DA · Admin 그대로. | UX |
| R-05 | 결재 역할(DA · 기관 담당자 · 감리)은 **본인이 첫 로그인해 임시 비밀번호를 바꾼 뒤에** 열린다. 결재 역할 계정의 비밀번호를 초기화하면 기관 담당자에게 알린다. | UX · Codex |
| R-08 | 결재 위임은 마이페이지에서 기간 · 대리인(같은 역할 · 같은 범위). 실행 때 양쪽 자격 · 기간을 다시 확인, 재위임 없음, 최종 단계 독립성은 원 담당자 · 대리인 모두 기준. | Codex · UX |
| R-09 · R-10 | **사업 목록(N-03)**: 설정 › 기관 › 사업(사업명 · 용역사 · 기간 · 대상 시스템). 사용자 양식은 소속 → 사업 → 기한 · 담당 시스템(사업 값 기본) → 역할. 목록은 이름 옆 배지와 ‘D-n’. [사업 종료]는 사업 상세의 단계형 창(대상 → 인계 항목(신청 · 영역 담당 · 엑셀 묶음 · 후보) → 인수자 → 일괄 중지). 내부 직원이 외주 사업을 맡아도 소속은 내부(N-06). 만료 예고에 남은 일(N-04). | UX · Codex |
| R-11 | 조회 범위는 **소속에서 정한다**(내부 = 기관 전체, 외주 · 감리 = 담당 시스템). 예외만 사유를 받아 바꾼다. 모델 화면 진입 · 영역 목록 · 트리 · 시스템 전체 ERD · DDL · 산출물에 같은 판정. | UX · Codex |
| R-12 | 감리는 **허용 범위의 끝난 문서**만. 기관 관리 로그(설정 · 계정)는 감리에게 기본 공개하지 않는다. | Codex |
| R-14 | DDL · ERD는 감사 로그만. **개인정보 컬럼 목록이 들어간 산출물**은 DA · 기관 담당자 · 감리만, 사유를 받는다. 모델러의 내려받기는 담당 시스템 안. | UX · Codex |
| R-17 | 역할상 편집할 일이 없는 사람(조회만 · DA · 기관 담당자 · 감리 · Admin)은 **편집 도구를 숨기고**, 모델러가 지금만 못 하는 경우(담당 밖 · 결재 중 · 확정본)는 끄고 이유를 보인다. DA · 기관 담당자에게 [역할 변경 요청]을 권하지 않는다. | UX |
| R-19 | DA에게 `area.create`. **검수 기준은 ‘표준 사전 › 검수 기준’ 화면으로 옮긴다**(DA · Admin 고침, 모두 읽기). 설정은 Admin 화면으로 둔다. | UX |
| R-20 | `area.info`(이름 · 설명 · 담당 — 담당 모델러 · Admin) · `area.manage`(옮기기 · 복제 · 중지 · 삭제 — Admin). | Codex · UX |
| R-26 | 중간으로 올린다. | Codex |
| R-27 · R-28 | 시스템 전용 타입은 대상 시스템 코드로 검사, 참조 영향 미리보기는 열람 가능한 버전만 — 구현 단계 기록. | Codex |
| N-01 | 기관 담당자가 0명일 때만 Admin이 첫 1명을 바로 지정(사유 · 감사 · 알림). | UX |
| N-07 | 확인 요청 메일 — 구현 단계. | UX |
