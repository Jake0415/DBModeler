# Codex 리뷰 — 잘못 입력한 값 바로잡기

결정 §5, 목업 반영 §6, 관련 결재함과 DDL 경로를 정적으로 검토했다. 아래 재현 경로는 소스에서 확인했으며 브라우저에서 실행하지 않았다. 목업의 권한 평가는 화면과 저장 함수에 적용된 클라이언트 검사 기준이다.

## 높은 우선순위

### CF-01 · 엔터티 이동이 대상에만 저장돼도 성공으로 표시

- **심각도** 높음
- **근거** `docs/ux/mockups/model.html:2238–2251`, `model.html:296–310,483`. 대상을 먼저 저장하고 이동·감사 기록을 남긴 다음 원본 저장을 렌더링에 맡긴다. 이동 창을 띄운 사이 다른 탭이 원본을 저장하거나 확정 신청하면 원본 저장이 거절되지만 대상에는 엔터티가 남고 성공 토스트가 뜬다. 원본 저장 공간 오류도 같은 결과를 낸다.
- **제안** 실행 직전에 양쪽의 시스템·활성 상태·작업 버전·권한·rev를 검증하고, 두 모델과 이동 기록을 함께 커밋한다. 목업에서 키를 나눠 저장해야 한다면 부분 실패 시 복구할 수 있게 하고 두 저장이 확인된 뒤 성공을 알린다.

### CF-02 · 끊어진 관계의 FK와 충돌한 관계 그룹이 남음

- **심각도** 높음
- **근거** `docs/ux/mockups/model.html:1870,2075–2083,2097,2222–2230,2241–2246`. 이동은 원본 관계를 지우면서 남는 엔터티의 FK 속성을 정리하지 않고, 옮기는 엔터티의 속성은 통째로 복제한다. 예를 들어 부모만 옮기면 원본 자식에 끊긴 FK가 남고, 자식만 옮기면 그 FK가 대상에 따라간다. 자기 참조 관계는 끝점 ID만 바꾸므로 관계 그룹 키 `g`와 속성의 `fkg` 충돌도 처리하지 않는다. 시스템 간 복제에서 참조 관계를 제거할 때도 남는 FK 속성과 보기의 좌표가 정리되지 않는다(`assets/app.js:227–229`).
- **제안** 기존 관계 삭제 규칙을 활용해 끊기는 관계별로 FK를 일반 속성으로 남길지, 함께 제거할지, 식별자와 하위 관계에 어떤 영향이 있는지 미리 보여 준다. 유지하는 자기 참조는 관계 그룹과 FK 매핑을 함께 재할당하고, 보기의 구성원과 좌표도 함께 정리한다.

### CF-03 · 진행 중 결재와 권한을 저장 직전에 검사하지 않음

- **심각도** 높음
- **근거** `docs/ux/mockups/system.html:100–108,121–153`, `assets/app.js:203–230,906–907`, `settings.html:280–310`, `model.html:2278,2238–2244`. 영역 관리 메뉴와 트리 딥링크는 렌더링 당시의 버튼 상태를 사용한다. 저장·복원 함수는 사용자 권한을 재검사하지 않는다. 예를 들어 관리자가 보관 또는 이동 창을 연 뒤 모델러가 다른 탭에서 결재를 신청하면, 실행 시 읽은 `u.review`가 차단에 쓰이지 않아 보관이나 복제가 진행된다. 설정 관리도 창을 여는 시점에만 권한을 확인하고, 엔터티 이동의 확인 버튼은 대상 권한만 재검사한다.
- **제안** 모든 변경 진입점에서 저장 직전에 현재 사용자와 대상 상태를 읽어 영역 정보는 편집자·관리자, 이동·복제·보관·삭제·복원은 관리자, 엔터티 이동은 양쪽 편집자로 검사한다. 보관·이동·복제는 진행 중 결재가 있으면 거부하고, 실패 이유를 창에 표시한다. 서버 구현의 권한 검사도 같은 규칙으로 검증한다.

### CF-04 · 영역 삭제가 시드 영역을 되살리고 오래 열린 모델 탭이 저장할 수 있음

- **심각도** 높음
- **근거** `docs/ux/mockups/assets/app.js:181,185,195–217,235–240`, `model.html:279–308`. 삭제 가능한 시드 영역을 저장소에서 지우면 다음 조회에서 기본 데이터로 다시 채워진다. 보관 상태는 모델 잠금에 반영되지 않는다. 신규 영역 삭제 뒤에는 영역 조회가 기본 영역으로 대체되므로, 열린 탭에서 버전·권한 조건이 맞으면 삭제로 저장 키가 사라진 경우에도 옛 데이터를 다시 쓸 수 있다. `areaUse`는 보관된 참조 영역과 과거 확정·제출 사본을 집계에서 제외한다.
- **제안** 시드 영역의 삭제를 영속적으로 기록하고, 편집 경로에서 ID가 없거나 보관된 영역을 명시적으로 거절한다. 이력 및 참조 판정 범위에 보관 영역과 보존할 버전을 포함한다. 화면은 저장 함수의 실제 결과에 따라 성공을 표시한다.

### CF-05 · 시스템 설정 탭 사이에 등록·수정·보관 내용이 덮어써짐

- **심각도** 높음
- **근거** `docs/ux/mockups/assets/app.js:175–180,2283–2288`, `settings.html:282–289,298–310`. 시스템 목록은 탭을 열 때 한 번 읽고 저장 시 배열 전체를 쓴다. 두 설정 탭을 열어 A에서 새 시스템을 등록한 뒤 B에서 기존 시스템 정보를 저장하면 A에서 등록한 시스템이 목록에서 사라질 수 있다. 이미 그곳으로 복제한 영역의 시스템 코드도 해석할 수 없게 된다.
- **제안** 저장 직전에 최신 시스템 목록을 읽고 해당 시스템만 갱신한다. 동일 항목 충돌을 감지하고 코드 유일성, 대상의 활성 상태, 남은 영역 유무를 함께 검증한다. 시스템 변경도 다른 탭 알림에 포함한다.

### CF-06 · DBMS 정정 뒤 물리 모델 재생성과 과거 DDL 보존이 연결되지 않음

- **심각도** 높음
- **근거** `docs/ux/mockups/system.html:124–125`, `assets/app.js:221–230`, `model.html:982`, `ddl.html:80–91,113–125`. 영향 안내는 대상의 명명·타입 규칙으로 물리 모델을 다시 만든다고 하지만, 이동은 시스템 코드만 바꾸고 복제는 기존 엔터티·속성의 물리 값을 복사한다. 확정 신청 사본에는 당시 스키마가 별도로 고정되지 않으며, DDL은 사본을 열어도 현재 시스템 스키마를 사용한다.
- **제안** 교차 DBMS 작업에서 실제 변환하거나 별도 재적용 단계로 넘길 항목을 확인 창에 명확히 표시한다. 대상 규칙으로 산출물을 검증하고, 확정 사본에는 DDL 재현에 필요한 DBMS·스키마 등 당시 설정을 함께 보존한다.

## 중간 우선순위

### CF-07 · 과거 결재의 이동 표시가 현재 이동 로그에 따라 바뀜

- **심각도** 중간
- **근거** `docs/ux/mockups/assets/app.js:233–234,1015–1021`, `model.html:2242,2248`, `approvals.html:475`. 삭제 쪽 비교는 엔터티 ID와 이름만으로 최대 200건의 전역 로그에서 최신 항목을 찾는다. 같은 ID·이름의 다른 영역 이동이나 재이동이 과거 결재의 목적지를 바꿀 수 있고, 로그가 밀려나면 과거의 이동이 삭제로 보인다.
- **제안** 이동 ID와 출발·도착 영역, 각 작업 버전, 변경 당시 표시명을 양쪽의 결재 사본에 기록한다. 비교에 해당 버전의 이동 건만 사용한다.

### CF-08 · 보관 영역의 결재 문서는 남지만 사본 링크가 다른 영역으로 열림

- **심각도** 중간
- **근거** `docs/ux/mockups/approvals.html:165,461,555,565`, `model.html:234,258–262,888–892`, `assets/app.js:183,498,1600–1602`. 결재 문서는 영역 활성 목록과 별도로 남는다. 그러나 모델 화면에서 보관된 영역을 기본 영역으로 치환한 후 결재 사본의 영역으로 다시 보내려 해서 동일 URL 재이동이 반복될 수 있다. 참조 상세의 원본 링크도 보관 상태를 표시하지 않고 일반 모델 주소로 보낸다.
- **제안** 보관 영역의 기존 결재와 확정본은 원래 열람 권한을 적용해 읽기 전용으로 연다. 참조에는 ‘원본 보관됨’과 참조 버전을 표시하고 해당 사본에 연결한다. 일반 작업본 링크에는 보관 안내를 표시한다.

### CF-09 · 이동 뒤 이전 실행 취소 기록이 원본을 복원할 수 있음

- **심각도** 중간
- **근거** `docs/ux/mockups/model.html:413–425,2232,2244–2250`. 이동 자체의 실행 취소 기록을 만들지 않지만, 직전 편집에서 쌓인 기록은 원본의 전체 모델 상태를 복원한다. 직전 편집 → 이동 → Ctrl+Z 순서로 실행하면 원본에 이동한 엔터티가 되살아나고 대상은 그대로 남을 수 있다.
- **제안** 성공한 이동을 실행 취소·다시 실행의 경계로 삼는다. 대상의 사용자 지정 보기에는 자동 배치되지 않는다는 점을 안내하고, 이동 성공 링크는 엔터티가 보이는 전체 보기로 연결한다.

### CF-10 · 이름과 시스템 연결 검증이 경로마다 다름

- **심각도** 중간
- **근거** `docs/ux/mockups/system.html:137–142,148–151`, `assets/app.js:90–104,221–230`, `settings.html:298–305`. 이름 수정은 활성 영역만 검사하지만 이동·복제·복원에는 같은 시스템의 이름 중복 검사가 없다. 시스템 권한 범위는 표시 이름을 사용하므로 시스템 이름을 바꾸면 기존 이름으로 배정된 사용자의 범위도 달라진다. 교차 시스템 이동에는 원본의 외부 참조를 검증하는 경로도 없다.
- **제안** 같은 시스템 이름 충돌 규칙을 네 경로에 적용하고 복원 가능한 이름의 처리 방침을 명시한다. 사용자 범위는 안정적인 시스템 코드로 식별한다. 교차 시스템 참조는 이동 전 양방향으로 확인하고 발견 시 차단하거나 정리 범위를 명시한다.

### CF-11 · 복제 완료 뒤 원래 시스템 정리로 돌아가는 길이 약함

- **심각도** 중간
- **근거** `docs/ux/mockups/settings.html:114,215–216,223,289–290,293–296`, `system.html:121–126,140–142`. 설정 안내는 원래 시스템의 사용 중지만 설명하고 타입 매핑에는 ‘DBMS를 바꾸면’이라는 문구가 남아 있다. 영역 복제 직후에는 새 모델로 이동하면서 원래 시스템의 남은 영역을 정리할 링크가 없다. 대상이 없다는 안내와 결재 회수 안내도 해당 화면으로 연결되지 않는다.
- **제안** 등록 뒤 원래 시스템 홈, 복제 뒤 원본 영역 정리로 이동하는 링크를 제공한다. 설정 안내에서 이력에 따른 이동·복제와 남은 영역에 따른 시스템 삭제·보관을 같은 용어로 설명한다. 회수 안내에는 해당 문서 링크를 제공한다.

### CF-12 · 빈 대상 목록에서 실행 버튼이 활성화되고 차단 이유가 갱신되지 않음

- **심각도** 중간
- **근거** `docs/ux/mockups/model.html:2220–2227,2235–2240`. 다른 영역이 없을 때 값이 빈 안내 옵션도 활성 옵션으로 검색돼 실행 버튼이 켜진다. 대상이 창을 연 후 결재 중으로 바뀌면 클릭 시 아무 설명 없이 반환한다.
- **제안** 빈 값과 불가 대상을 실행 가능 후보에서 제외한다. 권한·결재·확정으로 막힌 상태의 이유를 셀렉트 밖에도 표시하고, 상태가 바뀌면 실행 버튼과 안내를 함께 갱신한다.

## 낮은 우선순위 및 유지

### CF-13 · ⋯ 메뉴 상태와 모달 취소 후 포커스가 연결되지 않음

- **심각도** 낮음
- **근거** `docs/ux/mockups/system.html:104–110,134–136`, `settings.html:280,297`, `model.html:2235–2237`, `assets/app.js:1214–1217,1520–1522,2295–2302,2336–2342`. 공통 메뉴는 열기, 방향키, Esc를 지원한다. 행 메뉴 항목 실행은 메뉴의 클래스만 닫아 버튼의 `aria-expanded`가 남는다. 영역·시스템 창은 호출 버튼을 기록하지 않아 공통 포커스 복귀가 작동하지 않고, 엔터티 이동 취소는 캔버스로만 돌아간다. 결재 중 보관 창은 숨겨진 사유 입력에 포커스를 주려 하고, 삭제 창은 삭제 버튼에 먼저 포커스를 준다.
- **제안** 공통 닫기 동작으로 메뉴 상태와 포커스를 함께 관리한다. 모달에서 호출 요소를 기록하고 Esc·취소 뒤 원래 버튼이나 트리 항목으로 되돌린다. 실행이 막혔거나 삭제를 확인하는 창의 초기 포커스는 안내 또는 취소에 둔다.

### CF-14 · 결정 및 기존 보호 동작 유지

- **심각도** 유지
- **근거** `docs/ux/mockups/assets/app.js:203–209`의 정보 수정과 전후 감사 기록, `settings.html:213–223,286–289,301–302`의 DBMS 등록 확인과 조회 전용 필드, `model.html:303–304,973–975,2241,2244–2246`의 ID 충돌 회피·원본 보기 정리·rev 검사.
- **제안** 영역 정보의 무결재 수정과 등록 후 DBMS 고정 원칙을 유지한다. 대상 저장이 완료된 뒤 오래 열린 대상 탭의 일반 저장과 확정 신청은 올라간 rev를 보고 거절하므로 이 경로를 유지한다. 모델러의 직접 이동과 다음 결재에서 DA가 확인하는 흐름을 유지하면서 저장과 사본 기록은 CF-01·CF-07에 따라 보완한다.
