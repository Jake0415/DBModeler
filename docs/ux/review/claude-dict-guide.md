# 사전 메뉴 '화면 안내'(pageGuide) 리뷰 — Claude

- 대상: `assets/app.js` `PAGE_GUIDE` · `pageGuide()`, `assets/app.css` `.pguide` / 사전 메뉴 8개 화면
- 확인 방법: http://localhost:5178, 1600×900, `?as=kim&audit=1`(모델러·DA) · `?as=hyun&audit=1`(기관 담당자) — 화면 실제 버튼 · 탭 · 배너 문구와 안내 문구를 대조, 접기/펼치기 · aria · 높이 측정
- 테스트 중 바꾼 `dbm-guide-kim` · `dbm-guide-hyun` 키는 지워서 첫 방문 상태로 되돌렸습니다. 목업 파일은 고치지 않았습니다.

## 한 줄 총평

한 자리 · 한 모양으로 모은 방향은 맞습니다. 다만 **8개 중 5개 화면에서 안내 문구가 화면과 다릅니다**(없는 필터, 다른 버튼 이름, 빠진 종류 탭). 또 **역할을 가리지 않아** 읽기 전용 사용자에게 "쓰고 신청하라"고 안내합니다. **펼친 상태(99px)가 8개 화면마다 따로 열려 있는 것**도 매일 쓰는 사용자에게는 부담입니다. 문구를 화면에 맞추고, 역할별로 갈라 보여 주고, 처음 본 뒤에는 접히게 하면 바로 쓸 수 있는 수준입니다.

---

## 1. 지적 목록

심각도: **P1** 틀린 안내 · 역할 혼동(바로 고칠 것) / **P2** 일관성 · 공간 · 중복 / **P3** 다듬기

### P1

**DG-01 · P1 · 변경 내역(dict-history) · 없는 필터와 틀린 조작을 안내함**
- 근거: 1단계 "기간 · **종류** · 작업(…)으로 거릅니다"라고 하지만 화면에는 단어/용어 같은 '종류' 필터가 없습니다. 칩 묶음(`aria-label="변경 종류"`)은 실제로 작업(전체 · 추가 · 변경 · 미사용 · **공표**)을 거르고, 기간은 선택 상자입니다. 3단계 "'미공표'로 … 봅니다"도 맞지 않습니다. 그런 필터는 없고, 기간 선택의 **'직전 공표 이후'**가 그 역할을 합니다(`?unpub=1`도 이 값으로 바뀜). '언제' 줄은 라벨과 본문이 겹쳐 "**언제 언제** 왜 바뀌었는지"로 읽힙니다. [공표] 버튼은 DA 권한(`dict.publish`)에만 보이는데, 이 사실도 안내에 없습니다.
- 권고: 문구를 화면에 맞춥니다(§2 표). 3단계에 "DA는 [공표 (미공표 n건)]으로 제정 차수를 올림"을 덧붙입니다.

**DG-02 · P1 · 업로드 이력(uploads) · 버튼 이름이 화면과 다름**
- 근거: 안내는 [이어서 하기] · [반영본 확인]이라고 쓰지만 화면 버튼은 **[이어서 작업]**과 **[반영본]**(내려받기) · **[반영본 다시 올려 확인]**입니다. 대괄호는 "화면에 이 이름의 버튼이 있다"는 약속이므로 한 글자라도 다르면 찾지 못합니다. 1단계 "행 수 · 오류 · 신청 문서를 봅니다"도 상태 필터(임시 저장 · 신청됨 · 반영됨 · 반려·회수 · 취소)를 빠뜨렸습니다.
- 권고: 버튼 이름을 화면 그대로 씁니다. **규칙: 안내 문구의 `[ ]`는 화면 버튼 라벨을 그대로 옮긴다**(검수 항목으로 01 디자인 가이드에 추가).

**DG-03 · P1 · 직접 등록(dict-grid) · 종류 탭 수 · 버튼 이름이 다름**
- 근거: 안내는 종류 탭을 "도메인분류 · 단어 · 도메인 · 용어 · 코드" **5개**로 적지만, 화면에는 **6개**(1 도메인분류 · 2 단어 · 3 도메인 · 4 용어 · **5 엔터티 용어** · 6 코드 · 코드값)가 있습니다. 3단계 "검사를 통과한 행을 바구니로 보내"의 실제 버튼은 **[정상 행 바구니에 담기 (n)]**입니다('통과'와 '정상', '보내'와 '담기'가 다름).
- 권고: 탭을 나열하지 말고 "**번호 순서(1 도메인분류부터)**"로 가리킵니다. 탭이 늘어도 문구를 고칠 필요가 없습니다. 버튼명은 화면 그대로 씁니다.

**DG-04 · P1 · 엑셀 가져오기(excel-import) · '파일 하나로 여러 종류'로 오해하게 함 · 화면 단계와 번호가 겹침**
- 근거: 한 줄 설명 "엑셀 파일 하나로 단어 · 용어 · 도메인 · 코드 여러 건을"은 한 파일에 여러 종류를 섞을 수 있다고 읽힙니다. 실제로는 **방식(편집용 파일 다시 올리기 / 빈 양식)과 종류(표준단어 · 표준도메인 · 표준용어 · 코드값) 하나**를 먼저 고릅니다. 또 안내 바로 아래 **6단계 진행 막대**(방식·종류 → 업로드 → 열 매핑 → 검증·비교 → 결과 검토·보정 → 신청)가 붙어 있어서, 번호 원(①②③)이 **두 줄 연달아** 나오고 서로 맞지 않습니다. 3단계 "통과한 행만 골라 신청"은 6단계의 두 갈래, 곧 [신청]과 [바구니로 보내기]를 빠뜨렸습니다.
- 권고: 설명에 "종류 하나를 골라"를 넣습니다. 3단계 앞에 진행 막대 범위를 붙여 **두 번호 체계를 이어 줍니다**(예: "1~2단계 …", "3~5단계 …", "6단계 …"). 또는 이 화면은 안내 단계를 빼고 한 줄 + '언제'만 둡니다(DG-12).

**DG-05 · P1 · 직접 등록 · 엑셀 가져오기 · 후보 큐 · 도메인 그룹 (hyun) · 역할을 가리지 않음 — 읽기 전용 사용자에게 '쓰고 신청하라'고 안내**
- 근거: 기관 담당자(hyun)로 열면 직접 등록과 엑셀 가져오기에는 안내 바로 아래 **읽기 전용 / 열람 전용 배너**가 붙습니다. 그런데 바로 위 안내는 "표에 한 줄씩 씁니다 → 바구니로 보내 신청합니다"라고 합니다. 연속한 두 상자가 서로 반대말을 하는 셈입니다. 후보 큐는 3단계가 모두 DA 조작인데, 모델러(park) · 기관 담당자에게는 조작 버튼이 없습니다. 도메인 그룹은 [그룹 추가] · [분류 추가 신청]이 비활성인데 안내는 만들라고 합니다. 통합 검색의 링크 "새 항목 몇 건 → 직접 등록"도 권한 없는 사용자를 막힌 화면으로 보냅니다.
- 권고: `PAGE_GUIDE` 항목에 **역할별 변형**을 둡니다. 예: `{ d, s, w, l, ro: { d?, s, note } }` 형태로, `can('dict.request')`가 없으면 `ro`를 씁니다. 읽기 전용이면
  - 3단계를 "볼 수 있는 것"으로 바꾸고,
  - 끝에 **"보기만 가능 — 신청은 모델러 · DA에게"** 한 줄을 두고,
  - 이 경우 화면의 읽기 전용 배너를 안내 안으로 합칩니다(상자 2개 → 1개).
  - 권한 없는 화면으로 가는 링크는 숨깁니다.

### P2

**DG-06 · P2 · 전 화면 · '신청 · 품의 · 결재' 용어가 섞임**
- 근거: 통합 검색 머리 버튼은 **[바구니 · 품의]**, 패널 제목은 "바구니 · 품의 올리기"입니다. 그런데 안내는 "바구니에서 한 번에 **신청(결재)**"이라고 하고, 공통표준은 "**품의**를 올립니다", 엑셀 · 직접 등록 · 후보는 "신청", 변경 내역은 "어느 **결재**로"를 씁니다. 처음 쓰는 사용자는 신청 · 품의 · 결재가 다른 절차인지 알 수 없습니다.
- 권고: 안내 문구 규칙을 정합니다. ① 사용자의 행위 = **신청**(배지 '신청 중', '내 신청', '신청 전환'과 같은 말) ② 결재선에 올라간 문서 = **신청 문서**(버튼에 '품의'가 남아 있는 곳은 "[바구니 · 품의]에서 신청"처럼 버튼명만 그대로 인용) ③ 승인 과정 = **결재**. 용어집 팝오버(DG-15)에 "품의 = 결재를 받으려고 올리는 신청 문서"를 적습니다. 장기적으로는 버튼 라벨도 하나로 맞출지 결정이 필요합니다(별도 안건).

**DG-07 · P2 · 전 화면 · '언제' 라벨 오용 — 8개 중 4개가 '언제'가 아님**
- 근거: 업로드 이력 "파일은 30일 임시 보관 · 원본은 올린 사람과 DA만 열람"(보관 정책), 후보 큐 "DA가 처리 · 모델러는 …"(누가), 도메인 그룹 "사전 구축 순서: ① … ⑤ · 공통(행안부) 그룹 · 분류는 읽기 전용…"(순서 + 권한, 95자), 공통표준 "기관 항목과 충돌하는 건은 …"(정책)는 '언제'에 해당하지 않습니다.
- 권고: 메타 줄을 **`언제` / `누가` / `참고`** 세 가지로 나눕니다(값이 있을 때만 표시). '언제'는 "~할 때"로 끝나는 한 구절, 30자 안쪽으로 씁니다.

**DG-08 · P2 · 전 화면 · 문체 · 길이 불일치**
- 근거: 단계 끝맺음이 섞여 있습니다. "찾습니다 · 봅니다"(합니다체)와 "바구니에서 한 번에 신청(결재)" · "DA · 최종 승인 뒤 반영"(명사 종결)이 함께 쓰입니다. 한 줄 설명은 31~62자로 들쭉날쭉하고, 후보 큐(62자)와 공통표준(58자)은 1600 폭에서도 길게 읽힙니다. 'Admin'(도메인 그룹)과 '관리자'(공통표준 화면 안 배너)도 함께 쓰입니다.
- 권고: **한 줄 설명은 "~합니다."로 끝나는 한 문장, 45자 이내**로 씁니다. **단계는 "~합니다"(마침표 없음), 35자 이내, 동사 하나**로 씁니다. 역할명은 화면과 같게 'DA · 관리자'로 통일합니다. 링크는 지금의 "조건 → 화면 이름" 형식을 유지하고, 조건을 **명사구**로 맞춥니다(예: "많은 건 → 엑셀 가져오기", "지난 업로드 → 업로드 이력").

**DG-09 · P2 · 전 화면 · 세로 공간 — 펼친 상태가 화면마다 따로 열림**
- 근거: 1600×900에서 머리 막대 48 + 페이지 머리 56 + 사전 탭 50 + **안내 99 = 253px**입니다. 본문이 화면 높이의 28% 아래에서 시작합니다(접으면 199px). '첫 방문 펼침'이 **화면별**이라, 사전 메뉴를 처음 둘러보는 사용자는 8번 펼쳐진 안내를 보고 8번 접어야 합니다. DA처럼 매일 쓰는 사용자에게 99px은 표 4~5행에 해당합니다.
- 권고:
  1. **첫 방문만 펼치고, 그 화면을 두 번째 열 때는 자동으로 접습니다**(사용자가 직접 펼쳐 둔 경우만 유지). 저장 값을 `{file: 0|1|'auto'}`로 나누면 됩니다.
  2. 펼친 안내 오른쪽 끝에 **[다른 화면도 접기]** 링크를 둡니다(`dbm-guide-<id>`에 `_all: 0`).
  3. 접힌 상태 45px → **36px**로 줄입니다(padding 8 → 4, 한 줄 28px 유지). 펼친 상태도 단계 · 메타를 한 줄로 합칠 수 있는 화면(1920)에서는 2줄로 줄입니다.

**DG-10 · P2 · 공통표준(std-common) · 머리 버튼 · 탭 안 단계와 중복**
- 근거: 링크 "공통 항목 → 통합 검색"은 머리의 **[사전에서 공통 항목 보기]**와 같은 곳(`dictionary.html?src=공통`)으로 갑니다. [새 판 반영] 탭에는 자체 3단계(1 원본 올리기 · 2 판 비교 · 3 품의 올리기)가 있어 안내 2~3단계와 겹칩니다. 한 줄 설명 "행안부 공통표준과 행정표준코드를 **봅니다**"도 부정확합니다. 공통 단어 · 용어는 이 화면에서 보지 않습니다. 이 화면에 있는 것은 판 카드 · 행정표준코드 · 새 판 반영 · 적재 이력입니다.
- 권고: 링크를 "반영 결과 → 변경 내역"으로 바꿉니다(중복 제거 + 다음 행동). 2단계는 탭 단계 이름을 그대로 써서 "원본을 올려 지금 판과 비교"로 고칩니다. 설명은 §2 표대로 고칩니다.

**DG-11 · P2 · 통합 검색(dictionary) · 검색 범위가 검색창 안내보다 좁음**
- 근거: 1단계 "이름 · 영문약어 · 초성으로 찾습니다"인데 검색창 안내는 "이름, 영문약어, 영문명, 이음동의어, 금칙어, 과거 이름, 초성"입니다. 특히 **금칙어 · 과거 이름으로도 찾힌다**는 점은 "있는지 먼저 확인"이라는 이 화면의 목적에 가장 중요한 정보입니다. 3단계 "[바구니에 담기] → 바구니에서 한 번에 신청(결재)"는 실제 머리 버튼 [바구니 · 품의]를 가리키지 못합니다.
- 권고: §2 표의 문구로 바꿉니다.

**DG-12 · P2 · 엑셀 가져오기 · 직접 등록 · 후보 큐 · 화면 자체 안내와의 중복**
- 근거:
  - 엑셀 가져오기: 안내 1단계 괄호 "(지금 사전을 내려받아 고쳐도 됩니다)"가 바로 아래 '어떻게 가져올까요?' 선택 카드(편집용 파일 다시 올리기 / 새 항목 등록)와 같은 내용입니다. 오른쪽 '왕복 편집 규칙' 카드도 있습니다.
  - 직접 등록: 안내(99) → 자동 저장 알림("이전에 쓰던 10행을 불러왔습니다") → 모드 세그먼트 → 종류 탭 → **긴 키보드 안내 줄**(Tab · Enter · Ctrl+Enter …)이 이어져, 표가 화면 절반 아래에서 시작합니다.
  - 후보 큐: 1단계 괄호 "(같은 이름은 한 행 · 발생 위치를 함께 보여 줌)"가 목록 머리 "같은 이름은 한 행으로 묶어 발생 위치를 표시합니다"와 같습니다.
- 권고: 화면이 이미 말하는 내용은 안내에서 뺍니다. 직접 등록의 키보드 안내 줄은 표 머리 오른쪽 **[⌨ 단축키]** 팝오버로 옮기고, 안내 '참고'에는 "단축키는 표 위 ⌨"만 둡니다.

**DG-13 · P2 · 후보 큐 · 대상 범위 · 결과 안내가 화면과 다름**
- 근거: 설명은 "사전에 없는 **단어**를 '후보'로"라고 하지만 목록에는 **용어** 후보(요구사항변경사유내용)도 있습니다. 실제 버튼은 **[단어 신청으로 전환]**(종류에 따라 '용어 신청으로 전환'), **[기존 표준어 사용 안내]**, **[반려]**입니다. 3단계 "발생 위치의 모델러에게 알림"도 화면 문구("처리 결과는 **요청자** 박설계에게 앱 알림")와 대상이 다릅니다.
- 권고: §2 표처럼 DA용과 모델러용 단계를 나눕니다(DG-05).

### P3

**DG-14 · P3 · 전 화면 · 토글 표시와 접근성 다듬기**
- 근거(확인 결과): `aria-expanded` · `aria-controls="pg-more"`가 맞게 바뀝니다. 클릭 뒤에도 포커스가 버튼에 남고, 탭 순서는 사전 탭 → 토글 → 본문입니다. `section[aria-label="이 화면 안내"]`는 region 랜드마크가 됩니다. 대비는 설명 #171717/흰 바탕, 메타 #4D4D4D(약 8.6:1), 링크 #0068D6(약 5.0:1)로 모두 AA를 넘습니다. 남은 문제는 다음과 같습니다.
  - 토글 라벨이 열림 · 닫힘 모두 "사용 방법"이고, 상태는 12px 화살표로만 구분됩니다.
  - 메타 줄 13px은 디자인 가이드 글자 단계(14 본문 / 12 도움말)에 없는 크기입니다.
  - 한 줄 설명이 본문과 같은 14px · 진한 글자색(#171717)이라 표 내용과 같은 무게로 보입니다.
  - 랜드마크가 페이지마다 하나 더 생기므로, 이름을 화면별로 "통합 검색 화면 안내"처럼 바꾸면 랜드마크 목록에서 구분됩니다.
- 권고: 라벨을 **"사용 방법 보기 / 접기"**로 바꾸거나 화살표를 14px로 키웁니다. 메타는 12px(`.caption`)로 맞춥니다. 설명 글자색은 `--fg-2`로 낮춥니다(아이콘 파랑은 유지). aria-label에 화면 이름을 넣습니다. 그 밖에 **`?` 키로 안내 열기/접기**(입력 칸 밖에서만)를 권장합니다.

**DG-15 · P3 · 전 화면 · 빠진 것: 용어집 · 자세한 도움말 · 사전 전체 지도**
- 근거: 안내 문구에 **후보 · 품의 · 공표 · 제정 차수 · 기준본 · 바구니 · 미사용(폐기)**이 설명 없이 나옵니다. 사전 구축 순서(그룹 → 분류 → 단어 → 도메인 → 용어)는 도메인 그룹 화면에만 있어서, 처음 쓰는 사람이 통합 검색에서 시작하면 볼 기회가 없습니다. 더 자세한 설명으로 가는 길도 없습니다.
- 권고:
  1. 안내 안의 핵심 용어에 점선 밑줄 + **용어 팝오버**를 붙입니다(정의 한 문장). 예: "공표 = 승인된 변경을 묶어 기관 사전 제정 차수를 올리는 일(DA)".
  2. 펼친 안내 끝 링크 줄 마지막에 **"사전 전체 흐름 ↗"**(구축 순서 + 메뉴 지도 모달 또는 도움말 문서)을 고정으로 둡니다.
  3. 도메인 그룹의 구축 순서는 그 모달로 옮기고, 도메인 그룹 '참고'에는 한 줄만 남깁니다.

**DG-16 · P3 · 업로드 이력 · '내가 올린'의 범위**
- 근거: 설명은 "내가 올린 엑셀 묶음"인데 목록에는 '올린 사람' 열이 있고, '참고'에는 "원본은 올린 사람과 DA만 열람"이 있습니다. DA가 남의 묶음도 보는지 화면에서 확인되지 않습니다.
- 권고: DA가 전체를 본다면 DA용 설명을 "기관의 엑셀 묶음…"으로 나눕니다(DG-05의 역할 변형으로 처리). 아니라면 '올린 사람' 열을 빼거나 그 이유를 적습니다.
