# 종합 — 잘못 입력한 값 바로잡기(25) 목업 리뷰

> 리뷰: Codex [codex-correction-flows](codex-correction-flows.md)(CF-01 ~ 14) · UX [claude-correction-flows](claude-correction-flows.md)(UC-01 ~ 29). 요청은 [brief-correction-flows](brief-correction-flows.md).
> 상태: **X-01 ~ X-15 적용 완료**(2026-11-24) — 기록은 [25 §7](../25-correction-flows.md).

## 결론
결정 세 가지(이름 수정은 결재 없음 · 엔터티 이동은 모델러 · DBMS 변경 불가)는 두 리뷰 모두 유지로 봤다. 고칠 것은 셋이다.
1. **엔터티 이동의 일관성**: 저장 순서, FK, 참조 정리, Ctrl+Z.
2. **실행 직전 재검사와 삭제 안전**
3. **DBMS 바로잡기 흐름에서 다음 행동이 보이지 않는 문제**

## 합의된 수정
| # | 심각도 | 수정 | 근거 |
|---|---|---|---|
| X-01 | 높음 | **엔터티 이동을 한 덩어리로**<br>· 실행 직전에 두 영역의 상태 · 권한 · 버전을 다시 검사한다.<br>· 원래 영역을 먼저 저장하고, 실패하면 아무것도 옮기지 않는다. 대상 저장이 실패하면 원래 영역을 되돌린다.<br>· 성공 뒤에는 Ctrl+Z 기록을 비운다(이동이 경계). | CF-01 · 09, UC-07 · 11 |
| X-02 | 높음 | **끊기는 관계의 FK 정리**<br>· 끊기는 관계의 FK 속성은 일반 속성으로 바꾸고, 창에 개수와 목록을 보여 준다.<br>· 자기 참조 관계는 대상에서 관계 그룹(g · fkg)이 겹치면 새로 붙인다. | CF-02, UC-02 |
| X-03 | 높음 | **참조 정리**<br>· 대상 영역에 이 엔터티의 참조가 있으면 실체로 바꾸고, 그 참조에 걸린 관계를 실체로 다시 잇는다(같은 엔터티 2개 방지).<br>· 다른 영역의 참조는 작업 중이면 새 원본을 가리키게 고치고, 잠겨 있으면 창에 목록을 보여 준다. | UC-01 |
| X-04 | 높음 | **영역 작업 실행 직전 재검사**<br>· 권한(정보 수정은 편집자 · 관리자, 나머지는 관리자)과 결재 중 여부를 함수 안에서 다시 확인하고, 이유를 창에 표시한다. | CF-03, UC-15 |
| X-05 | 높음 | **삭제 안전**<br>· 삭제 창의 첫 포커스는 [취소]에 둔다.<br>· 삭제한 영역은 기록해 기본 데이터로 되살아나지 않게 한다.<br>· 없어진 · 보관된 영역에는 모델 저장을 거절한다.<br>· 참조 판정에 보관 영역도 넣는다. | CF-04, UC-08 · 16 |
| X-06 | 높음 | **시스템 목록 덮어쓰기 방지**: 저장 직전에 최신 목록을 읽고 그 시스템만 바꾼다. | CF-05 |
| X-07 | 높음 | **물리 타입 변환을 실제로**<br>· 다른 DBMS로 옮기거나 복제할 때 컬럼 타입을 변환한다(Oracle · Tibero ↔ PostgreSQL ↔ MySQL).<br>· 창에 변환 건수를 보여 준다.<br>· 확정 사본에는 당시 DBMS · 스키마를 남긴다. | CF-06, UC-09 |
| X-08 | 높음 | **바로잡기 흐름**<br>· 옮기기 · 복제의 대상 기본값은 최근 등록한 시스템으로 한다.<br>· 등록 뒤 토스트에 [원래 시스템 홈] 링크를 단다.<br>· 복제 뒤에는 원래 시스템 홈에 남아 원본 [사용 중지] 창을 바로 연다(사유 미리 채움).<br>· 영역이 참조하던 원래 시스템 영역은 영향 목록에 보여 준다.<br>· 먼저 복제한 영역에 대한 참조는 복제본끼리 다시 잇는다. | UC-03 · 04 · 05 · 06, CF-11 |
| X-09 | 중간 | **보관 영역 열람**<br>· 결재 문서 · 참조 링크로 보관 영역을 열면 조회 전용으로 연다.<br>· 같은 주소를 반복해서 다시 열지 않게 한다. | CF-08 |
| X-10 | 중간 | **이름 중복**: 옮기기 · 복제 · 다시 사용에도 같은 시스템 이름 중복 검사를 한다(보관 영역 포함). | CF-10, UC-16 |
| X-11 | 중간 | **막힘 이유**<br>· 엔터티 이동 대상이 막히면 이유를 셀렉트 밖에 표시한다.<br>· 빈 대상일 때는 [옮기기]를 끈다.<br>· 결재 중으로 막히면 결재함 링크를 단다. | CF-12, UC-17 |
| X-12 | 중간 | **포커스 · 메뉴**<br>· 창을 닫으면 연 버튼으로 포커스를 돌린다.<br>· 메뉴 항목 실행 뒤 `aria-expanded`를 끈다.<br>· 막힌 창의 첫 포커스는 안내 또는 [취소]에 둔다. | CF-13, UC-10 |
| X-13 | 중간 | **시스템 등록 · 정보 창**<br>· 오류는 칸 아래에 보이고 첫 오류 칸에 포커스를 준다(R-01).<br>· 사용 중지 · 삭제는 창 안에서 두 번 눌러 확인한다(브라우저 confirm 쓰지 않음). | UC-12 · 13 |
| X-14 | 중간 | **트리 영역 메뉴**<br>· 시연용 ‘영역 복제’를 없앤다.<br>· 권한이 없으면 이유와 함께 막는다. | UC-14 |
| X-15 | 낮음 | **문구 · 위치**<br>· ‘DBMS를 바꾸면’ 같은 옛 문구를 정리한다.<br>· 사용 중지 뒤에는 보관함을 펼친다.<br>· 등록하면 상단 시스템 메뉴에 바로 보인다. | UC-18 · 19 · 20 |

## 이번에 하지 않는 것 (기록)
- **이동 기록의 결재 사본 고정**(CF-07): 지금은 전역 이동 로그에서 id · 이름으로 찾는다. 구현 단계에서 확정 사본에 이동 건을 함께 저장한다.
- **시스템별 타입 매핑 표**(UC-09 일부): 설정의 타입 매핑 표는 아직 한 벌이다. 구현 단계에서 DBMS별 기본값을 둔다.
- **시스템 전체 한 번에 옮기기**(UC-06 일부): 영역마다 하는 왕복은 X-08로 줄인다. 일괄 이동은 다음 단계에서 다룬다.
- 시스템 권한 범위를 이름이 아니라 코드로 바꾸기(CF-10 일부)는 사용자 데이터 구조를 바꾸는 일이라 구현 단계에서 한다.
