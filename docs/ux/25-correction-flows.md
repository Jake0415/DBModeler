# 25. 잘못 입력한 값 바로잡기 — 시스템 · 업무 영역 · 모델 (v0 초안, 2026-11-24)

> 질문: 시스템을 설정하고 모델링을 시작한 뒤에 업무 영역이나 DB 정보가 잘못 들어간 것을 알게 되면 어떻게 고치나?
> 범위: 목업(`system.html` · `settings.html` · `model.html` · `assets/app.js`)을 점검한 결과와 수정 방안. **목업에는 아직 반영하지 않았다.**

## 1. 지금 목업에서 고칠 수 있는 것 / 없는 것
| 잘못 들어간 것 | 지금 고칠 수 있나 | 근거 |
|---|---|---|
| 엔터티 · 속성 · 관계 내용 | **됨** — 작업 중이면 바로 고침(Ctrl+Z · 버전 비교). 검토 중이면 회수 뒤 고침. 확정본이면 새 작업 버전 → 다시 확정 결재 | 모델 트리 메뉴 이름 바꾸기 · 삭제, 결재 회수 |
| 명명 템플릿 · 타입 매핑 · 시스템 컬럼 | **됨** — 설정 › 시스템에서 저장. 다음 DDL · 물리 반영부터 적용. [영향 미리보기] | settings.html 시스템 탭 |
| 업무 영역 **이름 · 설명** | **안 됨** — 만들 때 이름만 받고 이후 바꾸는 곳 없음 | system.html 새 업무 영역 창만 있음, 트리 영역 메뉴에 이름 바꾸기 없음 |
| 업무 영역 **잘못 만듦(중복 · 오타 · 필요 없음)** | **안 됨** — 삭제 · 보관 없음 | 같음 |
| 업무 영역을 **다른 시스템에 만듦** | **안 됨** — 시스템 간 이동 없음(영역 복제도 같은 시스템 안, 시연만) | app.js 트리 영역 메뉴 '영역 복제'(목업 시연) |
| 엔터티를 **다른 업무 영역에 만듦** | **안 됨** — 다른 영역에서 ‘참조’만 됨, 옮기기 없음 | app.js 엔터티 메뉴 '지금 영역에 참조 추가' |
| 업무 영역 **담당자** | **안 됨** — 화면에 고정 값 | system.html `OWN` 고정 |
| 시스템의 **DBMS · 버전 · 스키마** | **안 됨** — 설정에서 조회 전용(“시스템을 등록할 때 정합니다”)인데 **시스템 등록 · 수정 화면이 없음** | settings.html `#sys-dbms` disabled, `SYSLIST` 고정 |
| **시스템 자체** 추가 · 이름 · 삭제 | **안 됨** | `SYSLIST` 고정 2개 |

→ **모델 안의 내용은 고칠 수 있지만, 그 틀(시스템 · 업무 영역)은 한 번 만들면 고칠 길이 없다.** 이것이 빈칸이다.

## 2. 바로잡기 원칙 (사용자 · 역할 관리와 같은 규칙)
1. **이름 · 설명 · 담당 같은 정보 값은 언제든 고친다.** 결재 없이 고치고, 감사 로그에 남긴다. 다른 곳에 보이는 이름(참조 · 결재 문서 제목 · 산출물)은 새 이름으로 보인다. 이미 만든 결재 문서와 확정본에는 당시 이름이 남는다.
2. **모델 내용과 구조는 상태에 따라 고친다.**
   | 상태 | 고치는 법 |
   |---|---|
   | 작업 중 · 확정본 없음 | 바로 고침 · 지움 |
   | 검토 중(결재 진행) | 먼저 **회수** → 작업 중으로 돌아와 고침 |
   | 확정본 있음 | 확정본은 그대로 두고 **새 작업 버전**에서 고침 → 다시 확정 결재 |
3. **이력이 있으면 지우지 않고 ‘사용 중지(보관)’한다.** 확정본 · 결재 문서 · 다른 영역의 참조가 하나라도 있으면 삭제는 막고 보관만 된다(계정 삭제와 같은 규칙). 보관한 것은 목록에서 숨고 조회 전용, 언제든 다시 쓸 수 있다.
4. **물리 설계에 영향이 큰 값(DBMS · 스키마 · 시스템 이동)은 바꾸기 전에 영향을 보여 준다.** 바뀌는 컬럼 수 · 테이블 수 · 업무 영역 · 진행 중 결재를 보여 주고 확인 뒤 저장한다(설정의 ‘영향이 큰 변경’ 확인 창과 같은 꼴).
5. **확정본은 바꾸지 않는다.** 이미 확정한 버전의 DDL · 산출물은 확정할 때의 값(DBMS · 이름 규칙)으로 남는다. 새 값은 작업 버전과 다음 확정부터 적용된다.

## 3. 경우별 수정 방안
### 3-1. 업무 영역 이름 · 설명 · 담당이 틀림
- **어디서**: 시스템 홈 업무 영역 표의 행 메뉴 ⋯ › **[영역 정보 수정]**, 모델 트리 영역 메뉴 › 같은 항목.
- **누가**: 그 영역 담당 모델러 · 관리자.
- **무엇을**: 이름(같은 시스템 안에서 중복 금지) · 설명 · 담당 모델러.
- **결과**: 바로 적용 · 감사 로그 ‘업무 영역 정보 수정(이전 → 이후)’. 다른 영역의 참조 이름과 결재함 표시도 새 이름으로 바뀐다. 이미 만든 결재 문서 본문과 확정본은 당시 이름 그대로다.

### 3-2. 업무 영역을 잘못 만듦(오타 · 중복 · 필요 없음)
- **[삭제]**: 확정본 · 결재 문서 · 다른 영역의 참조가 **하나도 없을 때만**. 확인 창에 엔터티 수를 보여 주고, 되돌릴 수 없다고 알린다.
- **[사용 중지(보관)]**: 이력이 있을 때. 트리 · 시스템 홈에서 숨김(‘보관함 보기’로 열기), 조회 전용, 진행 중 결재가 있으면 먼저 회수하라고 막는다. 다른 영역이 참조 중이면 그 영역 목록을 보여 주고, 참조는 ‘원본 보관됨’으로 표시한다.
- **중복으로 만든 경우**: [다른 영역으로 옮기기](3-4)로 엔터티를 맞는 영역으로 옮긴 뒤 빈 영역을 삭제한다.

### 3-3. 업무 영역을 다른 시스템에 만듦
- **확정본 · 결재 이력이 없을 때**: 영역 메뉴 › **[다른 시스템으로 옮기기]**(관리자). 대상 시스템의 DBMS · 명명 템플릿 · 타입 매핑으로 물리 모델을 다시 만든다는 영향을 보여 준 뒤 옮긴다. 다른 영역에서 참조하던 관계는 끊김 목록으로 보여 준다.
- **확정본이 있을 때**: 옮기지 않는다. **[다른 시스템으로 복제]**로 대상 시스템에 새 영역(v1 작업 중)을 만들고, 원본은 3-2 규칙으로 보관한다. 원본 이력은 그대로 남는다.

### 3-4. 엔터티를 다른 업무 영역에 만듦
- **어디서**: 엔터티 메뉴 › **[다른 영역으로 옮기기…]** → 같은 시스템의 영역 고르기.
- **조건**: 두 영역 모두 **작업 중**이고 편집 권한이 있어야 한다. 검토 중이면 회수부터.
- **결과**: 원래 영역에서 빠지고 대상 영역에 추가된다. 원래 영역에 남은 관계는 대상 영역 엔터티를 **참조**하는 관계로 바뀐다. 두 영역의 다음 확정 결재에 ‘이동(→ ○○ 영역)’ · ‘이동(← ○○ 영역)’으로 보인다(버전 비교 · 결재 변경 내역).
- 엔터티가 원래 영역 **확정본에 이미 있으면** 확정본은 그대로이고, 다음 확정 때 ‘삭제(이동)’로 결재받는다.

### 3-5. 시스템 DBMS · 버전 · 스키마가 틀림
- **어디서**: 시스템 홈 머리 **[시스템 정보]**(관리자) — 설정 › 시스템의 조회 전용 칸 옆 링크도 여기로.
- **영향 미리보기**(저장 전 확인 창):
  - 타입이 바뀌는 컬럼 수(예: Oracle `VARCHAR2` → PostgreSQL `VARCHAR`)
  - 이름 길이 · 예약어 위반이 새로 생기는 테이블 · 컬럼
  - 업무 영역별 영향
  - 진행 중 결재
- **규칙**:
  - 논리 모델은 그대로다. 각 영역의 **작업 버전** 물리 모델은 새 타입 매핑으로 다시 계산한다.
  - 확정본과 이미 만든 DDL은 당시 DBMS로 남는다.
  - 검토 중인 영역이 있으면 경고한다. 그 결재는 옛 값으로 끝나고, 다음 버전부터 새 값을 쓴다.
  - 감사 로그에 남긴다.
- 스키마(소유자)만 틀린 경우: DDL의 스키마 접두만 바뀌므로 영향 미리보기 없이 저장한다. 감사 로그에는 남긴다.

### 3-6. 명명 템플릿 · 타입 매핑이 틀림 (지금도 됨 — 보강)
- 지금: 설정 › 시스템에서 저장 → 다음 DDL · 물리 반영부터 적용.
- **보강**: 모델 › 물리 보기에 **[이름 · 타입 규칙 다시 적용]**을 둔다. 작업 버전의 테이블 · 컬럼 · 제약조건 이름과 타입을 새 규칙으로 다시 만든다. 바뀌는 항목을 미리 보여 주고 고른 것만 적용한다. 직접 고친 물리명은 ‘직접 지정’이라 건너뛴다.

### 3-7. 시스템 자체가 틀림(이름 · 중복 · 필요 없음)
- **어디서**: 설정 › 시스템 탭 시스템 고르기 옆 **[시스템 등록]** · **[시스템 정보]**.
- 이름 · 설명은 3-1처럼 바로 고친다. 삭제는 업무 영역이 하나도 없을 때만 하고, 있으면 보관한다(3-2).

## 5. 정할 것 (사용자 확인)
1. 업무 영역 이름을 바꿀 때 **결재 없이** 바로 바꿔도 되는가(제안: 결재 없이 · 감사 로그만).
2. 엔터티 영역 이동을 **모델러가 직접** 하는가, DA 확인을 거치는가(제안: 모델러 직접 · 다음 확정 결재에서 DA가 봄).
3. DBMS 변경을 허용하는가, **새 시스템을 만들어 복제**하게만 하는가(제안: 허용 · 영향 미리보기 필수 · 관리자만).
