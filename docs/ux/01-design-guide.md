## 1. 원칙

| # | 원칙 | 적용 |
|---|---|---|
| 1 | **무채색이 기본, 색은 의미에만** | 회색 단계와 잉크색(거의 검정)이 기본. 색은 상태(표준 · 결재 · 오류)에만 쓴다. 그라데이션 · 장식 색 없음 |
| 2 | **주 버튼은 화면당 하나** | 잉크색 채움 버튼은 화면(또는 열린 패널 · 모달)당 1개. 단계형 화면은 지금 단계의 버튼만 주 버튼 |
| 3 | **얇은 선과 낮은 그림자** | 구분은 1px 선. 그림자는 떠 있는 것(메뉴 · 모달 · 토스트)에만 |
| 4 | **촘촘하되 답답하지 않게** | 표 행 36px(기본), 컨트롤 32px. 그룹 사이 여백은 충분히 |
| 5 | **두 글꼴 목소리** | 한글 UI는 Pretendard(라틴 · 숫자는 Geist). 물리명 · 약어 · 코드 · DDL · 도메인명은 Geist Mono |
| 6 | **색만으로 전달하지 않는다** | 상태는 색 + 글자(또는 아이콘). 비활성은 이유를 툴팁 · 설명으로 |
| 7 | **결과는 항상 보인다** | 0건 · 실패 · 미산정도 표시한다. "0%" 대신 "미산정" |
| 8 | **한 역할 = 한 부품** | 같은 역할(상태 · 탭 · 표 · 버튼)은 모든 화면에서 같은 부품을 쓴다. 화면에서 새로 그리지 않는다 |

## 2. 색 토큰

화면 코드에는 hex를 쓰지 않는다. 아래 토큰만 쓴다(`assets/app.css` `:root`).

### 2.1 단계(Geist)
- 제공하는 단계만 쓴다:
  - 회색 `--ds-gray-100 · 200 · 300 · 400 · 500 · 600 · 700 · 800 · 900 · 1000`
  - 파랑 `100 · 200 · 300 · 400 · 700 · 800 · 900`
  - 초록 `100 · 200 · 400 · 700 · 900`
  - 빨강 `100 · 200 · 400 · 700 · 800 · 900`
  - 호박 `100 · 200 · 400 · 700 · 800 · 900`
  - 바탕 `--ds-background-100/200`
  - 없는 단계(예: `--ds-blue-500`)를 쓰지 않는다.
- 단계별 쓰임:
  - 100~300: 바탕(기본 · hover · 눌림)
  - 400~600: 선
  - 700~800: 채움
  - 900: 보조 글자
  - 1000: 본문 글자
- 글자는 900 · 1000만 쓴다(700은 흰 바탕에서 4.5:1 미달).
- 다크 테마는 같은 이름에 다른 값을 넣는다(`:root[data-theme="dark"]`).

### 2.2 화면이 쓰는 이름
| 토큰 | 값 | 쓰임 |
|---|---|---|
| `--bg` · `--surface` | background-100 | 바탕 · 패널 |
| `--surface-2` | gray-100 | hover · 입력 비활성 · 코드 영역 |
| `--nav-bg` · `--nav-line` | background-200 · gray-400 | 상단 바 · 모델 트리(ㄱ자 틀) |
| `--border` · `--border-strong` | gray-400 · gray-500 | 1px 선 · 강조 선 |
| `--fg` · `--fg-2` · `--fg-3` | gray-1000 · gray-900 · #666 | 본문 · 보조 · 메타(5.7:1) |
| `--ink` · `--on-ink` | gray-1000 · 흰색 | 주 버튼 |
| `--focus` | blue-700 | 포커스 링 |
| `--info` · `--success` · `--warning` · `--danger` (+ `-soft` · `-deep`) | blue · green · amber · red 단계 | 의미 색 |
| `--violet` | gray-900 | 예외(무채색으로 둔다 — 색을 늘리지 않음) |
| `--p-1` · `--p-2` … | 공동 편집자 색 | 모델 캔버스의 다른 사용자 커서 · 표시(화면에 hex 금지) |

### 2.3 상태 → 표시 (모든 화면 공통, D2)
상태 표시는 **배지 하나(`.badge`)**로 그린다. v8 꼬리표(`.tag`)는 쓰지 않는다.

| 의미 | 클래스 | 모양 |
|---|---|---|
| 표준 · 승인 · 완료 · 정상 | `.badge.b-success` | 초록 바탕 |
| **내 차례**(내가 처리할 것) · 정보 · 조합 가능 · 신청 중 | `.badge.b-info` · `tag('mine')` | 파랑 바탕 — 가장 눈에 띈다 |
| 진행 중 · 대기(남의 차례) | `.badge` · `tag('run')` | 회색 바탕 |
| 경고 · 미등록 단어 · 미산정 · 기한 임박 | `.badge.b-warning` | 호박 바탕 |
| 오류 · 반려 · 차단 · 기한 넘김 | `.badge.b-danger` | 빨강 바탕 |
| 예외(사유 있음) | `.badge.b-ex` | 점선 테두리 |
| 중립(분류 · 개수 · 공통 출처) | `.badge` · `.b-common` | 회색 바탕 |
| 기관 출처 | `.badge.b-org` | 테두리만 |
| 끝남 · 회수 · 비대상 | `.badge.b-end` | 바탕 없이 흐린 글자 |

- 한 행에 상태 배지는 하나다. 배지 안 글자는 상태 이름 그대로 쓴다(색만으로 구분하지 않음). 내 차례 배지에는 "내 차례"를 글자로 쓴다.
- "자기 승인"처럼 상태가 아닌 덧붙임은 배지가 아니라 회색 글자 `(자기 승인)`로 쓴다.
- 다크에서 배지 테두리(예외 · 기관)는 3:1 이상(gray-600).
- 표 행 왼쪽 색 막대는 쓰지 않는다(상태는 배지).

## 3. 글자

| 역할 | 크기 / 굵기 / 줄 높이 | 쓰임 |
|---|---|---|
| 화면 제목 | 20 / 600 / 28 | 페이지 헤더 `h1` |
| 패널 · 모달 제목 | 16 / 600 / 24 | 우측 패널 `h2`, 모달 `h3` |
| 묶음 제목 | 14 / 600 / 20 | 섹션 제목(`.sec-h`, `.section-t`) |
| 본문 · 표 · 버튼 · 입력 | 14 / 400(버튼 500) / 20 | 기본 |
| 메타 · 도움말 · 배지 | 12 / 400(배지 500) / 16 | `.caption`, 표 아래 설명 |
| 코드 · 물리명 | 13 / 400 / 20 Geist Mono | `.mono`, DDL |

- 굵기는 **400 · 500 · 600만** 쓴다. `<b>` · `<strong>`도 600이다(700 금지).
- **최소 12px.** 예외: 모델 캔버스는 100% 배율에서 12px 이상이면 되고, 축소 표시는 작아져도 된다.
- 숫자는 같은 폭 숫자(`tabular-nums`)를 쓴다. 한글 제목 자간 -0.3px, 본문 -0.1px.

## 4. 간격 · 반경 · 선 · 그림자

- 간격: 4px 단위 `4 · 8 · 12 · 16 · 20 · 24 · 32 · 48`.
  - 화면 좌우 여백 20, 패널 안 16, 폼 필드 사이 12, 섹션 사이 24~32.
  - 여백은 부품 기본값과 **유틸리티 `u-*`**로만 준다. 인라인 `style="margin…"`은 쓰지 않는다.
  - 유틸리티 목록(`app.css` 15절):
    - 간격: `u-mt-0/4/8/12/16/20/24`, `u-mb-…`, `u-my-8`, `u-gap-4/8/12/16/24`, `u-p-0/16/24/32`, `u-ml-auto`, `u-ml-24`
    - 배치: `u-flex`, `u-col`, `u-flex-1`, `u-wrap`, `u-jc-c`, `u-ai-c`, `u-rel`, `u-nowrap`
    - 크기: `u-w-*`, `u-h-*`
    - 글자 · 색: `u-fs-12/14/16`, `u-fw-*`, `u-lh-20/22`, `u-tc`, `u-tr`, `u-fg/fg2/fg3`, `u-danger`, `u-warning`, `u-success`, `u-accent`
    - 기타: `u-bg`, `u-bg2`, `u-bb`, `u-r-md`, `u-op-50`
    - 간격은 위 단계 값만 둔다.
  - **계약**: 유틸리티는 인라인 스타일을 대신하므로 `!important`다. 그래서 상태나 스크립트가 바꾸는 속성(스크립트가 켜고 끄는 `display`, 상태를 따르는 색)에는 쓰지 않는다. 그런 것은 부품 규칙에 둔다.
- 반경:
  - `--r-sm` 4: 체크박스 · 키 표시
  - `--r-md` 6: 버튼 · 입력 · 메뉴 항목(기본)
  - `--r-lg` 8: 카드 · 표 상자
  - `--r-xl` 12: 메뉴 · 모달 · 토스트
  - `--r-full`: 배지 · 칩 · 검색 칸
  - 버튼은 6px 하나다(원형 버튼 없음).
- 선: 1px. 포커스는 **모든 부품이 2px `--focus` 링, 바깥 2px**(세그먼트 버튼처럼 틀 안에 있는 것은 안쪽 2px)이다.
- 그림자: `--ring`(카드 · 입력 테두리), `--menu-shadow`(메뉴 · 토스트 · 팝오버), `--modal-shadow`(모달). 다크는 선으로 대신한다.

## 6. 부품

### 6.1 버튼 (높이 3종)
| 종류 | 클래스 | 모양 |
|---|---|---|
| 주 | `.btn.primary` | 잉크 채움 · 흰 글자, hover #383838 |
| 보조 | `.btn` | 흰 바탕 + 1px gray-500 링 |
| 고스트 | `.btn.ghost` | 바탕 없음, hover gray-100 |
| 위험 | `.btn.danger` | 빨강 글자 + 빨강 링. 모달의 최종 확인만 빨강 채움 |
| 크기 | 기본 **32** · `.sm` **28**(표 · 도구 막대 · 패널 안) · `.lg` **40**(로그인 · 빈 상태 행동) | 가로 여백 10 / 8 / 14. `.lg`만 글자 16px · 반경 8px(로그인 같은 단독 행동) |
| 아이콘 버튼 | `.iconbtn` 32(도구 막대 28) | 6px 반경, `aria-label` 필수 |
| 비활성 | gray-100 바탕 · gray-700 글자 | 이유를 툴팁(`.has-tip`)으로 |

- 두 줄 글자를 넣은 카드형 버튼은 만들지 않는다(높이가 규격 밖으로 나감). 밑줄 탭(48~50px)은 버튼 높이 규칙과 별개다.
- 아이콘은 Lucide(`<i data-ic=…>`)만 쓴다. `↖ ▭ ⟜ ↔ ✓ ★` 같은 문자를 아이콘 대신 쓰지 않는다.

### 6.2 입력
- 높이 32, 6px, 1px gray-700 링(3.2:1), 14px. hover gray-900, 포커스 ink 링 + 4px 후광.
- 선택(`select.input`)은 오른쪽 36px 여백. 물리명 입력은 `.mono`.
- 모든 입력에 보이는 라벨 또는 `aria-label`이 있어야 한다.
- 오류: 빨강 링 + 아래 12px 사유. 체크박스 · 라디오 16px.

### 6.3 탭 (쓰임 3종, D2 정리)
| 쓰임 | 부품 | 예 |
|---|---|---|
| 화면 · 패널 안 **구역 전환** | 밑줄 탭 `.tabs` | 설정 탭, 패널 탭(속성 · 보안 · 관계), 사전 탭 줄 |
| 같은 목록의 **보기 전환** | 세그먼트 `.seg`(`role="group"` + 버튼 `aria-pressed`) | 논리/물리, 다이어그램/표, 결재함 대기함 · 내 신청 · 참조함 |
| 목록 **거르기** | 칩 `.chip` | 상태별 거르기, 분류 |
| 같은 업무 영역의 **화면 사이 이동** | 링크형 세그먼트 `.anav`(`<nav>` 안 `<a>`, 지금 화면 `aria-current="page"`) — 모양은 세그먼트, 동작은 링크 | 모델 · 표준 맞추기 · DDL · 산출물 머리(`areaNav()`) |
| **화면 안내**(이 화면이 무엇이고 어떻게 쓰는지) | `.pguide`(`pageGuide()`) — 탭 바로 아래 한 줄 설명(늘 보임) + [사용 방법 보기 / 접기] 3단계 · 언제 / 누가 / 참고 · "조건 → 화면" 링크. `[ ]`는 화면 버튼 라벨 그대로, 권한 없으면 역할 변형(읽기 전용 띠는 안내에 합침), 기본 접힘(탭 줄 [ⓘ 화면 안내] · `?` 키로 펼침), 추가 칸(x)으로 용어 · 처리 방법 · 상태 뜻. 규칙 전체: `review/resolution-dict-guide.md` | 표준 사전 메뉴 8개 화면 · 결재함 · 설정 · 감사 로그 |

- 결재함 헤더의 알약 탭(`.utabs`)은 세그먼트로 바꾼다.

### 6.4 표 (D1)
| 항목 | 값 |
|---|---|
| 행 높이 | **36px(기본)**. **마이페이지 › 환경 › 표 밀도**: 촘촘 32 · 기본 36 · 넓게 44(`--row`). 모델 표 보기 · 속성 그리드도 따른다. 두 줄 칸이 있는 행(표준 맞추기 비교 등)은 내용만큼 높아진다. 행이 많은 사전 · 표준 맞추기는 촘촘을 권한다 |
| 머리줄 | 행과 같은 높이, gray-100 바탕, 14/400 `--fg-2`, 고정(sticky) |
| 글자 | 14px, 물리명 · 약어 열은 Geist Mono 13 |
| 좌우 여백 | 16 |
| hover / 선택 | gray-100 / blue-100 + 첫 칸 2px blue-700 막대 |
| 상자 | 스크롤 칸을 채우는 목록 표 = 네모(선만). 섹션 · 카드 안 표 = 8px 둥근 상자(`.box`). `.plain`은 쓰지 않는다 |
| 빈 결과 | `tr.er`(none · first · done) 한 부품 |

### 6.5 배지 · 칩
- 배지 24px · 12/500 · 좌우 12 · 알약(§2.3 상태표).
- 칩 32px 알약, 선택 = gray-100.

## 9. 화면 코드 규칙 (퍼블리싱)
1. 부품은 `app.css`에 한 번만 정의한다. 버전마다 덧붙이지 않는다(덮어쓸 때는 원래 규칙을 고친다).
2. 화면 `<style>`은 그 화면에만 있는 배치만 둔다. 색 · 글자 크기 · 반경은 토큰과 부품을 쓴다.
3. 인라인 `style`은 계산된 값(위치 · 폭 · 진행률)에만 쓴다.
4. 새 부품이 필요하면 이 문서와 견본에 먼저 넣는다.
5. 바꾼 뒤에는 목업 도구 [퍼블리싱 점검]으로 **19개 화면**(목업 지도 · ERD 별칭 제외) × 1920 · 1600을 다시 잰다. 결과에는 테마 · 프레임 · 밀도 조건이 함께 찍힌다. 같은 조건끼리만 비교한다. 점검은 처음 보이는 상태만 잰다. 패널 · 메뉴 · 모달 · 다른 탭은 화면을 열어 따로 확인한다.
6. 사전 탭 줄과 상단 메뉴 `사전▾`의 역할은 다르다. 탭 줄은 사전 화면 안에서 지금 위치를 보여 주는 이동이고, `사전▾`는 다른 화면에서 사전 업무로 바로 가는 길이다.
