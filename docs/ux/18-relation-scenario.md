- 근거: [03-erd-editor.md §4](03-erd-editor.md#4-관계-ie), 교차 검토 [Claude](review/claude-relation.md) · [Codex](review/codex-relation.md) · [결정 기록](review/resolution-relation.md)

## 0. 원칙

1. **연결은 묻지 않는다 — 겹칠 때만 묻는다.** 부모 식별자(PK) 전체가 자식 FK가 된다. 자식에 같은 이름(논리명 또는 물리명)의 속성이 있거나 역할명이 필요할 때만 **중복 속성 해소 창**(§1-1)을 띄운다(M-1, 2026-11-25).
2. **한 사실은 한 곳에서 고친다.** 카디널리티(자식 쪽 개수) · 선택성(부모 필수 = FK 필수) · ON DELETE(물리)는 관계 패널에서만 바꾼다. 속성 그리드의 FK 필수 칸은 잠기고 이유를 보인다.
3. **모델 삭제와 DB 행 삭제를 섞지 않는다.** ‘모델에서 관계 삭제’는 모델의 관계·FK 제약·컬럼을 다룬다. ‘부모 행을 지울 때 (ON DELETE)’는 운영 DB 동작이며 DDL에만 들어간다.
4. **구조가 바뀌면 먼저 보여 준다.** 식별 전환과 컬럼이 걸린 삭제는 패널 안 띠에서 영향을 보인 뒤 적용한다. 단일 값 변경은 바로 반영하고 토스트에 [실행 취소]를 둔다.
5. **안전한 쪽이 기본이다.** 삭제 띠의 첫 버튼은 컬럼을 남기는 선택이고, 처음 포커스는 [취소]다.

## 1. 연결

| 단계 | 화면 | 키보드 |
|---|---|---|
| 1 | 도구 막대 [관계 R] · 유형(1:N 비식별 / 1:N 식별 / 1:1 / M:N) | 엔터티 선택 후 `R` |
| 2 | 부모 클릭 → 테두리 강조 · 안내 ‘자식 엔터티를 클릭하세요 · 같은 엔터티를 누르면 재귀 관계 · Esc 취소’ | 자식 고르기 목록(글자로 거르기 · ↑↓ · Enter) |
| 3 | 자식 클릭 → 겹침이 없으면 즉시 생성, 관계 패널 열림, 토스트 ‘부서 → 사원 관계 · FK 1개 추가 [실행 취소]’. 겹침이 있으면 §1-1 창 — **확정하기 전에는 관계도 FK도 만들지 않는다** | 같음 · 결과는 `aria-live`로 알림 |

**생성 규칙**

| 경우 | 결과 |
|---|---|
| 일반 1:N 비식별 | 부모 PK 전체 → 자식 FK. 기본 카디널리티 0..N, **선택성 ‘반드시 있다’(FK 필수)**, ON DELETE ‘막기’ |
| 1:N 식별 | FK가 자식 PK에 들어가고 손자 식별 관계 · 자식의 재귀 관계로 이어진다. 내려가는 길에서 겹치는 것도 같은 창에 함께 나온다 |
| 1:1 · 0~1 | FK 컬럼 조합 전체에 **UK 자동 추가**(`{자식}_UKn`). 자식 PK가 FK 컬럼뿐인 식별 1:1만 PK가 대신해 UK 없음 |
| M:N | FK 없음 · ‘M:N 해소 필요’ · 패널의 [미리보기 후 해소] |
| 부모에 PK 없음 | 막지 않는다. 관계만 만들고 ‘FK 대기’ + [식별자 지정]. 부모 PK가 생기면 FK가 **관계의 선택성 그대로**(기본 필수) 채워지고 UK도 다시 맞춘다 |
| 같은 이름의 속성이 자식에 있음 | **중복 속성 해소 창**(§1-1) — [기존 속성을 FK로 사용] / [새 이름으로 만들기](`원○○` · `ORG_`, 이미 있으면 `원부서코드2` · `ORG_DEPT_CD_2`) |
| 같은 방향 두 번째 관계 | 창 제목 ‘같은 두 엔터티의 두 번째 관계 — 역할명을 정하세요’(예: 출발창고 · 도착창고). 첫 관계의 FK는 ‘다른 관계의 FK’라 [기존 속성 사용]이 흐려진다 |
| 재귀 | 부모 PK **전체**에 `상위○○` · `UPR_` 컬럼, 선택성 ‘없어도 된다’(최상위 행). 창 제목 ‘재귀 관계 — 역할명을 정하세요’가 한 번의 확인이다. **부모에 PK를 더할 때도** 재귀 관계에 `상위○○`가 같은 창으로 생긴다(예전에는 전파되지 않던 결함) |
| 이미 같은 관계 있음 | 창에 ‘이미 … 관계가 있습니다 · 다른 역할일 때만 확정’ + [기존 관계 열기] |
| 자식이 참조 엔터티 | 만들지 않음 · ‘원본 영역에서 수정하세요’ |

### 1-1. 중복 속성 해소 창 (M-1, 2026-11-25)

관계 생성(재귀 포함) · PK 추가(확인란 · Space · 트리 메뉴 · 키 구역으로 끌어 놓기) · 식별 전환 · FK 짝 변경 · M:N 해소 · FK 복구(게이트 A ‘FK 만들기’)가 **모두 이 창 하나**를 쓴다. 예전의 역할명 팝오버 · 조용한 `원○○` 이름 붙이기 · FK 만들기 확인 창을 대신한다.

| 항목 | 규칙 |
|---|---|
| 겹침 판정 | 자식 속성의 **논리명 또는 물리명**이 부모 키와 같으면 겹침(대소문자 무시). 표준화 뒤에는 같은 용어 id도 겹침으로 본다(구현). 사용자가 선을 그었거나 PK를 지정했을 때만 판정한다 — 관계 후보를 미리 찾아 주지는 않는다(RV-R04는 W3 제외) |
| 모양 | 1건 = 자식 엔터티 옆 **팝오버**, 2건 이상(자식이 여럿인 경우 포함) = **모달(640)**. 제목 ‘자식 엔터티에 같은 이름의 속성이 있습니다 (n건)’. 겹치지 않는 FK는 묻지 않고 ‘겹치지 않는 FK n개는 부모 키와 같은 이름으로 추가합니다’ 한 줄 |
| 행 | `자식 엔터티 ← 부모 키(논리명 · 물리명)` + 두 선택. **[기존 속성을 FK로 사용]**: 이름 · 정의 · 예외 사유는 그대로, **타입 · 길이 · 도메인 · 필수를 부모 키에 맞춘다** — 바뀌는 값만 전 → 후로 보인다(없으면 ‘바뀌는 값 없음 — FK 표시만 붙습니다’). **[새 이름으로 만들기]**: `원○○` · `ORG_`(재귀는 `상위○○` · `UPR_`) 제안, 이름은 고칠 수 있다 |
| 기본 선택 | 물리명이 같고, 타입 계열(문자 · 숫자 · 날짜)이 맞고, 다른 관계의 FK가 아니면 ‘기존 속성 사용’. 아니면 ‘새 이름’ |
| 흐리게 + 이유 | 기존 속성이 **다른 관계의 FK** → ‘○○ → △△ 관계의 FK입니다 — 한 컬럼은 관계 하나의 FK만 됩니다’. 기존 속성이 **자식의 PK**인데 비식별 관계 → ‘△△의 식별자(PK)입니다 — 비식별 관계의 FK로 쓸 수 없습니다’(식별 관계에서는 그 PK를 그대로 FK로 쓸 수 있다). 재귀 · 같은 창의 다른 관계가 같은 이름을 만드는 경우 → 역할명이 필요하다는 이유 |
| 한 속성은 부모 키 하나만 (재리뷰 R2-03) | 복합 PK에서 자식 속성 하나가 두 부모 키에 맞을 수 있다(한 키에는 물리명, 다른 키에는 논리명). 계획 단계에서 **속성별로 사용을 예약**한다 — 먼저 고른 행이 그 속성을 쓰면 다른 행에서는 [기존 속성 사용]이 흐려지고 ‘이 창에서 부모 키 ‘○○’이(가) 이미 이 속성을 쓰기로 했습니다 — 한 속성은 부모 키 하나만 받습니다’. 물리명이 같은 쪽을 먼저 짝짓는다. **이 관계에서 이미 다른 부모 키의 짝인 컬럼**(FK 복구 때)도 같은 이유로 흐려진다 — ‘이 관계에서 이미 부모 키 ‘○○’의 짝입니다 — 한 속성은 부모 키 하나만 받습니다’. 자식의 기존 PK는 **식별 관계에서는 재사용할 수 있다**(조정자 판정으로 유지) |
| 끝까지 내려보내기 (재리뷰 R2-04) | 식별 관계를 따라 내려가는 깊이에는 제한이 없다. 같은 관계로 되돌아오면(식별 관계 순환) **계획 전체를 거부**하고 적용 전에 이유를 보인다 — ‘식별 관계가 돌아옵니다(A → B → A …) — … 아무것도 바꾸지 않았습니다 — 순환하는 관계 하나를 비식별로 바꾼 뒤 다시 하세요’. 만들려는 관계 자신이 순환을 닫는 경우도 같다. 순환 여부는 **키가 실제로 내려가는지와 상관없이** 본다 — 자식의 기존 PK를 그대로 쓰게 되어 더 내려보낼 것이 없어도, 식별 관계끼리 고리를 이루면 거부한다(식별 전환도 같다). **부모에 식별자가 아직 없어도**(FK 대기로 만들어질 관계) 같은 검사를 한다 — 키가 생기는 순간 끝없이 내려가게 되기 때문이다(수정 3회차) |
| 일괄 | 2건 이상이면 [모두 기존 속성 사용](쓸 수 있는 행만) · [모두 새 이름] |
| 새 이름 검사 | 입력하는 즉시 검사 — 비어 있음 · 자식에 이미 있는 이름 · 이 창의 다른 새 이름과 겹침. 오류가 있으면 [확정]이 꺼진다 |
| 확정 · 취소 | 첫 포커스 = 첫 행의 고른 선택. **Enter = 확정, Esc = 취소**(창 밖에서 눌러도). 취소 버튼 문구는 하던 일을 말한다 — ‘연결 취소’ · ‘PK 지정 취소’ · ‘유형 변경 취소’ · ‘FK 짝 변경 취소’ · ‘해소 취소’ · ‘FK 만들기 취소’. 취소하면 **관계 · PK 지정을 통째로** 되돌린다(애초에 만들지 않았으므로 모델은 그대로). **취소는 아무것도 바꾸지 않는다 — 저장도 리비전 증가도 없다**(창이 떠 있는 동안 다른 편집이 저장을 기다렸다면 그것만 저장한다) |
| 적용 | 확정하면 관계 · PK 지정 · 모든 FK를 **한 번에** 적용하고 토스트 하나(‘… 관계 · FK n개(기존 속성 사용 a) · 새 이름 b개’) + [실행 취소] 한 번으로 전부 돌아간다 |
| 저장(공동 편집) | 창이 떠 있는 동안은 저장하지 않는다(머리 ‘저장 대기 · 중복 속성 확인 중’). 구현: 창이 떠 있는 동안 **Yjs에 쓰지 않고**, 확정 뒤 **한 Y 트랜잭션**으로 적용한다(T-P2-402/403 계약). 확정 직전에 계획을 다시 계산해 그 사이 모델이 바뀌었으면 창을 갱신하고 다시 확인받는다. 서버 쓰기 검증에 ‘엔터티 안 물리명 유일’을 둔다 |
| 용어 | 엑셀 가져오기의 ‘덮어쓰기’와 헷갈리지 않게 이 창에서는 ‘기존 속성을 FK로 사용’이라고 쓴다 |

> 아래 ‘역할명 팝오버’ 문단은 이 창으로 바뀌었다(기록으로 남긴다).

~~**역할명 팝오버**~~(→ §1-1): 제안값이 미리 채워지고 전체 선택된다. 입력 칸에서 Enter = 확정, Esc · [연결 취소] = 되돌림.

**M:N 해소**(두 부모의 키 이름이 겹치면 §1-1 창에서 역할명을 묻는다 — 예전에는 묻지 않고 `원○○`): 패널 띠가 미리보기다 — 교차 엔터티 이름(`직급자격증관계`) · 물리명(`JBGD_CRTFCT_R`) · PK(두 부모 PK 전체). [교차 엔터티로 해소]를 누르면 식별 관계 2개와 함께 만든다. 한쪽 부모에 PK가 없으면 비활성.

## 2. 관계 패널 (오른쪽, 420px)

```
부서기본 ─────< 사원기본                     ← IE 미리보기 (선 · 끝 기호가 설정을 따라감)
[모델]
  관계명                 [소속                   ]
  유형                   [비식별 | 식별]  식별: FK가 자식 PK에 들어가고 손자까지 이어짐
  카디널리티 · 선택성     부서기본 1개는 사원기본을 [0개 이상 ▾] 가진다
                         사원기본 1개는 부서기본이 [반드시 있다 ▾]
  FK 짝                  DEPT_CD 부서코드  →  [DEPT_CD · 부서코드 ▾]
                         FK 반영 · EMP_M_DEPT_M_FK
▸ DB 반영 (물리)  부모 행을 지울 때: 막기          ← 접힘 (물리 모드이거나 값이 기본이 아니면 펼침)
    부모 행을 지울 때 (ON DELETE)  [자식이 있으면 막기 (기본 · NO ACTION) ▾]
    FK 제약 이름 · FK 인덱스 · 1:1 보장 UK
[모델에서 관계 삭제]  Delete · 컬럼을 남길지 고릅니다 · DB 행은 바뀌지 않음
```

| 항목 | 규칙 |
|---|---|
| 관계명 | 선택 입력. 비우면 선 이름 없음 |
| 유형 | 누르면 바로 바뀌지 않는다. 패널 띠에 ‘식별 관계로 바꾸면’ · FK가 PK가 됨 · 손자 테이블 증감 · 자식에 식별자가 남지 않음 경고 · SET NULL이면 ‘막기로 바꿉니다’를 보이고 [적용] / [취소 Esc]. 처음 포커스는 [취소], [적용]은 300ms 뒤 활성 |
| 카디널리티 | 0개 이상 / 1개 이상 / 0~1개 / 정확히 1개. ‘0~1개’ · ‘정확히 1개’는 UK로 최대 1개를 보장(추가 · 삭제를 토스트로 알림). ‘최소 1개’(1개 이상 · 정확히 1개)는 FK로 강제할 수 없는 업무 규칙이라고 도움말에 적는다 |
| 선택성 | 반드시 있다 = FK 필수. 식별 관계는 고정. ‘반드시’로 바꾸면 SET NULL은 ‘막기’로 돌아가고 토스트로 알린다 |
| FK 짝 | 부모 PK 순서로 한 줄씩. 자식 컬럼을 고르면 그 컬럼이 이 관계의 FK 묶음에 들어간다. **다른 관계의 FK, 이 관계의 다른 키 짝은 목록에서 비활성 + 이유**(‘부서기본 관계의 FK’). 식별 관계에서 짝을 풀거나 바꾸면 손자 FK도 함께 정리 · 전파하고 토스트로 알린다. 상태는 반영 / 누락(이유) / 제외 / FK 대기 |
| ON DELETE | 막기(기본 · DDL에 절 없음) / CASCADE / SET NULL. SET NULL은 **이 관계의 FK 컬럼이 모두 NULL 허용**(PK · 필수 아님)일 때만. CASCADE를 고르면 실제 FK만 따라가 ① 함께 지워지는 테이블 ② 그 아래 ‘막기’라 실패할 수 있는 테이블 ③ 같은 부모의 다른 자식 중 ‘막기’인 관계를 따로 보인다 |
| 조회 전용 | 모든 칸 비활성, 패널 위 한 줄로 이유를 하나만(참조 엔터티 · 결재 중 · 확정본 · 권한 없음). [식별자 지정]도 숨김. `R`은 도구로 들어가지 않고 이유만 알린다 |

## 3. 삭제

진입: 패널 [모델에서 관계 삭제] · 관계 선택 후 `Delete` · 트리 관계 메뉴. 띠는 패널 안(모달 아님, `role=group`).

띠 내용: 제목 ‘모델에서 부서 → 사원 관계를 삭제합니다’ → ‘관계와 FK 제약을 모델에서 뺍니다. 운영 DB의 행은 바뀌지 않습니다’ → 세 줄 영향(자식 컬럼 · 손자 테이블 · DDL 감소) → [자세히] 테이블.컬럼 목록 → ‘컬럼을 어떻게 할까요?’ 버튼 세로 나열 → [취소 (Esc)].

**삭제 조건 표**

| 관계 | FK 상태 | 묻는가 | 첫 버튼(기본 · primary) | 다른 선택 |
|---|---|---|---|---|
| M:N | 없음 | 묻지 않음 — 바로 삭제 + 실행 취소 | — | — |
| 아무 유형 | FK 0개(대기 · 누락) | 묻지 않음 | — | — |
| 비식별 1:N · 1:1 | FK n개 | 띠 1회 | 일반 컬럼으로 남김 | FK 컬럼도 삭제(danger) |
| 재귀 · 역할명 | 역할 컬럼 n개 | 띠 1회 | 일반 컬럼으로 남김 | 이 관계의 역할 컬럼만 삭제(danger) |
| 식별 | 손자 없음 · 자식에 다른 PK 있음 | 띠 1회 | 자식 식별자(PK)로 남김 | PK에서 빼고 일반 컬럼으로 남김 · 컬럼도 삭제(danger) |
| 식별 | 손자 m개 또는 자식 PK가 이 컬럼뿐 | 띠 1회 + 손자 목록 | 자식 식별자(PK)로 남김 · 손자 유지 | 컬럼도 삭제 · 손자 FK까지 정리(danger) |

- 컬럼 판정은 관계의 **FK 묶음(`g`) 기준**이다. 다른 관계의 컬럼은 건드리지 않는다. 묶음이 없던 옛 데이터는 불러올 때 대응이 확실한 경우만 묶음을 만든다(`gAuto`, 제약 이름은 바꾸지 않음).
- 실수 방지: 처음 포커스는 [취소], 선택 버튼은 300ms 동안 비활성(두 번 Enter 방지). Esc는 띠를 닫고 [모델에서 관계 삭제]로 포커스를 돌려준다.
- 띠의 DDL 줄은 실제 FK일 때만 ‘FK 제약 1개 줄어듦’(누락 · 제외면 ‘변화 없음’), 식별 관계에서 남는 PK가 없으면 경고 줄.
- 실행: 관계 · 컬럼 · UK · 손자 컬럼을 한 번에 바꾸고, 바뀐 엔터티를 2초 강조, 토스트 ‘관계를 삭제했습니다 · 컬럼 n개 정리(손자 m개 포함) [실행 취소]’. 컬럼을 일반 컬럼으로 남겼으면 토스트에 **[이 컬럼도 지우기]**. Ctrl+Z 한 번으로 전부 돌아온다.

### 3-1. 부모 PK를 끄거나 지울 때 (M-5, 2026-11-25)

관계 삭제가 아니라 **부모 쪽 PK 속성**을 끄거나 지우는 경우다([16 §3.2](16-attribute-edit-grid.md)).

- 한 동작만 한다: 자식 FK 컬럼은 **FK만 풀리고 일반 속성으로 남는다. 관계는 유지**된다(부모에 식별자가 하나도 없으면 ‘FK 대기’, 일부만 빠지면 남은 키로 FK가 이어진다).
- 식별 관계의 자식은 그 컬럼을 **자식 식별자(PK)에 그대로** 둔다 — 위 삭제 조건 표의 기본값(‘자식 식별자(PK)로 남김’)과 같다. 손자까지 연쇄로 풀지 않는다.
- 띠: 영향 목록(자식 컬럼마다 ‘일반 속성으로 남음’ / ‘자식 식별자(PK)로 남음’) + [취소 (Esc)] · [확인]. **[자식 FK도 삭제]는 없다.**
- 토스트: ‘… 자식 FK n개는 일반 속성으로 남김(식별 관계 m개는 자식 식별자로) · 관계 유지’ + [실행 취소] · [이 컬럼도 지우기](PK에 남은 컬럼은 빼고 지운다). **[이 컬럼도 지우기]는 누르는 순간 다시 확인한다**(재리뷰 R2-05) — 그사이 PK나 FK가 됐거나 없어진 컬럼은 지우지 않고 ‘남긴 컬럼이 그사이 PK · FK가 됐거나 이미 없어져 지우지 않았습니다’로 알린다(관계 삭제의 같은 버튼도 같다).

**FK 짝을 기존 컬럼으로 바꿀 때**(§2 FK 짝): 관계가 스스로 만든 컬럼(`원○○` · `ORG_` · `상위○○`)은 다른 컬럼이 짝이 되면 **함께 지운다**(예전에는 FK 표시만 빠지고 쓰지 않는 컬럼이 남았다). 새로 짝이 된 컬럼은 타입 · 길이 · 도메인을 부모 키에 맞춘다. ‘(없음 — FK 누락)’을 고르면 컬럼은 남는다.

## 4. 산출물 연동

| 곳 | 반영 |
|---|---|
| DDL | `FOREIGN KEY … REFERENCES …` 뒤에 `ON DELETE CASCADE` / `ON DELETE SET NULL`. 막기는 절 없음. 1:1 비식별은 `CONSTRAINT {p}_UKn UNIQUE (cols)` |
| 결재 비교 | 관계 행(추가 · 삭제 · 유형 · 관계명 · 자식 쪽 개수 · 부모 쪽 · FK 짝)은 ‘모델’ 묶음, ON DELETE · UK 변경은 **‘DB 동작 변경’** 묶음으로 따로. CASCADE 추가는 경고 배지. 같은 관계는 FK 묶음 → 부모·자식·관계명 → 부모·자식 순으로 짝지어 옛 확정본과도 맞춘다 |
| 트리 · 엔터티 제약 | 관계 노드 · 제약 목록(재귀 포함, ON DELETE 표시)의 FK 상태는 패널과 같은 판정(fkOf). FK 이름 접미사는 역할명 FK에만 |

## 5. 남긴 것 (구현 단계에서 정함)

- 공동 편집 중 띠를 연 사이에 대상이 바뀌면 적용 직전 다시 계산하고 띠를 갱신(Codex #9) — 실시간 편집 구현 때. **중복 속성 해소 창은 계획을 클라이언트에서만 갖고 있다가 확정 뒤 한 Y 트랜잭션으로 적용한다**(§1-1, M-1 — T-P2-402/403 계약에 적는다).
- 부모 PK 이름 · 타입 변경 시 자식 FK 따라가기 미리보기와 [다시 매핑](Codex #10 · Claude #13).
- 참조 부모의 원본이 새 확정본으로 바뀌었을 때 ‘원본 PK 바뀜 · 다시 맞추기’(Codex #11).
- FK 짝의 타입 · 도메인 호환 검사, 선택형 복합 FK의 ‘전부 비우거나 전부 채움’ 제약(Codex #5).
- DBMS별 ON DELETE 지원 차이(Oracle은 ON DELETE SET DEFAULT · ON UPDATE 없음) — DDL 방언 설계 때.
- (사후 검토) 결재 비교 기준본을 제출 때 확정 문서 id로 고정 · ALTER DDL의 FK · UK 절 · 정의서의 FK 상태 · 부모 행 삭제 규칙 열 · UK 이름 고정 · ‘관계 잃은 컬럼’ 표시 · 역할 팝오버 Tab 가두기.

## 관계명 표기 (2026-11-24 결정)
- 입력 칸 이름은 **관계명**(‘(동사구)’ 빼기). 값은 **명사형**으로 짧게 쓴다: 소속 · 담당 · 포함 · 주문 · 지급. 서술형(“부서가 사원을 가진다”, “포함한다”)은 쓰지 않는다.
- 같은 두 엔터티 사이에 관계가 둘 이상이거나 재귀 관계면 **역할명**으로 구분한다: 출발 · 도착, 상위.
- 목업 시드의 관계명도 명사형으로 바꿨다(‘수행한다’ → ‘수행’, ‘소속된다’ → ‘소속’ 등).

## 용어 (2026-11-24 결정)
- 화면 · 문서에서 **‘필수’**로 쓴다(값이 꼭 있어야 함). DB에서는 NOT NULL이며, DDL에만 `NOT NULL`로 나온다. 테이블 정의서 열도 ‘필수’(Y = 필수)다.

## 재귀 관계 표기 (2026-11-24)
- 관계 패널은 재귀 관계를 역할로 읽는다. 제목은 ‘관계 · 재귀 — {엔터티} 상위 → 하위’로 쓴다.
- 카디널리티 · 선택성 문장은 ‘상위 {엔터티} 1개는 하위 {엔터티}을(를) …’ · ‘하위 {엔터티} 1개는 상위 {엔터티}이(가) …’로 쓴다. 값을 바꿀 때 뜨는 알림도 같은 말을 쓴다.
