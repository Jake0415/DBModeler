# 28. ERD 논리 · 물리 통합 보기 — 검토와 플랜 (v0, 2026-11-24)

> 요청: 모델 캔버스의 [논리 | 물리]에 **논리와 물리를 함께 보는 보기**를 더한다. 사용자는 필요할 때 두 모델을 한 화면에서 겹쳐 보고 확인한다.
> 대상: `mockups/model.html`(캔버스 도구 막대 `#lp`), 관련 화면(속성 그리드 · 오른쪽 패널 · 트리 · 내보내기).
> 상태: **결정 완료(§6) · UX 재검토 반영(§7) — 목업 반영 전**.

## 1. 지금 어떻게 되어 있나 (`model.html` 확인 결과)
| 항목 | 논리 | 물리 |
|---|---|---|
| 전환 | 도구 막대 `[논리 \| 물리]`(`#lp`, `setMode('L' \| 'P')`) — 상태 변수 `mode` | 처음 물리로 갈 때 **게이트 A**(미매핑 · 타입 미정 점검) 창을 거친다 |
| 노드(엔터티) 한 줄 | **논리명** · 오른쪽에 물리명 | **물리명** · 오른쪽에 타입 |
| 노드 아래 | 서브타입 구조(배타/포괄) | ‘서브타입 → 한 테이블로 통합’ · **시스템 컬럼 4개** 줄 |
| 배치 | `x, y`(보기별 `pos[0..1]`) | **따로 저장** `px, py`(보기별 `pos[2..3]`) |
| 메모 | `mode: 'L'` 메모만 | `mode: 'P'` 메모만 |
| 오른쪽 패널 · 그리드 | ‘속성’ 탭 | ‘컬럼’ · **‘제약 · 인덱스’** 탭, 시스템 컬럼 행 |
| 관계 패널 | DB 반영(ON DELETE)은 접힘 | DB 반영 펼침 |
| 위쪽 띠 | — | 게이트 A 띠 · 동기화 띠 |
| 내보내기 | ‘논리 ERD’ | ‘물리 ERD’ |

→ 같은 엔터티를 두 번 그리는 구조다. 두 쪽을 함께 보려면 지금은 전환을 오가며 기억에 의존해야 한다.

## 2. 왜 통합 보기가 필요한가
- **매핑 검토**: 논리명 ↔ 물리명 ↔ 타입이 맞는지 한 줄에서 본다(표준 맞추기 · 확정 결재 전 검토).
- **미매핑 찾기**: 물리명 · 타입이 빈 속성이 논리 구조 안 어디에 있는지 바로 보인다.
- **관계와 FK**: 논리 관계(관계명 · 카디널리티)와 물리 FK(제약 이름 · 반영/누락)를 같은 선에서 본다.
- **공유 · 설명**: 업무 담당자(논리)와 DBA(물리)에게 한 장으로 보여 준다(산출물).

## 3. 통합 보기 설계안
### 3-1. 전환
- 도구 막대 `[논리 | 물리 | 통합]` 세 칸으로 바꾼다. 통합 칸의 도움말은 ‘논리 + 물리를 한 화면에’로 쓴다. 상태 변수는 `mode = 'A'`.
- 마지막 보기를 사용자 · 업무 영역별로 기억한다. 주소 `?mode=L|P|A`로 바로 열 수 있다.
- 통합은 **게이트 A 창을 거치지 않는다**. 물리 쪽 문제는 노드 안 표시와 위쪽 띠로만 알린다(§3-4).

### 3-2. 노드 — 한 줄에 논리 · 물리를 함께
```
┌ 사원기본 · EMP_M ──────────────────────────┐   ← 제목: 논리명 · 물리명(테이블)
│ ● 사원번호        EMP_NO        VARCHAR2(10) PK │   ← 논리명 │ 물리명 │ 타입
│ ● 부서코드        DEPT_CD       VARCHAR2(10) FK │
│ ● 입사일자        — 미매핑      — 타입 미정      │   ← 물리 문제는 회색 + 경고 점
│ 시스템 컬럼 4 · 등록일시 · 등록자 · 수정일시 · 수정자 │   ← 물리에만 있는 줄
└──────────────────────────────────────────┘
```
- 열 셋: 논리명 / 물리명 / 타입(+ PK · FK · 필수 표시). 표준 상태 점(●)은 논리와 같다.
- 서브타입은 논리 구조를 보이고, 아래에 ‘물리: 한 테이블로 통합 · 구분 컬럼’ 한 줄을 더한다.
- 노드가 넓어지므로(약 1.5배) 확대 · 축소 단계(LOD)의 기준을 따로 둔다. 멀리서는 제목만, 중간에는 PK · FK 줄만, 가까이서는 전체를 보인다.

### 3-3. 배치
- **제안: 통합 전용 배치를 따로 저장**한다(`ax, ay`, 보기별 `pos[4..5]`).
  - 처음 열 때는 논리 배치를 가로로 1.5배 펼쳐 시작하므로, 넓어진 노드가 겹치지 않는다.
  - 통합에서 옮긴 위치는 통합에만 남는다. 논리 · 물리 배치는 바뀌지 않는다.
- [자동 배치]는 통합에서도 된다.

### 3-4. 관계 · 띠 · 메모
- **관계선**: 논리 관계명(명사)과 카디널리티 기호를 보인다. 선 가운데 이름표에 물리 FK 이름과 상태(반영 · 누락 · 대기)를 작게 붙인다. 누락은 경고 색.
- **위쪽 띠**: 물리와 같은 게이트 A 띠(‘미매핑 n · 타입 미정 n’)를 보이고, [보기]를 누르면 해당 노드로 간다.
- **메모**: 논리 · 물리 메모를 함께 보이고, 메모 머리에 ‘논리’ · ‘물리’ 표시를 단다. 통합에서 새로 만드는 메모는 ‘통합’ 메모로 따로 둔다.

### 3-5. 편집 범위
- **제안: 통합은 ‘보며 고치는’ 보기**로 둔다.
  - 캔버스에서 이름을 바로 바꾸는 동작(두 번 클릭 · F2)은 논리명인지 물리명인지 헷갈리므로, 오른쪽 **속성 그리드**를 연다.
  - 속성 그리드는 통합에서 **논리명 · 물리명 · 타입 · 도메인 · PK · 필수** 열을 함께 보이고, 열마다 편집한다(논리 · 물리 각각의 규칙 그대로).
  - 엔터티 추가 · 관계 그리기 · 삭제 · 이동(배치)은 논리와 같게 된다. 관계를 그리면 논리 관계가 생기고, FK는 지금처럼 자동으로 붙는다.
  - 제약 · 인덱스 탭은 통합에서도 보인다(물리 정보).

### 3-6. 함께 바뀌는 곳
| 곳 | 통합일 때 |
|---|---|
| 모델 트리 | 엔터티 · 속성 이름을 ‘논리명 · 물리명’으로 보인다 |
| 표 보기([표]) | 논리 · 물리 열을 함께 보인다 |
| 미니맵 · 찾기 | 논리명과 물리명 둘 다로 찾는다 |
| 내보내기 | **‘논리 · 물리 통합 ERD’**(이미지 · 산출물). 표제란에 ‘통합’을 적는다 |
| 화면 안내 · 범례 | 통합의 세 열과 회색 ‘미매핑’ 뜻을 범례에 더한다 |
| 접근성 | 세 칸 전환 `aria-pressed`. 노드 낭독은 ‘사원번호, 물리 EMP_NO, VARCHAR2(10), PK’ 순서. 단축키 제안: `Shift+1/2/3` = 논리/물리/통합 |

### 3-7. 성능
- 300 엔터티 · 500 관계 측정(`?perf`)을 통합에서도 한다.
- 줄이 한 열 늘어 노드 HTML이 커지므로, 멀리서 볼 때(LOD low · mid) 열을 줄이는 것으로 지금 수준(전환 · 끌기 시간)을 지킨다.

## 5. 위험과 대응
- **노드가 넓어져 화면이 복잡함** → LOD로 멀리서는 열을 줄인다. 통합 전용 배치를 1.5배로 펼쳐 시작한다.
- **어느 쪽 이름을 고치는지 헷갈림** → 캔버스 즉석 이름 바꾸기는 막고 그리드에서 열을 나눠 고친다.
- **배치가 세 벌이 됨** → 통합 배치는 선택 사항이다. 한 번도 옮기지 않으면 계속 논리 배치를 펼쳐 보여 준다(저장 안 함).

## 6. 결정 (2026-11-24, 사용자)
1. 전환 칸 이름은 **‘통합’**이다(도움말 ‘논리 + 물리’).
2. 배치는 **논리 배치를 펼쳐서 보여 준다**. 통합 전용 배치는 저장하지 않는다 — §3-3의 ‘전용 배치 저장’ 제안은 채택하지 않음.
3. 통합에서도 **편집할 수 있다**.
4. 통합으로 갈 때 **게이트 A 점검 창 없이** 간다(물리 문제는 띠 · 노드 표시로).

> UX 전문가 재검토 결과: **바꿀 결정은 없음.** 결정 2 · 3은 아래 §7의 규칙을 보탠다 — [claude-integrated-view](review/claude-integrated-view.md) IV-01 ~ 20.

## 7. 결정을 지키기 위한 보완 규칙 (UX 재검토 반영, 2026-11-24)
§3의 설계안 중 아래가 바뀐다. §3-3 ‘통합 전용 배치 저장’은 결정 2에 따라 쓰지 않는다.

### 7-1. 배치 — 논리 배치를 펼쳐 보여 준다(결정 2)
- 통합의 위치는 **논리 배치(x, y)에서 계산**한다. 저장하는 값은 없다. 물리 배치(px, py)는 통합에서 절대 바뀌지 않는다. 지금 `pos` · `setPos`는 논리가 아니면 물리를 고치는 두 갈래라, `mode='A'` 갈래를 꼭 따로 둔다(IV-01).
- **통합에서 끌어 옮기면 그 위치를 배율로 나눠 논리 배치에 저장**한다(IV-02). Shift+화살표 · [자동 배치]도 같다.
  - 처음 옮길 때 한 번만 알린다: ‘통합에서 옮긴 위치는 논리 배치에도 반영됩니다’.
- **배율은 영역마다 계산**한다(IV-03). 노드 너비 비율(통합 ÷ 논리)로 가로 배율을, 가장 긴 노드 높이로 세로 배율을 정해 겹치지 않게 한다. 고정 1.5배는 쓰지 않는다.
- 보기를 바꿔도 **선택한 엔터티와 화면 가운데 위치를 유지**한다(IV-04).
- 통합에서 만든 메모는 **논리 메모**로 저장한다. 물리 메모는 통합에서 ‘물리’ 표시를 달아 보여 준다(IV-05).

### 7-2. 편집 — 통합에서도 고친다(결정 3)
- **캔버스에서 이름을 바꾸면(두 번 클릭 · F2) 논리명**이다. 지금 물리 화면의 F2도 논리명을 연다. 입력하는 동안 물리명 자리에 **자동 변환 결과를 미리** 보여 준다(IV-06).
- 물리명 · 타입 · 시스템 컬럼 · 제약 · 인덱스 · ON DELETE는 **오른쪽 그리드 · 패널의 해당 열**에서 고친다. 열 머리에 ‘논리’ · ‘물리’를 붙인다(IV-07 · 08).
- **동기화 띠를 통합에도 둔다**: 물리 화면에만 있던 ‘논리 변경 n건 대기’ 띠를 통합에도 보이고, 노드 줄마다 ‘반영 대기’를 표시한다(예: `EMP_NO → EMPL_NO`)(IV-09).

### 7-3. 게이트 A 창 없이(결정 4)
- 노드 제목에 **‘미매핑 n’ 배지**를 단다. 멀리서(LOD low)도 배지는 보인다. 위쪽 게이트 A 띠는 [다음 미매핑으로] 버튼으로 차례로 이동하게 한다(IV-10 · 11).
- 일관성: **게이트 A 창은 ‘물리’로 갈 때만**, 그 세션에서 점검을 이미 열었으면 생략한다. 통합 → 물리로 갈 때도 같은 규칙이다(IV-12).

### 7-4. 이름 · 문구 — ‘통합’(결정 1)
- 통합 노드 안의 서브타입 문구 ‘한 테이블로 통합’은 **‘한 테이블로 합침’**으로 바꿔 ‘통합’ 보기와 겹치지 않게 한다(IV-15).
- 글로 남는 곳(내보내기 파일명 · 표제란 · 화면 안내)은 **‘논리 · 물리 통합’**으로 쓴다. 시스템 이름 ‘통합ERP’와 붙어 ‘통합ERP › 인사관리 · 통합 ERD’처럼 읽히는 것을 막는다(IV-16).
- `mode === 'L' ? … : …` 갈래 22곳을 점검해, 통합에서 ‘컬럼’ · ‘물리 ERD’ 같은 물리 전용 말이 나오지 않게 한다. 통합에서는 ‘속성 · 컬럼’ 등으로 쓴다(IV-13).

### 7-5. 접근성 · 성능 · 내보내기
- 단축키는 **Alt+1 / Alt+2 / Alt+3**(논리 / 물리 / 통합)으로 한다. Shift+1 · 2는 이미 ‘전체 맞춤’ · ‘선택 맞춤’이다(IV-14).
- 낭독 순서는 ‘논리명, 물리 물리명, 타입, PK’로 한다. 미매핑은 색만이 아니라 ‘— 미매핑’ 글자로도 보인다(흑백 인쇄)(IV-17).
- 성능은 300 · 500 규모에서 측정한다. 대상은 통합 전환 시간 · 끌기 · 확대 · 축소 단계 바뀜이다(IV-18).
- 내보내기 ‘논리 · 물리 통합 ERD’는 A3 가로를 기본으로 하고, 범례에 세 열의 뜻과 미매핑 표시를 넣는다(IV-19).

| 단계 | 바뀐 내용 |
