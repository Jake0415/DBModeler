## 1. 왜 바꾸나

지금 검수 기준(`rules.html`, SC-43)에서 고칠 수 있는 값은 **단어 영문약어명 최대 길이 하나**뿐이다. 나머지는 화면에 글자로만 있고 실제 판정은 여러 곳에 **하드코딩**돼 있다.

| 지금 하드코딩 | 위치 |
|---|---|
| 단어 약어 `^[A-Z][A-Z0-9]*$`, 이름 공백 금지 | `app.js:871 · 881` |
| 용어 약어 = 단어 약어를 `_`로 이음, 30자 | `app.js:888-889 · 978`, `decompose()`, 약어 전파 `app.js:797-798` |
| 엔터티 분류어 `기본 · 내역 · 이력 · 관계 · 정보` → `_M _D _H _R _I` | `app.js:885 · 888 · 895` |
| 형식단어로 끝남 · 1음절 분해 의심(경고 고정) | `app.js:887 · 892` |
| 도메인명 = 분류명 + 축약명 + 길이[,소수점], 코드값 길이 = 도메인명 끝 숫자 | `app.js:897 · 911` |
| 직접 등록이 약어를 대문자로 바꿈 · 마법사 자체 정규식 | `dict-grid.html:218 · 346`, `term-wizard.html:582` |
| 엑셀 단어 약어 상한 | `excel-import.html:394` |
| 모델: 표준 맞추기가 저장된 `a.s === 'ok'`를 그대로 믿음 · DDL 별도 물리명 검사 · ERP 샘플 `_` 조합 | `standardize.html:117`, `ddl.html:119`, `app.js:616-656` |

**목표**
1. **기관이 자기 명명 표준을 세운다** — 사전 종류 × 필드별 허용 문자(특수문자 포함) · 길이 · 어기면 처리, 그리고 하드코딩된 명명 규칙(단어 사이 기호 · 엔터티 접미 · 조합 엄격도)을 기준값으로 꺼낸다.
2. **모델러도 표준을 만드는 데 참여한다** — 기준 줄마다 [이 기준 변경 제안] → DA 확인. (시스템별 기준은 다음 차수, §6 Q1)
3. **같은 기준으로 사전을 검수한다** — 직접 등록 · 그리드 · 엑셀 · 마법사 · 신청 · 결재 재검사가 판정 한 곳(`checkItem`)과 기준 한 곳(`getPolicy`)만 쓴다.
4. **같은 기준으로 모델을 검증한다** — 표준 맞추기 미리보기 · 적용, 모델 편집, 확정 신청 · 승인, DDL이 같은 판정을 다시 돌린다.

## 2. SWS에서 가져올 것 · 바꿀 것

| SWS | NeoDB |
|---|---|
| 사전별 탭 × 필드 카드: 검사 사용 · 글자수(미사용) · 허용 문자 체크 | **가져옴, 모양은 바꿈** — 표 행 펼침(필드끼리 비교가 쉬움) |
| 특수문자 `/ - _ ,` + 모두 허용(팝업) | **바꿈** — 라디오 "쓰지 않음 / 고른 것만 / 모든 기호" + 칩(`_ - / , . ( ) &`) + 직접 입력. 공백 · 외국 글자는 기호로 허용하지 않음 |
| `null` ≠ `[]` ≠ `all` | **가져옴, 화면에는 숨김** — 문구로만 보임(UX-03). SWS의 "기존 기준 유지" 넷째 상태는 만들지 않음 |
| 숫자 시작 금지 · `__` 연속 금지 · 예약어 금지 | **가져옴** |
| 위반 처리 고정(사전 차단 · 코드값 경고) | **바꿈** — 필드마다 [막기][경고만][검사 안 함]. 필수 · 중복 · 참조 · 타입 · 코드값 무결성은 고정 |
| 저장 후 재검사 · 엑셀 결과 정책 버전 다르면 재검증 | **이미 있음** — 오류 행 · 토큰 없는 옛 묶음까지 넓힘 |

## 3. 기준 데이터(정책 v2)

```js
getPolicy() = {
  schemaVersion: 2,                    // 저장 형식 — 정책 내용 버전(ver)과 별개
  ver, at, by, hist: [{ ver, at, by, changes: [{ k, field, from, to }] }],
  bodies: { [ver]: <그 버전 정책 본문> },   // 옛 버전 조회 · 판정 재현용
  dbms: 'oracle' | 'postgresql',       // 공용 사전 용어 약어 상한 기본(30 / 63)
  fields: {                            // 사전
    word:   { name, abbr, eng, desc },
    domain: { name, desc },
    term:   { name, abbr, desc },
    code:   { abbr, name, value, valueName }
  },
  model: {                             // 모델 이름 규칙(사전 칩이 아닌 별도 묶음, UX-12)
    entity: { name, phys }, attr: { name, phys },
    entitySuffix: [{ w: '기본', a: 'M' }, ...], entitySuffixLvl
  },
  naming: {
    sep: '_' | '' | '-',               // 단어 사이 기호(용어 · 엔터티 약어)
    composeLvl,                        // 용어 약어 = 구성 단어 약어 조합
    endsWithFormatWordLvl, splitSuspectLvl,
    scaleSep: ',' | '_'                // 도메인 소수점 — 만들기 · 해석 둘 다
  }
}
Rule = { lvl: 'block' | 'warn' | 'off',
         max: number|null, min: number|null,        // 글자 수(코드포인트), null = 제한 없음
         chars: ['hangul','upper','lower','digit','space'] | null,   // null = 글자 종류 제한 없음, [] = 허용 없음
         special: [] | ['_','-',...] | 'all',       // 기호만 따로, chars와 독립
         noLeadDigit, noDoubleSep, noReserved }
*Lvl = 'block' | 'warn' | 'off'
```

- 값은 앞뒤 공백을 자른 뒤 NFC로 정규화해 검사한다. 직접 입력 기호는 한 글자씩, 전각은 반각으로 바꿀지 묻는다.
- **옛 값 옮기기**: 저장값 없음 → 기본값 / `wordAbbr` 없음 → 6 / `wordAbbr` 있음 → `fields.word.abbr.max` / v2의 명시적 `null` → 그대로. 옮길 때 문자 범위 · 처리도 지금 동작과 같게(판정 케이스로 확인).
- **판정 결과 모양**: `{ rule: 'word.abbr.chars', k, field, lvl, msg, ver }` — 화면은 문자열 비교 대신 `rule`로 묶는다.
- **모델 입력 규칙**(M-6, 2026-11-25): `modelInput = { defEmpty: 'block' | 'warn', defShort: 'warn' | 'block' | 'off', minLen: 1~100 }`, 기본 `{ defEmpty: 'block', defShort: 'warn', minLen: 5 }`. 대상은 **엔터티 정의**(`e.desc`) · **속성 설명**(`a.desc`).
  - 비어 있음(앞뒤 공백을 자르면 빈 값) → `defEmpty`.
  - 이름과 같음(공백 · 대소문자를 무시하고 엔터티명 · 속성명과 같음) 또는 `minLen` 미만(앞뒤 공백을 자른 코드포인트 수) → `defShort`. `off`면 이 검사를 하지 않는다.
  - 설명 한 칸의 판정은 `descJudge(name, desc, rules)` → `ok · empty · same · short` 하나로 하고(검수 기준 화면의 예시 · 영향 미리보기도 같은 함수), 모델 전체 판정은 `modelCheck(model, policy)` 하나(모델 화면 [모델 검증] · 확정 신청 · 서버 재검사 · 승인 재검사 공용, 01-summary §4-D). **막음은 확정 신청 · 승인을 막고, 경고는 결재 문서에 남는다.**
  - 저장: 정책 본문 `modelInput`(버전 · 이력 · 옛 본문에 함께) + 목업은 localStorage `neodb.modelInputRules`에도 같은 값(모델 화면이 읽음). 옛 본문에 `modelInput`이 없으면 비교하지 않는다(‘무엇이 바뀌었나’에 나오지 않음).
- **어긋남 검사** `policyConflicts(pol)`: 구분자가 용어 · 엔터티 약어 허용 기호에 없음, 단어 약어가 허용하는 글자를 용어 약어가 막음, 단어 약어 상한 × 흔한 단어 수 > 용어 약어 상한, 물리명에 인용이 필요한 기호 허용.

## 4. 화면 — `rules.html`

1. **머리**: `검수 기준 vN` · "공통표준 기본값에서 **n곳 바꿈**" [다른 곳만 보기] [기본값으로 되돌리기]. 첫 진입 안내 한 줄.
2. **사전 규칙** — 칩 단어 · 도메인 · 용어 · 코드(바뀐 칩에 점). 표 칸: `필드 · 필수 · 최대 길이 · 허용 글자 · 추가 조건 · 어기면`.
   - 모두에게: 요약 글자(예: `영문 대문자 · 숫자 · 기호 _ -`).
   - DA · Admin: 줄 펼침(`aria-expanded`, 포커스 이동) — 글자 종류 체크, 기호 라디오 + 칩 + 직접 입력, 최대 길이 + "길이 제한 없음", 추가 조건, `[막기][경고만][검사 안 함]`. 고정 줄은 자물쇠 + 이유. 바뀐 줄은 표시.
   - 모델러: 줄마다 **[이 기준 변경 제안]** → 사유 + 바라는 값 → DA 할 일(결재함 "기준 제안")에서 시험해 보기 · 영향 미리보기로 검토.
   - **시험해 보기**: 값을 넣으면 "지금 기준 / 바꾼 뒤" 두 줄 판정. 예시 칩, 이름 하나로 전체(단어 → 용어 → 물리명) 시험.
3. **모델 이름 규칙**(새 묶음, "(모델)" 표시): 엔터티 · 속성 이름 · 물리명 규칙, 엔터티 분류어 → 접미 표.
   - **모델 입력 규칙**(M-6, 모델 이름 규칙 바로 다음 묶음, `?sec=input`): ‘정의 비어 있음’ `[막음][경고]` · ‘이름과 같음 · 짧음’ `[경고][막음][끔]` + ‘최소 글자 수 n 자’ · ‘예시’(엔터티 ‘고객’의 정의 4개를 지금 고친 값으로 판정). 편집은 `rules.edit`(DA · Admin), 그 밖은 흐리게(조회 전용). 저장은 다른 규칙과 같이 영향 창을 거쳐 버전을 올린다 — 영향 창 ③에 ‘모델 정의 · 설명 신규 막음 n개 · 신규 경고 n개 · 완화 n개’.
4. **명명 규칙**: 단어 사이 기호, 조합 엄격도, 형식단어로 끝남, 한 글자 단어로 잘게 쪼개진 것 같음, 소수점 기호. **미리보기 상자**: 용어 · 엔터티 · 도메인 · 물리명 예시를 이전 → 이후로, 선택지마다 위험 글자("DB에서 따옴표 필요", "단어 경계가 안 보임"). 소문자 허용 시 "사전 `custNo` → DDL `CUSTNO`" 줄.
5. **저장 전 영향 창**(PC-02 확장) 순서: ① 서로 맞지 않는 설정(있으면 빨강, 막기면 [저장] 꺼짐, 바로 고치기 단추) → ② 바뀐 규칙 → ③ 새로 막힘 · 경고 · 새로 통과 수(사전 항목 · 진행 중 신청 · 모델 속성 · 엑셀 묶음, 예시 3개 + 목록 링크) · 이름 충돌 → ④ 적용 방식("기존 데이터는 고치지 않음 · 다시 검사 필요 표시 · 이름 바꾸기는 [변경 신청 만들기]로 따로"). 영향이 큰 변경만 확인 체크.
6. **변경 이력**: "단어 영문약어명 6 → 8자 외 3곳 [펼치기]", 줄을 누르면 그 버전 기준 읽기 전용 보기.

쉬운 말(UX-15): 차단 → 막기, 끔 → 검사 안 함, 위반 시 → 어기면, 구분자 → 단어 사이 기호, DBMS 예약어 → DB가 쓰는 낱말, 1음절 분해 의심 → 한 글자 단어로 잘게 쪼개진 것 같음. 나열은 `·` 앞뒤 띄움.

## 5. 검수 · 검증에 적용

| 소비처 | 바꿀 것 |
|---|---|
| `checkItem()` | `ruleProblems(k, field, value, pol)` 하나로 길이 · 글자 · 기호 · 추가 조건. 하드코딩 정규식 제거. 결과에 `rule · lvl · ver` |
| `checkDictDoc()` · 결재 | 중복 판정(단어 약어 길이 · 30자) 제거 → `checkItem`만. 변경 결재는 바뀐 칸 + **함께 영향받는 칸**(이름 바뀌면 약어 조합) 재판정. 경고도 검수 탭까지 |
| `decompose()` · 약어 조합 · 전파 | `naming.sep` 사용, 문자열 쪼개기 대신 **구성 단어 ID · 순서**로. 구성이 모호한 옛 항목은 "직접 확인" |
| 직접 등록 · 마법사 | 대문자 강제 변환 · 자체 정규식 제거 → 기준이 대문자만이면 "대문자로 바꿀까요?" 제안 |
| 엑셀 | `wordLim` 제거 → 정책 규칙. 재검증은 오류 행 포함, 토큰 없는 옛 묶음도 신청 전 재검사 |
| 도메인 · 코드값 | `parseDomName`이 `scaleSep` 사용, 코드값 길이는 해석한 도메인 길이 |
| 표준 맞추기 · 모델 편집 · 확정 신청/승인 | 저장된 `s`를 믿지 않고 `model` · `naming` 규칙으로 다시 판정. 미리보기 뒤 기준 · 사전이 바뀌면 미리보기 갱신 |
| DDL | 같은 판정 + 시스템 DBMS 식별자 규칙(길이 · 예약어 · 대문자 정규화 충돌) |
| 모델 검증 · 확정 신청 · 승인 재검사(M-6) | `modelCheck(model, policy)`가 `modelInput`으로 엔터티 정의 · 속성 설명을 판정. 결재함 승인 재검사 · 검사 결과 탭은 `modelCheck`의 ‘막음’ 건수를 쓴다(없으면 기존 미준수 계산) |
| 오류 문구(모든 화면) | `기준: 필드 · 규칙 · 검수 기준 vN [기준 보기]` → `rules.html?k=word&f=abbr&v=N` 해당 줄 강조 |

**버전 계약**: 신청 때 `policyVer`를 기록(지금처럼), 검사 탭 · 승인 재검사는 최신 기준. 이력에 "신청 vA · 판정 vB"를 함께 남기고, 차이가 있으면 결재 화면에 "신청 뒤 기준이 바뀌었습니다 [무엇이 바뀌었나]". 승인 때 막힘이 생기면 반영 중단 + 사유 · 버전.

**일치 장치**: `assets/policy-cases.js` — (정책, 값) → 기대 판정. 반드시 넣을 경우: 옛 v3 값, `null` · `[]` · `'all'`, 구분자 없음과 이름 충돌, 소문자 · 인용 필요 기호, 오래된 엑셀 묶음, 진행 중 결재. `styleguide.html` 자체 점검에서 돌린다.

|---|---|---|
| **Q1 권한** | **지금: A(기관 기준, DA · Admin 고침) + 모델러 변경 제안.** 다음 차수: B를 "모델 이름 규칙만 · 시스템별로 좁히기만 · 출처 배지"로. C(개인별 기준) 기각 | Codex-7 · UX-13 합의 — 사전은 기관 공용이라 시스템마다 넓히면 같은 단어가 통과하기도 막히기도 함 |
| **Q2 "검사 안 함"과 준수율** | **결정(2026-11-25 사용자)**: 준수율은 **속성(항목) 단위**. 분모 = 대상 속성 수 그대로. 각 속성은 **켜진 규칙으로만** 판정(꺼진 규칙은 통과 · 위반 어느 쪽에도 안 셈). 준수율 옆에 `검사 안 함 규칙 n개`(누르면 목록). 예: 속성 10개, ③ 조합 규칙 끔, A는 ③만 어김 · B는 길이 어김 → 9/10 = 90% · 검사 안 함 규칙 1개 | [협의 결과](review/resolution-inspection-policy-v2.md) |
| Q3 단어 사이 기호 변경 | 영향 확인(+확인 체크) 후 저장 허용. 기존 사전 · 확정본 · 물리명은 그대로, "다시 검사 필요" 표시. 실제 이름 바꾸기는 [변경 신청 만들기]로 따로(참조 · PK/FK · DDL 확인) | Codex-5 · UX-17 |
| Q4 공통표준 항목 | 형식 검사 예외 — 회색 "기관 기준 예외" 배지 + 차이 사유. 중복 · 참조는 계속 검사. 그걸로 만든 기관 용어 · 물리명은 검사 | Codex-8 · UX-14 |
| Q5 소문자 · 인용 | 표기 보존, 물리 비교 · DDL은 시스템 DBMS(대문자 정규화 충돌 검사). 따옴표가 필요한 기호(`-` · 공백 등)는 물리명에서 막음 | Codex-6 |
