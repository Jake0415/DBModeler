# 30. 퍼블리싱 정합성 점검 2차 — 전체 화면 디자인 · 문구 일관성 (2026-11-25)

> 1차는 [17](17-publishing-audit.md)(2026-11-20). 그 뒤 바로잡기(25) · 엑셀 정의서 가져오기(26) · 데이터 타입(27) · 통합 보기(28) · RBAC 2차(29)로 화면이 늘어, 구현 전에 마지막으로 전체를 맞췄다.
> 상태: **반영 완료(목업)**. 문구 기준은 [01 디자인 가이드 §11](01-design-guide.md)에 넣었다.

## 1. 방법
1. **자동 측정**([pub2-auto-check](review/pub2-auto-check.md)):
   - NeoAudit로 25개 화면 × 1920 · 1600을 쟀다.
   - 화면 구조(헤더 · 경로 · 패널 폭 · 탭 종류 · 인라인 색)를 23개 화면에서 비교했다.
   - 문구는 HTML · app.js 문자열에서 표기가 섞인 곳을 검사했다.
2. **리뷰 두 건**:
   - Codex는 코드 · 문자열을 전수 비교했다([codex-pub2](review/codex-pub2.md), PC-01 ~ 25).
   - UX 전문가는 브라우저로 역할별 화면을 직접 보고 비교했다([claude-pub2](review/claude-pub2.md), UX-01 ~ 38).
3. **합의 → 반영 → 회귀 점검**(§3 · §5).

## 2. 결론
- **디자인 측정값은 이미 안정적이다.** 12px 미만 글자 · 굵기 700 · 이름 없는 버튼 · 아이콘 대신 문자 · 가로 넘침은 모든 화면에서 0이다. 버튼 높이는 28 · 32 · 40의 3종이고, 헤더 56px · 인라인 색 0이다.
- **흔들린 것은 ‘말’과 ‘새 화면의 부품’이다.**
  - 같은 결재 문서를 ‘품의’와 ‘신청’으로 불렀다.
  - 결재가 아닌 요청이 반려 · 거절 · 철회 · 취소를 섞어 썼다.
  - 모델의 ‘엑셀로 가져오기’가 사전의 ‘엑셀 가져오기’와 한 글자 차이였다.
  - 새 화면(26 · 27 · 29)이 단계 막대 · 탭 줄 · 모달 폭을 인라인으로 다시 만들었다.
  - 디자인 가이드에 **문구 기준이 없었다**.

## 4. 하지 않은 것 (기록)
- **DDL 가져오기를 4단계 흐름으로**(UX-20): 화면 흐름을 새로 설계해야 해서 구현 단계로 넘긴다. 이번에는 ‘파싱’ 말만 바꿨다.
- **토스트 문장 전수 정리**(PC-17 · UX-11): 기준은 §11.2에 정했다. 토스트 수백 개를 한 번에 바꾸면 회귀 위험이 커서 구현 단계에서 공통 생성기로 맞춘다.
- **일시 표기 통일**(PC-23 · UX-15): 목업 시드 데이터가 ‘M/D HH:mm’으로 저장돼 있어, 구현 때 저장 형식과 표시기에서 맞춘다(§11.3).
- **데이터 타입 ‘사용 중지’ → ‘미사용’**(UX-07): 상태 값이 데이터 키로도 쓰여 이번에는 기준만 정했다.
- **설정형 저장 막대 하나로**(UX-17 일부): 검수 기준 · 시스템별 매핑의 막대를 `.setbar`로 합치는 일은 구현 단계에서 한다(이번에는 확인 창 · 바로 적용 표시로 구분만 분명히 했다).
- **필수 표시 모양 통일**(UX-36): `.req` 부품만 만들고 화면 적용은 구현 단계.
- 결재함 상자별 화면 안내(PC-11 일부), 데이터 타입 탭 안내 위치(PC-12).

## 5. 검증
- **오류 점검**: 업무 화면 26개 + 상태 3개(확인 요청 · 설정 사용자 탭 · 통합 보기) × 사용자 5명 = 145회, 오류 0건.
- **NeoAudit 재측정**(26개 화면 × 1920 · 1600 = 52회): 12px 미만 · 굵기 700 · 이름 없는 버튼 · 이름 없는 입력 · 아이콘 대신 문자 · 가로 넘침 **모두 0**. 1차 측정에서 걸렸던 검수 기준 라벨 문제도 해결됐다.
- **버튼 높이**: 28 · 32 · 40. 예외는 모델 캔버스의 ‘접힌 안내 띠’(`.cv-banner.min`) 안 24px 버튼 하나로, 띠를 한 줄로 접는 기존 결정(ERD 리뷰)이라 그대로 둔다.
- **인라인 스타일(소스)**: 모델 33 · 견본 15 · 결재함 11 · 엑셀 가져오기 10 · 엑셀 정의서 7 · 홈 6 · 설정 5. 데이터 타입 0 · 검수 기준 1. 남은 것은 대부분 계산된 값(좌표 · 폭)이고, 정적 여백은 구현 단계에서 유틸리티로 옮긴다.
