## 1. SWS 템플릿 (기준 양식)
- 시트 **‘테이블 설계’** 한 장 + **‘작성가이드’**. **한 행 = 한 컬럼.** 테이블 정보는 모든 행에 반복한다.
- 14열: **테이블 물리명\*** · 테이블 논리명 · 테이블 설명 · **컬럼 물리명\*** · **컬럼 논리명\*** · **컬럼 타입\*** · 길이 · 소수점 자리수 · PK(Y) · **필수(Y)** · 기본값 · 컬럼 설명 · 참조 테이블 · 참조 컬럼. (\* 필수)
- 예전 18열 양식도 읽는다.
  - 용어는 **‘필수’**로 쓴다: Y = 값이 꼭 있어야 함(DB에서는 NOT NULL), 비우면 필수 아님. SWS 파일의 ‘NOT NULL’ 머리글도 ‘필수’로 읽는다.
  - 예전 ‘NULL 허용 여부’는 의미가 반대(N = 필수)다.
  - 표준용어명 · 영문약어명 · 원천 테이블 · 원천 컬럼 열이 있다.
  - 데이터 시트는 여러 장일 수 있다. ‘인덱스’ 시트는 안내한 뒤 빼고, ‘ERD’ 시트는 건너뛴다.
- 인덱스는 엑셀로 받지 않는다(모델 화면에서 편집).
- 원칙: **원본 이름 · 타입 · 규격 · 참조를 임의로 고치지 않는다.** 업로드는 **파일 · 빈 칸 · 이름 중복만** 막고(M-2), 참조 · 타입 · 표준 · 구조 문제는 경고로 알린 뒤 가져와 모델의 **모델 검증**에서 다시 본다.
- 저장: 타입 · 길이 · 소수점은 한 문자열(`VARCHAR2(10)`)로 합치지 않고 속성의 `t`(타입명) · `len` · `scale`로 따로 넣는다. 한 칸에 `NUMBER(5,2)`처럼 적힌 것은 나눠 넣고, 길이 · 소수점 칸이 있으면 그 칸을 쓴다.

## 2. 업로드 시나리오
| 단계 | 화면 · 동작 |
|---|---|
| ① 진입 | 세 곳에서 들어온다.<br>· 모델 › ⋯ › 가져오기 › **[엑셀 정의서]**(활성화)<br>· 시스템 홈 [+ 업무 영역] 창의 **[엑셀로 만들기]**<br>· 빈 업무 영역 캔버스의 첫 안내 **‘엑셀로 시작’** |
| ①-1 사전 준비도 | ① 단계 위 띠 ‘사전(공통표준 + 기관): 단어 n(기관 n) · 용어 n(기관 n) · 결재 중인 단어 · 용어 추가 n’ — **수치만**(B-2). 사전을 먼저 채우라는 권유는 파일을 본 뒤 ③에서 한다(2026-11-26 흐름 리뷰 U-11) |

| ③ 파일 올리기 | `.xlsx`만 받는다. 크기 · 압축 해제 크기 제한(SWS: 100MiB)을 둔다. 끌어 놓기와 [파일 고르기] 둘 다 된다. 읽는 동안 진행 표시 |
| ④ 검사 · 미리보기 | 위에 요약: **등록 가능 n · 등록 불가 n(중복 n)** · 컬럼 n · 만들 관계 n · 막는 오류 n · 경고 n, 그 아래 줄 ‘등록 가능 n · 등록 불가 n(중복 n) · **경고 n — 가져온 뒤 모델 검증에서 다시 봅니다**’.<br>탭 3개(+기존 영역은 ‘추가 계획’): **문제**(구분 오류 / 추가 안 함 / 경고 · 시트 · 행 · 열 · 내용, [행 보기]) / **테이블**(물리명 · 논리명 · 컬럼 수 · PK · 참조 · 점검 — 정상 · PK 없음 · 오류 · **중복 — 등록 불가** · **이미 있음 — 추가 안 함** · **기존 부모 참조(연결)**, 중복 · 이미 있음은 근거를 함께) / **관계**(부모 → 자식 · FK 짝 · 유형 · 선택성 · 처리).<br>**표준 예상 한 줄(B-1):** ‘사전 기준 표준 예상 n%(가져올 컬럼 N개 중 m개가 사전 용어) · 사전에 없는 용어(단어는 있음) n개 · 미등록 단어 n개 — 가져온 뒤 표준 맞추기 → 용어 자동분석’. **반영 가능한 테이블(오류 · 중복 · 이미 있음 제외)과 ‘사용’ 상태 용어만**으로 계산한다(F-11 · U-10). 결재 중인 단어 · 용어 **추가** 신청이 있으면 ‘결재 중인 단어 · 용어 추가 신청 n건 — 승인 뒤 표준이 늘어납니다’(U-23). 파일 전체가 막히면(처음 업로드의 막는 오류, 기존 영역의 파일 자체 오류 — 머리글 없음 · 데이터 없음) ‘사전 기준 표준 예상 — 막힘(가져올 컬럼 0개)’으로만 보인다(F-11). 예상 표준률이 **50% 미만**이면 경고 띠 ‘사전을 먼저 채우면 표준 맞추기에서 더 많이 해결됩니다’ + [사전 엑셀 일괄](U-11). 대략 계산이라 ‘예상’이라고 쓴다.<br>처음 업로드가 막혔으면 ‘등록 가능 0 (전체 막힘)’, ‘등록 불가 = 전체 테이블 수(오류 n · 함께 막힘 n)’로 보인다(F-012 · U-16).<br>중복은 묶음으로 보인다: ‘엔터티명 사원기본 — 12행 · 40행 중복(논리명 일치 · EMP_M / EMP_H)’.<br>**[검사 결과 표시된 엑셀 내려받기]**.<br>막는 오류가 있으면 [가져오기]는 꺼지고(M-3), 경고만 있으면 켜진다 |
| ⑤ 가져올 위치 | **새 업무 영역**(이름, = **처음 업로드**) 또는 **기존 업무 영역**(= **엔터티 추가**).<br>기존 영역은 **‘추가만’ 한 가지**다(M-4, W1). 고르는 선택지는 없다.<br>· 같은 시스템 **전체 업무 영역**의 기존 엔터티(지금 작업본 이름 — 표준화로 바뀐 이름 포함, 바뀌기 전 원래 이름(`orig`)도 함께 비교, 참조 엔터티 제외)와 **논리명 또는 물리명**이 같은 테이블은 ‘이미 있음 — 추가 안 함’으로 빼고 나머지만 추가한다. 기존 테이블 · 컬럼 · 관계는 바꾸지 않는다.<br>· 일치한 엔터티의 영역 · 논리명 · 물리명 · [모델에서 열기]는 **사용자가 그 영역 사본을 열람할 수 있을 때만**(`areaView` 열람 판정, R-07) 보인다. 못 보면 이름 없이 ‘열람 권한 밖의 업무 영역에 같은 이름이 있습니다’로만 보이고 링크는 없다. 판정 자체는 시스템 전체 그대로다.<br>· 파일 안 오류 · 중복이 있는 테이블도 **그 테이블만** ‘오류 · 중복으로 빠짐’으로 빼고 정상 테이블은 추가한다(M-3).<br>· 새 테이블이 기존 엔터티를 부모로 참조하는 것은 중복이 아니다 → ‘기존 부모 참조(연결)’로 관계를 잇는다.<br>· 안내 띠: ‘기존 ○○을 바꾸려면 모델에서 삭제한 뒤 다시 올리세요’ + [모델에서 ○○ 열기](새 탭) + [다시 검사](같은 파일을 지금 모델 기준으로 다시 판정) + 주의 ‘삭제한 뒤 다시 추가하면 운영 DB에는 DROP/CREATE로 나갈 수 있습니다’.<br>· ~~병합(기본) · 덮어쓰기 · 병합 충돌 값 고르기~~ → **W2로 미룸**(§6-1 변경) |
| ⑥ 적용 | 대상 영역이 **작업 중**일 때만 된다. 결재 중이면 막고, 확정본이면 “새 작업 버전을 먼저 시작”으로 안내한다.<br>**처음 업로드는 막는 오류가 하나라도 있으면 전체를 적용하지 않는다(M-3).** 처음 업로드도 저장 직전에 시스템 테이블명 검사(작업본 + 유효 확정본)를 다시 돌려, 미리보기 뒤 생긴 충돌이면 저장하지 않고 다시 검사한 결과를 보인다(F-08). 엔터티 추가는 오류 · 중복 테이블과 ‘이미 있음’ 테이블만 빼고 정상 테이블을 추가한다. 파일 자체 오류(필수 머리글 없음 · 데이터 없음 · 파일 읽기 불가)는 두 경로 모두 전체를 막는다.<br>추가하는 순간 다시 판정해 **추가 대상 · 제외 대상 · 부모 연결 집합**을 이전 미리보기와 비교한다(개수가 아님). 다르면 바뀐 ‘추가 계획’ 탭을 열고 토스트로 알린 뒤 멈추고, 다시 눌러야 추가한다.<br>새 엔터티 · 속성 id는 물리명으로 만들지 않고 `newId(prefix)`로 새로 발급한다 — 삭제 후 같은 이름으로 다시 올려도 새 엔터티다(R2-13).<br>저장 직전 결과 모델에 `modelInvariants(model)`(엔터티 안 컬럼 물리명 중복 · 테이블명/엔터티명 중복, 대소문자 무시)을 돌려, **이번 가져오기로 새로 생기는 위반**이 있으면 저장하지 않고 아래 줄 ‘가져오면 모델 규칙에 어긋납니다 — <이유>. 가져오지 않았습니다’ + 토스트로 알린다(이미 있던 위반은 막지 않음).<br>새 영역은 v1 작업 버전으로 만든다. 자동 배치는 관계 기준으로 부모가 위에 오게 한다(지금대로). ‘가져온 테이블’ 보기(연결한 기존 부모 포함)를 만들고, 엔터티 · 속성 표준 판정을 바로 계산한다.<br>완료 화면 + **[가져오기 취소]**(1회 되돌림). 끝날 때 `dbm-import-last`에 `{id, at, src:'excel', area, dst, tables, cols, warn}`를 남기고, 완료 화면 [표준 맞추기] 링크에 `&imp=<id>`를 붙여 표준 맞추기가 바로 이 가져오기의 결과와 짝짓는다(A-1 · F-12, DDL 가져오기는 `src` 없음). 감사 로그에 남긴다(방식 · 추가 · 추가 안 함 · 관계 · FK 후보 · 경고 수) |
| ⑦ 이어서 작업 | 완료 화면의 주 버튼은 **[표준 맞추기]**, 보조 [모델 열기]. 안내 ‘다음 순서: **모델 등록 ✓ → 표준 입히기 → 남은 용어(용어 자동분석) → 검증 · 신청**’ — 진행 띠 4단계와 같은 말(2026-11-26 U-09). 자동 배치는 가져올 때 이미 한다.<br>모델 화면에서 자유롭게 고친다: 테이블 · 컬럼 · **관계 맺기(18)**. 관계 없는 FK 후보(`fkCand`)는 모델 검증에서 다시 보인다.<br>같은 파일을 고쳐 다시 올리면 **추가만** 된다 — 기존 테이블을 바꾸려면 모델에서 고치거나 삭제한 뒤 다시 올린다(흐름 [02 §5.6](02-flows.md)) |

## 3. 검증 시나리오 — 세 단계
### 3-1. 업로드 단계 — 막는 것(오류) — 2026-11-25 M-2로 다시 나눔
중복 비교는 대소문자를 무시한다. 중복은 묶음(행 목록)과 근거(논리명 일치 / 물리명 일치)를 함께 보인다.
**이름 비교는 저장될 최종 이름으로 한다**(재리뷰 N-04): 논리명이 빈 테이블 · 컬럼은 물리명이 논리명으로 저장되므로 그 이름으로 비교하고(근거에 ‘빈 논리명은 물리명으로 저장’), 원래 적힌 이름도 함께 본다. 파일 안 중복 · 기존 엔터티 중복 모두 같다. 그래서 미리보기의 ‘등록 가능’은 저장 직전 `modelInvariants` 검사와 결과가 같다.

| 검사 | 메시지 예 |
|---|---|
| 파일을 읽을 수 없음 · 크기 초과 · 데이터 없음 | ‘파일을 읽을 수 없습니다 — .xlsx로 저장해 다시 올리세요’ |
| 필수 열 없음(머리글) | ‘필수 열 ‘컬럼 타입’이 없습니다 — 1행 머리글을 양식대로 두세요’ |
| 필수 칸 빈 행: 테이블 물리명(새 양식) · 컬럼 물리명 · 컬럼 논리명 · 컬럼 타입 | 시트 · 행 · 열 위치 |
| **엔터티(테이블 논리명) 중복** — 물리명이 다른 두 테이블의 논리명이 같음 *(신규)* | ‘엔터티명 사원기본 — 4행 · 13행 중복(논리명 일치 · EMP_M / EMP_H)’ |
| **테이블 물리명 중복** — 같은 물리명이 다른 테이블 행 뒤에 또는 다른 시트에 다시 나옴 | ‘테이블명 DEPT_M — 2행 · 14행 중복(물리명 일치)’ |
| **같은 테이블 안 속성(컬럼 논리명) 중복** *(신규)* | ‘속성명 사원기본.사원번호 — 4행 · 6행 중복(논리명 일치 · EMP_NO / EMP_NM)’ |
| 같은 테이블 안 컬럼 물리명 중복 | ‘컬럼명 EMP_M.DEPT_CD — 12행 · 18행 중복(물리명 일치)’ — 논리명도 같으면 한 묶음 ‘컬럼 … (물리명 · 논리명 일치)’ |

| **처음 업로드: 같은 시스템 다른 업무 영역과 테이블 물리명이 같음** *(2026-11-26 Q-F4 · F-013)* — 각 영역의 **작업본과 유효한 확정본(최신 확정 사본)** 모두와 비교(F-08) | ‘‘DEPT_M’은 같은 시스템 다른 업무 영역(인사관리 › 부서기본)에 있습니다. 물리명은 시스템 안에서 유일해야 합니다’(확정본이면 ‘인사관리 확정본 v4 › 부서기본’). 작업본을 열람할 수 없으면 이름 없이 ‘… 열람 권한 밖의 업무 영역에 있습니다’ — 확정본은 영역을 볼 수 있으면 보인다(U-21) |

처음 업로드에서 **엔터티명(논리명)**이 다른 영역과 같으면 막지 않고 경고한다(‘가져온 뒤 이름을 구분하세요’). 기존 영역(엔터티 추가)은 지금처럼 논리명 · 물리명 모두 ‘이미 있음 — 추가 안 함’이다.

**처음 업로드(새 업무 영역)는 이 중 하나라도 있으면 전체를 가져오지 않는다(M-3).** 기존 영역(엔터티 추가)은 파일 자체 오류(파일 읽기 불가 · 필수 머리글 없음 · 데이터 없음)만 전체를 막고, 나머지 오류 · 중복은 **그 테이블만 빼고**(문제 탭 구분 ‘오류 · 제외’, 테이블 탭 ‘중복 — 등록 불가’ · ‘오류 — 등록 불가’) 정상 테이블을 추가한다. 테이블에 속하지 않는 행(테이블 물리명이 빈 행)은 그 행만 빠진다. 대소문자만 다른 두 테이블은 둘 다 뺀다. 기존 엔터티와 겹치는 것은 오류가 아니라 ‘이미 있음 — 추가 안 함’이다(§2 ⑤).

### 3-2. 업로드 단계 — 알리고 가져오는 것(경고)
- **2026-11-25 M-2로 경고로 내린 것** — 가져오되, 참조 문제가 있는 행은 **관계를 만들지 않고 컬럼만** 가져오며 그 컬럼에 `fkCand: {table, col}`(적힌 참조 테이블 · 참조 컬럼)을 남긴다. 모델 화면의 **모델 검증**이 ‘관계 없는 FK 후보’로 보여 준다. 메시지 끝: ‘— 관계 없이 컬럼만 가져옵니다(모델 검증에서 ‘관계 없는 FK 후보’로 다시 봅니다)’.
  - 참조 테이블 · 참조 컬럼 중 하나만 입력
  - 참조 대상이 이 파일 · 대상 영역 · 같은 시스템 다른 영역 어디에도 없음
  - 참조 컬럼이 부모에 없거나 PK가 아님
  - 참조 컬럼과 타입 계열이 다름(‘참조 컬럼과 타입이 맞지 않습니다(NUMBER(10) / VARCHAR2(12))’)
  - 어느 한쪽 타입 계열을 판정할 수 없음(미인식 타입, ‘참조 컬럼과 타입 계열을 판정할 수 없습니다(FOO(10) / VARCHAR2(10))’)
  - 부모 복합 PK를 일부만 참조(빠진 키 표시)
  - 다른 영역 참조를 끄거나 원본에 확정본이 없음(§4)
  - 같은 테이블의 논리명 · 설명이 행마다 다름 → 처음 행 값으로 가져오고, 쓰지 않은 값은 엔터티에 `xDiff: {n: [다른 논리명들], d: [다른 설명들]}`로 남긴다 — 모델 검증 일괄 처리에서 행별 값을 고른다(A-5)
- PK가 없는 테이블.
- 길이가 필요한 타입(VARCHAR · CHAR · NUMBER 계열)에 길이가 없음.
- 길이 · 자릿수가 숫자가 아님. 원본 그대로 보존하고 표시한다.
- **이 시스템의 데이터타입 매핑에 없는 타입.** 예: Oracle 시스템에 `TEXT` → 보존하고 표시한다.
- DBMS 이름 길이 · 예약어 위반, 명명 템플릿과 다른 이름.
- 인덱스 시트를 뺌, 예전 양식으로 읽음, 표준용어 열이 있음(참고로만 보존).

### 3-3. 가져온 뒤 — 모델에서 하는 검사
- **표준 사전 판정**(준수 · 조합 · 미등록) → [표준 맞추기] · 후보 큐.
- **모델 검증**(01-summary §4-D, 모델 화면 담당): FK 누락, PK인데 필수가 아닌 컬럼, M:N 미해소, 관계 잃은 컬럼, **관계 없는 FK 후보(`fkCand`)**, 정의 · 설명 누락.
- **확정 신청** 때 전체를 다시 검사하고, 오류가 있으면 결재를 막는다.

## 4. 엑셀 참조 열 → 관계 만들기 규칙 (18과 같은 결과)
| 엑셀 | 만들어지는 관계 |
|---|---|
| 같은 자식 → 같은 부모로 가는 참조 행 여러 개 | **관계 하나(복합 FK, FK 묶음 `g`)** |
| 참조 컬럼이 자식 PK에 들어 있음 | **식별** 관계 |
| 그 밖의 경우 | **비식별** 관계 |
| 자식 FK 컬럼이 필수 | 선택성 ‘반드시 있다’ |
| 자식 FK 컬럼이 필수 아님 | 선택성 ‘없어도 된다’ |
| 자식 FK 컬럼 조합에 UK가 있음(1:1) | 카디널리티 ‘0~1개’ |
| 그 밖의 경우 | 카디널리티 ‘0개 이상’ |
| 같은 테이블 참조 | **재귀** 관계, 역할명은 컬럼 논리명에서 ‘상위’ 같은 말을 쓴다 |
| 같은 두 테이블 사이 두 번째 관계 | 역할명을 컬럼 논리명으로 정한다(출발 · 도착) |
| 부모가 같은 시스템의 다른 업무 영역 테이블 | 미리보기 관계 탭에 **‘○○ 영역 › 부서기본 — 참조로 가져오기 ☑’**(기본 켬). 켜면 참조 엔터티로 넣고 관계를 잇는다. 끄면 FK 컬럼만 남기고(`fkCand`) 경고한다. 원본 영역에 확정본이 없으면 칸을 끄고 이유를 보인다 |

| (엑셀에 관계명 열 없음) | 관계명은 비워 둔다 — 가져온 뒤 관계 패널에서 명사로 입력 |
| ON DELETE | 기본 ‘막기’ — DB 반영 설정은 모델에서 |

## 5. 지금 ERD의 관계 설정 — 시나리오와 목업 확인 결과
**시나리오:** [18-relation-scenario.md](18-relation-scenario.md) 확정안. 목업은 `model.html`에 반영되어 있다.
- **연결:** 도구 [관계 R] → 부모 클릭 → 자식 클릭으로 바로 만든다. 키보드는 자식 고르기 목록(글자로 거르기 · ↑↓ · Enter).
  - 부모 PK 전체가 자식 FK가 된다. 식별 관계는 손자까지 이어진다(`pkSpread`).
  - 1:1은 UK를 자동으로 붙인다.
  - M:N은 [미리보기 후 해소]로 교차 엔터티를 만든다.
  - 부모에 PK가 없으면 ‘FK 대기’로 둔다.
  - 이름이 겹치면 역할명 팝오버로 정한다(재귀 · 두 번째 관계).
- **관계 패널(오른쪽 420px):** 관계명(명사형) · 유형(식별 전환은 영향 띠 → [적용]) · 카디널리티 · 선택성 · FK 짝 · DB 반영(ON DELETE · FK 이름 · UK, 기본은 접힘).
- **삭제:** 패널 안 띠에서 컬럼 처리 방식을 고른다(남김 / 함께 삭제, 손자 정리). 처음 포커스는 [취소]이고, 실행 취소 한 번으로 모두 돌아온다.
- **연동:** DDL(FK · ON DELETE · UK), 결재 비교(모델 / DB 동작 변경 묶음), 트리 관계 노드.
- 다른 업무 영역 엔터티는 **참조 엔터티**(부모만 됨)로 끌어와 관계를 맺는다.
- **이번 확인에서 보인 점(인사관리 · 부서기본 재귀 관계 패널) — 2026-11-24 다시 확인:**
  - FK 짝은 실제로 `UP_DEPT_CD`가 선택돼 있었다. 처음 확인 때는 선택 상자의 모든 항목 글자를 함께 읽어 ‘(없음 — FK 누락)’으로 잘못 봤다. 상태 줄 ‘FK 반영’과 맞는다 — **문제 없음.**
  - 카디널리티 문장이 ‘부서기본 1개는 부서기본을 …’으로 읽히던 것은 고쳤다. 재귀 관계는 패널 제목 ‘관계 · 재귀 — 상위 → 하위’, 문장 ‘상위 부서기본 1개는 하위 부서기본을 …’ · ‘하위 부서기본 1개는 상위 부서기본이 …’로 읽고, 바꿀 때 뜨는 알림도 같은 말을 쓴다.
- 남은 일(18 §5): 부모 PK 변경 시 자식 FK 따라가기, 참조 원본 변경 시 다시 맞추기, FK 짝 타입 호환 검사, DBMS별 ON DELETE 차이.

- **진입:** 모델 ⋯ [엑셀로 가져오기], 트리 아래 링크, DDL 가져오기의 [엑셀 정의서], 시스템 홈 새 영역 창의 [엑셀로 만들기](입력한 이름을 넘긴다).

  - Y 값은 Y · 예 · O · 1을 ‘예’로 읽고, 그 밖의 값은 경고한다.
  - 테이블 이름도 예약어 · 길이를 검사한다.
  - 부모 복합 PK를 일부만 참조하면 ~~**오류**~~ **경고**(빠진 키 표시, 2026-11-25 M-2)다.

- **미리보기:**
  - 요약(테이블 · 컬럼 · 만들 관계 · 오류 · 경고)과 탭(문제 · 테이블 · 관계 · 병합/덮어쓰기 계획)을 보여 준다. 문제 행은 [행 보기]로 그 행의 값을 연다.
  - 다른 영역 참조가 있으면 관계 탭을 먼저 연다. 고른 값은 다시 검사해도 유지한다.
- **병합 · 덮어쓰기 — 2026-11-25 W2로 미룸(M-4), 아래 두 항목은 W2 참고용:**
- **병합:**
  - 관계는 ‘새로 · 이미 있음(같은 부모 · 자식 · FK 짝 전체) · FK 충돌’로 나눈다.
  - 값 충돌(논리명 · 타입 · PK · 필수 · 테이블 논리명)은 기본 ‘엑셀 값’이고, [모두 엑셀 값] · [모두 지금 값]으로 한 번에 고를 수 있다. 바뀐 논리명은 표준 판정을 다시 한다.
- **덮어쓰기:**
  - 빠지는 테이블, 남는 테이블에서 빠지는 컬럼, 지워지는 관계 수를 보여 준다.
  - 기존 관계는 모두 지우고 엑셀 참조로 다시 만든다. 두 번 눌러 확인한다.
- **적용:**
  - 새 영역은 등록과 저장을 모두 확인한다.
  - 새 엔터티는 기존 엔터티 아래에 놓고, ‘가져온 테이블 (파일명)’ 보기를 만든다.
  - 재귀 관계는 자식 논리명이 ‘상위…’면 역할명 ‘상위’를 넣는다.
  - 완료 · 감사에는 실제로 만든 관계 수를 쓴다.
- **[가져오기 취소]:** 두 번 눌러 확인한다. 가져온 직후 상태(같은 버전 · 저장 수)일 때만 되고, 다른 편집이 있었으면 막고 이유를 보인다.
- **검사 결과 엑셀:** 원본 시트 · 행 · 열을 그대로 두고 각 데이터 시트 끝에 ‘검사 결과’ 열을, 따로 ‘검사 요약’ 시트를 더한다. 다시 올릴 때 이 열과 시트는 무시한다.
- **접근성:**
  - 탭은 `role=tab` · `aria-selected` · 방향키로 움직인다.
  - 단계를 바꾸면 그 단계 제목으로 포커스를 옮긴다.
  - 관계 체크박스 이름에 부모 → 자식을 넣는다.
  - 파일 오류는 1단계 화면 안 띠로 보인다.
- **남긴 것:** 명명 템플릿 위반 경고(표준 맞추기에서), UNIQUE 참조(양식에 UK 열 없음), 같은 이름 테이블이 여러 영역에 있을 때 영역 고르기 — 구현 단계에서 한다.
