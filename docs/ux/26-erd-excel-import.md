## 1. SWS 템플릿 (기준 양식)
- 시트 **‘테이블 설계’** 한 장 + **‘작성가이드’**. **한 행 = 한 컬럼.** 테이블 정보는 모든 행에 반복한다.
- 14열: **테이블 물리명\*** · 테이블 논리명 · 테이블 설명 · **컬럼 물리명\*** · **컬럼 논리명\*** · **컬럼 타입\*** · 길이 · 소수점 자리수 · PK(Y) · **필수(Y)** · 기본값 · 컬럼 설명 · 참조 테이블 · 참조 컬럼. (\* 필수)
- 예전 18열 양식도 읽는다.
  - 용어는 **‘필수’**로 쓴다: Y = 값이 꼭 있어야 함(DB에서는 NOT NULL), 비우면 필수 아님. SWS 파일의 ‘NOT NULL’ 머리글도 ‘필수’로 읽는다.
  - 예전 ‘NULL 허용 여부’는 의미가 반대(N = 필수)다.
  - 표준용어명 · 영문약어명 · 원천 테이블 · 원천 컬럼 열이 있다.
  - 데이터 시트는 여러 장일 수 있다. ‘인덱스’ 시트는 안내한 뒤 빼고, ‘ERD’ 시트는 건너뛴다.
- 인덱스는 엑셀로 받지 않는다(모델 화면에서 편집).
- 원칙: **원본 이름 · 타입 · 규격 · 참조를 임의로 고치지 않는다.** 업로드는 파일 · 구조 오류만 막고, 표준 · 구조 문제는 가져온 뒤 모델에서 검사한다.

## 2. 업로드 시나리오
| 단계 | 화면 · 동작 |
|---|---|
| ① 진입 | 세 곳에서 들어온다.<br>· 모델 › ⋯ › 가져오기 › **[엑셀 정의서]**(활성화)<br>· 시스템 홈 [+ 업무 영역] 창의 **[엑셀로 만들기]**<br>· 빈 업무 영역 캔버스의 첫 안내 **‘엑셀로 시작’** |
| ② 양식 받기 | **[양식 내려받기]**. 예시 타입은 그 시스템의 데이터타입 매핑을 따른다(PostgreSQL 시스템이면 `VARCHAR(n)`). 작성가이드 시트를 함께 넣는다 |
| ③ 파일 올리기 | `.xlsx`만 받는다. 크기 · 압축 해제 크기 제한(SWS: 100MiB)을 둔다. 끌어 놓기와 [파일 고르기] 둘 다 된다. 읽는 동안 진행 표시 |
| ④ 검사 · 미리보기 | 위에 요약: 테이블 n · 컬럼 n · 관계 n · **오류 n · 경고 n**.<br>탭 3개: **문제**(시트 · 행 · 열 · 내용, 누르면 해당 행 미리보기) / **테이블**(물리명 · 논리명 · 컬럼 수 · PK · 점검) / **관계**(자식.컬럼 → 부모.컬럼 · 만들 관계 유형).<br>**[오류 표시된 엑셀 받기]**: 문제 셀에 색과 메모를 단다.<br>오류가 있으면 [가져오기]는 꺼지고, 경고만 있으면 켜진다 |
| ⑤ 가져올 위치 | **새 업무 영역**(이름) 또는 **기존 업무 영역**.<br>기존 영역일 때 고르는 방식:<br>· **병합(기본)**: 같은 물리명은 갱신, 새 것은 추가, 엑셀에 없는 기존 테이블은 그대로 둔다<br>· **덮어쓰기**: 엑셀 기준으로 바꾼다. 빠지는 테이블 · 관계 목록을 보여 주고 두 번 눌러 확인한다<br>병합 충돌(같은 컬럼의 타입 · PK · 필수가 다름)은 행마다 ‘엑셀 값 / 지금 값’을 고른다 |
| ⑥ 적용 | 대상 영역이 **작업 중**일 때만 된다. 결재 중이면 막고, 확정본이면 “새 작업 버전을 먼저 시작”으로 안내한다.<br>새 영역은 v1 작업 버전으로 만든다. 자동 배치는 관계 기준으로 부모가 위에 오게 한다. ‘가져온 테이블’ 보기를 만들고, 엔터티 · 속성 표준 판정을 바로 계산한다.<br>토스트 ‘테이블 n · 관계 n을 가져왔습니다’ + **[가져오기 취소]**(1회 되돌림). 감사 로그에 남긴다 |
| ⑦ 이어서 작업 | 모델 화면에서 자유롭게 고친다: 테이블 · 컬럼 · **관계 맺기(18)**.<br>그다음 표준 맞추기 → 구조 점검(게이트 A) → 확정 신청 → 결재. 같은 파일을 고쳐 다시 올리면 병합으로 반영한다 |

## 3. 검증 시나리오 — 세 단계
### 3-1. 업로드 단계 — 막는 것(오류)
| 검사 | 메시지 예 |
|---|---|
| 파일을 읽을 수 없음 · 크기 초과 · 데이터 없음 | ‘파일을 읽을 수 없습니다 — .xlsx로 저장해 다시 올리세요’ |
| 필수 열 없음(헤더) | ‘필수 열 ‘컬럼 타입’이 없습니다 — 1행 머리글을 양식대로 두세요’ |
| 테이블 물리명 빈 행(새 양식) · 컬럼 물리명 빈 행 | 시트 · 행 · 열 위치 |
| 같은 테이블 안 컬럼 물리명 중복(대소문자 무시) | ‘EMP_M.DEPT_CD가 두 번 있습니다(12행 · 18행)’ |
| 대소문자만 다른 테이블명 | ‘emp_m과 EMP_M이 겹칩니다’ |
| 같은 테이블의 논리명 · 설명이 행마다 다름 | 처음 값과 다른 행 위치 |
| 참조 테이블 · 참조 컬럼 중 하나만 입력 | ‘참조 테이블과 참조 컬럼을 함께 입력하세요’ |
| 참조 대상이 엑셀에도 대상 영역에도 없음 | ‘참조 테이블 TB_X가 없습니다’ |
| 참조 컬럼이 부모의 PK · UK가 아님 | ‘참조 대상은 PK 또는 UNIQUE 컬럼이어야 합니다’ |
| 참조 컬럼과 타입 계열이 다름 | ‘타입이 맞지 않습니다(VARCHAR / NUMBER)’ |

### 3-2. 업로드 단계 — 알리고 가져오는 것(경고)
- PK가 없는 테이블.
- 길이가 필요한 타입(VARCHAR · CHAR · NUMBER 계열)에 길이가 없음.
- 길이 · 자릿수가 숫자가 아님. 원본 그대로 보존하고 표시한다.
- **이 시스템의 데이터타입 매핑에 없는 타입.** 예: Oracle 시스템에 `TEXT` → 보존하고 표시한다.
- DBMS 이름 길이 · 예약어 위반, 명명 템플릿과 다른 이름.
- 인덱스 시트를 뺌, 예전 양식으로 읽음, 표준용어 열이 있음(참고로만 보존).

### 3-3. 가져온 뒤 — 모델에서 하는 검사(지금 있는 기능)
- **표준 사전 판정**(준수 · 조합 · 미등록) → [표준 맞추기] · 후보 큐.
- **구조 점검(게이트 A)**: FK 누락, PK인데 필수가 아닌 컬럼, M:N 미해소, 관계 잃은 컬럼.
- **확정 신청** 때 전체를 다시 검사하고, 오류가 있으면 결재를 막는다.

## 4. 엑셀 참조 열 → 관계 만들기 규칙 (18과 같은 결과)
| 엑셀 | 만들어지는 관계 |
|---|---|
| 같은 자식 → 같은 부모로 가는 참조 행 여러 개 | **관계 하나(복합 FK, FK 묶음 `g`)** |
| 참조 컬럼이 자식 PK에 들어 있음 | **식별** 관계 |
| 그 밖의 경우 | **비식별** 관계 |
| 자식 FK 컬럼이 필수 | 선택성 ‘반드시 있다’ |
| 자식 FK 컬럼이 필수 아님 | 선택성 ‘없어도 된다’ |
| 자식 FK 컬럼 조합에 UK가 있음(1:1) | 카디널리티 ‘0~1개’ |
| 그 밖의 경우 | 카디널리티 ‘0개 이상’ |
| 같은 테이블 참조 | **재귀** 관계, 역할명은 컬럼 논리명에서 ‘상위’ 같은 말을 쓴다 |
| 같은 두 테이블 사이 두 번째 관계 | 역할명을 컬럼 논리명으로 정한다(출발 · 도착) |
| 부모가 같은 시스템의 다른 업무 영역 테이블 | 미리보기 관계 탭에 **‘○○ 영역 › 부서기본 — 참조로 가져오기 ☑’**(기본 켬). 켜면 참조 엔터티로 넣고 관계를 잇는다. 끄면 FK 컬럼만 남기고 경고한다. 원본 영역에 확정본이 없으면 칸을 끄고 이유를 보인다 |
| (엑셀에 관계명 열 없음) | 관계명은 비워 둔다 — 가져온 뒤 관계 패널에서 명사로 입력 |
| ON DELETE | 기본 ‘막기’ — DB 반영 설정은 모델에서 |

## 5. 지금 ERD의 관계 설정 — 시나리오와 목업 확인 결과
**시나리오:** [18-relation-scenario.md](18-relation-scenario.md) 확정안. 목업은 `model.html`에 반영되어 있다.
- **연결:** 도구 [관계 R] → 부모 클릭 → 자식 클릭으로 바로 만든다. 키보드는 자식 고르기 목록(글자로 거르기 · ↑↓ · Enter).
  - 부모 PK 전체가 자식 FK가 된다. 식별 관계는 손자까지 이어진다(`pkSpread`).
  - 1:1은 UK를 자동으로 붙인다.
  - M:N은 [미리보기 후 해소]로 교차 엔터티를 만든다.
  - 부모에 PK가 없으면 ‘FK 대기’로 둔다.
  - 이름이 겹치면 역할명 팝오버로 정한다(재귀 · 두 번째 관계).
- **관계 패널(오른쪽 420px):** 관계명(명사형) · 유형(식별 전환은 영향 띠 → [적용]) · 카디널리티 · 선택성 · FK 짝 · DB 반영(ON DELETE · FK 이름 · UK, 기본은 접힘).
- **삭제:** 패널 안 띠에서 컬럼 처리 방식을 고른다(남김 / 함께 삭제, 손자 정리). 처음 포커스는 [취소]이고, 실행 취소 한 번으로 모두 돌아온다.
- **연동:** DDL(FK · ON DELETE · UK), 결재 비교(모델 / DB 동작 변경 묶음), 트리 관계 노드.
- 다른 업무 영역 엔터티는 **참조 엔터티**(부모만 됨)로 끌어와 관계를 맺는다.
- **이번 확인에서 보인 점(인사관리 · 부서기본 재귀 관계 패널):**
  - FK 짝이 ‘(없음 — FK 누락)’으로 보이는데, 상태 줄은 ‘FK 반영 · DEPT_M_DEPT_M_FK_G1’로 나온다. 둘이 서로 맞지 않는다. 실제 FK 컬럼 `UP_DEPT_CD`가 짝으로 선택돼 있지 않다.
  - 카디널리티 문장이 ‘부서기본 1개는 부서기본을 …’으로 읽힌다. 재귀 관계는 ‘상위 부서기본 1개는 하위 부서기본을 …’처럼 역할로 써야 한다.
- 남은 일(18 §5): 부모 PK 변경 시 자식 FK 따라가기, 참조 원본 변경 시 다시 맞추기, FK 짝 타입 호환 검사, DBMS별 ON DELETE 차이.

## 6. 정할 것
1. 기존 영역에 올릴 때 기본은 **병합**인가(제안: 병합 기본, 덮어쓰기는 확인 2회)?
2. 업로드 단계에서 **참조 오류(없는 테이블 · PK 아님 · 타입 불일치)를 막을지, 경고로 가져온 뒤 모델에서 고치게 할지**(SWS는 참조 오류를 막는다 — 제안: 막기)?
3. 다른 업무 영역 테이블을 참조하는 행은 **참조 엔터티로 자동 추가**할지, 미리보기에서 고르게 할지?
   - **상황:** 인사관리 영역에 올리는 엑셀의 ‘사원기본’ 행에 참조 테이블 = `DEPT_M`(부서기본)이 적혀 있다. 그런데 부서기본은 이 엑셀에 없고, 같은 시스템의 **조직관리 영역**에 이미 있는 테이블이다.
   - **ERD 규칙(12 §3.2):** 다른 영역의 테이블은 직접 넣지 않고, 읽기 전용 **‘참조 엔터티’**(원본 확정본의 사본)로 끌어와 부모로만 관계를 맺는다.
   - **고를 것:**
     - (가) 가져올 때 부서기본을 참조 엔터티로 **자동으로** 넣고 관계까지 잇는다.
     - (나) 미리보기 관계 탭에 ‘조직관리 › 부서기본 — 참조로 가져오기 ☑’를 보여 주고 **사용자가 고르게** 한다(끄면 관계 없이 FK 컬럼만 남기고 경고).
     - (다) 막는다 — 오류로 보고 엑셀에서 지우게 한다.
   - **결정(2026-11-24): (나) 미리보기에서 선택.** ~~제안 (나):~~ 다른 영역의 확정본을 끌어오는 일이라 사용자가 알고 고르는 편이 안전하다. 원본 영역에 확정본이 없으면 선택 칸을 끄고 이유를 보여 준다(‘조직관리에 확정본이 없어 참조할 수 없습니다’).
4. 엑셀에 **관계명 열**을 추가할지(제안: 이번에는 넣지 않고 모델에서 입력)?
