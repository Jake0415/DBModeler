# 16. 속성 편집 그리드 — 엔터티·컬럼을 한 곳에서 관리

> 2026-11-19 · 상태: **적용** (목업 `model.html` 오른쪽 패널 [속성] 탭)
> 사용자 요청: 엔터티 · 컬럼 추가 · 삭제처럼 사용자가 관리하는 인터페이스를 갖춘다. "편집 그리드부터 진행".

## 1. 왜 필요한가

이전 목업은 속성을 **추가만** 할 수 있었다. 다음이 비어 있었다.

| 빠진 것 | 이전 상태 |
|---|---|
| 속성 삭제 | 입력 중인 새 줄만 Esc로 버릴 수 있음. 저장된 속성은 지울 방법 없음 |
| PK 지정 · 해제 | 관계를 식별 ↔ 비식별로 바꿀 때만 바뀜 |
| 필수(NOT NULL) · 도메인 | 표 보기 일괄 변경으로만. 한 속성을 직접 고치는 칸 없음 |
| 순서 | 없음 |
| 정의 · 기본값 | 없음 |

DA#에서는 엔터티 편집창의 속성 그리드에서 이것을 모두 한다. NeoDB는 창을 따로 띄우지 않고 **오른쪽 패널의 속성 표를 편집 그리드로** 바꾼다. 캔버스에서 엔터티를 고르면 바로 그 자리에서 고친다.

## 2. 화면

```
┌ 차입금기본  LOAN_M ─────────────────────────┐
│ [속성 7] 보안  엔터티  관계                   │
│  상태 PK  속성명 / 물리명      도메인     필수 │
│  ●   ☑  차입번호  BRWG_NO     번호V20 🔒  ☑  │  ← PK는 필수 고정
│  ●   ☐  차입기관명 BRWG_INST_NM 명V100 🔒 ☐  │  ← 표준 용어 → 도메인 고정
│  ●   ☐  이자율  INTRT          [율N5 ▾]  ☐  │  ← 미등록·조합 → 도메인 선택
│ [+ 속성 추가 (Insert)]                        │
│ ┌ 선택한 속성: 차입일자    [↑][↓][이름][삭제] ┐ │
│ │ 물리명 · 타입 · 표준 상태(+ 표준 맞추기/예외) │ │
│ │ 정의  [ 테이블 정의서 · 컬럼 COMMENT ]      │ │
│ │ 기본값 [ DDL DEFAULT ]                     │ │
│ └────────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

- **행 안에서 바로 고치는 것**(자주 쓰는 것): PK · 도메인 · 필수.
- **선택한 행 아래 상세**에서 하는 것: 순서 위/아래, 이름 바꾸기, 삭제, 정의, 기본값, 표준 상태 확인(미등록·조합이면 [표준 맞추기] · [예외로 유지]).
- 패널 폭이 좁으면(380px) [↔]로 560px까지 넓힌다. 표가 좁아도 이름이 잘리지 않게 이름 칸은 두 줄(논리명 / 물리명)로 쓴다.
- [논리] 보기: 속성명 / 물리명. [물리] 보기: 컬럼명 / 논리명 · 타입, 맨 아래에 시스템 컬럼 4개(읽기 전용).

## 3. 규칙 — 무엇을 막고 무엇을 같이 바꾸는가

### 3.1 고정되는 칸 (자물쇠와 툴팁으로 이유를 보인다)

| 칸 | 고정 조건 | 이유 · 대신 할 일 |
|---|---|---|
| PK | FK 속성 | FK의 PK 여부는 **관계 유형**이 정한다 → 관계선을 골라 식별/비식별 전환 |
| 필수 | PK | PK는 항상 필수 |
| 도메인 | FK 속성 | 부모 PK의 도메인을 따른다 |
| 도메인 | 표준 용어(표준 · 용어 신청 중) | 용어가 도메인을 정한다 → 용어를 바꾸거나 예외로 등록 |

### 3.2 다른 엔터티까지 바뀌는 변경

| 변경 | 같이 바뀌는 것 | 확인 |
|---|---|---|
| PK 켜기 | 자식 엔터티마다 FK 속성 추가. 식별 관계면 자식에서도 PK가 되어 손자까지 내려간다. 이름이 겹치면 `원○○`(역할명 확인) | 바로 적용 + 토스트 [실행 취소] |
| PK 끄기 | 이 PK를 받아 간 자식 FK | 자식 FK가 있으면 **패널 안 확인**: [자식 FK도 삭제] [자식 FK는 일반 속성으로] |
| PK 도메인 변경 | 자식 FK의 도메인·타입도 같이 | 바로 적용 |
| PK 삭제 | 자식 FK | 확인: [자식 FK도 삭제] [일반 속성으로]. 마지막 PK면 "식별자 없음이 된다" 경고 |
| FK 삭제 | 그 FK가 속한 관계 | 확인: [속성만 삭제](관계는 남고 **FK 누락**으로 표시) [관계도 삭제](같은 관계의 다른 FK는 일반 속성으로) |
| 일반 속성 삭제 | 없음 | 바로 삭제 + [실행 취소] |

- 영향이 있는 변경만 묻는다. 영향이 없으면 바로 적용하고 실행 취소를 준다(확인 창 남발 방지).
- 확인 띠의 첫 포커스와 왼쪽 위치는 [취소]다. 위험한 버튼은 오른쪽 끝에 둔다. FK 삭제 버튼은 [속성만 삭제 (관계 유지)] · [관계까지 삭제]다.
- 확인 띠는 위치가 아니라 **속성 자체**를 기억한다. 기다리는 동안 순서가 바뀌어도 다른 속성이 지워지지 않는다.
- "일반 속성으로" 남긴 자식 FK는 PK에서도 빠진다.
- FK 컬럼은 받아 온 부모 컬럼(`fkp`)을 기억한다. 공통 FK 판정은 위치가 아니라 이 짝으로 맞춘다. 이름이 겹쳐 역할명(`ORG_`)으로 전파하거나 같은 자식으로 관계가 둘이면 관계 그룹을 만든다.
- 관계의 식별/비식별 전환도 같은 규칙을 쓴다(PK 묶음 이동 · 손자 전파/정리).
- PK 이름을 용어로 바꾸면 자식 FK의 물리명 · 타입 · 도메인이 함께 바뀐다.
- 확인은 대화상자가 아니라 **패널 안 경고 띠**로 띄운다(엔터티 삭제의 영향 확인 · 관계 삭제와 같은 방식). Esc로 취소한다.

### 3.3 순서

- **PK는 PK끼리, 일반 속성은 일반 속성끼리** 순서를 바꾼다. PK는 항상 맨 위다.
- 배열 순서가 곧 캔버스 · DDL `CREATE TABLE` · 테이블 정의서의 컬럼 순서다.
- PK를 켜면 PK 묶음 맨 끝으로, 끄면 일반 속성 맨 앞으로 옮긴다.

### 3.4 이름 바꾸기

이름은 **한 곳에서만** 입력한다: 캔버스의 입력 칸(표준 용어 자동완성). 그리드의 [이름] · F2 · 행 더블클릭은 그 엔터티로 화면을 옮기고 입력 칸을 연다. 용어를 고르면 물리명 · 타입 · 도메인 · 보안 속성이 함께 채워지고, PK · FK · 필수는 그대로 남는다. 이름을 바꾼 뒤 Enter는 다음 속성을 만들지 않는다(새 속성일 때만 이어서 추가).

### 3.5 정의 · 기본값

- 정의 → 테이블 정의서(정의 열), DDL `COMMENT ON COLUMN ... IS '논리명 — 정의'`(작은따옴표는 두 개로).
- 기본값 → DDL `DEFAULT`. 타입에 맞는지 검사한다.
  - 문자 타입: 따옴표 없이 쓰면 붙여 준다.
  - 숫자 타입: 숫자만 받는다.
  - 날짜 타입: SYSDATE · TO_DATE만 받는다.
  - 맞지 않으면 저장하지 않고 이유를 알린다.
- ALTER(확정본 대비) 출력:
  - 새 컬럼: DEFAULT · NOT NULL · 주석
  - 기본값 변경 · 해제: `MODIFY ... DEFAULT`
  - 이름 · 정의 변경: 주석
- 입력 칸을 벗어나거나 Enter(기본값)로 저장한다(패널을 다시 그리지 않아 다음 클릭이 그대로 동작). 비우면 지운다. Esc는 취소다.

### 3.6 권한 · 잠금

편집은 캔버스와 같은 실행 시점 확인(`guard`)을 쓴다: 결재 중 · 확정 · 조회 전용 · 담당 시스템 아님 · 참조 엔터티면 막고 이유를 알린다. 조회 전용이면 체크박스 · 선택 칸은 비활성, [추가] · [↑↓] · [이름] · [삭제]는 숨기고 정의 · 기본값은 글로만 보인다.

## 4. 키보드 · 접근성

| 키 (행에 포커스) | 동작 |
|---|---|
| ↑ ↓ · Home · End | 행 이동(선택이 따라온다. 트리의 속성 줄도 같이 선택) |
| Alt + ↑ ↓ | 순서 바꾸기 |
| Space | PK 켜기/끄기(고정이면 이유를 알림) |
| N | 필수 켜기/끄기 |
| Enter | 상세의 첫 칸(도메인 → 필수 → 정의)으로 |
| F2 | 이름 바꾸기 |
| Delete | 삭제(영향 있으면 확인) |
| Alt+Enter · Insert | 속성 추가 |
| Esc | 확인 띠 취소. 정의 · 기본값 칸에서는 저장된 값으로 되돌림 |

- 표 안에서 Tab 정지점은 하나(선택한 행)다. 행 안 체크박스 · 선택 칸은 마우스로 바로 고친다. 선택한 행의 상세에도 **도메인 선택 · 필수 체크**가 있어 키보드(Tab)로 닿는다.
- 다시 그린 뒤에도 포커스는 같은 행 · 같은 칸으로 돌아온다.
- 순서 이동 · 필수 변경 · 저장은 낭독기 알림(aria-live)으로 알린다. 행 이름에 PK · FK · 표준 상태를 넣는다.
- 모델 화면의 전역 키(Delete = 엔터티 삭제, Enter = 속성 추가)는 포커스가 오른쪽 패널 안이면 동작하지 않는다.

## 6. 검증

- 재무관리 · 차입금기본에서 확인:
  - PK 켜기 → 차입금상환내역에 FK 추가(식별 관계라 PK로).
  - PK 끄기 → 확인 띠 → 자식 FK 삭제.
  - 도메인 변경 → 타입이 NUMBER(18)로.
  - 정의 저장.
  - ↑↓ · Alt+↑↓ · Home.
  - 계좌번호(FK) 삭제 → 관계는 FK 누락으로 남음.
  - 실행 취소 4번으로 모두 되돌림.
- [물리] 보기: 컬럼명 / 논리명 · 타입, 시스템 컬럼 4개.
- 조회 전용(현DA): 편집 칸 0개, 버튼 없음.
