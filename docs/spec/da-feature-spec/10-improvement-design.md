# DA# 기능정의서 — 10. 개선 설계 방향 (1차)

> 상태: **1차 방향 설계**. 화면 설계·구현 계획 아님. 영역별 상세 정의서가 나올 때마다 갱신한다.
> 입력: [00-index.md](00-index.md)(전수 목록·F-xx), [워크스루 v1](../../research/da-modeler-usability-walkthrough-v1.md)(U-xx).
> 기준: **표준화 프로세스를 끊김 없이 완주할 수 있는가**를 1순위로 둔다.

## 1. 진단 요약

DA#는 표준화에 필요한 기능을 **거의 다 갖추고 있다**. 단어 자동 분해, 분해 대안, 명명 템플릿, 준수검사까지 있다. 문제는 기능이 없는 것이 아니라 **흐름이 끊기고, 잘못된 결과가 조용히 통과한다**는 데 있다.

| 구조적 문제 | 증상 (근거) |
|---|---|
| ① 두 프로그램·두 연결 | 사전은 별도 exe, 같은 DB를 표준관리자와 모델러에서 각각 연결 (F-03, U-06). 연결 전 표준 버튼은 이유 없이 비활성 (U-05) |
| ② 검증이 흐름 밖에 있음 | 오분해를 "모든 조건 충족"으로 판정 (F-04), 템플릿 컬럼 밀림을 정합성 체크가 통과 (F-06), 미매핑 물리명·타입 공란 무경고 (F-16, U-03), 불완전 DDL 무경고 (U-01), **준수검사가 테이블명을 안 봄 → 한글 테이블명인데 100%** (F-24) |
| ③ "단어는 있는데 용어가 없음"이 막다른 길 | 동기화는 등록 용어만 매칭 (F-11). 비표준 판정에서 등록으로 이어지는 동선 없음. **엔터티명은 아예 용어로 등록 불가** (F-23) |
| ④ 컨텍스트가 여러 곳 | 분류체계가 리본·조회 패널·용어 등록 탭·모델 설정에 따로 있음 (F-09, F-10, F-26) |
| ⑤ 결과·단계가 안 보임 | 정합성 사유가 잘린 열에만 (F-19), 처리 중 UI 멈춤 (F-20), [적용] 전 숨은 [동기화 설정] 단계 (F-21), 산출 범위 암묵 결정 (F-22), 검토·물리 변환 결과 모호 (U-09, U-18), 전체 준수율 없음 (F-13) |

## 2. 설계 원칙

| # | 원칙 | 해소 대상 |
|---|---|---|
| P1 | **사전은 모델러 안에** — 별도 창·별도 연결 없이 사이드 패널로 조회·등록 | ①, ④ |
| P2 | **검증은 단계마다 자동, 결과는 항상 표시** — 0건이어도 "위반 0건" | ②, ⑤ |
| P3 | **비표준 판정은 곧 등록 동선** — "비표준" 옆에 [용어 등록] [단어 등록 요청] | ③ |
| P4 | **불확실하면 확정하지 않는다** — 미등록 단어가 끼면 자동 분해 결과를 "후보"로만 두고 사람 확인 요구 | ② (F-04) |
| P5 | **하나의 작업 컨텍스트** — 모델 = 분류체계 1개. 화면 상단에 항상 표시, 바꾸면 영향 범위 미리보기 | ④ |
| P6 | **강점은 그대로 계승** — 자동 분해·대안 분해·명명 템플릿·제외 규칙·인텔리센스 (00-index §4.1) | — |

## 3. 목표 프로세스 (To-Be)

```
S0 준비      프로젝트 생성 시 분류체계 1개 지정 (연결 개념 숨김)
   │
S1~S3 사전   [사전 패널] 단어·도메인·용어 조회/등록 · Excel 일괄등록(컬럼 매핑 미리보기 → 검증 → 업로드)
   │            ▲ 미등록 단어 후보 큐 ─────────────┐
S4 모델 적용 속성 입력 즉시 표준 매칭(인텔리센스) · 일괄 "표준 맞추기" (=자동분석+동기화 통합)
   │            · 결과: 표준 / 조합 가능(용어 미등록) / 미등록 단어 포함 / 비대상
   │
[게이트 A]   물리 변환 전 점검: 미매핑 N건, 도메인 미지정 N건 → 해결 또는 예외 승인
   │
S5 물리      명명 템플릿 + 표준 물리명 → 테이블·컬럼·제약·인덱스명, 도메인 → 타입
   │
[게이트 B]   DDL 전 점검: 타입 누락·예약어·FK 누락·이름 길이 → 차단/경고
   │
S6 산출      준수율 대시보드(모델 전체 %·엔터티별) · DDL · 정의서
```

**핵심 변경**: As-Is의 "용어 자동분석"(마법사 4단계)과 "속성 표준 동기화"(별도 대화상자)를 **하나의 "표준 맞추기" 작업**으로 합치고, 결과를 4가지 상태로 나눈다.

| 상태 | 의미 | 사용자 동작 |
|---|---|---|
| 🟢 표준 | 등록 용어와 일치 | 없음 (자동 적용) |
| 🟡 조합 가능 | 모든 단어가 등록됨, 용어만 미등록 (예: 제출일자) | [용어로 등록] 한 번 클릭 → 물리명·도메인 제안 확인 |
| 🔴 미등록 단어 포함 | 사전에 없는 단어가 있음 (예: 산출물) | 분해 결과를 확정하지 않음. [단어 등록 요청] → 후보 큐 |
| ⚪ 비대상 | 제외 규칙(Pseudo·System 등) | 없음 |

## 4. 영역별 개선 방향

### 4.1 표준 사전 (S0~S3) — 우선순위 최상

| As-Is 기능 | 문제 | 개선 방향 | 근거 |
|---|---|---|---|
| W-01 DB 연결 / M-D01 A/R 연결 | 두 번 연결, 크래시, 경로 입력 불가 | 서버 측 사전으로 일원화 — 사용자는 연결 개념을 보지 않음 | F-01, F-02, F-03 |
| W-02 / M-D04 분류체계 | 컨텍스트 3곳, 체크박스인데 단일 선택 | 모델(프로젝트) 속성으로 1개 지정, 상단 고정 표시. 변경 시 영향 미리보기 | F-09, F-10 |
| W-03 표준 데이터 관리 | 빈 검색 0건 무응답, 검색어 이어 붙음 | 빈 검색 = 전체 목록(페이지), 결과 건수 항상 표시, 즉시 검색 | F-08 |
| W-05~W-07 단어·도메인·용어 등록 | 등록이 별도 화면 | 사전 패널 안에서 인라인 등록. 용어 등록은 자동 분해·대안 분해 계승 | U-06 |
| W-07 용어 자동 분해 | 미등록 단어를 아무 단어로 쪼갬(산출물→산출+물), 도메인 추천 부정확 | (1) 최장일치 후 **잔여 음절이 1글자 단어로만 매칭되면 "미등록 의심"** 표시 (2) 도메인은 **마지막 단어(분류어) 기준**으로 추천하고 근거 표시 (3) 확정 전 사람 확인 | F-04, F-05 |
| W-08~W-10 일괄등록 | 템플릿 2종 혼재로 컬럼 밀림, 사유가 잘린 열에만, 처리 중 멈춤, 기존과 같은 값도 오류 표시 | **헤더 기반 컬럼 매핑 + 미리보기** (위치 기반 금지), 필수 컬럼 누락 시 차단, 결과를 **신규/동일(건너뜀)/충돌** 3분류, 충돌은 기존값 비교+대안 물리명 제안, 비동기+진행률, 템플릿은 앱에서 내려받기(버전 일치) | F-06, F-19, F-20, F-25, F-27 |
| W-05/W-08 단어 중복 검사 | 복합어가 기존 단어 조합과 겹쳐도 통과 (`요구사항=RQRM` vs `요구+사항=DEMND_MATER`) | 새 단어가 기존 단어 조합으로 표현 가능하면 경고 + 기존 표기 제시 | F-29 |
| W-07 용어 등록 | 도메인 필수 → 엔터티명 등록 불가 | 용어 유형 분리: **속성 용어**(도메인 필수) / **엔터티 용어**(도메인 없음, 분류어 접미 규칙 예: 기본→`_M`) | F-23 |
| W-11~W-15 설정 | 대부분 OK | 데이터타입·축약형·타입변환을 한 화면(DBMS 탭)으로 | — |
| (신규) 후보 큐 | 없음 | 모델링 중 나온 미등록 단어·용어를 **후보 큐**로 모으고, 표준 관리자가 승인/반려 — 기존 docuCBD 공통표준 사전의 후보 큐 재사용 | F-04, F-11 |

### 4.5 일반 모델링 (표준화 외)

워크스루 U-11~U-22 방향을 유지한다 — 관계 2단계 생성+미리보기, 자동 크기 맞춤 일관화, 엔터티 회피 라우팅, 모달 대신 속성 패널, 탭 전환 확인창 제거. 3차([02-logical.md](02-logical.md))에서 추가된 방향:

| As-Is 기능 | 문제 | 개선 방향 | 근거 |
|---|---|---|---|
| 속성 인텔리센스 | 팝업이 열 폭이라 판독 불가 | 별도 자동완성 드롭다운(용어·도메인·타입 함께) — 표준 맞추기의 입력 단계 버전 | F-30 |
| M:M 해소 | 교차 엔터티 `RelationN`, 비식별 FK | 미리보기에서 이름(표준 용어 제안)·식별 여부 확정 | F-31 |
| 서브타입 | 구분 속성=PK, 레이아웃 겹침 | 구분 속성 선택/생성, 자동 레이아웃, 물리 변환 전략 속성화 | F-32, F-35 |
| 키 표시 | AK 미표시 | PK·AK·FK 표시 규칙 통일 | F-33 |
| 편집창 | 다른 모니터에 열림, Escape=취소 후 닫기 | 비모달 우측 패널(창 위치 문제 자체를 없앰) | F-36 |
| FK 상속 | 이름 충돌 자동 개명이 로그에만 | 충돌·역할명은 상속 시 확인 | F-37 |
