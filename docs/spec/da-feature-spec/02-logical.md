# DA# 기능정의서 — 02. 논리 모델 상세 (3차)

> 상태: **3차 — 논리 모델 상세 정의**. 엔터티·속성·식별자·관계·서브타입·표준대상·정보보호를 실제로 조작해 확인했다.
> 상위: [00-index.md](00-index.md) · [04-standard.md](04-standard.md) · [10-improvement-design.md](10-improvement-design.md).
> 실습: 2차까지 표준을 적용한 샘플 모델 **사본**. 테스트용 엔터티 `엔터티1`(식별 관계 자식)과 M:M 해소 교차 엔터티를 추가했다.

## 0. 수행 요약

| 항목 | 한 일 | 결과 |
|---|---|---|
| 엔터티 속성 | 편집창 엔터티 탭 전 항목, 분류·단계·유형·표준화 드롭다운 | 확인. 분류=Main 지정 시 단계가 자동으로 바뀌고 `Level` 행이 끼어듦 |
| 속성·인텔리센스 | 새 행에 "요구" 입력 | 용어 제안 팝업 동작 — **폭이 열 폭(약 3글자)이라 읽을 수 없음** (F-30). 고른 결과가 기존 속성과 중복 → 중복 경고 |
| 식별자 | 대체키(AK) 그룹 추가, 속성 지정 | 성공. 다이어그램에 AK 표시 없음 (F-33) |
| 식별 관계 | 1:M Identify로 산출물기본 → 엔터티1 | 자식 PK에 `# 산출물ID (FK)` 상속. 부모에 AK가 있으면 **어느 키를 상속할지 묻는 창**(역할명 지정 가능) |
| M:M 해소 | M:M 관계 생성 → 우클릭 "M:M 관계 해소" | 교차 엔터티 자동 생성 — **이름이 관계명 `Relation1`, 두 FK 모두 비식별(`*`)이라 PK 없음** (F-31) |
| 배타 관계 | 배타관계 도구로 클릭·드래그 시도 | 사용법을 찾지 못함 — 툴팁은 "새로운 배타적관계선을 추가합니다"뿐 (F-34). 📖 |
| 서브타입 | 엔터티 편집 → 서브타입 → 서브타입셋 편집 | 생성 성공. **구분 속성 기본값이 PK** (F-32), 하위 박스가 겹치고 캔버스 밖으로 나감 (F-35) |
| 표준대상 편집 | 데이터 ▸ 표준대상 편집 | 조건 일괄 지정 화면 확인 |
| 정보보호 편집 | 데이터 ▸ 정보보호 편집 | 속성별 개인정보·암호화 지정 화면 확인 |

**환경 메모**: 듀얼 모니터에서 편집창이 메인 창과 **다른 모니터**에 뜨는 일이 반복됐다(창 좌표 확인으로 확인). 사용자는 "더블클릭해도 편집창이 안 열린다"로 느낀다 (F-36). 메인 창을 편집창이 뜨는 모니터로 옮긴 뒤 진행했다.

## 1. 기능 정의

형식은 04와 같다. ID는 `LG-xx`.

### LG-01 엔터티 생성·편집 (M-H03, M-E01) ★★ (S4)

| 항목 | 내용 |
|---|---|
| 생성 | 엔터티 도구 → 캔버스 클릭. 이름 기본값 `엔터티N` |
| 편집창 탭 | 엔터티 / 속성 / 관계 / 식별자그룹. 하단 탭: 정의·데이터 처리 형태·특이사항·노트·UDP. 상단 콤보로 다른 엔터티로 이동, AutoSave 옵션 |
| 엔터티 탭 항목 | **편집**: 엔터티명·테이블명·동의어·보조명·연계정보·DB Owner / **설정**: 분류·(Level)·단계·유형·소속·표준화·약어·태그 / **공유**: 공유·원천 엔터티·공유/연계 참조중 / **기타**: 상태·발생주기·월간발생량·보존기한(월)·총건수 |
| 분류 | (없음) / Key / Main / Action → 다이어그램 배지 K·M·A |
| 단계 | 본질적 / 실용적. **분류 선택 시 단계가 자동 변경**되고 Level 행이 추가됨(안내 없음) |
| 유형 | Normal / Pseudo / Additional / External / Drop (표준 제외 규칙과 연결, ST-12) |
| 표준화 | 상속 / 대상 / 비대상 |
| As-Is 문제 | 탭 전환마다 저장 확인 (U-16), Escape = 변경 취소 후 닫기(확인 없이 편집 내용 손실), 편집창 위치 (F-36) |
| To-Be | 우측 속성 패널(비모달), 분류·단계 연동 규칙은 화면에 안내, 볼륨 정보(발생주기 등)는 물리 설계 입력으로 연결 |

### LG-02 속성 편집 (M-E01 속성 탭) ★★★ (S4)

| 항목 | 내용 |
|---|---|
| 그리드 | 속성명·컬럼명·실질식별자·NotNull·유형·데이터타입·길이·소수점·기본값 (+항목설정으로 열 추가) |
| 속성 상세 | FK·UK·비고·보조명·동의어·핵심·본질식별자·보조식별자·표준동기화·비상속·Inclusive·표준화·도메인·리버스정보 / **정보보호**: 개인정보여부·구분·보호등급·암호화여부·방법·데이터오너 |
| 버튼 | 서브타입·추가·삭제·위로·아래로·항목설정·표준 정보 |
| 검증 (확인됨) | 같은 엔터티 내 속성명 중복 → "속성명의 중복이 발생되었습니다. 수정하시겠습니까?" |
| 인텔리센스 | 속성명 입력 중 용어 제안 팝업(옵션 ▸ 편집 ▸ 기본). 선택 시 표준 용어로 채워짐 |
| 자동 처리 | 관계로 FK가 들어오며 이름이 겹치면 `요구사항ID2`로 **자동 개명** — 출력 로그에만 기록 (F-37) |
| As-Is 문제 | 속성명 열 폭 극히 좁음 (U-17) → 인텔리센스 팝업도 그 폭이라 판독 불가 (F-30). 삭제 버튼이 선택 행에 반응 안 한 경우 있음 |
| To-Be | 내용 기준 열 폭, 인텔리센스는 별도 드롭다운(용어·도메인·타입 함께 표시), 자동 개명은 확인 받기 |

### LG-03 식별자·키 (M-E01 식별자그룹 탭) ★★ (S5)

| 항목 | 내용 |
|---|---|
| 구성 | 주키(PrimaryKey, Unique) / 대체키(추가·편집·삭제, Unique 여부). 오른쪽에 식별자 구성 ↔ 속성 구성 (본질·실질 표시, ▲▼로 이동) |
| 식별자 종류 | 실질식별자(그리드 체크) · 본질식별자 · 보조식별자(속성 상세) |
| 식별 관계 상속 | 자식 PK로 FK 상속(`#`). 부모에 AK가 있으면 **식별자그룹 선택 창**에서 PK/AK와 **역할명(Rolename)** 지정 |
| As-Is 문제 | AK가 다이어그램에 표시되지 않음 (F-33). 대체키 이름 입력이 별도 팝업 |
| To-Be | 다이어그램에 PK·AK·FK 표시 규칙 통일, 키 이름은 명명 템플릿에서 자동 |

### LG-04 관계 생성·편집 (M-H05, M-E02, M-C03) ★ (—)

| 항목 | 내용 |
|---|---|
| 유형 | 1:M Optional / Mandatory / Identify · M:M · 1:1 Mandatory / Identify · 1:M Pseudo |
| 생성 | 도구 선택 → 부모에서 자식으로 **드래그**. 같은 엔터티 클릭 = 재귀 (U-11) |
| 편집창 | 관계명·유형·타입·식별자 사용·비상속 처리·부모/자식(엔터티·관계동사·필수) + 식별자정보·정의·특이사항·노트·UDP |
| 우클릭 | 편집 / 삭제 / 삭제(관계선 only) / 관계선 참조확인 / 관계선 유형 / 관계선 숨기기 / **M:M 관계 해소**(M:M일 때) / 관계선 정리 / 관계명 가로·세로 / 객체 정보 |
| 표기 | 식별=실선, 비식별=점선, M:M 이름 기본값 `RelationN` |
| As-Is 문제 | 관계선이 얇아 우클릭이 캔버스 메뉴로 빠짐. 트리의 관계 노드에는 우클릭 메뉴 없음 |
| To-Be | 관계선 히트 영역 확대, 트리·캔버스 메뉴 동일 |

### LG-05 M:M 관계 해소 ★ (—)

| 항목 | 내용 |
|---|---|
| 처리 | M:M 관계 우클릭 → 해소 → 교차 엔터티 + 1:M 관계 2개 생성 |
| 실측 | 교차 엔터티명 = 관계명(`Relation1`), FK 2개가 **비식별**(`* 산출물ID (FK)`, `* 사원번호 (FK)`) → PK 없음 |
| As-Is 문제 | F-31. 교차 엔터티는 보통 두 FK를 합친 PK(식별 관계)가 기본인데 반대로 만들어짐 |
| To-Be | 해소 시 미리보기: 교차 엔터티명(표준 용어 제안 `A+B+관계`), 식별/비식별 선택(기본 식별) |

### LG-06 배타 관계 (M-H06) ★ (—) 📖

툴팁 외 안내 없음. 클릭·드래그로 생성 방법을 찾지 못했다(F-34). 도움말 목차 "배타 관계" 기준으로 다음 차수에 재확인.

### LG-07 서브타입 (M-E01 ▸ 서브타입) ★★ (S5)

| 항목 | 내용 |
|---|---|
| 서브타입셋 편집 | 구분속성 이름·Inclusive·Set Hide·설명 + 서브타입 그리드(서브타입명·테이블명·보조명·구분값·감추기), +/-/▲/▼ |
| 표기 | 슈퍼타입 박스 안에 중첩 박스 (구분 속성명 표시) |
| 관련 기능 📖 | 서브타입 감추기·나타내기·분리, Transforms(슈퍼 통합 / 서브 분할 / 각각 분할) |
| As-Is 문제 | 구분 속성 기본값이 PK (F-32), 중첩 박스가 겹치고 캔버스 밖으로 확장 (F-35) |
| To-Be | 구분 속성은 "구분코드" 속성 선택(없으면 생성 제안), 서브타입 레이아웃 자동, 물리 변환 전략(통합/분할)을 서브타입셋 속성으로 |

### LG-08 표준대상 편집 (M-D07) ★★ (S4)

| 항목 | 내용 |
|---|---|
| 영역 | 논리(대상) / Target DB(ORACLE) / 물리(대상) |
| 일괄 편집 | 엔터티 선택 · 속성 선택(엔터티·서브타입 포함·속성·포함 이름·데이터타입·길이 → 변경값 상속/대상/비대상 [적용]) · 테이블 선택 · 컬럼 선택 |
| 자동 설정 | 논리/물리 표준설정, 물리 표준설정, 삭제용어 비대상설정, 물리 비대상설정 (속성/컬럼 재설정 링크) |
| 결과 | 엔터티·테이블별 상태와 상/대/비 건수 트리 |
| As-Is 문제 | 열 때 선택된 엔터티만 대상(범위 암묵, F-22와 같은 패턴) |
| To-Be | 표준 제외 규칙(ST-12)과 한 화면, 범위 명시 |

### LG-09 정보보호 편집 (M-D08) ★★ (S4)

| 항목 | 내용 |
|---|---|
| 화면 | 왼쪽 엔터티 목록(필터) + 대상 편집 그리드: 엔터티·속성·컬럼·용어 정보·도메인 정보·개인정보여부·개인정보구분·정보보호등급·암호화여부·암호화방법·데이터오너 |
| 기능 | 정보보호 동기화(도메인의 보안 속성 → 속성), 정보보호 제거, 검색 |
| As-Is 문제 | 엔터티 목록에 서브타입·코드값이 엔터티처럼 섞임 (F-12 재확인) |
| To-Be | 도메인 보안 속성(사전, 04 §1) 상속을 기본으로, 예외만 속성에서 지정. 개인정보 대상 목록 리포트 |

## 2. 이번 차수 신규 문제 (F-30~F-37)

| ID | 심각도 | 문제 | 근거 |
|---|---|---|---|
| F-30 | 중 | 인텔리센스 팝업 폭 = 속성명 열 폭(약 3글자) → 제안 내용 판독 불가 | 속성 탭에서 "요구" 입력 |
| F-31 | 중 | M:M 해소 교차 엔터티가 관계명(`Relation1`)으로 생성, FK가 비식별이라 PK 없음 | M:M 해소 결과 |
| F-32 | 중 | 서브타입 구분 속성 기본값이 PK | 서브타입셋 편집 |
| F-33 | 하 | 대체키(AK)가 다이어그램에 표시되지 않음 | AK 추가 후 다이어그램 |
| F-34 | 중 | 배타 관계 도구 사용법 발견 불가 | 클릭·드래그 모두 무반응, 툴팁만 |
| F-35 | 하 | 서브타입 중첩 박스가 겹치고 캔버스 밖으로 확장, 자동 스크롤 없음 | 서브타입 2개 추가 |
| F-36 | 중 | 듀얼 모니터에서 편집창이 메인 창과 다른 모니터에 열림 → "편집창이 안 열린다"로 인식 | 창 좌표로 확인 |
| F-37 | 하 | FK 이름 충돌 시 자동 개명(`요구사항ID2`)이 출력 로그에만 기록 | 출력 패널 |

**재확인**: U-16(탭 전환 저장 확인), U-17(속성명 열 폭), F-12(코드값이 엔터티 목록에 섞임), F-22(선택 기준 암묵 범위)가 이번 화면들에서도 반복됐다.

## 3. 웹 버전 기능 요구사항 (논리 모델, 1차안)

| ID | 요구사항 | 대응 | 우선 |
|---|---|---|---|
| LG-R01 | 엔터티·속성 편집은 우측 비모달 패널. 탭 전환 시 확인창 없음, Escape는 편집 취소만(닫기 아님) | U-16, F-36 | P0 |
