# DA# 기능정의서 — 04. 표준 영역 상세 (2차)

> 상태: **2차 — 표준 영역 상세 정의**. 표준화 프로세스 S0~S6을 실제 데이터로 끝까지 수행하고 기능 단위로 정리했다.
> 상위: [00-index.md](00-index.md)(전수 목록) · [10-improvement-design.md](10-improvement-design.md)(개선 방향).
> 실습: 샘플 모델 `drm03/모델링실습1_요구사항관리시스템_논리모델.damx` + 표준사전 `wordict5_참조모델표준화.db` (**모두 사본**, 원본 무변경).

## 0. 수행 요약

| 단계 | 한 일 | 결과 |
|---|---|---|
| S0 준비 | 표준관리자·모델러 각각 SQLite 사전 연결, 분류체계 "요구사항관리시스템" 지정 | 성공 (긴 경로는 크래시 → 짧은 경로로 우회, F-01) |
| S1 단어 | 45개 일괄등록 → 정합성 체크 → 업로드. 이후 `산출물` 1개 단건 등록 | **5개만 통과**(나머지 기존 단어와 중복). 단건 등록 성공 |
| S2 도메인 | 동봉 템플릿을 **현행 양식으로 다시 만들어** 16개 일괄등록 | 15개 기존 중복, **신규 `산출물유형코드` 1개 등록** |
| S3 용어 | 37개 일괄등록 → 분석 → 정합성 → 업로드 | 33개 기존 중복, **신규 4개 등록**. 단, `산출물` 단어 등록 전에는 `PRDC_WTR_ID`로 오분해된 채 통과 (F-04) |
| S4 모델 적용 | 산출물기본 속성 표준 동기화 → **동기화 설정 → 적용** | 속성 5개 표준 일치. 엔터티(테이블명)는 표준화 **불가** (F-23) |
| S5 물리 | 기존 물리 모델에 자동 반영 확인 | 컬럼 `DLVRBL_ID VARCHAR2(10)` 등으로 갱신. 테이블명은 `산출물기본` 그대로 |
| S6 검증·산출 | 준수검사, DDL 생성 | 준수도 **전 엔터티 100%** — 한글 테이블명은 검사 대상 아님 (F-24). DDL 컬럼은 유효해짐 |

**Before / After (같은 테이블 DDL)**

```sql
-- 표준 적용 전 (1차 워크스루)          -- 표준 적용 후 (2차)
CREATE TABLE 산출물기본 (                CREATE TABLE 산출물기본 (
    산출물ID NOT NULL,                       DLVRBL_ID      VARCHAR2(10) NOT NULL,
    산출물명,                                DLVRBL_NM      VARCHAR2(100),
    산출물유형코드,                          DLVRBL_TYPE_CD CHAR(2),
    제출일자,                                SBMT_DATE      CHAR(8),
    DEMND_MATER_ID VARCHAR2(10) NOT NULL     DEMND_MATER_ID VARCHAR2(10) NOT NULL
);                                       );
```

컬럼은 표준화됐지만 **테이블명·PK명(`산출물기본_PK`)은 한글로 남는다.**

## 1. 표준 사전 데이터 모델 (As-Is)

표준관리자가 쓰는 SQLite 사전의 스키마를 읽기 전용으로 확인했다. 웹 버전의 표준 사전 설계 시 비교 기준이 된다.

| 테이블 | 역할 | 주요 컬럼 | 비고 |
|---|---|---|---|
| `STD_AREA` | 표준분류체계 | ID·이름·상위ID, **사용 여부 플래그**(용어·도메인·조합·단어·코드·코드도메인매핑) | 분류체계마다 쓰는 사전 요소를 켜고 끔. 계층 가능 |
| `STD_DIC` | **단어와 용어를 한 테이블에** | 논리명·물리명·영문풀네임·한자·설명, `DIC_GBN_CD`(단어/용어 구분), `ENT_CLSS_YN`/`ATTR_CLSS_YN`(분류어), `STANDARD_YN`, **`FORBID_YN`(금칙어)**, `DOM_ID`, 타입·길이, `USE_END_DT`·사유, 소유자 | 금칙어·폐기 개념이 데이터에는 있으나 화면에서 확인 못 함 |
| `STD_WORD_COMBI` | 용어 → 단어 구성 | 용어ID·순번·단어ID | 용어 분해 결과 저장 |
| `STD_DOM` | 도메인 | 대표도메인명·도메인명·유형·타입·길이·소수점·그룹·최소/최대·포맷·열거값·기본값, 개인정보·암호화·보안등급 | 보안 속성이 도메인에 붙음 |
| `STD_DOM_GRP` | 도메인 그룹 | | |
| `STD_DATATYPE` / `STD_DATATYPE_CONV` | DBMS별 타입 / 타입 변환 규칙 | DB종류·타입·길이사용, 조건식 | |
| `STD_DIC_REL` | 사전 항목 간 관계 | 부모·자식·관계구분 | 동의어 등 |
| `STD_CODE` | 코드값 | 코드영역·코드·명·영문명·도메인 | 코드 도메인과 연결 |
| (공통) | **유효기간** `AVAL_ST_DT`/`AVAL_END_DT`가 PK에 포함 | | 변경 이력을 행 단위로 보존하는 구조 |

**시사점**: 단어·용어 통합 테이블, 유효기간 이력, 금칙어, 분류체계별 기능 플래그, 도메인 보안 속성은 웹 사전에서도 필요한 개념이다. docuCBD 공통표준 사전과 비교할 때 이 목록을 체크리스트로 쓴다 (10-improvement-design Q-1).

## 2. 기능 정의

형식: **입력 → 처리 → 출력 / 검증 규칙 / As-Is 문제 / To-Be 요구사항**. ID는 `ST-xx`. 00-index의 메뉴 ID를 함께 적는다.

### ST-01 표준 사전 연결 (W-01, M-D01) — S0 ★★★

| 항목 | 내용 |
|---|---|
| 입력 | DB 종류(ORACLE·POSTGRESQL·TIBERO·SQLITE), 접속정보(SQLite는 파일경로 — "…" 선택만 가능) |
| 처리 | 테스트 → 접속. 표준관리자와 모델러가 **각자** 연결 |
| 출력 | 상태 "성공/실패", 출력 패널 로그. 모델러는 연결 후 데이터 탭 표준 버튼 활성 |
| 검증 규칙 | 경로 미입력 시 "올바른 접속 정보를 입력해주십시오" |
| As-Is 문제 | 두 번 연결 (F-03), 긴 경로 크래시 (F-01), 직접 입력 불가·Enter로 닫힘 (F-02), 연결 설정 미보존 |
| To-Be | 서버 측 사전 하나. 사용자에게 "연결" 단계 없음. 관리자만 사전 소스 설정 |

### ST-02 표준분류체계 (W-02, W-11, M-D04) — S0 ★★★

| 항목 | 내용 |
|---|---|
| 입력 | 분류체계 등록(명·설명), 작업 대상 분류 선택, 모델에 적용할 분류 선택 |
| 처리 | 표준관리자: 리본 콤보 = 등록 대상, 조회 패널 콤보 = 조회 대상, 용어 등록 탭 콤보 = 분해 대상. 모델러: 모델당 1개 |
| 출력 | 모델러 변경 시 "기존 분류체계가 변경됩니다" 확인 |
| As-Is 문제 | **컨텍스트 3곳이 따로 움직임** (F-09) — 이번에도 용어 등록 탭이 다른 분류로 분해해 재작업. 체크박스 UI인데 단일 선택 (F-10). 마우스 선택이 반영 안 되는 경우 있어 키보드로 우회 |
| To-Be | 프로젝트(모델)에 분류 1개 고정, 모든 화면 상단에 표시. 다른 분류 조회는 "참조 보기"로만 |

### ST-03 표준 데이터 조회 (W-03) — S1~S3 ★★★

| 항목 | 내용 |
|---|---|
| 입력 | 분류, 검색어(접두 일치), 대상(단어·도메인·용어), 분류어 필터, 도메인 유형, 데이터 타입, 계층조회 |
| 출력 | 목록(구분·논리명·물리명·도메인·타입·길이) + 상세(논리·물리·영문풀네임·한자·동의어·분류어·표준단어여부·설명) + 연관 용어. 로그에 "N건이 검색되었습니다" |
| As-Is 문제 | **빈 검색어 = 0건, 메시지 없음** (F-08) — 이 때문에 1차 조사에서 분류체계가 "비어 있다"고 잘못 판단했다(실제로는 단어·용어가 이미 있음) |
| To-Be | 빈 검색 = 전체(페이지네이션), 건수 화면 표시, 입력 즉시 필터 |

### ST-04 단어 등록 · 일괄등록 (W-05, W-08) — S1 ★★★

| 항목 | 내용 |
|---|---|
| 입력(단건) | 논리명·물리명(필수)·영문풀네임·한자·동의어(쉼표)·분류어(엔터티/속성)·설명. **중복확인 후에만 등록 활성** |
| 입력(일괄) | Excel: 논리명·물리명·영문풀네임·한자·엔터티분류·속성분류·동의어·설명 (위치 기반 매핑, `UploadForm/WordList.xls`와 같은 순서) |
| 처리 | 불러오기 → 정합성 체크 → (통과 행만 체크 유지) → 업로드 |
| 출력 | 행별 **사유** + **상태(Y/N)**, "N건이 등록되었습니다" |
| 검증 규칙 (확인됨) | `단어중복`(논리·물리 모두 기존과 같음) · `단어물리명중복`(물리명이 다른 단어에서 사용 중) · `단어논리명중복`(논리명은 있는데 물리명이 다름) |
| 실측 | 45개 중 통과 5 (대안·발주처·요구사항·팀원·일시). 물리명 중복 예: 상위 UPR, 우선 PRIOR, 종료 END, 산출물 DLVR, 년도 YR, 비율 RT |
| As-Is 문제 | 사유가 맨 오른쪽 좁은 열에 잘려 보이고 툴팁 없음 (F-19). 기존과 같은 단어(=재등록 불필요)도 오류처럼 표시 (F-27). 물리명 중복 시 대안 제시 없음. **복합어 중복 미검출**: `요구사항=RQRM`이 통과했지만 사전에는 이미 `요구`+`사항`=`DEMND_MATER`가 있어 같은 개념의 두 표기가 공존하게 됨 (F-29) |
| To-Be | 결과를 신규/동일(건너뜀)/충돌로 3분류. 충돌은 기존 값과 나란히 비교 + 대안 물리명 제안. 복합어가 기존 단어 조합으로 표현 가능하면 경고 |

### ST-05 도메인 등록 · 일괄등록 (W-06, W-09, W-12) — S2 ★★★

| 항목 | 내용 |
|---|---|
| 입력(단건) | 대표도메인·도메인명(중복확인)·도메인명 자동생성·유형·그룹·논리 타입·길이·소수점·범위·포맷·설명 |
| 입력(일괄) | Excel: 대표도메인명·도메인명·유형·**그룹**·논리타입·길이·소수점·최소·최대·포맷·설명. "도메인 그룹 자동 생성" 옵션 |
| 검증 규칙 | 도메인 중복(기존 도메인과 같음) |
| 실측 | 현행 양식으로 다시 만든 16개 중 신규 `산출물유형코드`만 통과·등록 |
| As-Is 문제 | **동봉 템플릿이 두 종류이고 서로 다름** — `drm03/…도메인일괄등록시스템.xlsx`(구형, 그룹 열 없음, 유형이 코드값 `0003`) vs `UploadForm/DomainList.xls`(현행, 그룹 열 있음). 구형을 넣으면 값이 한 칸씩 밀리고 정합성 체크도 통과 (F-06, F-25). 성공 메시지에 경고 아이콘 (F-28) |
| To-Be | 헤더명 기반 매핑 + 매핑 미리보기, 필수 열 누락 시 차단, 템플릿은 앱에서 현재 버전으로 내려받기 |

### ST-06 용어 등록 (자동 분해) (W-07) — S3 ★★★

| 항목 | 내용 |
|---|---|
| 입력 | 분류(탭 자체 콤보), 용어 논리명, 구분자(기본 `_`) |
| 처리 | 등록 단어로 분해 → 구성정보(`제출+일자(SBMT+DATE)`)·논리/물리 용어명·도메인 후보 → 적용 |
| 검증 규칙 (확인됨) | **도메인 필수** — 없으면 "용어에 맵핑된 도메인이 없습니다" |
| 실측 | `제출일자`→`SBMT_DATE`(도메인 후보 "등록일자"), `산출물ID`→단어 미등록 시 `PRDC_WTR_ID`, 등록 후 `DLVRBL_ID`. `산출물기본`→`DLVRBL_BASIC`이지만 도메인이 없어 **등록 불가** |
| As-Is 문제 | 미등록 단어를 아무 단어로 분해 (F-04). 도메인 후보 부정확 (F-05). 검색창이 기존 텍스트를 대체하지 않음, 한 번 꼬이면 입력이 안 먹어 탭을 닫고 다시 열어야 함 (F-26). **엔터티명처럼 도메인이 없는 용어를 등록할 길이 없음** (F-23) |
| To-Be | 4상태 분해 결과(표준/조합 가능/미등록 포함/비대상), 미등록 단어는 후보 큐. 용어 유형을 "속성 용어(도메인 필수)"와 "엔터티 용어(도메인 없음)"로 나눔 |

### ST-07 용어 일괄등록 (W-10) — S3 ★★★

| 항목 | 내용 |
|---|---|
| 입력 | Excel: 용어명·용어설명·도메인명 (+선택: 논리타입·길이·소수점·물리용어명) |
| 처리 | 불러오기 → **분석**(분해·물리명 생성) → 정합성 체크 → 업로드 |

| 실측 | 37개 중 33개 중복, 신규 4개 등록. 기존 용어는 사전의 물리명을 그대로 반환(예: 리스크대안내용 `RISK_LARGE_PRPS_TEXT`) |

### ST-09 속성 표준 동기화 (M-D05) — S4 ★★★

| 항목 | 내용 |
|---|---|
| 입력 | 대상 엔터티(왼쪽 목록 체크), 동기화 대상 필터, 대소문자 표시 |
| 처리 | 속성 논리명 ↔ 등록 용어 매칭 → **[동기화 설정]으로 표준값을 결과 행에 올림** → **[적용]으로 모델에 반영** |
| 출력 | 행별 상태: `비`(비표준·용어 없음) / `불`(불일치·용어는 있으나 모델 값이 다름) / `일`(일치) + 표준 용어 논리·물리명·타입·도메인 |
| 실측 | 분류가 맞으면 5개 모두 `불` → 설정 → `일` → 적용 → 물리 컬럼까지 갱신, 모델 도메인 목록에 `산출물유형코드` 추가 |
| As-Is 문제 | **[적용]만 누르면 아무 일도 없고 경고도 없음** — 설정 단계가 숨어 있음 (F-21). 단어로 조합 가능해도 용어 미등록이면 `비` (F-11). 코드값이 엔터티처럼 목록에 나옴 (F-12). 적용 후 결과 요약 없음 |
| To-Be | 한 번의 "표준 맞추기"로 미리보기 → 확정. 상태별 일괄 처리, 적용 후 "N개 반영" 요약 |

### ST-10 엔터티 표준 동기화 (M-D06) — S4 ★★★

| 항목 | 내용 |
|---|---|
| 처리 | 엔터티명 ↔ 등록 용어 매칭 → 테이블명 반영 |
| 실측 | `산출물기본` = `비`. 용어로 등록하려 했으나 도메인 필수 규칙 때문에 불가 → **테이블명 표준화 경로 없음** |
| As-Is 문제 | F-23. 샘플의 기존 테이블(`PRJ_M` 등)은 미리 만들어진 이름이라 이 경로를 쓰지 않음 |
| To-Be | 엔터티 용어(도메인 없음) + 엔터티 분류어(기본→`_M`, 내역→`_D` 등) 접미 규칙 |

### ST-11 용어 자동분석 마법사 (M-D11) — S3·S4 ★★★

| 항목 | 내용 |
|---|---|
| 단계 | ① 대상 선택(논리/물리명 기준, 최대 결과 수, 간편 모드, 단어 연결자, Suffix, 제외 문자, 우선순위) → ② 결과(분석 용어·물리명·결과 설명·도메인) → ③ 단어 구성(대안 분해, 단어 변경) → ④ 용어 등록 → ⑤ 모델 반영 |
| As-Is 문제 | 오분해를 "구성 단어가 모든 조건을 충족합니다"로 표시 (F-04). ②에서 미선택 항목은 ③의 대안 분해를 볼 수 없음 |
| To-Be | ST-09와 통합한 "표준 맞추기"의 고급 모드로 |

### ST-12 표준 제외 규칙 (M-O06) — S4 ★★★

Pseudo·External·Drop·Import 엔터티, Pseudo·Drop·Additional·System 속성 제외, 논리 비대상 → 물리 비대상. **강점 — 그대로 계승**, 결과 화면에 "비대상(사유)"로 표시.

### ST-13 물리 반영 (M-P01, M-O07) — S5 ★★★

| 항목 | 내용 |
|---|---|
| 처리 | 속성 동기화 적용 시 기존 물리 모델 컬럼명·타입 자동 갱신(확인). 테이블명은 `%(EntityName)` 규칙 |
| As-Is 문제 | 미매핑이면 한글 물리명·타입 공란 무경고 (F-16, U-03). 제약·인덱스명이 테이블명에서 파생되므로 테이블명이 한글이면 모두 한글 |
| To-Be | 게이트 A(물리 변환 전 미매핑 점검) |

### ST-14 준수검사 (M-D13) — S6 ★★★

| 항목 | 내용 |
|---|---|
| 출력 | 표준 준수 체크(속성별 상태) + 표준 준수도(엔터티별 대상·비대상·표준·비표준) + 엑셀 출력 |
| 실측 | 분류를 맞춘 뒤 전 엔터티 100% — 하지만 `산출물기본` 테이블명은 한글 |
| As-Is 문제 | **엔터티·테이블명은 준수율 계산에서 빠짐** (F-24). 전체 준수율 요약 없음 (F-13). 코드값이 엔터티 행으로 나옴 (F-12) |
| To-Be | 속성·엔터티 모두 포함한 모델 전체 %, 위반 목록 바로가기, 이력 추이 |

### ST-15 스크립트 생성 범위 (M-P07) — S6 ★★★

| 항목 | 내용 |
|---|---|
| 실측 | 물리 뷰에서 테이블이 선택돼 있으면 **그 테이블만** 스크립트 생성 — 화면에 범위 표시 없음 (F-22). 1차 때 전체가 나온 것은 선택이 없었기 때문 |
| To-Be | 범위(전체/선택/주제영역)를 명시적으로 고르게 하고 결과에 "테이블 N개" 표시 |

## 3. 이번 차수 신규 문제 (F-19~F-29)

00-index §4에 함께 반영했다.

| ID | 심각도 | 문제 | 근거 |
|---|---|---|---|
| F-19 | 중 | 정합성 체크 결과(사유)가 맨 오른쪽 좁은 열에 잘려 보이고 툴팁 없음 — 창을 최대화하고 열을 넓혀야 읽힘 | 단어 일괄등록 |
| F-20 | 중 | 분석·정합성 체크 중 UI가 멈춤(창 공백), 진행 표시 없음, 그사이 클릭 무시 → "버튼이 안 눌린다"로 보임 | 용어 일괄등록에서 반복 |
| F-21 | 상 | 속성 표준 동기화의 [적용]은 [동기화 설정] 없이는 **무동작·무경고** | 적용 후 재실행 시 여전히 `불` |
| F-22 | 중 | 스크립트 생성 범위가 현재 선택 객체로 **암묵 결정** | PRJ_M 선택 상태에서 PRJ_M만 생성 |
| F-23 | 상 | 엔터티명(테이블명) 표준화 경로 없음 — 용어 등록에 도메인 필수 | "용어에 맵핑된 도메인이 없습니다" |
| F-24 | 상 | 준수검사가 엔터티·테이블명을 평가하지 않음 → 한글 테이블명인데 100% | 준수도 화면 |
| F-25 | 중 | 동봉 템플릿 2종(구형 drm03 / 현행 UploadForm) 혼재 | F-06의 원인 |
| F-26 | 중 | 분류 콤보가 화면마다 따로 + 용어 등록 탭 입력이 무반응이 되어 탭 재오픈 필요 | 용어 등록 |
| F-27 | 하 | 일괄등록에서 "이미 같은 값이 있음"도 오류로 표시 — 신규/동일/충돌 구분 없음 | 45개 중 40개 거부 |
| F-28 | 하 | 성공 메시지에 경고(⚠) 아이콘 | "N건이 등록되었습니다" |
| F-29 | 중 | 복합어 중복 미검출 — `요구사항=RQRM` 등록 허용, 기존 `요구+사항=DEMND_MATER`와 공존 | 단어 일괄등록 후 용어 분석 결과 |

**정정**: 1차에서 F-07을 "정합성 체크 결과 표시 모호"로 적었으나, 결과는 **사유·상태 열에 표시된다**(잘려서 안 보였을 뿐). F-07은 F-19로 대체한다. 또 1차 조사 중 "요구사항관리시스템 분류는 비어 있다"고 본 것은 빈 검색어 동작(F-08) 때문이었다.

## 5. 남은 확인

- 금칙어(`FORBID_YN`)·폐기(`USE_END_DT`)·동의어 조회·약어 관리 화면은 이번에 열지 않았다(약어 관리는 비활성).
- 정보보호 편집(M-D08)·표준대상 편집(M-D07)·인텔리센스 실제 동작은 3차(논리 모델)에서 함께 확인한다.
- 사전 쓰기 결과를 DB에서 직접 대조하지 않았다(화면 메시지·후속 분석 결과로만 확인).
