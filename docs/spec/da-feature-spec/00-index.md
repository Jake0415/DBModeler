### 0.1 표기

**확인 수준**

| 기호 | 의미 |
|---|---|
| ✅ | 실제로 실행해 결과까지 확인 |
| 👁 | 메뉴/대화상자를 열어 화면 구성만 확인 |
| 📖 | 도움말 목차로만 확인 (앱에서 열지 않음) |
| ⛔ | 비활성 또는 실행 실패 (사유는 비고) |

**표준화 단계 (S)** — 아래 §1 프로세스의 어느 단계에 쓰이는가. `—`는 표준화와 무관한 일반 모델링 기능.

**중요도** — 표준화 프로세스 기준

| 등급 | 기준 |
|---|---|
| ★★★ 핵심 | 해당 단계를 수행하려면 반드시 필요. 없으면 표준화가 성립하지 않음 |
| ★★ 지원 | 표준화 품질·속도를 크게 좌우 (검증, 일괄 처리, 추천 등) |
| ★ 일반 | 표준화와 무관하거나 편의 기능 |

**웹 우선순위(P)** — [기능 인벤토리 v1](../../planning/web-data-modeler-feature-inventory-v1.md)의 P0~P2를 따르되, 표준화 중요도를 반영해 조정한 값. 조정한 항목은 `P0↑`처럼 표시.

**문제 ID** — `U-xx`: 워크스루 v1 / `F-xx`: 이번 조사 (목록은 §4).

## 1. 표준화 프로세스 (DA# As-Is)

실제로 따라가 본 흐름. **두 프로그램 + 두 번의 DB 연결**이 필요하다는 점이 구조적 특징이다.

```
[표준관리자 DAWordict]                                  [모델러 Modeler5]
S0 준비   DB 연결 → 표준분류체계 → 데이터타입·약어·타입변환      A/R 연결 → 분류체계 선택
S1 단어   단어 등록 / 단어 일괄등록(Excel)
S2 도메인 도메인 등록 / 도메인 일괄등록(Excel)
S3 용어   용어 등록(후보 자동 분해) / 용어 일괄등록(분석→정합성→업로드)
S4 모델 적용                                              용어 자동분석(마법사) · 속성/엔터티 표준 동기화 · 인텔리센스 · 표준속성 추가
S5 물리 변환·명명                                         물리모델 생성 · 명명규칙(%(EntityName) 등) · 데이터타입 매핑
S6 검증·산출                                              준수검사(준수율) · 모델 검토 · DDL · 리포트/엑셀
```

| 단계 | 산출물 | As-Is에서 막힌 지점 (근거) |
|---|---|---|
| S0 | 분류체계, 타입 매핑 | Wordict 연결과 Modeler A/R 연결이 **별개** — 같은 DB를 두 번 연결해야 하고, 모델러는 연결 전까지 표준 버튼이 이유 없이 비활성 (F-03, U-05) |
| S1~S3 | 단어·도메인·용어 사전 | 동봉 도메인 템플릿이 그리드와 컬럼 불일치 → 값 밀림, 정합성 체크 미검출 (F-06). 미등록 단어 오분해 (F-04) |
| S4 | 표준 용어가 붙은 속성 | 동기화는 **등록된 용어**만 매칭 — 단어로 조합 가능해도 "비표준" (F-11). 분석 마법사는 오분해를 "모든 조건 충족"으로 표시 (F-04) |
| S5 | 영문 물리명·타입 | 미매핑 시 물리명 = 한글 논리명, 타입 공란 — 경고 없음 (F-16, U-03) |
| S6 | 준수율, DDL | 준수도에 전체 요약 없음 (F-13), 불완전 DDL 무경고 생성 (U-01) |
