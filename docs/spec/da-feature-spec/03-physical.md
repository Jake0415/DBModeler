## 0. 수행 요약

| 항목 | 한 일 | 결과 |
|---|---|---|
| 논리→물리 동기화 | 3차에서 논리에 추가한 엔터티·관계가 물리에 반영됐는지 확인 | **자동 반영** (`Relation1`, `엔터티1` 테이블, FK 컬럼, AK→`산출물기본_UK`) |
| 테이블 편집창 | RQRM_D의 테이블·컬럼·관계·제약조건·인덱스·테이블 정보 탭 | 확인. **제약조건 탭에 PK만 있고 FK 없음** |
| **FK 누락 원인 (U-02)** | 트리 Constraint 노드, 물리객체 명명규칙 FK 필터, 옵션 ▸ 제약조건 | **모델 전체에 FK 제약조건 객체가 0개**. 관계는 있지만 FK 제약조건 객체가 만들어지지 않아 DDL에 안 나온다. 화면에서 FK 제약조건을 만드는 경로를 찾지 못함 (F-38) |
| 물리객체 명명규칙 | 테이블·컬럼·제약조건·인덱스 탭 | 필터·규칙(접두사/접미사)·변경 후 이름 미리보기 확인 |
| 시스템 컬럼 | 등록일시 컬럼 추가 시도 | Tab 이동이 데이터타입 칸을 건너뜀, 길이 칸에 문자 "DATE" 입력이 허용됨 (F-40) |
| DBMS 비교 | 마법사 첫 화면 | 대상 DB 접속(리버스)이 필요해 진행 안 함 |

## 1. 기능 정의 (ID `PH-xx`)

### PH-01 물리 모델 생성·동기화 (M-P01, M-H17) ★★★ (S5)

| 항목 | 내용 |
|---|---|
| 생성 | DBMS 선택 + 논리/물리 동기화 옵션(테이블명·컬럼명·데이터타입·길이) + 표준화 대상 + CharUsed |
| 동기화 (확인) | 논리 변경(엔터티·속성·관계·AK)이 **즉시** 물리 모델에 반영. 표준 동기화 결과(컬럼명·타입)도 반영 |
| 명명 | 테이블 `%(EntityName)`, 컬럼 `%(AttrName)` (옵션) — 표준 미매핑 시 한글 그대로 (F-16) |
| 위치 동기화 | 논리/물리 위치 동기화(선택 객체 필요) |
| As-Is 문제 | 동기화가 조용히 일어나 무엇이 바뀌었는지 알 수 없음 (변경 요약 없음). 교차 엔터티 `Relation1` 같은 비표준 이름이 그대로 테이블명이 됨 |
| To-Be | 논리→물리 변경 로그(추가·변경·삭제), 게이트 A(미매핑·타입 미정 점검) |

### PH-02 테이블 편집 (M-E03) ★★★ (S5)

| 탭 | 내용 |
|---|---|
| 테이블 | 테이블명·보조명 등 |
| 컬럼 | 속성명·컬럼명·데이터타입·길이·소수점·NotNull·PK·유형·FK·Validation / 상세: 보조명·기본값·비고·표준화·CharUsed / **정보보호** 6항목 / DBMS 고유 |
| 관계 | 부모 구성(부모 엔터티·부모/자식 식별자·관계명·필수·식별자·구분) + 자식 구성 |
| 제약조건 | 제약조건 목록(이름·유형) + 컬럼 + Oracle 스토리지(Percent Free·Initial Extent 등) |
| 인덱스 | PrimaryKey Index / Other Index, 컬럼 선택·정렬(Desc), Global Index, TableSpace·Parallel·Compress·Logging 등. 하위 탭 파티션·서브파티션·스토리지·스크립트 |
| 테이블 정보 | Table Type·Table Space·Parallel·Cache·Logging + 파티션·서브파티션·스토리지·LOB·인스턴스·스크립트 |
| As-Is 문제 | 컬럼 그리드에 도메인·용어 없음 (F-14). 관계 탭에서 FK 제약조건 생성 여부를 볼 수 없음 (F-38). 편집창이 다른 모니터에 열림 (F-36) |
| To-Be | 컬럼에 도메인·표준 상태 열, 관계마다 "FK 제약조건 생성" 표시·토글, DBMS 고유 옵션은 접어 두기 |

### PH-03 제약조건·FK (M-O08, 트리 Constraint) ★★★ (S5·S6)

| 항목 | 내용 |
|---|---|
| 확인 | 트리 Constraint = 테이블별 `_PK` + AK에서 만든 `산출물기본_UK`. **FK 0개** |
| 명명 옵션 | PK `%(TableName)_PK` · UK `%(TableName)_UK` · **FK `%(TableName)_FK`** · CK `%(TableName)_CK`, 중복명 포맷(0 Base), 테이블명 변경 시 제약조건명 동시 수정, 서브셋 생성 시 Validation 제약조건 자동 생성 |
| As-Is 문제 | **관계를 그려도 FK 제약조건 객체가 생기지 않고, 만드는 방법이 화면에 드러나지 않음** (F-38). DDL에서 FK 옵션을 켜도 FK가 0건인 원인 (U-02). FK 이름 기본 패턴에 순번이 없어 한 테이블에 FK가 둘 이상이면 이름 충돌 소지 (F-39) |
| To-Be | 관계 = FK 제약조건(기본 생성, 관계별로 끌 수 있음). FK 이름 `%(ChildTable)_%(ParentTable)_FK` 또는 순번 포함. DDL 미리보기에서 관계 수 대비 FK 수 표시 |

### PH-04 물리객체 명명규칙 (M-P06) ★★★ (S5)

| 항목 | 내용 |
|---|---|
| 탭 | 테이블 / 컬럼 / 제약조건 / 인덱스 |
| 테이블 | 필터(Pseudo·Additional·Drop·External 제외) + 명명 규칙·접두사 값 → 그리드(엔터티명·테이블명·리버스명·보조명·**변경 테이블명**·유형) → 적용 |
| 제약조건 | Filter Target(PK/UK/FK/CK) · Naming Rule(접두사 등) · Naming Value · Sync IndexName · DupSeq Prefix/Format |
| 강점 | 변경 전/후 이름을 그리드에서 미리 보고 적용 — **계승** |
| As-Is 문제 | 명명 "규칙"이 접두/접미 수준. 엔터티 분류어 기반 규칙(기본→`_M`)이나 표준 용어 기반 규칙은 없음 (F-23과 연결) |
| To-Be | 명명 템플릿 변수 확장(분류어·주제영역 약어·표준 물리명), 미리보기 유지 |

### PH-05 시스템 컬럼 (M-P03) ★★ (S5)

| 항목 | 내용 |
|---|---|
| 화면 | 시스템 컬럼 그리드(컬럼명·속성명·데이터타입·길이·NN·디폴트·설명·참조갯수) + 불러오기·엑셀출력·▲▼·+/-·저장 / 테이블 목록 체크 → [▽반영] [△해제] |
| As-Is 문제 | Tab이 데이터타입 드롭다운을 건너뜀, 길이 칸에 문자 허용, 타입 목록이 길고 타이핑 검색 없음 (F-40). 닫을 때 "저장하지 않은 시스템 컬럼" 확인 |
| To-Be | 공통 컬럼 세트를 사전(표준 용어)에서 고르고, 테이블 유형별 자동 적용 규칙 |

### PH-06 데이터타입 매핑·DBMS 변경 (M-O10, W-13) ★★★ (S0·S5)

DBMS별 논리→물리 타입 표 + 축약형. 물리 타입 드롭다운에 `CHAR(CH)`, `VARCHAR2(VC)`처럼 축약형이 함께 표시된다. 04 ST-08 참조.

### PH-07 DBMS 비교 (M-P09) ★★ (S6)

마법사: 기준 모델·물리모델·주제영역 → 비교 대상 DBMS(리버스 접속·스키마·테이블) → 비교. 대상 DB가 없어 실행 못 함 (⛔).

### PH-08 기타 (📖)

컬럼순서 초기화(기본/구분속성우선/속성타입/컬럼기준), 인스턴스 편집·출력, 뷰 생성, 서브타입 Transforms(통합/분할), 파티션·LOB 상세.

## 2. 이번 차수 신규 문제

| ID | 심각도 | 문제 | 근거 |
|---|---|---|---|
| F-38 | 상 | 관계가 있어도 **FK 제약조건 객체가 생성되지 않음**, 생성 경로가 화면에 없음 → DDL FK 누락(U-02)의 원인 | 트리 Constraint, 명명규칙 FK 필터 0건 |
| F-39 | 중 | FK 이름 기본 패턴 `%(TableName)_FK`에 순번·부모명 없음 → 한 테이블 다중 FK 시 충돌 소지 | 옵션 ▸ 제약조건 |
| F-40 | 중 | 그리드 입력 검증·이동 문제: Tab이 드롭다운 셀 건너뜀, 숫자 칸에 문자 허용, 긴 목록에 타이핑 검색 없음 | 시스템 컬럼 |
| F-41 | 하 | 논리→물리 자동 동기화에 변경 요약 없음 | 3차 변경이 물리에 조용히 반영 |
