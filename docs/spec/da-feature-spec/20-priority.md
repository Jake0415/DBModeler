## 1. 우선순위 기준

1차 목표는 **"웹에서 표준화 프로세스(S0~S6)를 끊김 없이 완주하고, 잘못된 결과가 밖으로 나가지 않는다"** 이다. 그래서 일반적인 "기능 개수" 기준 대신 아래 4개 축으로 매겼다.

| 축 | 질문 | 점수 |
|---|---|---|
| A. 표준화 경로 | 이게 없으면 S0~S6 중 어느 단계가 끊기는가 | 끊김 3 / 품질 저하 2 / 무관 1 |
| B. 잘못된 산출 방지 | 없으면 틀린 DDL·정의서·준수율이 조용히 나가는가 | 예 3 / 일부 2 / 아니오 1 |
| C. 근거 심각도 | 연결된 문제(U/F) 중 "상"이 있는가 | 상 3 / 중 2 / 하 1 |
| D. 재사용 | docuCBD 자산으로 바로 만들 수 있는가 | 거의 그대로 3 / 확장 2 / 신규 1 |

**웨이브** = A·B·C 합(9점 만점)이 높고 서로 의존하는 것끼리 묶었다. D는 같은 웨이브 안의 착수 순서에만 썼다.

| 웨이브 | 의미 | 완료 판정 |
|---|---|---|
| **W0 기반** | 다른 모든 요구사항의 전제(서버 저장·사전·편집 패널) | 모델을 서버에 저장·이력 조회, 사전 조회 가능 |
| **W1 표준화 완주 (MVP)** | 샘플 모델로 S0→S6을 웹에서 끝까지, 게이트로 잘못된 산출 차단 | 1~2차 실습 시나리오(산출물기본)를 웹에서 재현해 DDL·준수율이 맞게 나옴 |
| **W2 모델링 완성도** | 실무 모델링에 필요한 나머지 편집·물리·리버스 | 샘플 6종 규모 모델을 웹에서 신규 작성 |
| **W3 확장** | 있으면 좋은 것, 외부 의존(DB 접속) | — |

| Q-2 | 후보 큐 승인을 모델러 본인이 할 수 있나 | **기본은 admin 승인(docuCBD 정책 유지)**. 다만 소규모 팀을 위해 프로젝트 설정 "모델러 자가 승인 허용"(기본 꺼짐, 감사 로그 필수)을 W2에 둔다 | docuCBD §13 "승인 권한은 require_admin 유지, 결재선 없음". 표준 오염 방지가 1차 목표와 맞음 |
| Q-3 | 게이트는 차단인가, 경고+예외 승인인가 | **게이트 A(물리 변환) = 경고 + 예외 사유 기록, 게이트 B(DDL) = 문법 오류(타입 누락·식별자 무효)는 차단, 표준 위반·FK 누락은 경고 + 예외 승인** | 실행 불가 DDL(U-01)은 막아야 하고, 표준 위반은 현업 사정(레거시 이름 유지 등)이 있어 예외 경로가 필요. 예외는 준수율 보고서에 "예외 승인"으로 별도 집계 |
| Q-4 | 미등록 단어 판정 규칙 | **docuCBD 명명 엔진 규칙 채택: "전 구간이 등록 단어로 커버될 때만 성공", 그 외는 실패로 후보 큐**. 추가로 DA# 실측 사례(산출물→산출+물)를 막기 위해 **1음절 단어가 끼는 분해는 '의심'으로 표시해 자동 확정하지 않는다** | docuCBD §4 "전 구간 커버 시에만 성공". 1음절 규칙은 행정표준용어 샘플로 오탐률 검증 후 확정(검증 과제) |
| Q-5 | `.damx` 가져오기 시 모델 내 용어·도메인을 사전 후보로 넣나 | **W3로 미루고, 넣는다면 "후보 큐(세트 미지정)"로만** 넣는다. 사전에 직접 등재 금지 | 인벤토리 OQ-3(`.damx` 포맷 분석 필요). docuCBD §13 "세트 미지정 후보는 자동 적재하지 않음" |
| Q-6 | 엔터티 용어 물리명 규칙(분류어 접미)을 사전에 두나, 명명 템플릿에 두나 | **분류어(기본·내역·관계 등)와 그 물리 접미(`_M`·`_D`·`_R`)는 사전 단어 속성으로, 조합 방식은 명명 템플릿 변수(`%(EntityStdName)%(ClassSuffix)`)로**. 둘 다 필요 | 샘플의 기존 테이블명(`PRJ_M`, `RQRM_D`, `RQRM_RISK_R`)이 이 패턴. DA# 사전에도 엔터티 분류어 플래그(`ENT_CLSS_YN`)가 있음 |
| Q-7 | DA# 사전의 유효기간 이력·금칙어·분류체계 플래그를 가져가나 | **유효기간 이력 → docuCBD 불변 개정으로 대체**, **금칙어 → docuCBD에 이미 있음(그대로)**, **분류체계별 기능 플래그(용어·도메인·코드 사용 여부) → 가져가지 않음**(세트는 항상 전 요소 사용), **도메인 보안 속성(개인정보·암호화) → docuCBD 도메인에 추가 필요**(LG-R10 전제) | docuCBD §2(개정)·§4(금칙어). 보안 속성은 docuCBD에 없음 → W2 과제 |
