> - ⑧ **검색·목록 성능 규칙** (ST-R03 보강, 2026-11-18 확정, [23 §6-1·3](23-performance-spike.md)): 이름·약어·초성(별도 열) 3개 열에 trigram 색인을 둔다(20만 건에서 3자 이상 검색 p95 10ms 미만). **2글자 이하 검색어는 앞부분 일치**로 찾는다. 부분 일치 결과의 **총건수는 1,000건까지만** 세고 "1,000건 이상 — 더 입력하세요"로 표시한다. 목록은 OFFSET 페이지로 하고, 1만 건 이후의 깊은 페이지는 키셋으로 한다. 사전 목록 화면은 가상화한다.
> - ⑦ **영구 삭제 절차** (MD-24 보강): V0 보관 뒤 영구 삭제는 DA·Admin만 할 수 있다. 대상 이름을 그대로 입력해 확인하고 사유를 반드시 적는다. 참조가 남아 있으면 차단한다. 수행 기록은 별도 삭제 로그에 남긴다. 결재 기록은 보존한다.

## 1. 범위

### 1.1 SWS에서 참조하는 시나리오

| SWS 메뉴·시나리오 | DBModeler 모듈 | 참조 방식 |
|---|---|---|
| 표준사전 관리(단어·도메인·용어 탭, 신청 팝업, 상세·연관) | **사전 관리** | 시나리오·규칙 참조, 화면은 새로 설계 |
| 도메인 그룹 관리(그룹, 분류 자동 추출) | 사전 관리 ▸ 도메인 그룹 | 참조 |
| 표준코드·코드값 관리 | 사전 관리 ▸ 코드 | 참조 |
| 표준 제·개정 신청 / 결재 처리 | **사전 결재** | 단일 결재 시나리오 참조 |
| 변경이력 관리 / 삭제 데이터 관리 | 사전 이력·삭제 보관 | 참조 |
| 검수 기준(입력 형식 정책) | 사전 검수 기준 | 참조 |
| 표준화 검수(설계↔사전 판정 사유) | **표준 맞추기 · 준수율** (ST-R07·R08) | 판정 사유 체계만 참조, 흐름은 DBModeler 설계 |
| 모델 컬럼의 용어·코드 그룹 연결, 메타데이터 변경 반영 | 모델 ↔ 사전 연결 | 연결·재검토 시나리오만 참조 |

### 1.2 참조하지 않는 것

- SWS 모델링 화면, ERD, 산출물·묶음 결재, 문서 잠금, 통합 기준본, 사용자·메뉴·프로그램 권한 관리 UI.
- 업무관리도메인, 표준코드 매핑, 과거 2단계 결재, OpenMetadata·NiFi 연동 흔적. SWS에서도 이미 제외된 영역이다.

## 2. 개념 모델

```
[사전 세트 DictSet] ── 기관에 고정 2개 (v1.1: 선택 UI 없음)
   ├ 공통 세트(행안부 공통표준 시드, 읽기 전용)  ┐ 해석 순서: 공통 우선
   └ 기관 세트 1개(등록·결재 대상)               ┘ 공통과 이름 충돌 시 등록 거부
[기관 > 시스템(대상 DB) > 업무 영역] ── 시스템마다 DBMS·명명 템플릿·모델 확정 최종 승인 설정
        │
        ├ 표준단어 Word ──────────────┐ 형식단어 → 도메인분류
        │   └ 엔터티 분류어(신규)       │
        ├ 도메인그룹 → 도메인분류 → 표준도메인 Domain (+보안 속성, 신규)
        ├ 표준용어 Term = 단어 조합 (+용어 유형: 속성/엔터티, 신규)
        ├ 표준코드 그룹 → 코드값
        ├ 후보 큐 Candidate (신규)
        └ 검수 기준 Policy
[사전 신청 ChangeRequest] → 단일 결재 → 반영 + 이력(History) / 삭제 보관(V0)
[모델 컬럼·엔터티] ── 용어 ID + 참조 서명 → 표준 맞추기·준수 판정
```

### 2.1 엔터티 정의

SWS 항목명은 행안부 공통표준 관리항목을 따른다. DBModeler도 같은 화면 명칭을 쓴다(SWS `metadata-terminology.md`).

| 엔터티 | 주요 속성 | SWS 대비 |
|---|---|---|
| **DictSet** | 세트명·유형(공통/기관)·설명·사용상태 | **신규** — 공통·기관 2개 고정(v1.1). 공통 우선·충돌 거부 규칙에 필요 |
| **System** (구 ProjectStandardProfile) | 시스템명·대상 DBMS·기본 스키마·명명 템플릿 ID·모델 확정 최종 승인 사용 여부 | **신규** — v1.1에서 프로젝트 → 시스템 단위로 변경 |
| **ApprovalLineTemplate** | 결재 문서 유형(사전 신청/모델 확정)·단계 목록(단계명·승인 역할·필수 여부) | **신규** — 사전 신청은 기관 설정, 모델 확정은 시스템 설정의 최종 승인 토글을 따름 |
| **Word** | 단어명·단어 영문약어명·영문명·설명·형식단어 여부·도메인분류 ID·이음동의어 목록·금칙어 목록·중복 허용 사유·제정차수·사용상태·버전 | 동일 + **엔터티 분류어 여부·엔터티 접미(`_M`·`_D`·`_R`)** 추가 (Q-6) |
| **DomainGroup** | 그룹명·설명(필수, ≤500자)·사용상태 | 동일 (결재 없이 DA·Admin 직접 관리) |
| **DomainClassification** | 분류명·그룹 ID·구성 단어 ID 목록·형식단어 ID·예외 사유·사용상태 | 동일 |
| **Domain** | 도메인명(= 분류명+타입+길이[,소수점], 예 `번호V20`)·분류 ID·데이터타입(V/C/N/D/T/L)·길이·소수점·허용값·저장/표현형식·단위·예외 사유·제정차수·사용상태·버전 | 동일 + **보안 속성(개인정보 여부·보호등급·암호화 여부·암호화 방법)** 추가 (Q-7, LG-R10) |
| **Term** | 용어명·용어 영문약어명(= 단어 약어 `_` 결합)·구성 단어 ID 목록(순서)·도메인 ID·허용값·저장/표현형식·출처·기관·제정차수·사용상태·버전 | 동일 + **용어 유형(속성/엔터티)**. 엔터티 용어는 도메인 없음 (ST-R06) |
| **CodeGroup** | 영문/한글코드명·적용 범위(공통/시스템)·대상 시스템·구조(단일/계층)·코드 타입(기관/법정/자체)·도메인 ID 또는 자체 규격 선언 | 동일 |
| **CodeValue** | 코드값(문자열, 앞자리 0 보존)·의미·상위 코드·정렬·유효 시작/종료·사용상태 | 동일 |
| **Candidate** | 유형(단어/용어)·이름·제안 약어·발생 위치(모델·엔터티·속성)·세트 ID·상태(대기/승인/반려) | **신규** — SWS는 미등록 단어가 있으면 차단만 함. docuCBD 후보 큐 개념 참고 |
| **ChangeRequest** (결재 문서) | 신청번호·문서 유형(사전 신청/모델 확정)·동작·전후 값·사유·상태(진행 중/승인/반려/회수)·**결재선 스냅샷(단계별 결재자·결과·의견·자기 승인 사유)**·참조자·신청 시점 검사 결과 | v1.1: 단일 결재 → 다단계 결재선. SWS의 과거 2단계 "재확인"과는 다른 설정형 구조 |
| **History** | 항목 ID·버전 전후 스냅샷·반영 구분(초기 적재/데이터 보완/사용자 변경 승인)·기안·결재 | 동일 |
| **ValidationPolicy** | 사전별 필드 입력 형식(필수·길이·허용 문자·차단/경고)·약어 바이트 상한·DBMS 기준 | 동일 |
| **DataType** | 타입 코드·기본 타입·길이 방식·최대 길이·소수점 허용 + DBMS별 물리 타입 | 동일 (DA# 축약형 포함, PH-06) |

**버전 규칙** (SWS와 같음):
- 신규 승인은 V1이다. 승인된 변경마다 +1 한다.
- 신청·반려·회수만으로는 버전이 바뀌지 않는다.
- 제정차수는 시스템 버전과 별개인 원문 메타데이터다.
- 이력은 변경 전후 스냅샷으로 남긴다. 불변 개정 묶음은 쓰지 않는다 (Q-7).

## 3. 시나리오

시나리오 ID는 `MD-xx`. **★ = DBModeler 신규 또는 변경**, 나머지는 SWS 시나리오를 그대로 따른다.

### 3.1 사전 등록 (S1~S3)

|---|---|---|---|
| MD-01 | 표준단어 신청 | 신청 창 왼쪽 입력 → 목록에 추가 → 사유(1~1,000자) → 제출 → 신청번호 | 단어명+약어 둘 다 중복이면 ⛔. 한쪽만 중복이면 중복 허용 사유 📝. 영문명 중복 ⛔. 이음동의어·금칙어가 다른 단어명·동의어·금칙어와 충돌하면 ⛔. 비교 시 공백 제거·대소문자 정규화 |

### 3.2 결재·이력·삭제

| ID | 시나리오 | 핵심 규칙 |
|---|---|---|
| MD-20 ★ | 결재선 진행 (v1.1) | 신청 시 유형별 템플릿으로 결재선 생성: **1단계 DA(필수)** → **2단계 기관 담당자 최종 승인(사전 신청은 기관 설정, 모델 확정은 시스템 설정이 켜진 경우)**. 각 단계는 해당 역할 보유자 중 누구든 먼저 처리. 최종 단계 승인 시에만 사전·모델에 반영. 매 단계 승인 시 현재 기준으로 재검사, 실패하면 그 단계 승인 취소 + 실패 이력. 반려는 의견 필수, 어느 단계든 반려하면 신청자에게 돌아감 |

| MD-22 | 신청 현황 | 대기함(내가 처리할 단계)·내 신청·참조함. 상세는 사유·전후 값·결재선 진행·신청 시점과 현재 기준의 검사 결과를 구분 표시. 모델 확정은 **표준 예외 목록** 섹션 필수 |
| MD-25 ★ | 자기 승인 (v1.1) | 신청자가 해당 단계 역할을 가지면 자기 승인 가능, **사유 필수**, 이력·감사 로그에 "자기 승인" 표시 |
| MD-26 ★ | 참조자 (v1.1) | 신청자가 참조자를 추가(템플릿 단계는 삭제 불가). 참조자는 결재권 없이 열람·알림 |
| MD-27 ★ | 알림 (v1.1) | 앱 내 알림(대기함 배지·참조·후보·재검토) + **메일은 결재선 담당자에게만**: 결재 요청은 지금 차례인 결재자에게, 결과·회수는 신청자와 앞 단계 결재자에게 |
| MD-23 | 버전별 이력 | 현재 사전 ↔ 버전별 이력 전환. 항목 버전(V1·V2…)·제정차수·변경 구분 검색. 직전 버전과 필드별 비교, NULL·빈 문자열·0 구분 |
| MD-24 | 삭제 보관·영구 삭제 | 삭제 신청 → DA 승인 → V0(삭제 보관). 참조 중이면 ⛔. DA·Admin 영구 삭제는 사유 기록, 결재 기록은 보존, 복원 없음 |

## 4. 검증 규칙 요약 (SWS 공통 흐름 채택)

```
① 권한 → ② 입력 형식(검수 기준) → ③ 업무 규칙 → ④ 신청 → ⑤ 단일 결재·반영
                                   (③은 ④ 신청과 ⑤ 승인 시점에 다시 실행)
```

| 구분 | 기호 | 의미 |
|---|---|---|
| 차단 | ⛔ | 신청·승인 불가 |
| 사유 필요 | 📝 | 사유를 적으면 신청 가능, DA 검토 |
| 경고 | ⚠ | 확인 후 신청 가능, 신청 시점 기록 보존 |

- 검수 기준(입력 형식)은 사전별·필드별로 정한다: 필수·길이·허용 문자·차단/경고.
- 같은 기준을 프런트·서버·엑셀에 동일하게 적용한다.
- DBMS 이름 길이 기준은 프로젝트 대상 DBMS를 따른다.
  - SWS는 기준값을 직접 고른다(63바이트=PostgreSQL, 그 외=Oracle).
  - DBModeler는 MD-40에서 지정한 프로젝트 DBMS를 쓴다.
