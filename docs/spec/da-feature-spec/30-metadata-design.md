# DBModeler 메타데이터(표준 사전) 설계 — SWS 시나리오 참조 재구현 (v1)

> 상태: **설계 초안 v1** (2026-11-17). 구현 계획 아님.
> 결정: SWS(`D:\project\sws-data-governance`)의 **메타데이터 부분 시나리오만 참조**해 DBModeler에 맞게 **새로 구현**한다. SWS 코드·DB·API를 공유하거나 복사하지 않는다. SWS의 모델링·ERD·산출물·결재 외 영역은 참조하지 않는다(모델링은 DA# 분석 01~07이 기준).
> 참조한 SWS 자료(읽기 전용): `docs/user-guide/delivery-user-handbook.md` §3~5·8~10·변경이력·삭제, `docs/architecture/validation-rules.md` §1~4·6~8, `docs/user-guide/metadata-terminology.md`, `docs/getting-started/scope.md`.
> 연관: [04-standard.md](04-standard.md)(DA# 표준 영역 분석) · [20-priority.md](20-priority.md)(우선순위·결정) · [21-dictionary-sws-review.md](21-dictionary-sws-review.md)(적합성 검토).

## 1. 범위

### 1.1 SWS에서 참조하는 시나리오

| SWS 메뉴·시나리오 | DBModeler 모듈 | 참조 방식 |
|---|---|---|
| 표준사전 관리(단어·도메인·용어 탭, 신청 팝업, 상세·연관) | **사전 관리** | 시나리오·규칙 참조, 화면은 새로 설계 |
| 도메인 그룹 관리(그룹, 분류 자동 추출) | 사전 관리 ▸ 도메인 그룹 | 참조 |
| 표준코드·코드값 관리 | 사전 관리 ▸ 코드 | 참조 |
| 표준 제·개정 신청 / 결재 처리 | **사전 결재** | 단일 결재 시나리오 참조 |
| 변경이력 관리 / 삭제 데이터 관리 | 사전 이력·삭제 보관 | 참조 |
| 검수 기준(입력 형식 정책) | 사전 검수 기준 | 참조 |
| 표준화 검수(설계↔사전 판정 사유) | **표준 맞추기 · 준수율** (ST-R07·R08) | 판정 사유 체계만 참조, 흐름은 DBModeler 설계 |
| 모델 컬럼의 용어·코드 그룹 연결, 메타데이터 변경 반영 | 모델 ↔ 사전 연결 | 연결·재검토 시나리오만 참조 |

### 1.2 참조하지 않는 것

- SWS 모델링 화면, ERD, 산출물·묶음 결재, 문서 잠금, 통합 기준본, 사용자·메뉴·프로그램 권한 관리 UI.
- 업무관리도메인, 표준코드 매핑, 과거 2단계 결재, OpenMetadata·NiFi 연동 흔적. SWS에서도 이미 제외된 영역이다.

## 2. 개념 모델

```
[사전 세트 DictSet] ── 프로젝트가 1개 선택 (ST-R02, 신규)
   ├ 공통 세트(행안부 공통표준 시드, 읽기 전용)  ┐ 해석 순서: 공통 우선
   └ 기관/프로젝트 세트(등록·결재 대상)          ┘ 공통과 이름 충돌 시 등록 거부
        │
        ├ 표준단어 Word ──────────────┐ 형식단어 → 도메인분류
        │   └ 엔터티 분류어(신규)       │
        ├ 도메인그룹 → 도메인분류 → 표준도메인 Domain (+보안 속성, 신규)
        ├ 표준용어 Term = 단어 조합 (+용어 유형: 속성/엔터티, 신규)
        ├ 표준코드 그룹 → 코드값
        ├ 후보 큐 Candidate (신규)
        └ 검수 기준 Policy
[사전 신청 ChangeRequest] → 단일 결재 → 반영 + 이력(History) / 삭제 보관(V0)
[모델 컬럼·엔터티] ── 용어 ID + 참조 서명 → 표준 맞추기·준수 판정
```

### 2.1 엔터티 정의

SWS 항목명은 행안부 공통표준 관리항목을 따른다. DBModeler도 같은 화면 명칭을 쓴다(SWS `metadata-terminology.md`).

| 엔터티 | 주요 속성 | SWS 대비 |
|---|---|---|
| **DictSet** | 세트명·유형(공통/기관)·설명·사용상태 | **신규** — SWS는 전역 사전 1개. DA# "표준분류체계" 대응 |
| **ProjectStandardProfile** | 프로젝트 ID·세트 ID·대상 DBMS·명명 템플릿 ID | **신규** |
| **Word** | 단어명·단어 영문약어명·영문명·설명·형식단어 여부·도메인분류 ID·이음동의어 목록·금칙어 목록·중복 허용 사유·제정차수·사용상태·버전 | 동일 + **엔터티 분류어 여부·엔터티 접미(`_M`·`_D`·`_R`)** 추가 (Q-6) |
| **DomainGroup** | 그룹명·설명(필수, ≤500자)·사용상태 | 동일 (결재 없이 DA·Admin 직접 관리) |
| **DomainClassification** | 분류명·그룹 ID·구성 단어 ID 목록·형식단어 ID·예외 사유·사용상태 | 동일 |
| **Domain** | 도메인명(= 분류명+타입+길이[,소수점], 예 `번호V20`)·분류 ID·데이터타입(V/C/N/D/T/L)·길이·소수점·허용값·저장/표현형식·단위·예외 사유·제정차수·사용상태·버전 | 동일 + **보안 속성(개인정보 여부·보호등급·암호화 여부·암호화 방법)** 추가 (Q-7, LG-R10) |
| **Term** | 용어명·용어 영문약어명(= 단어 약어 `_` 결합)·구성 단어 ID 목록(순서)·도메인 ID·허용값·저장/표현형식·출처·기관·제정차수·사용상태·버전 | 동일 + **용어 유형(속성/엔터티)**. 엔터티 용어는 도메인 없음 (ST-R06) |
| **CodeGroup** | 영문/한글코드명·적용 범위(공통/시스템)·대상 시스템·구조(단일/계층)·코드 타입(기관/법정/자체)·도메인 ID 또는 자체 규격 선언 | 동일 |
| **CodeValue** | 코드값(문자열, 앞자리 0 보존)·의미·상위 코드·정렬·유효 시작/종료·사용상태 | 동일 |
| **Candidate** | 유형(단어/용어)·이름·제안 약어·발생 위치(모델·엔터티·속성)·세트 ID·상태(대기/승인/반려) | **신규** — SWS는 미등록 단어가 있으면 차단만 함. docuCBD 후보 큐 개념 참고 |
| **ChangeRequest** | 신청번호·대상 유형·동작(등록/수정/미사용/삭제)·전후 값·사유·상태(대기/승인/반려/회수)·신청 시점 검사 결과 | 동일 (2단계·재확인 상태 제외) |
| **History** | 항목 ID·버전 전후 스냅샷·반영 구분(초기 적재/데이터 보완/사용자 변경 승인)·기안·결재 | 동일 |
| **ValidationPolicy** | 사전별 필드 입력 형식(필수·길이·허용 문자·차단/경고)·약어 바이트 상한·DBMS 기준 | 동일 |
| **DataType** | 타입 코드·기본 타입·길이 방식·최대 길이·소수점 허용 + DBMS별 물리 타입 | 동일 (DA# 축약형 포함, PH-06) |

**버전 규칙** (SWS와 같음):
- 신규 승인은 V1이다. 승인된 변경마다 +1 한다.
- 신청·반려·회수만으로는 버전이 바뀌지 않는다.
- 제정차수는 시스템 버전과 별개인 원문 메타데이터다.
- 이력은 변경 전후 스냅샷으로 남긴다. 불변 개정 묶음은 쓰지 않는다 (Q-7).

## 3. 시나리오

시나리오 ID는 `MD-xx`. **★ = DBModeler 신규 또는 변경**, 나머지는 SWS 시나리오를 그대로 따른다.

### 3.1 사전 등록 (S1~S3)

| ID | 시나리오 | 흐름 | 핵심 규칙 |
|---|---|---|---|
| MD-01 | 표준단어 신청 | 신청 창 왼쪽 입력 → 목록에 추가 → 사유(1~1,000자) → 제출 → 신청번호 | 단어명+약어 둘 다 중복이면 ⛔. 한쪽만 중복이면 중복 허용 사유 📝. 영문명 중복 ⛔. 이음동의어·금칙어가 다른 단어명·동의어·금칙어와 충돌하면 ⛔. 비교 시 공백 제거·대소문자 정규화 |
| MD-02 | 형식단어 최초 등록 | 분류 없이 형식단어로 승인 → 도메인 등록 시 분류의 "연결 형식단어"로 지정 | 빈 사전에서 닭과 달걀 문제 회피 |
| MD-03 | 표준도메인 신청 | 도메인명 직접 입력 → 분류명 자동 추출(읽기 전용) → 타입·길이 자동 해석 → 그룹 선택 → 제출 | 도메인명 = 분류명+타입+길이[,소수점]. V/C/N은 길이 필수, 소수점은 N만. 새 분류는 단어 분해가 되거나 예외 사유가 있으면 도메인과 같은 결재로 함께 등록. 입력 중 기존 도메인 후보 표시(가격 → 가격N10·가격N9,2) |
| MD-04 | 표준용어 신청 | 용어명 입력 → 입력이 멈추면 분석 → 후보(최대 30) 1개면 적용, 여러 개면 선택 → 약어 자동 → 마지막 형식단어의 분류로 도메인 추천 → 제출 | 미등록 단어·금칙어 ⛔. 약어는 조합값과 같아야 함. 약어는 UTF-8 바이트 상한 이내. 형식단어로 끝나면 그 분류의 도메인만, 아니면 ⚠ 후 허용. 이음동의어는 표준명으로 치환(아이피번호 → IP번호/IP_NO) |
| **MD-05 ★** | **엔터티 용어 신청** | 유형 "엔터티" 선택 → 엔터티명 분석(예: 산출물기본 → 산출물+기본) → 마지막 단어가 엔터티 분류어면 물리명 = 앞 단어 약어 + 접미 (`DLVRBL_M`) → 도메인 입력란 숨김 → 제출 | 도메인 없음. 엔터티 분류어가 아니면 ⚠. DA# F-23(테이블명 표준화 경로 없음) 해소 |
| **MD-06 ★** | **분해 의심 표시** | 분석 결과에 1음절 단어가 포함되면(산출+물) "의심" 배지 → 자동 적용 안 함, 사용자가 확인하거나 단어 신청 | Q-4. DA# F-04(산출물 → PRDC_WTR) 재발 방지. 1음절 규칙은 공통표준 데이터로 오탐률 검증 후 확정 |
| **MD-07 ★** | **복합어 중복 경고** | 새 단어(요구사항)가 기존 단어 조합(요구+사항)으로 분해되면 ⚠ + 기존 표기 제시 | DA# F-29 |
| MD-08 | 엑셀 일괄 신청 | 양식 다운로드 → 업로드(XLSX/CSV ≤20MB) → 원본 표시(미검증) → **파일 검증**(셀 단위 사유) → 정상 N건만 신청 | **헤더명 매핑**(구 양식 별칭 허용). 5색 상태: 녹색 신청 가능 / 회색 기등록 동일 / 파란색 동일 결재 대기 / 주황색 중복·대기와 다름 / 붉은색 입력 오류. 통계는 행 단위. 미리보기 이후 파일·DB가 바뀌면 ⛔ |
| **MD-09 ★** | **엑셀에서 분해 후보 선택** | 검증 결과 후보가 여러 개인 용어 행 → 미리보기에서 행별로 후보 선택 → 신청 | SWS는 이 경우 오류로 처리. DA# ST-R04 개선 |
| MD-10 | 수정 신청 | 상세에서 값 변경 + 사유 → 변경 신청. 승인 전까지 기존 승인본 사용 | 같은 대상의 대기 신청이 있으면 ⛔. 대상 버전이 바뀌면 다시 조회 |
| MD-11 | 상위 변경 영향 확인 | 단어·도메인 수정 시 연결 용어·분류·코드·**모델 사용처** 건수 경고 | 하위·설계는 자동으로 연쇄 변경하지 않음. 도메인 규격 변경은 기존 코드값 재검사, 맞지 않으면 ⛔. 사용 중 하위가 있는 그룹·분류의 미사용 전환 ⛔ |
| MD-12 | 미사용 전환 | 사용상태만 미사용으로 바꾸는 신청 | 상위가 미사용이어도 허용, 연결 ID 유지. 다른 값과 함께 바꾸면 전체 규칙 재적용 |

### 3.2 결재·이력·삭제

| ID | 시나리오 | 핵심 규칙 |
|---|---|---|
| MD-20 | 단일 결재 | DA(승인 권한) 또는 Admin 중 누구든 먼저 처리. **자기 승인 허용**(Q-2). 승인 시점에 현재 사전 기준으로 재검사, 실패하면 승인 취소 + 실패 이력. 반려는 의견 필수 |
| MD-21 | 회수·재신청 | 본인 대기 신청 회수(자기 반려 불가). 재신청은 새 신청번호로 만들고 현재 규칙으로 재검증 |
| MD-22 | 신청 현황 | 일반 사용자는 본인 신청, DA·Admin은 전체/내 신청. 상세는 사유·전후 값·신청 시점과 현재 기준의 검사 결과를 구분 표시 |
| MD-23 | 버전별 이력 | 현재 사전 ↔ 버전별 이력 전환. 항목 버전(V1·V2…)·제정차수·변경 구분 검색. 직전 버전과 필드별 비교, NULL·빈 문자열·0 구분 |
| MD-24 | 삭제 보관·영구 삭제 | 삭제 신청 → DA 승인 → V0(삭제 보관). 참조 중이면 ⛔. DA·Admin 영구 삭제는 사유 기록, 결재 기록은 보존, 복원 없음 |

### 3.3 코드

| ID | 시나리오 | 핵심 규칙 |
|---|---|---|
| MD-30 | 표준코드 신청 | 도메인 검색(신규 정의) + 기등록 코드 검색(참고)을 한 양식에. 도메인 미연결 시 자체 규격(타입·길이) 선언. 공통이면 대상 시스템 ⛔, 시스템별이면 필수 |
| MD-31 | 코드값 신청 | 같은 코드의 코드값 목록을 1건 품의로. 승인 시 전체 재검사, 하나라도 충돌하면 전체 중단. 코드값은 도메인(또는 자체) 규격·허용값 목록으로 검사, 앞자리 0 보존, 계층 순환 ⛔ |
| MD-32 | 모델 컬럼에 코드 그룹 연결 | 같은 표준도메인에 연결된 코드 그룹을 기본 후보로. 용어와 코드 그룹의 도메인 ID가 다르면 재검토 대상 |

### 3.4 프로젝트·후보 큐 (★ 신규)

| ID | 시나리오 | 흐름 | 규칙 |
|---|---|---|---|
| **MD-40 ★** | 프로젝트 표준 기준 지정 | 프로젝트 생성 시 사전 세트·대상 DBMS·명명 템플릿 선택 → 모든 화면 상단에 세트 표시 | 세트 변경 시 영향 미리보기(재검토 대상 컬럼 수). DA# F-09·F-10·F-26 해소 |
| **MD-41 ★** | 기관 세트 관리 | DA·Admin이 기관 세트 생성·이름 변경(삭제 없음). 세트별 업로드·후보 | 공통 세트와 같은 한글명인데 약어·도메인이 다르면 "공통 충돌"로 등록 거부 |
| **MD-42 ★** | 모델링 중 후보 등록 | 표준 맞추기에서 "미등록 단어 포함" 항목 → [단어 후보 등록] → 후보 큐(세트 귀속) | 후보는 사전에 반영되지 않음. 모델 속성에는 "후보 대기" 상태 표시 |
| **MD-43 ★** | 후보 승인 | DA가 후보 큐에서 확인 → 승인하면 **MD-01/04 신청으로 전환되어 같은 결재 경로** → 승인 후 모델에 "재검토 가능" 알림 | 유사 표준어 제시(반려 유도). 용어 후보는 구성 단어·도메인 검증 필수 |

### 3.5 모델 연결·판정 (표준 맞추기·준수율과의 접점)

| ID | 시나리오 | 핵심 규칙 |
|---|---|---|
| MD-50 | 속성에 용어 적용 | 용어 선택 시 논리명=용어명, 물리명=용어 약어, 타입·길이=도메인. **참조 서명**(용어·단어·도메인·분류·그룹 ID+버전의 해시) 저장 |
| MD-51 | 상위 변경 재검토 | 참조 서명이 현재와 다르면 "재검토 필요". 설계는 자동 수정하지 않음 |
| MD-52 | 선택한 변경 반영 | 최신 사전과 차이 확인 → 반영할 컬럼 체크 → 새 모델 버전으로 반영. 용어 약어 변경 시 그 컬럼을 참조하는 FK 컬럼명도 함께. 확인 후 사전·모델이 다시 바뀌면 ⛔ |
| MD-53 | 컬럼 판정 사유 | SWS 12개 사유를 그대로 쓴다: 이름 누락 / 용어 미지정 / 용어 없음 / 용어 연결 오류 / 연결 기준 변경 / 용어명·약어 불일치 / 미승인·미사용 / 컬럼명≠용어 / 도메인 없음 / 도메인 정의 변경 / DB 타입≠도메인 / 코드 그룹 불일치 |
| **MD-54 ★** | **엔터티 판정 사유 추가** | SWS는 테이블에 이름·컬럼이 있고 미준수 컬럼이 없으면 준수로 본다. 여기에 **엔터티 용어 미지정 / 테이블명≠엔터티 용어 물리명 / 엔터티 분류어 접미 불일치**를 추가한다 (ST-R08, DA# F-24) |
| MD-55 | 준수율 | 평가 가능 건수 중 준수 건수. 평가 대상이 없으면 0%가 아니라 **미산정**. 물리가 논리보다 오래됐거나 누락이면 위반이 아니라 "동기화 필요"로 따로 집계 |

## 4. 검증 규칙 요약 (SWS 공통 흐름 채택)

```
① 권한 → ② 입력 형식(검수 기준) → ③ 업무 규칙 → ④ 신청 → ⑤ 단일 결재·반영
                                   (③은 ④ 신청과 ⑤ 승인 시점에 다시 실행)
```

| 구분 | 기호 | 의미 |
|---|---|---|
| 차단 | ⛔ | 신청·승인 불가 |
| 사유 필요 | 📝 | 사유를 적으면 신청 가능, DA 검토 |
| 경고 | ⚠ | 확인 후 신청 가능, 신청 시점 기록 보존 |

- 검수 기준(입력 형식)은 사전별·필드별로 정한다: 필수·길이·허용 문자·차단/경고.
- 같은 기준을 프런트·서버·엑셀에 동일하게 적용한다.
- DBMS 이름 길이 기준은 프로젝트 대상 DBMS를 따른다.
  - SWS는 기준값을 직접 고른다(63바이트=PostgreSQL, 그 외=Oracle).
  - DBModeler는 MD-40에서 지정한 프로젝트 DBMS를 쓴다.
